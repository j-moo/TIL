## 2. 핵심 개념 정리

### 2.1 문제를 푸는 힘은 구현력만이 아니다

강의에서는 SW 문제해결 역량을 **제약 조건과 요구 사항을 이해하고, 그 안에서 최선의 방법을 찾아내는 능력**으로 설명한다.  
여기서 중요한 점은, 이 능력이 단순히 특정 문법을 아는 것과는 다르다는 것이다. 자료구조, 알고리즘, 언어 문법, 라이브러리 같은 조각들을 상황에 맞게 조합해 **큰 그림을 만드는 힘**이 함께 필요하다.

### 2.2 문제해결 과정은 구현 전에 이미 시작된다

문제를 읽고 바로 코드를 치는 습관은 생각보다 위험하다. 강의에서 강조한 순서는 다음과 같다.

1. 문제를 읽고 이해한다.
2. 익숙한 말로 다시 정의한다.
3. 어떤 자료구조와 알고리즘을 쓸지 계획한다.
4. 그 계획이 맞는지 검증한다.
5. 구현한다.
6. 더 나은 방법이 있는지 돌아본다.

여기서 특히 중요한 것은 **1~4번 과정**이다. 실제 채점에서는 히든 테스트케이스가 있고, 그 안에는 보통 **엣지 케이스**나 **시간 초과를 유발하는 최악 입력**이 숨어 있기 때문이다.

### 2.3 복잡도는 “될까?”를 판단하는 기준이다

좋은 아이디어처럼 보여도 입력 크기가 커지면 바로 시간 초과가 날 수 있다.  
그래서 복잡도는 단순한 이론이 아니라, 문제를 풀기 전에 **이 풀이가 현실적으로 통과 가능한지 판단하는 기준**이 된다.

### 2.4 입력 처리와 진법 변환은 실전 구현의 기본 도구다

문제풀이 환경에서는 입력을 여러 번 바꾸며 테스트해야 하고, 숫자를 다른 진법으로 바꾸거나 비트 단위로 다루는 문제도 자주 만난다.  
이 강의는 그래서 단순 개념 소개를 넘어서, **파일 입력**, **10진수 ↔ 2진수**, **16진수 ↔ 2진수**, **비트 연산**까지 한 번에 연결한다.

## 3. 본문 정리

## 3.1 SW 문제해결 역량이란 무엇인가

SW 문제해결 역량은 **문제를 코드로 번역하기 전에, 문제를 구조적으로 이해하는 능력**이라고 볼 수 있다.

강의 노트에서는 이 역량을 추상적인 기술이라고 표현했다. 이 말은 꽤 중요하다.  
왜냐하면 이 능력은 “딕셔너리 문법을 안다”, “DFS 코드를 외웠다”처럼 눈에 딱 보이는 지식 하나로 설명되지 않기 때문이다. 오히려 여러 지식을 상황에 맞게 꺼내고 조립하는 과정에서 드러난다.

예를 들어, 어떤 문제를 받았을 때 바로 코드부터 쓰기보다 아래 질문을 먼저 던지는 것이 문제해결 역량에 가깝다.

- 이 문제는 **무엇을 구하라는 문제인가**
- 입력 크기를 봤을 때 **완전탐색이 가능한가**
- 리스트, 딕셔너리, 집합, 큐, 스택, 트리 중 **무엇이 자연스러운가**
- 정답을 구하는 과정에서 **반복이 핵심인가, 상태 저장이 핵심인가**

### 문제해결 과정 다시 보기

강의에서 강조한 문제해결 과정은 아래처럼 이해하면 좋다.

| 단계 | 의미 | 왜 중요한가 |
|---|---|---|
| 문제 이해 | 조건과 목표를 정확히 읽기 | 잘못 이해하면 구현을 아무리 잘해도 틀린다 |
| 재정의 | 내 말로 바꾸기 | 애매한 표현을 분명하게 만든다 |
| 설계 | 자료구조/알고리즘 선택 | 구현 전에 방향을 정한다 |
| 검증 | 예제/복잡도/엣지 케이스 확인 | 시간초과, 반례를 미리 막는다 |
| 구현 | 실제 코드 작성 | 설계를 옮기는 단계다 |
| 회고 | 개선점 찾기 | 같은 유형에서 더 빨라진다 |

💡 **포인트**  
강의에서 특히 힘줘 말한 부분은 **1~4번 과정이 훈련되어야 한다**는 점이다.  
실전에서는 구현 실수도 문제지만, 더 자주 틀리는 이유는 애초에 접근 방향이 잘못되었기 때문이다.

`📌 핵심`  
문제해결은 “코드를 빨리 치는 능력”이 아니라, **문제를 구조화하고 설계하는 능력**에서 시작된다.

### 3.2 예시로 보는 접근: 리스트에 숫자 넣기

이 예시는 아주 복잡한 문제는 아니지만, **문제를 해석하고 자료구조와 반복 구조를 고르는 연습**에 잘 맞는다.

문제 요약은 다음과 같다.

- 수 `N`을 입력받는다.
- 윗줄에는 `N`부터 시작해 1씩 증가하는 숫자 4개를 **왼쪽부터** 채운다.
- 아랫줄에는 `N`부터 시작해 1씩 감소하는 숫자 4개를 **오른쪽부터** 채운다.
- 비어 있는 칸은 0으로 둔다.

![alt text](<../assets/images/03_04_start_1/스크린샷 2026-03-04 092531-1.png>)

이 그림을 보면 핵심은 두 가지다.

1. 값을 어디에 넣을지 **인덱스로 관리**해야 한다.
2. 반복 횟수가 정해져 있으므로 **for문 중심의 단순 반복**으로 충분하다.

강의 필기에서도 이 문제를 보며 자료구조는 **리스트 2개 또는 2차원 리스트**, 알고리즘은 **단순 반복**이라고 정리했다.  
이 판단이 좋은 이유는, 문제의 핵심이 복잡한 탐색이 아니라 **정해진 위치에 값을 채우는 규칙 구현**이기 때문이다.

쉬운 말로 바꾸면 이런 문제다.

- 윗줄은 “앞에서부터 채우기”
- 아랫줄은 “뒤에서부터 채우기”

즉, 숫자 규칙도 중요하지만 사실 더 중요한 것은 **방향과 위치를 헷갈리지 않는 것**이다.

⚠️ **주의**  
이런 문제는 계산이 어려운 것이 아니라, 인덱스를 반대로 쓰거나 시작 위치를 한 칸 잘못 잡아서 틀리기 쉽다.  
그래서 구현 전에 종이에 직접 칸을 그려 보는 것이 훨씬 도움이 된다.

`📌 핵심`  
간단한 구현 문제일수록 “무슨 알고리즘을 써야 하지?”보다 **값이 들어갈 위치를 어떻게 표현할지**를 먼저 정하는 편이 좋다.

### 3.3 복잡도 분석: 알고리즘의 좋고 나쁨은 무엇으로 판단할까

강의에서는 알고리즘을 **유한한 단계를 통해 문제를 해결하기 위한 절차나 방법**이라고 정리했다.  
여기서 한 걸음 더 나가면, 알고리즘은 단지 “정답을 구하느냐”만으로 평가되지 않는다. **얼마나 빠르게, 얼마나 적은 자원으로 구하느냐**도 함께 봐야 한다.

그래서 등장하는 개념이 **효율성**이다.

- **시간적 효율성**: 작업을 끝내는 데 걸리는 시간
- **공간적 효율성**: 필요한 메모리 양

효율성을 뒤집어 표현한 것이 **복잡도(Complexity)** 다.  
즉, 복잡도가 높다는 말은 보통 시간이 오래 걸리거나 메모리를 많이 쓴다는 뜻에 가깝다.

### 왜 점근적 표기가 필요한가

실제 연산 횟수는 식으로 쓰면 복잡해지는 경우가 많다. 예를 들어 `2n^2 - 7n + 4` 같은 식이 있을 수 있다.  
그런데 우리가 정말 알고 싶은 것은 아주 정확한 횟수보다, **입력 크기 `n`이 커졌을 때 무엇이 지배적인가**이다.

그래서 사용하는 것이 **점근적 표기(Asymptotic Notation)** 다.

- **Big-O**: 상한, 보통 최악의 경우를 볼 때 많이 사용
- **Big-Omega**: 하한
- **Big-Theta**: 상한과 하한이 같은 정도의 성장

이 강의에서는 특히 **Big-O 표기**를 중심으로 설명한다.

`📌 핵심`  
복잡도 표기는 정확한 초 단위를 맞히기 위한 도구가 아니라, **입력이 커질수록 어떤 풀이가 버틸 수 있는지 판단하는 기준**이다.

### 3.4 Big-O 표기와 반복문 읽기

Big-O는 복잡도의 **점근적 상한**을 나타낸다.  
강의 노트의 예시인 `f(n) = 2n^2 - 7n + 4`를 보면, 입력이 커질수록 결국 `n^2` 항이 가장 큰 영향을 준다. 그래서 이 함수는 `O(n^2)`로 본다.

![alt text](<../assets/images/03_04_start_1/화면 캡처 2026-03-05 005626-2.jpg>)

이 그림에서 보고 싶은 것은 “정확히 어디서 만나는가”가 아니라, **어느 순간 이후에는 `cn^2`가 `2n^2 - 7n + 4`의 위를 덮는다**는 점이다.  
그래서 Big-O는 대략적으로 **이 정도보다 더 빨리 커지지는 않는다**는 상한 개념으로 받아들이면 된다.

#### 자주 만나는 Big-O

- `O(1)` : 입력 크기와 무관하게 거의 일정
- `O(log n)` : 조금씩 천천히 증가
- `O(n)` : 입력에 비례해서 증가
- `O(n log n)` : 정렬 계열에서 자주 등장
- `O(n^2)` : 이중 반복문에서 자주 등장
- `O(n^3)` : 삼중 반복문에서 자주 등장

여기서 중요한 점은 **표기만 보고 기계적으로 판단하지 않는 것**이다.  
강의 노트에도 `O(N) vs O(1)`은 조건에 따라 달라질 수 있다고 적혀 있다. 이 말은, 상수 시간이라고 무조건 모든 상황에서 더 낫다는 뜻이 아니라 **실제 문제의 크기와 구현 비용까지 같이 봐야 한다**는 뜻으로 이해하면 좋다.

### 예시 코드: 아래 코드는 몇 번 반복될까?

복잡도는 긴 이론보다 짧은 코드 하나를 해석해 보는 것이 더 잘 와닿는다.

```python
# 아래 코드는 몇 번 반복될까?

n = int(input())          # 입력 크기 n

for i in range(n):        # 0부터 n-1까지 총 n번 반복
    print(i, end='')      # 매 반복마다 한 번 실행
```

이 코드는 핵심 반복이 `for i in range(n)` 한 줄에 있으므로, 반복 횟수는 `n`번이다.  
따라서 시간복잡도는 **`O(n)`** 으로 본다.

### 코드 해설

- `n = int(input())`  
  입력을 받는 한 번의 동작이므로 전체 성장률에 큰 영향을 주지 않는다.
- `for i in range(n)`  
  반복 횟수를 사실상 결정하는 줄이다. 입력이 두 배가 되면 반복도 두 배에 가까워진다.
- `print(i, end='')`  
  반복문 내부에서 매번 실행되므로, 이 줄도 총 `n`번 수행된다.

여기서 중요한 건 **반복문의 깊이**다.  
반복문이 한 겹이면 보통 `O(n)`, 두 겹이면 `O(n^2)`처럼 읽을 수 있는 경우가 많다. 물론 실제로는 각 반복문의 범위를 더 자세히 봐야 하지만, 문제풀이 초반 감각을 잡을 때는 이 방식이 꽤 유용하다.

⚠️ **주의**  
`O(5N)`처럼 상수를 붙여 쓰는 경우가 아주 없지는 않지만, 일반적인 문제풀이에서는 보통 **상수는 생략하고 `O(N)`으로 단순화**한다.  
다만 강의 노트처럼, 논문이나 정밀 비교에서는 배수를 강조하는 표기를 일부러 남기기도 한다.

`📌 핵심`  
Big-O를 읽을 때는 식을 외우기보다, **반복 횟수를 결정하는 구조가 어디에 있는지** 먼저 찾는 것이 중요하다.

### 3.5 O(n), O(n²), O(log n)을 감각으로 이해하기

강의에서는 단순히 정의만 말하지 않고, **입력 크기를 넣어서 실제 감각으로 이해**하도록 설명한다.

예를 들어 `N = 10,000`일 때를 생각해 보자.

- `O(n)` 이면 대략 `10,000`번 수준
- `O(n^2)` 이면 대략 `100,000,000`번 수준
- `O(log n)` 이면 밑이 2일 때 약 `13~14`번 수준

이 숫자를 직접 비교해 보면, 왜 복잡도가 중요한지 훨씬 분명해진다.  
특히 `O(n^2)`와 `O(n log n)`의 차이는 입력이 커질수록 매우 크게 벌어진다.

![alt text](<../assets/images/03_04_start_1/화면 캡처 2026-03-05 011938-1.jpg>)

이 그래프는 복잡도 표기가 왜 실전에서 중요한지 잘 보여준다.  
작은 입력에서는 차이가 작아 보여도, 입력이 커지면 `O(n^2)`나 `O(2^n)` 계열은 금방 감당하기 어려워진다.

강의 노트에서 언급한 유명한 비교도 같은 맥락이다.

- 10억 개의 숫자를 정렬할 때
- `O(n^2)` 알고리즘은 사실상 비현실적으로 오래 걸리고
- `O(n log n)` 알고리즘은 실용적인 시간 안에 끝날 수 있다

이 말은 결국 **좋은 알고리즘은 좋은 하드웨어만큼, 때로는 그보다 더 큰 차이를 만든다**는 뜻이다.

`📌 핵심`  
복잡도는 시험용 이론이 아니라, **이 풀이가 커진 입력에서도 살아남는지**를 판단하는 실전 감각이다.

### 3.6 제한 시간 감각과 파이썬에서의 실전 판단

강의 노트에는 아주 실전적인 기준도 적혀 있다.

- C 기준으로 대략 **1초에 1억 번**
- Python 기준으로 대략 **1초에 3천만 ~ 4천만 번**

물론 정확한 수치는 환경에 따라 달라진다. 그래서 강의에서도 “문제가 몇 초 걸릴까?”에 대한 정답은 **알 수 없다**고 시작한다.  
그럼에도 문제풀이 사이트에서는 대략적인 약속이 있기 때문에, 이 감각은 충분히 유용하다.

예를 들어 테스트케이스가 14개이고 Python 제한이 3초라면, 한 케이스당 허용할 수 있는 연산량을 거칠게 나눠서 생각해 볼 수 있다.  
이렇게 하면 코드를 쓰기 전에 “이중 반복문이 괜찮나?”, “완전탐색이 위험하지 않나?”를 미리 판단할 수 있다.

### 실전 메모: 자료구조와 언어 선택

강의 필기에는 다음과 같은 실전 감각도 함께 적혀 있다.

- 자료구조는 탐색, 삽입, 삭제, 수정의 특성을 같이 봐야 한다.
- A형 역량테스트는 **구현 + 디버깅**
- B형 역량테스트는 **자료구조 + 알고리즘 적용**
- Python은 상대적으로 메모리에 민감하고, 동적 메모리 확장 비용도 생각해야 한다.
- `append()`를 무조건 나쁘다고 볼 수는 없지만, **불필요한 동적 확장을 줄이는 습관**은 도움이 된다.
- PyPy는 재귀 등에서 빠를 수 있지만 메모리는 더 비효율적일 수 있다.

이 부분은 완벽한 공식이라기보다, 문제를 풀면서 계속 체감하게 되는 **실전 판단 기준**으로 받아들이면 좋다.

`📌 핵심`  
빅오만 보고 끝내지 말고, **실제 연산 횟수와 언어 특성**까지 같이 생각해야 시간 초과를 더 정확하게 피할 수 있다.

### 3.7 표준 입출력 방법: 왜 파일 입력을 익혀야 할까

이 챕터의 목표는 아주 분명하다.  
**콘솔 입력 대신 파일 입력으로 테스트케이스를 편하게 바꾸며 실험할 수 있게 하는 것**이다.

문제를 풀다 보면 같은 로직으로 여러 입력을 반복 테스트해야 한다. 그때 매번 직접 붙여 넣는 방식보다, 입력 파일을 만들어 두고 돌리는 편이 훨씬 편하다.  
특히 구현 문제나 디버깅이 많은 문제에서는 이 차이가 크게 느껴진다.

강의 노트에는 개념만 적혀 있었지만, 이 내용을 실제로 연결하면 아래처럼 이해할 수 있다.

```python
import sys

# input.txt의 내용을 표준 입력처럼 읽어오도록 설정
sys.stdin = open('input.txt', 'r')

T = int(input())          # 테스트케이스 개수
for tc in range(1, T + 1):
    n = int(input())      # 케이스별 입력
    print(tc, n)
```

### 코드 해설

- `sys.stdin = open('input.txt', 'r')`  
  원래 키보드에서 받던 입력을 파일로 바꿔 준다.
- `input()`  
  이후부터는 평소처럼 `input()`을 써도 파일에서 한 줄씩 읽힌다.
- 테스트케이스를 바꾸고 싶으면 `input.txt`만 수정하면 된다.

⚠️ **주의**  
온라인 저지에 제출할 때는 보통 이 줄을 제거해야 한다.  
즉, 파일 입력은 **로컬 테스트용 도구**로 생각하는 것이 좋다.

`📌 핵심`  
파일 입력은 새로운 문법을 배우는 일이 아니라, **디버깅과 테스트를 빠르게 하기 위한 습관**이다.

### 3.8 진법의 기본: 왜 2진수와 16진수를 같이 배울까

강의에서는 10진수, 2진수, 8진수, 16진수를 함께 소개한다.

- **10진수**: 사람이 익숙한 표현
- **2진수**: 컴퓨터가 실제로 다루기 쉬운 표현
- **8진수 / 16진수**: 2진수를 더 짧고 보기 좋게 다루기 위한 표현

여기서 특히 16진수를 강조한 이유는, **2진수를 사람이 직접 다루기에는 너무 길고 불편하기 때문**이다.  
16진수 한 자리로 2진수 네 자리를 정확히 표현할 수 있으니, 비트를 묶어서 다루기에 아주 편하다.

쉽게 말해,

- 10진수는 사람이 이해하기 편하다.
- 2진수는 컴퓨터가 계산하기 편하다.
- 16진수는 **사람과 컴퓨터 사이의 타협점**처럼 쓸 수 있다.

그리고 이 흐름은 곧바로 **비트 연산**으로 이어진다.  
2진수로 표현할 수 있다는 것은 곧, 자리별 0과 1을 기준으로 `AND`, `OR`, `SHIFT` 같은 연산을 할 수 있다는 뜻이기 때문이다.

`📌 핵심`  
16진수를 배우는 이유는 새로운 숫자 체계가 신기해서가 아니라, **비트를 더 짧고 다루기 쉽게 표현하기 위해서**다.

### 3.9 10진수를 2진수로 바꾸기: while과 비트 연산 두 가지 관점

강의 노트의 첫 번째 진법 변환 코드는 `149`를 2진수로 바꾸는 예시다.  
이 코드는 두 가지 관점을 같이 보여 준다.

1. **나눗셈과 나머지**를 이용한 변환
2. **비트 연산**을 이용한 출력

먼저 while을 이용한 방식부터 보자.

```python
# 십진수를 이진수로

decimal = 149

# 중간 나눗셈의 나머지를 저장할 배열
arr = []

# 2로 계속 나누면서 나머지를 저장
while decimal != 0:
    arr.append(decimal % 2)     # 현재 자리의 비트(나머지)
    decimal = decimal // 2      # 다음 계산을 위해 몫으로 갱신

# 나머지는 뒤에서부터 읽어야 하므로 뒤집기
arr.reverse()

# 1 0 0 1 0 1 0 1 형태로 출력
print(*arr)
```

### 코드 흐름 해설

이 방식은 “2로 나눈 나머지를 거꾸로 읽는다”는 진법 변환의 정석을 그대로 코드로 옮긴 것이다.

- `149 % 2` → 가장 오른쪽 비트
- `149 // 2` → 다음 단계에서 다시 나눌 값
- 이 과정을 0이 될 때까지 반복
- 나머지가 **뒤에서부터 쌓이므로**, 마지막에 뒤집어야 한다

예를 들어 `149`는 아래처럼 진행된다.

| 현재 값 | 2로 나눈 나머지 |
|---|---|
| 149 | 1 |
| 74 | 0 |
| 37 | 1 |
| 18 | 0 |
| 9 | 1 |
| 4 | 0 |
| 2 | 0 |
| 1 | 1 |

나머지를 아래에서 위로 읽으면 `10010101`이 된다.

### 같은 값을 비트 연산으로 출력하기

강의 노트는 이어서 같은 숫자를 비트 연산으로 출력하는 함수도 보여 준다.

```python
# 비트연산으로 8비트 문자열 만들기
def bit_print(dec):
    output = ""

    # 가장 높은 비트(7)부터 가장 낮은 비트(0)까지 확인
    for i in range(7, -1, -1):
        # i번째 비트가 1이면 "1", 아니면 "0" 추가
        if dec & (1 << i):
            output += "1"
        else:
            output += "0"

    return output


print(bit_print(149))
```

### 코드 흐름 해설

여기서 핵심 표현은 `dec & (1 << i)`다.

- `1 << i` : 1을 왼쪽으로 `i`칸 민 값  
  예를 들어 `i=3`이면 `00001000`
- `dec & (1 << i)` : `dec`의 `i`번째 비트만 확인

즉, 이 함수는 7번째 자리부터 0번째 자리까지 하나씩 검사하면서, 그 자리가 켜져 있으면 `"1"`, 아니면 `"0"`을 붙이는 방식이다.

### 두 방식의 차이

| 방식 | 장점 | 언제 떠올리면 좋은가 |
|---|---|---|
| 나눗셈 / 나머지 | 진법 변환 원리가 잘 보인다 | 개념 이해, 다른 진법 변환 |
| 비트 연산 | 자리 확인이 빠르고 직접적이다 | 비트마스킹, 자리 검사, 고정 길이 출력 |

⚠️ **주의**  
비트 연산 방식은 자리 수를 직접 정해야 하므로, 여기서는 8비트 기준으로 출력된다.  
숫자 크기에 따라 더 긴 비트 수가 필요하면 범위를 조정해야 한다.

`📌 핵심`  
같은 2진수 출력이라도, **나눗셈 방식은 변환 원리**, **비트 연산 방식은 자리 확인 방식**이라는 차이가 있다.

### 3.10 16진수를 2진수로 바꾸기: 매핑과 비트 연산

16진수는 한 글자가 정확히 **4비트**와 대응된다.  
그래서 `"47FE"` 같은 문자열을 2진수로 바꾸려면, 각 글자를 4비트씩 확장해 주면 된다.

강의 노트에서는 두 가지 구현을 보여 준다.

#### 방법 1: 미리 만든 사전으로 바로 바꾸기

```python
# 16진수 한 글자 -> 4비트 문자열 매핑
hex_to_bin = {
    "0": "0000", "1": "0001", "2": "0010", "3": "0011",
    "4": "0100", "5": "0101", "6": "0110", "7": "0111",
    "8": "1000", "9": "1001", "A": "1010", "B": "1011",
    "C": "1100", "D": "1101", "E": "1110", "F": "1111"
}

hex_value = "47FE"

result = ""
for ch in hex_value:
    result += hex_to_bin[ch]    # 글자 하나를 바로 4비트로 치환

print(result)
```

### 코드 흐름 해설

이 방식은 가장 직관적이다.  
`"4"`를 보면 `"0100"`, `"7"`을 보면 `"0111"`처럼 바로 연결하므로, **16진수와 4비트의 대응 관계를 그대로 사용**한다.

#### 방법 2: 각 글자를 10진수로 바꾼 뒤 비트 연산으로 만들기

```python
hex_value = "47FE"

result2 = ""
for ch in hex_value:
    dec = int(ch, 16)           # 16진수 문자 -> 10진수 값

    result_bin = ""

    # 4비트만 확인하면 되므로 3부터 0까지 검사
    for i in range(3, -1, -1):
        result_bin += "1" if dec & (1 << i) else "0"

    result2 += result_bin

print(result2)
```

### 코드 흐름 해설

이 방식은 앞에서 본 `bit_print()`의 아이디어를 그대로 확장한 것이다.

- 먼저 `int(ch, 16)`으로 16진수 글자를 숫자로 바꾼다.
- 그 다음 4비트 범위 안에서 각 자리를 검사한다.
- 결국 각 글자가 4자리 이진수 문자열로 변환된다.

이 코드는 특히 **비트 자리 검사 방식에 익숙해지기 좋다**는 장점이 있다.

### 자주 하는 실수

- 소문자 `a~f` 입력을 그대로 받을 때 처리하지 않음
- 16진수 한 자리 = 4비트라는 점을 놓치고 자릿수를 가변적으로 출력함
- 문자열 이름을 `hex`로 두면 파이썬 내장 함수 이름과 겹칠 수 있음

💡 **포인트**  
강의 노트는 `hex`라는 이름을 썼지만, 실제 코드에서는 `hex_value`처럼 조금 더 안전한 이름을 쓰는 편이 좋다.

`📌 핵심`  
16진수 변환은 결국 **글자 하나를 4비트로 확장하는 과정**이다.

### 3.11 7비트씩 끊어서 10진수로 바꾸기

마지막 연습문제는 `00000010001101` 같은 비트 문자열을 **7칸씩 잘라**, 각 조각을 다시 10진수로 바꾸는 문제다.  
이 예시는 진법 변환과 인덱스 계산을 동시에 연습하기 좋다.

```python
bit = "00000010001101"

# 이진수를 7칸씩 나누기
N = len(bit)

for i in range(0, N, 7):
    # i 위치부터 7글자 잘라오기
    ith_bin = bit[i:i + 7]

    decimal = 0

    # 문자열의 각 자리를 10진수 값으로 환산
    # 왼쪽이 가장 큰 자리, 오른쪽이 가장 작은 자리
    for j in range(6, -1, -1):
        decimal += int(ith_bin[j]) * 2 ** (6 - j)

    print(decimal, ",")
```

### 코드 흐름 해설

이 문제는 두 단계로 보면 이해가 쉽다.

1. 전체 문자열을 **7글자씩 자른다**
2. 잘린 조각을 각각 **이진수 → 10진수**로 바꾼다

내부 반복문에서 하고 있는 계산은 사실 아래와 같은 원리다.

- 맨 오른쪽 비트 × `2^0`
- 그 왼쪽 비트 × `2^1`
- ...
- 맨 왼쪽 비트 × `2^6`

즉, 우리가 평소 10진수 자릿값을 계산하듯이, **2의 거듭제곱을 자릿값으로 사용하는 것**이다.

### 이해를 돕는 예시

예를 들어 `0000001`은 다음처럼 계산된다.

- `1 × 2^0 = 1`
- 나머지는 모두 0

그래서 결과는 `1`이다.

또 `0001101`은

- `1 × 2^0 = 1`
- `0 × 2^1 = 0`
- `1 × 2^2 = 4`
- `1 × 2^3 = 8`

이 되어 총합 `13`이 된다.

### 자주 하는 실수 / 디버깅 포인트

- 7칸씩 자를 때 범위를 잘못 잡아 마지막 조각이 어긋남
- 왼쪽과 오른쪽 비트의 자릿값 방향을 반대로 계산함
- 출력 형식에서 쉼표나 공백이 문제 요구와 다르게 나감

💡 **포인트**  
이 코드는 직접 자릿값을 계산하는 방식이라 원리를 익히기 좋다.  
실전에서는 누적 방식이나 내장 변환을 쓸 수도 있지만, **비트 문자열을 숫자로 해석하는 감각**을 익히기에는 지금 코드가 더 교육적이다.

`📌 핵심`  
비트 문자열을 십진수로 바꾸는 핵심은, **각 자리에 2의 거듭제곱 가중치를 곱해 더하는 것**이다.

## 4. 적용 관점에서 다시 보기

앞에서 본 내용은 서로 따로 떨어진 주제가 아니다. 실제 문제풀이에서는 보통 아래 흐름으로 이어진다.

### 4.1 문제를 보면 가장 먼저 떠올릴 것

1. **무엇을 구하는가**
2. **입력 크기가 어느 정도인가**
3. **어떤 자료구조가 자연스러운가**
4. **반복 횟수가 대략 얼마인가**
5. **비트나 진법 변환이 필요한 형태인가**

이 다섯 가지를 먼저 보면, 구현 전에 방향이 많이 정리된다.

### 4.2 어떤 유형에서 이 개념을 떠올리면 좋을까

| 상황 | 떠올릴 개념 |
|---|---|
| 칸 채우기, 배열 배치 | 리스트 / 2차원 배열 / 인덱스 설계 |
| 제한 시간 판단이 먼저 필요한 문제 | Big-O, 반복 횟수 계산 |
| 테스트케이스를 반복 디버깅해야 할 때 | 파일 입력 |
| 암호, 비트열, 플래그 처리 문제 | 2진수, 16진수, 비트 연산 |
| 문자열처럼 들어온 이진수/16진수를 숫자로 해석해야 할 때 | 진법 변환 |

### 4.3 구현 순서를 어떻게 잡으면 좋을까

강의 흐름을 문제풀이용으로 다시 정리하면 보통 아래 순서가 자연스럽다.

1. 문제를 내 말로 다시 쓴다.
2. 예제 입력 하나를 종이에 직접 따라가 본다.
3. 필요한 자료구조를 정한다.
4. 반복 횟수를 보고 시간복잡도를 계산한다.
5. 구현한다.
6. 엣지 케이스와 출력 형식을 다시 확인한다.

특히 진법 변환이나 비트 문제는, 코드를 보기 전에 **숫자 하나를 손으로 직접 변환**해 보면 이해가 훨씬 빨라진다.

### 4.4 실전에서 자주 헷갈리는 포인트

- 문제를 풀기도 전에 코드를 먼저 치는 것
- `O(n)`과 `O(n^2)`의 차이를 입력 크기 없이 추상적으로만 보는 것
- 파일 입력 코드를 제출본에서 지우지 않는 것
- 비트 문자열의 자릿값 방향을 반대로 계산하는 것
- 16진수 한 자리가 4비트라는 점을 놓치는 것

### 4.5 본문 예시와 코드를 어떻게 응용하면 좋을까

- **리스트 배치 예시**는 구현 문제 전반의 기본이다.  
  값 규칙보다 먼저 **인덱스 규칙**을 잡는 연습으로 응용할 수 있다.
- **반복문 복잡도 예시**는 어떤 코드든 빠르게 성장률을 읽는 출발점이 된다.
- **10진수 → 2진수 코드**는 다른 진법 변환으로도 확장 가능하다.
- **16진수 → 2진수 코드**는 암호문, 비트열, 디지털 회로 관련 문제에서도 자주 재활용된다.
- **7비트 분할 코드**는 문자열 슬라이싱과 자릿값 계산을 함께 다루는 문제에 응용하기 좋다.

## 5. 배운 점 / 느낀 점 / 확장 포인트

이번 강의에서 가장 크게 남는 점은, 문제풀이가 단순히 알고리즘 이름을 많이 아는 게임이 아니라는 것이다.  
오히려 더 중요한 것은 **문제를 구조화하고, 입력 크기와 자료구조를 보고, 구현 가능한 단위로 쪼개는 힘**이라는 점이다.

복잡도 파트는 특히 “왜 효율적인 알고리즘이 필요한가”를 감각적으로 느끼게 해 준다.  
작은 예제에서는 비슷해 보여도, 입력이 커지면 알고리즘 선택이 결과를 완전히 바꿔 놓는다.

또 진법과 비트 연산 파트는 처음 보면 조금 낯설지만, 실제로는 문자열 처리나 숫자 처리처럼 **구현 문제 안에 자연스럽게 섞여 들어오는 기초 도구**에 가깝다.  
그래서 이 부분은 공식처럼 외우기보다, 직접 변환 과정을 손으로 써 보고 코드와 연결해 보는 연습이 중요하다.

앞으로 더 확장해서 공부해 보면 좋은 주제는 다음과 같다.

- 완전탐색이 안 될 때 어떤 대안을 찾는가
- 정렬, 탐색, 그래프에서 복잡도 감각을 어떻게 적용하는가
- 비트 마스킹으로 상태를 압축하는 방법
- 재귀를 이용한 진법 변환
- 입력 최적화와 출력 최적화

## 6. 요약 정리

- **문제해결 역량**은 문법 지식보다 더 큰 개념이며, 문제를 해석하고 설계하는 힘에 가깝다.
- 문제를 풀 때는 구현 전에 **문제 이해 → 재정의 → 설계 → 검증** 과정이 꼭 필요하다.
- **Big-O**는 입력이 커질 때 알고리즘이 얼마나 빠르게 느려지는지를 보는 기준이다.
- 반복문 하나는 보통 `O(n)`, 이중 반복문은 보통 `O(n^2)`처럼 읽을 수 있다.
- 실전에서는 빅오만이 아니라 **실제 연산 횟수, 언어 특성, 제한 시간**도 같이 봐야 한다.
- 파일 입력은 디버깅을 쉽게 해 주는 실전 도구다.
- 10진수 ↔ 2진수, 16진수 ↔ 2진수 변환은 비트 연산의 기초가 된다.
- 비트 문자열을 십진수로 바꾸는 핵심은 **각 자리에 2의 거듭제곱 가중치를 곱하는 것**이다.

📌 **핵심**  
이번 강의는 따로 떨어진 여러 주제를 소개한 것이 아니라,  
**문제를 읽고 → 시간 안에 풀 수 있는지 판단하고 → 실제 구현으로 옮기는 전체 흐름**을 보여 준 강의라고 볼 수 있다.

🧠 **기억할 것**

- 구현 전에 설계가 먼저다.
- 반복 횟수를 보면 시간복잡도가 보인다.
- 16진수 한 자리는 4비트다.
- 비트 연산은 숫자를 더 작은 자리 단위로 다루는 방법이다.
- 테스트하기 쉬운 환경을 만드는 것도 문제풀이 실력의 일부다.
