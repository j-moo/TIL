## 1. 들어가며

알고리즘을 공부하다 보면 어느 순간 이런 질문을 만나게 됩니다.

- 왜 16진수는 2진수보다 읽기 편할까?
- `1 << n` 은 왜 자꾸 `2^n` 이라고 할까?
- 음수는 비트로 어떻게 저장될까?
- `0.1 + 0.2 == 0.3` 이 왜 항상 참이 아닐 수 있을까?

이 질문들은 전부 같은 방향을 가리킵니다.  
바로 **“컴퓨터는 숫자를 어떻게 표현하고 계산하는가?”** 입니다.

이번 강의는 그 기초를 다룹니다.  
겉으로 보면 진법 변환, 비트연산, 음수 표현, 부동소수점처럼 각각 따로 보이지만, 사실은 모두 **숫자를 컴퓨터 시선으로 다시 보는 과정**이라고 할 수 있습니다.

이 글에서는 그 흐름을 아래 순서대로 정리합니다.

1. 10진수, 2진수, 16진수는 어떻게 오가는지
2. 비트연산은 왜 중요한지
3. 음수는 왜 2의 보수로 표현하는지
4. 실수는 왜 정확하지 않을 수 있는지

## 2. 핵심 개념 정리

이 글을 읽기 전에 먼저 큰 줄기부터 잡고 가면 훨씬 편합니다.

### 📌 진법 변환
우리가 쓰는 10진수는 컴퓨터 내부에서 그대로 저장되지 않습니다.  
컴퓨터는 기본적으로 **2진수**를 사용하고, 사람이 보기 편하도록 **16진수**를 자주 함께 씁니다.

핵심만 먼저 적으면 이렇습니다.

- 10진수 → 다른 진수: **계속 나누고, 나머지를 역순으로 읽기**
- 2진수 → 10진수: 각 자리를 **2의 거듭제곱**으로 해석
- 16진수 ↔ 2진수: **16진수 1자리 = 2진수 4자리**

### 📌 비트연산
비트연산은 숫자를 비트 단위로 직접 다루는 연산입니다.

- `&`: 둘 다 1일 때만 1
- `|`: 하나라도 1이면 1
- `^`: 서로 다를 때만 1
- `<<`: 왼쪽으로 밀기
- `>>`: 오른쪽으로 밀기

이 연산은 단순 계산을 넘어서 **상태 표현, 부분집합, 비트마스킹**과 바로 연결됩니다.

### 📌 음수 표현
컴퓨터는 음수를 보통 **2의 보수(two's complement)** 방식으로 저장합니다.

- 비트를 반전시키고
- 1을 더한다

이 방식은 음수 계산을 더 일관되게 처리할 수 있게 해줍니다.

### 📌 실수 표현
실수는 정수처럼 딱 떨어지지 않습니다.  
컴퓨터는 실수를 보통 **부동소수점**으로 저장하고, 이 과정에서 값이 **근사값**이 될 수 있습니다.

그래서 실수 계산에는 오차가 생길 수 있습니다.

## 3-1. 10진수, 2진수, 16진수는 어떻게 연결될까? 🔢

이 섹션에서는 진법 변환을 먼저 정리합니다.  
여기서 핵심은 계산 공식을 외우는 것보다, **왜 그렇게 변환되는지**를 이해하는 것입니다.

### 10진수에서 다른 진수로 바꾸는 방법

가장 기본은 **나누기와 나머지**입니다.

![alt text](<../assets/images/03_05_start_2/스크린샷 2026-03-05 090803-1.png>)

이 그림이 보여주는 핵심은 하나입니다.  
**현재 자리값은 나머지로 나오고, 더 높은 자리는 몫으로 넘어간다**는 점입니다.

그래서 10진수를 2진수로 바꿀 때는:

1. 2로 나누고
2. 나머지를 기록하고
3. 몫으로 다시 반복한 뒤
4. 나머지를 **거꾸로 읽으면** 됩니다.

### 예시: 25를 2진수로 바꾸기
25를 2로 계속 나누면 나머지가 아래처럼 나옵니다.

- 25 ÷ 2 → 나머지 1
- 12 ÷ 2 → 나머지 0
- 6 ÷ 2 → 나머지 0
- 3 ÷ 2 → 나머지 1
- 1 ÷ 2 → 나머지 1

거꾸로 읽으면 `11001` 입니다.

### 💻 코드 예시: 10진수 → 2진수
이 코드는 위 과정을 그대로 구현한 버전입니다.

```python
# 10진수 n을 2진수 문자열로 바꾸는 함수
def decimal_to_binary(n):
    # 최종 결과를 저장할 문자열 변수
    binary_number = ''

    # 0은 예외적으로 바로 '0'을 반환
    if n == 0:
        return '0'

    # n이 0보다 큰 동안 반복하면서 각 자리 비트를 구함
    while n > 0:
        # 현재 자리의 비트 값을 얻기 위해 2로 나눈 나머지를 저장
        remain = n % 2

        # 나머지를 앞에 붙여야 최종 순서가 맞아짐
        binary_number = str(remain) + binary_number

        # 다음 자리 계산을 위해 몫으로 갱신
        n = n // 2

    # 완성된 2진수 문자열 반환
    return binary_number

# 예시: 25를 2진수로 변환
print(decimal_to_binary(25))
```

### 코드 해설
이 코드의 핵심은 `binary_number = str(remain) + binary_number` 입니다.  
처음 나오는 나머지는 가장 낮은 자리이기 때문에, 뒤가 아니라 **앞에 붙여야** 최종 순서가 맞습니다.

### ⚠️ 자주 하는 실수
- 나머지를 뒤에 붙여서 결과가 반대로 나옴
- `n == 0` 예외 처리를 빼먹음

### 2진수는 왜 10진수로 다시 읽을 수 있을까?

반대로 2진수를 10진수로 바꾸는 원리는 자리값 해석입니다.

![alt text](<../assets/images/03_05_start_2/스크린샷 2026-03-05 091717-1.png>)

예를 들어 `11001` 은

- `1 × 2^4`
- `1 × 2^3`
- `0 × 2^2`
- `0 × 2^1`
- `1 × 2^0`

으로 읽을 수 있고, 결과는 `25` 입니다.

즉, 2진수 변환은 외우는 규칙이 아니라 **자리값 체계의 차이**입니다.

### 16진수는 왜 자주 함께 등장할까?

2진수는 컴퓨터에게는 자연스럽지만, 사람에게는 너무 길고 읽기 어렵습니다.  
이때 16진수는 아주 유용합니다.

![alt text](<../assets/images/03_05_start_2/스크린샷 2026-03-05 091906-1.png>)

16진수 한 자리는 정확히 2진수 네 자리와 대응됩니다.  
그래서 긴 비트열을 짧고 읽기 쉽게 바꿔주는 역할을 합니다.

예를 들어:

- `1111` → `F`
- `1001` → `9`
- 따라서 `11111001` → `F9`

### 📌 핵심
**16진수 1자리 = 2진수 4자리**

이 한 줄만 기억해도, 진법 변환이 훨씬 쉬워집니다.

### 💻 코드 예시: 10진수 → 16진수
이번에는 같은 원리로 16진수 변환 코드를 볼 수 있습니다.

```python
# 10진수 n을 16진수 문자열로 바꾸는 함수
def decimal_to_hexadecimal(n):
    # 16진수 문자 테이블을 순서대로 저장
    hex_digits = '0123456789ABCDEF'

    # 최종 16진수 결과를 저장할 문자열
    hexadecimal_number = ''

    # 0은 예외적으로 바로 '0'을 반환
    if n == 0:
        return '0'

    # n이 0보다 큰 동안 반복
    while n > 0:
        # 16으로 나눈 나머지가 현재 자리의 16진수 값
        remain = n % 16

        # 나머지를 문자 테이블에서 찾아 앞에 붙임
        hexadecimal_number = hex_digits[remain] + hexadecimal_number

        # 다음 자리 계산을 위해 몫으로 갱신
        n = n // 16

    # 완성된 16진수 문자열 반환
    return hexadecimal_number

# 예시: 255를 16진수로 변환
print(decimal_to_hexadecimal(255))

# 파이썬 내장함수 예시
print(bin(5))
print(hex(255))
```

### 코드 해설
이 코드는 2진수 변환과 구조가 거의 같습니다.  
차이는 `2` 대신 `16`으로 나누고, 숫자 `10~15`를 문자 `A~F`로 바꾸기 위해 문자 테이블을 쓴다는 점입니다.

### ⚠️ 자주 하는 실수
- 문자 테이블을 `ABCDEF` 대신 이상하게 적는 경우
- `0` 예외 처리 누락
- 내장함수 `bin`, `hex` 결과에 붙는 접두사(`0b`, `0x`)를 보고 당황함

## 3-2. 비트연산은 왜 중요한가? 💡

이 섹션에서는 비트연산이 단순한 문법이 아니라, **문제풀이 도구**라는 점을 정리합니다.

### AND와 OR부터 다시 보기

![alt text](<../assets/images/03_05_start_2/스크린샷 2026-03-05 094217-1.png>)

- `AND (&)`: 둘 다 1일 때만 1
- `OR (|)`: 하나라도 1이면 1

이 두 연산은 가장 기초적이지만, 조건 필터링이나 마스크 처리에 자주 쓰입니다.

![alt text](<../assets/images/03_05_start_2/스크린샷 2026-03-05 094343-1.png>)

위 자료처럼 실제 정수를 이진수로 놓고 보면, 연산 결과를 훨씬 직관적으로 이해할 수 있습니다.

### XOR는 왜 자꾸 특별하게 다뤄질까?

XOR는 “서로 다를 때만 1”이라는 규칙을 갖습니다.

![alt text](<../assets/images/03_05_start_2/스크린샷 2026-03-05 100229-1.png>)

이 연산이 특히 중요한 이유는 **재미있는 성질** 때문입니다.

- 같은 수를 두 번 XOR 하면 원래 값으로 돌아옵니다.

이 성질은 중복 제거, 한 번만 등장하는 수 찾기, 간단한 암호화 예시와 자주 연결됩니다.

![alt text](<../assets/images/03_05_start_2/스크린샷 2026-03-05 100410-1.png>)

### 💻 코드 예시: XOR 응용
아래 코드는 XOR가 어떻게 활용될 수 있는지를 보여주는 간단한 예시입니다.

```python
# 비밀 키 역할을 하는 값을 저장
secret_code = 1004

# 첫 번째 숫자를 비밀 키와 XOR 해서 결과 확인
print(7070 ^ secret_code)

# 두 번째 숫자를 비밀 키와 XOR 해서 결과 확인
print(6258 ^ secret_code)
```

### 코드 해설
이 코드는 XOR의 성질을 보여주는 아주 간단한 예시입니다.  
핵심은 **같은 키로 다시 XOR 하면 원래 값으로 돌아갈 수 있다**는 점입니다.

### Shift는 왜 `2^n` 과 연결될까?

![alt text](<../assets/images/03_05_start_2/스크린샷 2026-03-05 100734-1.png>)

- `<<`: 비트를 왼쪽으로 이동
- `>>`: 비트를 오른쪽으로 이동

왼쪽으로 한 칸 밀면 자리값이 2배가 되므로,  
`1 << n` 은 자연스럽게 `2^n` 과 연결됩니다.

### 📌 핵심
- `1 << 3 = 8`
- `1 << 5 = 32`

이 개념은 비트마스킹 문제에서 정말 자주 나옵니다.

### 비트연산이 문제풀이와 연결되는 순간: 부분집합

비트연산이 “문법”에서 “도구”로 바뀌는 대표 예시가 부분집합입니다.

배열 원소가 4개라면, 각 원소는 “선택 / 선택 안 함” 두 상태를 가집니다.  
즉, 원소 하나를 비트 하나로 표현할 수 있습니다.

### 💻 코드 예시: 비트마스킹으로 부분집합 만들기
이 코드는 비트 하나가 원소 하나의 선택 여부를 뜻한다는 점을 그대로 보여줍니다.

```python
# 부분집합을 만들 원소들을 리스트에 저장
arr = [7, 1, 3, 5]

# 원소가 4개면 부분집합 수는 2^4 이므로 1 << len(arr)를 사용
print(f'부분 집합의 수 : {1 << len(arr)}개')

# 0번 부분집합부터 마지막 부분집합까지 차례대로 확인
for i in range(1 << len(arr)):
    # 현재 부분집합 번호를 먼저 출력
    print(f'{i}번 째 부분집합:', end=' ')

    # 배열의 각 원소 위치를 하나씩 확인
    for idx in range(len(arr)):
        # i의 idx번째 비트가 1이면 해당 원소를 포함한 것
        if i & (1 << idx):
            # 포함되는 원소를 출력
            print(arr[idx], end=' ')

    # 한 부분집합 출력이 끝나면 줄바꿈
    print()
```

### 코드 해설
- `1 << len(arr)` 는 전체 부분집합 개수 `2^N`
- `i` 는 부분집합 번호
- `idx` 는 배열 원소 위치
- `i & (1 << idx)` 가 참이면 그 원소를 포함합니다

예를 들어 `i = 5` 이면 이진수로 `0101` 이고, 이는 0번과 2번 원소를 선택했다는 뜻입니다.

### ⚠️ 자주 하는 실수
- `1 << n` 을 단순 이동으로만 외워 의미를 놓침
- `i` 와 `idx` 역할을 헷갈림
- `&`, `|`, `^` 를 서로 바꿔 씀

## 3-3. 음수는 왜 2의 보수로 저장될까? ➖

이 섹션에서는 음수 표현을 정리합니다.  
여기서는 “어떻게 외울까”보다 “왜 이 방식이 쓰일까”가 더 중요합니다.

컴퓨터는 보통 음수를 **2의 보수(two's complement)** 로 저장합니다.

### 2의 보수 구하는 방법
1. 비트를 뒤집고
2. 1을 더한다

![alt text](<../assets/images/03_05_start_2/스크린샷 2026-03-05 143914-1.png>)

예를 들어 어떤 값을 음수 형태로 바꿀 때,  
비트 반전만 하는 것이 아니라 **반전 후 +1** 까지 해야 합니다.

### 왜 이런 방식을 쓸까?
2의 보수를 쓰면:

- 덧셈/뺄셈 회로를 더 일관되게 사용할 수 있고
- `+0` 과 `-0` 을 따로 만들지 않아도 되며
- 음수 계산을 효율적으로 처리할 수 있습니다

즉 2의 보수는 단순 규칙이 아니라 **컴퓨터가 연산을 쉽게 하도록 만든 설계**입니다.

### 💻 코드 예시: 비트 상태 출력
아래 코드는 숫자를 8비트 형태로 출력해보는 예시입니다.  
특히 음수 표현을 감각적으로 이해하는 데 도움이 됩니다.

```python
# 정수 i를 8비트 형태로 출력하는 함수
def bit_print(i):
    # 비트 문자열을 저장할 변수
    output = ''

    # 가장 높은 비트(7번)부터 가장 낮은 비트(0번)까지 차례대로 확인
    for j in range(7, -1, -1):
        # j번째 비트가 켜져 있으면 '1', 아니면 '0'을 문자열에 추가
        output += '1' if i & (1 << j) else '0'

    # 완성된 비트 문자열 출력
    print(output)

# -5부터 5까지 차례대로 비트 형태를 확인
for i in range(-5, 6):
    # 현재 숫자 값을 먼저 출력
    print(f'{i} = ', end='')

    # 해당 숫자의 비트 형태를 출력
    bit_print(i)
```

### 코드 해설
이 코드는 `1 << j` 를 이용해 특정 비트만 켜진 값을 만들고,  
`i & (1 << j)` 로 해당 비트가 1인지 검사합니다.

즉, 높은 비트부터 차례대로 확인하면서 비트 문자열을 만들어내는 구조입니다.

### ⚠️ 자주 하는 실수
- 2의 보수에서 `+1` 을 빼먹음
- 음수 비트 표현을 “맨 앞이 1이면 무조건 끝” 정도로만 외움
- 파이썬의 음수 출력과 일반적인 고정 비트 정수 표현을 완전히 같은 것으로 오해함

## 3-4. 실수는 왜 정확하지 않을 수 있을까? 🌊

이 섹션에서는 정수보다 더 까다로운 **실수 표현**을 정리합니다.

정수는 자릿값이 명확하지만, 실수는 그렇지 않습니다.  
특히 10진수 소수는 2진수로 바꿨을 때 깔끔하게 끝나지 않는 경우가 많습니다.

그래서 컴퓨터는 실수를 보통 **부동소수점(floating-point)** 방식으로 저장하고, 이 과정에서 값이 **근사값**이 될 수 있습니다.

### 실수 출력 예시
아래 코드는 파이썬에서 실수 값을 포맷팅해서 출력하는 간단한 예시입니다.

```python
# 정수 예시 값을 저장
t1 = 10

# 실수 예시 값을 저장
t2 = 3.141592

# 정수 값을 문자열 안에 넣어 출력
print(f'변수 값은 {t1} 입니다')

# 실수 값을 소수 둘째 자리까지 출력
print(f'변수 값은 {t2:.2f} 입니다')
```

### 코드 해설
- `f'{값:.2f}'` 형태를 사용하면 소수 둘째 자리까지 출력할 수 있습니다
- 출력 형식을 조정하는 것은 실제 코드 가독성과 결과 확인에서 중요합니다

### 실수 오차는 왜 생길까?

![alt text](<../assets/images/03_05_start_2/스크린샷 2026-03-05 150856-1.png>)

핵심은 이겁니다.

**컴퓨터는 실수를 정확한 값이 아니라, 저장 가능한 가장 가까운 값으로 보관할 수 있다.**

그래서 우리가 보기에는 “당연히 같아야 할 것 같은 계산”도 미세하게 다를 수 있습니다.

예를 들어 `0.1` 은 10진수에서는 간단하지만, 2진수에서는 무한히 이어질 수 있습니다.  
그래서 내부 저장값은 근사치가 됩니다.

### 소수는 2진수로 어떻게 바꿀까?

![alt text](<../assets/images/03_05_start_2/스크린샷 2026-03-05 151053-1.png>)

정수 부분은 익숙한 방식으로 바꾸고,  
소수 부분은 2를 계속 곱하면서 정수 부분을 읽어가는 방식으로 바꿀 수 있습니다.

예를 들어:

- `0.75 = 0.11(2)`
- `0.40625 = 0.01101(2)`

이 과정을 보면, 실수가 왜 더 복잡한지 감이 옵니다.

### 부동소수점은 어떤 구조일까?

![alt text](<../assets/images/03_05_start_2/스크린샷 2026-03-05 151246-1.png>)

![alt text](<../assets/images/03_05_start_2/스크린샷 2026-03-05 151334-1.png>)

부동소수점은 보통 아래 세 부분으로 나뉩니다.

| 구분 | 의미 |
|---|---|
| 부호 비트 | 양수/음수 구분 |
| 지수부 | 값의 크기 |
| 가수부 | 실제 유효 숫자 |

즉 실수는 단순한 소수점 숫자가 아니라,  
내부적으로는 **정규화된 형태의 비트 구조**로 저장되는 값입니다.

### 예시: 12.375
- 2진수로 `1100.011`
- 정규화하면 `1.100011 × 2^3`
- 지수는 bias를 더해 저장
- 가수는 맨 앞의 1을 생략하고 저장

### ⚠️ 주의
실수 비교는 `==` 를 바로 쓰는 습관을 조심해야 합니다.  
문제풀이에서는 보통 **허용 오차 범위**로 비교합니다.

## 4. 적용 / 예시 / 코드 해설

이제 강의 내용을 문제풀이와 연결해서 보면, 각각의 개념이 왜 중요한지 더 분명해집니다.

### 진법 변환이 필요한 상황
- 문자열 형태의 진수 변환 문제

### 비트연산이 필요한 상황
- 부분집합 만들기
- 상태 압축
- 특정 비트 켜기/끄기/확인하기
- XOR 성질을 이용한 값 추적

### 음수 표현이 중요한 상황
- 정수 내부 표현 이해
- 언어별 비트연산 결과 해석
- low-level 개념 공부

### 실수 표현이 중요한 상황
- 오차 허용 비교 문제
- 수치 계산
- 부동소수점 구조 이해

- 실수 포맷 출력: `f'{x:.2f}'`

### ⚠️ 자주 하는 실수 / 디버깅 포인트
- 진법 변환에서 나머지 역순 처리 누락

- 음수 표현에서 2의 보수를 반만 기억함
- 실수 비교를 직접 `==` 로 수행함

## 5. 배운 점 / 느낀 점 / 확장 포인트

이번 강의는 단순히 연산자 몇 개를 외우는 시간이 아니라,  
**숫자를 컴퓨터가 바라보는 방식**을 이해하는 시간이었습니다.

특히 인상적인 부분은 세 가지였습니다.

### 1) 16진수는 사람이 2진수를 읽기 쉽게 바꿔주는 도구다
16진수는 단순히 또 다른 진법이 아니라,  
긴 비트열을 짧고 보기 좋게 바꾸는 실용적인 표현 방식이라는 점이 인상적입니다.

### 2) 비트연산은 실제 문제풀이 도구다
`&`, `|`, `^`, `<<` 는 문법처럼 보이지만,  
부분집합이나 상태 표현처럼 실제 문제풀이에 바로 연결됩니다.

### 3) 실수는 “당연히 정확하다”는 직관이 깨진다
정수와 달리 실수는 내부적으로 근사값일 수 있다는 점이 중요합니다.  
이건 알고리즘뿐 아니라, 프로그래밍 전반에서 굉장히 중요한 감각입니다.

### 더 공부해볼 만한 포인트
- 비트마스킹을 활용한 부분집합 / 조합 문제
- XOR 응용 문제
- IEEE 754 상세 구조
- 실수 오차 처리와 허용 오차 비교

## 6. 요약 정리

### 📌 핵심
- 10진수 → 다른 진수: **나누고 나머지를 역순으로 읽는다**
- 16진수 1자리 = 2진수 4자리
- 비트연산은 상태 표현과 문제풀이에 강력하다
- 음수는 2의 보수로 표현한다
- 실수는 근사값이라 오차가 생길 수 있다
- 부동소수점은 **부호 / 지수 / 가수** 구조를 사용한다

### 🧠 기억할 것
- `1 << n = 2^n`
- `i & (1 << n)` 은 n번째 비트 확인
- 2의 보수 = **비트 반전 + 1**
- 실수 비교는 `==` 를 조심해야 한다
