## 1. 들어가며

알고리즘을 처음 배울 때는 개별 기법을 따로 외우기 쉽다. 하지만 실제 문제를 풀다 보면 중요한 것은 이름을 기억하는 것이 아니라, **지금 이 문제를 어떤 방식으로 접근해야 하는지 판단하는 힘**이다.

이번 강의는 그 판단의 출발점이 되는 내용을 다룬다. 먼저 데이터를 일정한 기준으로 재배열하는 **정렬**을 배우고, 그중에서도 구조가 단순한 **버블 정렬**과 조건이 맞을 때 매우 빠른 **카운팅 정렬**을 살펴본다. 그다음에는 “가능한 경우를 전부 확인해 보자”는 관점의 **완전 검색**, 그리고 “매 순간 좋아 보이는 선택을 하자”는 관점의 **탐욕 알고리즘**으로 이어진다.

즉, 이번 내용은 단순히 알고리즘 몇 개를 소개하는 데서 끝나지 않는다. 문제를 만났을 때 **정렬이 필요한지, 전부 확인해야 하는지, 아니면 규칙을 세워 빠르게 선택할 수 있는지**를 구분하는 기본 틀을 만들어 준다.

## 2. 핵심 개념 정리

이번 강의의 흐름은 아래처럼 이해하면 자연스럽다.

1. **정렬**: 데이터를 다루기 쉽게 재배열하는 기본 작업
2. **버블 정렬**: 인접한 원소를 비교하며 큰 값을 뒤로 보내는 가장 직관적인 방식
3. **카운팅 정렬**: 값의 범위가 제한된 정수 데이터에서 개수를 세어 빠르게 정렬하는 방식
4. **완전 검색**: 가능한 모든 경우를 만들어 보고 정답을 확인하는 방식
5. **순열**: 완전 검색에서 자주 등장하는 대표적인 경우의 수 생성 방법
6. **탐욕 알고리즘**: 매 단계에서 가장 좋아 보이는 선택을 하며 해답을 만들어 가는 방식

여기서 중요한 점은, 이 개념들이 서로 완전히 분리되어 있지 않다는 것이다. 예를 들어 순열은 완전 검색을 구현할 때 자주 쓰이고, 정렬은 탐욕 알고리즘의 전처리로 자주 등장한다. 그래서 각각을 따로 암기하기보다, **문제 해결 흐름 속에서 어떤 역할을 맡는지**로 묶어 이해하는 편이 훨씬 오래 남는다.

## 3. 본문 정리

이 장에서는 각 개념을 따로 떼어 설명하지 않고, 왜 필요한지와 실제 코드 흐름까지 함께 묶어서 정리한다. 읽는 동안 개념과 구현이 자연스럽게 연결되도록 보는 것이 핵심이다.

### 3.1 정렬과 버블 정렬

정렬은 2개 이상의 자료를 어떤 기준값, 즉 **키(key)** 에 따라 오름차순 또는 내림차순으로 다시 배치하는 알고리즘이다.

왜 정렬이 중요할까? 정렬 자체가 목적일 때도 있지만, 많은 경우 정렬은 다음 작업을 쉽게 만들기 위한 준비 단계다. 예를 들어 가장 작은 값이나 가장 큰 값을 빨리 찾고 싶을 때, 중복을 확인하고 싶을 때, 혹은 특정 규칙으로 데이터를 비교하고 싶을 때 정렬된 상태는 문제를 훨씬 단순하게 만든다.

버블 정렬은 이런 정렬 알고리즘 가운데 가장 직관적인 방식이다. **서로 이웃한 두 원소를 비교해서, 순서가 잘못되어 있으면 자리를 바꾼다.** 이 과정을 한 번 끝까지 돌고 나면 가장 큰 값이 맨 뒤로 밀려난다. 마치 큰 값이 물 위로 떠오르듯 뒤로 이동한다고 해서 버블 정렬이라는 이름이 붙었다.

#### 버블 정렬의 동작 감각 잡기

예를 들어 `[5, 2, 4, 1]`을 오름차순으로 정렬한다고 해 보자.

- `5`와 `2`를 비교해서 바꾼다 → `[2, 5, 4, 1]`
- `5`와 `4`를 비교해서 바꾼다 → `[2, 4, 5, 1]`
- `5`와 `1`을 비교해서 바꾼다 → `[2, 4, 1, 5]`

이렇게 한 바퀴가 끝나면 가장 큰 값 `5`는 제자리를 찾는다. 다음 바퀴에서는 맨 끝을 제외한 앞부분만 다시 비교하면 된다.

#### 관련 코드

```python

def bubble_sort(a, N):
    # 뒤쪽부터 정렬 완료 구간이 하나씩 확정되므로,
    # i는 이번 패스에서 마지막으로 비교할 인덱스 범위를 의미한다.
    for i in range(N - 1, 0, -1):
        # 앞에서부터 인접한 원소를 비교한다.
        # j와 j + 1을 비교하므로 j는 i - 1까지만 가면 충분하다.
        for j in range(i):
            # 앞의 값이 더 크면 오름차순 조건에 맞지 않으므로 자리를 바꾼다.
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
```

#### 코드 흐름 해설

이 코드에서 바깥 반복문은 “몇 번째 자리까지 정렬이 끝났는가”를 관리한다. 한 번 순회가 끝날 때마다 가장 큰 값 하나가 뒤로 이동하므로, 다음 순회에서는 비교 범위를 하나 줄일 수 있다.

안쪽 반복문은 실제 비교와 교환을 담당한다. 여기서 중요한 점은 **멀리 떨어진 원소를 직접 바꾸는 것이 아니라, 인접한 원소끼리만 비교한다는 점**이다. 그래서 버블 정렬은 구현은 간단하지만, 비교 횟수가 많아지기 쉽다.

#### 자주 하는 실수 / 디버깅 포인트

- ⚠️ `for j in range(i + 1)`처럼 범위를 잘못 잡으면 `a[j + 1]`에서 인덱스 에러가 날 수 있다.
- ⚠️ `N`을 배열 길이와 다르게 넘기면 일부 원소만 정렬되거나 에러가 발생한다.
- ⚠️ 버블 정렬은 구조가 단순해서 “빠르다”고 착각하기 쉽지만, 시간 복잡도는 **O(n²)** 이다. 데이터가 커지면 급격히 느려진다.

📌 핵심: 버블 정렬은 **인접 비교와 교환을 반복해 큰 값을 뒤로 보내는 가장 직관적인 정렬**이며, 구조를 이해하는 데는 좋지만 큰 입력에는 비효율적이다.

### 3.2 카운팅 정렬

카운팅 정렬은 값들의 상대적인 크기를 직접 비교하는 대신, **각 값이 몇 번 등장했는지 세어서 정렬 결과를 만드는 방식**이다.

이 방식이 강력한 이유는 비교 기반 정렬처럼 원소끼리 계속 비교하지 않아도 되기 때문이다. 데이터가 **0 이상 k 이하의 정수**처럼 제한된 범위를 가질 때, 각 값의 출현 횟수를 기록한 뒤 누적합을 이용하면 매우 빠르게 정렬할 수 있다.

쉽게 말하면, 카운팅 정렬은 “값을 줄 세우는” 정렬이라기보다 “각 값이 몇 명씩 있는지 먼저 세고, 그 정보를 바탕으로 자리를 배정하는” 정렬에 가깝다.

#### 왜 제한 사항이 필요한가

카운팅 정렬은 매우 빠르지만 아무 데이터에나 쓸 수는 없다.

- 정수여야 한다.
- 값의 최댓값 `k`를 알아야 한다.
- `k`가 너무 크면 카운트 배열이 커져서 비효율적일 수 있다.

즉, **데이터 개수 `n`이 아니라 값의 범위 `k`가 성능에 직접 영향을 준다**는 점이 핵심이다.

#### 관련 코드

```python

def counting_sort(DATA, TEMP, k):
    # COUNTS[i]는 값 i가 몇 번 나왔는지를 저장하는 배열이다.
    COUNTS = [0] * (k + 1)

    # 1단계: 각 숫자의 등장 횟수를 센다.
    for i in range(len(DATA)):
        COUNTS[DATA[i]] += 1

    # 2단계: 누적합으로 바꿔서,
    # 값 i가 정렬 결과에서 어디까지 차지하는지 계산한다.
    for i in range(1, k + 1):
        COUNTS[i] += COUNTS[i - 1]

    # 3단계: 뒤에서부터 순회하면서 TEMP에 값을 배치한다.
    # 뒤에서부터 넣는 이유는 같은 값의 상대적 순서를 유지하기 위해서다.
    for i in range(len(DATA) - 1, -1, -1):
        COUNTS[DATA[i]] -= 1
        TEMP[COUNTS[DATA[i]]] = DATA[i]
```

#### 코드 흐름 해설

이 코드는 세 단계로 이해하면 된다.

첫 번째 단계에서는 각 숫자가 몇 번 등장했는지 센다. 예를 들어 `DATA = [4, 2, 4, 3]`이라면, `COUNTS[4]`는 2가 된다.

두 번째 단계에서는 단순 개수를 누적합으로 바꾼다. 이 누적합은 “값 `i`가 정렬 결과에서 몇 번째 위치까지 들어가는가”를 알려준다. 여기서 카운트 배열은 단순 빈도표가 아니라, **최종 위치를 계산하는 기준표**로 바뀐다.

세 번째 단계가 가장 중요하다. 원본 배열을 뒤에서부터 보면서 각 값을 TEMP의 올바른 위치에 넣는다. 이때 뒤에서부터 넣어야 같은 값이 여러 개 있을 때 원래의 앞뒤 순서가 유지된다. 이 성질을 **안정성(stability)** 이라고 한다.

#### 자주 하는 실수 / 디버깅 포인트

- ⚠️ `k`를 최댓값보다 작게 잡으면 카운트 배열 범위를 벗어난다.
- ⚠️ 누적합 단계와 단순 개수 단계를 혼동하면 값의 위치 계산이 틀어진다.
- ⚠️ 마지막 배치 단계에서 앞에서부터 순회하면 같은 값의 상대적 순서가 바뀔 수 있다.
- ⚠️ 시간 복잡도 **O(n + k)** 는 빠르게 보이지만, `k`가 지나치게 크면 실제로는 비효율적일 수 있다.

📌 핵심: 카운팅 정렬은 **정수 범위가 작고 최댓값을 알 수 있을 때 매우 효율적**이며, 누적합과 역방향 배치를 통해 정렬 위치를 계산한다.

### 3.3 완전 검색과 순열

완전 검색(Exhaustive Search)은 **가능한 모든 경우의 수를 만들어 보고, 그중에서 답이 되는 것을 찾는 방식**이다.

이 방법은 느릴 수 있다. 하지만 처음 접근할 때는 매우 강력하다. 왜냐하면 모든 경우를 확인하므로, 조건만 정확하게 구현했다면 정답을 놓칠 가능성이 작기 때문이다. 특히 자격시험이나 코딩테스트 초반 사고 과정에서는, 먼저 완전 검색으로 문제 구조를 잡고 그다음 성능 개선 여부를 판단하는 접근이 안정적이다.

여기서 자주 연결되는 개념이 **순열**이다. 순열은 서로 다른 것들 중 일부 또는 전부를 뽑아 순서를 고려해 나열하는 방법이다.

- 서로 다른 `n`개 중 `r`개를 택해 나열하는 경우의 수: `nPr`
- 전부를 나열하는 경우: `nPn = n!`

이 식을 외우는 것도 필요하지만, 더 중요한 것은 **순열이 완전 검색에서 “모든 배치 경우를 만들어 보는 도구”로 자주 쓰인다는 점**이다.

#### 단순한 순열 생성 예시

강의에서는 `{1, 2, 3}`의 모든 순열을 반복문으로 생성하는 예시가 나온다.

```python

for i1 in range(1, 4):
    # 첫 번째 자리에 들어갈 수를 고른다.
    for i2 in range(1, 4):
        # 두 번째 자리는 첫 번째 자리와 같으면 안 된다.
        if i2 != i1:
            for i3 in range(1, 4):
                # 세 번째 자리도 앞에서 이미 사용한 값과 달라야 한다.
                if i3 != i1 and i3 != i2:
                    print(i1, i2, i3)
```

#### 코드 흐름 해설

이 코드는 각 자리를 하나씩 채워 넣는 방식으로 순열을 만든다. 핵심은 “같은 숫자를 두 번 쓰지 않도록 검사한다”는 점이다. 즉, **값을 고르는 것보다 중복을 막는 조건이 순열 생성의 본질**이라고 볼 수 있다.

다만 이 방식은 자리 수가 늘어나면 반복문도 계속 늘어나므로 일반화가 어렵다. 그래서 실제 문제풀이에서는 재귀, 백트래킹, `visited` 배열 같은 방식으로 확장하는 경우가 많다. 그럼에도 이 예시는 순열의 구조를 처음 이해하기에는 매우 좋다. 각 자리를 채우는 방식과 중복 제거의 의미가 눈에 바로 보이기 때문이다.

#### 자주 하는 실수 / 디버깅 포인트

- ⚠️ 순열과 조합을 혼동하기 쉽다. 순열은 **순서가 중요**하지만, 조합은 순서를 보지 않는다.
- ⚠️ 중복 검사 조건을 빠뜨리면 같은 수가 여러 자리에서 반복되어 잘못된 결과가 나온다.
- ⚠️ 완전 검색은 정답을 보장하는 대신 경우의 수가 빠르게 커진다. 그래서 입력 크기를 항상 함께 확인해야 한다.

📌 핵심: 완전 검색은 **정답을 빠짐없이 확인하는 가장 안전한 출발점**이고, 순열은 그 과정에서 자주 쓰이는 대표적인 경우의 수 생성 방법이다.

### 3.4 탐욕 알고리즘

탐욕 알고리즘(Greedy)은 매 순간 여러 선택지 중에서 **지금 당장 가장 좋아 보이는 선택**을 하는 방식으로 해답을 만들어 간다.

이 방법은 매우 매력적이다. 구현이 단순하고 빠른 경우가 많기 때문이다. 하지만 여기서 가장 조심해야 할 점은, **각 단계의 최선이 전체의 최선이라는 보장이 없다는 것**이다. 즉, 지역적으로는 좋아 보여도 전역적으로는 틀릴 수 있다.

강의에서 제시한 탐욕 알고리즘의 흐름은 보통 다음 세 단계로 정리된다.

1. **해 선택**: 현재 상태에서 가장 좋아 보이는 부분 해를 고른다.
2. **실행 가능성 검사**: 그 선택이 문제의 제약 조건을 깨지 않는지 확인한다.
3. **해 검사**: 전체 해가 완성되었는지 확인하고, 아니면 다시 반복한다.

이 구조를 보면 탐욕 알고리즘은 단순히 “대충 좋아 보이는 걸 고르는 법”이 아니라, **선택 → 제약 확인 → 종료 판단**의 절차를 갖는 알고리즘이라는 점을 알 수 있다.

#### 왜 헷갈리기 쉬운가

많은 초보자가 떠오르는 아이디어를 바로 구현하고, 그 결과가 맞으면 그것을 탐욕 알고리즘이라고 생각한다. 하지만 진짜 핵심은 그 선택이 왜 항상 맞는지 설명할 수 있어야 한다는 데 있다. 즉, 탐욕 알고리즘은 구현보다 **선택의 정당화**가 더 중요하다.

#### 자주 하는 실수 / 디버깅 포인트

- ⚠️ “그 순간 좋아 보인다”와 “항상 최적이다”를 같은 말로 착각하기 쉽다.
- ⚠️ 정렬과 함께 쓰는 경우가 많기 때문에, 어떤 기준으로 먼저 정렬해야 하는지 잘못 잡으면 전체 결과가 틀어진다.
- ⚠️ 탐욕이 가능한 문제인지 검토하지 않고 바로 구현하면 반례가 쉽게 나온다.

📌 핵심: 탐욕 알고리즘은 **매 단계의 선택을 빠르게 이어 가는 방식**이지만, 그 선택이 전체 최적해로 이어진다는 근거가 있어야만 올바른 접근이 된다.

## 4. 적용 관점에서 다시 보기

이 장에서는 앞에서 다룬 내용을 실제 문제풀이 관점으로 다시 묶어 본다. 새로운 개념을 추가하기보다, 어떤 문제를 만나면 어떤 신호를 보고 접근할지 정리하는 것이 목적이다.

### 어떤 상황에서 무엇을 떠올릴까

- **버블 정렬**: 정렬 원리를 처음 설명해야 하거나, 인접 비교와 교환 흐름을 눈으로 확인하고 싶을 때 떠올리면 좋다.
- **카운팅 정렬**: 데이터가 정수이고 값의 범위가 작을 때, 비교 정렬보다 빠른 방법이 필요하다면 먼저 후보에 올릴 수 있다.
- **완전 검색**: 입력 크기가 작고, 정답을 놓치지 않는 것이 중요할 때 가장 먼저 떠올릴 수 있는 안전한 접근이다.
- **순열**: “서로 다른 배치를 모두 만들어 보라”는 신호가 보이면 완전 검색과 함께 연결해서 생각하면 된다.
- **탐욕 알고리즘**: 매 단계에서 기준이 분명하고, 그 선택이 이후에도 유효하다는 논리를 세울 수 있을 때 사용한다.

### 구현 순서를 어떻게 잡으면 좋은가

1. 문제를 보고 먼저 **전부 확인해야 하는지** 생각한다.
2. 전부 확인하기엔 너무 크다면, **정렬이나 규칙 기반 선택으로 줄일 수 있는지** 본다.
3. 정렬이 필요하다면 데이터의 형태를 확인한다.
   - 일반 비교가 필요한가?
   - 값의 범위가 작아 카운팅 정렬이 가능한가?
4. 탐욕으로 보인다면, 선택 기준이 항상 맞는지 반례를 떠올려 본다.

### 실전에서 자주 틀리는 패턴

- 완전 검색이 필요한데도 성급하게 탐욕으로 접근한다.
- 카운팅 정렬이 가능한 데이터인데도 무조건 비교 정렬만 사용한다.
- 탐욕 문제에서 “지금 최선”의 기준을 증명하지 못한 채 구현부터 시작한다.
- 순열 문제에서 중복 제거 조건을 누락해 잘못된 경우까지 세어 버린다.

🧠 기억할 것: 문제를 푸는 힘은 알고리즘 이름을 많이 아는 데서 오기보다, **입력의 크기와 데이터의 성질, 그리고 정답 보장 방식**을 함께 보는 데서 나온다.

## 5. 배운 점 / 느낀 점 / 확장 포인트

이번 강의의 핵심은 알고리즘 몇 개를 각각 배우는 데 있지 않다. 오히려 서로 다른 문제 해결 관점을 비교해 보는 데 의미가 있다. 정렬은 데이터를 정리하는 기술이고, 완전 검색은 빠짐없이 확인하는 기술이며, 탐욕 알고리즘은 선택을 누적해 가는 기술이다. 같은 문제라도 어떤 관점을 택하느냐에 따라 풀이 구조가 완전히 달라질 수 있다.

이후 학습에서는 선택 정렬, 삽입 정렬, 병합 정렬, 퀵 정렬처럼 정렬 알고리즘을 더 넓게 비교해 볼 수 있다. 또 완전 검색은 백트래킹으로, 탐욕 알고리즘은 활동 선택 문제나 최소 비용 문제로 확장된다. 이번 강의는 그런 확장의 출발점 역할을 한다.

## 6. 요약 정리

- 📌 정렬은 데이터를 일정한 기준에 따라 다시 배치하는 기본 작업이다.
- 📌 버블 정렬은 인접 원소를 비교·교환하며 큰 값을 뒤로 보내는 직관적인 정렬이다.
- 📌 카운팅 정렬은 정수 범위가 제한될 때 개수를 세어 빠르게 정렬하는 방식이다.
- 📌 완전 검색은 가능한 모든 경우를 확인하는 안전한 접근이다.
- 📌 순열은 완전 검색에서 자주 쓰이는 대표적인 경우의 수 생성 방식이다.
- 📌 탐욕 알고리즘은 매 순간 최선처럼 보이는 선택을 하지만, 그 선택이 전체 최적해로 이어진다는 근거가 필요하다.

🧠 기억할 것:
정렬, 완전 검색, 탐욕 알고리즘은 서로 경쟁하는 개념이 아니라, **문제를 어떤 시선으로 볼지 결정하는 서로 다른 도구**다.
