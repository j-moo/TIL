## 1. 들어가며

그래프를 공부하다 보면 비슷해 보이는데 실제로는 완전히 다른 질문을 자주 만나게 된다.

하나는 **모든 정점을 가장 적은 비용으로 연결하고 싶은가**이고, 다른 하나는 **시작점에서 각 정점까지 가장 짧은 경로를 알고 싶은가**이다. 둘 다 간선의 가중치를 다루고, 둘 다 “가장 작은 값”을 고른다는 점에서 헷갈리기 쉽다. 하지만 이 둘은 목표가 다르기 때문에 알고리즘도 달라진다.

이번 강의는 바로 이 지점을 분명하게 나눠 준다. 먼저 그래프를 인접 행렬과 인접 리스트로 표현하는 방법을 정리한 뒤, 전체 연결 비용을 최소화하는 **최소 신장 트리(MST)** 를 Prim과 Kruskal로 살펴보고, 마지막으로 시작 정점 기준 최단 경로를 구하는 **Dijkstra 알고리즘** 으로 넘어간다.

읽는 흐름은 아래처럼 잡으면 이해가 편하다.

1. 그래프를 컴퓨터 안에 어떻게 저장할까  
2. 전체를 최소 비용으로 연결하려면 무엇을 골라야 할까  
3. 한 출발점에서 각 정점까지의 최소 비용은 어떻게 갱신할까

## 2. 핵심 개념 정리

이번 강의의 핵심은 그래프 문제를 두 부류로 나누는 데 있다.

### 2-1. 그래프 표현이 먼저 필요한 이유

그래프 알고리즘은 결국 “어떤 정점에서 어디로 갈 수 있는가”를 반복해서 확인하는 과정이다.  
그래서 알고리즘보다 먼저, 그래프를 **인접 행렬**로 저장할지 **인접 리스트**로 저장할지를 결정해야 한다.

![](<../assets/images/04_07_graph_2/스크린샷 2026-04-26 152915.png>)

왼쪽은 가중치 인접 행렬이고, 오른쪽은 가중치 인접 리스트이다.  
인접 행렬은 두 정점 사이의 연결 여부를 바로 확인하기 쉽고, 인접 리스트는 실제로 연결된 간선만 저장하므로 메모리를 아끼고 인접 정점 순회가 편하다.

### 2-2. 최소 신장 트리(MST)

최소 신장 트리는 **그래프의 모든 정점을 사이클 없이 연결하면서, 전체 간선 가중치 합이 최소가 되도록 만든 트리**이다.

여기서 중요한 점은, MST는 “출발점에서 어디까지의 최단 거리”를 구하는 문제가 아니라는 점이다.  
관심사는 각 정점까지의 개별 거리보다도, **그래프 전체를 가장 싸게 연결하는 구조**를 만드는 데 있다.

이를 푸는 대표 알고리즘이 바로 **Prim** 과 **Kruskal** 이다.

### 2-3. 최단 경로

반면 Dijkstra는 **하나의 시작 정점에서 다른 정점들까지의 최소 비용**을 구하는 알고리즘이다.

즉, MST가 “전체 연결 비용 최소화”라면, Dijkstra는 “출발점 기준 거리 최소화”이다.  
둘 다 greedy하게 작은 값을 고르지만, 무엇을 기준으로 고르는지가 다르다.

### 2-4. 한 번에 구분하기

| 구분 | Prim | Kruskal | Dijkstra |
|---|---|---|---|
| 해결 문제 | MST | MST | 단일 시작점 최단 경로 |
| 선택 기준 | 현재 트리와 연결되는 최소 간선 | 전체 간선 중 가장 작은 간선 | 현재까지 거리값이 가장 작은 정점 |
| 사이클 처리 | 방문 여부로 간접 관리 | Union-Find로 직접 판별 | 사이클이 핵심이 아님 |
| 결과 | 최소 신장 트리 | 최소 신장 트리 | 시작점 기준 최단 거리 배열 |

이 구분이 머릿속에서 선명해지면, 이후 그래프 문제를 볼 때도 어떤 알고리즘을 떠올려야 할지가 훨씬 빨라진다.

### 3.1 그래프 표현: 인접 행렬과 인접 리스트

그래프를 구현할 때 가장 먼저 마주치는 선택은 **표처럼 저장할지, 연결 목록처럼 저장할지**이다.

![](<../assets/images/04_07_graph_2/스크린샷 2026-04-26 152915.png>)

인접 행렬은 `A[u][v]`처럼 접근할 수 있어서 두 정점의 연결 여부를 빠르게 확인하기 좋다.  
반대로 인접 리스트는 `u`와 실제로 연결된 정점만 저장하므로, 간선 수가 적은 그래프에서 훨씬 효율적이다.

쉽게 말하면,

- 인접 행렬은 “전체 노선도를 표로 펴놓는 방식”
- 인접 리스트는 “각 정점마다 실제 연결된 도착지만 적어두는 방식”

에 가깝다.

특히 Prim과 Dijkstra처럼 “현재 정점과 연결된 이웃들을 순회”하는 일이 많아지면, 인접 리스트가 자연스럽게 자주 쓰인다.

⚠️ 주의  
그래프 문제를 풀다가 시간 초과가 나는 경우, 알고리즘 자체보다도 **표현 방식 선택**이 원인인 경우가 많다.  
정점 수가 큰데 인접 행렬을 쓰면 필요 이상으로 많은 칸을 매번 확인하게 된다.

📌 핵심

### 3.2 Prim 알고리즘: 트리를 한 정점씩 키워 가는 방식

Prim은 **하나의 시작 정점에서 출발해, 현재 만들어진 트리에 가장 싸게 연결되는 정점을 계속 붙여 나가는 알고리즘**이다.

즉, 처음에는 아주 작은 트리 하나에서 시작하고, 거기에 정점을 하나씩 추가하며 MST를 키워 간다.

#### 왜 필요한가

MST를 만들 때 모든 간선을 한꺼번에 보지 않고도,  
“지금까지 선택한 정점 집합과 연결되는 최소 간선”만 잘 고르면 전체 최소 비용 트리를 만들 수 있다.

이 아이디어는 “지금 트리 바깥에 있는 정점 중, 가장 저렴하게 붙일 수 있는 정점은 누구인가”를 계속 묻는 방식이라고 보면 된다.

#### Prim 의사코드

![](<../assets/images/04_07_graph_2/스크린샷 2026-04-26 153721.png>)

여기서 `key`는 단순한 숫자가 아니라,  
**현재 트리에 포함된 정점들과 연결될 때 필요한 최소 간선 비용**을 뜻한다.  
또 `π(pi)`는 트리에서 부모 정점을 의미한다.

#### 예시 흐름

아래 이미지는 Prim이 어떻게 트리를 확장하는지 단계별로 보여준다.

![](<../assets/images/04_07_graph_2/스크린샷 2026-04-26 153408.png>)

![](<../assets/images/04_07_graph_2/스크린샷 2026-04-26 153429.png>)

이 예시에서는 시작 정점 0에서 출발해, 현재 트리와 가장 싸게 연결되는 정점을 차례대로 붙인다.  
마지막 표를 보면 각 정점의 부모(`st`)와 연결 비용(`val`)이 정리되어 있고, 이 정보가 곧 MST 구조를 만든다.

쉽게 말하면, Prim은 **“지금 내 손에 들고 있는 트리에서 가장 싸게 뻗어 나갈 수 있는 간선”** 을 반복해서 선택한다.

#### 관련 코드

강의에 포함된 `prim.py`는 설명용 주석과 실행 코드가 섞여 있어 바로 실행하기엔 다듬을 부분이 있었다.  
아래는 같은 흐름을 유지하면서, 학습용으로 읽기 쉽게 정리한 Prim 코드이다.

```python
from heapq import heappop, heappush

# V: 정점 수, E: 간선 수
V, E = map(int, input().split())

# 인접 리스트 생성
graph = [[] for _ in range(V)]

for _ in range(E):
    # 무방향 가중치 그래프
    s, e, w = map(int, input().split())
    graph[s].append((e, w))
    graph[e].append((s, w))


def prim(start):
    # (간선 가중치, 정점 번호)를 넣는 최소 힙
    heap = [(0, start)]

    # MST 포함 여부
    in_mst = [False] * V

    # 누적 최소 비용
    min_weight = 0

    # 현재까지 MST에 포함된 정점 수
    picked = 0

    while heap and picked < V:
        # 지금 당장 가장 저렴하게 선택 가능한 정점
        w, v = heappop(heap)

        # 이미 MST에 들어간 정점이면 건너뛴다.
        if in_mst[v]:
            continue

        # v를 MST에 포함
        in_mst[v] = True
        min_weight += w
        picked += 1

        # 새로 포함된 정점 v에서 갈 수 있는 후보 간선을 힙에 추가
        for nv, nw in graph[v]:
            # 아직 MST에 없는 정점만 후보로 본다.
            if not in_mst[nv]:
                heappush(heap, (nw, nv))

    return min_weight


print(prim(0))
```

#### 코드 흐름 해설

이 코드에서 핵심은 힙에 “정점”을 넣는 것이 아니라,  
**현재 트리에서 그 정점으로 연결되는 후보 간선 비용**을 넣는다는 점이다.

흐름은 다음과 같다.

1. 시작 정점을 비용 0으로 힙에 넣는다.  
2. 힙에서 가장 작은 비용을 꺼낸다.  
3. 아직 MST에 포함되지 않았다면, 그 정점을 MST에 추가한다.  
4. 그 정점에서 갈 수 있는 이웃 간선을 다시 힙에 넣는다.  
5. 모든 정점을 선택할 때까지 반복한다.

이렇게 하면 언제나 “현재 트리와 연결되는 최소 간선”이 먼저 선택된다.

#### 자주 하는 실수 / 디버깅 포인트

- `heap = [(가중치, 정점번호)]`처럼 설명용 문장을 그대로 코드에 남겨 두면 실행이 되지 않는다.
- 방문 처리 없이 힙에만 의존하면 같은 정점이 여러 번 선택될 수 있다.
- Prim은 **정점 기준으로 MST를 키우는 방식**이지, 전체 간선을 정렬해 차례대로 보는 방식이 아니다. 이 점에서 Kruskal과 자주 섞인다.

📌 핵심  
Prim은 **현재까지 만든 트리에 가장 싸게 연결되는 정점**을 하나씩 추가하며 MST를 완성한다.

### 3.3 Kruskal 알고리즘: 간선을 가중치 순으로 고르는 방식

Kruskal은 Prim과 같은 MST 알고리즘이지만, 접근 방식은 꽤 다르다.

Prim이 “트리를 키워 나가는” 느낌이라면,  
Kruskal은 **전체 간선을 가중치 오름차순으로 정렬한 뒤, 사이클이 생기지 않는 간선만 골라 붙이는 방식**이다.

#### 왜 필요한가

그래프 전체를 가장 싸게 연결하려면, 직관적으로는 작은 간선부터 쓰고 싶어진다.  
다만 작은 간선이라고 해서 무조건 다 쓰면 사이클이 생길 수 있다.  
그래서 Kruskal에서는 **이 간선을 넣어도 사이클이 생기지 않는가**를 판단하는 장치가 필요하고, 그 역할을 하는 것이 **서로소 집합(Union-Find)** 이다.

#### Kruskal 의사코드

![](<../assets/images/04_07_graph_2/스크린샷 2026-04-26 154226.png>)

핵심 흐름은 단순하다.

1. 모든 정점을 서로 다른 집합으로 시작한다.  
2. 간선을 가중치 오름차순으로 정렬한다.  
3. 가장 작은 간선부터 보면서, 두 정점의 대표가 다르면 채택한다.  
4. 채택했다면 두 집합을 union 한다.  
5. 간선이 `N-1`개 선택되면 MST가 완성된다.

#### 예시 흐름

먼저 전체 그래프와 간선의 정렬 결과를 보면 아래와 같다.

![](<../assets/images/04_07_graph_2/스크린샷 2026-04-26 153925.png>)

이제 가장 작은 간선부터 하나씩 본다.

![](<../assets/images/04_07_graph_2/스크린샷 2026-04-26 153957.png>)

작은 간선을 고르는 방향은 맞지만, 중간부터는 “사이클이 생기는가”가 더 중요해진다.

![](<../assets/images/04_07_graph_2/스크린샷 2026-04-26 154117.png>)

위 단계에서는 `0-1`을 넣으면 이미 이어진 정점들끼리 다시 연결되어 사이클이 만들어지므로 건너뛴다.

![](<../assets/images/04_07_graph_2/스크린샷 2026-04-26 154142.png>)

마지막으로 `N=7`개의 정점을 연결하려면 `N-1=6`개의 간선을 선택하면 된다.  
이 종료 조건이 Kruskal의 매우 중요한 체크포인트다.

#### 관련 코드

강의에 있던 `kruskal.py`의 구조를 유지하면서, 읽기 좋은 학습용 형태로 정리하면 아래와 같다.

```python
# V: 정점 개수, E: 간선 개수
V, E = map(int, input().split())

# 모든 간선 저장
edges = []
for _ in range(E):
    s, e, w = map(int, input().split())
    edges.append((s, e, w))

# 가중치 기준 오름차순 정렬
edges.sort(key=lambda x: x[2])

# 서로소 집합의 부모 배열
parent = [i for i in range(V)]


def find_set(x):
    # 대표자라면 그대로 반환
    if parent[x] == x:
        return x

    # 경로 압축
    parent[x] = find_set(parent[x])
    return parent[x]


def union(x, y):
    rx = find_set(x)
    ry = find_set(y)

    # 이미 같은 집합이면 합칠 필요가 없다.
    if rx == ry:
        return False

    # 한쪽 대표를 다른 쪽에 연결
    parent[ry] = rx
    return True


picked = 0
min_weight = 0

for s, e, w in edges:
    # 사이클이 생기지 않을 때만 간선 채택
    if union(s, e):
        picked += 1
        min_weight += w

        # 정점이 V개면 MST 간선은 V-1개
        if picked == V - 1:
            break

print(min_weight)
```

#### 코드 흐름 해설

Kruskal에서 진짜 핵심은 정렬보다도 **사이클 판별**이다.

- `find_set(x)`는 정점 `x`가 속한 집합의 대표를 찾는다.
- 두 정점의 대표가 같다면 이미 연결된 상태이므로, 그 간선을 추가하면 사이클이 생긴다.
- 대표가 다르면 안전하게 간선을 추가할 수 있다.
- 간선 수가 `V-1`개가 되는 순간 MST는 완성된다.

즉, Kruskal은 “가장 작은 간선부터 보자”가 출발점이지만,  
실제로 정답을 보장하는 이유는 **Union-Find로 사이클을 걸러내기 때문**이다.

#### 자주 하는 실수 / 디버깅 포인트

- 간선을 정렬만 하고 사이클 판별 없이 더하면 MST가 아니라 그냥 작은 간선 묶음이 된다.
- `V-1`개 간선을 선택했으면 바로 종료해야 한다.
- `find_set`에서 경로 압축을 하지 않아도 정답은 맞을 수 있지만, 속도가 크게 느려질 수 있다.
- Prim처럼 “방문 배열”로만 처리하려고 하면 Kruskal의 핵심이 사라진다.

📌 핵심  
Kruskal은 **가중치가 작은 간선부터 보되, Union-Find로 사이클을 막으면서 `V-1`개를 고르는 MST 알고리즘**이다.

---

### 3.4 Prim과 Kruskal을 함께 비교해 보기

두 알고리즘은 둘 다 MST를 만든다.  
하지만 문제를 바라보는 시선이 다르다.

- Prim은 **현재 트리 바깥 정점 중 누구를 가장 싸게 붙일까**에 집중한다.
- Kruskal은 **전체 간선 중 지금 가장 작은 간선을 써도 될까**에 집중한다.

그래서 구현에서도 차이가 난다.

- Prim: 인접 리스트 + 최소 힙 + 방문 여부
- Kruskal: 간선 리스트 + 정렬 + Union-Find

💡 포인트  
문제에서 간선 목록이 그대로 주어지고, “사이클 없이 최소 비용 연결”이 강조되면 Kruskal이 더 자연스럽게 떠오를 수 있다.  
반대로 시작 정점에서 확장해 가는 그림이 잘 보이거나, 인접 정점 순회가 핵심이면 Prim이 더 직관적일 수 있다.

⚠️ 주의  
둘 다 MST를 만든다는 공통점 때문에, Dijkstra와 섞이는 것보다 오히려 **Prim과 Kruskal끼리 구현 감각이 뒤섞이는 경우**가 많다.  
Prim은 정점 중심, Kruskal은 간선 중심이라는 구도를 분명히 잡고 가는 것이 좋다.

📌 핵심  
Prim과 Kruskal의 차이는 정답이 아니라 **선택의 기준과 구현의 중심축**에 있다.

---

### 3.5 Dijkstra 알고리즘: 시작점에서 각 정점까지의 최단 거리

Dijkstra는 **하나의 시작 정점에서 출발해, 다른 모든 정점까지의 최소 비용**을 구하는 알고리즘이다.

여기서 중요한 점은, Dijkstra는 MST를 만드는 알고리즘이 아니라는 것이다.  
즉, 그래프 전체를 최소 비용으로 연결하는 것이 목표가 아니라, **시작점에서의 거리 정보**를 정확히 계산하는 것이 목적이다.

#### 왜 필요한가

실전 문제에서는 “A에서 B까지 가장 싸게 가는 법”, “출발 도시에서 각 도시까지의 최소 이동 비용” 같은 질문이 자주 나온다.  
이런 문제는 “전체 연결 비용”이 아니라 **출발점 기준 누적 거리**가 핵심이다.

#### 예시 그래프

![](<../assets/images/04_07_graph_2/스크린샷 2026-04-26 154951.png>)

위 그래프에서 시작 정점을 `a`로 두고, 각 정점까지의 최단 거리를 구한다고 생각해 보자.

#### Dijkstra 의사코드

![](<../assets/images/04_07_graph_2/스크린샷 2026-04-26 155028.png>)

여기서 `D[v]`는 시작점에서 정점 `v`까지 알고 있는 현재 최단 거리이고,  
`U`는 이미 최단 거리가 확정된 정점 집합이다.

#### 단계별 적용 예시

강의 자료는 Dijkstra를 단계별로 아주 자세하게 보여 준다.

![](<../assets/images/04_07_graph_2/스크린샷 2026-04-26 155821.png>)

처음에는 시작점 `a`에서 갈 수 있는 정점들의 거리만 채운다.

- `D[a] = 0`
- `D[b] = 2`
- `D[c] = 4`

그 다음에는 아직 확정되지 않은 정점 중 `D`값이 가장 작은 정점을 고른다.  
예를 들어 `b`를 고르면, `b -> c` 비용 1 때문에 `c`의 거리는 `4`에서 `3`으로 줄어든다.  
이 지점이 Dijkstra의 핵심이다. **더 좋은 경로가 발견되면 거리값을 갱신한다.**

마지막에는 다음과 같은 거리 배열을 얻게 된다.

![](<../assets/images/04_07_graph_2/스크린샷 2026-04-26 160007.png>)

최종 결과는 다음과 같이 읽을 수 있다.

- `a -> a = 0`
- `a -> b = 2`
- `a -> c = 3`
- `a -> d = 9`
- `a -> e = 6`
- `a -> f = 10`

즉, Dijkstra는 “지금까지 알려진 최단 거리 중 가장 작은 정점”을 하나 확정하고,  
그 정점을 거쳐 갈 때 더 짧아지는 경로가 있는지 계속 확인하는 방식이다.

#### 학습용 코드 예시

강의 파일에는 Dijkstra의 파이썬 소스가 따로 포함되어 있지 않았으므로,  
의사코드 흐름을 그대로 옮긴 기본 형태를 함께 정리하면 아래와 같다.

```python
INF = float('inf')

# 정점 개수
V = 6

# 인접 행렬 예시
# 연결이 없으면 INF
A = [
    [0, 2, 4, INF, INF, INF],
    [INF, 0, 1, 7, INF, INF],
    [INF, INF, 0, INF, 3, INF],
    [INF, INF, INF, 0, 2, 1],
    [INF, INF, INF, INF, 0, 5],
    [INF, INF, INF, INF, INF, 0],
]


def dijkstra(start):
    # 거리 배열 초기화
    dist = A[start][:]

    # 최단 거리가 확정된 정점 표시
    visited = [False] * V
    visited[start] = True
    dist[start] = 0

    # 시작 정점을 제외한 나머지 정점들에 대해 반복
    for _ in range(V - 1):
        min_value = INF
        min_idx = -1

        # 아직 확정되지 않은 정점 중 dist가 가장 작은 정점 선택
        for i in range(V):
            if not visited[i] and dist[i] < min_value:
                min_value = dist[i]
                min_idx = i

        if min_idx == -1:
            break

        # 선택한 정점의 최단 거리 확정
        visited[min_idx] = True

        # 그 정점을 거쳐 가는 더 짧은 경로가 있는지 갱신
        for v in range(V):
            if not visited[v] and A[min_idx][v] != INF:
                dist[v] = min(dist[v], dist[min_idx] + A[min_idx][v])

    return dist


print(dijkstra(0))
```

강의 자료 중 Djikstra알고리즘 구현
```python
"""
6 8
0 1 2
0 2 4
1 2 1
1 3 7
2 4 3
3 4 2
3 5 1
4 5 5
"""
# V : 정점의 개수, E : 간선의 개수
V, E = map(int, input().split())

# G : 인접 행렬
# G[a][b] = 2
# G[a][c] = 4

# G : 인접 리스트
# G[i] : i번 정점과 연결되어 있는 정점 번호, 간선의 가중치
# G[a] = [(b,2), (c,4)]
G = [[] for _ in range(V)]

for i in range(E):
    # s와 e를 잇는 간선의 가중치 w ( s -> e )
    s, e, w = map(int, input().split())
    G[s].append((e, w))

import heapq

INF = 1e9

# D : 최단 거리를 저장할 리스트
# D[i] : 시작정점에서 i정점까지 가는데 최단 거리(가중치 합)
D = [INF] * V


# start : 시작 정점 번호
# start 정점에서 시작해서 다른 모든 정점까지 가는데 최단거리를 구하는 함수
def dijkstra(start):
    # 가중치가 가장 작은 간선을 선택하는데 최소힙의 도움을..
    heap = []

    # 처음상태에서 시작정점 처리
    heapq.heappush(heap, (0, start))

    # 시작정점에서 시작정점까지의 최단거리는 0
    D[start] = 0

    # 힙에 간선 정보가 남아있으면 계속 반복
    while heap:
        # 다음에 도착가능한 정점중에 최단거리인 정점을 선택
        # heap 에서 하나 꺼내오기만 하면 된다!!
        # w : 최소 가중치, v : 정점 번호
        w, v = heapq.heappop(heap)

        # v 까지 가는 경로는 여러개가 있다. (heap 안에 v까지 가는 경로의 정보가 여러개)
        # 힙에서 꺼낼때 가장 먼저 튀어나오는 v까지의 간선 정보는 거리가 최소 인 정보
        # 나머지 v까지 가는데 걸리는 거리정보는 필요 없다(이미 최소를 먼저 꺼냈으므로)
        # 힙안에 남아있는 v까지 가는 다른 경로들은 이제 고려할 필요가 없다.
        if w > D[v]:
            continue


        # v 를 선택, v를 거쳐서 갈 수 있는 새로운 간선들이 생겼다.
        # 이 새로운길을 선택해서 이전에 계산했던 거리보다 더 작아질수 있는지 확인

        # v와 인접한 정점들을 조사
        # nv : v와 인접한 정점 번호, nw : 그때 가중치
        for nv, nw in G[v]:
            # v를 거쳐서 nv로 가는 새로운 길 발견!
            # 이 새로운 길을 사용하면 최단거리가 되는지??

            # w = s에서 v까지 최단 거리
            # nw = v 에서 nv 로 이어진 간선의 가중치
            new_distance = w + nw

            # 새로운 길로 가는 거리가 최단거리였다
            if new_distance < D[nv]:
                # 최단거리 갱신
                D[nv] = new_distance
                # 힙에 최단거리를 사용해서 nv까지 도착한 정보를 추가
                heapq.heappush(heap, (new_distance, nv))

dijkstra(0)
```

#### 코드 흐름 해설

Dijkstra는 “간선을 고른다”기보다,  
**정점의 최단 거리 확정 순서**를 관리하는 알고리즘이다.

1. 시작 정점의 거리를 0으로 둔다.  
2. 아직 확정되지 않은 정점 중 거리값이 가장 작은 정점을 고른다.  
3. 그 정점을 거쳐 갈 때 더 짧아지는 이웃 정점이 있으면 `dist`를 갱신한다.  
4. 모든 정점이 확정될 때까지 반복한다.

Prim도 최소값을 고른다는 점에서는 비슷해 보이지만,  
Prim의 값은 **트리에 붙는 간선 비용**이고, Dijkstra의 값은 **시작점으로부터의 누적 거리**라는 점이 결정적으로 다르다.

#### 자주 하는 실수 / 디버깅 포인트

- MST 문제에 Dijkstra를 쓰는 실수를 자주 한다.
- Dijkstra는 **음수 가중치가 없는 경우**에 사용한다는 전제가 있다.
- `dist[v] = min(dist[v], dist[w] + cost)` 갱신식에서 `dist[w]`가 아니라 간선 가중치만 비교하면 틀린다.
- Prim처럼 “현재 트리에 가장 싸게 연결되는 간선” 개념으로 보면 오해가 생긴다.

📌 핵심  
Dijkstra는 **시작점에서의 누적 최단 거리**를 기준으로 정점을 하나씩 확정해 나가는 알고리즘이다.

## 4. 적용 관점에서 다시 보기

이제 문제를 봤을 때 어떤 신호를 보고 어떤 알고리즘을 떠올려야 하는지 정리해 보자.

### 4-1. Prim / Kruskal을 떠올려야 하는 신호

다음 표현이 나오면 MST 가능성을 먼저 떠올리는 것이 좋다.

- 모든 지점을 연결
- 전체 연결 비용 최소
- 전선, 도로, 통신망, 다리 설치
- 사이클 없이 연결
- 간선 `N-1`개 선택

이때는 “어떤 한 점에서 어디까지 가장 빨리 가는가”가 아니라,  
**전체를 가장 저렴하게 묶는 구조**를 찾는 문제다.

### 4-2. Dijkstra를 떠올려야 하는 신호

아래 표현이 보이면 최단 경로 쪽으로 생각해야 한다.

- 시작점에서 각 정점까지
- A에서 B까지 최소 비용
- 최소 이동 시간, 최소 거리, 최소 운임
- 각 도시까지의 최단 거리
- 출발점 기준 누적 비용

이 경우는 그래프 전체 연결보다도 **특정 출발점 기준 거리 정보**가 중요하다.

### 4-3. 구현 순서를 잡는 법

#### MST 문제라면

1. 문제 목표가 “전체 연결”인지 확인  
2. Prim 또는 Kruskal 중 구현하기 쉬운 쪽 선택  
3. Prim이면 인접 리스트 + 힙  
4. Kruskal이면 간선 정렬 + Union-Find  
5. `V-1`개 간선을 선택했는지 확인

#### 최단 경로 문제라면

1. 문제 목표가 “시작점 기준 거리”인지 확인  
2. 음수 가중치가 없는지 확인  
3. 거리 배열 `dist` 초기화  
4. 가장 짧은 거리 정점을 선택  
5. 이웃 정점 거리 갱신 반복

### 4-4. 실전에서 자주 틀리는 패턴

- **MST와 최단 경로를 문제 문장만 보고 섞는 경우**
- Prim의 `key`와 Dijkstra의 `dist`를 같은 값처럼 생각하는 경우
- Kruskal에서 사이클 판별 없이 정렬만 믿고 가는 경우
- 종료 조건을 놓쳐 불필요하게 끝까지 순회하는 경우

🧠 기억할 것  
작은 값을 고른다고 해서 다 같은 greedy가 아니다.  
**무엇의 최소값을 고르는지**를 먼저 정확히 말할 수 있어야 한다.

## 5. 배운 점 / 느낀 점 / 확장 포인트

이번 강의에서 가장 중요한 학습 포인트는 그래프 알고리즘을 “이름”으로 구분하는 것이 아니라,  
**문제가 요구하는 목표**로 구분해야 한다는 점이다.

Prim과 Kruskal은 둘 다 MST를 구하지만, 하나는 정점 중심으로 트리를 키우고 다른 하나는 간선 중심으로 사이클을 피한다.  
Dijkstra는 아예 질문 자체가 다르다. 출발점에서 각 정점까지의 거리라는, 훨씬 더 경로 중심적인 정보를 관리한다.

이 구분은 이후 학습에도 그대로 이어진다.

- MST를 더 확장하면 네트워크 설계 문제로 이어지고
- 최단 경로를 더 확장하면 다익스트라, 플로이드-워셜, 벨만-포드 비교로 이어진다.
- Union-Find는 MST뿐 아니라 사이클 판별, 집합 관리 문제에서도 반복해서 등장한다.

즉, 이번 강의는 그래프의 세부 알고리즘 하나를 익히는 시간이기보다,  
**그래프 문제를 읽는 기준점을 세우는 시간**에 더 가깝다.

📌 핵심

- 인접 행렬은 연결 여부 확인이 쉽고, 인접 리스트는 실제 연결만 저장해 효율적이다.
- Prim은 현재 MST에 가장 싸게 붙일 수 있는 정점을 계속 추가한다.
- Kruskal은 간선을 가중치 순으로 보면서, 사이클이 생기지 않는 간선만 선택한다.
- Kruskal의 핵심 도구는 Union-Find이다.
- Dijkstra는 시작점에서 각 정점까지의 최단 거리를 구한다.
- MST와 최단 경로는 모두 가중치 그래프 문제지만, **문제의 목표가 다르다.**

🧠 기억할 것

- Prim: 트리 확장
- Kruskal: 간선 선택 + 사이클 방지
- Dijkstra: 시작점 기준 거리 갱신
