## 2. 핵심 개념 정리

### 2.1 백트래킹은 “모든 경우를 생성하되, 볼 필요 없는 가지는 미리 자르는 방법”이다

완전탐색은 보통 가능한 경우를 전부 본다.  
순열, 조합, 부분집합처럼 경우의 수가 폭발하기 쉬운 문제에서는 이 방식이 금방 느려진다.

이때 필요한 생각이 바로 **유망성 검사**다.

- 지금까지의 선택이 답이 될 가능성이 있으면 더 내려간다.
- 지금 상태에서 이미 답이 될 수 없으면 그 아래는 아예 보지 않는다.

이 “아래를 더 안 보는 것”이 바로 **가지치기(pruning)** 이다.

### 2.2 백트래킹은 DFS를 쓰지만, DFS와 완전히 같지는 않다

둘 다 깊게 들어갔다가 돌아오는 구조라는 점에서는 비슷하다.  
하지만 DFS는 기본적으로 **모든 경로를 끝까지 따라갈 수 있는 탐색**이고, 백트래킹은 **가능성이 사라진 순간 그 경로를 버리는 탐색**이다.

쉽게 말하면 이렇다.

- DFS: “일단 가 보자.”
- 백트래킹: “가도 되는지 먼저 보고, 아니면 여기서 그만두자.”

### 2.3 트리는 “계층 관계”를 표현하는 자료구조다

트리는 부모-자식 관계가 있는 구조다.  
사이클이 없고, 한 노드에서 다른 노드로 가는 경로가 유일하다는 점이 핵심이다.

백트래킹에서 말하는 상태 공간 트리도 결국 이 관점으로 이해할 수 있다.  
즉, 트리는 단지 자료구조 챕터에서만 나오는 개념이 아니라, **문제해결 과정을 시각화하는 틀**이기도 하다.

### 2.4 이진 트리, BST, 힙은 각각 “용도”가 다르다

이 셋은 이름이 비슷해서 헷갈리기 쉽지만, 강조점이 다르다.

- **이진 트리**: 한 노드가 자식을 최대 2개까지 가지는 기본 구조
- **이진탐색트리(BST)**: 탐색을 빠르게 하기 위한 정렬 규칙이 있는 트리
- **힙(Heap)**: 최댓값/최솟값을 빠르게 꺼내기 위한 완전 이진 트리 기반 구조

`📌 핵심`  
이번 강의는 개념이 여러 개 나오는 것처럼 보여도, 실제로는 **트리라는 공통된 틀 위에서 탐색과 자료구조를 함께 보는 시간**이라고 생각하면 정리가 훨씬 잘 된다.

## 3. 본문 정리

## 3.1 백트래킹은 “선택 → 검사 → 되돌아오기”의 반복이다

백트래킹은 여러 선택지 중 하나를 고르고, 그 선택이 괜찮은지 검사한 뒤,  
아니면 바로 되돌아오는 방식으로 동작한다.

강의에서는 이를 N-Queen 문제로 설명했다.  
N개의 퀸을 체스판에 놓되, 서로 공격하지 못하게 배치해야 한다.  
겉으로는 단순해 보여도 경우의 수가 빠르게 커진다.

예를 들어 4-Queens만 생각해도, 각 행마다 4개의 열 중 하나를 고른다고 보면 가능한 배치 수는 다음처럼 시작한다.

- 1행: 4가지
- 2행: 4가지
- 3행: 4가지
- 4행: 4가지

즉, 단순 계산으로는 `4 × 4 × 4 × 4 = 256` 가지를 보게 된다.  
하지만 실제로는 중간에 이미 충돌이 나는 경우가 아주 많다.  
그래서 **끝까지 내려가기 전에 잘라 내는 것**이 중요하다.

### 왜 백트래킹이 필요한가

여기서 중요한 점은 “답을 찾을 수 있는가”보다도,  
**답이 될 수 없는 경로를 얼마나 빨리 버릴 수 있는가**에 있다.

N-Queen에서는 보통 아래 세 가지만 검사해도 강한 가지치기가 가능하다.

1. 같은 열에 이미 퀸이 있는가
2. 왼쪽 위 대각선에 이미 퀸이 있는가
3. 오른쪽 위 대각선에 이미 퀸이 있는가

이 검사를 통과한 위치만 다음 선택으로 넘어가면 된다.

### 원본 코드

```python
def check(row, col):
    # 1. 같은 열에 놓은 적이 있는가?
    for i in range(row):
        if visited[i][col]:
            return True

    # 2. 좌상단 대각선에 놓은 적이 있는가?
    i, j = row - 1, col - 1
    while i >= 0 and j >= 0:
        if visited[i][j]:
            return True

        i -= 1
        j -= 1


    # 3. 우상단 대각선에 놓은 적이 있는가?
    i, j = row - 1, col + 1
    while i >= 0 and j < N:
        if visited[i][j]:
            return True

        i -= 1
        j += 1

    # [참고] 두 가지 변수를 동시에 반복 ---> zipㅇ 을 활용
    # for i, j in zip(range(row-1, - 1, -1)), range(col-1, -1, -1):
    #     if visited[i][j]:
    #         return True

    return False

# deqpth : 모든 행에 퀸을 놓았는가? (N개)
# branch : 모든 열에 퀸을 놓았는가? (N개)

def recur(row):
    global answer

    if row == N:
        answer += 1
        print(*path)
        return

    for col in range(N):
        # 유망하지 않는 경우는 못 보도록 continue
        # - 가지치기
        if check(row, col):
            continue

        visited[row][col] = 1
        path.append(col)
        recur(row + 1)
        path.pop()
        visited[row][col] = 0

N = 4
answer = 0
path = []
# N * N 모든 위치의 방문 여부를 기록
visited = [[0] * N for _ in range(N)]
recur(0)
print(f'경우의 수 = {answer}')
```

### 주석을 보강한 코드

아래 코드는 원본 구조를 유지하면서,  
코드를 한 줄씩 읽을 때 왜 이런 흐름이 되는지 바로 이해할 수 있도록 주석을 더 촘촘히 보강한 버전이다.

```python
def check(row, col):
    # row행, col열에 퀸을 새로 놓으려 할 때
    # 기존에 놓인 퀸과 충돌하는지 검사한다.
    # 충돌하면 True, 놓아도 되면 False를 반환한다.
    # 이름이 check라서 헷갈릴 수 있는데,
    # 여기서는 "가능한지"가 아니라 "충돌이 있는지"를 검사한다.

    # 1) 같은 열에 이미 퀸이 있는지 확인한다.
    # 현재 row보다 위쪽 행들만 보면 된다.
    # 백트래킹은 위에서 아래로 한 행씩 내려오기 때문이다.
    for i in range(row):
        if visited[i][col]:
            return True  # 같은 열 충돌

    # 2) 왼쪽 위 대각선을 따라 올라가며 충돌을 확인한다.
    i, j = row - 1, col - 1
    while i >= 0 and j >= 0:
        if visited[i][j]:
            return True  # 좌상향 대각선 충돌

        i -= 1
        j -= 1

    # 3) 오른쪽 위 대각선을 따라 올라가며 충돌을 확인한다.
    i, j = row - 1, col + 1
    while i >= 0 and j < N:
        if visited[i][j]:
            return True  # 우상향 대각선 충돌

        i -= 1
        j += 1

    # 세 방향 모두 충돌이 없으면 이 자리는 유망하다.
    return False


def recur(row):
    global answer

    # row == N 이라는 뜻은
    # 0번 행부터 N-1번 행까지 퀸을 전부 성공적으로 놓았다는 의미다.
    if row == N:
        answer += 1          # 가능한 배치 1개를 찾았다.
        print(*path)         # path에는 각 행에 놓은 열 번호가 담겨 있다.
        return

    # 현재 row행에서 놓을 수 있는 모든 col을 시도해 본다.
    for col in range(N):
        # 현재 칸이 충돌나는 자리라면
        # 그 아래 가지는 더 볼 필요가 없으므로 바로 건너뛴다.
        if check(row, col):
            continue

        # 1) 선택: 현재 위치에 퀸을 놓는다.
        visited[row][col] = 1
        path.append(col)

        # 2) 다음 행으로 내려간다.
        recur(row + 1)

        # 3) 되돌아오기: 방금 했던 선택을 취소한다.
        # 이 과정이 있어야 다른 열 선택을 다시 시도할 수 있다.
        path.pop()
        visited[row][col] = 0


N = 4
answer = 0
path = []                            # 각 행에서 선택한 열 번호를 저장
visited = [[0] * N for _ in range(N)]  # 체스판에 퀸을 놓은 위치 기록

recur(0)
print(f'경우의 수 = {answer}')
```

### 코드 흐름 해설

이 코드는 백트래킹의 전형적인 구조를 아주 잘 보여 준다.

1. `recur(row)`는 **현재 몇 번째 행을 처리 중인지**를 나타낸다.
2. 한 행에서 가능한 모든 열 `col`을 시도한다.
3. `check(row, col)`로 유망성을 검사한다.
4. 가능하면 퀸을 놓고 다음 행으로 내려간다.
5. 재귀가 끝나면 원래 상태로 되돌린다.

여기서 `visited`는 실제 체스판처럼 생각하면 된다.  
`path`는 조금 더 추상적인 기록이다. 예를 들어 `[1, 3, 0, 2]`라면,

- 0행 → 1열
- 1행 → 3열
- 2행 → 0열
- 3행 → 2열

에 퀸을 놓았다는 뜻이다.

### 자주 하는 실수 / 디버깅 포인트

⚠️ **`check()`의 반환 의미를 반대로 이해하기 쉬움**  
이 함수는 “가능하면 True”가 아니라, **충돌이 있으면 True**다.  
그래서 `if check(row, col): continue`가 자연스럽다.

⚠️ **되돌리기(backtracking)를 빼먹기 쉬움**  
`path.pop()`과 `visited[row][col] = 0`을 하지 않으면,  
다음 경우의 수를 탐색할 때 이전 선택이 남아 있어 결과가 완전히 틀어진다.

⚠️ **대각선 검사를 모든 방향으로 할 필요는 없음**  
현재 행보다 아래쪽은 아직 퀸을 놓지 않았으므로 볼 필요가 없다.  
위쪽만 검사해도 충분하다.

`📌 핵심`  
백트래킹은 재귀를 쓴다는 점보다, **유망하지 않은 후보를 미리 버린다**는 점이 핵심이다.

## 3.2 상태 공간 트리에서 트리 개념으로 넘어가면 전체 구조가 더 잘 보인다

백트래킹을 공부한 뒤 트리로 넘어가는 흐름은 자연스럽다.  
왜냐하면 백트래킹의 선택 과정 자체를 **트리**로 볼 수 있기 때문이다.

트리는 사이클이 없는 계층 구조다.  
루트에서 시작해 자식으로 뻗어 나가고, 자식이 없는 노드는 리프가 된다.

아래 그림은 강의에서 사용한 일반 트리 예시다.

![alt text](<스크린샷 2026-03-12 101834-1.png>)

이 그림을 기준으로 보면 용어들이 훨씬 잘 잡힌다.

- **루트 노드**: `A`
- **부모-자식 관계**: `A`는 `B, C, D`의 부모
- **리프 노드**: `E, G, H, I, J, K`처럼 자식이 없는 노드
- **형제 노드**: 같은 부모를 가지는 노드들 (`B, C, D` 등)
- **서브트리**: 어떤 노드를 루트로 하는 작은 트리

💡 **포인트**  
트리는 “모양”보다 **관계**를 보는 자료구조다.  
배열처럼 순서대로 줄 세우는 구조가 아니라, 누가 누구의 부모이고 자식인지를 표현하는 데 강하다.

### 트리의 핵심 특징

트리는 보통 아래 특징으로 이해하면 된다.

- 사이클이 없다.
- 두 노드 사이 경로가 유일하다.
- 최상위 노드인 루트가 있다.
- 각 노드는 0개 이상의 자식을 가질 수 있다.

이때 강의에서 특히 중요한 포인트는,  
트리의 정의가 **재귀적**이라는 점이다.

> 하나의 트리는 루트 하나와, 그 아래에 있는 여러 개의 서브트리로 이루어진다.

이 말이 중요한 이유는, 이후 이진 트리 순회나 재귀 함수가 왜 자연스럽게 맞는지 설명해 주기 때문이다.

### 자주 하는 실수 / 디버깅 포인트

⚠️ **트리와 그래프를 완전히 별개로 생각하기 쉬움**  
트리는 그래프의 한 종류다.  
다만 “사이클이 없고 계층 구조를 갖는다”는 제약이 붙은 특별한 경우라고 이해하면 좋다.

⚠️ **리프 노드를 “맨 아래 노드”라고만 외우기 쉬움**  
정확한 기준은 아래쪽에 있느냐가 아니라, **자식이 없느냐**다.

`📌 핵심`  
트리는 단순한 그림이 아니라, **상태와 관계를 계층적으로 표현하는 틀**이다.

---

## 3.3 이진 트리는 “자식이 최대 2개인 트리”이고, 저장 방식과 순회 방식이 중요하다

이진 트리는 각 노드가 자식을 최대 두 개까지만 가지는 트리다.

- 왼쪽 자식(left child)
- 오른쪽 자식(right child)

이 제약 하나만으로도 구조가 훨씬 단순해지고,  
그래서 탐색, 정렬, 우선순위 관리 같은 문제에 자주 쓰이게 된다.

### 이진 트리의 기본 성질

강의에서는 이진 트리의 노드 수를 레벨과 높이로 설명했다.

- 레벨 `i`에서 가질 수 있는 최대 노드 수는 `2^i`
- 높이가 `h`인 이진 트리의 최대 노드 수는 `2^(h+1) - 1`
- 높이가 `h`인 이진 트리의 최소 노드 수는 `h + 1`

이 식은 그냥 외우기보다,  
“한 레벨 내려갈 때마다 자식 수가 최대 두 배씩 늘어난다”는 그림으로 이해하면 훨씬 오래 남는다.

### 이진 트리의 종류

강의에서 정리한 이진 트리 종류는 아래 세 가지다.

#### 1) 포화 이진 트리 (Full Binary Tree)

모든 레벨이 꽉 차 있는 트리다.  
노드 번호를 1번부터 차례로 붙였을 때 빈칸이 생기지 않는다.

#### 2) 완전 이진 트리 (Complete Binary Tree)

마지막 레벨을 제외하면 위쪽은 모두 차 있고,  
마지막 레벨도 **왼쪽부터 빈칸 없이 채워진** 트리다.

힙이 바로 이 구조를 사용한다.

#### 3) 편향 이진 트리 (Skewed Binary Tree)

한쪽으로만 길게 늘어진 트리다.  
이 경우 트리의 장점이 많이 사라지고, 거의 연결 리스트처럼 느려질 수 있다.

### 순회는 “노드를 어떤 순서로 방문할 것인가”의 문제다

이진 트리 순회에서는 방문 위치 `V`, 왼쪽 `L`, 오른쪽 `R`의 순서를 기억하면 된다.

- **전위 순회 (VLR)**: 루트 → 왼쪽 → 오른쪽
- **중위 순회 (LVR)**: 왼쪽 → 루트 → 오른쪽
- **후위 순회 (LRV)**: 왼쪽 → 오른쪽 → 루트

특히 중위 순회는 BST에서 매우 중요하다.  
왜냐하면 **중위 순회를 하면 값이 정렬된 순서로 나온다**는 특징이 있기 때문이다.

### 배열로 저장하는 방법

강의에서는 이진 트리를 배열로 저장하는 방식도 함께 다뤘다.

#### 노드 번호를 1부터 시작할 때

- 부모가 `i`
- 왼쪽 자식은 `2 * i`
- 오른쪽 자식은 `2 * i + 1`

#### 인덱스를 0부터 시작할 때

- 부모가 `i`
- 왼쪽 자식은 `2 * i + 1`
- 오른쪽 자식은 `2 * i + 2`

이 공식을 알고 있으면,  
트리를 실제 포인터 없이도 배열 하나로 꽤 편하게 다룰 수 있다.

### 배열 표현의 한계

하지만 배열 표현이 항상 좋은 것은 아니다.

- 편향 트리에서는 빈칸이 많아져 메모리가 낭비된다.
- 중간 삽입/삭제가 어렵다.
- 구조가 자주 바뀌는 트리에는 불편할 수 있다.

그래서 실제 구현에서는 연결 리스트 방식이나 노드 클래스를 쓰는 경우도 많다.

### 자주 하는 실수 / 디버깅 포인트

⚠️ **포화 이진 트리와 완전 이진 트리를 섞어 외우기 쉬움**  
포화는 “모든 칸이 꽉 찬 상태”, 완전은 “마지막 레벨만 덜 찰 수 있지만 왼쪽부터 채워진 상태”다.

⚠️ **배열 인덱스 공식에서 1-based와 0-based를 섞기 쉬움**  
이 부분은 실제 구현에서 정말 많이 틀리는 지점이다.  
문제에서 노드 번호를 어떻게 주는지 먼저 확인하고 공식을 써야 한다.

`📌 핵심`  
이진 트리는 단순히 자식이 두 개인 구조가 아니라, **순회와 배열 표현이 특히 강한 자료구조**다.

## 3.4 이진탐색트리(BST)는 “탐색을 빠르게 하기 위한 정렬 규칙이 있는 이진 트리”다

BST는 일반 이진 트리와 달리 **값의 대소 관계 규칙**이 있다.

아래 그림처럼, 루트를 기준으로 왼쪽에는 더 작은 값, 오른쪽에는 더 큰 값이 놓인다.

![alt text](<스크린샷 2026-03-12 104328-1.png>)

이 규칙을 문장으로 쓰면 다음과 같다.

- `왼쪽 서브트리의 모든 값 < 루트 값`
- `오른쪽 서브트리의 모든 값 > 루트 값`
- 왼쪽과 오른쪽 서브트리도 각각 다시 BST다.

쉽게 말하면,  
배열처럼 일렬로 정렬해 둔 것은 아니지만 **비교를 통해 갈 방향을 바로 정할 수 있게 해 둔 구조**다.

### 왜 탐색이 빨라지는가

루트에서 찾고 싶은 값 `x`를 비교한다고 생각해 보자.

- `x == 루트값`이면 찾았다.
- `x < 루트값`이면 왼쪽만 보면 된다.
- `x > 루트값`이면 오른쪽만 보면 된다.

즉, 매번 트리 전체를 보는 것이 아니라 **한쪽 방향만 선택해서 내려간다**.  
이 점이 BST의 핵심이다.

### 삽입 연산도 탐색의 연장선이다

삽입은 새로운 규칙을 따로 외울 필요가 없다.  
먼저 탐색하듯 내려가서, **더 이상 내려갈 자리가 없어진 위치**에 새 노드를 넣으면 된다.

그래서 BST를 공부할 때는 아래 세 가지를 함께 묶어 이해하는 것이 좋다.

- 탐색: 어디로 내려갈지 결정
- 삽입: 탐색 실패 지점에 넣기
- 삭제: 구조를 깨지 않도록 재연결하기

### 삭제 연산이 까다로운 이유

삭제는 세 경우로 나눠 생각하면 정리가 쉽다.

1. **리프 노드 삭제**  
   그냥 지우면 된다.

2. **자식이 1개인 노드 삭제**  
   부모와 그 자식을 바로 연결하면 된다.

3. **자식이 2개인 노드 삭제**  
   이 경우가 가장 중요하다.  
   보통 다음 둘 중 하나로 대체한다.

   - 왼쪽 서브트리에서 가장 큰 값
   - 오른쪽 서브트리에서 가장 작은 값

이렇게 해야 BST 규칙이 깨지지 않는다.

### 왜 중위 순회가 중요한가

BST는 **중위 순회(LVR)** 를 하면 값이 오름차순으로 나온다.  
이건 BST를 볼 때 거의 상징처럼 따라오는 특징이다.

즉, BST는 단순히 찾기 빠른 구조가 아니라,  
**정렬된 순서를 트리 구조로 보관하는 방식**이라고도 볼 수 있다.

### 시간복잡도는 “트리의 높이”에 달려 있다

BST의 탐색, 삽입, 삭제는 모두 트리 높이만큼 걸린다.

- 평균적으로 균형이 잡혀 있으면 `O(log n)`
- 한쪽으로 쏠리면 최악의 경우 `O(n)`

이 때문에 BST는 규칙만 보고 무조건 빠르다고 생각하면 안 된다.  
트리 모양이 나빠지면 배열 선형탐색과 비슷해질 수도 있다.

### 자주 하는 실수 / 디버깅 포인트

⚠️ **BST는 항상 빠르다고 오해하기 쉬움**  
균형이 무너지면 성능이 급격히 나빠질 수 있다.

⚠️ **중위 순회와 전위/후위를 헷갈리기 쉬움**  
정렬된 결과를 얻는 순회는 중위 순회다.

⚠️ **삭제에서 자식 2개인 경우를 대충 처리하기 쉬움**  
이 부분은 “왼쪽 최대” 또는 “오른쪽 최소”로 대체한다는 기준을 꼭 잡고 있어야 한다.

`📌 핵심`  
BST의 핵심은 이진 트리 모양 자체가 아니라, **비교를 통해 한쪽만 내려가게 만드는 정렬 규칙**이다.

## 3.5 힙은 “우선순위를 빠르게 관리하기 위한 완전 이진 트리”다

힙은 최대값이나 최소값을 빠르게 꺼내기 위해 만든 자료구조다.  
강의에서는 특히 **우선순위 큐 문제에서 힙이 매우 중요하다**고 강조했다.

힙은 이진 트리이지만, BST와는 목적이 다르다.

- BST: 특정 값을 찾기 좋게 만든 구조
- 힙: 가장 큰 값 또는 가장 작은 값을 빠르게 꺼내기 좋게 만든 구조

### 힙의 종류

#### 최대 힙 (Max Heap)

- 부모 값이 자식 값보다 크거나 같다.
- 루트에는 전체 최댓값이 온다.

#### 최소 힙 (Min Heap)

- 부모 값이 자식 값보다 작거나 같다.
- 루트에는 전체 최솟값이 온다.

여기서 중요한 점은,  
**형제끼리 정렬되어 있을 필요는 없고 부모-자식 관계만 맞으면 된다**는 것이다.

강의 메모에 있는 “부모와 자식만 신경쓰면 된다 / 형제끼리는 정렬 X / root 데이터만 본다”는 말이 바로 이 뜻이다.

### 왜 완전 이진 트리를 쓰는가

힙은 완전 이진 트리이기 때문에 배열로 저장하기 좋다.  
그래서 부모/자식 위치를 인덱스로 바로 계산할 수 있다.

이 점 덕분에 삽입과 삭제 과정도 비교적 단순하게 구현할 수 있다.

### 힙 삽입의 흐름

힙 삽입은 보통 이렇게 생각하면 된다.

1. 완전 이진 트리의 **마지막 빈 자리**에 일단 넣는다.
2. 부모와 비교한다.
3. 힙 조건을 깨면 자리를 바꾼다.
4. 자기 자리를 찾을 때까지 위로 올라간다.

이 과정을 흔히 **up-heap**, **sift-up**이라고 부른다.

### 힙 삭제의 흐름

힙에서 삭제는 보통 루트만 한다.  
최댓값 또는 최솟값이 루트에 있기 때문이다.

흐름은 다음과 같다.

1. 루트 값을 꺼낸다.
2. 마지막 노드를 루트 자리로 올린다.
3. 자식과 비교한다.
4. 힙 조건을 만족할 때까지 아래로 내려 보낸다.

이 과정을 **down-heap**, **sift-down**이라고 생각하면 된다.

### 시간복잡도

- 루트 조회: `O(1)`
- 삽입: `O(log n)`
- 삭제: `O(log n)`

그래서 우선순위 큐를 구현할 때 힙이 매우 자주 쓰인다.

### 자주 하는 실수 / 디버깅 포인트

⚠️ **힙을 BST처럼 생각하기 쉬움**  
힙은 전체 정렬 구조가 아니다.  
왼쪽이 항상 작고 오른쪽이 항상 큰 구조가 아니다.

⚠️ **형제 노드끼리도 정렬되어야 한다고 오해하기 쉬움**  
힙은 오직 부모-자식 관계만 본다.

⚠️ **삭제할 때 루트만 꺼낸다는 점을 놓치기 쉬움**  
힙은 임의 위치 삭제보다 “최우선 원소를 꺼낸다”는 목적에 맞춰 설계된 구조다.

`📌 핵심`  
힙은 정렬된 트리가 아니라, **가장 중요한 값 하나를 빠르게 관리하기 위한 우선순위 구조**다.

## 4. 적용 관점에서 다시 보기

이번 강의의 내용을 문제풀이 관점에서 다시 묶어 보면,  
중요한 것은 정의 암기보다 **어떤 상황에서 어떤 구조를 떠올릴 수 있느냐**다.

### 4.1 백트래킹을 떠올려야 하는 신호

아래 신호가 보이면 백트래킹을 의심해 볼 만하다.

- 가능한 경우를 전부 만들 수는 있지만, 경우의 수가 너무 많다.
- 중간 단계에서 이미 “틀린 선택”을 판별할 수 있다.
- 순열, 조합, 부분집합, 배치 문제처럼 선택이 단계적으로 이어진다.
- “가능한 배치를 모두 구하라”, “최적값을 구하라”, “조건을 만족하는 경우를 세어라” 유형이다.

이때 구현 순서는 보통 다음처럼 잡으면 안정적이다.

1. 재귀 함수의 **depth 의미**를 먼저 정한다.
2. 현재 상태에서 **무엇을 선택할지(branch)** 정한다.
3. 유망성 검사 함수를 만든다.
4. 선택 → 재귀 → 복구 순서를 지킨다.

### 4.2 트리를 떠올려야 하는 신호

트리는 아래처럼 **계층 구조**가 보이면 떠올리기 좋다.

- 부모-자식 관계가 있다.
- 루트에서 하위 노드로 내려가는 구조다.
- 조직도, 폴더 구조, 수식 트리, 상태 공간, 탐색 과정처럼 분기 구조가 보인다.

### 4.3 BST를 떠올려야 하는 신호

- 삽입/삭제가 자주 일어난다.
- 탐색도 빠르게 하고 싶다.
- 값의 대소 관계를 이용해 왼쪽/오른쪽으로 나누고 싶다.

다만 실전 코딩테스트에서는 직접 BST를 구현하기보다,  
언어 라이브러리나 정렬 자료구조 대체 수단을 활용하는 경우도 많다.

### 4.4 힙을 떠올려야 하는 신호

- 가장 큰 값 / 가장 작은 값을 반복해서 꺼내야 한다.
- 우선순위가 가장 높은 작업을 계속 선택해야 한다.
- 우선순위 큐, 스케줄링, 최소 비용 선택 문제와 연결된다.

💡 **포인트**  
BST와 힙은 둘 다 트리지만, 문제에서 원하는 연산이 다르면 선택도 달라진다.

- 특정 값 탐색 중심이면 BST 쪽 사고
- 최댓값/최솟값 반복 추출 중심이면 힙 쪽 사고

## 5. 배운 점 / 느낀 점 / 확장 포인트

이번 강의에서 가장 인상적인 점은,  
서로 다른 주제처럼 보이는 내용이 사실은 **트리라는 공통된 시각**으로 묶인다는 점이다.

백트래킹에서는 트리가 “선택의 흐름”을 표현한다.  
자료구조 파트에서는 트리가 “데이터를 저장하는 방식”이 된다.  
즉, 같은 트리라도 문제를 풀 때는 상태 공간으로, 자료를 다룰 때는 구조 자체로 쓰인다.

다음 학습으로 이어질 수 있는 확장 포인트도 분명하다.

- 백트래킹 → 부분집합, 순열, 조합, 스도쿠, N-Queen 심화
- 이진 트리 → 재귀 순회 구현, 배열 표현, 트리 DP
- BST → 균형 트리, ordered set/map 개념
- 힙 → 우선순위 큐, 다익스트라, 힙 정렬

특히 힙은 이후 그래프 알고리즘과도 강하게 연결되므로,  
이번 강의에서 꼭 감각을 잡아 두면 뒤 내용이 훨씬 편해진다.

## 6. 요약 정리

📌 **핵심**

- 백트래킹은 가능한 경우를 만들되, **유망하지 않은 가지를 미리 자르는 탐색**이다.
- N-Queen 같은 문제에서는 열/대각선 충돌 검사로 강한 가지치기가 가능하다.
- 트리는 **계층 구조**를 표현하는 자료구조이며, 상태 공간을 설명할 때도 자주 등장한다.
- 이진 트리는 자식이 최대 2개인 트리이고, 순회와 배열 표현이 중요하다.
- BST는 **탐색을 빠르게 하기 위한 비교 규칙**이 있는 이진 트리다.
- 힙은 **최댓값/최솟값을 빠르게 꺼내기 위한 완전 이진 트리**다.

🧠 **기억할 것**

- 백트래킹의 핵심은 “재귀”보다 **pruning**
- BST의 핵심은 “트리 모양”보다 **왼쪽 < 루트 < 오른쪽**
- 힙의 핵심은 “전체 정렬”이 아니라 **루트 우선순위 보장**
