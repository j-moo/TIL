백트래킹, 이진 트리, 이진탐색트리, 힙 정리

  • 🎯 글의 목표: 백트래킹과 트리 자료구조의 흐름을 한 번에 정리하고, 특히 이진탐색트리(BST)의 삽입·삭제와 힙의 삽입·삭제가 왜 그렇게 동작하는지까지 이해하는 데 있다.
  • 🧩 핵심 키워드: 백트래킹, 가지치기, 상태 공간 트리, 트리, 이진 트리, 순회, 배열 표현, 연결 리스트, 이진탐색트리, BST 삽입, BST 삭제, 힙, 최대 힙, 최소 힙, 우선순위 큐
  • ⭐ 중요도: 매우 높음 — 코딩 테스트와 자료구조 기초를 연결하는 핵심 주제
  • 📝 한눈에 보는 내용: 이 글에서는 먼저 백트래킹이 왜 필요한지 N-Queen 예시로 정리하고, 이어서 트리와 이진 트리의 구조를 살펴본다. 그 다음 이진탐색트리의 탐색·삽입·삭제를 이해하고, 마지막으로 힙의 구조와 삽입·삭제 연산을 개념이 나오는 자리에서 바로 코드와 함께 정리한다.
  • 🔗 관련 문제 / 주제(있다면): N-Queen, 트리 순회, BST 탐색/삽입/삭제, 우선순위 큐, 힙 정렬

1. 들어가며

이 글에서는 강의 노트의 흐름을 따라 백트래킹 → 트리 → 이진 트리 → 이진탐색트리 → 힙까지 한 번에 정리한다. 각각 따로 배우는 것처럼 보여도, 실제로는 “문제를 트리처럼 보고 필요한 경로만 탐색하는 사고”와 “트리 구조를 효율적으로 저장하고 다루는 방법”이라는 한 줄기로 연결된다.

이번 재정리에서는 코드 배치도 바꿨다. 자료구조 노트는 개념 설명을 읽고 난 뒤 바로 그 위치에서 코드를 보는 것이 훨씬 이해가 잘 된다. 그래서 이번 버전은 코드가 별도 섹션에 몰리지 않고, 해당 개념 아래에 바로 등장하도록 구성했다.

특히 강의 노트에서 조금 짧게 지나간 BST 삭제와 힙 삽입·삭제는 설명과 코드 해설을 더 촘촘하게 보강했다. 이 부분은 시험과 문제풀이에서 자주 헷갈리는 포인트라서, “정의”보다 “왜 그렇게 하는지”를 이해하는 것이 중요하다.

2. 핵심 개념 정리

이 섹션에서는 강의 전체의 큰 흐름을 먼저 잡는다. 세부 코드로 들어가기 전에, 각각의 자료구조와 알고리즘이 어떤 문제를 해결하려고 등장했는지를 이해하면 훨씬 오래 기억에 남는다.

백트래킹: 모든 경우를 보되, 필요 없는 길은 빨리 포기하는 방법

백트래킹은 여러 선택지가 있는 문제에서 가능한 경우를 탐색하되, 답이 될 수 없는 경로는 중간에 잘라내는 방식이다. 그냥 깊이 우선 탐색(DFS)으로 끝까지 내려가면 경우의 수가 너무 커지기 때문에, 중간중간 “이 길은 더 가도 답이 안 나온다”는 판단을 해 주는 것이 핵심이다.

여기서 자주 나오는 말이 가지치기(pruning) 이다. 말 그대로 나무의 가지를 잘라내듯, 유망하지 않은 선택을 빨리 버리는 것이다. N-Queen 문제처럼 배치 가능한 경우가 폭발적으로 늘어나는 문제에서 특히 강력하다.

트리: 계층 구조를 표현하는 가장 기본적인 틀

트리는 사이클이 없는 연결 구조이며, 부모-자식 관계가 있는 계층형 자료구조다. 폴더 구조, 조직도, DOM 구조처럼 현실에서도 자주 등장한다. 그래프와 비슷해 보여도, 트리는 두 노드 사이의 경로가 유일하고 사이클이 없다는 특징 덕분에 조금 더 단순하게 다룰 수 있다.

이진 트리: 자식이 최대 두 개까지인 트리

이진 트리는 각 노드가 왼쪽 자식과 오른쪽 자식, 최대 두 개만 가질 수 있는 트리다. 자식 수가 제한되기 때문에 구조가 단순해지고, 순회(preorder / inorder / postorder)나 배열 표현 같은 기법을 배우기 좋다.

이진탐색트리(BST): 탐색을 빠르게 하기 위한 규칙 있는 이진 트리

BST는 단순히 “자식이 둘 이하인 트리”가 아니라, 여기에 정렬 규칙이 추가된 구조다.

  • 왼쪽 서브트리의 모든 값 < 루트 값
  • 오른쪽 서브트리의 모든 값 > 루트 값

이 규칙 덕분에 탐색 방향을 절반씩 줄여 갈 수 있다. 그래서 평균적으로는 O(log n)에 탐색, 삽입, 삭제가 가능하다. 다만 한쪽으로 치우치면 O(n)까지 나빠질 수 있다.

힙: 최댓값 또는 최솟값을 빨리 꺼내기 위한 완전 이진 트리

힙은 정렬된 트리가 아니다. 대신 부모와 자식 사이의 대소 관계만 유지한다. 최대 힙에서는 부모가 자식보다 크고, 최소 힙에서는 부모가 자식보다 작다. 그래서 전체가 오름차순/내림차순으로 정렬되어 있지는 않지만, 루트에는 항상 가장 큰 값 또는 가장 작은 값이 온다.

이게 왜 중요할까? 우선순위 큐처럼 “가장 급한 것 하나를 빨리 꺼내야 하는 상황”에서는 전체 정렬보다 루트 하나를 빨리 찾는 능력이 더 중요하기 때문이다.

한 번에 비교하기

구조 핵심 목적 중요한 규칙 잘하는 일
백트래킹 경우의 수 탐색 최적화 유망하지 않으면 중단 조합, 배치, 완전탐색 가지치기
이진 트리 계층 구조 표현 자식이 최대 2개 순회, 구조적 표현
BST 빠른 탐색 왼쪽 < 루트 < 오른쪽 탐색, 삽입, 삭제
힙 최대/최소값 빠른 추출 부모-자식 대소 관계 우선순위 큐, 힙 정렬

💡 포인트
트리라고 해서 다 같은 트리가 아니다. BST는 “탐색”에 강한 트리, 힙은 “최댓값/최솟값 꺼내기”에 강한 트리라고 기억하면 구분이 쉬워진다.

3. 본문 정리

이 섹션에서는 강의 내용을 순서대로 따라가며 개념을 풀어쓴다. 이번 버전에서는 개념이 등장하면 그 자리에서 바로 코드와 해설이 따라오도록 배치했다.

3-1. 백트래킹과 N-Queen

이 부분에서는 백트래킹이 실제로 어떤 문제에서 빛을 발하는지 본다. 대표 예시가 바로 N-Queen 문제다.

N-Queen은 N x N 체스판에 퀸 N개를 서로 공격하지 않게 놓는 문제다. 퀸은 가로, 세로, 대각선으로 모두 움직일 수 있으므로, 단순히 빈 칸을 찾는 문제가 아니라 “지금 놓는 위치가 이후까지 안전한가?”를 계속 판단해야 한다.

예를 들어 4-Queen을 생각해 보면, 아무 생각 없이 각 행마다 4칸 중 하나를 고르면 경우의 수는 4 x 4 x 4 x 4 = 256개다. 하지만 실제로는 같은 열에 이미 퀸이 있거나, 대각선에서 충돌하는 경우가 많기 때문에 대부분은 중간에 버려도 된다.

백트래킹의 흐름은 다음과 같다.

  1. 현재 행에서 퀸을 놓을 열을 하나 고른다.
  2. 이전 퀸들과 충돌하는지 검사한다.
  3. 충돌하면 바로 다음 열로 넘어간다.
  4. 충돌하지 않으면 다음 행으로 재귀 호출한다.
  5. 끝까지 갔으면 정답 하나를 찾은 것이다.

이 코드는 “현재 자리가 유망한지 검사하고, 가능하면 다음 행으로 내려가는” 가장 전형적인 백트래킹 형태를 보여 준다.

N = 4
visited = [[False] * N for _ in range(N)]  # 체스판 방문 여부
path = [-1] * N                            # path[row] = row행에서 선택한 col
answer = 0


def check(row, col):
    # 1) 같은 열에 이미 퀸이 있는지 확인
    for i in range(row):
        if visited[i][col]:
            return True

    # 2) 좌상단 대각선 확인
    i, j = row - 1, col - 1
    while i >= 0 and j >= 0:
        if visited[i][j]:
            return True
        i -= 1
        j -= 1

    # 3) 우상단 대각선 확인
    i, j = row - 1, col + 1
    while i >= 0 and j < N:
        if visited[i][j]:
            return True
        i -= 1
        j += 1

    # 충돌이 없으면 놓을 수 있는 자리
    return False


def recur(row):
    global answer

    # 모든 행에 퀸을 다 놓았으면 정답 1개 완성
    if row == N:
        answer += 1
        print(path)
        return

    # 현재 행에서 가능한 모든 열 시도
    for col in range(N):
        # 유망하지 않으면 가지치기
        if check(row, col):
            continue

        # 퀸 배치
        visited[row][col] = True
        path[row] = col

        # 다음 행으로 이동
        recur(row + 1)

        # 원상 복구(backtracking)
        visited[row][col] = False
        path[row] = -1


recur(0)
print("정답 개수:", answer)

코드 해설

  • 한 행에는 퀸을 하나만 놓는다고 가정하고 row를 기준으로 재귀를 돈다.
  • 각 행마다 모든 col을 시도한다.
  • check()에서 같은 열, 왼쪽 위 대각선, 오른쪽 위 대각선을 검사한다.
  • 놓을 수 없으면 continue로 바로 가지치기한다.
  • 놓을 수 있으면 배치하고 다음 행으로 내려간다.
  • 재귀가 끝나면 다시 지워서 다른 경우를 시도한다.

⚠️ 자주 하는 실수

  • 재귀 호출 뒤에 원상 복구를 안 해서 다른 경우의 수가 오염되는 경우
  • check()가 “가능 여부”가 아니라 “충돌 여부”를 반환한다는 점을 헷갈리는 경우
  • 같은 행까지 검사해서 자기 자신과 충돌 처리하는 경우

📌 핵심
백트래킹은 “모든 경우를 보는 탐색”이지만, 유망하지 않은 경로를 중간에 버리는 DFS라고 이해하면 된다.

3-2. 트리의 기본 개념

이 부분에서는 트리의 용어를 먼저 정확히 정리한다. 이후 이진 트리, BST, 힙으로 갈수록 같은 용어가 계속 반복되기 때문이다.

  • 루트(root): 가장 위의 시작 노드
  • 부모(parent): 어떤 노드를 가리키는 상위 노드
  • 자식(child): 부모 아래에 연결된 하위 노드
  • 리프(leaf): 자식이 없는 노드
  • 형제(sibling): 같은 부모를 가진 노드
  • 서브트리(subtree): 특정 노드를 루트로 보는 작은 트리
  • 조상 / 자손: 위쪽으로 이어지는 노드 / 아래쪽으로 이어지는 노드
  • 높이(height): 트리 또는 노드가 가지는 깊이 정보

🧠 기억할 것
트리는 재귀적으로 정의된다. 즉, 큰 트리 안의 각 서브트리도 결국 또 하나의 트리다. 그래서 트리 문제에서는 재귀가 자연스럽게 잘 어울린다.

3-3. 이진 트리와 순회

이 부분에서는 이진 트리의 구조적 특징과 순회를 정리한다. 이진 트리는 자식이 최대 두 개뿐이어서, 왼쪽과 오른쪽을 기준으로 탐색 순서를 정의하기 쉽다.

이진 트리의 기본 성질

  • 레벨 i에서 가질 수 있는 최대 노드 수는 2^i
  • 높이 h인 이진 트리의 최대 노드 수는 2^(h+1) - 1
  • 모든 레벨이 가득 찬 형태를 포화 이진 트리
  • 마지막 레벨만 덜 찰 수 있고 왼쪽부터 채워지는 형태를 완전 이진 트리
  • 한쪽으로만 늘어선 형태를 편향 이진 트리라고 한다

순회 방법 3가지

  1. 전위 순회 (VLR): 루트 → 왼쪽 → 오른쪽
  2. 중위 순회 (LVR): 왼쪽 → 루트 → 오른쪽
  3. 후위 순회 (LRV): 왼쪽 → 오른쪽 → 루트

중위 순회는 특히 BST와 연결될 때 중요하다. BST를 중위 순회하면 값이 오름차순으로 나오기 때문이다.

이 코드는 연결 리스트 방식의 노드 클래스와 세 가지 순회를 함께 보여 준다.

class Node:
    def __init__(self, key):
        self.key = key      # 현재 노드가 저장하는 값
        self.left = None    # 왼쪽 자식
        self.right = None   # 오른쪽 자식


def preorder(node):
    if node is None:
        return
    print(node.key, end=' ')   # V: 루트를 먼저 방문
    preorder(node.left)        # L: 왼쪽 서브트리
    preorder(node.right)       # R: 오른쪽 서브트리


def inorder(node):
    if node is None:
        return
    inorder(node.left)         # L
    print(node.key, end=' ')   # V
    inorder(node.right)        # R


def postorder(node):
    if node is None:
        return
    postorder(node.left)       # L
    postorder(node.right)      # R
    print(node.key, end=' ')   # V: 마지막에 루트 방문

코드 해설

  • 전위 순회는 루트를 먼저 처리하므로 “구조를 먼저 본다”는 느낌이다.
  • 중위 순회는 BST에서 정렬 결과를 확인할 때 중요하다.
  • 후위 순회는 자식부터 처리하므로 삭제나 계산 누적과 잘 맞는다.

💡 쉽게 기억하는 법

  • 전위: 부모 먼저
  • 중위: 부모 가운데
  • 후위: 부모 나중

3-4. 이진 트리를 저장하는 방법

이 부분에서는 이진 트리를 코드에서 어떻게 표현하는지 정리한다. 강의 노트에서는 배열, 연결 리스트, 그래프 방식이 소개되었다.

1) 배열 표현

완전 이진 트리처럼 빈칸이 거의 없는 구조에서는 배열 표현이 아주 편하다.

  • 인덱스를 1부터 시작하면

    • 왼쪽 자식: i * 2
    • 오른쪽 자식: i * 2 + 1

  • 인덱스를 0부터 시작하면

    • 왼쪽 자식: i * 2 + 1
    • 오른쪽 자식: i * 2 + 2

아래 코드는 0-based 배열에서 부모와 자식을 계산하는 가장 기본적인 형태다.

arr = [50, 30, 70, 20, 40, 60, 80]

idx = 1                      # 값 30의 인덱스
left = idx * 2 + 1          # 왼쪽 자식 인덱스
right = idx * 2 + 2         # 오른쪽 자식 인덱스
parent = (idx - 1) // 2     # 부모 인덱스

print(arr[idx])             # 30
print(arr[left], arr[right])# 20 40
print(arr[parent])          # 50

2) 연결 리스트 표현

일반적인 트리 구현에서는 노드마다 왼쪽, 오른쪽 자식을 참조하는 방식이 더 유연하다. 중간에 노드를 삽입하거나 삭제하기도 편하다. BST 구현에서 많이 보는 방식이 바로 이것이다.

3) 그래프처럼 표현

인접 리스트나 인접 행렬로도 표현할 수 있지만, 순수 이진 트리 구현에서는 보통 배열 또는 노드 클래스를 더 많이 사용한다.

⚠️ 배열 표현의 단점

  • 편향 이진 트리에서는 중간이 많이 비어서 메모리 낭비가 크다.
  • 트리 중간 삽입·삭제가 생기면 구조 유지가 불편하다.

3-5. 이진탐색트리(BST)

이 부분에서는 BST의 핵심 규칙과 연산을 자세히 본다. 강의 노트에서 탐색·삽입·삭제가 간단히 소개되었는데, 실제로는 삭제 연산이 가장 많이 헷갈린다.

BST 탐색

루트에서 시작해서 찾고 싶은 값 x를 현재 노드 값과 비교한다.

  • 같으면 찾기 성공
  • 작으면 왼쪽으로 이동
  • 크면 오른쪽으로 이동

즉, 배열 이진 탐색처럼 “절반씩 버린다”는 느낌을 트리 구조에서 구현한 것이다.

def search(node, key):
    if node is None:
        return None

    if key == node.key:
        return node
    elif key < node.key:
        return search(node.left, key)
    else:
        return search(node.right, key)

BST 삽입

삽입은 사실 탐색의 연장이다.

  1. 삽입할 값과 같은 값이 있는지 찾는다.
  2. 탐색하다가 None을 만나는 위치가 삽입 자리다.
  3. 그 자리에 새 노드를 붙인다.

이 코드는 BST 삽입의 가장 기본적인 재귀 구현이다.

class BSTNode:
    def __init__(self, key):
        self.key = key
        self.left = None
        self.right = None


def insert(node, key):
    # 비어 있는 위치를 만나면 새 노드 생성
    if node is None:
        return BSTNode(key)

    # 현재 노드보다 작으면 왼쪽으로
    if key < node.key:
        node.left = insert(node.left, key)

    # 현재 노드보다 크면 오른쪽으로
    elif key > node.key:
        node.right = insert(node.right, key)

    # 같은 값이면 중복 삽입하지 않음
    return node

삽입 코드 해설

  • node is None인 순간이 바로 삽입 위치다.
  • 부모가 직접 새 노드를 만드는 게 아니라, 재귀 반환값을 받아 연결한다.
  • 그래서 node.left = insert(...) 같은 형태가 꼭 필요하다.

⚠️ 삽입에서 자주 하는 실수

  • node.left = ... 또는 node.right = ...를 빼먹어 연결이 안 되는 경우
  • 중복 값 허용 여부를 정하지 않고 넘어가는 경우
  • 루트가 None일 때 반환값을 다시 루트에 저장하지 않는 경우

BST 삭제 — 가장 헷갈리는 부분

삭제는 노드의 자식 수에 따라 경우를 나누면 훨씬 쉽다.

경우 1) 삭제할 노드가 리프 노드일 때

가장 단순하다. 부모가 그 노드를 가리키는 연결만 끊으면 된다.

경우 2) 삭제할 노드의 자식이 1개일 때

삭제할 노드를 건너뛰고, 부모와 자식을 바로 연결하면 된다.

  • 원래: 부모 → 30 → 40
  • 삭제 후: 부모 → 40
경우 3) 삭제할 노드의 자식이 2개일 때

이 경우 그냥 지워 버리면 BST 규칙이 깨질 수 있다. 그래서 보통 두 방법 중 하나를 사용한다.

  • 왼쪽 서브트리의 최댓값(중위 순회상 바로 이전 값) 을 올리기
  • 오른쪽 서브트리의 최솟값(중위 순회상 바로 다음 값) 을 올리기

보통 구현에서는 오른쪽 서브트리의 최솟값(중위 후속자) 을 많이 쓴다.

예를 들어 50을 삭제한다고 하자.

  • 왼쪽 서브트리: 30, 20, 40
  • 오른쪽 서브트리: 70, 60, 80

이때 50 대신 올릴 수 있는 값은:

  • 왼쪽에서 가장 큰 값 40, 또는
  • 오른쪽에서 가장 작은 값 60

왜 하필 이 둘일까?
BST 규칙을 깨지 않고 그 자리를 대신할 수 있는 값이기 때문이다.

아래 코드는 후속자(successor)를 사용하는 삭제 구현이다.

def find_min(node):
    # 가장 왼쪽으로 끝까지 내려가면 최솟값
    while node.left is not None:
        node = node.left
    return node

def delete(node, key):
    # 삭제할 값을 찾지 못한 경우
    if node is None:
        return None

    # 삭제할 값이 현재 노드보다 작으면 왼쪽에서 계속 탐색
    if key < node.key:
        node.left = delete(node.left, key)

    # 삭제할 값이 현재 노드보다 크면 오른쪽에서 계속 탐색
    elif key > node.key:
        node.right = delete(node.right, key)

    # 현재 노드가 삭제 대상인 경우
    else:
        # 경우 1, 2: 자식이 0개 또는 1개인 경우
        if node.left is None:
            return node.right
        if node.right is None:
            return node.left

        # 경우 3: 자식이 2개인 경우
        successor = find_min(node.right)   # 오른쪽 서브트리에서 가장 작은 값 찾기
        node.key = successor.key           # 후속자 값을 현재 노드에 복사
        node.right = delete(node.right, successor.key)  # 후속자를 원래 자리에서 삭제

    return node

삭제 코드 해설

  • 먼저 일반 탐색처럼 삭제할 값을 찾는다.
  • 찾은 뒤에는 자식 수에 따라 처리한다.
  • 자식이 0개 또는 1개면 연결만 바꾸면 끝난다.
  • 자식이 2개면 후속자 값을 복사한 뒤, 후속자를 원래 자리에서 다시 삭제한다.

💡 포인트

“자식이 2개인 노드 삭제”는 사실 2단계다.

  1. 대체할 값을 찾는다.
  2. 그 대체 값을 원래 자리에서 삭제한다.

즉, 복잡해 보여도 결국 리프 삭제 또는 자식 1개 삭제 문제로 바뀐다.

🧠 이해를 돕는 한 줄 비유
자식이 둘인 노드를 바로 없애면 트리 질서가 무너진다. 그래서 그 자리를 대신해도 질서를 깨지 않는 대표 선수를 한 명 뽑아 올린다고 생각하면 된다.

BST 성능

  • 평균적으로 균형이 잘 잡혀 있으면 O(log n)
  • 한쪽으로 치우친 편향 트리가 되면 O(n)

즉, BST는 규칙은 좋지만 항상 균형을 보장하지는 않는다는 한계가 있다.

3-6. 힙(Heap)

이 부분에서는 힙을 단순한 “트리”가 아니라 우선순위 큐를 구현하는 핵심 도구로 이해하는 것이 중요하다.

힙은 완전 이진 트리다. 그리고 중요한 것은 형제 간 정렬이 아니라 부모-자식 관계다.

  • 최대 힙: 부모 ≥ 자식
  • 최소 힙: 부모 ≤ 자식

여기서 많이 하는 오해가 하나 있다.

힙은 전체 정렬된 트리가 아니다.

예를 들어 최대 힙에서 루트가 100이고 자식이 80, 70이라고 해서, 80의 자식들이 반드시 70보다 클 필요는 없다. 힙은 각 부모가 자기 자식보다 크기만 하면 된다. 그래서 루트의 최대값 보장은 강하지만, BST처럼 임의 원소 탐색에 강하지는 않다.

힙 삽입: 맨 끝에 넣고 위로 올린다

힙은 완전 이진 트리여야 하므로, 삽입할 때는 먼저 마지막 빈 자리에 넣는다. 그리고 그 뒤 부모와 비교하면서 자신의 자리를 찾아간다. 이를 보통 heapify-up, sift-up, 또는 bubble-up이라고 한다.

왜 이렇게 할까?
완전 이진 트리 형태는 삽입 순간에 이미 지켜졌고, 이제 깨진 것은 부모-자식 대소 관계뿐이기 때문이다. 따라서 위로 올라가며 그 부분만 고치면 된다.

이 코드는 배열 기반 최대 힙에 값을 삽입하는 예시다.

class MaxHeap:
    def __init__(self):
        self.heap = []   # 0번 인덱스부터 사용하는 배열 기반 힙

    def push(self, value):
        # 1) 완전 이진 트리의 마지막 위치에 새 값 추가
        self.heap.append(value)

        # 2) 방금 넣은 값의 인덱스
        idx = len(self.heap) - 1

        # 3) 부모보다 크면 위로 올리기
        while idx > 0:
            parent = (idx - 1) // 2

            # 부모가 더 크거나 같으면 최대 힙 조건 만족
            if self.heap[parent] >= self.heap[idx]:
                break

            # 부모보다 크면 swap 후 계속 위로 이동
            self.heap[parent], self.heap[idx] = self.heap[idx], self.heap[parent]
            idx = parent

힙 삽입 코드 해설

  • 삽입은 항상 배열 맨 뒤에서 시작한다.
  • 완전 이진 트리 모양은 이미 맞췄으니, 이제 대소 관계만 고치면 된다.
  • 부모와 비교해서 더 크면 위로 올라간다.
  • 한 번 올라갈 때마다 트리 한 레벨 이동이므로 시간복잡도는 O(log n)이다.

⚠️ 삽입에서 자주 하는 실수

  • 부모 인덱스를 (idx // 2)로 써서 0-based 배열과 어긋나는 경우
  • 힙이 전체 정렬이라고 착각하는 경우
  • 삽입 뒤에 매번 전체 정렬을 해 버리는 경우

힙 삭제: 루트를 빼고 마지막 값을 올린 뒤 아래로 내린다

힙에서 삭제는 보통 루트 노드 삭제만 생각한다. 최대 힙/최소 힙의 목적이 루트의 최댓값/최솟값을 빠르게 꺼내는 것이기 때문이다.

최대 힙 삭제 과정은 다음과 같다.

  1. 루트 값을 꺼낸다.
  2. 마지막 노드를 루트로 올린다.
  3. 왼쪽/오른쪽 자식 중 더 큰 자식과 비교한다.
  4. 자식이 더 크면 swap 한다.
  5. 제자리를 찾을 때까지 반복한다.

왜 “더 큰 자식”과 바꿔야 할까?
최대 힙에서는 부모가 두 자식보다 모두 커야 한다. 그래서 내려갈 때는 두 자식 중 더 큰 쪽과 비교해야 힙 조건을 한 번에 맞출 수 있다.

아래 코드는 최대 힙의 루트(최댓값)를 꺼내는 구현이다.

class MaxHeap:
    def __init__(self):
        self.heap = []

    def push(self, value):
        self.heap.append(value)
        idx = len(self.heap) - 1

        while idx > 0:
            parent = (idx - 1) // 2
            if self.heap[parent] >= self.heap[idx]:
                break
            self.heap[parent], self.heap[idx] = self.heap[idx], self.heap[parent]
            idx = parent

    def pop(self):
        # 힙이 비어 있으면 예외 처리
        if not self.heap:
            raise IndexError("heap is empty")

        # 원소가 하나뿐이면 바로 반환
        if len(self.heap) == 1:
            return self.heap.pop()

        # 1) 루트의 최댓값 저장
        max_value = self.heap[0]

        # 2) 마지막 값을 루트로 올리고 마지막 칸 제거
        self.heap[0] = self.heap.pop()

        # 3) 루트에서 시작해 아래로 내려가며 자리 찾기
        idx = 0
        size = len(self.heap)

        while True:
            left = idx * 2 + 1
            right = idx * 2 + 2
            largest = idx

            # 왼쪽 자식이 더 크면 largest 갱신
            if left < size and self.heap[left] > self.heap[largest]:
                largest = left

            # 오른쪽 자식이 더 크면 largest 갱신
            if right < size and self.heap[right] > self.heap[largest]:
                largest = right

            # 더 이상 내려갈 필요가 없으면 종료
            if largest == idx:
                break

            # 더 큰 자식과 swap
            self.heap[idx], self.heap[largest] = self.heap[largest], self.heap[idx]
            idx = largest

        return max_value

힙 삭제 코드 해설

  • 루트를 바로 지우면 배열 중간이 비게 되므로 마지막 값을 위로 올린다.
  • 이제 문제는 루트 한 곳의 힙 조건만 깨졌을 가능성이 높다.
  • 그래서 아래로 내려가며 더 큰 자식과 교환한다.
  • 한 번 내려갈 때마다 트리 한 레벨씩 이동하므로 시간복잡도는 O(log n)이다.

예시로 이해하기

최대 힙 배열이 다음과 같다고 해 보자.

[90, 70, 80, 20, 40, 60, 50]

pop()을 하면:

  1. 90이 반환될 값이다.
  2. 마지막 값 50을 루트로 올린다.
  3. 배열은 임시로 [50, 70, 80, 20, 40, 60]
  4. 루트 50은 자식 70, 80보다 작다.
  5. 둘 중 더 큰 80과 교환한다.
  6. 결과는 [80, 70, 50, 20, 40, 60]
  7. 다시 내려갈 수 있으면 계속 내려간다.

🧠 기억할 것

  • 힙 삽입: 아래에서 위로 고치기
  • 힙 삭제: 위에서 아래로 고치기

이 한 줄로 외우면 헷갈림이 많이 줄어든다.

힙의 활용

  • 우선순위 큐 구현
  • 힙 정렬
  • 가장 큰 값 / 가장 작은 값을 반복적으로 꺼내는 문제

4. 적용 포인트 / 종합 예시

이 섹션에서는 중복 코드를 다시 늘어놓기보다, 지금까지 배운 구조를 언제 어떤 관점으로 써야 하는지를 정리한다.

BST와 힙은 둘 다 트리인데, 왜 다르게 쓸까?

항목 BST 힙
목적 탐색을 빠르게 최대/최소를 빠르게
규칙 왼쪽 < 루트 < 오른쪽 부모와 자식만 대소 관계 유지
루트 의미 중간 기준점 항상 최대/최소
중위 순회 결과 오름차순 정렬 결과 아님
잘하는 일 값 찾기, 삽입, 삭제 우선순위 큐, 최대/최소 추출

📌 문제풀이에서 떠올리는 법

  • “어떤 값을 빨리 찾고 싶다” → BST 쪽 사고
  • “가장 큰 값 / 가장 작은 값을 계속 꺼내야 한다” → 힙 쪽 사고
  • “모든 경우를 보되 불필요한 길은 빨리 잘라야 한다” → 백트래킹 사고

같이 보면 더 잘 보이는 연결점

  • 백트래킹은 상태 공간을 트리처럼 탐색하는 사고다.
  • 이진 트리는 구조 자체를 배우는 단계다.
  • BST와 힙은 이진 트리 위에 목적별 규칙을 얹은 구조다.

즉, 트리 파트는 흩어진 내용이 아니라 기본 구조 → 규칙 추가 → 목적별 최적화로 이어진다.

5. 배운 점 / 느낀 점 / 확장 포인트

이번 강의 흐름에서 가장 중요한 것은 “트리는 모양만 배우는 자료구조가 아니다”라는 점이다. 같은 이진 트리라도 어떤 규칙을 얹느냐에 따라 완전히 다른 역할을 하게 된다.

  • 백트래킹은 트리를 실제로 저장하지 않아도, 문제를 트리처럼 바라보며 탐색을 최적화한다.
  • BST는 탐색을 빠르게 하기 위한 구조다.
  • 힙은 우선순위를 빠르게 처리하기 위한 구조다.

여기서 한 단계 더 공부해 볼 만한 주제는 다음과 같다.

  • BST의 한계를 보완하는 균형 이진 탐색 트리(AVL, Red-Black Tree)
  • 힙을 라이브러리로 다루는 Python heapq
  • 백트래킹에서 가지치기 조건을 더 강하게 만드는 방법

6. 요약 정리

📌 핵심

  • 백트래킹은 유망하지 않은 경로를 중간에 잘라내는 DFS다.
  • 트리는 계층 구조를 표현하는 기본 자료구조다.
  • 이진 트리는 자식이 최대 두 개인 트리다.
  • BST는 왼쪽 < 루트 < 오른쪽 규칙으로 탐색에 강하다.
  • 힙은 부모-자식 대소 관계만 유지하며 최대/최소 추출에 강하다.

🧠 기억할 것

  • BST 삭제는 자식 수 0개 / 1개 / 2개로 나눠서 본다.
  • 자식이 2개인 BST 삭제는 대체 노드를 올리고, 그 노드를 다시 삭제하는 문제다.
  • 힙 삽입은 맨 끝에 넣고 위로 올리기
  • 힙 삭제는 루트를 빼고 마지막 값을 올린 뒤 아래로 내리기
  • 힙은 정렬 트리가 아니라 루트 우선 구조다.
