## 1. 들어가며

이번 강의는 단순히 “재귀함수 문법”을 배우는 시간이 아니다.  
핵심은 **반복으로 만들던 구조를 재귀로 일반화하는 감각**을 익히고, 그 감각을 이용해 **모든 경우를 생성하는 완전탐색 코드**로 넘어가는 것이다.

처음 재귀를 배우면 보통 두 군데에서 막힌다.

- 함수가 **언제 끝나는지**가 잘 안 보이고
- 함수가 끝난 뒤에 **어디로 돌아오는지**가 머릿속에서 흐려진다.

그래서 강의도 바로 순열 코드부터 들어가지 않고, 먼저 함수 호출의 기본 성질부터 짚는다.  
값이 어떻게 전달되는지, 함수가 끝나면 어디로 복귀하는지, 기저조건이 왜 필요한지를 이해해야 뒤의 순열과 완전탐색 코드가 자연스럽게 읽힌다.

이번 노트는 그 흐름을 다음 순서로 정리한다.

1. 반복과 재귀는 어떻게 닮아 있는가
2. 재귀를 읽기 전에 알아야 할 함수 호출의 성질
3. 기저조건과 재귀트리의 구조
4. path를 이용한 중복순열과 순열 생성
5. 완전탐색 문제에서 재귀를 어떻게 적용하는가

즉, 이번 내용은 “재귀를 배운다”기보다,  
**재귀를 이용해 탐색 문제를 설계하는 출발점**을 만드는 시간이라고 보면 된다.

## 2. 핵심 개념 정리

이번 강의의 큰 줄기는 아래 다섯 가지로 잡을 수 있다.

### 2.1 반복과 재귀는 같은 구조를 다른 방식으로 표현한다

반복문은 같은 작업을 여러 번 수행하는 가장 익숙한 방법이다.  
그런데 반복문의 깊이가 늘어나거나, 선택의 개수가 입력에 따라 달라지기 시작하면 `for`문만으로는 코드가 급격히 불편해진다.

이때 재귀는 **“현재 단계에서 하나 고르고, 다음 단계로 넘긴다”**는 구조를 아주 자연스럽게 표현해 준다.

### 2.2 재귀를 이해하려면 함수 호출 자체를 먼저 이해해야 한다

재귀는 결국 함수가 자기 자신을 다시 부르는 것이다.  
그래서 먼저 알아야 하는 것은 재귀 문법이 아니라 **함수 호출의 기본 성질**이다.

- 인자로 넘긴 값은 어떻게 전달되는가
- 함수가 끝나면 어디로 복귀하는가
- 호출이 여러 번 쌓이면 어떤 순서로 돌아오는가

이 부분이 잡혀야 `append → recurse → pop` 구조도 이해된다.

### 2.3 기저조건은 재귀의 브레이크다

재귀는 편리하지만, 끝나는 조건이 없으면 무한히 호출된다.  
그래서 재귀에서는 반드시 **언제 멈출지**를 먼저 정해야 한다. 이것이 기저조건(base case)이다.

### 2.4 재귀는 트리처럼 생각하면 훨씬 쉽다

강의에서 계속 등장한 `Level`과 `Branch`라는 표현은 매우 중요하다.

- **Level**: 지금 몇 번째 선택까지 왔는가
- **Branch**: 이 단계에서 몇 가지 선택지가 있는가

이 관점으로 보면 재귀는 어렵게 꼬인 함수 호출이 아니라,  
**트리를 따라 내려가며 모든 경우를 만드는 과정**이 된다.

### 2.5 순열과 완전탐색은 재귀의 대표 응용이다

이번 강의의 후반부는 결국 하나의 흐름으로 이어진다.

- path에 선택 기록 남기기
- 끝 레벨에서 출력하기
- 중복을 허용하면 중복순열
- 중복을 막으면 순열
- 생성한 모든 경우를 검사하면 완전탐색

`📌 핵심`  
이번 강의의 핵심은 “재귀함수 하나 외우기”가 아니라, **선택을 누적하고, 끝에서 검사하는 탐색 구조**를 익히는 것이다.

## 3. 본문 정리

## 3.1 반복으로 하던 일을 재귀로 바꿔 보는 이유

재귀는 반복과 완전히 다른 세계처럼 보이지만, 실제로는 **반복문의 구조를 더 일반화한 표현**이라고 보는 편이 이해에 좋다.

강의의 첫 예시는 아주 단순하다.  
`1, 2, 3`으로 만들 수 있는 두 자릿수를 출력하는 문제는 2중 `for`문으로 쉽게 쓸 수 있다.

```python
for a in range(1, 4):
    for b in range(1, 4):
        print(a, b)
```

이 코드는 두 단계의 선택을 정확히 보여 준다.

- 첫 번째 자리에서 `1, 2, 3` 중 하나 선택
- 두 번째 자리에서 다시 `1, 2, 3` 중 하나 선택

여기까지는 반복문으로 충분하다.  
하지만 문제를 이렇게 바꾸면 어떨까?

- `N = 2`면 `11 ~ 33`
- `N = 3`이면 `111 ~ 333`
- `N = 4`이면 `1111 ~ 3333`
- ...

즉, **자리 수가 입력에 따라 바뀌는 구조**가 된다.  
이 순간부터는 `for`문을 몇 겹 써야 할지 미리 정할 수 없어서, 재귀 표현이 훨씬 자연스러워진다.

### 관련 코드: N중 반복을 재귀로 표현하기

```python
path = []
N = 3

def run(lev):
    if lev == N:
        print(path)
        return

    for i in range(1, 4):
        path.append(i)
        run(lev + 1)
        path.pop()

run(0)
```

### 코드 흐름 해설

이 코드는 사실상 `N`중 `for`문과 같은 역할을 한다.

- `lev`는 **현재 몇 번째 자리까지 채웠는지**를 뜻한다.
- `path`는 지금까지 고른 숫자들을 쌓아 두는 리스트다.
- `lev == N`이 되면 `N`자리를 다 채운 것이므로 출력하고 종료한다.
- 아직 덜 채웠다면 `1, 2, 3` 중 하나를 고르고 다음 단계로 내려간다.
- 내려갔다 돌아오면 `pop()`으로 방금 고른 값을 지우고 다음 선택지를 시도한다.

여기서 중요한 점은 `append()`와 `pop()`이 한 쌍으로 움직인다는 것이다.  
쉽게 말하면, **이번 단계에서 한 선택의 흔적을 남기고 내려갔다가, 돌아오면 그 흔적을 지우는 과정**이다.

⚠️ **주의**  
재귀를 처음 짤 때 가장 자주 하는 실수는 `pop()`을 빼먹는 것이다. 그러면 다음 경우를 만들어야 하는데 이전 선택이 그대로 남아서 path가 엉킨다.

`📌 핵심`  
재귀는 “현재 단계에서 하나 선택 → 다음 단계로 이동 → 돌아오면 선택 취소”의 반복으로 이해하면 훨씬 쉽다.

### 아주 간단한 재귀 예시: 0부터 10까지 출력

복잡한 조합 문제로 가기 전에, 가장 단순한 자기 호출 구조를 먼저 보는 것도 도움이 된다.

```python
# 0 ~ 10을 출력

def recur(num):
    if num > 10:
        return
    print(num, end=' ')
    recur(num + 1)

recur(0)
```

이 예시는 재귀에서 꼭 봐야 할 세 가지를 보여 준다.

1. **시작값**: `recur(0)`
2. **종료조건**: `if num > 10: return`
3. **다음 호출 규칙**: `recur(num + 1)`

재귀가 어려운 이유는 사실 복잡해서가 아니라, 이 세 요소 중 하나라도 빠지면 구조가 무너지기 때문이다.

## 3.2 재귀를 읽기 전에 꼭 알아야 할 함수 호출의 성질

재귀가 헷갈리는 가장 큰 이유는 함수가 자기 자신을 부른다는 점보다도,  
**함수 호출이 끝난 뒤의 흐름이 눈에 잘 안 보이기 때문**이다.

그래서 강의는 먼저 “보통 함수 호출”의 성질을 예시로 짚는다.

### 3.2.1 값 전달: 인자로 넘긴 정수는 복사되어 들어간다

아래 그림은 `main`의 값과 `KFC` 안의 값이 같은 이름처럼 보여도, 실제로는 별개의 흐름이라는 점을 강조한다.

![함수 인자 값 전달](assets/func_arg_copy.png)

관련 코드는 다음과 같다.

```python
def KFC(x):
    print(x)
    x += 1
    print(x)

x = 3
KFC(x + 1)
print(x)
```

### 코드 흐름 해설

- `x = 3`
- `KFC(x + 1)` 이므로 함수 안으로는 `4`가 전달된다.
- 함수 안에서 `print(x)`는 `4`
- `x += 1` 이후 `print(x)`는 `5`
- 함수가 끝난 뒤 바깥의 `x`는 여전히 `3`

즉, 바깥 `x`와 함수 안 `x`는 같은 이름처럼 보여도 **같은 칸을 공유하는 것이 아니다**.  
강의에서 든 비유처럼, 이름만 같을 뿐 서로 다른 사람이라고 이해하면 된다.

⚠️ **주의**  
이 감각이 없으면 재귀에서 “왜 바깥 값이 안 바뀌지?” 혹은 “왜 값이 자동으로 이어지지?” 같은 혼란이 생긴다.

`📌 핵심`  
재귀의 각 호출은 이름이 같아도 **각자 자기 지역 변수와 자기 흐름**을 가진다.

### 3.2.2 함수는 끝나면 main으로 돌아가는 것이 아니라, 자신을 호출한 자리로 돌아간다

재귀를 이해하려면 이 문장이 특히 중요하다. 함수는 막연히 “끝나면 처음으로 돌아가는 것”이 아니라,  
**자신을 호출했던 정확한 지점 다음 줄로 복귀**한다.

![호출한 자리로 복귀하는 흐름](assets/return_to_caller.png)

```python
def BBQ(x):
    x += 10
    print(x)

def KFC(x):
    print(x)
    x += 3
    BBQ(x + 2)
    print(x)

x = 3
KFC(x + 1)
print(x)
```

### 코드 흐름 해설

이 코드의 핵심은 `BBQ(x + 2)`가 끝난 뒤, 곧바로 `main`으로 가는 것이 아니라 **KFC 함수 안의 다음 줄**인 `print(x)`로 돌아온다는 점이다.

흐름을 순서대로 쓰면:

1. `x = 3`
2. `KFC(x + 1)` → `KFC(4)` 호출
3. KFC 안에서 `print(x)` → `4`
4. `x += 3` → KFC 안의 `x`는 `7`
5. `BBQ(x + 2)` → `BBQ(9)` 호출
6. BBQ 안에서 `x += 10` → `19`, 출력
7. BBQ 종료
8. 다시 KFC로 복귀해서 `print(x)` → `7`
9. KFC 종료
10. 마지막으로 main의 `print(x)` → `3`

이 복귀 흐름이 머릿속에 잡히면, 재귀도 똑같은 방식으로 이해할 수 있다.  
재귀도 결국은 “자기 자신을 호출한 함수”일 뿐이기 때문이다.

`📌 핵심`  
재귀는 신비한 문법이 아니라, **함수가 자기 자신을 호출하는 평범한 함수 호출**이다. 다만 그 호출이 여러 겹 쌓일 뿐이다.

## 3.3 기저조건: 재귀가 멈추는 지점이 먼저 보여야 한다

재귀 공부의 출발점은 “어떻게 더 내려갈까?”가 아니라,  
**어디서 멈출까?** 를 먼저 정하는 것이다.

강의에서는 아래 그림과 함께, 기저조건이 없으면 재귀는 끝나지 않는다는 점을 먼저 강조했다.

![기저조건이 있는 재귀 흐름](assets/base_case_flow.png)

여기서 핵심은 단순하다.

- 어떤 값에 도달하면 더 이상 호출하지 않고 `return`
- 그 지점이 재귀의 바닥
- 바닥에 닿아야 위로 되돌아오며 남은 코드가 실행됨

쉽게 말하면, 재귀는 계단을 내려가기만 하는 구조가 아니다.  
**내려가다가 멈추고, 그다음 다시 올라오는 구조**다.

이 감각은 뒤에서 `print()`가 재귀호출 **앞**에 있느냐, **뒤**에 있느냐에 따라 결과가 왜 달라지는지를 이해하는 데 바로 쓰인다.

`📌 핵심`  
재귀 코드에서 가장 먼저 찾아야 할 줄은 호출문이 아니라, **멈추는 조건**이다.

## 3.4 재귀호출이 하나일 때, 둘일 때, 셋일 때

강의는 재귀트리를 아주 직관적으로 보여 주기 위해, 같은 모양의 함수를 조금씩 바꿔 가며 설명한다.  
이 부분을 잘 이해하면 순열이나 DFS를 볼 때 훨씬 덜 막힌다.

### 3.4.1 재귀호출이 하나일 때

![재귀호출이 하나인 구조](assets/single_recursive_call.png)

이 경우는 한 단계에서 다음 단계로 한 번만 내려간다.  
즉, 가지가 하나뿐인 긴 사슬처럼 생각하면 된다.

### 3.4.2 재귀호출이 둘일 때

먼저 자세한 함수 상자 그림으로 보면 아래와 같다.

![재귀호출이 둘인 상세 그림](assets/two_recursive_calls_detailed.png)

이 흐름을 트리로 간단히 바꾸면 이렇게 볼 수 있다.

![재귀호출이 둘인 트리](assets/two_recursive_calls_tree.png)

그리고 충분히 익숙해지면, 아래처럼 더 단순한 트리만 보고도 구조를 떠올릴 수 있어야 한다.

![재귀호출이 둘인 단순 트리](assets/two_recursive_calls_simple_tree.png)

관련 코드는 다음과 같다.

```python
def KFC(x):
    if x == 2:
        return
    
    KFC(x + 1)
    KFC(x + 1)
    print(x)

KFC(0)
```

### 코드 흐름 해설

- `x == 2`가 되면 더 이상 내려가지 않고 종료한다.
- `x == 0`에서는 `KFC(1)`을 두 번 호출한다.
- 각 `KFC(1)`은 다시 `KFC(2)`를 두 번 호출하지만, `x == 2`에서는 바로 종료한다.
- 그래서 실제 출력은 **모든 하위 호출이 끝난 뒤** 위로 올라오면서 이뤄진다.

여기서 `print(x)`가 맨 아래에 있다는 점이 중요하다.  
그래서 출력은 **내려갈 때가 아니라 올라올 때** 발생한다.

### 3.4.3 재귀호출이 셋일 때

![재귀호출이 셋인 트리](assets/three_recursive_calls_tree.png)

```python
def KFC(x):
    if x == 2:
        return
    
    KFC(x + 1)
    KFC(x + 1)
    KFC(x + 1)

    print(x)

KFC(0)
```

이제 구조는 더 분명해진다.

- 한 단계에서 세 갈래로 뻗는다.
- 깊이는 `x == 2`까지이므로 총 두 단계 내려간다.
- 가지 수가 늘어날수록 전체 호출 수는 빠르게 많아진다.

즉, 재귀는 단순히 “함수를 다시 부른다”가 아니라,  
**각 레벨마다 여러 선택지가 있는 트리를 전부 탐색하는 방식**이라고 이해하는 편이 훨씬 정확하다.

### Level과 Branch로 읽기

강의에서는 이 구조를 **Level 3, Branch 4** 같은 식으로 설명했다. 이 표현은 뒤의 순열/완전탐색 코드에서 거의 그대로 쓰인다.

- **Level**: 몇 단계까지 내려갈 것인가
- **Branch**: 각 단계에서 몇 개 선택지가 있는가

재귀호출이 둘이면 Branch 2, 셋이면 Branch 3이다.  
그리고 기저조건이 어디서 멈추는지에 따라 트리의 높이, 즉 Level이 정해진다.

⚠️ **주의**  
노트의 예시 중 하나는 `print(0)`만 남아 있어 실행 예시가 다소 축약되어 있다. 실제 의도는 **한 함수가 일정 레벨까지 내려가며 여러 갈래를 탐색한다**는 구조를 보여 주는 데 있다.

`📌 핵심`  
재귀를 함수 호출로만 보면 헷갈리지만, **레벨과 가지를 가진 트리 탐색**으로 보면 훨씬 단순해진다.

## 3.5 path를 이용해 중복순열을 만드는 법

이제 재귀를 “호출 흐름”이 아니라 “경우의 수 생성기”로 쓰기 시작한다.  
여기서 가장 중요한 도구가 바로 `path`다.

중복순열은 **중복을 허용하고, 순서를 고려하는 나열**이다.  
예를 들어 `0, 1, 2` 세 장의 카드 중에서 두 장을 뽑는다면:

- `[0, 0]`, `[0, 1]`, `[0, 2]`
- `[1, 0]`, `[1, 1]`, `[1, 2]`
- `[2, 0]`, `[2, 1]`, `[2, 2]`

처럼 같은 숫자를 여러 번 써도 된다.

![카드 예시와 순열 결과](assets/permutation_cards_example.png)

강의에서는 중복순열 구현 원리를 두 줄로 정리했다.

1. 재귀호출을 할 때마다 이동 경로를 `path`에 남긴다.
2. 마지막 레벨에 도착했을 때 그 경로를 출력한다.

![중복순열 재귀트리](assets/duplicate_permutation_tree.png)

관련 코드는 다음과 같다.

```python
# 중복 순열
# [0, 1, 2] 3개의 카드가 존재 (2개를 뽑는 모든 경우)

path = []

def recur(cnt):
    if cnt == 2:
        print(path)
        return
    
    # 0을 선택
    path.append(0)
    recur(cnt + 1)
    path.pop()

    # 1을 선택
    path.append(1)
    recur(cnt + 1)
    path.pop()

    # 2를 선택
    path.append(2)
    recur(cnt + 1)
    path.pop()

recur(0)
```

같은 코드를 `for`문으로 일반화하면 훨씬 익숙한 형태가 된다.

```python
path = []

def KFC(x):
    if x == 2:
        print(path)
        return
    
    for i in range(3):
        path.append(i)
        KFC(x + 1)
        path.pop()

KFC(0)
```

### 코드 흐름 해설

- `cnt` 또는 `x`는 현재 몇 장을 골랐는지 뜻한다.
- 아직 두 장을 다 안 골랐다면 `0, 1, 2` 중 하나를 고른다.
- 고른 값을 `path`에 기록하고 다음 단계로 간다.
- 두 장을 다 골랐다면 `path` 자체가 하나의 완성된 경우가 된다.

여기서는 중복을 막는 장치가 없기 때문에, 첫 번째 자리에서 `0`을 골랐더라도 두 번째 자리에서 또 `0`을 고를 수 있다.  
그것이 바로 중복순열이다.

### 전역 path 없이 쓰는 방식

강의 노트에는 심화 버전도 있었다.

```python
def recur2(cnt, p):
    if cnt == 2:
        print(*p)
        return 
    
    for i in range(3):
        recur2(cnt + 1, p + [i])

recur2(0, [])
```

이 방식은 전역 변수를 줄일 수 있다는 장점이 있지만, 매 호출마다 새 리스트를 만들어 넘긴다는 점도 함께 알아 두면 좋다.  
처음에는 `append/pop` 방식이 재귀 흐름을 이해하는 데 더 직관적이다.

⚠️ **주의**  
중복순열 코드를 볼 때 “왜 path를 출력하고 끝내지?”가 아니라, **path가 이미 한 경우의 수를 완성했기 때문**이라는 점을 먼저 떠올리면 훨씬 이해가 쉽다.

`📌 핵심`  
중복순열의 본질은 “매 레벨마다 모든 숫자를 다시 고를 수 있다”는 데 있다.

## 3.6 중복을 제거하면 순열이 된다

순열은 **중복 없이, 순서를 고려한 나열**이다.  
즉, 중복순열과 구조는 거의 같지만 한 가지 조건이 더 붙는다.

> **이미 사용한 숫자는 다음 레벨에서 다시 고를 수 없어야 한다.**

강의에서는 이 조건을 `used` 배열로 관리했다.

![used 배열로 중복 제거하기](assets/permutation_used_array.png)

### 관련 코드: used 배열을 이용한 순열

```python
path = []
used = [False, False, False]

def KFC(x):
    if x == 2:
        print(*path)
        return
    
    for i in range(3):
        if used[i] == True:
            continue
        used[i] = True
        path.append(i)
        KFC(x + 1)
        path.pop()
        used[i] = False

KFC(0)
```

### 코드 흐름 해설

이 코드는 중복순열 코드에 딱 한 가지 규칙을 추가한 것이다.

- `used[i] == True`면 이미 쓴 숫자이므로 건너뛴다.
- 아직 안 쓴 숫자라면 선택하고 `used[i] = True`로 표시한다.
- 하위 호출이 끝나고 돌아오면 `path.pop()`으로 선택을 지우고
- `used[i] = False`로 사용 기록도 되돌린다.

이 마지막 되돌리기가 바로 **백트래킹(backtracking)** 의 핵심이다.  
쉽게 말하면, “이번 가지에서 쓴 흔적을 지우고 옆 가지를 탐색할 준비를 하는 과정”이다.

### 중복순열과 순열의 차이 한 줄 정리

- **중복순열**: 매번 모든 숫자를 다시 선택 가능
- **순열**: 이미 고른 숫자는 다음 선택에서 제외

### 확장 예시: 1~6 중 3개 고르기

강의 후반에는 더 일반적인 형태의 코드도 나온다.

```python
arr = [1, 2, 3, 4, 5, 6]
N = 3

selected = [0] * len(arr)

def perm(i, path, selected):
    if i == N:
        print(path)
        return
    
    for j in range(len(arr)):
        if not selected[j]:
            path.append(arr[j])
            selected[j] = 1
            perm(i + 1, path, selected)
            path.pop()
            selected[j] = 0

perm(0, [], selected)
```

💡 **포인트**  
원본 노트의 코드에는 `if not selected:`처럼 적힌 부분이 있었는데, 의도상 `if not selected[j]:`로 읽는 것이 맞다.  
이런 부분도 재귀를 공부할 때 좋은 점검 포인트다. **“전체 배열이 아니라, 지금 보려는 원소 하나를 검사해야 한다”** 는 감각이 중요하다.

⚠️ **주의**  
순열 코드에서 가장 자주 생기는 버그는 아래 두 가지다.

- `used`를 `True`로 바꾸고, 돌아올 때 `False`로 되돌리지 않음
- `path.pop()`과 `used` 초기화의 순서를 헷갈림

`📌 핵심`  
순열은 중복순열에서 멀리 떨어진 별개의 개념이 아니라, **중복순열 + 사용 체크**로 이해하면 훨씬 쉽다.

## 3.7 완전탐색: 모든 경우를 만들고, 조건에 맞는지 검사한다

이제 재귀는 단순 출력 도구가 아니라 **정답 후보를 전부 생성하는 탐색 도구**가 된다.  
이것이 바로 완전탐색(Brute Force)의 핵심이다.

완전탐색은 말 그대로 **가능한 모든 경우를 시도해서 정답을 찾는 방법**이다.  
자전거 열쇠 비밀번호를 하나씩 전부 눌러 보는 비유가 딱 맞다.

강의에서 중요한 포인트는 두 가지였다.

1. 먼저 모든 경우를 생성하는 코드를 만든다.
2. 완성된 경우마다 정답 조건을 검사한다.

즉, 순열/중복순열 코드는 단순한 출력 연습이 아니라,  
**완전탐색 문제의 골격** 그 자체다.

---

## 3.8 완전탐색 문제 1: 주사위 눈의 합이 10 이하인 경우의 수

문제는 다음과 같다.

- 주사위 3개를 던진다.
- 나올 수 있는 모든 중복순열을 고려한다.
- 세 눈의 합이 10 이하인 경우는 몇 가지인가?

여기서 중요한 점은 단순 출력이 아니라, **선택하면서 누적합도 함께 들고 간다**는 것이다.

### 관련 코드

```python
path = []
cnt = 0

def kfc(x, sum):
    global cnt
    if sum > 10:
        return
    
    if x == 3:
        cnt += 1
        return
    
    for i in range(1, 7):
        path.append(i)
        kfc(x + 1, sum + i)
        path.pop()

kfc(x = 0, sum = 0)
print(cnt)
```

### 코드 흐름 해설

- `x`는 몇 번째 주사위까지 골랐는지
- `sum`은 지금까지 나온 눈의 합
- 합이 이미 `10`을 넘으면 더 볼 필요가 없으니 즉시 `return`
- 주사위 3개를 다 골랐다면 하나의 완성된 경우이므로 `cnt += 1`

여기서 눈여겨볼 점은 `sum > 10`인 순간 바로 돌아간다는 것이다.  
이것은 단순히 출력만 생략하는 것이 아니라, **그 아래의 하위 경우 전체를 잘라내는 가지치기**다.

쉽게 말하면, 이미 답이 될 수 없는 길로 들어갔으면 더 내려갈 필요가 없다는 뜻이다.

### 왜 이 코드가 중요한가

이 문제는 재귀의 확장을 잘 보여 준다.

- path만 들고 다니면 “무엇을 골랐는지”를 기록하는 코드
- 여기에 `sum`을 더하면 “지금 상태가 어떤지”까지 함께 관리하는 코드

즉, 완전탐색에서는 **선택 기록(path)** 과 **상태 정보(sum, cnt, score 등)** 를 함께 다루는 경우가 많다.

`📌 핵심`  
완전탐색은 모든 경우를 보되, **이미 불가능한 경우는 빨리 되돌아오는 가지치기**가 성능에 큰 차이를 만든다.

---

## 3.9 완전탐색 문제 2: 같은 카드가 연속 3장 나오는 경우 세기

문제는 다음과 같다.

- 카드 종류는 `A, J, Q, K` 네 가지
- 이 중 5장을 뽑아 나열
- 같은 종류의 카드가 **연속으로 3장** 나오는 경우의 수는?

이 문제도 기본 구조는 동일하다.

1. 길이 5인 모든 중복순열 생성
2. 완성된 path가 조건을 만족하는지 검사

### 관련 코드

```python
card = ['A', 'J', 'Q', 'K']
path = []
cnt = 0

def cont_three():
    if path[0] == path[1] == path[2]: return True
    if path[1] == path[2] == path[3]: return True
    if path[2] == path[3] == path[4]: return True
    return False

def permu(lev):
    global cnt
    if lev == 5:
        if cont_three():
            cnt += 1
        return
    
    for i in range(4):
        path.append(card[i])
        permu(lev + 1)
        path.pop()

permu(0)
print(cnt)
```

### 코드 흐름 해설

- `lev == 5`가 되면 카드 5장을 모두 뽑은 상태다.
- 이때 `cont_three()`로 세 칸 연속 같은 카드가 있는지 검사한다.
- 조건을 만족하면 `cnt += 1`

이 문제의 포인트는 검사 함수가 별도로 분리되어 있다는 점이다.  
완전탐색 문제를 풀 때 자주 쓰는 패턴이 바로 이것이다.

- **생성하는 함수**와
- **검사하는 함수**를 나눈다.

그러면 코드가 훨씬 읽기 쉬워지고, 디버깅도 편해진다.

⚠️ **주의**  
이런 문제에서는 “연속 3장”이므로, 검사 구간이 `[0:3]`, `[1:4]`, `[2:5]` 세 군데라는 점을 놓치기 쉽다.  
조건을 글로 읽고 바로 코드로 옮기기보다, 먼저 인덱스로 써 보는 습관이 좋다.

`📌 핵심`  
완전탐색 문제는 보통 **생성 + 검사** 구조로 나누어 생각하면 훨씬 정리된다.

## 3.10 완전탐색 문제 3: Baby-gin은 어떻게 접근할까

강의 마지막 문제는 Baby-gin이다.

- 0 이상 9 이하 숫자가 적힌 6장의 카드
- 3장이 연속 수면 `run`
- 3장이 모두 같으면 `triplet`
- 6장이 `run`과 `triplet`의 조합으로만 이루어지면 Baby-gin

이 문제에서 강의가 전달하려는 핵심은, 정답 코드를 당장 외우는 것이 아니라 **접근 순서**를 잡는 것이다.

### 접근 흐름

1. 6장의 카드로 만들 수 있는 **모든 순서**를 나열한다.
2. 각 순서에 대해
   - 앞의 3장이 run 또는 triplet인지
   - 뒤의 3장이 run 또는 triplet인지
   검사한다.
3. 하나라도 조건을 만족하면 Baby-gin이다.

여기서 중요한 점은, Baby-gin이라는 특별한 문제도 결국은 같은 틀 안에 있다는 것이다.

- 순열 생성
- 완성된 경우 검사
- 조건 만족 여부 판단

즉, 앞에서 배운 재귀 구조가 그대로 문제 해결의 뼈대가 된다.

💡 **포인트**  
Baby-gin은 나중에 카운팅 배열로 더 효율적으로 푸는 방법도 배우게 되지만, 이 강의에서는 먼저 **완전탐색 관점에서 문제를 해체하는 힘**을 익히는 것이 더 중요하다.

`📌 핵심`  
완전탐색 문제의 핵심은 “공식”보다, **모든 경우를 어떻게 만들고 어떤 조건으로 검사할지 분리해서 생각하는 습관**이다.

이제 본문 내용을 실제 문제풀이 관점에서 다시 묶어 보면, 이번 강의에서 챙겨야 할 신호는 꽤 분명하다.

### 4.1 언제 재귀를 떠올리면 좋을까

아래와 같은 표현이 보이면 재귀 기반 완전탐색을 의심해 볼 수 있다.

- 길이가 `N`인 모든 수열
- 카드 `R`장을 뽑는 모든 경우
- 가능한 모든 순서
- 모든 조합 / 모든 배치 / 모든 경우의 수
- 조건을 만족하는 경우가 몇 개인가

이런 문제는 대부분 “현재 하나 고르고, 다음 자리로 간다” 구조로 바꿀 수 있다.

### 4.2 구현 순서를 어떻게 잡으면 좋을까

실전에서는 아래 순서가 안정적이다.

1. **Level**이 무엇인지 정한다.  
   - 몇 번째 선택까지 했는가?
2. **Branch**가 몇 개인지 정한다.  
   - 이 단계에서 몇 가지를 고를 수 있는가?
3. **기저조건**을 먼저 쓴다.  
   - 언제 출력/검사/카운트할 것인가?
4. `append → 재귀호출 → pop` 구조를 만든다.
5. 필요하면 `used`, `sum`, `cnt` 같은 상태를 추가한다.

이 순서가 중요한 이유는, 재귀 문제는 코드보다 먼저 **트리 구조가 머릿속에 있어야** 하기 때문이다.

### 4.3 어떤 신호를 보면 중복 제거가 필요할까

문제에서 아래 표현이 나오면 `used` 또는 `visited`가 필요할 가능성이 크다.

- 서로 다른 숫자
- 한 번 뽑은 것은 다시 사용 불가
- 중복 없이 나열
- 순열

반대로 아래 표현이면 중복순열 쪽에 가깝다.

- 중복 허용
- 같은 숫자를 여러 번 사용 가능
- 주사위를 여러 번 던짐
- 카드가 충분히 많이 존재

### 4.4 가지치기는 언제 넣어야 할까

가지치기는 **정답이 될 수 없는 경우를 빨리 포기하는 규칙**이다.

예를 들어 주사위 합 문제에서는:

- 현재 합이 이미 10을 넘었다면
- 앞으로 무엇을 더 골라도 다시 10 이하가 될 수 없다.

이런 경우는 바로 `return` 하면 된다.

즉, 가지치기는 “더 내려가도 답이 안 된다”는 사실을 **현재 단계에서 알 수 있을 때** 넣는 것이다.

### 4.5 자주 하는 실수 패턴

- 기저조건보다 재귀호출을 먼저 써서 무한 호출 발생
- `append()`만 하고 `pop()`을 안 해서 path 꼬임
- `used[i] = True`만 하고 `False`로 복원하지 않음
- 검사 함수를 분리하지 않아 코드가 길어지고 디버깅이 어려워짐
- 중복순열과 순열의 차이를 헷갈려서 `used`를 넣어야 할 문제에 안 넣음

`🧠 기억할 것`  
재귀 문제를 만나면 곧바로 코드부터 쓰기보다, 먼저 **트리를 그려 보고 Level / Branch / 종료조건 / 상태 정보**를 적는 편이 훨씬 안전하다.

## 5. 배운 점 / 느낀 점 / 확장 포인트

이번 강의의 가장 큰 수확은, 재귀를 단순한 문법이 아니라 **탐색 구조를 표현하는 언어**로 보기 시작했다는 점이다.

처음에는 재귀가 막연히 어려워 보이지만, 이번 흐름을 따라가 보면 사실 핵심은 몇 가지로 압축된다.

- 함수 호출의 복귀 흐름을 이해한다.
- 언제 멈출지 먼저 정한다.
- 한 단계의 선택을 `path`에 기록한다.
- 하위 호출이 끝나면 선택 흔적을 지운다.
- 완성된 경우에서 검사한다.

이 다섯 가지가 잡히면 이후의 학습도 자연스럽게 이어진다.

- **DFS**: 그래프/트리 탐색으로 확장
- **백트래킹**: 불필요한 경우를 더 적극적으로 가지치기
- **조합 / 부분집합**: 선택 구조를 조금씩 바꾼 문제
- **최적화 문제**: 모든 경우를 보되, 조건에 따라 잘라내는 문제

즉, 이번 강의는 한 번 배우고 끝나는 재귀 문법 수업이 아니라,  
이후 탐색 단원의 공통 뼈대를 미리 익히는 시간이라고 볼 수 있다.

## 6. 요약 정리

- `for`문의 깊이가 입력에 따라 달라질 때, 재귀가 훨씬 자연스럽다.
- 재귀를 이해하려면 먼저 **인자 전달**과 **호출한 자리로 복귀하는 흐름**을 알아야 한다.
- 기저조건은 재귀의 시작점이 아니라 **브레이크**다.
- 재귀는 함수 호출로도 볼 수 있지만, **Level과 Branch를 가진 트리 탐색**으로 보면 더 이해하기 쉽다.
- `path`는 지금까지의 선택 기록이다.
- 중복순열은 **매 레벨에서 모든 선택 허용**, 순열은 **used 배열로 중복 제거**다.
- 완전탐색은 **경우 생성 + 조건 검사**의 구조로 정리하면 깔끔하다.
- 가지치기는 “더 봐도 답이 안 되는 경우”를 빨리 끊는 기술이다.

### 📌 핵심

재귀의 본질은 자기 자신을 부르는 데 있지 않다.  
**선택을 누적하고, 끝에 도달하면 검사하고, 돌아오며 흔적을 지우는 탐색 구조**를 만드는 데 있다.

### 🧠 기억할 것

재귀 문제를 만나면 아래 네 줄부터 떠올리자.

1. 종료조건은 무엇인가?
2. 현재 단계(Level)는 무엇인가?
3. 이 단계의 선택지(Branch)는 몇 개인가?
4. 어떤 상태(path, used, sum)를 들고 내려가야 하는가?
