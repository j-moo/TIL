1. 들어가며

이 글에서는 Brute Force(완전탐색) 와 Greedy(탐욕 알고리즘) 의 기초를 함께 정리한다.
처음 보면 두 방식은 서로 정반대처럼 보인다.

  • 완전탐색은 가능한 경우를 전부 보려는 방식
  • Greedy는 매 순간 가장 좋아 보이는 선택을 하는 방식

이 둘을 함께 배우는 이유는 분명하다.
문제를 만났을 때 “전부 봐야 하는 문제인지”, 아니면 “규칙을 찾고 빠르게 결정해도 되는 문제인지” 를 구분할 수 있어야 하기 때문이다.

이번 강의에서는 특히 다음 흐름이 중요했다.

  1. 부분집합을 만드는 방법을 이해한다.
  2. 그 과정에서 재귀 호출과 비트 연산이 어떻게 쓰이는지 익힌다.
  3. 조합을 만들 때 왜 단순 for문보다 재귀가 자연스러운지 이해한다.
  4. 마지막으로 Greedy가 성립하려면 어떤 조건이 필요한지 정리한다.

💡 포인트는 단순히 코드를 외우는 것이 아니라,
문제를 보고 어떤 방식으로 접근해야 할지 판단하는 기준을 만드는 데 있다.

2. 핵심 개념 정리

이 섹션에서는 강의 전체를 관통하는 핵심 개념을 먼저 정리한다.

2-1. 조합적 문제란?

조합적 문제는 말 그대로 가능한 선택의 조합이 매우 많이 생기는 문제를 뜻한다.
예를 들어, 어떤 원소를 뽑을지 말지 결정하거나, 여러 명 중 일부를 고르거나, 가능한 순서를 모두 따져보는 문제가 여기에 해당한다.

이런 문제는 보통 다음 질문으로 이어진다.

  • 가능한 경우를 전부 만들어야 하는가?
  • 전부 만들지 않고도 규칙적으로 줄일 수 있는가?

2-2. 부분집합

부분집합은 어떤 집합에서 만들 수 있는 모든 하위 집합을 의미한다.
공집합과 자기 자신도 부분집합에 포함된다.

원소 개수가 n개라면, 각 원소는 두 가지 상태를 가진다.

  • 포함한다
  • 포함하지 않는다

즉, 원소마다 선택지가 2개씩 있으므로 전체 부분집합의 수는 다음과 같다.

$$2^n$$

예를 들어 원소가 3개라면 부분집합 수는 2^3 = 8개가 된다.

2-3. 부분집합을 구하는 대표 방법

방법 핵심 아이디어 장점 주의할 점
완전탐색(재귀) 각 원소를 넣을지/말지 재귀적으로 결정 구조를 이해하기 쉽다 경우의 수가 많아지면 느려진다
Binary Counting 비트열로 포함 여부를 표현 구현이 짧고 모든 부분집합 생성에 적합 비트 의미를 정확히 이해해야 한다

2-4. 조합

조합은 서로 다른 n개의 원소 중 r개를 순서 없이 고르는 것이다.

순열과의 차이를 같이 기억하면 헷갈리지 않는다.

  • 순열: 순서가 중요함
  • 조합: 순서가 중요하지 않음

공식은 다음과 같다.

  • 순열
    $$ _nP_r = \frac{n!}{(n-r)!} $$

  • 조합
    $$ _nC_r = \frac{n!}{(n-r)!r!} $$

2-5. Greedy

Greedy는 매 순간 현재 기준으로 가장 좋아 보이는 선택을 하는 알고리즘이다.

하지만 여기서 가장 중요한 사실은 다음이다.

⚠️ 지금 좋아 보이는 선택이 항상 전체 최적해로 이어지는 것은 아니다.

그래서 Greedy를 적용할 때는 감으로 풀면 안 되고, 반드시 아래 조건을 확인해야 한다.

  1. 탐욕적 선택 속성 (Greedy Choice Property)
    현재의 최선 선택이 이후 선택에 악영향을 주지 않아야 한다.

  2. 최적 부분 구조 (Optimal Substructure)
    각 단계의 최선 선택을 쌓았을 때 전체 최적해가 되어야 한다.

  3. 반례가 없는지 확인
    작은 예시라도 깨지는 경우가 있으면 Greedy는 위험하다.

📌 핵심은 이거다.
앞부분의 Brute Force는 모든 경우를 만들어보는 안전한 접근,
뒷부분의 Greedy는 성립 조건이 맞을 때만 빠르게 쓰는 접근이다.

3. 본문 정리

이 섹션에서는 강의 흐름에 맞춰 부분집합 → Binary Counting → 조합 → Greedy 순서로 내용을 정리한다.

3-1. 완전탐색으로 부분집합 감각 잡기

처음 부분집합을 배울 때는 원소 자체보다 선택의 구조를 보는 것이 더 중요하다.
예를 들어 친구 3명이 있을 때, 각 친구는 다음 두 상태 중 하나를 가진다.

  • 같이 간다
  • 같이 가지 않는다

즉, 친구 1명마다 선택지가 2개이고, 총 3명을 결정하므로 트리 관점에서 보면 다음과 같다.

  • Branch = 2
  • Level = 3

이 관점이 중요한 이유는 나중에 재귀를 볼 때
“왜 함수가 두 갈래로 계속 뻗어 나가는지”를 직관적으로 이해할 수 있기 때문이다.

# 예시 1) O / X 선택으로 부분집합 구조를 눈으로 확인하기

# 각 단계에서 할 수 있는 선택
choices = ['O', 'X']

# 현재까지 선택한 결과를 저장할 리스트
path = []

def recur(depth):
    # depth가 3이라는 것은 친구 3명에 대한 선택이 모두 끝났다는 뜻
    if depth == 3:
        # 지금까지 만든 한 가지 경우의 수를 출력
        print(*path)
        return

    # 1) 현재 친구를 포함하는 경우
    path.append(choices[0])      # 'O'를 추가해서 포함 상태를 기록
    recur(depth + 1)             # 다음 친구 선택으로 이동
    path.pop()                   # 다음 경우를 위해 방금 선택을 되돌림

    # 2) 현재 친구를 포함하지 않는 경우
    path.append(choices[1])      # 'X'를 추가해서 미포함 상태를 기록
    recur(depth + 1)             # 다음 친구 선택으로 이동
    path.pop()                   # 백트래킹으로 상태 복원

# 0번째 친구부터 선택 시작
recur(0)

코드 흐름 해설

이 코드는 부분집합의 본질을 아주 단순하게 보여준다.

  • 한 단계(depth)는 한 명의 친구를 결정하는 순간
  • 각 단계의 선택지는 포함(O) / 미포함(X)
  • 끝까지 내려가면 하나의 경우의 수가 완성된다

즉, 이 코드는 실제 원소를 출력하는 코드라기보다
부분집합 생성의 트리 구조를 보여주는 학습용 코드로 이해하면 좋다.

⚠️ 주의할 점

  • append() 한 뒤에는 반드시 pop() 으로 되돌려야 한다.
  • 종료 조건이 없으면 재귀가 끝나지 않는다.
  • depth == 3은 친구 수가 3명이라는 문제 조건과 연결된다.

3-2. 실제 원소를 사용해 부분집합 만들기

이제는 O/X 대신 실제 원소를 넣어서 부분집합을 만든다.
핵심 아이디어는 같다.

  • 현재 원소를 선택한다
  • 현재 원소를 선택하지 않는다

이 두 갈래를 재귀적으로 반복하면 된다.

# 예시 2) 실제 원소를 이용해 부분집합 생성하기

arr = [1, 2, 3]
N = len(arr)

def subset(i, selected):
    # i가 N이 되면 모든 원소에 대해 포함/미포함 결정이 끝난 상태
    if i == N:
        print(selected)
        return

    # 1) arr[i]를 부분집합에 포함하는 경우
    selected.append(arr[i])      # 현재 원소를 선택
    subset(i + 1, selected)      # 다음 원소 판단
    selected.pop()               # 다른 경우를 위해 원상 복구

    # 2) arr[i]를 부분집합에 포함하지 않는 경우
    subset(i + 1, selected)      # 선택하지 않고 다음 원소 판단

# 아직 아무 원소도 고르지 않은 상태에서 시작
subset(0, [])

왜 이 방식이 중요한가?

이 코드는 부분집합 문제를 풀 때 가장 기본이 되는 형태다.
특히 DFS, 백트래킹, 조합 생성 문제로 확장될 때 거의 같은 구조가 반복된다.

💡 포인트

  • i는 지금 판단 중인 원소의 인덱스
  • selected는 지금까지 고른 원소들
  • 각 원소마다 선택지는 정확히 2가지

즉, 부분집합 문제는 본질적으로 이진 선택의 반복이라고 볼 수 있다.

⚠️ 자주 하는 실수

  1. N과 실제 배열 길이가 다르게 설정되는 경우
  2. append() 후 pop() 을 빼먹는 경우
  3. 종료 조건을 if i == N: 대신 애매하게 잡아서 일부 경우가 누락되는 경우

3-3. Binary Counting으로 부분집합 만들기

재귀가 부분집합의 구조를 이해하는 데 좋다면,
Binary Counting은 모든 부분집합을 깔끔하게 생성하는 데 실용적이다.

아이디어는 간단하다.

원소가 n개라면 길이 n의 비트열을 생각한다.

  • 비트가 1이면 포함
  • 비트가 0이면 미포함

예를 들어 원소가 [A, B, C]일 때,

  • 001 → {A}
  • 110 → {B, C}

처럼 표현할 수 있다.

또한 부분집합의 총개수 2^n은 비트 시프트로 1 << n 으로 표현할 수 있다.

# 예시 3) Binary Counting으로 모든 부분집합 출력하기

arr = [1, 2, 3, 4]
n = len(arr)

def get_subsets():
    # 0부터 (2^n - 1)까지의 수를 부분집합 번호로 사용
    for mask in range(1 << n):
        # mask의 각 비트를 확인해서 원소 포함 여부 판단
        for idx in range(n):
            # idx번째 비트가 1이면 arr[idx]를 현재 부분집합에 포함
            if mask & (1 << idx):
                print(arr[idx], end=' ')
        print()

get_subsets()

Binary Counting 해설

이 방식은 각 숫자를 하나의 부분집합 설계도(mask) 로 본다는 점이 핵심이다.

예를 들어 mask = 5이면 이진수로 0101이다.
그러면

  • 0번 비트가 1 → arr[0] 포함
  • 1번 비트가 0 → arr[1] 미포함
  • 2번 비트가 1 → arr[2] 포함
  • 3번 비트가 0 → arr[3] 미포함

이런 식으로 해석할 수 있다.

📌 핵심

  • 1 << n → 전체 부분집합 개수
  • mask & (1 << idx) → idx번째 원소 포함 여부 확인

⚠️ 주의할 점

  • 비트의 순서와 배열 인덱스를 헷갈리지 않기
  • n이 커질수록 부분집합 수가 급격히 증가한다는 점 기억하기
    (O(n * 2^n) 수준)

3-4. 조합: 부분집합과 비슷하지만 목표가 다르다

조합은 부분집합과 닮아 있지만, 중요한 차이가 있다.
부분집합은 모든 선택 결과를 다 만들지만, 조합은 그중에서도 원소 개수가 정확히 R개인 경우만 필요하다.

예를 들어 5명 중 3명을 뽑는다면,

  • [1, 2, 3] 과 [3, 2, 1] 은 같은 조합이다.
  • 즉, 순서는 의미가 없다.

여기서 자연스럽게 재귀가 필요해진다.
5명 중 3명 정도는 3중 for문으로도 만들 수 있지만,
“n명 중 r명”처럼 일반화하면 중첩 for문 개수를 고정할 수 없기 때문이다.

3-5. 부분집합 방식으로 조합 만들기

아래 코드는 부분집합을 생성하는 구조를 유지하되,
선택한 원소 수가 R개가 되면 출력하는 방식이다.

arr = [1, 2, 3, 4, 5]
N = 5
R = 3

def subset_comb(i, selected, cnt):
    # 이미 R개를 골랐다면 하나의 조합 완성
    if cnt == R:
        print(selected)
        return

    # 모든 원소를 다 확인했는데도 R개를 못 채웠다면 종료
    if i == N:
        return

    # 1) 현재 원소를 고르는 경우
    subset_comb(i + 1, selected + [arr[i]], cnt + 1)

    # 2) 현재 원소를 고르지 않는 경우
    subset_comb(i + 1, selected, cnt)

subset_comb(0, [], 0)

코드 해설

이 방식은 “부분집합 생성”을 약간 바꿔서 “조합 생성”으로 확장한 형태다.

  • i : 지금 보고 있는 원소의 인덱스
  • selected : 현재까지 고른 원소들
  • cnt : 현재까지 고른 개수

cnt == R 이 되면 더 이상 뒤를 볼 필요 없이 바로 출력할 수 있다는 점이 포인트다.

💡 장점
부분집합 코드와 구조가 비슷해서 이해하기 쉽다.

⚠️ 아쉬운 점
조합만 필요해도 여전히 “고른다 / 안 고른다” 두 갈래를 모두 타기 때문에
불필요한 분기가 꽤 생길 수 있다.

3-6. 시작 인덱스를 이용한 정석적인 조합 생성

조합에서는 순서가 중요하지 않기 때문에,
이미 앞에서 고른 원소보다 뒤쪽 원소만 고르게 제한하면 중복을 자연스럽게 막을 수 있다.

arr = [1, 2, 3, 4, 5]
N = 5
R = 3

def comb(cnt, selected, start):
    # R개를 모두 고르면 하나의 조합 완성
    if cnt == R:
        print(selected)
        return

    # start부터 끝까지 보면서 다음 원소 선택
    for i in range(start, N):
        # arr[i]를 고르고, 다음 선택은 i+1 이후에서만 가능하도록 제한
        comb(cnt + 1, selected + [arr[i]], i + 1)

# 아직 아무것도 고르지 않았고, 0번 인덱스부터 선택 가능
comb(0, [], 0)

왜 start가 중요한가?

start는 조합 문제에서 정말 자주 쓰이는 장치다.

예를 들어 [1, 2]를 이미 골랐다면 다음에는 3, 4, 5 ... 처럼
뒤의 원소만 보도록 제한해야 한다.

이렇게 해야

  • [1, 2, 3]
  • [2, 1, 3]

처럼 순서만 다른 중복 결과를 막을 수 있다.

📌 핵심 비교

방식 특징 추천 상황
부분집합 기반 조합 이해하기 쉽다 개념 학습용
start 기반 조합 중복 없이 깔끔하다 실전 구현용

3-7. 이제 Greedy로 넘어가기

앞에서는 가능한 경우를 만들어 보는 방식이었다면,
Greedy는 반대로 지금 가장 좋아 보이는 선택만 빠르게 고르는 방식이다.

대표적인 문제 해결 기법을 비교하면 다음과 같다.

기법 핵심 아이디어
완전탐색 가능한 모든 경우를 시도
Greedy 매 순간 가장 좋아 보이는 선택
DP 과거 계산 결과를 이용해 현재 최적값 구성
분할정복 큰 문제를 작은 문제로 나눠 해결

여기서 Greedy는 가장 단순해 보이지만, 사실 가장 조심해서 써야 한다.

4. 적용 / 예시 / 코드 해설

이 섹션에서는 강의에서 다룬 개념을 실제 문제 풀이 관점으로 연결해본다.

4-1. 완전탐색이 필요한 순간

다음과 같은 상황에서는 완전탐색 쪽으로 먼저 생각하는 것이 안전하다.

  • 가능한 경우가 많지 않다
  • 정답 조건을 정확히 판별할 수 있다
  • 규칙이 바로 보이지 않는다
  • Greedy 반례가 쉽게 떠오른다

예를 들어 부분집합, 조합, 비트마스킹 문제는
“모든 경우를 만들어 보고 조건에 맞는 답을 찾는 방식”이 자주 쓰인다.

4-2. Greedy는 언제 가능한가?

Greedy는 단순히 “지금 제일 좋아 보이니까” 고르면 되는 것이 아니다.
다음 두 조건이 맞아야 한다.

(1) 탐욕적 선택 속성

현재 단계에서의 최선 선택이 이후 단계의 정답 가능성을 해치지 않아야 한다.

(2) 최적 부분 구조

현재 단계까지의 최선 선택을 쌓아 갔을 때, 전체 문제의 최적해가 되어야 한다.

즉, 지역 최적해(local optimum) 가 전역 최적해(global optimum) 로 이어져야 한다.

4-3. 동전 거스름돈 문제로 보는 Greedy 감각

동전 단위가 500원, 100원, 50원, 10원처럼 배수 관계를 잘 이루고 있다면
가장 큰 동전부터 고르는 전략이 자연스럽게 맞아떨어진다.

이 경우에는

  • 큰 동전을 최대한 많이 쓰는 것이
  • 전체 동전 수를 줄이는 데 유리하고
  • 이후 선택에도 큰 손해를 주지 않는다

그래서 Greedy가 잘 작동한다.

하지만 동전 체계가 바뀌면 이야기가 달라진다.
예를 들어 동전이 10, 6, 1이고 목표가 12라면,

  • Greedy: 10 + 1 + 1 → 3개
  • 최적해: 6 + 6 → 2개

이처럼 반례가 하나라도 있으면 Greedy를 그대로 믿으면 안 된다.

⚠️ 주의
“왠지 가장 큰 것부터 고르면 될 것 같다”는 느낌만으로는 부족하다.
반드시 왜 항상 맞는지 설명 가능해야 한다.

4-4. 코드 관점에서 기억할 포인트

부분집합/조합 재귀 코드에서 반복적으로 등장하는 핵심은 다음이다.

  1. 종료 조건이 분명해야 한다
  2. 현재 상태를 저장할 변수의 의미가 분명해야 한다
  3. 선택 후 되돌리기(백트래킹) 또는 새 리스트 전달 방식을 정확히 써야 한다
  4. 문제의 요구가 부분집합인지, 조합인지, 순열인지 먼저 구분해야 한다

4-5. 자주 하는 실수 / 디버깅 포인트

부분집합 재귀에서

  • 종료 조건을 잘못 잡아서 일부 경우가 빠짐
  • append() 이후 pop() 을 안 해서 이전 선택이 다음 분기에 섞임
  • N과 len(arr)를 다르게 두어 인덱스 오류 발생

Binary Counting에서

  • 1 << n 이 전체 개수라는 점을 놓침
  • mask & (1 << idx)의 의미를 헷갈림
  • 출력 순서가 기대와 달라도 코드가 틀린 것은 아니라는 점을 모름

조합에서

  • 순열처럼 중복 결과가 나와도 원인을 못 찾음
  • start를 갱신하지 않아 같은 원소를 다시 고름
  • R개를 다 골랐을 때 바로 종료하지 않아 불필요한 재귀가 계속됨

Greedy에서

  • 반례 검증 없이 바로 구현부터 들어감
  • “현재 최선”과 “전체 최선”을 혼동함
  • Greedy로 안 되는 문제를 Greedy로 억지로 풀려고 함

5. 배운 점 / 느낀 점 / 확장 포인트

이 강의에서 특히 중요했던 것은 문제를 바라보는 시선의 차이였다.

5-1. 부분집합과 조합은 재귀 감각을 키워준다

부분집합 문제는 단순해 보여도 재귀 학습에 아주 좋다.
각 단계에서 “고른다 / 안 고른다”를 반복하는 구조는
많은 탐색 문제의 기본 틀이 된다.

조합 역시 부분집합과 매우 가깝지만,
순서가 중요하지 않다는 조건 때문에 start 같은 장치가 왜 필요한지 배울 수 있다.

5-2. Greedy는 빠르지만, 증명이 더 중요하다

Greedy는 구현만 보면 간단한 경우가 많다.
하지만 실제로는 구현보다 증명과 반례 검토가 더 중요하다.

즉, Greedy 문제를 만났을 때는 다음 순서로 생각하는 습관이 필요하다.

  1. 규칙이 있는지 찾기
  2. 그 규칙이 항상 맞는지 검증하기
  3. 반례가 없는지 작은 예시로 깨보기
  4. 그 다음에야 구현하기

5-3. 실전 문제풀이로 확장되는 지점

이 내용은 이후 다음 주제로 자연스럽게 이어진다.

  • 비트마스킹
  • 백트래킹
  • 조합 최적화 문제
  • 회의실 배정, 활동 선택 같은 Greedy 문제
  • 배낭 문제(특히 fractional knapsack vs 0/1 knapsack 차이)

🧠 기억할 것
같은 “선택 문제”라도 어떤 것은 전부 봐야 하고, 어떤 것은 지금 최선만 골라도 된다.
그 차이를 구분하는 힘이 문제 해결의 핵심이다.

6. 요약 정리

이번 강의의 핵심을 다시 짧게 정리하면 다음과 같다.

📌 핵심

  • 부분집합은 각 원소에 대해 포함 / 미포함 두 선택을 반복하는 문제다.
  • 원소가 n개일 때 부분집합의 수는 2^n개다.
  • 부분집합은 재귀로도 만들 수 있고, Binary Counting(비트 연산) 으로도 만들 수 있다.
  • 조합은 순서 없이 R개를 고르는 문제이며, start 인덱스를 사용하면 중복 없이 깔끔하게 구현할 수 있다.
  • Greedy는 매 순간 최선처럼 보이는 선택을 하는 방식이지만, 항상 정답이 되는 것은 아니다.
  • Greedy를 적용하려면 탐욕적 선택 속성, 최적 부분 구조, 반례 검토가 필요하다.

🧠 기억할 것

  • “모든 경우를 볼 것인가?” → Brute Force
  • “규칙이 있고, 지금 최선이 전체 최선으로 이어지는가?” → Greedy 검토
  • 재귀 문제에서는 항상
    종료 조건 / 현재 상태 / 다음 선택 / 상태 복원
    이 네 가지를 먼저 보자.
