## 1. 들어가며

이번 강의는 크게 두 덩어리로 나뉜다.  
앞부분은 **조합적 문제를 실제 코드로 어떻게 만들어 내는지**를 다루고, 뒷부분은 **그렇게 모든 경우를 보는 대신, 그때그때 가장 좋아 보이는 선택으로 풀 수 있는 문제는 어떤 것인지**를 설명한다.

처음 보면 부분집합, 조합, 그리디가 서로 다른 주제처럼 보일 수 있다.  
그런데 실제로는 같은 질문에서 출발한다.

> **"가능한 선택들을 어떻게 다루어야 답을 구할 수 있을까?"**

어떤 문제는 가능한 경우를 직접 만들어 보아야 한다.  
이럴 때는 부분집합, 조합, 순열처럼 **경우의 수를 생성하는 기술**이 필요하다.  
반대로 어떤 문제는 모든 경우를 다 보지 않고도, **현재 단계에서 가장 좋아 보이는 선택**만 잘하면 답을 만들 수 있다. 그게 바로 그리디다.

그래서 이번 강의는 단순히 “부분집합 코드 하나”, “그리디 정의 하나”를 배우는 시간이 아니다.  
핵심은 **문제를 봤을 때 어떤 사고방식으로 접근해야 하는지**를 구분하는 감각을 만드는 데 있다.

이번 노트는 이 흐름을 다음 순서로 정리한다.

1. 부분집합을 재귀로 만드는 방법  
2. 부분집합을 비트 연산으로 만드는 방법  
3. 조합을 재귀로 만드는 두 가지 관점  
4. 그리디란 무엇인지, 왜 늘 통하지는 않는지  
5. 어떤 조건을 만족해야 그리디로 풀 수 있는지

## 2. 핵심 개념 정리

### 2.1 부분집합은 "포함할까, 말까"의 반복이다

부분집합은 어떤 원소를 **넣을지 말지** 결정하는 문제다.  
원소가 `n`개라면 각 원소마다 선택지는 2가지이므로, 전체 경우의 수는 `2^n`개가 된다.

이 관점은 재귀와 아주 잘 맞는다.

- **Level**: 지금 몇 번째 원소를 보고 있는가
- **Branch**: 그 원소를 포함 / 미포함, 즉 2가지 선택

쉽게 말하면, 부분집합은 “각 원소에 대해 O/X를 적어 가는 과정”이라고 볼 수 있다.

### 2.2 Binary Counting은 부분집합을 비트열로 표현하는 방법이다

재귀가 부분집합의 구조를 이해하는 데 좋다면, Binary Counting은 **모든 부분집합을 빠르게 순회**할 때 강력하다.

예를 들어 원소가 3개면, 길이 3의 비트열을 생각할 수 있다.

- `001` → 첫 번째 원소만 포함
- `110` → 두 번째, 세 번째 원소 포함

즉, **한 개의 정수**를 이진수로 해석하면 부분집합 하나를 표현할 수 있다.

### 2.3 조합은 "부분집합 중에서 개수를 제한한 경우"로 볼 수 있다

조합은 순서 없이 `r`개를 고르는 것이다.  
그래서 부분집합 생성과 매우 닮아 있지만, 한 가지가 더 필요하다.

- 지금까지 **몇 개를 골랐는지**
- 또는 앞으로 **어디부터 고를 수 있는지**

이 둘 중 하나를 잘 관리하면 조합 코드를 만들 수 있다.

### 2.4 그리디는 "현재 가장 좋아 보이는 선택"으로 가는 방식이다

그리디는 매 단계에서 최선처럼 보이는 선택을 하는 방식이다.  
하지만 여기서 가장 중요한 점은, **좋아 보인다고 해서 항상 정답은 아니라는 것**이다.

그래서 그리디 문제를 만났을 때는 먼저 규칙을 찾고, 그 다음에 그 규칙이 정말 최적해를 보장하는지 검증해야 한다.

### 2.5 완전탐색과 그리디는 서로 대비해서 이해하면 더 잘 보인다

이번 강의의 흐름을 한 줄로 요약하면 이렇다.

- 부분집합 / 조합: **가능한 선택들을 실제로 만들어 본다**
- 그리디: **가능한 선택들을 다 보지 않고, 그때 가장 좋아 보이는 선택만 한다**

`📌 핵심`  
이번 강의의 중심은 코드를 외우는 것이 아니라, **문제를 만났을 때 경우를 다 볼 것인지, 규칙으로 줄일 수 있는지 판단하는 감각**을 만드는 데 있다.

## 3. 본문 정리

## 3.1 부분집합은 "포함 / 미포함" 두 갈래로 내려가는 재귀트리다

부분집합의 가장 기본적인 생각은 아주 단순하다.  
원소 하나를 볼 때마다 할 일은 두 가지뿐이다.

1. 이 원소를 부분집합에 **넣는다**
2. 이 원소를 부분집합에 **넣지 않는다**

그래서 부분집합 문제는 자연스럽게 **Branch가 2개인 재귀트리**로 이해할 수 있다.

강의에서는 먼저 `{min, co, tim}` 세 명의 친구 중 영화관에 갈 사람을 고르는 예시로 이 구조를 보여 준다.  
각 사람마다 `O` 또는 `X`를 적는다고 생각하면 된다.

- `O`: 포함
- `X`: 미포함

즉, 사람 수가 3명이면 **Level 3**, 각 단계의 선택은 2가지이므로 **Branch 2**가 된다.

### 예시 감각 잡기

가능한 결과는 다음처럼 나온다.

```text
O O O
O O X
O X O
O X X
X O O
X O X
X X O
X X X
```

이 예시는 단순해 보이지만, 사실 부분집합 재귀의 핵심 구조를 그대로 담고 있다.

### 관련 코드: O / X로 부분집합의 모양 만들기

```python
# 선택 여부를 표시할 문자
arr = ['O', 'X']

# 지금까지의 선택 기록
path = []

def recur(cnt):
    # 친구 3명에 대한 선택이 모두 끝났다면 출력하고 종료
    if cnt == 3:
        print(*path)
        return

    # 현재 친구를 부분집합에 포함하는 경우
    path.append(arr[0])
    recur(cnt + 1)
    path.pop()

    # 현재 친구를 부분집합에 포함하지 않는 경우
    path.append(arr[1])
    recur(cnt + 1)
    path.pop()

recur(0)
```

### 코드 흐름 해설

이 코드는 사람이 3명일 때, 각 사람에 대해 O/X를 적는 과정을 그대로 재귀로 옮긴 것이다.

- `cnt`는 지금 몇 번째 사람까지 결정했는지를 뜻한다.
- `cnt == 3`이면 세 사람 모두 결정한 상태이므로 더 내려가지 않고 출력한다.
- 아직 결정할 사람이 남아 있으면, 먼저 `O`를 넣고 한 단계 내려간다.
- 돌아오면 `pop()`으로 방금 선택한 흔적을 지운 뒤, 이번에는 `X`를 넣고 다시 내려간다.

여기서 중요한 점은 `append()`와 `pop()`이 항상 한 쌍이라는 것이다.  
쉽게 말하면, **이번 선택을 기록하고 내려갔다가, 돌아오면 그 선택을 지우고 다음 선택으로 넘어가는 구조**다.

⚠️ **주의**  
`pop()`을 빼먹으면 다음 경우를 만들어야 할 때 이전 선택이 그대로 남아서 `path`가 꼬인다.  
재귀를 처음 구현할 때 가장 자주 놓치는 부분이 바로 이 지점이다.

`📌 핵심`  
부분집합 재귀의 본질은 “현재 원소를 넣을까 말까를 정하고, 다음 원소로 넘어간다”는 반복이다.

## 3.2 실제 부분집합을 만들 때는 선택된 원소 목록을 함께 관리한다

앞의 O/X 예시는 구조를 이해하기 좋다.  
이제 실제 원소를 다루려면, 선택 여부만 적는 대신 **선택된 원소 자체를 리스트에 담아야** 한다.

강의에서는 `arr = [1, 2, 3, 4, 5]` 중 앞의 세 원소만 대상으로 부분집합을 만드는 예시가 나온다.  
여기서 핵심은 `selected` 리스트와 `i` 인덱스를 함께 움직이는 것이다.

- `i`: 지금 포함할지 말지 결정하고 있는 원소의 위치
- `selected`: 지금까지 부분집합에 담은 원소들

### 관련 코드: 재귀로 실제 부분집합 만들기

```python
arr = [1, 2, 3, 4, 5]
N = 3

def subset(i, selected):
    # i가 N에 도달했다는 것은
    # 앞에서부터 N개의 원소에 대해 포함/미포함 결정을 모두 끝냈다는 뜻
    if i == N:
        print(selected)
        return

    # 1) i번 원소를 부분집합에 포함하는 경우
    selected.append(arr[i])
    subset(i + 1, selected)

    # 방금 넣었던 원소를 되돌린다.
    # 그래야 다음 경우(미포함)를 만들 수 있다.
    selected.pop()

    # 2) i번 원소를 부분집합에 포함하지 않는 경우
    subset(i + 1, selected)

subset(0, [])
```

### 출력 예시

```text
[1, 2, 3]
[1, 2]
[1, 3]
[1]
[2, 3]
[2]
[3]
[]
```

### 코드 흐름 해설

이 코드는 각 원소마다 두 갈래로 갈라진다.

- 포함하면 `selected`에 넣고 다음 원소로 이동
- 미포함이면 넣지 않고 다음 원소로 이동

그리고 `i == N`이 되면, 앞의 `N`개 원소에 대한 선택을 모두 끝낸 것이므로 현재 `selected`를 출력한다.

여기서 한 번 더 눈여겨볼 점은 종료 조건이다.  
주석에는 “이 선택을 5번 하면 끝”처럼 보이지만, 실제 코드에서 `N = 3`이므로 **지금 예시는 3개의 원소만 대상으로 부분집합을 만들고 있다**.  
즉, 설명을 읽을 때는 주석 문장보다 **실제 변수 값과 종료 조건**을 함께 확인하는 습관이 중요하다.

### 더 촘촘히 읽는 주석 강화 버전

```python
arr = [1, 2, 3, 4, 5]   # 전체 원소 목록
N = 3                   # 이번에는 앞의 3개 원소만 대상으로 부분집합 생성

def subset(i, selected):
    # i: 지금 포함/미포함을 결정할 원소의 인덱스
    # selected: 지금까지 부분집합에 담아 둔 원소들

    # 종료 조건:
    # 0, 1, 2번 원소까지 모두 결정했다면 현재 부분집합을 출력
    if i == N:
        print(selected)
        return

    # 현재 원소 arr[i]를 선택하는 경우
    selected.append(arr[i])     # 현재 원소를 부분집합에 추가
    subset(i + 1, selected)     # 다음 원소 결정하러 이동

    # 선택했던 원소를 되돌린 뒤
    # 같은 레벨에서 "선택하지 않는 경우"를 만들어 준다
    selected.pop()

    # 현재 원소 arr[i]를 선택하지 않는 경우
    subset(i + 1, selected)

# 아직 아무 원소도 결정하지 않았으므로
# 시작 인덱스는 0, 선택된 원소 목록은 빈 리스트
subset(0, [])
```

⚠️ **주의**  
`selected.append()`만 하고 `selected.pop()`을 하지 않으면, “포함하지 않는 경우”를 만들 때도 이전 값이 남아 있어서 잘못된 결과가 나온다.

`📌 핵심`  
부분집합 재귀에서 `i`는 **무엇을 결정하고 있는지**, `selected`는 **지금까지 무엇을 골랐는지**를 나타낸다.

## 3.3 Binary Counting은 부분집합을 정수 하나로 다루게 해 준다

재귀로 부분집합을 만들면 구조를 이해하기 좋다.  
하지만 모든 부분집합을 빠르게 순회해야 할 때는 **비트 연산**이 훨씬 간결할 수 있다.

핵심 아이디어는 이렇다.

- 원소가 `n`개면 길이 `n`의 비트열을 생각한다.
- 비트가 `1`이면 그 원소를 포함
- 비트가 `0`이면 그 원소를 미포함

예를 들어 원소가 4개라면, `0000`부터 `1111`까지의 비트열이 모든 부분집합을 나타낸다.  
그래서 전체 개수는 자연스럽게 `2^n`이고, 코드에서는 이를 `1 << n`으로 자주 표현한다.

### 관련 코드: 비트마스크로 부분집합 만들기

```python
arr = [1, 2, 3, 4]
n = len(arr)

def get_subset1():
    # 0부터 (2^n - 1)까지의 숫자를 모두 확인
    for i in range(1 << n):
        # i의 각 비트를 검사
        for idx in range(n):
            # idx번째 비트가 1이면 arr[idx]를 현재 부분집합에 포함
            if i & (1 << idx):
                print(arr[idx], end=' ')
        print()

get_subset1()
```

### 코드 흐름 해설

이 코드를 읽을 때는 `i`를 그냥 숫자가 아니라 **부분집합 번호**라고 생각하면 훨씬 쉽다.

- `i = 0`이면 `0000` → 아무 원소도 선택하지 않음
- `i = 5`이면 `0101` → 0번, 2번 원소 선택
- `i = 15`이면 `1111` → 모든 원소 선택

그리고 `if i & (1 << idx)`는  
“`i`의 `idx`번째 비트가 1이냐?”를 검사하는 문장이다.

### 더 촘촘히 읽는 주석 강화 버전

```python
arr = [1, 2, 3, 4]      # 부분집합을 만들 원소들
n = len(arr)            # 원소 개수

def get_subset1():
    # 1 << n 은 2^n 과 같다.
    # 즉, 부분집합의 총 개수만큼 반복한다.
    for i in range(1 << n):
        # i를 이진수라고 생각하고,
        # 각 자리의 비트가 1인지 확인한다.
        for idx in range(n):
            # 1 << idx 는 idx번째 비트만 1인 값
            # i & (1 << idx)가 0이 아니면
            # idx번째 원소가 현재 부분집합에 포함된다는 뜻
            if i & (1 << idx):
                print(arr[idx], end=' ')
        print()  # 현재 부분집합 출력이 끝났으니 줄바꿈

get_subset1()
```

💡 **포인트**  
재귀는 “구조를 이해하는 데” 좋고, Binary Counting은 “모든 부분집합을 순회하는 데” 강하다.  
문제에 따라 둘 중 더 편한 쪽을 선택하면 된다.

`📌 핵심`  
부분집합을 비트열로 보면, `2^n`개의 경우를 **정수 0부터 `(1 << n) - 1`까지**로 자연스럽게 다룰 수 있다.

## 3.4 조합은 "부분집합 중에서 정확히 R개 고른 경우"라고 생각할 수 있다

조합은 순서 없이 `R`개를 고르는 문제다.  
그래서 부분집합과 매우 닮아 있다. 다만 모든 부분집합을 출력하는 것이 아니라, **원소 개수가 정확히 `R`개인 경우만 출력**해야 한다.

강의의 첫 번째 조합 코드는 이 관점을 그대로 따른다.  
즉, 각 원소에 대해 포함 / 미포함을 결정하되, `cnt`로 현재까지 몇 개를 골랐는지 관리한다.

### 관련 코드: 부분집합 관점으로 조합 만들기

```python
arr = [1, 2, 3, 4, 5]
N = 5
R = 3

def subset(i, selected, cnt):
    # R개를 모두 골랐다면 하나의 조합 완성
    if cnt == R:
        print(selected)
        return

    # 끝까지 왔는데도 R개를 못 골랐다면 종료
    if i == N:
        return

    # 1) i번 원소를 고르는 경우
    subset(i + 1, selected + [arr[i]], cnt + 1)

    # 2) i번 원소를 고르지 않는 경우
    subset(i + 1, selected, cnt)

subset(0, [], 0)
```

### 출력 예시

```text
[1, 2, 3]
[1, 2, 4]
[1, 2, 5]
[1, 3, 4]
[1, 3, 5]
[1, 4, 5]
[2, 3, 4]
[2, 3, 5]
[2, 4, 5]
[3, 4, 5]
```

### 코드 흐름 해설

이 코드는 부분집합과 거의 같은 구조를 가진다.  
다만 종료 조건이 하나 더 또렷해진다.

- `cnt == R`이면 이미 필요한 개수만큼 골랐으므로 출력
- `i == N`이면 더 이상 볼 원소가 없으므로 종료

여기서는 `append()` / `pop()` 대신 `selected + [arr[i]]`를 사용했다.  
즉, 기존 리스트를 직접 수정하지 않고 **새 리스트를 만들어 다음 호출로 넘기는 방식**이다.

이 방법의 장점은 코드가 비교적 간단하게 보인다는 점이고, 단점은 매번 새 리스트를 만든다는 점이다.  
학습 단계에서는 흐름을 읽기 좋다는 장점이 있다.

### 주석 강화 버전

```python
arr = [1, 2, 3, 4, 5]   # 전체 원소
N = 5                   # 전체 원소 개수
R = 3                   # 이 중에서 3개를 고를 것

def subset(i, selected, cnt):
    # i: 현재 고려 중인 원소의 인덱스
    # selected: 지금까지 고른 원소들
    # cnt: 지금까지 고른 원소 개수

    # 필요한 개수 R개를 모두 골랐다면
    # 현재 selected가 하나의 조합이 된다.
    if cnt == R:
        print(selected)
        return

    # 모든 원소를 다 확인했는데도
    # R개를 채우지 못했다면 더 볼 것이 없으므로 종료
    if i == N:
        return

    # 현재 원소 arr[i]를 고르는 경우
    # 새 리스트를 만들어 다음 호출로 넘긴다.
    subset(i + 1, selected + [arr[i]], cnt + 1)

    # 현재 원소 arr[i]를 고르지 않는 경우
    subset(i + 1, selected, cnt)

# 아직 아무것도 고르지 않은 상태에서 시작
subset(0, [], 0)
```

⚠️ **주의**  
조합과 부분집합이 비슷하다고 해서 종료 조건까지 같지는 않다.  
조합에서는 “끝까지 갔는가?”뿐 아니라, **이미 `R`개를 다 골랐는가?**를 함께 봐야 한다.

`📌 핵심`  
조합은 부분집합 생성에 **개수 조건 `cnt == R`**을 붙인 문제라고 이해하면 자연스럽다.

## 3.5 `start` 인덱스를 쓰면 조합을 더 직접적으로 표현할 수 있다

앞의 코드는 “고른다 / 안 고른다”라는 부분집합 관점에서 조합을 만든다.  
그런데 조합을 실제로 자주 구현할 때는 `start` 인덱스를 쓰는 방식이 더 직관적일 때가 많다.

핵심 아이디어는 이렇다.

- 한 번 어떤 원소를 골랐다면
- 다음에는 그 **뒤쪽 원소들만** 고를 수 있게 한다

이렇게 하면

- 같은 원소를 다시 고르는 일도 막을 수 있고
- `123`과 `321`처럼 **순서만 다른 중복 상태**도 자연스럽게 사라진다

### 관련 코드: `start`를 이용한 조합 생성

```python
arr = [1, 2, 3, 4, 5]
N = 5
R = 3

def comb(cnt, selected, start):
    # R개를 모두 골랐다면 출력
    if cnt == R:
        print(selected)
        return

    # start부터 뒤쪽 원소만 고를 수 있다
    for i in range(start, N):
        comb(cnt + 1, selected + [arr[i]], i + 1)

comb(0, [], 0)
```

### 코드 흐름 해설

이 코드는 조합의 “순서가 중요하지 않다”는 성질을 아주 잘 반영한다.

예를 들어 첫 단계에서 `arr[1] = 2`를 골랐다면,  
다음 단계에서는 다시 1번 이전으로 돌아가지 않고 **2의 뒤쪽만** 보게 된다.

그래서

- `1 → 2 → 3`은 만들어지지만
- `2 → 1 → 3` 같은 순서 뒤집기는 애초에 생성되지 않는다

즉, `start`는 단순한 인덱스가 아니라  
**중복을 막고 조합의 순서 없는 성질을 보장하는 장치**라고 보면 된다.

### 더 촘촘히 읽는 주석 강화 버전

```python
arr = [1, 2, 3, 4, 5]   # 전체 원소
N = 5
R = 3

def comb(cnt, selected, start):
    # cnt: 지금까지 고른 원소 수
    # selected: 지금까지 만든 조합
    # start: 이번 단계에서 고를 수 있는 시작 인덱스

    # R개를 모두 골랐다면 현재 조합 완성
    if cnt == R:
        print(selected)
        return

    # start부터 N-1까지 순서대로 보면서
    # 이번 자리에 들어갈 원소를 하나 고른다.
    for i in range(start, N):
        # arr[i]를 고른 뒤에는
        # 다음 단계에서 i 뒤쪽 원소만 볼 수 있도록 i + 1을 넘긴다.
        comb(cnt + 1, selected + [arr[i]], i + 1)

# 아직 아무것도 고르지 않았으므로 cnt = 0
# 처음에는 0번 인덱스부터 고를 수 있다.
comb(0, [], 0)
```

💡 **포인트**  
조합 구현에서 `start`는 “어디부터 골라야 중복 없이 순서 없는 선택이 되는가”를 제어하는 핵심 장치다.

⚠️ **주의**  
순열 코드와 섞어서 생각하면 `start` 대신 `used` 배열이 필요하다고 착각하기 쉽다.  
하지만 조합은 이미 **뒤쪽만 보도록 제한**하면 되기 때문에, 보통 `used` 없이도 충분하다.

`📌 핵심`  
`start`를 넘겨 주는 조합 코드는 “고른 원소 뒤에서만 계속 선택한다”는 원리를 그대로 코드로 옮긴 것이다.

## 3.6 그리디는 "지금 가장 좋아 보이는 선택"이 정말 맞는지 따져야 한다

강의의 후반부는 완전탐색 계열에서 한 걸음 옮겨, 그리디 알고리즘으로 넘어간다.

그리디는 결정이 필요할 때마다, **현재 기준으로 가장 좋아 보이는 선택지**를 고르는 방식이다.

예를 들면 이런 식이다.

- 가장 큰 동전부터 고른다
- 가장 빨리 끝나는 활동부터 고른다
- 현재 가장 이득이 큰 선택을 먼저 한다

이런 방식은 직관적으로 매우 매력적이다.  
매 순간 가장 좋아 보이는 것을 고르니, 전체 답도 좋을 것처럼 느껴진다.

하지만 바로 여기서 조심해야 한다.  
**직관적으로 좋아 보인다고 해서 항상 최적해가 되는 것은 아니다.**

그래서 강의는 그리디를 “무조건 빠르고 좋은 방법”으로 소개하지 않고,  
먼저 다음과 같이 문제해결 기법 전체 속에서 위치를 잡아 준다.

### 대표적인 문제해결 기법 비교

1. **완전 탐색**  
   - 답이 될 수 있는 모든 경우를 시도한다.
2. **Greedy**  
   - 결정이 필요할 때 가장 좋아 보이는 선택을 한다.
3. **DP**  
   - 현재만 보지 않고, 과거의 계산 결과를 이용해 현재 값을 만든다.
4. **분할 정복**  
   - 큰 문제를 작은 문제로 나누어 해결한다.

이 비교가 중요한 이유는,  
문제를 봤을 때 “무조건 그리디로 풀어야지”가 아니라 **어떤 접근이 맞는지 먼저 판단해야 하기 때문**이다.

`📌 핵심`  
그리디는 “빠른 방법”이라기보다, **조건이 맞을 때만 정답이 보장되는 특별한 전략**이다.

## 3.7 어떤 문제가 정말 그리디인가: 두 가지 검증 조건

강의에서 가장 중요한 메시지 중 하나는 이 말이다.

> **규칙을 찾는 것만으로는 부족하고, 그 규칙이 정말 최적해를 보장하는지 검증해야 한다.**

즉, “가장 큰 것부터”, “가장 작은 것부터”, “빨리 끝나는 것부터” 같은 규칙을 하나 찾았다고 해서 끝이 아니다.  
그 규칙이 항상 맞는지 확인해야 한다.

강의에서는 이를 두 가지 조건으로 설명한다.

### 3.7.1 탐욕적 선택 속성 (Greedy Choice Property)

각 단계에서 내린 최적 선택이,  
이후 단계의 선택 기준을 망가뜨리지 않아야 한다.

쉽게 말하면,

- 지금 가장 좋아 보이는 선택을 했더니
- 나중에 갑자기 그 선택 때문에 전체가 틀어지면

그 문제는 그리디로 풀 수 없다는 뜻이다.

강의 메모에서는 동전 문제를 이 조건의 예시로 떠올리도록 안내한다.

### 3.7.2 최적 부분 구조 (Optimal Substructure)

각 단계의 최적 선택들을 쌓아 갔을 때,  
그 결과가 전체 문제의 최적해가 되어야 한다.

즉,

- 부분 문제에서의 최선이
- 전체 문제에서도 최선으로 이어져야 한다

는 뜻이다.

강의에서는 이 부분을 증명과 연결해서 설명한다.

- 직접 증명
- 간접 증명(귀류법)
- 귀납적 사고

즉, 그리디는 “느낌상 될 것 같다”가 아니라,  
**왜 그 규칙이 전체 최적해로 이어지는지 논리적으로 확인해야 하는 알고리즘**이다.

### 동전 문제를 떠올려 보기

강의 메모에는 다음과 같은 형태의 생각이 들어 있다.

- 명제: 가장 큰 동전부터 순서대로 고르면 최소 동전 수가 나온다.
- 검증: 정말 더 적은 수의 동전으로 표현하는 경우가 가능한지 따져 본다.

여기서 중요한 건 동전 문제 자체보다도,  
**그리디는 규칙을 찾은 뒤 반드시 검증이 뒤따라야 한다**는 태도다.

⚠️ **주의**  
그리디를 처음 배우면 “규칙만 보이면 된다”고 오해하기 쉽다.  
하지만 실제로는 **규칙 발견보다 검증이 더 중요할 때가 많다.**

### 강의에서 언급된 대표 예시

강의 노트 마지막에는 아래 문제가 이어질 주제로 언급된다.

- Knapsack 문제
- 활동 선택 문제

이번 자료에서는 이 문제들의 상세 전개까지는 나오지 않고, **대표적인 그리디 예시로 예고**되는 수준에서 등장한다.  
즉, 이번 노트에서는 정의와 조건을 먼저 잡고, 구체적인 증명과 문제 적용은 다음 학습으로 이어지는 흐름이라고 이해하면 좋다.

`📌 핵심`  
그리디 문제는 “좋아 보이는 규칙”을 찾는 것에서 끝나지 않는다.  
**탐욕적 선택 속성과 최적 부분 구조가 성립하는지 확인해야 비로소 그리디라고 말할 수 있다.**

## 4. 적용 관점에서 다시 보기

이제 본문 내용을 실제 문제풀이 관점에서 다시 묶어 보자.  
핵심은 “문제를 보자마자 어떤 신호를 읽을 것인가”이다.

### 4.1 부분집합 신호

다음 표현이 보이면 부분집합을 떠올릴 가능성이 크다.

- 모든 경우를 확인하라
- 어떤 원소를 선택할 수도, 선택하지 않을 수도 있다
- 부분집합의 합 / 조건을 만족하는 부분집합 개수
- 포함 / 미포함 두 갈래 결정

이런 문제에서는 먼저 **원소 하나당 선택이 2가지인지**를 확인해 보면 좋다.  
그렇다면 재귀의 Branch 2 구조나 Binary Counting으로 이어질 수 있다.

### 4.2 조합 신호

다음 표현이 보이면 조합을 의심해 볼 수 있다.

- `n`개 중 `r`개를 고른다
- 순서는 중요하지 않다
- 같은 집합을 순서만 바꿔 세면 안 된다

이 경우에는 두 가지 구현 관점이 있다.

1. **부분집합 관점**: 고른다 / 안 고른다 + `cnt`
2. **직접 조합 관점**: `start` 인덱스로 뒤쪽만 고른다

실전에서는 `start` 방식이 더 깔끔하게 느껴지는 경우가 많다.

### 4.3 Binary Counting을 떠올릴 때

다음 상황이면 비트 연산이 특히 잘 맞는다.

- 원소 수가 크지 않다
- 모든 부분집합을 순회해야 한다
- 선택 상태를 정수 하나로 표현하고 싶다

예를 들어 “길이가 10 이하인 집합의 모든 부분집합” 같은 문제는  
비트마스킹으로 처리하면 코드가 간결해질 수 있다.

### 4.4 그리디 신호

다음 문장을 보면 그리디 가능성을 떠올릴 수 있다.

- 최소 개수 / 최대 이익 / 가장 빨리 / 가장 크게
- 매 단계에서 하나씩 결정해야 한다
- 지금의 좋은 선택이 다음에도 나쁘지 않을 것 같다

다만 여기서 바로 그리디로 뛰어들면 안 된다.  
항상 아래 두 질문을 붙여야 한다.

1. 지금의 최선 선택이 이후 선택 기준을 깨지 않는가?  
2. 그 선택들을 쌓으면 전체 최적해가 되는가?

이 질문에 확신이 없다면, 그 문제는 그리디가 아니라 완전탐색이나 DP 쪽일 수 있다.

### 4.5 구현 순서를 잡는 방법

부분집합 / 조합 / 그리디 문제를 만났을 때는 아래 순서로 정리해 보면 좋다.

1. **선택의 종류를 파악한다**  
   - 포함/미포함인지, 하나를 고르는지, 여러 개 중 최선 하나인지
2. **상태 변수를 정한다**  
   - `i`, `cnt`, `selected`, `start` 같은 값
3. **종료 조건을 먼저 쓴다**  
   - 언제 한 경우가 완성되는가
4. **다음 단계 규칙을 적는다**  
   - 포함/미포함, 뒤쪽만 선택, 가장 좋은 것 선택
5. **중복과 실수를 점검한다**  
   - `pop()` 누락, `start` 갱신 실수, 그리디 검증 부족

`🧠 기억할 것`  
재귀 계열 문제는 “상태 + 종료 조건 + 다음 호출 규칙”으로 읽고,  
그리디 계열 문제는 “규칙 + 검증 조건”으로 읽어야 한다.

## 5. 배운 점 / 느낀 점 / 확장 포인트

이번 강의는 겉보기보다 훨씬 중요한 연결 고리를 담고 있다.

앞부분의 부분집합과 조합은 단순히 경우의 수를 출력하는 연습처럼 보일 수 있다.  
하지만 실제로는 이후의 **백트래킹, 순열, 부분집합의 합, 조합 최적화 문제**로 그대로 이어진다.

특히 다음 감각이 중요하다.

- 부분집합은 “각 원소를 어떻게 처리할지”의 문제
- 조합은 “순서 없이 필요한 개수만 고르는” 문제
- 그리디는 “모든 경우를 만들지 않고 규칙으로 줄일 수 있는지”의 문제

즉, 이번 강의는 각 기법을 따로 외우게 하는 것이 아니라,  
**문제를 봤을 때 어떤 방식으로 모델링할지 구분하는 눈**을 만드는 데 의미가 있다.

앞으로 더 이어서 공부해 볼 만한 포인트는 다음과 같다.

- 부분집합에서 조건을 걸어 가지치기하는 방법
- 조합에서 `start`와 `used`의 차이
- 비트마스킹으로 부분집합 합 계산하기
- 그리디가 실패하는 반례 만들기
- 동전 문제, 배낭 문제, 활동 선택 문제의 비교
- 그리디와 DP를 구분하는 기준

## 6. 요약 정리

- `📌 핵심` 부분집합은 각 원소에 대해 **포함 / 미포함**을 결정하는 문제이므로, 재귀에서는 Branch 2 구조로 표현된다.
- `📌 핵심` 부분집합의 총 개수는 `2^n`개이고, 이는 코드에서 `1 << n`으로 자주 표현한다.
- `📌 핵심` Binary Counting은 부분집합을 비트열로 나타내는 방식이며, 모든 부분집합을 순회할 때 강력하다.
- `📌 핵심` 조합은 부분집합과 닮아 있지만, **정확히 `R`개를 고른다**는 조건이 추가된다.
- `📌 핵심` 조합 구현에서 `start` 인덱스는 뒤쪽 원소만 고르게 하여 순서 중복을 막는다.
- `📌 핵심` 그리디는 매 단계의 최선 선택으로 답을 만드는 방식이지만, 항상 정답을 보장하지는 않는다.
- `🧠 기억할 것` 그리디가 성립하려면 **탐욕적 선택 속성**과 **최적 부분 구조**를 함께 확인해야 한다.
- `🧠 기억할 것` 완전탐색은 경우를 실제로 만들고, 그리디는 경우를 줄이는 규칙이 성립할 때만 쓸 수 있다.
