## 1. 들어가며

웹 페이지는 처음에는 정적인 문서에 가까웠다. HTML로 내용을 작성하고, 브라우저는 그 문서를 화면에 보여주는 역할을 했다. 하지만 사용자가 버튼을 클릭했을 때 화면이 바뀌거나, 입력값에 따라 문구가 변경되거나, 특정 조건에 따라 스타일이 바뀌는 기능이 필요해지면서 웹은 단순한 문서에서 동적인 애플리케이션으로 발전했다.

이 변화의 중심에 있는 언어가 **JavaScript**다. JavaScript는 브라우저 안에서 HTML 문서를 읽고, 필요한 요소를 찾아서, 그 내용이나 스타일을 바꾸는 역할을 한다. 이때 JavaScript가 직접 HTML 파일의 문자열을 수정하는 것이 아니라, 브라우저가 HTML을 해석해 만들어둔 객체 구조를 조작한다. 이 객체 구조를 **DOM**, 즉 Document Object Model이라고 부른다.

이번 강의는 크게 두 흐름으로 나누어 볼 수 있다. 첫 번째 흐름은 JavaScript라는 언어가 어떻게 등장했고, 왜 ECMAScript라는 표준이 중요한지 이해하는 것이다. 두 번째 흐름은 DOM을 통해 실제 웹 페이지를 어떻게 선택하고 조작하는지 배우는 것이다.

그리고 이 두 흐름 사이에는 변수 선언 방식이 놓여 있다. DOM을 조작하려면 선택한 요소를 변수에 담아야 하고, 그 변수의 값이 바뀌는지 아닌지에 따라 `const`와 `let`을 적절히 선택해야 한다. 즉, 변수와 DOM은 따로 떨어진 문법이 아니라 실제 웹 페이지 조작 코드 안에서 자연스럽게 함께 쓰인다.

---

## 2. 핵심 개념 정리

이번 강의의 큰 질문은 다음과 같다.

> JavaScript는 어떻게 HTML 문서를 읽고, 선택하고, 바꿀 수 있을까?

이 질문에 답하려면 먼저 브라우저 안에서 JavaScript가 어떤 역할을 하는지 이해해야 한다. JavaScript는 웹 페이지에 동적인 기능을 부여한다. HTML이 문서의 구조를 만들고, CSS가 시각적인 표현을 담당한다면, JavaScript는 사용자의 동작에 반응해 문서의 내용과 상태를 바꾸는 역할을 한다.

이때 JavaScript가 접근하는 대상은 HTML 원문 자체가 아니라 브라우저가 HTML을 해석해서 만든 **DOM Tree**다. DOM Tree에서는 `<body>`, `<h1>`, `<p>` 같은 HTML 태그들이 각각 객체로 표현된다. 개발자는 `document.querySelector()` 같은 DOM API를 사용해 이 객체를 선택하고, `textContent`, `classList`, `setAttribute()`, `appendChild()` 같은 기능으로 객체의 내용과 속성을 바꾼다.

강의의 흐름은 다음 순서로 이어진다.

1. JavaScript가 등장한 배경과 웹 표준의 필요성을 이해한다.
2. ECMAScript와 JavaScript의 관계를 정리한다.
3. `let`, `const`, `var`의 차이와 변수 선언 기준을 배운다.
4. DOM이 HTML 문서를 객체 구조로 표현한 것임을 이해한다.
5. `document` 객체를 통해 DOM에 접근하는 방법을 익힌다.
6. DOM 요소를 선택하고, 클래스·속성·텍스트·스타일·요소 자체를 조작한다.
7. Node, NodeList, Element, Parsing, Hoisting, TDZ를 정리해 JavaScript 동작 원리를 보완한다.

즉, 이번 내용은 “문법을 외우는 강의”라기보다, 브라우저가 HTML을 어떻게 객체로 만들고 JavaScript가 그 객체를 어떻게 바꾸는지 이해하는 강의라고 볼 수 있다.

## 3. 본문 정리

## 3.1 JavaScript가 웹에서 필요해진 이유

JavaScript를 배우기 전에 먼저 웹이 어떤 문제를 해결하면서 발전했는지 살펴보면, DOM 조작이 왜 중요한지 자연스럽게 이해할 수 있다.

초기 웹은 정적인 텍스트 페이지 중심이었다. 사용자는 문서를 읽고 링크를 클릭할 수는 있었지만, 지금처럼 버튼을 누르면 화면 일부가 바뀌거나 입력값을 즉시 검증하는 기능은 제한적이었다. 웹을 만든 Tim Berners-Lee는 URL, HTTP, WWW의 기반을 마련했고, 이를 통해 전 세계의 문서가 서로 연결될 수 있게 되었다.

```text
URL  : 특정 웹 페이지나 파일을 찾기 위한 고유한 경로 주소
HTTP : 웹 브라우저와 서버가 데이터를 주고받기 위한 통신 규약
WWW  : 전 세계적인 정보 공유 시스템
```

웹이 널리 사용되면서 단순 문서만으로는 부족해졌다. 사용자의 클릭, 입력, 이동에 따라 화면이 반응해야 했고, 이 필요에서 JavaScript가 등장했다.

---

### 3.1.1 JavaScript의 탄생과 브라우저 전쟁

1995년 Netscape의 Brendan Eich는 웹 페이지에 동적인 기능을 추가하기 위한 스크립트 언어를 만들었다. 처음 이름은 Mocha였고, 이후 LiveScript를 거쳐 JavaScript라는 이름이 되었다. 당시 Java의 인기에 기대어 이름이 바뀌었지만, JavaScript와 Java는 서로 다른 언어다.

문제는 Microsoft가 Internet Explorer에 JavaScript와 비슷한 JScript를 도입하면서 시작되었다. 브라우저마다 서로 다른 방식으로 JavaScript 기능을 구현했고, 개발자는 같은 웹 페이지가 브라우저마다 다르게 동작하는 문제를 겪었다.

이 상황을 **JavaScript 파편화**라고 볼 수 있다. 파편화는 단순히 언어 이름이 여러 개였다는 뜻이 아니라, 같은 코드를 작성해도 브라우저마다 동작이 달라질 수 있다는 의미다. 그래서 웹 표준의 필요성이 커졌고, ECMA International에서 ECMAScript라는 표준 명세가 만들어졌다.

```text
ECMAScript: JavaScript가 따라야 하는 표준화된 스크립트 언어 명세
JavaScript: ECMAScript 표준을 구현한 구체적인 프로그래밍 언어
```

즉, ECMAScript는 설계도에 가깝고, JavaScript는 그 설계도를 실제 브라우저와 실행 환경에서 구현한 언어라고 이해하면 된다.

---

### 3.1.2 Chrome과 웹 표준

1차 브라우저 전쟁에서는 Internet Explorer가 압도적인 점유율을 차지했다. 하지만 IE는 웹 표준을 적극적으로 따르지 않았고, 이로 인해 개발자는 브라우저별 예외 처리를 많이 해야 했다.

이후 Chrome이 등장하면서 흐름이 바뀌었다. Chrome은 빠른 성능, 강력한 개발자 도구, 적극적인 웹 표준 준수를 바탕으로 빠르게 점유율을 확보했다. 특히 Google이 개발한 V8 JavaScript 엔진은 JavaScript 실행 성능을 크게 높였고, 웹을 단순 문서가 아니라 애플리케이션 플랫폼으로 확장하는 데 중요한 역할을 했다.

여기서 중요한 점은 JavaScript가 단순히 브라우저의 부가 기능이 아니라, 현대 웹 애플리케이션을 만드는 핵심 언어가 되었다는 것이다. 이후 Node.js가 등장하면서 JavaScript는 브라우저 밖에서도 실행될 수 있게 되었고, 서버 사이드 개발에도 사용되기 시작했다.

## 3.2 변수 선언: let, const, var

DOM을 조작할 때는 선택한 요소를 변수에 담는 일이 많다. 예를 들어 `document.querySelector('h1')`로 찾은 요소를 `h1Tag`라는 변수에 저장해두고, 그 요소의 텍스트나 클래스를 바꾼다.

그래서 DOM을 배우기 전에 변수 선언 방식을 먼저 정리해둘 필요가 있다. JavaScript에서는 변수를 선언할 때 `let`, `const`, `var`를 사용할 수 있지만, 현대 JavaScript에서는 기본적으로 `const`를 우선 사용하고, 값의 재할당이 필요한 경우에만 `let`을 사용한다. `var`는 호이스팅과 스코프 문제 때문에 권장되지 않는다.

---

### 3.2.1 변수 이름 작성 규칙

변수 이름은 아무렇게나 지을 수 없다. JavaScript 식별자는 반드시 문자, 달러 기호(`$`), 밑줄(`_`)로 시작해야 하며, 대소문자를 구분한다. 또한 `for`, `if`, `function`처럼 언어가 이미 문법적으로 사용하고 있는 예약어는 변수명으로 사용할 수 없다.

```js
// 의미가 드러나는 이름을 사용하는 것이 좋다.
const userName = 'Jongmu'
const totalPrice = 12000
const submitButton = document.querySelector('button')
```

식별자 이름을 지을 때는 보통 다음 규칙을 따른다.

| 표기법 | 주로 사용하는 곳 | 예시 |
|---|---|---|
| camelCase | 변수, 객체, 함수 | `userName`, `totalPrice`, `changeColor` |
| PascalCase | 클래스, 생성자 | `UserProfile`, `TodoItem` |
| SNAKE_CASE | 상수 | `API_URL`, `MAX_COUNT` |

이 규칙은 문법적으로 반드시 강제되는 것은 아니지만, 협업에서 코드를 읽기 쉽게 만드는 소통 규칙이다. 중요한 것은 일관성이다.

---

### 3.2.2 let

`let`은 재할당이 필요한 변수를 선언할 때 사용한다. 한 번 선언한 뒤 다른 값을 다시 넣을 수 있지만, 같은 스코프 안에서 같은 이름으로 다시 선언할 수는 없다.

```js
// number라는 변수를 선언하고 10을 할당한다.
let number = 10

// let은 재할당이 가능하다.
number = 20

// 같은 스코프에서 같은 이름으로 다시 선언하면 에러가 발생한다.
// let number = 30
```

`let`은 값이 변하는 상황에서 사용한다. 예를 들어 반복문에서 카운트를 증가시키거나, 사용자의 입력에 따라 값이 바뀌어야 하는 경우가 여기에 해당한다.

```js
let count = 0

count = count + 1
count = count + 1

console.log(count) // 2
```

⚠️ 주의: `let`은 재할당이 가능하다는 뜻이지, 아무 곳에서나 다시 선언할 수 있다는 뜻은 아니다. 같은 블록 안에서 `let number`를 두 번 선언하면 에러가 발생한다.

---

### 3.2.3 const

`const`는 재할당이 불가능한 변수를 선언할 때 사용한다. 현대 JavaScript에서는 특별한 이유가 없다면 `const`를 기본으로 사용하는 것을 권장한다.

```js
// number라는 상수를 선언하고 10을 할당한다.
const number = 10

// const는 재할당할 수 없다.
// number = 20

// 같은 이름으로 재선언할 수도 없다.
// const number = 30
```

처음에는 `const`가 불편해 보일 수 있다. 하지만 실제 코드에서는 “이 값은 바뀌지 않는다”는 의도가 분명해진다. 특히 DOM 요소를 선택해 변수에 담는 경우, 선택한 요소 자체를 다른 요소로 바꿀 일이 없다면 `const`를 사용하는 것이 자연스럽다.

```js
// h1Tag라는 변수에는 h1 요소 객체를 담는다.
// 이 변수 자체를 다른 요소로 바꾸지 않을 것이므로 const가 적절하다.
const h1Tag = document.querySelector('h1')

// const여도 객체 내부의 속성은 변경할 수 있다.
h1Tag.textContent = '새 제목'
```

여기서 자주 헷갈리는 부분이 있다. `const`는 변수에 다른 값을 다시 할당하는 것을 막는다. 하지만 객체의 내부 속성을 바꾸는 것까지 막는 것은 아니다. DOM 요소를 `const`에 담아도 `textContent`, `classList`, `style` 같은 속성은 변경할 수 있다.

📌 핵심: 기본은 `const`, 값 자체를 다시 바꿔야 할 때만 `let`을 사용한다.

### 3.2.4 블록 스코프

`let`과 `const`는 블록 스코프를 가진다. 블록 스코프란 `if`, `for`, 함수 등에서 사용하는 중괄호 `{}` 내부 범위를 의미한다. 블록 안에서 선언한 변수는 블록 바깥에서 접근할 수 없다.

```js
let x = 1

if (x === 1) {
  // 이 x는 if 블록 안에서 새로 선언된 변수다.
  let x = 2
  console.log(x) // 2
}

// 바깥의 x는 여전히 1이다.
console.log(x) // 1
```

이 코드는 처음 보면 같은 이름의 `x`가 두 번 나와 헷갈릴 수 있다. 하지만 안쪽 블록의 `x`와 바깥쪽의 `x`는 서로 다른 변수다. 블록 스코프는 변수가 의도하지 않은 범위까지 퍼지는 것을 막아주므로, 코드의 안정성을 높인다.

⚠️ 주의: Python을 먼저 배운 경우, JavaScript의 `{}` 블록 범위가 어색할 수 있다. JavaScript에서는 중괄호가 변수의 접근 가능 범위를 결정하는 중요한 기준이 된다.

---

### 3.2.5 var를 권장하지 않는 이유

`var`는 ES6 이전에 주로 사용하던 변수 선언 키워드다. 재할당과 재선언이 모두 가능하고, 블록 스코프가 아니라 함수 스코프를 가진다. 또한 호이스팅 특성 때문에 선언 전에 접근해도 에러가 나지 않고 `undefined`가 나오는 등 예기치 못한 동작이 발생할 수 있다.

```js
// var는 재선언이 가능하다.
var age = 20
var age = 30

console.log(age) // 30
```

이런 유연함은 작은 코드에서는 편해 보일 수 있지만, 규모가 커질수록 버그를 만들기 쉽다. 그래서 현대 JavaScript에서는 `var` 대신 `const`와 `let`을 사용하는 것이 일반적이다.

## 3.3 웹 브라우저에서 JavaScript 실행하기

JavaScript는 웹 브라우저 안에서 여러 방식으로 실행할 수 있다. 강의에서는 세 가지 방식을 확인했다.

첫 번째는 HTML 문서 안에 `<script>` 태그를 직접 작성하는 방식이다.

![HTML script 태그로 JavaScript 실행](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 164155.png>)

이 방식은 간단한 실습이나 짧은 코드 확인에는 편하지만, 코드가 길어지면 HTML 구조와 JavaScript 로직이 섞여 관리하기 어려워진다.

```html
<body>
  <script>
    console.log('hello')
  </script>
</body>
```

두 번째는 JavaScript 코드를 별도의 `.js` 파일로 분리하고, HTML에서 `src` 속성으로 불러오는 방식이다.

![외부 JavaScript 파일 연결](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 164222.png>)

```html
<body>
  <!-- hello.js 파일을 불러온다. -->
  <script src="hello.js"></script>
</body>
```

```js
// hello.js
console.log('hello')
```

실제 프로젝트에서는 이처럼 JavaScript 파일을 분리하는 방식이 일반적이다. HTML은 구조를 담당하고, JavaScript는 동작을 담당하게 나누면 유지보수가 쉬워진다.

세 번째는 브라우저 개발자 도구의 Console 탭에서 직접 JavaScript를 실행하는 방식이다.

![브라우저 Console에서 JavaScript 실행](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 164243.png>)

Console은 간단한 코드 테스트, DOM 요소 확인, 에러 메시지 확인에 자주 사용된다. 앞으로 DOM 조작을 연습할 때도 `console.log()`를 통해 선택한 요소가 제대로 잡혔는지 확인하는 습관이 중요하다.

## 3.4 문서 구조와 DOM

HTML 문서는 여러 태그가 중첩된 구조로 이루어진다. 겉으로 보면 텍스트 파일처럼 보이지만, 브라우저는 이 HTML을 그대로 문자열로만 다루지 않는다. 브라우저는 HTML을 해석해서 각 태그를 객체로 만들고, 부모-자식 관계를 가진 트리 구조로 구성한다.

![HTML 문서 구조 예시](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 164327.png>)

위와 같은 HTML 문서를 브라우저가 해석하면, 각 태그는 상자처럼 중첩된 구조로 볼 수 있다.

![HTML 문서를 상자 구조로 이해하기](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 164343.png>)

이렇게 브라우저가 문서를 표현하기 위해 사용하는 객체 모델이 **DOM**이다.

```text
DOM(The Document Object Model)
웹 페이지를 구조화된 객체로 제공하여,
프로그래밍 언어가 문서 구조와 내용, 스타일에 접근하고 조작할 수 있게 하는 모델
```

쉽게 말하면 DOM은 HTML 문서를 JavaScript가 다룰 수 있는 객체 구조로 바꾼 것이다. JavaScript는 이 객체 구조를 통해 특정 요소를 찾고, 그 요소의 내용이나 속성을 변경한다.

---

### 3.4.1 DOM API

DOM API는 JavaScript 같은 프로그래밍 언어가 웹 페이지에 접근하고 조작할 수 있도록 제공되는 명령어 모음이다. HTML 요소들이 객체 형태로 제공되고, 이 객체에는 관련 속성과 메서드가 함께 들어 있다.

![JavaScript와 DOM API](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 164728.png>)

예를 들어 `document.querySelector()`는 HTML 문서에서 특정 요소를 찾는 메서드이고, `element.textContent`는 선택한 요소의 텍스트 내용을 읽거나 바꾸는 속성이다.

```js
// 문서에서 h1 요소를 하나 찾는다.
const h1Tag = document.querySelector('h1')

// 선택한 h1 요소의 텍스트를 변경한다.
h1Tag.textContent = 'DOM 조작 연습'
```

이 코드는 HTML 파일 자체를 열어서 문자열을 바꾸는 것이 아니다. 브라우저가 만들어둔 DOM 객체의 속성을 변경하고, 브라우저는 그 변경 사항을 화면에 반영한다.

---

### 3.4.2 document 객체

`document` 객체는 웹 페이지를 나타내는 DOM Tree의 최상위 객체다. HTML 문서 안의 모든 콘텐츠에 접근하고 조작할 수 있는 진입점이라고 볼 수 있다.

![document 객체와 브라우저 개발자 도구](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 164834.png>)

DOM에서 모든 요소, 속성, 텍스트는 하나의 객체로 표현된다. 그리고 이 객체들은 모두 `document` 객체의 하위에 구성된다.

![document를 중심으로 구성되는 DOM 객체](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 164906.png>)

예를 들어 브라우저 Console에서 다음과 같이 입력하면 현재 문서의 제목을 확인하고 바꿀 수 있다.

![document.title 변경 예시](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 164938.png>)

```js
// 현재 문서의 title을 확인한다.
console.log(document.title)

// 문서의 title을 새로운 값으로 변경한다.
document.title = 'Hello JS'
```

여기서 `document.title`은 HTML의 `<title>` 요소와 연결되어 있다. 값을 바꾸면 브라우저 탭에 표시되는 제목도 함께 바뀐다.

📌 핵심: DOM 조작은 대부분 `document`에서 출발한다. 먼저 문서 전체에 접근하고, 그 안에서 필요한 요소를 선택한 뒤 조작한다.

---

### 3.4.3 DOM Tree

DOM Tree는 HTML 태그들의 관계를 나무 모양으로 표현한 계층 구조다. HTML 문서의 각 부분은 Node로 표현되고, 요소들은 부모와 자식 관계를 가진다.

![DOM Tree 구조](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 165152.png>)

위 구조를 보면 `document` 아래에 `html`이 있고, 그 아래에 `head`와 `body`가 나뉜다. `body` 안에는 `h1`, `p`, `a` 같은 요소가 들어갈 수 있다.

이 구조를 이해해야 하는 이유는 DOM 선택과 조작이 결국 이 트리 안에서 특정 노드를 찾는 과정이기 때문이다. `document.body`라고 쓰면 문서의 body 요소에 접근하고, `document.querySelector('h1')`이라고 쓰면 문서 안에서 첫 번째 `h1` 요소를 찾는다.

---

## 3.5 DOM 조작의 기본 흐름

웹 페이지를 동적으로 만든다는 것은 결국 웹 페이지를 조작한다는 뜻이다. DOM 조작은 항상 비슷한 순서로 진행된다.

1. 조작하고 싶은 요소를 선택한다.
2. 선택한 요소의 콘텐츠, 속성, 클래스, 스타일, 구조를 바꾼다.

이 흐름을 놓치면 코드가 복잡해 보인다. 하지만 어떤 DOM 코드든 “선택 → 조작”으로 나누어 읽으면 훨씬 이해하기 쉽다.

```js
// 1. 선택
const h1Tag = document.querySelector('h1')

// 2. 조작
h1Tag.textContent = '새로운 제목'
```

---

### 3.5.1 querySelector()

`document.querySelector(selector)`는 제공한 CSS 선택자와 일치하는 첫 번째 요소를 하나 선택한다. 일치하는 요소가 없으면 `null`을 반환한다.

```js
// 문서에서 첫 번째 h1 요소를 선택한다.
const h1Tag = document.querySelector('h1')

// class가 content인 첫 번째 요소를 선택한다.
const content = document.querySelector('.content')

// id가 title인 요소를 선택한다.
const title = document.querySelector('#title')
```

`querySelector()`는 하나만 반환한다. 같은 선택자를 만족하는 요소가 여러 개 있어도 첫 번째 요소만 가져온다.

---

### 3.5.2 querySelectorAll()

`document.querySelectorAll(selector)`은 제공한 선택자와 일치하는 여러 요소를 선택한다. 반환값은 `NodeList`다.

```js
// 문서의 모든 p 요소를 선택한다.
const pTags = document.querySelectorAll('p')

// NodeList는 인덱스로 접근할 수 있다.
console.log(pTags[0])
console.log(pTags[1])
```

NodeList는 배열과 비슷하게 보이지만, 정확히는 DOM 메서드가 반환하는 노드 목록이다. `forEach()` 같은 일부 배열 메서드는 사용할 수 있지만, 일반 배열과 완전히 같다고 생각하면 헷갈릴 수 있다.

---

### 3.5.3 DOM 선택 실습

강의에서는 `querySelector()`와 `querySelectorAll()`을 이용해 HTML 문서의 특정 요소를 선택하는 실습을 진행했다.

![DOM 선택 실습](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 173749.png>)

예시 흐름은 다음과 같이 정리할 수 있다.

```html
<body>
  <h1 class="heading">DOM 조작</h1>
  <p class="content">content 1</p>
  <p class="content">content 2</p>
  <p class="content">content 3</p>
</body>
```

```js
// class가 heading인 첫 번째 요소를 선택한다.
const h1Tag = document.querySelector('.heading')
console.log(h1Tag)

// class가 content인 모든 요소를 선택한다.
const contents = document.querySelectorAll('.content')
console.log(contents)

// NodeList에서 첫 번째 요소에 접근한다.
console.log(contents[0])
```

⚠️ 주의: `querySelector()`의 인자는 CSS 선택자 형태로 작성해야 한다. 클래스는 `.heading`, 아이디는 `#title`, 태그는 `h1`처럼 쓴다. 클래스 이름만 `heading`이라고 쓰면 `<heading>`이라는 태그를 찾으려는 의미가 된다.

📌 핵심: DOM 조작은 먼저 선택이 정확해야 한다. 선택 결과가 `null`이면 그 다음 조작 코드는 정상적으로 실행될 수 없다.

---

## 3.6 DOM 속성 조작

DOM에서 요소를 선택한 뒤에는 그 요소의 속성을 바꿀 수 있다. 속성 조작은 크게 두 가지로 나눌 수 있다.

1. 클래스 속성 조작
2. 일반 HTML 속성 조작

클래스 속성은 스타일링과 상태 표현에 자주 사용된다. 일반 속성은 `id`, `href`, `src`, `alt`처럼 HTML 요소가 가진 속성 값을 조회하거나 변경할 때 사용한다.

---

### 3.6.1 classList로 클래스 조작하기

`classList`는 요소의 클래스 목록을 DOMTokenList 형태로 반환하는 속성이다. 이 속성을 사용하면 클래스를 쉽게 추가하거나 제거할 수 있다.

```js
const h1Tag = document.querySelector('h1')

// red 클래스를 추가한다.
h1Tag.classList.add('red')

// red 클래스를 제거한다.
h1Tag.classList.remove('red')

// red 클래스가 있으면 제거하고, 없으면 추가한다.
h1Tag.classList.toggle('red')
```

`toggle()`은 상태 전환에 자주 사용된다. 예를 들어 버튼을 클릭할 때마다 다크 모드를 켜고 끄거나, 메뉴를 열고 닫는 기능을 만들 때 유용하다.

---

### 3.6.2 classList 실습

강의에서는 CSS에 특정 클래스를 미리 정의한 뒤, JavaScript에서 해당 클래스를 추가하고 제거하는 방식으로 스타일 변화를 확인했다.

![클래스 조작을 위한 CSS 예시](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 174423.png>)

![classList를 사용한 클래스 조작 실습](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 174443.png>)

예시 코드는 다음처럼 정리할 수 있다.

```html
<h1 class="heading">DOM 조작</h1>
```

```css
.red {
  color: crimson;
}
```

```js
// class가 heading인 h1 요소를 선택한다.
const h1Tag = document.querySelector('.heading')

// 현재 h1 요소의 클래스 목록을 확인한다.
console.log(h1Tag.classList)

// red 클래스를 추가하면 CSS 규칙이 적용되어 글자색이 바뀐다.
h1Tag.classList.add('red')
console.log(h1Tag.classList)

// red 클래스를 제거하면 다시 원래 상태로 돌아간다.
h1Tag.classList.remove('red')
console.log(h1Tag.classList)

// toggle은 red가 없으면 추가하고, 있으면 제거한다.
h1Tag.classList.toggle('red')
console.log(h1Tag.classList)
```

여기서 중요한 점은 JavaScript가 직접 색상을 바꾸는 것이 아니라, 클래스 목록을 바꾸고 CSS가 그 클래스에 맞는 스타일을 적용한다는 점이다. 스타일을 많이 변경해야 할 때는 `style` 속성을 직접 바꾸는 것보다 class를 제어하는 방식이 더 관리하기 쉽다.

⚠️ 주의: `classList.add('red')`에서 `red` 앞에 점을 붙이지 않는다. CSS 선택자에서는 `.red`라고 쓰지만, 클래스 이름을 메서드에 전달할 때는 `'red'`만 전달한다.

---

### 3.6.3 일반 속성 조작

일반 속성은 `getAttribute()`, `setAttribute()`, `removeAttribute()`로 다룰 수 있다.

| 메서드 | 역할 |
|---|---|
| `getAttribute(name)` | 해당 속성 값을 조회한다. |
| `setAttribute(name, value)` | 속성 값을 설정한다. 속성이 없으면 새로 추가한다. |
| `removeAttribute(name)` | 해당 속성을 제거한다. |

```js
const aTag = document.querySelector('a')

// href 속성 값을 조회한다.
console.log(aTag.getAttribute('href'))

// href 속성 값을 새 주소로 변경한다.
aTag.setAttribute('href', 'https://www.naver.com/')

// target 속성을 추가한다.
aTag.setAttribute('target', '_blank')

// href 속성을 제거한다.
aTag.removeAttribute('href')
```

강의 실습에서는 링크 태그의 `href` 값을 확인하고, 다른 주소로 변경한 뒤, 속성을 제거하는 흐름을 확인했다.

![일반 속성 조작 실습](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 174812.png>)

⚠️ 주의: `setAttribute()`에 숫자나 boolean 값을 넣어도 HTML 속성으로 저장될 때는 문자열처럼 다뤄진다. 또한 `getAttribute()`는 HTML 속성 값을 기준으로 읽고, `.value` 같은 DOM 프로퍼티는 현재 상태 값을 읽는 경우가 있어 입력 요소를 다룰 때 차이가 날 수 있다.

---

## 3.7 HTML 콘텐츠 조작

요소의 텍스트 내용을 바꾸고 싶을 때는 `textContent`를 사용할 수 있다. `textContent`는 요소 안의 텍스트 콘텐츠를 표현하는 속성이다.

```js
const h1Tag = document.querySelector('h1')

// 현재 텍스트를 확인한다.
console.log(h1Tag.textContent)

// 텍스트를 변경한다.
h1Tag.textContent = '내용 수정'
```

강의 실습에서는 `h1` 요소의 기존 텍스트를 출력한 뒤, 새로운 텍스트로 바꾸는 과정을 확인했다.

![textContent를 사용한 콘텐츠 조작](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 175008.png>)

`textContent`는 HTML 태그를 해석하지 않고 순수 텍스트로 다룬다. 즉, 문자열 안에 `<strong>` 같은 태그를 넣어도 HTML로 해석되는 것이 아니라 텍스트 그대로 들어간다.

```js
const h1Tag = document.querySelector('h1')

// strong 태그가 실제 태그로 적용되는 것이 아니라 문자열로 표시된다.
h1Tag.textContent = '<strong>제목</strong>'
```

이 특징은 보안 측면에서 장점이 있다. 사용자가 입력한 값을 화면에 보여줄 때 HTML로 해석하지 않기 때문에, 원하지 않는 태그 실행을 막는 데 도움이 된다.

---

## 3.8 DOM 요소 조작

기존 요소의 내용이나 속성을 바꾸는 것뿐만 아니라, JavaScript로 새로운 HTML 요소를 만들고 문서에 추가하거나 제거할 수도 있다.

DOM 요소 조작에서 자주 사용하는 메서드는 다음과 같다.

| 메서드 | 역할 |
|---|---|
| `document.createElement(tagName)` | 새로운 HTML 요소 객체를 생성한다. |
| `appendChild(node)` | 특정 부모 요소의 마지막 자식으로 노드를 추가한다. |
| `removeChild(node)` | 특정 부모 요소에서 자식 노드를 제거한다. |

---

### 3.8.1 createElement와 appendChild

`createElement()`는 새 요소를 만든다. 하지만 이때 만들어진 요소는 아직 화면에 보이지 않는다. 메모리 안에 객체만 만들어진 상태이기 때문이다. 화면에 보이게 하려면 부모 요소에 `appendChild()`로 삽입해야 한다.

![DOM 요소 생성과 추가 실습](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 175340.png>)

```html
<body>
  <div></div>
</body>
```

```js
// 1. 새로운 h1 요소를 만든다.
const h1Tag = document.createElement('h1')

// 2. 새로 만든 h1 요소에 텍스트를 넣는다.
h1Tag.textContent = '제목'

// 3. h1을 넣을 부모 div 요소를 선택한다.
const divTag = document.querySelector('div')

// 4. div의 마지막 자식으로 h1을 추가한다.
divTag.appendChild(h1Tag)
```

이 코드는 “새 요소 만들기 → 내용 채우기 → 부모 선택 → 부모에 추가하기” 순서로 읽으면 된다. `createElement()`까지만 작성하면 화면에는 아무 변화가 없다. 실제 문서에 연결하는 작업은 `appendChild()`가 담당한다.

---

### 3.8.2 removeChild

`removeChild()`는 부모 요소에서 특정 자식 요소를 제거한다.

```js
// 제거할 p 태그를 선택한다.
const pTag = document.querySelector('p')

// p 태그의 부모 요소를 선택한다.
const divTag = document.querySelector('div')

// div의 자식인 pTag를 제거한다.
divTag.removeChild(pTag)
```

주의할 점은 `removeChild()`는 제거하려는 요소의 부모에서 호출해야 한다는 것이다. 자식 요소 스스로가 아니라, 그 자식을 포함하고 있는 부모가 자식을 제거한다.

⚠️ 주의: `createElement()`로 만든 요소는 `appendChild()`로 문서에 넣기 전까지 화면에 나타나지 않는다. 또한 `removeChild()`로 제거된 노드는 완전히 사라지는 것이 아니라 변수에 담아두었다면 다시 사용할 수 있다.

---

## 3.9 style 조작

`style` 속성은 해당 요소의 인라인 스타일 목록을 포함한다. JavaScript에서 `element.style`을 사용하면 HTML 태그의 `style="..."` 속성을 직접 수정하는 것과 비슷하게 동작한다.

![style 속성을 사용한 스타일 조작](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 175525.png>)

```js
// p 요소를 선택한다.
const pTag = document.querySelector('p')

// 글자색을 crimson으로 변경한다.
pTag.style.color = 'crimson'

// 글자 크기를 2rem으로 변경한다.
pTag.style.fontSize = '2rem'

// 테두리 스타일을 지정한다.
pTag.style.border = '1px solid black'
```

CSS에서는 `font-size`처럼 하이픈을 사용하지만, JavaScript의 `style` 객체에서는 `fontSize`처럼 camelCase로 작성한다.

```css
/* CSS */
font-size: 2rem;
```

```js
// JavaScript style property
pTag.style.fontSize = '2rem'
```

⚠️ 주의: 스타일을 한두 개 바꾸는 정도라면 `style` 속성이 간단하다. 하지만 여러 스타일을 상태에 따라 바꿔야 한다면 `classList`로 클래스를 추가·제거하는 방식이 더 깔끔하다.

---

## 3.10 개발자 도구에서 DOM 속성 확인하기

브라우저 개발자 도구에서는 선택한 요소의 DOM 속성을 직접 확인할 수 있다. Elements 탭에서 요소를 선택한 뒤 Properties를 보면 해당 요소가 가진 다양한 속성과 메서드를 살펴볼 수 있다.

![개발자 도구에서 DOM 속성 확인](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 175610.png>)

DOM을 처음 배울 때는 HTML에서 보이는 속성과 JavaScript 객체로서의 속성이 어떻게 연결되는지 헷갈릴 수 있다. 이럴 때 개발자 도구에서 실제 객체 속성을 확인하면 이해가 훨씬 빨라진다.

예를 들어 `<input>` 요소는 HTML 속성으로 `value`를 가질 수 있지만, 사용자가 입력한 현재 값은 DOM 프로퍼티인 `.value`로 읽는 경우가 많다. 이런 차이는 이후 form 처리나 이벤트 처리에서 자주 등장한다.

---

## 3.11 DOM 관련 용어 정리

DOM을 다룰 때 Node, NodeList, Element 같은 용어가 반복해서 나온다. 이 용어들은 비슷해 보이지만 범위가 다르기 때문에 구분해두면 좋다.

---

### 3.11.1 Node

Node는 DOM의 기본 구성 단위다. DOM Tree의 각 부분은 Node라는 객체로 표현된다.

```text
Document Node  : HTML 문서 전체를 나타내는 노드
Element Node   : <p>, <div>, <body> 같은 HTML 요소를 나타내는 노드
Text Node      : 요소 내부의 텍스트 콘텐츠를 나타내는 노드
Attribute Node : HTML 요소의 속성을 나타내는 노드
```

즉, Node는 DOM 안의 모든 구성 요소를 포괄하는 넓은 개념이다.

---

### 3.11.2 NodeList

NodeList는 DOM 메서드를 사용해 선택한 Node의 목록이다. `querySelectorAll()`을 사용하면 NodeList가 반환된다.

```js
const items = document.querySelectorAll('li')

console.log(items)
console.log(items[0])
```

NodeList는 배열과 비슷하게 인덱스로 접근할 수 있고, `forEach()`를 사용할 수 있다. 하지만 JavaScript의 일반 배열과 완전히 같지는 않다. 필요한 경우 `Array.from()`을 사용해 배열로 변환할 수 있다.

```js
const items = document.querySelectorAll('li')
const itemArray = Array.from(items)
```

강의에서 중요한 포인트는 `querySelectorAll()`로 반환되는 NodeList가 DOM의 변경 사항을 실시간으로 반영하지 않는다는 점이다. 즉, 선택한 뒤 DOM에 새 요소가 추가되어도 기존 NodeList가 자동으로 늘어나지 않을 수 있다.

---

### 3.11.3 Element

Element는 DOM Tree에서 HTML 요소를 나타내는 특별한 유형의 Node다. `<p>`, `<div>`, `<span>`, `<body>` 같은 태그들이 Element Node를 만든다.

Element는 Node의 하위 유형이므로 Node의 속성과 메서드를 가지고 있으며, 추가로 `className`, `innerHTML`, `id`, `classList` 같은 요소 특화 기능도 가진다.

```text
모든 Element는 Node이지만,
모든 Node가 Element인 것은 아니다.
```

이 문장을 이해하면 Node와 Element의 관계가 정리된다. 텍스트도 Node지만 Element는 아니다. 반면 `<p>` 요소는 Element이면서 동시에 Node다.

---

### 3.11.4 Parsing

Parsing은 브라우저가 HTML 문자열을 해석하여 DOM Tree로 만드는 과정이다.

![Parsing 과정](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 180516.png>)

HTML 파일은 처음에는 문자열에 가깝다. 브라우저는 이 문자열을 읽으면서 태그의 시작과 끝, 부모-자식 관계, 텍스트 내용을 해석한다. 그리고 그 결과로 JavaScript가 접근할 수 있는 DOM Tree를 만든다.

Parsing을 이해하면 `script` 태그 위치가 왜 중요할 수 있는지도 이해할 수 있다. JavaScript가 실행되는 시점에 아직 HTML 요소가 DOM으로 만들어지지 않았다면, `querySelector()`로 해당 요소를 찾지 못할 수 있다.

⚠️ 주의: DOM 요소가 생성되기 전에 JavaScript가 먼저 실행되면 선택 결과가 `null`이 될 수 있다. 그래서 script를 body 끝에 두거나, DOMContentLoaded 이벤트 이후에 실행하는 방식이 사용된다.

---

## 3.12 Hoisting과 TDZ

JavaScript에서 변수 선언을 이해할 때 가장 헷갈리는 개념 중 하나가 호이스팅이다. 호이스팅은 코드가 실행되기 전 변수와 함수 선언이 스코프의 최상단으로 끌어올려지는 것처럼 보이는 현상이다.

정확히는 JavaScript 엔진이 코드를 실행하기 전에 선언 정보를 먼저 처리하기 때문에 이런 현상이 발생한다. 중요한 것은 모든 선언이 같은 방식으로 처리되는 것이 아니라는 점이다.

---

### 3.12.1 함수 스코프

`var`는 블록 스코프가 아니라 함수 스코프를 가진다. 함수 스코프란 함수의 중괄호 내부를 기준으로 변수 접근 범위가 결정된다는 뜻이다.

![함수 스코프 예시](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 180904.png>)

```js
function foo() {
  var x = 1
  console.log(x) // 1
}

// x는 함수 내부에서 선언되었기 때문에 바깥에서 접근할 수 없다.
// console.log(x) // ReferenceError: x is not defined
```

`var`는 함수 안에서는 지역 변수처럼 동작하지만, `if`나 `for` 같은 블록은 무시하는 특징이 있다. 이 때문에 `let`, `const`와 다르게 예측하기 어려운 코드가 만들어질 수 있다.

---

### 3.12.2 var의 호이스팅

JavaScript 엔진은 변수를 생성할 때 크게 세 단계를 거친다.

1. 선언(Declaration)
2. 초기화(Initialization)
3. 할당(Assignment)

`var`는 호이스팅될 때 선언과 초기화가 함께 진행된다. 즉, 코드의 실제 선언문에 도달하기 전에도 변수 이름은 이미 존재하고, 값은 `undefined`로 초기화되어 있다.

![var 호이스팅 예시](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 181250.png>)

```js
// 선언 전에 접근해도 에러가 아니라 undefined가 출력된다.
console.log(age) // undefined

var age = 30
```

이 코드는 실제로 아래처럼 동작하는 것처럼 이해할 수 있다.

```js
var age

console.log(age) // undefined

age = 30
```

⚠️ 주의: `undefined`가 출력된다고 해서 코드가 안전하다는 뜻은 아니다. 오히려 실수를 조용히 지나가게 만들어 디버깅을 어렵게 할 수 있다.

---

### 3.12.3 let과 const의 호이스팅

`let`과 `const`도 호이스팅된다. 다만 `var`처럼 선언과 초기화가 함께 진행되지 않는다. 스코프의 최상단에서 변수 이름은 등록되지만, 실제 선언문에 도달하기 전까지 초기화되지 않는다. 이 구간을 **TDZ**, 즉 Temporal Dead Zone이라고 부른다.

![let과 const의 호이스팅 예시](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 181406.png>)

```js
// let 변수는 호이스팅되지만 초기화 전에는 접근할 수 없다.
// console.log(age) // ReferenceError

let age = 30
```

만약 `let`과 `const`가 아예 호이스팅되지 않는다면 `age is not defined`처럼 변수 자체를 모른다는 에러가 나야 한다. 하지만 실제로는 초기화 전에 접근했다는 성격의 ReferenceError가 발생한다. 이는 엔진이 변수의 존재는 알고 있지만, 아직 사용할 수 있는 상태가 아니라는 뜻이다.

---

### 3.12.4 TDZ

TDZ는 스코프가 시작되는 지점부터 변수의 초기화가 이루어지는 실제 선언문까지의 구간이다. `let`, `const`, `class`는 이 구간에 있을 때 접근할 수 없다.

```js
// 여기부터 age의 TDZ가 시작된다.

// console.log(age) // ReferenceError

let age = 30

// 선언문 이후에는 접근 가능하다.
console.log(age) // 30
```

TDZ는 개발자의 실수를 막는 안전장치로 볼 수 있다. 선언 전에 변수를 사용하는 코드는 대부분 의도하지 않은 코드일 가능성이 높기 때문이다.

📌 핵심: `let`과 `const`도 호이스팅되지만, TDZ 때문에 선언 전에 접근할 수 없다.

---

### 3.12.5 함수 선언문의 호이스팅

함수 선언문은 `var`보다 더 강하게 호이스팅된다. 함수 선언문은 선언, 초기화, 할당이 모두 함께 처리되기 때문에, 함수 선언문보다 앞에서 함수를 호출해도 정상적으로 실행된다.

![함수 선언문의 호이스팅](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 181800.png>)

```js
// 함수 선언문은 선언 전에도 호출할 수 있다.
sayHello() // "Hello!" 출력

function sayHello() {
  console.log('Hello!')
}
```

하지만 함수 표현식이나 화살표 함수를 `const`에 담은 경우에는 변수의 TDZ 영향을 받는다.

```js
// sayHello는 const로 선언되었기 때문에 선언 전 접근이 불가능하다.
// sayHello() // ReferenceError

const sayHello = function () {
  console.log('Hello!')
}
```

---

### 3.12.6 호이스팅 요약 비교

강의에서는 `var`, `let/const`, `function`, `class`의 호이스팅 차이를 표로 정리했다.

![호이스팅 요약 비교](<../assets/images/05_13_DOM/화면 캡처 2026-06-09 181940.png>)

정리하면 다음과 같다.

| 구분 | 호이스팅 여부 | 초기화 시점 | 선언 전 접근 |
|---|---:|---|---|
| `var` | O | 스코프 진입 시 `undefined`로 초기화 | 가능하지만 `undefined` |
| `let` / `const` | O | 실제 선언문 실행 시 | ReferenceError |
| `function` 선언문 | O | 함수 객체까지 준비 | 호출 가능 |
| `class` | O | 실제 선언문 실행 시 | ReferenceError |

⚠️ 주의: “호이스팅된다”는 말을 “선언 전에 마음대로 써도 된다”로 이해하면 안 된다. 어떤 선언이 어느 단계까지 먼저 처리되는지가 핵심이다.

---

## 4. 적용 관점에서 다시 보기

이번 강의의 내용은 JavaScript로 실제 웹 페이지를 조작할 때 가장 기본이 되는 흐름이다. 앞으로 이벤트 처리, form 입력 처리, Vue의 반응형 렌더링을 배울 때도 이번 내용이 계속 연결된다.

먼저 DOM 조작 문제를 만나면 항상 “선택 → 조작” 순서로 생각하면 된다. 원하는 요소가 하나라면 `querySelector()`, 여러 개라면 `querySelectorAll()`을 떠올린다. 선택 결과가 기대와 다르면 조작 코드를 보기 전에 먼저 `console.log()`로 선택한 요소가 맞는지 확인해야 한다.

클래스나 스타일을 바꿀 때는 상황에 따라 도구를 나누어야 한다. 한두 개의 인라인 스타일을 빠르게 바꾸는 정도라면 `element.style`을 사용할 수 있다. 하지만 상태에 따라 여러 스타일을 함께 바꿔야 한다면 CSS 클래스를 미리 만들고 `classList.add()`, `classList.remove()`, `classList.toggle()`로 제어하는 편이 더 깔끔하다.

새로운 요소를 추가해야 한다면 `createElement()`만으로는 화면에 나타나지 않는다는 점을 떠올려야 한다. 요소를 만든 뒤 텍스트나 속성을 채우고, 마지막에 부모 요소를 선택해 `appendChild()`로 문서에 삽입해야 한다. 반대로 요소를 제거할 때는 제거할 대상의 부모에서 `removeChild()`를 호출한다.

변수 선언은 기본적으로 `const`를 사용한다. DOM 요소를 선택해 변수에 담을 때도 보통 선택한 요소 자체를 다른 요소로 바꾸지 않으므로 `const`가 적절하다. 다만 반복문 카운터처럼 값이 바뀌는 경우에는 `let`을 사용한다. `var`는 재선언, 함수 스코프, 호이스팅 문제 때문에 새 코드에서는 피하는 것이 좋다.

호이스팅과 TDZ는 에러를 해석할 때 도움이 된다. `undefined`가 출력되는지, `ReferenceError`가 발생하는지에 따라 `var`인지, `let/const`인지, 혹은 선언 위치가 잘못되었는지를 추적할 수 있다.

## 5. 배운 점 / 확장 포인트

### 5.1 이번 강의 이전에 몰랐던 것 또는 새로 이해된 것

DOM은 HTML 문서 자체가 아니라, 브라우저가 HTML을 해석해서 만든 객체 구조라는 점이 핵심이다. 그래서 JavaScript는 HTML 파일을 직접 수정하는 것이 아니라, DOM 객체의 속성과 메서드를 통해 화면을 변경한다.

또한 `const`는 값이 절대 변하지 않는다는 뜻이 아니라, 변수에 다른 값을 재할당할 수 없다는 뜻이다. DOM 요소를 `const`에 담아도 그 요소의 `textContent`, `classList`, `style` 같은 내부 속성은 변경할 수 있다.

### 5.2 앞으로 이어지는 연결점

이번 내용은 이벤트 처리로 바로 이어진다. DOM 요소를 선택한 뒤 클릭, 입력, 제출 같은 이벤트를 감지하고, 이벤트가 발생했을 때 DOM을 조작하는 방식으로 동적인 웹 페이지를 만들 수 있다.

또한 Vue를 배울 때도 DOM 조작의 기본 이해가 도움이 된다. Vue에서는 개발자가 직접 `querySelector()`로 DOM을 자주 조작하지는 않지만, 결국 Vue도 상태가 바뀌면 DOM을 갱신한다. DOM을 알고 있으면 Vue가 왜 편리한지 더 잘 이해할 수 있다.

### 5.3 더 파볼 만한 주제

이번 강의 이후에는 이벤트 처리(`addEventListener`), 입력값 다루기, 폼 제출 제어, 비동기 요청과 화면 갱신, DOMContentLoaded, innerHTML과 보안 문제를 함께 살펴볼 만하다. 특히 `textContent`와 `innerHTML`의 차이는 실제 프로젝트에서 보안과 직결될 수 있으므로 별도로 정리해두면 좋다.

## 6. 요약 정리

📌 핵심

- JavaScript는 웹 페이지에 동적인 기능을 추가하기 위해 등장했다.
- ECMAScript는 JavaScript의 표준 명세이고, JavaScript는 그 표준을 구현한 언어다.
- 현대 JavaScript에서는 기본적으로 `const`를 사용하고, 재할당이 필요한 경우에만 `let`을 사용한다.
- `var`는 재선언, 함수 스코프, 호이스팅 문제 때문에 권장되지 않는다.
- DOM은 HTML 문서를 브라우저가 객체 구조로 표현한 것이다.
- DOM 조작은 보통 “요소 선택 → 선택한 요소 조작” 순서로 진행된다.
- `querySelector()`는 첫 번째 요소 하나를 선택하고, `querySelectorAll()`은 여러 요소를 NodeList로 반환한다.
- `classList`는 클래스 추가, 제거, 토글에 사용한다.
- `getAttribute()`, `setAttribute()`, `removeAttribute()`는 일반 HTML 속성을 다룰 때 사용한다.
- `textContent`는 요소의 텍스트 내용을 읽거나 변경한다.
- `createElement()`는 요소를 만들고, `appendChild()`는 만든 요소를 문서에 삽입한다.
- `style` 속성은 인라인 스타일을 직접 조작한다.
- Node는 DOM의 기본 구성 단위이고, Element는 HTML 요소를 나타내는 특별한 Node다.
- Parsing은 브라우저가 HTML 문자열을 DOM Tree로 만드는 과정이다.
- `let`과 `const`도 호이스팅되지만 TDZ 때문에 선언 전에 접근할 수 없다.

🧠 기억할 것

> DOM 조작은 먼저 정확히 선택하고, 그 다음 필요한 속성이나 내용을 바꾸는 과정이다.  
> `createElement()`는 만들기만 할 뿐이고, 화면에 보이게 하려면 `appendChild()`가 필요하다.  
> 읽기 어려운 JavaScript 에러는 스코프, 호이스팅, TDZ 관점에서 보면 원인을 찾기 쉬워진다.
