- 🎯 글의 목표: AJAX가 왜 필요한지 이해하고, JavaScript에서 비동기 요청을 보내 서버 응답을 받아 화면에 반영하는 기본 흐름을 정리한다.
- 🧩 핵심 키워드: AJAX, 비동기 요청, XMLHttpRequest, fetch, Axios, Promise, JSON, then/catch, Network 탭
- ⭐ 중요도: 높음. 이후 Django와 연결해 팔로우, 좋아요, 댓글 같은 기능을 새로고침 없이 구현하는 기반이다.
- 📝 한눈에 보는 내용: 사용자의 요청으로 서버에 데이터를 보내고, 서버가 돌려준 응답을 JavaScript가 받아 DOM을 갱신하는 흐름을 학습한다.
- 🔗 관련 문제 / 주제: 비동기 JavaScript, API 요청, JSON 응답 처리, Axios, Django Ajax 연동

웹 페이지에서 서버와 통신한다고 하면 가장 먼저 떠오르는 흐름은 페이지 이동이다. 링크를 누르면 새로운 페이지를 받고, form을 제출하면 서버가 처리한 뒤 다시 HTML을 보내준다. 이 방식은 명확하지만 매번 화면 전체가 다시 그려진다.

AJAX는 이 흐름을 바꾼다. 페이지 전체를 새로 받지 않고, JavaScript가 필요한 데이터만 서버에 요청한다. 서버는 HTML 전체 대신 JSON 같은 데이터를 응답하고, 브라우저는 그 데이터를 이용해 필요한 DOM만 바꾼다.

이 개념을 잡아두면 다음 강의의 팔로우와 좋아요 비동기 구현이 훨씬 자연스럽게 이어진다. 결국 Django와 함께 쓰는 Ajax도 "요청을 보낸다 → JSON을 받는다 → DOM을 바꾼다"는 흐름 위에 놓여 있다.

## 2. 핵심 개념 정리

AJAX는 특정 라이브러리 이름이 아니라, 브라우저에서 서버와 비동기적으로 데이터를 주고받는 방식 전체를 가리킨다. 예전에는 `XMLHttpRequest`를 직접 사용했고, 지금은 `fetch`나 `Axios` 같은 도구를 더 자주 쓴다.

이 강의에서 잡아야 할 큰 그림은 세 가지다.

첫째, 비동기 요청은 코드가 서버 응답을 기다리는 동안 페이지 전체를 멈추지 않는다. 사용자는 화면을 계속 보고 있고, 응답이 도착하면 그때 필요한 처리를 이어간다.

둘째, 서버 응답은 보통 JSON 형태로 다룬다. JSON은 JavaScript 객체와 비슷한 구조라서 프론트엔드 코드에서 읽고 사용하기 쉽다.

셋째, 요청이 성공할 수도 있고 실패할 수도 있다. 그래서 성공 흐름은 `then`, 실패 흐름은 `catch`로 나누어 다룬다.

## 3. 본문 정리

### 3.1 AJAX는 화면 전체가 아니라 필요한 데이터만 요청한다

기존 form 제출 방식에서는 브라우저가 서버에 요청을 보내고, 서버가 새 HTML을 만들어 응답한다. 브라우저는 기존 화면을 버리고 새 HTML을 다시 렌더링한다.

AJAX에서는 이 과정이 더 작아진다. JavaScript가 서버에 요청을 보내고, 서버는 JSON 같은 데이터만 응답한다. 브라우저는 기존 화면을 유지한 채 응답 데이터를 이용해 필요한 부분만 바꾼다.

예를 들어 검색어를 입력했을 때 페이지 전체를 이동하지 않고 결과 목록만 바꾸거나, 좋아요 버튼을 눌렀을 때 버튼 문구만 바꾸는 방식이 여기에 해당한다.

```text
기존 요청 흐름
사용자 행동 -> 브라우저가 페이지 요청 -> 서버가 HTML 응답 -> 화면 전체 새로고침

AJAX 요청 흐름
사용자 행동 -> JavaScript가 데이터 요청 -> 서버가 JSON 응답 -> 필요한 DOM만 변경
```

📌 핵심: AJAX의 목적은 서버와 통신하지 않는 것이 아니라, 통신 결과를 페이지 전체 새로고침 없이 반영하는 것이다.

### 3.2 비동기 흐름은 "나중에 도착하는 응답"을 다루는 방식이다

서버 요청은 시간이 걸린다. 네트워크 상태나 서버 처리 시간에 따라 응답이 언제 도착할지 정확히 알 수 없다. JavaScript가 요청을 보낸 뒤 응답을 기다리느라 화면 전체를 멈추면 사용자 경험이 나빠진다.

그래서 비동기 방식에서는 요청을 보낸 뒤, 응답이 도착했을 때 실행할 코드를 따로 연결한다.

```javascript
console.log('요청 전')

axios({
  method: 'get',
  url: 'https://example.com/api/data/',
})
  .then((response) => {
    // 서버 응답이 성공적으로 도착한 뒤 실행된다.
    console.log('응답 데이터:', response.data)
  })
  .catch((error) => {
    // 요청 실패, 서버 오류, 네트워크 문제 등이 발생하면 실행된다.
    console.log('에러:', error)
  })

console.log('요청 후')
```

이 코드에서 `요청 후` 로그는 서버 응답보다 먼저 출력될 수 있다. 요청을 보낸 뒤 JavaScript가 다음 코드를 계속 실행하기 때문이다. 서버 응답을 사용하는 코드는 반드시 `then` 안쪽에서 처리해야 한다.

⚠️ 주의: AJAX를 처음 배울 때 가장 많이 헷갈리는 지점은 "요청 아래에 코드를 썼으니 응답 뒤에 실행되겠지"라고 생각하는 것이다. 비동기 요청의 결과는 응답이 도착한 뒤 실행되는 콜백 안에서 다루어야 한다.

### 3.3 JSON은 서버와 JavaScript 사이의 공통 데이터 형식이다

AJAX 요청에서 서버는 HTML이 아니라 데이터를 응답하는 경우가 많다. 이때 자주 쓰는 형식이 JSON이다.

JSON은 문자열 기반 데이터 형식이지만, 구조가 JavaScript 객체와 비슷하다.

```json
{
  "is_liked": true,
  "like_count": 12
}
```

Axios는 응답 JSON을 JavaScript에서 바로 사용할 수 있도록 `response.data`에 담아준다.

```javascript
axios({
  method: 'get',
  url: '/articles/1/status/',
})
  .then((response) => {
    const isLiked = response.data.is_liked
    const likeCount = response.data.like_count

    console.log(isLiked)
    console.log(likeCount)
  })
```

이 흐름을 이해하면 Django의 `JsonResponse`도 자연스럽게 연결된다. Django view가 JSON을 반환하면, JavaScript는 그 JSON을 `response.data`로 읽어 화면을 바꿀 수 있다.

### 3.4 Axios는 비동기 요청을 편하게 작성하게 해준다

브라우저에는 `fetch`가 기본으로 제공되지만, 수업과 실습에서는 Axios를 자주 사용한다. Axios는 요청 설정과 응답 처리가 깔끔하고, JSON 응답을 다루기 편하다.

가장 기본적인 GET 요청은 다음처럼 쓸 수 있다.

```javascript
axios({
  method: 'get',
  url: '/api/articles/',
})
  .then((response) => {
    // 서버가 보낸 데이터는 response.data에 들어 있다.
    console.log(response.data)
  })
  .catch((error) => {
    console.log(error)
  })
```

POST 요청에서는 서버에 보낼 데이터를 `data`에 담는다.

```javascript
axios({
  method: 'post',
  url: '/api/articles/',
  data: {
    title: 'AJAX 정리',
    content: '페이지 새로고침 없이 데이터를 주고받는다.',
  },
})
  .then((response) => {
    console.log('생성 결과:', response.data)
  })
  .catch((error) => {
    console.log('요청 실패:', error)
  })
```

GET은 주로 데이터를 조회할 때 쓰고, POST는 서버 상태를 바꾸거나 새 데이터를 만들 때 쓴다. 좋아요나 팔로우처럼 서버의 관계 데이터를 바꾸는 기능은 POST 요청으로 처리하는 편이 자연스럽다.

### 3.5 응답 데이터로 DOM을 갱신하기

AJAX 요청은 서버와 통신하는 것만으로 끝나지 않는다. 사용자가 결과를 볼 수 있으려면 응답 데이터를 화면에 반영해야 한다.

```html
<button id="load-button">데이터 불러오기</button>
<p id="result">아직 데이터가 없습니다.</p>
```

```javascript
const loadButton = document.querySelector('#load-button')
const result = document.querySelector('#result')

loadButton.addEventListener('click', function () {
  axios({
    method: 'get',
    url: '/api/message/',
  })
    .then((response) => {
      // 응답 데이터 중 message 값을 화면에 반영한다.
      result.textContent = response.data.message
    })
    .catch((error) => {
      result.textContent = '데이터를 불러오지 못했습니다.'
      console.log(error)
    })
})
```

이 예제의 핵심은 서버 응답을 `console.log`로 확인하는 데서 끝내지 않고, 실제 DOM에 반영한다는 점이다. Ajax 기능은 사용자 입장에서 화면 변화로 확인되어야 한다.

### 3.6 form과 AJAX를 함께 쓰려면 기본 제출을 막아야 한다

form은 기본적으로 제출과 동시에 페이지 이동을 일으킨다. Ajax로 form 데이터를 보내려면 이 기본 동작을 막고, JavaScript가 직접 요청을 보내야 한다.

```html
<form id="comment-form">
  <input name="content" type="text">
  <button type="submit">댓글 작성</button>
</form>
<ul id="comment-list"></ul>
```

```javascript
const commentForm = document.querySelector('#comment-form')
const commentList = document.querySelector('#comment-list')

commentForm.addEventListener('submit', function (event) {
  // form의 기본 제출과 페이지 새로고침을 막는다.
  event.preventDefault()

  const content = event.currentTarget.content.value

  axios({
    method: 'post',
    url: '/api/comments/',
    data: {
      content: content,
    },
  })
    .then((response) => {
      const li = document.createElement('li')
      li.textContent = response.data.content
      commentList.appendChild(li)

      // 제출 후 입력창을 비워 다음 입력을 준비한다.
      event.currentTarget.reset()
    })
    .catch((error) => {
      console.log(error)
    })
})
```

이 구조는 이후 Django와 연결할 때 거의 그대로 사용된다. 차이가 있다면 Django POST 요청에는 CSRF 토큰이 필요하고, 서버 view는 `JsonResponse`로 응답해야 한다는 점이다.

⚠️ 주의: `preventDefault()`를 빼먹으면 Ajax 요청을 보내기도 전에 브라우저가 페이지를 새로고침할 수 있다. form 기반 Ajax 구현에서 가장 먼저 확인해야 할 줄이다.

### 3.7 Network 탭은 AJAX 디버깅의 출발점이다

Ajax 요청이 실패했을 때는 JavaScript 코드만 들여다보면 원인을 놓치기 쉽다. 브라우저 개발자도구의 Network 탭을 보면 실제 요청이 어디로 갔는지, 어떤 상태 코드가 왔는지, 응답 데이터가 무엇인지 확인할 수 있다.

확인할 순서는 다음과 같다.

1. 요청이 실제로 발생했는지 확인한다.
2. 요청 URL이 의도한 주소인지 확인한다.
3. 요청 method가 GET/POST 등 의도한 방식인지 확인한다.
4. 상태 코드가 200번대인지 확인한다.
5. 응답 데이터가 예상한 JSON 구조인지 확인한다.
6. POST 요청이라면 CSRF나 권한 문제로 실패하지 않았는지 확인한다.

AJAX는 보이지 않는 곳에서 서버와 통신하기 때문에, Network 탭이 사실상 가장 중요한 디버깅 도구가 된다.

## 4. 적용 관점에서 다시 보기

AJAX 기능을 구현할 때는 먼저 "이 기능이 페이지 전체 새로고침 없이 처리되어야 하는가"를 판단한다. 사용자가 즉시 결과를 확인해야 하고, 바뀌는 화면이 일부라면 AJAX를 적용하기 좋다.

그다음 요청 흐름을 정리한다.

- 조회 기능이면 GET 요청을 생각한다.
- 상태 변경 기능이면 POST 요청을 생각한다.
- 서버가 돌려줘야 할 데이터가 무엇인지 먼저 정한다.
- 응답 데이터로 어떤 DOM을 바꿀지 정한다.

좋아요 버튼이라면 서버가 `is_liked`를 알려줘야 버튼 문구를 바꿀 수 있다. 팔로우 버튼이라면 `is_followed`, `followers_count`, `followings_count`가 필요하다. 즉, Ajax 구현에서는 view를 작성하기 전에 화면 갱신에 필요한 데이터를 먼저 생각해야 한다.

## 5. 배운 점 / 확장 포인트

### 5.1 이번 강의 이전에 몰랐던 것 또는 새로 이해된 것

AJAX는 단순히 빠른 요청이 아니라, 서버 응답을 화면 전체가 아닌 일부 DOM에 반영하는 방식이다. 그래서 요청 코드와 DOM 갱신 코드가 함께 있어야 기능이 완성된다.

### 5.2 앞으로 이어지는 연결점

이 내용은 바로 다음 강의인 `비동기 JS with Django`로 이어진다. Axios로 요청을 보내고 JSON을 받아 처리하는 기본 흐름 위에, Django의 CSRF 처리와 `JsonResponse`가 추가된다.

### 5.3 더 파볼 만한 주제

Promise의 동작 방식과 `async/await` 문법을 더 살펴보면 비동기 코드를 더 읽기 쉽게 정리할 수 있다. 또한 API 응답 형식을 일관되게 설계하는 방법은 DRF 학습과 연결된다.

## 6. 요약 정리

AJAX는 JavaScript가 서버와 비동기적으로 데이터를 주고받고, 응답 결과를 이용해 필요한 화면만 갱신하는 방식이다.

🧠 기억할 것:

- AJAX는 페이지 전체 새로고침 없이 서버와 통신하는 방식이다.
- Axios 요청의 성공 결과는 `then`, 실패 결과는 `catch`에서 처리한다.
- JSON 응답은 보통 `response.data`에서 읽는다.
- form을 Ajax로 처리할 때는 `event.preventDefault()`가 필요하다.
- 서버 응답을 받은 뒤에는 사용자가 볼 수 있도록 DOM을 갱신해야 한다.
- Ajax 디버깅은 개발자도구 Network 탭에서 시작하는 것이 좋다.
