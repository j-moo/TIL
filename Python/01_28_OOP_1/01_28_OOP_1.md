## 1. 들어가며

여러 학생의 이름, 나이, 학번을 관리하고 각 학생이 자기소개하도록 만드는 프로그램을 생각해 보자. 학생 한 명만 다룬다면 변수 몇 개와 함수 하나로도 충분하다. 그러나 학생 수가 늘면 `name1`, `age1`, `name2`, `age2`처럼 서로 관련된 데이터를 계속 따로 관리해야 한다. 함수에 어떤 학생의 값을 넘겨야 하는지도 개발자가 매번 맞춰야 한다.

객체 지향 프로그래밍은 이 문제를 보는 관점을 바꾼다. 이름과 나이를 따로 떠다니는 값으로 두지 않고, 그 정보를 사용하는 자기소개 기능까지 묶어 하나의 `Student` 객체로 다룬다. 먼저 학생을 만드는 공통 틀인 클래스를 정의하고, 그 틀에서 서로 다른 정보를 가진 학생 인스턴스를 생성하는 방식이다.

이번 강의에서는 절차 지향과 객체 지향의 차이에서 출발한다. 이어 객체·클래스·인스턴스의 관계를 정리하고, 클래스 변수와 인스턴스 변수가 저장되는 공간을 살펴본다. 마지막으로 세 종류의 메서드, 매직 메서드, 데코레이터까지 연결한다.

객체 지향 문법을 배울 때는 `class`, `self`, `@classmethod` 같은 표면적인 문법만 외우기 쉽다. 그러나 더 중요한 질문은 다음과 같다.

> 이 데이터와 동작은 누구의 책임이며, 무엇의 상태를 읽거나 바꾸는가?

이 질문에 답할 수 있으면 속성과 메서드를 어디에 두어야 하는지, 세 종류의 메서드 중 무엇을 선택해야 하는지도 자연스럽게 결정된다.

## 2. 핵심 개념 정리

이번 강의가 해결하려는 핵심 문제는 **서로 관련된 데이터와 기능을 어떻게 묶어, 독립적이고 재사용 가능한 단위로 관리할 것인가**이다.

본문은 다음 흐름으로 이어진다.

1. 먼저 절차 지향이 실행 순서를 중심으로 프로그램을 구성하는 방식을 살펴본다. 이를 통해 프로그램이 커질 때 데이터와 함수가 흩어지는 문제가 왜 생기는지 확인한다.
2. 객체 지향에서는 데이터와 기능을 객체에 묶고, “어떤 순서인가?”보다 “어떤 객체가 책임질 것인가?”를 먼저 생각한다.
3. 클래스는 공통 구조를 정의하는 설계도이자 새로운 타입이고, 인스턴스는 그 클래스로 만든 구체적인 객체라는 관계를 잡는다.
4. 클래스 안에서는 모든 인스턴스가 공유하는 클래스 변수와 각 인스턴스가 따로 보관하는 인스턴스 변수를 구분한다.
5. 무엇의 상태를 다루는지에 따라 인스턴스 메서드, 클래스 메서드, 스태틱 메서드를 선택한다.
6. 속성을 찾는 이름 공간의 탐색 순서를 이해한 뒤, 특별한 상황에 자동 호출되는 매직 메서드와 기존 함수를 감싸 기능을 확장하는 데코레이터까지 살펴본다.

이 흐름의 중심에는 언제나 **클래스는 공통 규칙을, 인스턴스는 개별 상태를 담당한다**는 구분이 있다.

## 3. 본문 정리

이 섹션에서는 강의 흐름을 따라 객체 지향의 관점과 Python 문법을 함께 정리한다. 예제 코드는 OCR 오류를 바로잡고, 처음 읽는 사람도 실행 흐름을 따라갈 수 있도록 주석을 보강했다.

### 3.1 프로그래밍 패러다임: 문제를 바라보는 방식

프로그래밍 패러다임은 프로그램을 구성하고 문제를 해결하는 데 사용하는 사고방식이다. 같은 문제라도 어떤 관점을 택하느냐에 따라 데이터와 함수의 배치, 실행 흐름, 코드의 책임이 달라진다.

절차 지향과 객체 지향은 서로 완전히 반대되는 기술이 아니다. 객체 지향 프로그램 안에서도 문장은 위에서 아래로 실행되고, 함수와 조건문을 사용한다. 객체 지향은 절차 지향의 실행 구조를 없애는 것이 아니라, 프로그램을 더 잘 조직하기 위해 **객체**라는 단위를 도입한 패러다임이다.

### 3.2 절차 지향 프로그래밍: 순서와 함수 중심의 구성

절차 지향 프로그래밍(Procedural Programming)은 함수와 로직을 중심으로 데이터를 순차적으로 처리한다. 라면을 끓이는 과정을 떠올리면 이해하기 쉽다.

1. 물을 끓인다.
2. 스프를 넣는다.
3. 면을 넣고 익힌다.
4. 불을 끄고 그릇에 담는다.

무엇을 어떤 순서로 실행할지가 핵심이며, 입력을 받아 처리하고 결과를 내는 흐름이 위에서 아래로 이어진다. 다음 코드는 사람의 정보와 자기소개 기능을 각각 변수와 함수로 분리한다.

```python
# 사람의 데이터는 함수 밖의 별도 변수로 관리한다.
name = "Alice"
age = 25


def introduce(name, age):
    # 전달받은 데이터를 순서대로 조합해 결과를 출력한다.
    print(f"안녕하세요, {name}입니다. 나이는 {age}살입니다.")


# 어떤 데이터를 사용할지 호출하는 쪽에서 직접 전달해야 한다.
introduce(name, age)
```

작은 프로그램에서는 이 방식이 단순하고 명확하다. 처리 순서가 중요하고 데이터 구조가 복잡하지 않다면 절차 지향만으로도 충분히 좋은 코드를 작성할 수 있다.

하지만 프로그램 규모가 커지면 데이터와 함수의 수가 함께 늘어난다. 여러 함수가 같은 전역 변수를 읽고 바꾸기 시작하면, 한 부분의 수정이 어디까지 영향을 주는지 추적하기 어려워진다. 관련 데이터와 함수가 흩어져 있어 유지보수 비용도 커진다.

⚠️ 주의: 절차 지향을 “나쁜 방식”, 객체 지향을 “좋은 방식”으로 나누면 안 된다. 문제의 성격과 규모에 따라 적절한 구성 방식이 다르며, 객체 지향도 내부적으로 절차적인 실행 흐름을 사용한다.

### 3.3 객체 지향 프로그래밍: 데이터와 기능을 객체로 묶기

객체 지향 프로그래밍(Object-Oriented Programming, OOP)은 관련된 데이터와 그 데이터를 처리하는 기능을 하나의 객체로 묶어 프로그램을 구성한다.

절차 지향에서는 이름과 나이가 함수로 전달되는 수동적인 데이터였다. 객체 지향에서는 사람 객체가 자신의 이름과 나이를 보관하고, 자기소개라는 기능도 스스로 수행한다.

```python
class Person:
    # 새 Person 인스턴스가 생성될 때 이름과 나이를 저장한다.
    def __init__(self, name, age):
        self.name = name
        self.age = age

    # 각 인스턴스가 자신의 데이터를 이용해 동작한다.
    def introduce(self):
        print(f"안녕하세요, {self.name}입니다. 나이는 {self.age}살입니다.")


# Person이라는 같은 틀에서 Alice 객체를 만든다.
alice = Person("Alice", 25)

# 데이터를 다시 인자로 나열하지 않아도 alice가 자신의 정보로 동작한다.
alice.introduce()
```

이제 이름, 나이, 자기소개 기능이 `Person`이라는 한 단위 안에 모인다. 객체마다 자신의 값을 가지므로 여러 사람을 만들어도 데이터가 뒤섞이지 않는다.

두 관점의 질문을 비교하면 차이가 더 선명하다.

| 관점 | 먼저 던지는 질문 | 구성의 중심 |
|---|---|---|
| 절차 지향 | 어떤 순서로 처리할까? | 함수 호출과 실행 흐름 |
| 객체 지향 | 어떤 객체가 해결할까? 이 객체는 어떤 속성과 기능을 가질까? | 객체의 책임과 상호작용 |

객체 지향에서는 객체끼리 메시지를 주고받으며 협력한다. 여기서 메시지를 보낸다는 것은 보통 다른 객체의 메서드를 호출하는 형태로 나타난다.

💡 포인트: 객체 지향의 핵심은 현실의 사물을 무조건 클래스로 바꾸는 데 있지 않다. 함께 변하고 함께 사용되는 상태와 동작을 하나의 책임 있는 단위로 조직하는 데 있다.

### 3.4 객체, 속성, 메서드

객체(Object)는 실제 사물이나 개념에서 필요한 특징을 추려 프로그램 안에 표현한 것이다. 객체는 보통 상태를 나타내는 **속성(Attribute)**과 행동을 나타내는 **메서드(Method)**를 가진다.

강아지 객체를 예로 들면 이름, 품종, 나이는 속성이 되고, 짖기와 뛰기는 메서드가 된다. 가수 객체라면 직업, 생년월일, 국적 같은 정보와 춤추기, 노래하기 같은 행동을 묶을 수 있다.

| 구성 요소 | 의미 | 예시 |
|---|---|---|
| 속성 | 객체의 상태 또는 데이터 | 이름, 나이, 잔액, 반지름 |
| 메서드 | 객체의 행동 또는 기능 | 자기소개, 입금, 출금, 넓이 계산 |
| 고유성 | 같은 종류의 객체도 서로 다른 상태를 가짐 | Alice와 Bella의 이름·나이가 다름 |

모든 현실 정보를 객체에 넣을 필요는 없다. 프로그램의 목적에 필요한 속성과 행동만 선택하는 것이 추상화의 출발점이다.

### 3.5 클래스와 인스턴스: 설계도와 실제 물건

클래스(Class)는 관련된 데이터와 기능을 하나의 틀로 정의한 설계도이며, Python에서 새로운 타입을 만드는 수단이다. 인스턴스(Instance)는 클래스를 호출해 실제로 생성한 구체적인 객체이다.

자동차 설계도에는 색상, 최고 속도, 좌석 수 같은 속성과 가속하기, 정지하기, 방향 바꾸기 같은 기능을 정의할 수 있다. 같은 설계도를 사용해 생산한 자동차들은 공통 구조를 따르지만, 각 자동차의 색상과 주행 거리는 서로 다를 수 있다.

```python
class Person:
    # 클래스 이름은 여러 단어라면 PascalCase로 작성한다.
    def __init__(self, name, age):
        # 인스턴스마다 독립적으로 저장될 속성이다.
        self.name = name
        self.age = age

    def introduce(self):
        print(f"안녕하세요, 저는 {self.name}, 나이는 {self.age}살입니다.")


# 같은 클래스에서 서로 다른 두 인스턴스를 생성한다.
p1 = Person("Alice", 25)
p2 = Person("Bella", 30)

p1.introduce()  # 안녕하세요, 저는 Alice, 나이는 25살입니다.
p2.introduce()  # 안녕하세요, 저는 Bella, 나이는 30살입니다.
```

클래스와 인스턴스의 관계를 표현할 때는 기준이 되는 클래스를 함께 말하는 것이 정확하다. “아이유는 객체다”는 맞고, “아이유는 가수 클래스의 인스턴스다”도 맞다. 반면 “아이유는 인스턴스다”만으로는 **무슨 클래스의 인스턴스인지** 알 수 없어 설명이 모호하다.

```python
class Singer:
    pass


iu = Singer()

# 객체가 어떤 클래스에서 생성되었는지 확인한다.
print(type(iu))  # <class '__main__.Singer'>
```

클래스를 정의하는 일은 새로운 타입을 만드는 일과 같다. Python에서 이미 사용해 온 `int`, `str`, `list`도 모두 클래스다.

```python
name = "Alice"

# 문자열 객체 name은 str 클래스에서 만들어진 인스턴스이다.
print(type(name))  # <class 'str'>

# 각 객체는 자신이 속한 클래스가 제공하는 메서드를 사용할 수 있다.
print("hello".upper())  # HELLO

numbers = [3, 1, 2]
numbers.sort()
print(numbers)  # [1, 2, 3]
```

따라서 `123`, `900`, `5`는 `int` 클래스의 인스턴스이고, 문자열들은 `str` 클래스의 인스턴스이며, `[232, 89, 1]`과 `[]`는 `list` 클래스의 인스턴스이다.

📌 핵심: 클래스는 공통 구조와 동작을 정의하는 타입이고, 인스턴스는 그 타입에서 생성되어 독립적인 상태를 가지는 객체이다.

### 3.6 클래스 정의와 생성자 메서드

Python에서는 `class` 키워드로 클래스를 정의한다. 클래스 이름은 관례적으로 PascalCase를 사용한다. 아직 아무 기능이 없는 클래스라면 `pass`로 본문을 비워 둘 수 있다.

```python
class MyClass:
    # 문법적으로 비어 있는 블록을 만들기 위한 자리 표시자이다.
    pass
```

실제 클래스에서는 인스턴스 생성에 필요한 초기 상태를 `__init__` 메서드에서 설정한다. `__init__`은 인스턴스가 만들어질 때 자동으로 호출되는 생성자 메서드라고 배운다.

```python
class Person:
    def __init__(self, name):
        # 왼쪽 self.name은 인스턴스 변수이다.
        # 오른쪽 name은 호출할 때 전달받은 매개변수이다.
        self.name = name
        print("인스턴스가 생성되었습니다.")

    def greeting(self):
        print(f"안녕하세요. {self.name}입니다.")


# Person("지민")을 평가하면 새 객체가 만들어지고 __init__이 자동 호출된다.
person1 = Person("지민")  # 인스턴스가 생성되었습니다.

# 생성 과정에서 저장한 self.name을 greeting이 다시 사용한다.
person1.greeting()  # 안녕하세요. 지민입니다.
```

`self.name = name`에서 양쪽 이름이 같아 처음에는 헷갈리기 쉽다. 왼쪽은 **객체 안에 저장되는 속성**이고, 오른쪽은 **메서드가 잠시 전달받은 값**이다. 이름을 다르게 바꾸면 구분이 더 잘 보인다.

```python
class Person:
    def __init__(self, input_name):
        # 전달받은 input_name을 인스턴스 속성 name에 저장한다.
        self.name = input_name
```

⚠️ 주의: 생성자 이름은 `_init_`이나 `init`이 아니라 양쪽에 밑줄이 두 개씩 있는 `__init__`이다. 철자가 틀리면 인스턴스 생성 시 원하는 초기화가 실행되지 않는다.

### 3.7 `self`: 현재 인스턴스를 가리키는 첫 번째 인자

인스턴스 메서드는 첫 번째 매개변수로 현재 인스턴스 자신을 받는다. 관례적으로 이 매개변수의 이름을 `self`라고 한다.

```python
class Counter:
    def __init__(self):
        # Counter 인스턴스마다 자기 count를 0에서 시작한다.
        self.count = 0

    def increment(self):
        # 메서드를 호출한 바로 그 인스턴스의 count만 증가시킨다.
        self.count += 1


c = Counter()
c.increment()
print(c.count)  # 1
```

`c.increment()`라는 호출은 내부적으로 `Counter.increment(c)`와 같은 방식으로 해석할 수 있다. 점 앞의 인스턴스 `c`가 첫 번째 인자인 `self`로 자동 전달되는 것이다.

이미 사용해 온 문자열 메서드도 같은 원리로 이해할 수 있다.

```python
# 일반적으로 사용하는 객체 지향식 호출
result1 = "hello".upper()

# 실제 동작 관계를 드러낸 호출: 문자열 인스턴스를 직접 전달한다.
result2 = str.upper("hello")

print(result1)  # HELLO
print(result2)  # HELLO
```

`self`는 Python 예약어가 아니라 매개변수 이름이므로 다른 이름도 문법상 사용할 수 있다. 하지만 Python 코드의 공통 관례이고 역할을 즉시 드러내므로 반드시 `self`를 사용하는 것이 좋다.

⚠️ 주의: 메서드를 정의할 때는 `self`를 적지만, `c.increment()`처럼 호출할 때는 직접 넘기지 않는다. 인스턴스가 자동으로 전달되기 때문이다.

### 3.8 클래스 변수와 인스턴스 변수

클래스 안의 변수는 저장되는 위치와 공유 범위에 따라 클래스 변수와 인스턴스 변수로 나뉜다.

- **클래스 변수**는 클래스 본문에 직접 정의하며 모든 인스턴스가 공유한다.
- **인스턴스 변수**는 보통 `self.변수명` 형태로 정의하며 각 인스턴스가 독립적으로 가진다.

```python
class Circle:
    # 모든 Circle 인스턴스가 공유하는 클래스 변수이다.
    pi = 3.14

    def __init__(self, radius):
        # 원마다 값이 달라지는 인스턴스 변수이다.
        self.radius = radius


c1 = Circle(1)
c2 = Circle(2)

print(c1.radius)  # 1
print(c2.radius)  # 2
print(c1.pi)      # 3.14
print(c2.pi)      # 3.14
```

반지름은 원마다 달라야 하므로 인스턴스 변수로 두고, 예제의 원주율은 모든 원이 함께 참조하므로 클래스 변수로 둔다.

클래스 변수를 명확히 참조하려면 `Circle.pi`처럼 클래스 이름을 사용하는 편이 좋다. 인스턴스를 통해 `c1.pi`로도 읽을 수 있지만, 같은 이름의 인스턴스 변수가 생기면 탐색 결과가 달라진다.

```python
class Circle:
    pi = 3.14

    def __init__(self, radius):
        self.radius = radius


c1 = Circle(5)
c2 = Circle(10)

print(c1.radius)  # 5
print(c2.radius)  # 10

# c1에만 pi라는 인스턴스 변수를 새로 만든다.
c1.pi = 100

# c1.pi는 같은 이름의 인스턴스 변수를 먼저 찾는다.
print(c1.pi)      # 100

# 클래스 변수 자체는 바뀌지 않았다.
print(Circle.pi)  # 3.14

# c2에는 pi 인스턴스 변수가 없으므로 클래스 변수까지 찾아간다.
print(c2.pi)      # 3.14
```

여기서 `c1.pi = 100`은 `Circle.pi`를 수정한 것이 아니다. `c1`의 이름 공간에 새로운 `pi`를 추가해 클래스 변수와 같은 이름을 가린 것이다.

⚠️ 주의: 모든 객체가 공유해야 하는 값을 바꿀 때 `instance.class_variable = value`처럼 쓰면 해당 인스턴스에 새 변수가 생길 수 있다. 공유값은 `ClassName.class_variable` 또는 적절한 클래스 메서드로 변경한다.

### 3.9 메서드의 세 종류

메서드는 클래스 내부에 정의된 함수로, 객체가 어떻게 동작할지를 표현한다. Python의 메서드는 무엇을 첫 번째 인자로 받고 어떤 상태를 다루는지에 따라 세 종류로 나뉜다.

| 종류 | 데코레이터 | 자동 전달 인자 | 주된 역할 |
|---|---|---|---|
| 인스턴스 메서드 | 없음 | `self` | 개별 인스턴스의 상태를 읽거나 변경 |
| 클래스 메서드 | `@classmethod` | `cls` | 클래스 변수 조작, 클래스 수준의 동작 |
| 스태틱 메서드 | `@staticmethod` | 없음 | 클래스에 관련은 있지만 상태와 무관한 독립 기능 |

선택 기준은 단순하다. **무엇의 상태를 읽고 바꾸는가**를 먼저 본다.

### 3.10 인스턴스 메서드: 개별 객체의 상태 다루기

인스턴스 메서드(Instance Method)는 인스턴스의 상태를 조작하거나 그 인스턴스의 동작을 수행한다. 클래스 내부에서 일반 함수처럼 정의하고 첫 번째 인자로 `self`를 받는다.

```python
class Counter:
    def __init__(self):
        self.count = 0

    # 특정 Counter 인스턴스의 상태를 변경한다.
    def increment(self):
        self.count += 1


first = Counter()
second = Counter()

first.increment()
first.increment()
second.increment()

# 각 인스턴스가 독립된 count를 보관한다.
print(first.count)   # 2
print(second.count)  # 1
```

생성자 `__init__`도 인스턴스 메서드이다. 새 인스턴스가 생성되는 특별한 시점에 자동 호출되어 인스턴스 변수의 초기값을 설정한다.

### 3.11 클래스 메서드: 클래스 전체의 상태 다루기

클래스 메서드(Class Method)는 클래스 변수를 조작하거나 클래스 수준의 동작을 수행한다. `@classmethod` 데코레이터를 붙이고, 첫 번째 인자로 호출한 클래스가 `cls`에 자동 전달된다.

```python
class Person:
    # 모든 Person 인스턴스가 공유하는 사람 수이다.
    population = 0

    def __init__(self, name):
        self.name = name

        # 새 인스턴스가 생길 때 클래스 수준의 수를 증가시킨다.
        Person.increase_population()

    @classmethod
    def increase_population(cls):
        # cls는 이 메서드를 호출한 클래스를 가리킨다.
        cls.population += 1


person1 = Person("Alice")
person2 = Person("Bella")

print(Person.population)  # 2
```

강의 코드에서는 생성자에서 `Person.increase_population()`을 호출한다. 클래스 메서드 내부에서는 구체적인 클래스 이름 대신 `cls.population`을 사용한다. 이렇게 하면 상속으로 다른 클래스가 이 메서드를 사용할 때 실제 호출한 클래스를 기준으로 동작할 수 있다.

`cls` 역시 문법적으로 다른 이름을 쓸 수 있지만, 역할을 명확히 나타내는 표준 관례이므로 그대로 사용한다.

### 3.12 스태틱 메서드: 상태와 무관한 도우미 기능

스태틱 메서드(Static Method)는 클래스와 논리적으로 관련은 있지만 인스턴스 상태나 클래스 상태에 의존하지 않는 기능을 표현한다. `@staticmethod`를 붙이며 `self`나 `cls`가 자동으로 전달되지 않는다.

```python
class MathUtils:
    @staticmethod
    def add(a, b):
        # 전달받은 값만 사용하며 클래스나 인스턴스 속성은 읽지 않는다.
        return a + b


print(MathUtils.add(3, 5))  # 8
```

스태틱 메서드는 일반 함수처럼 입력만으로 결과를 만든다. 다만 해당 기능이 특정 클래스의 개념과 밀접하게 관련되어 있어 클래스 안에 두는 편이 코드의 의미를 더 잘 드러낼 때 사용한다.

⚠️ 주의: 클래스 내부에 둘 수 있다는 이유만으로 모든 도우미 함수를 스태틱 메서드로 만들 필요는 없다. 클래스의 책임과 관련이 없다면 모듈 수준의 일반 함수가 더 자연스럽다.

### 3.13 세 종류의 메서드를 함께 사용한 은행 계좌

은행 계좌 예제는 클래스 변수, 인스턴스 변수, 세 종류의 메서드를 한 번에 보여준다.

계좌 소유자와 잔액은 계좌마다 다르므로 인스턴스 변수로 둔다. 기본 이자율은 모든 계좌가 공유하므로 클래스 변수로 둔다. 입금과 출금은 특정 계좌의 잔액을 변경하므로 인스턴스 메서드가 된다. 전체 이자율 변경은 클래스 메서드, 금액이 양수인지 검사하는 기능은 상태와 무관하므로 스태틱 메서드가 된다.

```python
class BankAccount:
    # 모든 계좌가 공유하는 기본 이자율이다.
    interest_rate = 0.02

    def __init__(self, owner, balance=0):
        # 계좌마다 소유자와 잔액을 따로 저장한다.
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        # 특정 계좌의 잔액을 변경하므로 인스턴스 메서드이다.
        self.balance += amount

    def withdraw(self, amount):
        # 출금 전에 현재 계좌의 잔액을 확인한다.
        if self.balance >= amount:
            self.balance -= amount
        else:
            print("잔액 부족!")

    @classmethod
    def set_interest_rate(cls, rate):
        # 클래스가 공유하는 이자율을 변경한다.
        cls.interest_rate = rate

    @staticmethod
    def is_positive(amount):
        # 객체 상태 없이 전달된 값만으로 판단한다.
        return amount > 0


# 계좌 개설: __init__이 호출되어 소유자와 초기 잔액이 설정된다.
alice_acc = BankAccount("Alice", 1000)

# 개별 계좌의 잔액을 바꾸므로 인스턴스를 통해 호출한다.
alice_acc.deposit(500)
alice_acc.withdraw(200)

# 1000 + 500 - 200의 결과이다.
print(alice_acc.balance)  # 1300

# 모든 계좌에 적용되는 이자율은 클래스를 통해 변경한다.
BankAccount.set_interest_rate(0.03)
print(BankAccount.interest_rate)  # 0.03

# 양수 판정은 특정 계좌 상태와 무관한 독립 기능이다.
print(BankAccount.is_positive(alice_acc.balance))  # True
```

이 예제의 메서드를 선택한 기준을 다시 정리하면 다음과 같다.

| 기능 | 다루는 대상 | 선택한 메서드 |
|---|---|---|
| `deposit`, `withdraw` | 한 계좌의 `balance` | 인스턴스 메서드 |
| `set_interest_rate` | 모든 계좌가 공유하는 `interest_rate` | 클래스 메서드 |
| `is_positive` | 전달받은 숫자만 검사 | 스태틱 메서드 |

⚠️ 주의: 강의의 `deposit`은 양수가 아닌 금액도 그대로 더할 수 있다. 실제 계좌 모델이라면 본문에서 이미 만든 `is_positive` 검사를 입출금 정책에 연결하고, 잘못된 금액에는 예외를 발생시키는 식의 보완이 필요하다.

📌 핵심: “어디서 호출할 수 있는가”보다 “무엇의 상태를 책임지는가”가 메서드 종류를 고르는 기준이다.

### 3.14 호출할 수 있음과 사용해야 함은 다르다

Python 문법상 클래스와 인스턴스는 여러 방식으로 메서드를 호출할 수 있다.

```python
class MyClass:
    def instance_method(self):
        return "instance method", self

    @classmethod
    def class_method(cls):
        return "class method", cls

    @staticmethod
    def static_method():
        return "static method"


instance = MyClass()

# 클래스에서 인스턴스 메서드를 직접 호출하려면 인스턴스를 명시해야 한다.
print(MyClass.instance_method(instance))

# 클래스 메서드에는 클래스가 자동 전달된다.
print(MyClass.class_method())

# 스태틱 메서드에는 자동 전달되는 인자가 없다.
print(MyClass.static_method())

# 인스턴스를 통해서도 세 메서드에 접근하는 것은 가능하다.
print(instance.instance_method())
print(instance.class_method())
print(instance.static_method())
```

그러나 **할 수 있다**와 **해도 된다**는 같지 않다. 의도를 분명히 드러내려면 다음 원칙을 따른다.

- 개별 객체의 상태를 다루는 인스턴스 메서드는 인스턴스로 호출한다.
- 클래스 전체의 상태를 다루는 클래스 메서드는 클래스로 호출한다.
- 클래스에 속한 독립 기능인 스태틱 메서드도 클래스로 호출한다.

이 원칙을 지키면 호출 코드만 보고도 메서드가 어느 수준의 책임을 다루는지 알 수 있다.

### 3.15 클래스와 인스턴스의 이름 공간

클래스를 정의하면 클래스의 이름 공간(namespace)이 생긴다. 인스턴스를 만들면 각 인스턴스에도 독립적인 이름 공간이 생긴다.

인스턴스에서 속성을 읽을 때 Python은 먼저 인스턴스의 이름 공간을 찾고, 그곳에 이름이 없으면 클래스의 이름 공간으로 올라가 찾는다.

```text
인스턴스에서 속성 접근
        │
        ▼
인스턴스 이름 공간에 있는가? ── 예 ──▶ 인스턴스 값 사용
        │ 아니요
        ▼
클래스 이름 공간에 있는가? ─── 예 ──▶ 클래스 값 사용
```

다음 예제에서 이 탐색 순서를 확인할 수 있다.

```python
class Person:
    # 인스턴스에 name이 없을 때 사용할 클래스 변수이다.
    name = "unknown"

    def talk(self):
        # self.name은 인스턴스부터 클래스 순서로 탐색된다.
        print(self.name)


# p1에는 아직 name 인스턴스 변수가 없다.
p1 = Person()
p1.talk()  # unknown: 클래스 변수 사용

# p2 역시 처음에는 클래스 변수를 사용한다.
p2 = Person()
p2.talk()  # unknown

# p2의 이름 공간에만 name을 추가한다.
p2.name = "Kim"
p2.talk()  # Kim: 인스턴스 변수가 우선

# 클래스 변수는 그대로 유지된다.
print(Person.name)  # unknown

# p2는 자신의 값을 사용한다.
print(p2.name)  # Kim

# p1에는 여전히 인스턴스 변수가 없으므로 클래스 값을 사용한다.
print(p1.name)  # unknown
```

같은 클래스에서 생성된 인스턴스라도 서로 다른 이름 공간을 갖기 때문에 `p2.name`을 바꿔도 `p1.name`에는 영향이 없다. 이 독립성은 객체를 모듈화하고 각 객체가 자신의 상태를 안전하게 관리하게 해 준다.

⚠️ 주의: 이 예제에서 `p2.name = "Kim"`은 클래스 변수 `Person.name`을 수정하지 않는다. 같은 이름의 인스턴스 변수를 `p2`에 새로 만든다.

이름 공간의 분리는 코드의 가독성, 유지보수성, 재사용성을 높인다. 객체들이 각자 상태를 관리하므로 한 인스턴스의 변경이 다른 인스턴스에 우연히 전파되는 일을 줄일 수 있다.

### 3.16 매직 메서드: 특별한 상황에 자동 호출되는 메서드

매직 메서드(Magic Method)는 이름 앞뒤에 이중 밑줄이 붙은 특별한 인스턴스 메서드이다. 스페셜 메서드 또는 던더(dunder) 메서드라고도 부르며, 특정 문법이나 내장 함수가 사용될 때 Python이 자동으로 호출한다.

대표적인 예는 다음과 같다.

| 메서드 | 연결되는 동작 |
|---|---|
| `__init__(self, ...)` | 인스턴스 초기화 |
| `__str__(self)` | `str(obj)`, `print(obj)`에 사용할 문자열 표현 |
| `__len__(self)` | `len(obj)` |
| `__eq__(self, other)` | `obj == other` |
| `__lt__(self, other)` | `obj < other` |
| `__gt__(self, other)` | `obj > other` |

강의에서는 `__str__`을 사용해 원 객체를 사용자 친화적인 문자열로 표현한다.

```python
class Circle:
    def __init__(self, radius):
        self.radius = radius

    def __str__(self):
        # print가 객체를 출력할 때 사용할 문자열을 반환한다.
        return f"원의 반지름: {self.radius}"


c1 = Circle(10)
c2 = Circle(1)

print(c1)  # 원의 반지름: 10
print(c2)  # 원의 반지름: 1
```

`print(c1)`을 호출하면 Python이 `c1.__str__()`을 찾아 그 반환값을 출력한다. 개발자가 직접 `__str__`을 호출하기보다 `print`, `str` 같은 일반 문법을 사용하면 Python이 알맞은 매직 메서드를 연결한다.

⚠️ 주의: `__str__`은 문자열을 **출력하는** 메서드가 아니라 문자열을 **반환하는** 메서드이다. 내부에서 `print()`만 호출하고 값을 반환하지 않으면 `str`이 기대하는 규약을 위반한다.

### 3.17 데코레이터: 원본 함수를 유지하며 기능 확장하기

데코레이터(Decorator)는 다른 함수의 코드를 직접 수정하지 않고, 함수 실행 전후에 새로운 기능을 덧붙이는 함수이다.

```python
def my_decorator(func):
    # 원본 함수를 감싸 대신 실행될 함수를 정의한다.
    def wrapper():
        # 원본 함수 실행 전의 공통 작업이다.
        print("함수 실행 전")

        # 전달받은 원본 함수를 실행하고 반환값을 보관한다.
        result = func()

        # 원본 함수 실행 후의 공통 작업이다.
        print("함수 실행 후")
        return result

    # 데코레이터는 새로 만든 wrapper 함수를 반환한다.
    return wrapper


@my_decorator
def my_function():
    print("원본 함수 실행")


my_function()
```

실행 결과는 다음과 같다.

```text
함수 실행 전
원본 함수 실행
함수 실행 후
```

`@my_decorator`는 아래 대입을 읽기 좋게 표현한 문법이다.

```python
# 데코레이터 문법의 개념적인 의미
my_function = my_decorator(my_function)
```

따라서 이후 `my_function()`을 호출하면 원본 함수 대신 `wrapper()`가 실행되고, `wrapper` 안에서 원본 함수가 호출된다.

이번 강의에서 먼저 사용한 `@classmethod`와 `@staticmethod`도 데코레이터 문법이다. 이들은 메서드가 클래스 또는 독립 기능의 방식으로 동작하도록 의미를 부여한다.

⚠️ 주의: 강의의 가장 단순한 `wrapper()`는 인자가 없는 함수만 감쌀 수 있다. 인자를 받는 여러 함수에 재사용하려면 이후 `*args`, `**kwargs`와 함수 메타데이터를 보존하는 `functools.wraps`를 함께 학습해야 한다.

## 4. 적용 관점에서 다시 보기

객체 지향 문제를 만나면 클래스 문법부터 쓰기보다, 먼저 문제의 명사와 동사를 구분한다. 지속해서 보관해야 하는 명사형 정보는 속성 후보이고, 그 정보를 읽거나 바꾸는 동작은 메서드 후보이다.

예를 들어 “은행 계좌가 소유자와 잔액을 가지며 입금하고 출금한다”는 요구사항에서는 계좌가 객체 후보, 소유자와 잔액이 인스턴스 변수 후보, 입금과 출금이 인스턴스 메서드 후보가 된다. “모든 계좌가 같은 이자율을 공유한다”는 문장은 클래스 변수를 떠올리게 한다.

구현 순서는 다음과 같이 잡으면 안정적이다.

1. **객체의 책임을 정한다.** 무엇을 하나의 단위로 묶을지 결정한다.
2. **클래스를 정의한다.** 이름은 PascalCase로 작성한다.
3. **인스턴스마다 달라지는 값을 찾는다.** `__init__`에서 `self.속성`으로 초기화한다.
4. **모두가 공유하는 값을 찾는다.** 클래스 본문에 클래스 변수로 둔다.
5. **동작이 어느 상태를 다루는지 확인한다.** 개별 상태면 인스턴스, 공유 상태면 클래스, 상태와 무관하면 스태틱 메서드를 선택한다.
6. **인스턴스를 두 개 이상 만들어 본다.** 값이 독립적으로 유지되는지 확인해야 클래스 변수와 인스턴스 변수의 혼동을 발견하기 쉽다.
7. **출력과 경계 조건을 검증한다.** 잔액 부족, 잘못된 금액, 의미 있는 객체 출력 같은 상황을 점검한다.

문제에서 다음 신호가 보이면 해당 개념을 떠올릴 수 있다.

| 요구사항의 신호 | 떠올릴 개념 |
|---|---|
| “각 사용자마다”, “각 계좌마다” | 인스턴스 변수 |
| “모든 객체가 공유”, “전체 설정” | 클래스 변수와 클래스 메서드 |
| “전달값만 검사”, “독립 계산” | 스태틱 메서드 또는 일반 함수 |
| “생성할 때 초기값 설정” | `__init__` |
| “객체를 출력했을 때 의미 있는 문장” | `__str__` |
| “여러 함수 실행 전후에 같은 처리” | 데코레이터 |

디버깅할 때는 속성이 저장된 위치를 먼저 확인한다. `obj.value`가 예상과 다르면 `obj.__dict__`에 인스턴스 변수가 있는지, 클래스에 같은 이름의 변수가 있는지 생각해 본다. 인스턴스에서 속성을 찾을 때 인스턴스에서 클래스로 탐색한다는 규칙이 문제를 푸는 기준이 된다.

메서드 호출 오류가 발생하면 정의와 호출을 함께 본다. 인스턴스 메서드의 첫 번째 `self`를 빠뜨렸는지, 클래스 메서드에 `@classmethod`와 `cls`가 모두 있는지, 스태틱 메서드가 객체 상태를 억지로 참조하고 있지는 않은지 확인한다.

무엇보다 클래스는 관련된 값을 한곳에 넣기 위한 단순한 상자가 아니다. 객체가 어떤 상태를 책임지고 어떤 동작을 제공할지 경계를 정하는 도구다. 속성과 메서드를 한 클래스에 넣을 때는 “이 기능이 정말 이 객체의 책임인가?”를 계속 확인해야 한다.

## 5. 배운 점 / 확장 포인트

### 5.1 이번 강의 이전에 몰랐던 것 또는 새로 이해된 것

Python에서 평소 사용하던 문자열과 리스트도 각각 `str`, `list` 클래스의 인스턴스이며, `"hello".upper()` 같은 표현은 객체 자신이 인스턴스 메서드를 호출하는 구조라는 점을 이해할 수 있다. 또한 클래스 변수와 같은 이름을 인스턴스에 대입하면 공유값을 수정하는 것이 아니라 인스턴스 이름 공간에 새 값을 만든다는 점이 중요하다.

### 5.2 앞으로 이어지는 연결점

클래스와 인스턴스의 구분은 이후 상속, 메서드 오버라이딩, 다형성을 이해하는 기반이 된다. 독립된 이름 공간과 객체의 책임이라는 관점은 캡슐화, 모듈화, 테스트 가능한 설계로도 이어진다.

### 5.3 더 파볼 만한 주제

매직 메서드의 심화 활용, `@property`, 클래스 메서드를 이용한 대안 생성자, `dataclass`, 클래스 속성 탐색 순서인 MRO를 더 살펴볼 수 있다. 데코레이터에서는 `*args`, `**kwargs`, 클로저, `functools.wraps`를 학습하면 실전적인 함수를 만들 수 있다.

## 6. 요약 정리

📌 핵심

- 절차 지향은 함수 호출과 실행 순서를 중심으로 데이터를 처리한다.
- 객체 지향은 관련 데이터와 기능을 객체 하나에 묶고 객체의 책임과 상호작용을 중심으로 구성한다.
- 클래스는 객체를 만드는 설계도이자 Python의 새로운 타입이고, 인스턴스는 클래스로 생성한 구체적인 객체이다.
- 속성은 객체의 상태를, 메서드는 객체의 동작을 나타낸다.
- `__init__`은 인스턴스 생성 시 초기 상태를 설정하고, `self`는 현재 메서드를 호출한 인스턴스를 가리킨다.
- 클래스 변수는 모든 인스턴스가 공유하고, 인스턴스 변수는 각 인스턴스가 독립적으로 가진다.
- 인스턴스에서 속성을 읽을 때는 인스턴스 이름 공간을 먼저 찾고, 없으면 클래스 이름 공간을 찾는다.
- 인스턴스 메서드는 개별 객체의 상태, 클래스 메서드는 클래스의 공유 상태, 스태틱 메서드는 상태와 무관한 기능을 담당한다.
- 매직 메서드는 특정 문법이나 내장 함수에 의해 자동 호출되며, `__str__`은 객체의 문자열 표현을 반환한다.
- 데코레이터는 원본 함수 코드를 직접 바꾸지 않고 실행 전후의 기능을 확장한다.

🧠 기억할 것

메서드의 종류가 헷갈릴 때는 데코레이터 문법부터 외우지 말고 **무엇의 상태를 읽고 바꾸는가**를 묻는다. 개별 객체라면 `self`, 클래스 전체라면 `cls`, 어느 쪽에도 의존하지 않는다면 스태틱 메서드나 일반 함수를 검토한다.

## 7. 미니 퀴즈 또는 체크리스트

1. 절차 지향과 객체 지향이 문제를 바라보는 질문은 각각 어떻게 다른가?
2. “Alice는 인스턴스다”보다 “Alice는 `Person` 클래스의 인스턴스다”가 더 정확한 이유는 무엇인가?

6. 클래스나 인스턴스를 통해 모든 종류의 메서드를 호출할 수 있더라도 권장 호출 방식이 따로 있는 이유는 무엇인가?
