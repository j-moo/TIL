## 1. 들어가며

친구의 전화번호를 이름으로 찾는 상황을 생각해 보자. 전화번호만 리스트에 차례대로 넣으면 특정 번호가 누구의 것인지 알기 어렵고, 이름과 번호를 두 리스트에 따로 저장하면 두 자료의 인덱스를 계속 맞춰야 한다. 이때 필요한 것은 순서가 아니라 **이름과 전화번호의 관계**이다.

```python
# 이름을 키로, 전화번호를 값으로 연결한다.
phone_book = {
    "민수": "010-1234-5678",
}

# 인덱스를 찾을 필요 없이 이름으로 전화번호를 바로 조회한다.
number = phone_book["민수"]
print(number)  # 010-1234-5678

# 새 친구도 같은 키-값 구조로 추가한다.
phone_book["지수"] = "010-9876-5432"
```

딕셔너리는 이처럼 데이터에 의미 있는 이름을 붙여 조회하게 한다. 코드에서 `phone_numbers[0]`보다 `phone_book["민수"]`가 훨씬 직관적인 이유다. 자료 구조를 알맞게 선택하면 검색 방식뿐 아니라 코드의 가독성과 유지보수성까지 달라진다.

한편 학생 명단에서 중복된 이름을 제거하거나 두 반에 공통으로 속한 학생을 찾으려면 값 사이의 **포함 관계**가 중요하다. 이때는 세트가 알맞다. 딕셔너리와 세트는 겉으로 하는 일이 다르지만, 내부에서는 모두 해시 테이블을 활용한다.

이번 강의는 다음 질문을 차례대로 해결한다.

- 딕셔너리의 값을 안전하게 조회하고 수정하려면 어떤 메서드를 써야 할까?
- 세트로 중복을 제거하고 합집합·교집합·차집합을 구하려면 어떻게 해야 할까?
- 딕셔너리와 세트가 빠른 이유는 무엇이며, 왜 리스트를 키나 요소로 쓸 수 없을까?
- 공식 문서의 `D.pop(key[, default])`에서 대괄호는 무엇을 뜻할까?

## 2. 핵심 개념 정리

이번 강의의 중심에는 **데이터를 어떤 기준으로 찾을 것인가**라는 질문이 있다. 순서가 중요하면 리스트 같은 시퀀스를 사용하지만, 이름과 값의 연결이 중요하면 딕셔너리, 중복 없는 구성과 집합 관계가 중요하면 세트를 선택한다.

본문은 먼저 딕셔너리의 키-값 구조와 조회·수정·삭제 메서드를 살펴본다. 이어서 세트의 요소 관리와 집합 연산을 익힌다. 반복문 안에서 값을 누적할 때 초기화 코드를 줄이는 `defaultdict`도 딕셔너리의 확장으로 연결한다.

그다음 두 자료 구조의 공통 기반인 해시 테이블로 내려간다. 키나 요소가 해시 함수를 거쳐 버킷에 배치되는 흐름을 이해하면, 세트에 순서가 없는 이유, 문자열의 배치가 실행마다 달라질 수 있는 이유, 가변 객체를 키로 쓸 수 없는 이유가 한 흐름으로 설명된다.

마지막에는 BNF와 EBNF를 다룬다. 이는 새로운 자료 구조가 아니라, 앞에서 본 메서드의 공식 문법을 정확히 읽기 위한 도구다. 즉, 자료 구조를 사용하는 단계에서 끝나지 않고 공식 문서로 사용법을 검증하는 단계까지 나아간다.

## 3. 본문 정리

이 섹션에서는 강의의 순서를 따라 딕셔너리, 세트, `defaultdict`, 해시 테이블, Python 문법 표기법을 연결한다. 각 메서드는 반환값과 원본 변경 여부, 키나 요소가 없을 때의 동작까지 함께 봐야 안전하게 사용할 수 있다.

### 3.1 딕셔너리: 키와 값을 연결하는 자료 구조

딕셔너리(`dictionary`, `dict`)는 **고유한 키와 그 키에 대응하는 값을 한 쌍으로 저장하는 자료 구조**이다. 리스트가 정수 인덱스로 값을 찾는다면 딕셔너리는 개발자가 정한 키로 값을 찾는다.

```python
# 문자열 키와 여러 자료형의 값을 연결한다.
person = {
    "name": "Alice",
    "age": 25,
    "is_student": False,
}

# 키를 사용해 대응하는 값을 조회한다.
print(person["name"])  # Alice

# 같은 키에 새 값을 대입하면 기존 값이 바뀐다.
person["age"] = 26

# 존재하지 않았던 키에 값을 대입하면 새 항목이 추가된다.
person["country"] = "KOREA"
```

키는 딕셔너리 안에서 하나만 존재한다. 같은 키를 다시 사용하면 항목이 하나 더 생기는 것이 아니라 기존 값이 덮어써진다. 반면 값은 중복될 수 있고 리스트나 다른 딕셔너리처럼 다양한 자료형도 저장할 수 있다.

딕셔너리는 내부적으로 해시 테이블을 사용한다. 키를 해시 함수로 계산해 값이 저장된 위치를 찾기 때문에, 일반적인 상황에서 데이터의 크기와 크게 관계없이 삽입·삭제·검색을 빠르게 수행한다.

⚠️ 주의: 딕셔너리 리터럴에서 같은 키를 두 번 작성해도 오류가 나지 않는다. 뒤에 작성한 값이 앞의 값을 덮어쓰므로, 키 중복은 데이터 손실처럼 보이는 버그를 만들 수 있다.

📌 핵심: 딕셔너리는 값의 순번보다 **그 값이 무엇을 의미하는지 나타내는 키**가 중요할 때 선택한다.

### 3.2 `get()`: 키가 없어도 안전하게 조회하기

대괄호 조회 `D[key]`는 키가 반드시 있다고 확신할 때 간결하다. 하지만 외부 입력이나 선택적인 데이터처럼 키가 없을 수 있다면 `KeyError`가 발생한다. `get()`은 이 상황을 처리하기 위한 조회 메서드이다.

| 문법 | 키가 있을 때 | 키가 없을 때 |
|---|---|---|
| `D.get(key)` | 연결된 값 반환 | `None` 반환 |
| `D.get(key, default)` | 연결된 값 반환 | `default` 반환 |
| `D[key]` | 연결된 값 반환 | `KeyError` 발생 |

```python
person = {"name": "Alice", "age": 25}

# 존재하는 키이므로 연결된 값을 반환한다.
print(person.get("name"))  # Alice

# 키가 없고 기본값을 생략했으므로 None을 반환한다.
print(person.get("country"))  # None

# 키가 없으면 두 번째 인자로 전달한 기본값을 반환한다.
print(person.get("country", "Unknown"))  # Unknown

# 대괄호 조회는 키가 없으면 예외를 발생시킨다.
# print(person["country"])  # KeyError: 'country'
```

`get()`이 돌려주는 기본값은 조회 결과일 뿐 딕셔너리에 새 키를 추가하지 않는다. 이 차이는 뒤에서 다룰 `setdefault()`와 `defaultdict`를 구분하는 기준이 된다.

⚠️ 주의: 실제 값으로 `None`을 저장할 수 있는 딕셔너리에서는 `get()` 결과가 `None`이라는 사실만으로 키가 없는지 판단할 수 없다. 키 존재 자체가 중요하면 `key in dictionary`를 사용한다.

### 3.3 `keys()`, `values()`, `items()`: 딕셔너리 순회하기

딕셔너리를 반복할 때는 무엇을 꺼낼 것인지 먼저 정해야 한다. 키만 필요하면 `keys()`, 값만 필요하면 `values()`, 키와 값을 함께 사용하면 `items()`가 알맞다.

```python
person = {"name": "Alice", "age": 25}

# 모든 키를 모은 dict_keys 뷰 객체를 반환한다.
print(person.keys())  # dict_keys(['name', 'age'])

for key in person.keys():
    print(key)
# name
# age

# 모든 값을 모은 dict_values 뷰 객체를 반환한다.
print(person.values())  # dict_values(['Alice', 25])

for value in person.values():
    print(value)
# Alice
# 25

# 각 키-값 쌍을 튜플처럼 꺼낼 수 있는 dict_items 뷰 객체를 반환한다.
print(person.items())
# dict_items([('name', 'Alice'), ('age', 25)])

for key, value in person.items():
    # 한 항목에서 키와 값을 동시에 구조 분해한다.
    print(key, value)
# name Alice
# age 25
```

세 메서드가 반환하는 것은 고정된 리스트 복사본이 아니라 딕셔너리의 현재 상태를 보여주는 **뷰 객체**이다. 따라서 딕셔너리가 바뀌면 기존에 얻어 둔 뷰에도 변경이 반영된다.

```python
person = {"name": "Alice"}
keys_view = person.keys()

person["age"] = 25

# keys_view를 다시 만들지 않아도 새 키가 보인다.
print(keys_view)  # dict_keys(['name', 'age'])
```

💡 포인트: `for key in person:`처럼 딕셔너리 자체를 반복해도 기본적으로 키를 순회한다. 다만 키와 값이 모두 필요할 때는 `items()`가 의도를 가장 분명하게 드러낸다.

### 3.4 `pop()`과 `clear()`: 딕셔너리 항목 삭제하기

`pop()`은 키를 삭제하는 동시에 그 키에 연결되어 있던 값을 반환한다. 삭제한 값을 다음 로직에 사용해야 할 때 유용하다.

```python
person = {"name": "Alice", "age": 25}

# 'age' 항목을 삭제하고 기존 값 25를 반환한다.
removed_age = person.pop("age")
print(removed_age)  # 25
print(person)       # {'name': 'Alice'}

# 키가 없더라도 기본값을 전달하면 예외 대신 그 값을 반환한다.
removed_country = person.pop("country", None)
print(removed_country)  # None

# 기본값 없이 없는 키를 삭제하면 KeyError가 발생한다.
# person.pop("country")  # KeyError: 'country'
```

`clear()`는 개별 항목이 아니라 딕셔너리의 모든 키-값 쌍을 제거한다. 기존 객체 자체는 유지되고 내용만 빈 상태가 된다.

```python
person = {"name": "Alice", "age": 25}

# 같은 딕셔너리 객체의 모든 항목을 제거한다.
person.clear()
print(person)  # {}
```

⚠️ 주의: `pop()`은 조회 메서드가 아니라 원본을 변경하는 메서드다. 값을 확인만 하려는 상황에서 사용하면 다음 코드에서 키가 사라져 예상하지 못한 오류가 생길 수 있다.

### 3.5 `setdefault()`: 조회와 기본값 삽입을 한 번에 처리하기

`setdefault(key, default)`는 키가 있으면 기존 값을 반환한다. 키가 없으면 `default`를 값으로 하는 새 항목을 추가한 뒤 그 값을 반환한다.

```python
person = {"name": "Alice", "age": 25}

# 'country' 키가 없으므로 새 항목을 만든 뒤 'KOREA'를 반환한다.
country = person.setdefault("country", "KOREA")

print(country)  # KOREA
print(person)
# {'name': 'Alice', 'age': 25, 'country': 'KOREA'}

# 이미 키가 있으면 기존 값을 유지하며 반환한다.
same_country = person.setdefault("country", "USA")
print(same_country)        # KOREA
print(person["country"])  # KOREA
```

리스트에 값을 그룹핑할 때도 사용할 수 있다. 키가 없으면 빈 리스트를 넣고, 반환된 리스트에 바로 `append()`하는 방식이다.

```python
groups = {}

for color, fruit in [("red", "apple"), ("yellow", "banana"), ("red", "cherry")]:
    # color가 처음 나오면 빈 리스트를 만든다.
    groups.setdefault(color, []).append(fruit)

print(groups)
# {'red': ['apple', 'cherry'], 'yellow': ['banana']}
```

⚠️ 주의: `get()`은 기본값을 반환만 하지만 `setdefault()`는 키가 없을 때 원본 딕셔너리에 항목을 추가한다. 단순 조회와 초기화가 필요한 조회를 구분해야 한다.

### 3.6 `update()`: 여러 키-값 쌍으로 딕셔너리 갱신하기

`update()`는 다른 데이터가 제공하는 키-값 쌍을 현재 딕셔너리에 반영한다. 기존 키는 새 값으로 덮어쓰고, 없던 키는 새로 추가한다.

```python
person = {"name": "Alice", "age": 25}
other_person = {"name": "Jane", "country": "KOREA"}

# 다른 딕셔너리의 항목을 한꺼번에 반영한다.
person.update(other_person)
print(person)
# {'name': 'Jane', 'age': 25, 'country': 'KOREA'}

# 키워드 인자 형태로도 여러 항목을 갱신할 수 있다.
person.update(age=100, address="SEOUL")
print(person)
# {'name': 'Jane', 'age': 100, 'country': 'KOREA', 'address': 'SEOUL'}
```

여기서 문법의 `other`는 반드시 이름이 `other`인 변수만 받는다는 뜻이 아니다. 딕셔너리나 키-값 쌍처럼 갱신할 데이터를 제공하는 객체를 가리키는 자리 표시자다.

| 메서드 | 핵심 동작 | 원본 변경 |
|---|---|---|
| `get()` | 키를 안전하게 조회 | 하지 않음 |
| `keys()` | 키 뷰 반환 | 하지 않음 |
| `values()` | 값 뷰 반환 | 하지 않음 |
| `items()` | 키-값 쌍 뷰 반환 | 하지 않음 |
| `pop()` | 항목 삭제 후 값 반환 | 변경함 |
| `clear()` | 모든 항목 삭제 | 변경함 |
| `setdefault()` | 기존 값 조회 또는 기본 항목 삽입 | 키가 없으면 변경함 |
| `update()` | 여러 항목 추가·덮어쓰기 | 변경함 |

Python 딕셔너리의 전체 메서드는 공식 문서의 [Mapping Types — dict](https://docs.python.org/3/library/stdtypes.html#dict)에서 확인할 수 있다. 공식 문서의 문법 표기법은 3.22절에서 다시 읽어 본다.

### 3.7 세트: 고유한 요소를 저장하는 자료 구조

세트(`set`)는 **중복을 허용하지 않는, 순서가 없는 컬렉션**이다. 같은 값을 여러 번 넣어도 하나만 남기 때문에 중복 제거에 적합하고, 어떤 값이 포함되어 있는지 빠르게 검사할 수 있다.

```python
# 중복된 2를 여러 번 작성해도 하나만 저장된다.
numbers = {1, 2, 2, 3}
print(numbers)  # 출력 순서는 보장되지 않지만 요소는 {1, 2, 3}

# 존재 여부를 빠르게 확인한다.
print(2 in numbers)  # True
print(5 in numbers)  # False

# 빈 중괄호는 빈 딕셔너리이므로 빈 세트는 set()으로 만든다.
empty_set = set()
print(type(empty_set))  # <class 'set'>
```

세트도 내부적으로 해시 테이블을 사용한다. 이 덕분에 요소 추가, 삭제, `in`을 이용한 존재 여부 확인을 평균적으로 매우 빠르게 수행한다. 또한 수학의 집합처럼 합집합, 교집합, 차집합을 바로 계산할 수 있다.

⚠️ 주의: `{}`는 빈 세트가 아니라 빈 딕셔너리다. 빈 세트를 만들 때는 반드시 `set()`을 사용한다.

### 3.8 `add()`, `update()`, `clear()`: 세트 요소 추가와 전체 삭제

`add(x)`는 요소 하나를 추가한다. 이미 같은 요소가 있으면 오류 없이 아무 변화도 일어나지 않는다.

```python
my_set = {1, 2, 3}

# 요소 하나를 추가한다.
my_set.add(4)
print(my_set)  # 요소는 {1, 2, 3, 4}, 출력 순서는 달라질 수 있음

# 이미 있는 요소를 다시 넣어도 중복되지 않는다.
my_set.add(4)
print(len(my_set))  # 4
```

`update(iterable)`는 다른 반복 가능한 객체의 요소를 하나씩 꺼내 모두 추가한다. 리스트 자체를 요소 하나로 넣는 것이 아니라 리스트 안의 값들을 펼쳐 넣는다.

```python
my_set = {"a", "b", "c", 1, 2, 3}

# 리스트의 각 요소 1, 4, 5를 세트에 추가한다.
my_set.update([1, 4, 5])
print(my_set)
# {'a', 'b', 'c', 1, 2, 3, 4, 5}와 같은 구성, 출력 순서는 보장되지 않음

# 모든 요소를 제거하면 빈 세트가 된다.
my_set.clear()
print(my_set)  # set()
```

`dict.update()`와 `set.update()`는 이름은 같지만 받아들이는 데이터가 다르다. 딕셔너리는 키-값 쌍을 갱신하고, 세트는 반복 가능한 객체의 각 요소를 추가한다.

⚠️ 주의: `my_set.add([4, 5])`처럼 리스트 자체를 세트의 한 요소로 추가할 수는 없다. 리스트는 해시 불가능하기 때문이다. 여러 값을 추가하려면 `update([4, 5])`를 사용한다.

### 3.9 `remove()`, `discard()`, `pop()`: 세트 요소 삭제하기

세트에는 삭제 목적에 따라 세 메서드가 있다. 삭제할 값을 정확히 지정할 때는 `remove()` 또는 `discard()`를 사용하고, 임의의 요소 하나를 꺼낼 때는 `pop()`을 사용한다.

| 메서드 | 동작 | 요소가 없을 때 |
|---|---|---|
| `remove(x)` | `x`를 삭제 | `KeyError` 발생 |
| `discard(x)` | `x`를 삭제 | 아무 일도 하지 않음 |
| `pop()` | 임의의 요소를 삭제하고 반환 | 빈 세트면 `KeyError` 발생 |

```python
my_set = {1, 2, 3, "a", "b", "c"}

# 존재하는 2를 삭제한다.
my_set.remove(2)

# 없는 값을 remove()로 삭제하면 KeyError가 발생한다.
# my_set.remove(10)  # KeyError: 10

# discard()는 값이 없어도 예외를 발생시키지 않는다.
my_set.discard(3)
my_set.discard(10)

# pop()은 어떤 요소가 선택될지 약속하지 않은 채 하나를 삭제해 반환한다.
element = my_set.pop()
print(element)
print(my_set)
```

`pop()`의 설명에서 **임의의 요소**는 매번 완전한 난수로 고른다는 뜻이 아니다. 세트 내부의 해시 테이블 배치에 따라 선택되며, 개발자가 어떤 요소가 나올지 의존해서는 안 된다는 뜻이다.

⚠️ 주의: 리스트의 `pop()`처럼 세트의 `pop()`에 인덱스를 전달할 수 없다. 세트에는 인덱스와 순서가 없으므로 `my_set.pop(0)`은 올바른 사용법이 아니다.

### 3.10 세트의 집합 연산

세트의 가장 큰 장점 중 하나는 두 데이터 집합 사이의 관계를 코드로 직접 표현할 수 있다는 점이다.

| 의미 | 메서드 | 연산자 | 결과 |
|---|---|---|---|
| 차집합 | `set1.difference(set2)` | `set1 - set2` | `set1`에만 있는 요소 |
| 교집합 | `set1.intersection(set2)` | `set1 & set2` | 두 세트에 모두 있는 요소 |
| 합집합 | `set1.union(set2)` | `set1 \| set2` | 하나 이상에 있는 모든 요소 |
| 부분집합 검사 | `set1.issubset(set2)` | `set1 <= set2` | `set1`의 모든 요소가 `set2`에 있는지 |
| 상위집합 검사 | `set1.issuperset(set2)` | `set1 >= set2` | `set1`이 `set2`의 모든 요소를 포함하는지 |

```python
set1 = {0, 1, 2, 3, 4}
set2 = {1, 3, 5, 7, 9}
set3 = {0, 1}

# set1에는 있지만 set2에는 없는 요소를 구한다.
print(set1.difference(set2))  # {0, 2, 4}
print(set1 - set2)            # {0, 2, 4}

# 두 세트에 공통으로 들어 있는 요소를 구한다.
print(set1.intersection(set2))  # {1, 3}
print(set1 & set2)              # {1, 3}

# 모든 요소가 다른 세트에 포함되는지 검사한다.
print(set1.issubset(set2))  # False
print(set3.issubset(set1))  # True

# 다른 세트의 모든 요소를 포함하는지 검사한다.
print(set1.issuperset(set2))  # False

# 어느 한쪽 또는 양쪽에 있는 요소를 모두 합친다.
print(set1.union(set2))
# {0, 1, 2, 3, 4, 5, 7, 9}
```

집합 연산 결과도 세트이므로 출력 순서를 비교 기준으로 삼으면 안 된다. `{1, 3}`과 `{3, 1}`은 표현 순서가 달라 보여도 같은 세트다.

📌 핵심: “공통”, “한쪽에만”, “모두 포함”, “중복 제거”라는 표현이 보이면 세트와 집합 연산을 먼저 떠올린다.

### 3.11 `defaultdict`: 없는 키의 기본값을 자동으로 만들기

`defaultdict`는 Python 표준 라이브러리 `collections` 모듈이 제공하는 딕셔너리의 확장이다. 존재하지 않는 키를 대괄호로 조회할 때 미리 지정한 함수로 기본값을 만들고, 그 키를 딕셔너리에 추가한다.

일반 딕셔너리로 문자의 등장 횟수를 세려면 키가 이미 있는지 확인해야 한다.

```python
text = "banana"
counts = {}

for char in text:
    # 문자가 처음 나오면 누적을 시작할 0을 먼저 넣는다.
    if char not in counts:
        counts[char] = 0

    # 이미 준비된 값을 1 증가시킨다.
    counts[char] += 1

print(counts)  # {'b': 1, 'a': 3, 'n': 2}
```

`defaultdict(int)`를 사용하면 없는 키를 처음 조회할 때 `int()`가 만든 `0`이 자동으로 저장된다. 따라서 반복문은 실제 집계 로직에 집중할 수 있다.

```python
from collections import defaultdict

text = "banana"

# int()의 결과인 0을 없는 키의 기본값으로 사용한다.
counts = defaultdict(int)

for char in text:
    # char 키가 없으면 먼저 0을 만든 뒤 1을 더한다.
    counts[char] += 1

print(counts)
# defaultdict(<class 'int'>, {'b': 1, 'a': 3, 'n': 2})

# 일반 딕셔너리가 필요하면 dict()로 변환할 수 있다.
print(dict(counts))  # {'b': 1, 'a': 3, 'n': 2}
```

### 3.12 `defaultdict` 활용: 숫자 세기와 그룹핑

`defaultdict`를 만들 때 전달하는 것은 기본값 자체가 아니라 **기본값을 만드는 함수**이다. `int`는 `0`, `list`는 빈 리스트 `[]`를 만든다.

| 선언 | 없는 키에 생성되는 값 | 대표 용도 |
|---|---|---|
| `defaultdict(int)` | `0` | 빈도수·개수 누적 |
| `defaultdict(list)` | `[]` | 분류·그룹핑·그래프 인접 리스트 |

```python
from collections import defaultdict

fruits = [
    ("red", "apple"),
    ("yellow", "banana"),
    ("red", "cherry"),
]

# 색이 처음 나올 때마다 빈 리스트를 자동 생성한다.
fruits_by_color = defaultdict(list)

for color, fruit in fruits:
    # color 키가 없더라도 빈 리스트가 생기므로 바로 append할 수 있다.
    fruits_by_color[color].append(fruit)

print(fruits_by_color)
# defaultdict(<class 'list'>,
#             {'red': ['apple', 'cherry'], 'yellow': ['banana']})
```

일반 `dict`는 데이터 조회가 주목적이고 키의 존재 여부가 로직에서 중요할 때 적합하다. `defaultdict`는 반복문에서 데이터를 계속 집계하거나 그룹으로 모으고, 초기화 코드를 줄이고 싶을 때 강력하다.

`setdefault()`도 비슷한 그룹핑을 할 수 있지만 차이가 있다. `setdefault()`는 필요한 지점마다 기본값을 전달한다. `defaultdict`는 객체를 만들 때 기본값 생성 규칙을 한 번 정하고 이후의 모든 없는 키에 적용한다.

⚠️ 주의: `defaultdict`는 **조회만 해도 키를 생성할 수 있다.** `counts["missing"]`을 읽으면 `0`이 반환되는 동시에 `"missing"` 키가 추가된다. 단순히 키가 있는지 확인하려면 `"missing" in counts`를 사용해야 한다.

### 3.13 해시 테이블: 키를 저장 위치로 바꾸는 구조

해시 테이블은 키와 값을 짝지어 저장하고, 키로 값의 위치를 빠르게 찾는 자료 구조이다. 도서관에서 책 제목을 색인으로 찾아 몇 번째 책장에 있는지 알아낸 뒤 곧바로 그 책장으로 가는 과정에 비유할 수 있다.

전체 책장을 처음부터 훑는다면 책이 많아질수록 시간이 늘어난다. 색인을 사용하면 제목으로 위치를 계산하고 해당 위치를 바로 확인할 수 있다. 해시 테이블에서는 색인의 역할을 해시 함수가 하고, 실제 데이터를 담는 칸을 버킷(`bucket`)이라고 부른다.

동작 흐름은 다음과 같다.

1. 키를 해시 함수에 넣어 정수 형태의 해시 값을 만든다.
2. 해시 값을 바탕으로 데이터를 저장할 버킷 인덱스를 결정한다.
3. 삽입할 때는 해당 버킷에 데이터를 저장한다.
4. 조회·삭제할 때도 같은 계산을 반복해 해당 버킷으로 이동한다.

```text
키 ──> 해시 함수 ──> 해시 값 ──> 버킷 인덱스 ──> 저장된 값
```

같은 규칙으로 저장 위치와 검색 위치를 계산하므로 전체 데이터를 순서대로 확인할 필요가 없다. 충돌 처리 등 내부 세부 동작이 있지만, 이번 강의에서는 딕셔너리와 세트가 평균적으로 빠르게 동작하는 기반이라는 점을 잡는 것이 우선이다.

### 3.14 해시와 해시 함수

해시(`hash`)는 임의 크기의 데이터를 일정한 방식으로 정수 값에 대응시키는 과정 또는 그 결과를 가리킨다. 생성된 해시 값은 데이터를 구분하고 저장 위치를 계산하는 데 사용하는 지문과 비슷하다.

해시 함수(`hash function`)는 입력 데이터를 받아 해시 값을 만드는 함수다. Python에서는 내장 `hash()`로 객체의 해시 값을 확인할 수 있다.

```python
# 정수는 같은 프로세스에서 반복 계산해도 같은 해시 값을 갖는다.
print(hash(1))  # 일반적인 CPython에서는 1
print(hash(1))  # 같은 실행 안에서는 같은 결과

# 문자열도 같은 실행 안에서는 같은 해시 값을 유지한다.
first = hash("a")
second = hash("a")
print(first == second)  # True
```

해시 값 자체를 애플리케이션의 영구 식별자로 저장해서는 안 된다. 특히 문자열의 해시는 Python 프로세스를 새로 실행하면 달라질 수 있다. 중요한 성질은 **한 객체가 해시 테이블에 머무는 동안 해시 값이 바뀌지 않아야 한다**는 점이다.

⚠️ 주의: 해시 값이 다르면 객체도 다르지만, 해시 값이 같다고 객체가 반드시 같은 것은 아니다. 서로 다른 입력이 같은 해시 값이나 같은 버킷에 대응하는 해시 충돌이 생길 수 있으며, 해시 테이블은 이를 처리하는 별도 절차를 가진다.

### 3.15 세트 요소와 딕셔너리 키가 배치되는 방식

세트는 각 요소를 해시 함수에 넣어 얻은 값을 바탕으로 내부 버킷에 배치한다. 요소가 입력된 순번보다 버킷 위치가 내부 배치를 결정하므로 세트는 순서를 보장하지 않는다.

딕셔너리의 키도 같은 방식으로 해시 테이블에 저장된다. 다만 Python 3.7 이상에서는 딕셔너리를 반복할 때 **삽입 순서가 언어 사양으로 보장**된다. 내부 검색 구조는 해시 테이블이지만, 사용자에게 보이는 키 순회 순서는 추가한 순서를 유지한다.

```python
person = {}
person["name"] = "Alice"
person["age"] = 25
person["country"] = "KOREA"

# 키는 삽입한 순서대로 순회한다.
print(list(person.keys()))  # ['name', 'age', 'country']
```

| 자료 구조 | 내부 기반 | 외부에서 보장되는 순서 |
|---|---|---|
| `set` | 해시 테이블 | 순서 없음 |
| `dict` | 해시 테이블 | Python 3.7 이상에서 삽입 순서 보장 |

⚠️ 주의: 딕셔너리가 삽입 순서를 유지한다고 해서 정렬된 것은 아니다. 키의 크기나 알파벳순이 필요하면 `sorted()` 같은 정렬 절차가 별도로 필요하다.

### 3.16 세트 `pop()`과 정수 요소

정수는 해시 값이 안정적이고 단순하게 계산되는 경우가 많다. 그래서 같은 Python 환경에서 정수로만 구성한 세트를 여러 번 실행하면 `pop()` 결과가 일정한 패턴처럼 보일 수 있다.

```python
numbers = {3, 2, 1, 9, 100, 4, 87, 39, 10, 52}

while numbers:
    # 내부 버킷 순서에 따라 임의의 요소 하나를 꺼낸다.
    print(numbers.pop())
```

하지만 이 결과를 정렬 순서나 삽입 순서로 해석하면 안 된다. 정수 해시와 현재 테이블 크기에서 만들어진 내부 배치가 우연히 규칙적으로 보일 뿐이다. Python은 어떤 정수가 먼저 나온다는 계약을 제공하지 않는다.

### 3.17 문자열 해시 난수화와 난수 시드

문자열 해시에는 보안을 위한 해시 난수화(`hash randomization`)가 적용된다. Python 프로세스가 시작될 때 해시 계산에 사용하는 난수 시드가 정해지며, 새 프로세스에서는 다른 시드가 사용될 수 있다.

따라서 같은 문자열도 서로 다른 Python 실행 사이에서는 해시 값이 달라질 수 있다. 해시 함수의 원리가 매번 무작위로 바뀌는 것이 아니라, 계산에 함께 쓰는 시드가 실행마다 달라지는 것이다.

```python
# 같은 프로세스 안에서는 두 결과가 같다.
print(hash("a"))
print(hash("a"))

# 프로그램을 종료하고 다시 실행하면 위 숫자는 달라질 수 있다.
```

문자열 세트의 버킷 배치도 해시 값의 영향을 받는다. 그 결과 문자열 세트의 출력 순서나 `pop()`으로 제거되는 순서가 프로세스를 다시 실행했을 때 달라질 수 있다.

```python
letters = {"a", "b", "c", "d"}

while letters:
    # 실행마다 다른 순서로 보일 수 있지만, 어떤 순서도 계약된 결과가 아니다.
    print(letters.pop())
```

⚠️ 주의: `set.pop()`의 “임의의 요소”를 “균등한 확률로 무작위 선택한 요소”라고 이해하면 안 된다. 무작위 선택이 필요하다면 세트의 `pop()`이 아닌 목적에 맞는 난수 도구를 사용해야 한다.

### 3.18 `hashable`: 해시 값을 안정적으로 유지할 수 있는 객체

`hashable`은 `hash()` 함수에 넣어 해시 값을 구할 수 있고, 객체가 살아 있는 동안 그 값이 바뀌지 않는 성질을 가진 객체를 뜻한다. 딕셔너리의 키와 세트의 요소는 반드시 해시 가능해야 한다.

대부분의 내장 불변 자료형은 해시 가능하다.

```python
# 대표적인 해시 가능 객체
print(hash(1))          # int
print(hash(1.0))        # float
print(hash("Python"))   # str
print(hash((1, 2, 3)))  # 불변 요소만 담은 tuple
```

튜플은 자체가 불변이지만, 내부 요소까지 모두 해시 가능해야 한다. 리스트를 포함한 튜플은 해시할 수 없다.

```python
# 튜플 안의 리스트가 해시 불가능하므로 전체 튜플도 해시할 수 없다.
# hash((1, 2, [3, 4]))  # TypeError: unhashable type: 'list'
```

해시 가능 여부는 단순히 `hash()` 호출에 성공하는지만의 문제가 아니다. 같은 객체라면 동등성 비교와 해시 값의 관계도 일관되어야 해시 테이블에서 저장한 위치를 다시 찾을 수 있다.

📌 핵심: `dict`의 키와 `set`의 요소는 저장된 뒤에도 위치를 다시 계산할 수 있도록 **안정적인 해시 값**을 가져야 한다.

### 3.19 가변 객체가 해시 불가능한 이유

리스트, 딕셔너리, 세트 같은 가변 객체는 내용을 바꿀 수 있다. 만약 이런 객체를 딕셔너리 키로 허용하고 저장한 뒤 내용을 변경한다면, 변경 전 해시 값으로 정한 버킷과 변경 후 조회할 버킷이 달라질 수 있다.

```text
저장할 때:   객체 A ──> 해시 값 10 ──> 10번 버킷에 저장
변경한 뒤:  객체 A ──> 해시 값 27 ──> 27번 버킷에서 검색
```

이 경우 값은 10번 버킷에 남아 있는데 검색은 27번 버킷에서 수행되어, 데이터가 있어도 찾지 못하는 문제가 생긴다. Python은 해시 테이블의 무결성을 지키기 위해 대표적인 가변 내장 객체의 해시 계산을 허용하지 않는다.

```python
# 리스트는 해시할 수 없다.
# print(hash([1, 2, 3]))
# TypeError: unhashable type: 'list'

# 리스트를 세트 요소로 사용할 수 없다.
# my_set = {[1, 2, 3]}
# TypeError: unhashable type: 'list'

# 세트를 딕셔너리 키로 사용할 수 없다.
# my_dict = {{3, 2}: "a"}
# TypeError: unhashable type: 'set'
```

“해시 가능하면 무조건 불변이고, 불변이면 무조건 해시 가능하다”를 모든 사용자 정의 객체까지 포함한 절대 법칙으로 외우는 것은 정확하지 않다. 다만 Python의 대표적인 내장 자료형을 다루는 현재 단계에서는 **불변 자료형은 대체로 해시 가능하고, 가변 컨테이너는 해시 불가능하다**고 이해하면 좋다.

⚠️ 주의: 중복 없는 집합을 다시 세트의 요소로 넣어야 한다면 가변 `set` 대신 불변 집합인 `frozenset`을 고려할 수 있다. 이는 확장 주제이며, 기본 원리는 “저장 뒤 해시 값이 바뀌지 않아야 한다”는 데 있다.

### 3.20 해시 가능한 객체가 필요한 이유

해시 가능성은 해시 테이블의 빠른 검색과 데이터 일관성을 함께 지키는 조건이다.

1. **해시 테이블 기반 자료 구조 사용**  
   딕셔너리 키와 세트 요소의 저장 위치를 해시 값으로 계산할 수 있다.

2. **중복 방지와 빠른 검색**  
   같은 값을 다시 만났는지 빠르게 확인해 딕셔너리 키의 고유성과 세트 요소의 고유성을 유지한다.

3. **불변성을 통한 일관된 위치 유지**  
   저장할 때와 찾을 때 같은 해시 값이 나와야 같은 버킷을 확인할 수 있다.

4. **안정성과 예측 가능성**  
   객체의 동등성 판단과 해시 계산이 일관되어야 해시 테이블의 삽입·조회·삭제 로직이 안정적으로 동작한다.

해시 테이블 부분을 한 문장으로 정리하면 다음과 같다.

> 딕셔너리와 세트는 해시 값으로 버킷을 찾아 빠르게 동작하며, 그 위치를 안정적으로 다시 찾기 위해 해시 가능한 키와 요소만 허용한다.

### 3.21 BNF와 EBNF: 프로그래밍 언어의 문법을 표현하는 규칙

Python 공식 문서는 자연어 설명만으로 문법을 나열하지 않는다. 프로그래밍 언어의 구문을 모호하지 않게 표현하기 위해 BNF 계열의 표기법을 사용한다.

BNF는 **Backus-Naur Form**의 약자로, 프로그래밍 언어의 문법을 표현하는 표기법이다. EBNF는 **Extended Backus-Naur Form**의 약자로 BNF에 메타 기호를 더해 선택과 반복 같은 구조를 더 간결하게 표현한다.

이런 표기법을 사용하는 이유는 Python뿐 아니라 서로 다른 프로그래밍 언어, 데이터 형식, 프로토콜의 문법을 일정한 규칙으로 정의하기 위해서다. 자연어로 “있어도 되고 없어도 된다”를 매번 길게 설명하는 대신 약속된 기호 하나로 나타낼 수 있다.

### 3.22 EBNF 메타 기호로 공식 문서 읽기

강의에서 다룬 대표적인 메타 기호는 다음과 같다.

| 메타 기호 | 의미 | 읽는 방법 |
|---|---|---|
| `[ ... ]` | 선택적 요소 | 생략하거나 한 번 사용할 수 있음 |
| `*` | 0번 이상 반복 | 없어도 되고 여러 번 나올 수 있음 |
| `( ... )` | 그룹화 | 안쪽 요소를 하나의 문법 단위로 묶음 |

공식 문서의 딕셔너리 메서드 표기를 예로 보자.

```text
get(key[, default])
pop(key[, default])
```

여기서 `key`는 대괄호 밖에 있으므로 필수 인자다. `default`는 대괄호 안에 있으므로 선택 인자다. 표기의 `[, default]`에서 쉼표까지 대괄호 안에 들어간 이유는 `default`를 전달할 때에만 그 앞의 쉼표도 함께 필요하기 때문이다.

이를 실제 호출로 바꾸면 다음 세 줄처럼 읽을 수 있다.

```python
person = {"name": "Alice"}

# key는 필수이므로 반드시 전달한다.
print(person.get("name"))  # Alice

# default는 선택이므로 필요할 때만 두 번째 인자로 전달한다.
print(person.get("country", "Unknown"))  # Unknown

# 인자를 하나도 전달하는 호출은 문법에 맞지 않는다.
# person.get()  # TypeError
```

⚠️ 주의: 공식 문서의 문법 설명에서 대괄호는 “실제 코드에 대괄호를 입력하라”는 뜻이 아니다. `person.get("name"[, "Unknown"])`처럼 작성하면 잘못된 코드다. 표기법의 기호와 Python 코드의 실제 문자를 구분해야 한다.

📌 핵심: EBNF의 `[ ]`를 이해하면 어떤 인자가 필수이고 어떤 인자를 생략할 수 있는지 메서드 시그니처만 보고 판단할 수 있다.

## 4. 적용 관점에서 다시 보기

이번 강의의 자료 구조는 문제의 문장에 나타나는 신호와 연결하면 선택하기 쉽다.

먼저 “이름으로 정보 찾기”, “학번별 점수”, “상품 코드별 재고”처럼 **어떤 식별자와 값을 연결**해야 한다면 딕셔너리를 떠올린다. 키가 반드시 있다는 보장이 없으면 대괄호 조회보다 `get()`을 고려하고, 없는 키에 값을 계속 누적해야 한다면 `setdefault()`나 `defaultdict`가 자연스럽다.

“중복 제거”, “공통 원소”, “한쪽에만 존재”, “포함 관계”, “빠른 존재 여부 검사”가 보이면 세트가 후보가 된다. 원본의 순서를 유지해야 하는 문제라면 세트로 바꾸는 순간 순서 정보가 사라질 수 있으므로, 중복 제거와 순서 보존 중 무엇이 요구되는지 먼저 확인한다.

빈도수 계산의 구현 순서는 단순하다.

1. 키가 무엇인지 정한다. 문자 빈도라면 각 문자가 키다.
2. 값에 무엇을 누적할지 정한다. 등장 횟수라면 정수다.
3. 일반 딕셔너리, `get()`, `setdefault()`, `defaultdict(int)` 가운데 키 부재를 처리할 방식을 고른다.
4. 반복문에서 하나씩 값을 갱신한다.
5. 결과를 출력할 때 삽입 순서가 필요한지, 정렬이 필요한지 별도로 판단한다.

그룹핑도 같은 흐름을 사용한다. 분류 기준을 키로, 같은 그룹에 모을 데이터를 리스트 값으로 둔다. `defaultdict(list)`를 사용하면 키 존재 확인과 빈 리스트 초기화를 생략하고 핵심인 `append()`에 집중할 수 있다.

세트 연산을 적용할 때는 기준이 되는 왼쪽 세트를 명확히 해야 한다. 특히 차집합 `A - B`는 방향이 있으며, “A에는 있지만 B에는 없는 값”을 뜻한다. 교집합과 합집합은 좌우를 바꿔도 결과가 같지만 차집합은 그렇지 않다.

오류 메시지도 자료 구조의 제약을 알려주는 단서다. `TypeError: unhashable type: 'list'`가 나오면 리스트가 딕셔너리 키나 세트 요소처럼 해시 가능한 값이 필요한 위치에 들어갔는지 확인한다. 키로 사용할 내용이 바뀌지 않는 값들의 묶음이라면 튜플 같은 불변 구조로 표현할 수 있는지 검토한다.

마지막으로 메서드 사용법이 기억나지 않을 때는 추측하지 말고 공식 문서의 시그니처를 읽는다. `[default]`는 선택 인자라는 식으로 EBNF 표기를 해석하고, 반환값과 키가 없을 때의 동작까지 확인해야 안전한 코드를 작성할 수 있다.

## 5. 배운 점 / 확장 포인트

### 1. 이번 강의 이전에 몰랐던 것 또는 새로 이해된 것

딕셔너리와 세트가 단지 편리한 문법이 아니라 해시 테이블을 기반으로 하며, 빠른 조회와 `hashable` 제약이 같은 원리에서 나온다는 점을 연결할 수 있다. 또한 `set.pop()`의 임의성은 무작위 추첨이 아니라 순서를 약속하지 않는다는 의미이고, `get()`, `setdefault()`, `defaultdict`는 모두 없는 키를 다루지만 원본에 키를 생성하는지에서 차이가 난다.

### 2. 앞으로 이어지는 연결점

딕셔너리의 빈도수 계산은 문자열·배열 문제의 카운팅으로, `defaultdict(list)` 그룹핑은 그래프의 인접 리스트와 분류 문제로 이어진다. 세트의 빠른 존재 검사는 중복 탐지와 탐색 최적화에 반복해서 사용되며, 해시 가능성은 복합 데이터를 키로 설계할 때 중요한 기준이 된다.

### 3. 더 파볼 만한 주제

해시 충돌을 실제 해시 테이블이 처리하는 방식, 평균 시간 복잡도와 최악 시간 복잡도의 차이, 불변 집합 `frozenset`, 삽입 순서를 유지하는 딕셔너리의 내부 구현을 더 살펴볼 수 있다. 공식 문서를 더 정확히 읽기 위해 Python 언어 레퍼런스의 전체 문법 표기 규칙도 확장 학습할 만하다.

## 6. 요약 정리

📌 핵심

- 딕셔너리는 고유한 키와 값을 연결하며, 의미 있는 키로 데이터를 빠르게 찾을 때 사용한다.
- `get()`은 키가 없을 때 예외 대신 기본값을 반환하고 원본은 바꾸지 않는다.
- `keys()`, `values()`, `items()`는 각각 키, 값, 키-값 쌍을 순회할 때 사용한다.
- `pop()`은 항목을 삭제하고 값을 반환하며, `clear()`는 모든 항목을 제거한다.
- `setdefault()`는 없는 키에 기본값을 삽입하고, `update()`는 여러 키-값 쌍을 갱신한다.
- 세트는 중복 없는 요소를 저장하고, 빠른 존재 여부 확인과 집합 연산에 적합하다.
- `remove()`는 없는 요소에서 오류를 내지만 `discard()`는 조용히 넘어간다.
- `set.pop()`은 임의의 요소를 반환하며 그 순서에 의존해서는 안 된다.
- `defaultdict(int)`는 개수 누적, `defaultdict(list)`는 그룹핑에 유용하다.
- 딕셔너리와 세트는 해시 값을 이용해 버킷을 찾기 때문에 평균적으로 빠르게 동작한다.
- 세트는 순서를 보장하지 않지만, 딕셔너리는 Python 3.7 이상에서 삽입 순서를 보장한다.
- 문자열 해시는 프로세스마다 다른 난수 시드의 영향을 받을 수 있다.
- 딕셔너리 키와 세트 요소에는 안정적인 해시 값을 가진 `hashable` 객체만 사용할 수 있다.
- 리스트·딕셔너리·세트 같은 가변 내장 객체는 일반적으로 해시할 수 없다.
- EBNF의 `[ ]`는 선택 요소를 나타내므로 `pop(key[, default])`의 `default`는 생략할 수 있다.

🧠 기억할 것

자료 구조를 선택할 때 문법부터 떠올리기보다 필요한 관계를 먼저 본다. **키와 값의 연결은 딕셔너리, 고유성과 집합 관계는 세트, 반복적인 기본값 초기화는 `defaultdict`**로 연결하면 된다. 그리고 이 자료 구조의 빠른 검색과 사용 제약은 모두 해시 값으로 저장 위치를 정한다는 원리에서 출발한다.
