# 1767. 프로세서 연결하기 - 내 코드 분석 / 코드 리뷰용 🔍

- 🎯 목표: SWEA 1767 풀이 코드의 흐름을 이해하고, 왜 이 백트래킹 구조가 맞는지 분석한다.
- 🧩 키워드: DFS, 백트래킹, 가지치기, 상태복구, 재귀
- ⭐ 난이도: 상
- 🛠 핵심 알고리즘: **내부 코어 대상 DFS + 전선 설치/제거 백트래킹**

---

## 1. 문제 이해 📌

이 문제는 내부 코어들을 가장자리 전원에 연결하는 문제다.  
단, 아무렇게나 연결하는 것이 아니라 다음 우선순위를 지켜야 한다.

1. **연결한 코어 수가 최대여야 한다.**
2. 그 상태에서 **전선 길이 합이 최소여야 한다.**

즉 단순 최단경로 문제가 아니라,  
**최대화와 최소화가 함께 있는 탐색 문제**다.

---

## 2. 문제를 내 말로 재정의 🧠

내부 코어를 하나씩 보면서,
- 이 코어를 어느 방향으로 연결할지
- 아니면 아예 연결하지 않을지

를 결정하는 문제라고 볼 수 있다.

핵심은 다음이다.

- 전선은 직선으로만 가능
- 전선끼리 겹치면 안 됨
- 코어 위를 지나가면 안 됨
- 어떤 코어는 일부러 포기해야 전체 최적해가 될 수 있음

---

## 3. 관련 개념 정리 📚

### DFS
코어를 순서대로 하나씩 처리하는 재귀 탐색 구조다.

### 백트래킹
전선을 깔아보고, 다음 단계 탐색 후 다시 지운다.

### 가지치기
남은 코어를 전부 연결해도 최적해를 못 넘으면 탐색 중단.

### 상태복구
전선을 설치했다면 재귀 후 반드시 제거해야 한다.

---

## 4. 내 풀이 아이디어 분석 💡

이 풀이의 핵심 아이디어는 꽤 정석적이다.

- 가장자리 코어는 제외
- 내부 코어만 리스트에 저장
- 각 코어마다 4방향을 시도
- 가능하면 전선 설치 후 재귀
- 끝나면 전선 제거
- 연결하지 않는 경우도 시도

이 구조는 SWEA 1767에서 매우 안정적인 정답 패턴이다.

### ✅ 이 접근의 장점
- 문제 조건을 자연스럽게 반영할 수 있다.
- “코어 수 최대 → 길이 최소” 우선순위를 정확히 처리할 수 있다.
- 전선 설치/제거 구조가 명확해서 디버깅이 쉽다.

### ⚠️ 주의할 점
- 연결 안 하는 경우를 빠뜨리면 오답
- 가지치기가 없으면 탐색량이 커질 수 있음
- 상태복구를 잘못하면 보드가 꼬인다

---

## 5. 최종 풀이 전략 🚀

### 상태 정의
`dfs(idx, connected, length)`

- `idx`: 현재 처리할 코어 번호
- `connected`: 지금까지 연결한 코어 수
- `length`: 현재까지 사용한 전선 길이 합

### 흐름
1. 가지치기 검사
2. 모든 코어 처리 완료 여부 확인
3. 현재 코어의 4방향 연결 시도
4. 가능하면 전선 설치 후 재귀
5. 재귀 후 전선 제거
6. 연결하지 않는 경우도 탐색

---

## 6. 검증 ✅

### 시간복잡도
최악은 각 코어당 5가지 선택으로 볼 수 있어 `O(5^K)` 수준이다.  
하지만 실제로는 연결 불가능 방향과 가지치기 때문에 줄어든다.

### 공간복잡도
재귀 깊이 `O(K)`

### 제한 조건에서 가능한 이유
- 코어 수 최대 12개
- 전형적인 백트래킹 범위 안
- 가지치기 적용 가능

### 반례 / 예외 상황
- 연결 가능한 방향이 하나도 없는 코어
- 연결 가능하지만 포기해야 더 좋은 해가 나오는 경우
- 길이 최소보다 연결 수 최대가 우선인 상황

---

## 7. 구현 포인트 🛠

### 변수 설명
- `cores`: 내부 코어 목록
- `max_connected`: 현재까지 최대 연결 코어 수
- `min_length`: 그때의 최소 전선 길이
- `dr`, `dc`: 방향 벡터

### 함수 설명
- `can_connect`: 끝까지 갈 수 있는지 확인
- `set_line`: 전선 설치/제거
- `dfs`: 전체 탐색 담당

### 🚨 디버깅 포인트
- `set_line(..., 2)` 한 뒤 반드시 `set_line(..., 0)` 해야 함
- `idx == len(cores)`에서 정답 갱신 조건 확인
- 가지치기 부등호 방향 실수 주의

---

## 8. 코드 💻

```python
import sys
sys.stdin = open('input.txt', 'r')

T = int(input())

# 상, 하, 좌, 우 방향을 나타내는 델타 배열
dr = [-1, 1, 0, 0]
dc = [0, 0, -1, 1]

for tc in range(1, T + 1):
    # 보드 크기 입력
    N = int(input())

    # 보드 정보 입력
    board = [list(map(int, input().split())) for _ in range(N)]

    # 가장자리가 아닌 코어만 저장할 리스트
    cores = []

    # 내부 코어만 백트래킹 대상으로 수집
    for r in range(1, N - 1):
        for c in range(1, N - 1):
            if board[r][c] == 1:
                cores.append((r, c))

    # 현재까지 찾은 최대 연결 코어 수
    max_connected = -1

    # 최대 연결 코어 수를 만들 때의 최소 전선 길이
    min_length = float('inf')

    # 해당 방향으로 끝까지 전선을 놓을 수 있는지 확인하는 함수
    def can_connect(r, c, d):
        # 현재 코어에서 한 칸 이동한 위치부터 검사 시작
        nr = r + dr[d]
        nc = c + dc[d]

        # 보드 범위 안에 있는 동안 계속 전진
        while 0 <= nr < N and 0 <= nc < N:
            # 빈 칸이 아니면 코어나 전선이 이미 있다는 뜻이므로 연결 불가
            if board[nr][nc] != 0:
                return False

            # 같은 방향으로 한 칸 더 이동
            nr += dr[d]
            nc += dc[d]

        # 끝까지 막히지 않았으면 연결 가능
        return True

    # 전선을 설치하거나 제거하는 함수
    # val이 2면 전선 설치, 0이면 전선 제거
    def set_line(r, c, d, val):
        # 현재 코어에서 한 칸 이동한 위치부터 시작
        nr = r + dr[d]
        nc = c + dc[d]

        # 설치하거나 제거한 전선 길이를 저장할 변수
        length = 0

        # 보드 밖으로 나갈 때까지 직선으로 이동
        while 0 <= nr < N and 0 <= nc < N:
            # 현재 칸을 val 값으로 바꾼다
            board[nr][nc] = val

            # 전선 길이 1 증가
            length += 1

            # 같은 방향으로 계속 전진
            nr += dr[d]
            nc += dc[d]

        # 설치하거나 제거한 총 길이 반환
        return length

    # idx번째 코어부터 처리하는 DFS
    # connected: 지금까지 연결한 코어 수
    # length: 지금까지 사용한 전선 길이 합
    def dfs(idx, connected, length):
        nonlocal max_connected, min_length

        # 가지치기:
        # 남은 코어를 모두 연결해도 현재 최댓값보다 작으면 더 볼 필요가 없다
        if connected + (len(cores) - idx) < max_connected:
            return

        # 모든 코어를 다 확인했다면 정답 후보 갱신
        if idx == len(cores):
            # 더 많은 코어를 연결했다면 정답 갱신
            if connected > max_connected:
                max_connected = connected
                min_length = length
            # 연결한 코어 수가 같다면 전선 길이가 더 짧은 쪽 선택
            elif connected == max_connected:
                min_length = min(min_length, length)
            return

        # 현재 처리할 코어 위치
        r, c = cores[idx]

        # 4방향으로 전선 연결 시도
        for d in range(4):
            # 해당 방향으로 연결 가능하면
            if can_connect(r, c, d):
                # 전선을 설치하고 설치 길이를 저장
                line_len = set_line(r, c, d, 2)

                # 다음 코어로 넘어가며 연결 수와 길이를 갱신
                dfs(idx + 1, connected + 1, length + line_len)

                # 백트래킹: 설치했던 전선을 다시 제거
                set_line(r, c, d, 0)

        # 현재 코어를 연결하지 않고 넘어가는 경우도 반드시 고려
        dfs(idx + 1, connected, length)

    # 0번째 코어부터 탐색 시작
    dfs(0, 0, 0)

    # 정답 출력
    print(f'#{tc} {min_length}')
```

## 9. 코드 해설 📝

### 1) 내부 코어만 수집
이 문제에서 가장자리 코어는 이미 연결된 상태이므로 탐색 대상이 아니다.  
그래서 `cores`에는 내부 코어만 들어간다.

### 2) `can_connect`
전선을 놓기 전에 먼저 길이 비어 있는지 확인한다.  
이 단계가 없으면 전선을 놓다가 중간에 충돌하는 문제가 생길 수 있다.

### 3) `set_line`
설치와 제거를 같은 함수로 처리한 점이 깔끔하다.  
`val=2`면 설치, `val=0`이면 제거다.

### 4) `dfs`
현재 코어 기준으로 가능한 모든 방향을 탐색하고,  
각 방향마다 상태복구까지 정확히 수행한다.

### 5) 포기 선택
마지막의
```python
dfs(idx + 1, connected, length)
```
이 한 줄이 중요하다.  
이 줄이 있어야 “현재 코어를 연결하지 않는 선택”까지 탐색된다.

## 10. 코드 리뷰

### ✅ 잘한 점
- 내부 코어만 따로 분리해서 탐색량을 줄였다.
- `can_connect`, `set_line`, `dfs` 역할이 잘 분리되어 있다.
- 정답 갱신 우선순위를 정확히 반영했다.
- 가지치기를 넣어서 불필요한 탐색을 줄였다.

### ⚠️ 아쉬운 점
- `2`가 전선 표시라는 점이 처음 보면 직관적이지 않을 수 있다.
- 상수(`EMPTY`, `CORE`, `WIRE`)로 빼두면 더 읽기 쉬울 수 있다.

### 💡 개선 아이디어
```python
EMPTY = 0
CORE = 1
WIRE = 2
```
이렇게 상수화하면 가독성이 좋아진다.

또한 코어 순서를 조정해서  
연결 가능성이 낮은 코어부터 먼저 처리하는 방식도 생각해볼 수 있지만,  
구현 복잡도 대비 필수는 아니다.

### 🚨 디버깅 포인트
- 전선을 설치만 하고 제거하지 않으면 다음 탐색이 전부 틀어진다.
- 가장자리 코어까지 넣으면 정답이 꼬일 수 있다.
- `connected`와 `length` 갱신 타이밍을 헷갈리면 오답 가능성이 높다.
