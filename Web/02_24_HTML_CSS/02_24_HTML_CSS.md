## 1. 들어가며

이름과 연락처만 적힌 텍스트를 실제 명함처럼 보이게 만들려면 두 종류의 정보가 필요하다. 먼저 어느 문장이 이름이고 어느 문장이 설명인지 구조를 정해야 한다. 그다음 글자색, 테두리, 여백, 크기 같은 시각적 규칙을 더해야 한다. 웹에서는 전자를 HTML이, 후자를 CSS가 담당한다.

HTML과 CSS를 처음 배울 때는 태그와 속성을 외우는 데 집중하기 쉽다. 그러나 실제로 자주 막히는 지점은 따로 있다. 태그가 화면에서 어떻게 보이는지만 보고 의미를 놓치거나, CSS 규칙을 작성했는데 다른 규칙에 밀려 적용되지 않거나, `width: 100px`로 지정한 상자가 실제로는 124px이 되는 경우다. 이런 현상은 모두 문서 구조, cascade, 상속, Box Model이라는 규칙으로 설명할 수 있다.

따라서 이번 강의는 **웹과 HTML의 역할 → HTML 문서와 텍스트 구조 → CSS 적용과 선택 → 스타일 충돌 해결 → 값과 단위 → 상속 → 박스의 크기 계산** 순서로 이해하는 것이 좋다. 문법을 각각 외우기보다 브라우저가 문서를 읽고 최종 화면을 만드는 흐름을 따라가면, 결과가 예상과 다를 때도 원인을 추적할 수 있다.

## 2. 핵심 개념 정리

이번 강의가 해결하려는 질문은 다음과 같다.

> 브라우저가 이해할 수 있는 문서 구조를 만들고, 원하는 요소에 원하는 스타일을 충돌 없이 적용하려면 어떤 규칙을 알아야 할까?

본문은 이 질문을 다섯 단계로 풀어간다.

1. **웹과 HTML의 역할을 구분한다.** 인터넷 위의 정보 공간인 Web, 여러 페이지의 묶음인 Web site, 그 구성 단위인 Web page를 구분하고 HTML·CSS·JavaScript의 책임을 나눈다.
2. **HTML로 의미 있는 문서를 만든다.** 문서 골격, 요소와 속성, 제목·문단·목록·강조·링크·이미지를 구조와 의미에 맞게 작성한다.
3. **CSS가 대상을 선택하는 방법을 익힌다.** 세 가지 적용 방법과 기본 선택자, 속성 선택자, 자손·자식 결합자를 통해 스타일의 적용 범위를 조절한다.
4. **여러 선언이 만났을 때 최종값을 계산한다.** cascade, 명시도, 소스 순서, `!important`, 상속을 함께 보며 “왜 이 색이 적용되었는가”를 설명한다.
5. **크기와 공간을 계산한다.** 절대·상대 단위의 기준을 비교하고 content, padding, border, margin 및 `box-sizing`이 실제 박스 크기를 어떻게 결정하는지 확인한다.

이 흐름의 끝에서 중요한 능력은 코드를 보고 결과를 외우는 것이 아니라, 브라우저가 어떤 규칙으로 결과를 선택하고 계산했는지 단계적으로 설명하는 것이다.

## 3. 본문 정리

### 3.1 Web, Web site, Web page

**World Wide Web(Web)**은 인터넷으로 연결된 컴퓨터들이 정보를 공유하는 거대한 정보 공간이다. 인터넷이 통신을 가능하게 하는 기반이라면, Web은 그 기반 위에서 문서와 서비스를 연결하고 이용하는 대표적인 체계라고 볼 수 있다.

- **Web site**는 사용자에게 정보나 서비스를 제공하는 여러 Web page의 묶음이다.
- **Web page**는 HTML, CSS 등의 웹 기술로 만든 한 페이지이며 Web site를 구성하는 단위다.
- **Web application**은 정보 열람을 넘어 입력, 검색, 저장 같은 상호작용을 제공하는 웹 기반 프로그램이다.

하나의 Web page를 집에 비유하면 역할이 선명해진다.

| 웹 기술 | 역할 | 집에 비유하면 |
|---|---|---|
| HTML | 의미와 구조 | 철골과 방의 용도 |
| CSS | 디자인과 배치 | 페인트, 크기, 간격 |
| JavaScript | 동작과 상호작용 | 스위치로 켜는 조명 |

HTML 없이 CSS만으로는 무엇이 제목이고 문단인지 안정적으로 표현할 수 없다. 반대로 HTML만 있어도 정보는 전달되지만, 시각적 구분과 배치가 제한적이다. 세 기술은 서로 대신하는 것이 아니라 각자의 책임을 나누어 가진다.

### 3.2 HTML: HyperText를 Markup하는 언어

HTML은 **HyperText Markup Language**의 약자로, 웹 페이지의 의미와 구조를 정의하는 언어다.

**HyperText**는 링크를 통해 다른 문서로 즉시 이동할 수 있는 비선형 텍스트다. 책처럼 정해진 순서만 따라가는 것이 아니라 사용자가 링크를 선택하며 경로를 만든다. 이 특성은 상호연결성과 사용자 주도 탐색을 가능하게 한다.

**Markup Language**는 태그 같은 표식을 사용해 데이터의 구조와 의미를 명시하는 언어다. 예를 들어 다음 원문은 사람에게는 제목과 설명처럼 보일 수 있지만 컴퓨터에는 단순 문자열일 뿐이다.

```text
HTML
HTML은 HyperText Markup Language의 약자이다.
```

HTML로 마크업하면 제목과 문단이라는 의미가 명시된다.

```html
<h1>HTML</h1>
<p>HTML은 HyperText Markup Language의 약자이다.</p>
```

브라우저는 태그를 해석해 화면을 그리며, 검색 엔진과 보조 기술도 이 구조를 이용한다. 마크업의 핵심은 단순히 글자를 크게 만드는 것이 아니라 **내용이 맡은 역할을 기계도 이해할 수 있게 표현하는 것**이다.

### 3.3 HTML 문서의 기본 구조

HTML 문서는 다음 골격에서 시작한다.

```html
<!DOCTYPE html>
<html lang="ko">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>나의 첫 페이지</title>
  </head>
  <body>
    <p>화면에 표시될 내용입니다.</p>
  </body>
</html>
```

- `<!DOCTYPE html>`은 브라우저에 이 문서를 현대 HTML 문서로 해석하라고 알리는 선언이다. HTML 요소가 아니라 문서 형식 선언이다.
- `<html>`은 전체 페이지를 감싸는 최상위 요소다. `lang="ko"`는 문서의 주 언어를 알려 스크린 리더와 검색 엔진의 해석을 돕는다.
- `<head>`에는 문자 인코딩, 탭 제목, CSS 연결처럼 문서를 설명하고 설정하는 메타데이터를 둔다. 일반적으로 페이지 본문에는 직접 표시되지 않는다.
- `<meta charset="UTF-8">`은 한글을 포함한 문자를 올바르게 해석하게 한다.
- viewport 메타 태그는 페이지 너비를 기기 너비에 맞추며 이후 반응형 디자인의 출발점이 된다.
- `<title>`은 브라우저 탭과 즐겨찾기에 표시될 문서 제목이다.
- `<body>`에는 제목, 문단, 이미지 등 사용자에게 보일 콘텐츠를 둔다. 한 문서에 하나만 존재한다.

실습의 `01basic.html`도 이 골격에 탭 제목, 링크, 이미지, CSS를 추가한 형태다. 문서 구조를 먼저 안정적으로 만든 뒤 콘텐츠와 스타일을 채우는 습관이 디버깅에도 유리하다.

### 3.4 요소와 속성

HTML **요소(element)**는 보통 여는 태그, 내용, 닫는 태그로 구성된다.

```html
<p>My cat is very grumpy.</p>
```

`<p>`가 여는 태그, 문장이 내용, `</p>`가 닫는 태그이며 전체가 하나의 요소다. `img`, `meta`, `link`처럼 내용을 가지지 않는 void element는 닫는 태그를 쓰지 않는다.

**속성(attribute)**은 요소 자체의 의미를 화면에 그대로 추가하지 않으면서, 동작·식별·부가 정보를 설정한다.

```html
<p class="editor-note">편집자 메모입니다.</p>
```

속성 작성 규칙은 다음과 같다.

1. 태그 이름과 첫 속성 사이를 공백으로 구분한다.
2. 속성이 여러 개면 속성끼리도 공백으로 구분한다.
3. 속성값은 일관되게 큰따옴표로 감싼다. 값에 공백이 있으면 따옴표는 반드시 필요하다.

`class`는 같은 목적의 여러 요소를 묶어 CSS나 JavaScript에서 선택할 때 주로 사용한다. `id`는 문서 안에서 고유한 식별자여야 한다.

⚠️ 주의: 실습 `02css.html`에는 `id="purple"`이 두 요소에 반복된다. CSS는 둘 다 선택해 보일 수 있지만 이는 유효한 문서 작성법이 아니다. 고유한 대상은 `id`, 반복되는 스타일 역할은 `class`를 사용한다.

### 3.5 텍스트에 구조와 의미 부여하기

HTML의 주요 목적 중 하나는 텍스트에 구조와 의미를 주는 것이다. 시각적 결과만 보고 태그를 선택하면 문서의 논리 구조가 무너진다.

```html
<body>
  <h1>웹 개발 학습 기록</h1>
  <h2>오늘 배운 내용</h2>
  <p>HTML은 문서의 <strong>구조와 의미</strong>를 표현합니다.</p>
  <p>태그를 역할에 맞게 쓰는 것이 <em>특히</em> 중요합니다.</p>

  <ol>
    <li>HTML 문서 구조</li>
    <li>CSS 선택자</li>
  </ol>

  <ul>
    <li>복습하기</li>
    <li>직접 작성하기</li>
  </ul>
</body>
```

- `<h1>`부터 `<h6>`까지는 제목 단계다. `<h1>`은 단순히 가장 큰 글자가 아니라 문서의 최상위 제목이라는 뜻을 가진다. 단계는 문서의 계층에 맞게 내려간다.
- `<p>`는 하나의 문단을 나타낸다.
- `<ol>`은 순서가 의미 있는 ordered list, `<ul>`은 순서 없는 unordered list이며, 두 목록의 각 항목은 `<li>`로 표현한다.
- `<em>`은 문맥상 강세를, `<strong>`은 강한 중요성을 나타낸다. 기본 기울임·굵은 모양은 브라우저의 기본 스타일일 뿐 핵심은 의미다.

의미에 맞는 마크업은 화면을 소리로 읽는 스크린 리더가 문서 구조를 안내하게 하고, 검색 엔진이 제목과 내용을 해석하는 기반이 된다. 이것이 접근성과 검색 엔진 최적화(SEO)의 출발점이다.

### 3.6 링크와 이미지

링크와 이미지는 HTML이 문서를 연결하고 외부 자원을 포함하는 대표적인 방식이다.

```html
<a href="https://www.google.co.kr/">Google로 이동</a>

<img
  src="images/profile.png"
  alt="홍길동의 프로필 사진"
  width="100"
  height="100"
>
```

`<a>`의 `href`에는 이동할 주소를 지정한다. `<img>`의 `src`에는 이미지 경로를 지정하며, 로컬 상대 경로와 `https://...` 형태의 외부 URL을 모두 사용할 수 있다.

`alt`는 이미지를 불러오지 못했을 때 보이는 대체 텍스트이자 스크린 리더가 전달할 이미지 설명이다. 장식용 이미지라면 `alt=""`로 두어 보조 기술이 건너뛰게 할 수 있지만, 내용이 있는 이미지에는 목적을 전달하는 문구를 써야 한다.

명함 실습은 이 요소들을 조합한다.

```html
<img src="profile.png" alt="홍길동 프로필 사진" width="100" height="100">
<h1>홍길동</h1>
<p>Front-End Developer, Example</p>
<p>서울시 강남구 테헤란로 1234</p>
<p>02-123-4567</p>
```

이미지를 기준으로 상대 경로를 찾을 때는 **HTML 파일의 위치**에서 출발한다. 경로 오류는 개발자 도구의 Network 탭이나 Console에서 404 응답을 확인하면 빠르게 찾을 수 있다.

### 3.7 개발자 도구로 문서 확인하기

브라우저는 HTML 오류를 만나도 가능한 범위에서 문서를 복구해 그린다. 그래서 Python처럼 명확한 에러 메시지가 나타나지 않고, 잘못 중첩된 태그가 조용히 다른 DOM 구조로 보정될 수 있다.

Chrome 개발자 도구는 `F12`, `Ctrl + Shift + I`, 또는 요소를 우클릭한 뒤 **검사**를 선택해 연다.

- **Elements**에서 브라우저가 실제로 구성한 DOM과 각 요소에 적용된 CSS를 확인한다.
- **Styles**에서 선택된 규칙, 취소선 처리된 규칙, 규칙의 출처를 본다.
- **Computed**에서 cascade와 상속을 모두 거친 최종 계산값을 확인한다.

개발자 도구에서 수정한 값은 원본 파일에 저장되지 않는 임시 실험이다. 올바른 값을 찾은 뒤 소스 파일에도 반영해야 한다.

### 3.8 CSS 구문과 세 가지 적용 방법

CSS는 **Cascading Style Sheets**의 약자로, 웹 페이지의 디자인과 레이아웃을 구성한다.

```css
h1 {
  color: red;
  font-size: 30px;
}
```

`h1`은 어떤 요소를 꾸밀지 정하는 **선택자(selector)**다. 중괄호 안의 각 `속성: 값;` 쌍은 **선언(declaration)**이다. `color`와 `font-size`가 속성(property), `red`와 `30px`이 값(value)이다. 선언은 세미콜론으로 구분한다.

CSS를 HTML에 적용하는 방법은 세 가지다.

```html
<!-- 1. 인라인 스타일: 해당 요소의 style 속성에 작성 -->
<h1 style="color: blue; background-color: yellow;">제목</h1>

<!-- 2. 내부 스타일 시트: head의 style 요소에 작성 -->
<style>
  h2 {
    color: red;
  }
</style>

<!-- 3. 외부 스타일 시트: 별도 CSS 파일을 연결 -->
<link rel="stylesheet" href="css/style.css">
```

외부 스타일 시트는 여러 HTML 문서가 규칙을 공유할 수 있고 구조와 표현이 분리되어 유지보수에 유리하다. 내부 스타일은 한 문서의 작은 실습에 편리하고, 인라인 스타일은 재사용이 어렵고 HTML과 표현을 섞으므로 임시 실험이나 매우 제한적인 경우에만 사용한다.

⚠️ 주의: 강의 슬라이드의 “인라인 > 내부 > 외부”는 입문용 단순화다. 인라인 선언은 일반 author 스타일 규칙보다 높은 우선순위를 갖지만, **내부 CSS와 외부 CSS 사이에는 적용 방식 자체의 서열이 없다.** 중요도·명시도가 같다면 HTML에서 나중에 읽힌 규칙이 이긴다. 실습 `01basic.html`에서도 `<style>` 뒤에 `<link>`가 있으므로 같은 명시도의 규칙이라면 외부 파일이 나중 규칙이 될 수 있다.

### 3.9 기본 선택자

선택자는 스타일을 적용할 HTML 요소의 범위를 정한다.

```css
/* 모든 요소 */
* {
  color: red;
}

/* 해당 태그를 모두 선택; 쉼표는 선택자 목록 */
h3,
h4 {
  color: blue;
}

/* class="green"인 모든 요소 */
.green {
  color: green;
}

/* id="purple"인 고유 요소 */
#purple {
  color: purple;
}

/* class 값이 문자 y로 시작하는 요소 */
[class^="y"] {
  color: yellow;
}
```

전체 선택자 `*`는 모든 요소를, 요소 선택자 `h2`는 같은 태그를 모두 고른다. 클래스 선택자 `.green`은 재사용 가능한 역할을 표현하기 좋다. 아이디 선택자 `#purple`은 고유 요소를 찾지만 높은 명시도 때문에 일반 스타일링에 남용하면 덮어쓰기 어려워진다.

속성 선택자는 속성의 존재나 값의 조건으로 대상을 찾는다. 실습의 `[class^="y"]`에서 `^=`는 “값이 이 문자열로 시작함”을 뜻하므로 `class="yellow"`를 선택한다. 단, 실제 `class` 속성이 여러 토큰일 때는 문자열 전체의 시작을 검사한다는 점을 구분해야 한다.

### 3.10 자손 결합자와 자식 결합자

결합자는 요소의 관계까지 조건으로 사용한다.

```html
<ul class="green">
  <li>파이썬</li>
  <li>웹
    <ol>
      <li>HTML</li>
      <li>CSS</li>
    </ol>
  </li>
</ul>

<p class="green">Lorem, <span>ipsum</span> dolor.</p>
```

```css
/* .green 내부의 모든 깊이에 있는 li */
.green li {
  color: brown;
}

/* .green의 바로 한 단계 아래 span만 */
.green > span {
  font-size: 50px;
}

/* 관계를 단계별로 더 구체화할 수도 있다. */
.green > li > ol > li {
  color: aqua;
}
```

공백으로 쓰는 **자손 결합자**는 깊이와 관계없이 내부의 모든 일치 요소를 선택한다. `>`로 쓰는 **자식 결합자**는 바로 아래 한 단계만 선택한다. 실습에서 `.green li`는 바깥 `ul`의 `li`뿐 아니라 중첩된 `ol`의 `li`도 고르지만, `.green > li`라면 바깥 목록의 직계 항목만 고른다.

⚠️ 주의: 선택자가 지나치게 긴 DOM 경로에 의존하면 HTML 중첩이 조금만 바뀌어도 스타일이 깨진다. 관계 자체가 중요한 경우에 결합자를 쓰고, 재사용 가능한 시각적 역할은 의미 있는 class로 표현하는 편이 유지보수에 유리하다.

### 3.11 Cascade와 명시도

한 요소의 같은 속성에 여러 선언이 도달하면 브라우저는 **cascade** 알고리즘으로 최종 선언을 정한다. 여기서 **명시도(specificity)**는 경쟁하는 선택자 중 어느 것이 더 구체적인지 비교하는 기준이다.

입문 단계에서는 다음 순서로 판단하면 된다.

1. `!important` 여부 등 선언의 중요도와 출처를 비교한다.
2. 같은 층위라면 인라인 스타일과 선택자의 명시도를 비교한다.
3. 선택자에서는 대체로 ID > class·속성 > 요소 순으로 가중치가 높다.
4. 앞 조건이 모두 같으면 소스 코드에서 나중에 선언된 규칙이 이긴다.

```css
h1 {
  color: red;
}

h1 {
  color: purple; /* 같은 명시도이므로 나중 선언이 적용된다. */
}

.make-red {
  color: red;
}

h1 {
  color: purple;
}
```

`<h1 class="make-red">`에는 `.make-red`가 `h1`보다 명시도가 높으므로, 뒤에 있는 `h1` 규칙보다 앞의 class 규칙이 이긴다. class 속성에 적힌 클래스 이름의 순서는 명시도나 적용 순서를 바꾸지 않는다. `.green`과 `.orange`의 명시도가 같다면 **CSS에서 어느 규칙이 뒤에 있는지**가 결과를 정한다.

슬라이드의 예를 정리하면 다음과 같다.

```css
h2 { color: darkviolet !important; }
p { color: blue; }
.orange { color: orange; }
.green { color: green; }
#red { color: red; }
```

- `<p>`는 요소 선택자의 파란색을 받는다.
- `<p class="orange">`는 class가 더 구체적이므로 주황색이다.
- `<p class="green orange">`와 `<p class="orange green">`은 둘 다 `.orange`와 `.green`에 일치한다. 위 코드에서는 뒤에 선언된 `.green`이 이기므로 둘 다 초록색이다.
- `<p id="red" class="orange">`는 ID 선택자가 이겨 빨간색이다.
- `<p ... style="color: brown;">`은 인라인 스타일이 일반 선택자보다 우선해 갈색이다.
- `<h2 ... style="color: brown;">`은 `h2`의 `!important` 선언이 일반 인라인 선언보다 높은 중요도 층에 있어 진한 보라색이다.

`!important`는 cascade의 일반 구조를 건너뛰어 덮어쓰기 경쟁을 더 어렵게 만든다. 우선 선택자의 범위와 구조를 바로잡고, 정말 필요한 예외에서만 제한적으로 사용한다.

💡 포인트: “CSS가 적용되지 않는다”는 표현은 대부분 정확하지 않다. 규칙은 대개 선택되었지만 다른 선언에 의해 최종값에서 졌다. Elements의 Styles와 Computed 패널에서 취소선, 명시도, 규칙 순서를 확인하면 된다.

### 3.12 선언의 값과 단위

CSS 속성마다 받을 수 있는 값의 종류가 정해져 있다. 색처럼 `red`라는 키워드를 쓸 수도 있지만 크기와 간격에는 단위가 필요하다.

| 단위 | 기준 | 장점 | 주의점 | 대표 사용처 |
|---|---|---|---|---|
| `px` | CSS 픽셀 | 직관적이고 예측하기 쉬움 | 글자 크기에 남용하면 사용자 설정 대응이 불리함 | 가는 border 등 고정 크기 |
| `em` | 해당 요소에서 계산된 글자 크기. `font-size` 자체에서는 부모 글자 크기 | 컴포넌트 안에서 비례 조절 | 중첩 시 크기가 누적되어 계산이 복잡해질 수 있음 | 특정 컴포넌트 내부 비례 |
| `rem` | 루트 `<html>`의 글자 크기 | 일관성, 유지보수성, 접근성 | 루트 글자 크기에 의존 | 전역 글자·여백·간격 |
| `%` | 속성에 따라 정해지는 기준. 흔히 containing block의 크기 | 컨테이너에 맞춘 유동적 크기 | 항상 “부모의 같은 속성”인 것은 아님 | width 등 유동 레이아웃 |
| `vw`, `vh` | viewport 너비·높이의 1% | 화면 크기에 직접 반응 | 콘텐츠와 모바일 viewport 특성을 고려해야 함 | 화면 기준 크기 |

강의에서는 `em`과 `rem`의 차이를 다음 예로 비교한다.

```html
<div class="parent-for-em">
  부모 요소
  <div class="em-unit">em 단위 자식</div>
</div>
<div class="rem-unit">rem 단위 요소</div>
```

```css
.parent-for-em {
  font-size: 20px;
}

.em-unit {
  font-size: 1.5em; /* 부모 20px × 1.5 = 30px */
}

.rem-unit {
  font-size: 1.5rem; /* 루트 16px 가정 × 1.5 = 24px */
}
```

브라우저 기본 루트 글자 크기가 흔히 16px이지만 사용자가 바꿀 수 있으므로 절대 상수처럼 가정해서는 안 된다. `rem`은 루트 기준을 공유해 전체 비율을 관리하기 쉽고 사용자 글자 크기 설정도 반영할 수 있다.

⚠️ 주의: `0px`, `0rem`처럼 값이 0일 때는 `0`만 쓰는 것이 권장된다. 또한 `px`가 물리적 모니터 픽셀과 항상 1:1인 것은 아니다. CSS 픽셀은 브라우저가 사용하는 논리 단위다.

### 3.13 CSS 상속

상속은 부모 요소에서 계산된 일부 속성값이 자식 요소로 전달되는 메커니즘이다. 텍스트 관련 스타일을 매 요소에 반복하지 않게 해 재사용성을 높인다.

```html
<ul class="parent">
  <li class="child">Hello</li>
  <li class="child">Bye</li>
</ul>
```

```css
.parent {
  color: red;              /* 기본적으로 자식에게 상속됨 */
  border: 1px solid black; /* 기본적으로 상속되지 않음 */
}
```

`li`의 글자는 빨간색이 되지만 각 `li`에 테두리가 생기지는 않는다. 대체로 `color`, `font-*`, `text-align`, `visibility` 같은 텍스트·표현 관련 속성은 상속되고, `width`, `height`, `margin`, `padding`, `border`, `box-sizing`, 위치 관련 속성은 상속되지 않는다.

상속 여부는 감으로 외우기보다 MDN 각 속성 문서의 **Inherited** 항목에서 확인한다. 필요하면 값을 명시적으로 제어할 수 있다.

```css
.inner-box {
  border: inherit;  /* 부모의 계산된 border 값을 의도적으로 상속 */
  color: black;     /* 상속된 red를 자식에서 덮어씀 */
  text-align: start;
}
```

워크숍 `web_ws_1_4`에서 바깥 박스의 `color: red`와 `text-align: center`는 안쪽 콘텐츠에 상속되지만, `border`는 자동 상속되지 않는다. `border: inherit`를 직접 썼을 때만 바깥 박스와 같은 테두리를 받는다.

⚠️ 주의: 상속과 자손 선택자는 다른 개념이다. 상속은 값이 부모에서 자식으로 전달되는 CSS 동작이고, `.parent .child`는 규칙을 적용할 대상을 선택하는 문법이다.

### 3.14 CSS Box Model

브라우저의 모든 HTML 요소는 사각형 상자로 계산된다. 둥근 요소도 기본 사각형 상자를 그린 뒤 모서리를 깎아 표현한 결과다. 이 **Box Model**은 안쪽부터 네 영역으로 구성된다.

```text
margin  ┌────────────────────────────┐
border  │ ┌────────────────────────┐ │
padding │ │ ┌────────────────────┐ │ │
content │ │ │ 실제 내용          │ │ │
        │ │ └────────────────────┘ │ │
        │ └────────────────────────┘ │
        └────────────────────────────┘
```

- **content**: 텍스트나 이미지가 놓이는 실제 내용 영역
- **padding**: content와 border 사이의 안쪽 여백
- **border**: content와 padding을 감싸는 테두리
- **margin**: 다른 요소와 거리를 만드는 바깥 여백

각 영역은 `-top`, `-right`, `-bottom`, `-left`로 방향별 지정이 가능하다.

```css
.box1 {
  width: 200px;
  padding-left: 25px;
  padding-bottom: 25px;
  margin-left: 25px;
  margin-top: 50px;
  border-width: 3px;
  border-style: solid;
  border-color: black;
}

.box2 {
  width: 200px;
  padding: 25px 50px;
  margin: 25px auto;
  border: 1px dashed black;
}
```

`.box2`의 `padding: 25px 50px`는 위·아래 25px, 왼쪽·오른쪽 50px이다. `margin: 25px auto`는 위·아래 25px이며, 블록의 사용 가능한 가로 공간이 있을 때 좌우 auto margin이 남는 공간을 나누어 가로 중앙 정렬에 사용할 수 있다.

### 3.15 shorthand 속성 읽기

shorthand는 관련된 여러 개별 속성을 한 선언으로 묶는다.

```css
.box {
  /* width, style, color를 한 번에 지정; 이 세 값의 순서는 유연하다. */
  border: 2px solid black;

  /* top right bottom left: 시계 방향 */
  margin: 10px 20px 30px 40px;

  /* top | left·right | bottom */
  padding: 10px 20px 30px;
}
```

`margin`과 `padding`의 값 개수는 다음처럼 해석한다.

| 값 개수 | 방향 |
|---|---|
| 1개 | 네 방향 모두 |
| 2개 | 위·아래 / 왼쪽·오른쪽 |
| 3개 | 위 / 왼쪽·오른쪽 / 아래 |
| 4개 | 위 / 오른쪽 / 아래 / 왼쪽 |

네 방향은 시계 방향으로 기억하면 된다. shorthand는 간결하지만 지정하지 않은 하위 속성까지 초기화할 수 있으므로, 기존 규칙 위에 덮어쓸 때는 개발자 도구에서 최종값을 확인한다.

### 3.16 `box-sizing`: width가 가리키는 영역

기본값인 `content-box`에서 `width`와 `height`는 content 영역만 지정한다. 따라서 실제 바깥 너비는 좌우 padding과 border를 더해야 한다.

```css
.content-box {
  box-sizing: content-box;
  width: 100px;
  padding: 10px;
  border: 2px solid black;
}
```

이 요소가 차지하는 border 바깥쪽 너비는 `100 + 10×2 + 2×2 = 124px`이다. margin은 박스 바깥 간격이므로 이 124px 자체에는 포함하지 않지만 주변 배치에 필요한 공간에는 영향을 준다.

`border-box`에서는 선언한 `width` 안에 content, padding, border가 모두 포함된다.

```css
.border-box {
  box-sizing: border-box;
  width: 100px;
  padding: 10px;
  border: 2px solid black;
}
```

전체 border box 너비는 100px이고 content 너비는 `100 - 10×2 - 2×2 = 76px`이 된다. 원하는 최종 크기를 바로 선언할 수 있어 레이아웃 계산이 단순해진다. 실무에서는 흔히 다음처럼 모든 요소에 적용한다.

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}
```

⚠️ 주의: `border-box`가 padding과 border를 없애는 것은 아니다. 이들을 지정한 width 안에 포함시키는 계산법이다. padding과 border의 합이 width보다 지나치게 크면 content 영역을 확보할 수 없으므로 여전히 값을 합리적으로 설계해야 한다.

### 3.17 HTML·CSS 스타일 가이드

HTML은 태그명과 속성명의 대소문자를 엄격히 구분하지 않지만 소문자로 통일하는 것이 표준적인 작성 관례다. 속성값에는 큰따옴표를 사용하고, 보통 공백 두 칸으로 중첩 구조를 들여쓴다. 한 요소를 한 줄에 두고 자식 요소는 한 단계 더 들여쓰면 닫는 태그 누락과 잘못된 중첩을 찾기 쉽다.

HTML은 소스 코드의 연속 공백과 일반 줄바꿈을 화면에서 하나의 공백으로 합친다. 시각적 간격을 만들려고 공백이나 Enter를 반복하지 말고 문서 구조와 CSS를 사용한다.

```html
<!-- 잘못된 의도 전달: 따옴표가 없어서 class 값이 끊긴다. -->
<p class=text-style red-color>...</p>

<!-- 두 class 토큰을 하나의 속성값으로 전달한다. -->
<p class="text-style red-color">...</p>
```

CSS도 선택자와 선언을 각 줄에 분리하고, 중괄호 앞과 콜론 뒤에 공백을 두며 마지막 선언에도 세미콜론을 붙인다. 속성과 값은 소문자로 작성하고 0에는 단위를 생략한다. 클래스명은 목적이 드러나는 `profile-card`, `contact-list` 같은 kebab-case를 권장한다.

일반 컴포넌트 스타일에는 class 선택자를 우선 사용한다. ID 선택자는 명시도가 지나치게 높고, 요소 선택자는 적용 범위가 넓어 다른 규칙과 결합될 때 유지보수가 어려워질 수 있다. 인라인 스타일 역시 구조와 표현을 섞으므로 가급적 피한다.

### 3.18 MDN을 개발 도구처럼 사용하기

CSS의 모든 속성과 값을 외울 필요는 없다. 자주 쓰는 속성은 반복하며 익히고, 나머지는 필요할 때 신뢰할 수 있는 문서에서 확인하는 것이 정상적인 개발 방식이다.

MDN Web Docs는 HTML, CSS, JavaScript, Web API와 개발 도구에 대한 종합 참고 자료다. 특정 요소나 속성을 찾을 때는 다음 항목을 함께 확인한다.

## 4. 적용 관점에서 다시 보기

HTML/CSS 화면을 구현할 때는 보이는 모양부터 맞추기보다 다음 순서로 접근하면 수정 비용이 줄어든다.

1. **콘텐츠의 역할을 먼저 분류한다.** 최상위 제목, 하위 제목, 문단, 목록, 링크, 이미지가 무엇인지 정한 뒤 의미에 맞는 HTML을 작성한다.
2. **문서 골격과 자원 경로를 확인한다.** `doctype`, 언어, 문자 인코딩, viewport, title을 넣고 이미지와 CSS 상대 경로가 HTML 파일 기준으로 맞는지 확인한다.
3. **재사용할 역할에 class를 붙인다.** 보이는 색 이름보다 `profile-card`, `contact-info`처럼 목적이 드러나는 이름을 사용한다.
4. **CSS 적용 여부를 작은 범위부터 검증한다.** 외부 CSS가 로드되었는지, 선택자가 실제 요소와 일치하는지, Styles 패널에서 규칙이 취소선 처리되었는지를 본다.
5. **충돌은 cascade 순서로 추적한다.** `!important`를 추가하기 전에 중요도, 인라인 여부, 명시도, 소스 순서를 차례대로 비교한다.
6. **크기 문제는 Box Model로 계산한다.** Computed 패널에서 content, padding, border, margin을 보고 `box-sizing`까지 확인한다.

문제를 보고 떠올릴 신호도 정리할 수 있다.

| 증상 | 먼저 확인할 것 |
|---|---|
| 한글이 깨진다 | `meta charset="UTF-8"` |
| 이미지가 보이지 않는다 | `src` 상대 경로, 파일명 대소문자, Network 404 |
| CSS 파일 전체가 적용되지 않는다 | `link`의 `rel`, `href`, 로드 순서 |
| 특정 규칙만 적용되지 않는다 | 선택자 일치 여부, 명시도, 소스 순서, 상속 |
| class를 두 개 썼는데 순서대로 적용되지 않는다 | HTML의 class 토큰 순서가 아니라 CSS 선언 순서 |
| 자식 텍스트까지 같은 색이 된다 | 상속되는 `color`인지 확인 |
| 자식 테두리는 따라오지 않는다 | `border`는 기본 비상속 속성; 필요하면 `inherit` |
| 지정한 width보다 상자가 크다 | `content-box`에서 padding과 border가 추가되었는지 확인 |
| 중첩할수록 글자가 커진다 | `em` 기준이 누적되는지 확인하고 `rem` 검토 |

명함 실습처럼 작은 화면도 이 원칙을 그대로 적용할 수 있다. 먼저 이미지와 이름, 직책, 주소, 전화번호를 의미 있는 요소로 마크업한다. 그 뒤 카드 전체를 감싸는 class를 두고, 글자 스타일과 Box Model을 적용한다. 모양을 고치기 위해 HTML에 인라인 스타일을 계속 붙이는 대신 외부 또는 내부 스타일 시트에서 역할별 규칙을 관리해야 이후 항목이 늘어도 재사용할 수 있다.

## 5. 배운 점 / 확장 포인트

### 5.1 이번 강의 이전에 몰랐던 것 또는 새로 이해된 것

HTML 태그는 화면 모양을 지정하는 명령이 아니라 콘텐츠의 의미와 계층을 표현한다. CSS 결과도 단순한 “나중 값이 덮어쓰기”가 아니라 중요도, 명시도, 소스 순서, 상속을 거쳐 결정되며, `width`의 실제 의미는 `box-sizing`에 따라 달라진다.

### 5.2 앞으로 이어지는 연결점

Box Model은 다음 단계의 `display`, Normal Flow, Flexbox, Grid 같은 CSS Layout을 이해하는 바탕이 된다. 상대 단위와 viewport 설정은 반응형 웹으로, 의미 있는 HTML은 접근성·SEO와 DOM 조작으로 이어진다.

### 5.3 더 파볼 만한 주제

HTML의 구획 요소인 `header`, `nav`, `main`, `section`, `article`, `footer`, 사용자 입력을 다루는 form control, 링크와 이미지의 접근 가능한 이름을 더 학습할 수 있다. CSS에서는 pseudo-class·pseudo-element, margin collapsing, CSS custom properties, cascade layer를 살펴보면 이번 강의의 선택과 충돌 원리를 확장할 수 있다.

## 6. 요약 정리

- HTML은 HyperText를 태그로 마크업하여 웹 문서의 **의미와 구조**를 정의한다.
- `head`는 문서 설정과 메타데이터, `body`는 사용자에게 표시할 콘텐츠를 담는다.
- 제목, 문단, 목록, 강조, 링크, 이미지는 보이는 모양이 아니라 콘텐츠의 역할에 맞는 요소를 선택한다.
- CSS 규칙은 `선택자 { 속성: 값; }`이며 인라인, 내부, 외부 스타일 시트로 적용할 수 있다.
- 내부와 외부 CSS 사이에는 고정된 우선순위가 없다. 같은 중요도와 명시도에서는 소스 순서가 결과를 정한다.
- 기본 선택자와 결합자는 대상과 관계를 선택하고, cascade와 명시도는 충돌하는 선언 중 최종값을 정한다.
- class는 재사용 가능한 스타일 역할에 적합하고, 고유해야 하는 ID와 강제력이 큰 `!important`는 신중하게 사용한다.
- `px`, `em`, `rem`, `%`는 기준이 다르다. 특히 `em`은 중첩 기준, `rem`은 루트 기준이라는 차이를 기억한다.
- 텍스트 관련 속성은 흔히 상속되지만 Box Model 관련 속성은 대체로 상속되지 않는다.
- Box Model은 content, padding, border, margin으로 구성되며 `border-box`는 padding과 border를 선언한 width 안에 포함한다.
- 결과가 예상과 다르면 추측으로 규칙을 더하지 말고 개발자 도구의 Styles와 Computed에서 선택, cascade, 상속, 박스 계산을 확인한다.

🧠 기억할 것: HTML은 “무엇인가”를 표현하고 CSS는 “어떻게 보이는가”를 표현한다. 브라우저의 최종 결과는 선택자 하나가 아니라 cascade, 상속, 단위, Box Model이 함께 계산한 값이다.
