- 🎯 글의 목표: Markdown으로 문서 구조를 표현하고, 파일을 Notion으로 가져갈 때 유지되는 형식과 다시 손봐야 하는 형식을 구분한다.
- 🧩 핵심 키워드: Markdown, 마크업, 제목, 목록, 링크, 코드 블록, 표, Notion import
- ⭐ 중요도: ★★★★☆ — README, TIL, 기술 문서에서 같은 원문을 여러 도구로 옮겨 쓰는 기본 형식이다.
- 📝 한눈에 보는 내용: Markdown은 기호로 문서의 의미 구조를 표시한다. 표준 문법은 여러 서비스에서 비교적 잘 변환되지만, HTML이나 서비스 전용 블록은 같은 모습으로 옮겨지지 않을 수 있다.

## 1. Markdown이란?

Markdown은 일반 텍스트에 간단한 기호를 더해 제목, 목록, 링크, 코드 같은 문서 구조를 표현하는 경량 마크업 언어다.

```markdown
# 학습 기록

오늘 배운 내용은 **배열 메서드**입니다.

- map
- filter
- reduce
```

원문은 텍스트이므로 Git으로 변경 이력을 관리하기 쉽다. GitHub, 코드 편집기, 문서 도구가 이 기호를 읽어 사람이 보기 좋은 화면으로 렌더링한다.

Markdown은 디자인을 정밀하게 배치하는 언어가 아니다. “이 문장은 제목이다”, “이 부분은 코드다”처럼 내용의 역할을 표시하는 데 강하다.

## 2. 자주 사용하는 기본 문법

### 2.1 제목

`#` 개수로 제목 단계를 표현한다.

```markdown
# 문서 제목
## 큰 주제
### 세부 주제
```

한 문서에는 최상위 `#` 제목을 하나만 두고 본문은 `##`부터 내려가는 방식이 읽기 쉽다. `##` 다음에 바로 `####`를 쓰지 않고 제목 계층을 한 단계씩 연결한다.

### 2.2 목록

```markdown
- 순서 없는 항목
- 다음 항목
  - 하위 항목

1. 첫 단계
2. 두 번째 단계
```

하위 목록은 공백으로 들여쓴다. 탭과 공백 해석은 도구마다 조금 다를 수 있으므로 한 저장소에서는 같은 들여쓰기 규칙을 유지한다.

### 2.3 강조

```markdown
**굵은 글씨**
*기울임 글씨*
~~취소선~~
```

강조를 너무 많이 사용하면 무엇이 중요한지 오히려 구분하기 어렵다. 용어의 첫 등장이나 핵심 결론처럼 실제로 필요한 곳에 사용한다.

### 2.4 인용문

```markdown
> 외부 문장을 인용하거나 중요한 참고 내용을 구분한다.
```

인용문은 단순히 예쁜 박스를 만드는 문법이 아니다. 다른 출처의 문장이나 본문과 구별할 참고 내용을 나타낸다.

### 2.5 링크와 이미지

```markdown
[표시할 텍스트](https://example.com)
![이미지의 의미를 설명하는 대체 텍스트](https://example.com/image.png)
```

상대 경로 이미지는 Markdown 파일의 위치를 기준으로 찾는다. GitHub에서는 파일 이름의 대소문자도 경로의 일부이므로 실제 폴더 이름과 링크를 같게 작성한다.

### 2.6 인라인 코드와 코드 블록

변수명이나 짧은 명령은 백틱 하나로 감싼다.

```markdown
배열 길이는 `items.length`로 확인한다.
```

여러 줄 코드는 백틱 세 개로 감싸고 언어 이름을 지정한다.

````markdown
```javascript
const doubled = [1, 2, 3].map((number) => number * 2)
```
````

언어 이름은 실행 언어를 바꾸지 않는다. 렌더러가 문법 강조를 적용하도록 알려 주는 정보다.

### 2.7 표

```markdown
| 메서드 | 결과 |
| --- | --- |
| map | 새 배열 |
| reduce | 누적값 |
```

표는 항목을 같은 기준으로 비교할 때 유용하다. 한 셀에 긴 문단이나 복잡한 코드를 넣으면 작은 화면에서 읽기 어려우므로 목록이나 소제목으로 바꾸는 편이 낫다.

### 2.8 수평선

```markdown
---
```

수평선은 큰 문맥을 나눌 때 사용한다. 제목으로 구조가 충분히 드러난다면 모든 소절 사이에 반복할 필요는 없다.

## 3. Markdown을 Notion으로 옮기는 방법

Notion에서 Markdown 문서를 사용하는 방법은 크게 두 가지다.

### 3.1 짧은 내용은 복사해 붙여넣기

제목, 목록, 인용문, 코드처럼 표준적인 Markdown은 복사해 Notion 페이지에 붙여넣을 때 블록으로 변환될 수 있다. 다만 붙여넣기 결과는 원본 구조와 Notion 편집기의 해석에 영향을 받으므로 중요한 문서는 변환 결과를 직접 확인한다.

다음 항목을 점검한다.

- 제목 단계가 유지되었는가?
- 중첩 목록의 들여쓰기가 유지되었는가?
- 코드 블록의 언어가 올바른가?
- 표가 일반 텍스트로 풀리지 않았는가?
- 로컬 이미지 경로가 끊기지 않았는가?

### 3.2 문서 전체는 `.md` 파일로 가져오기

긴 문서는 붙여넣기보다 Notion의 `Settings → Import → Text & Markdown`에서 `.md` 파일을 가져오는 방법이 더 분명하다. 여러 파일은 한 번에 선택하거나 폴더 구조를 ZIP으로 묶어 가져올 수 있다.

Notion 공식 안내를 기준으로 일반 텍스트, 표준 Markdown, 제목, 목록과 코드 블록은 가져올 수 있다. 반면 anchor link와 도구별 비표준 확장은 깔끔하게 변환되지 않을 수 있다.

```text
TIL Markdown 파일
       ↓ Notion Import
제목·문단·목록·코드 블록 변환
       ↓
표·링크·이미지·특수 블록 점검
       ↓
필요한 부분을 Notion 블록으로 보정
```

## 4. `<aside>`와 Callout은 같은 문법이 아니다

`<aside>`는 HTML 요소다. Markdown 표준의 Callout 문법이 아니며, Notion의 Callout 블록과도 동일하지 않다.

```html
<aside>
  중요한 참고 내용
</aside>
```

이 코드를 붙여넣었을 때 Notion이 자동으로 Callout으로 바꾼다고 기대하면 안 된다. 다음처럼 표준 Markdown 인용문으로 단순화하면 여러 도구에서 의미를 유지하기 쉽다.

```markdown
> 💡 중요한 참고 내용
```

Notion 고유의 Callout 모양이 필요하다면 페이지에서 `/callout` 블록을 만들고 내용을 옮긴다. GitHub에서도 읽혀야 하는 TIL 원본은 표준 Markdown을 우선하고, Notion에서만 필요한 표현은 옮긴 뒤 보정하는 편이 안전하다.

## 5. 표와 이미지가 깨지는 이유

Markdown 렌더러마다 지원하는 확장 문법이 다르다. GitHub에서 보이는 표가 다른 편집기에서 일반 텍스트로 들어갈 수 있고, 로컬 상대 경로 이미지는 Notion이 해당 파일에 접근할 수 없어 표시되지 않을 수 있다.

이미지가 포함된 문서를 옮길 때는 다음을 확인한다.

1. 이미지 파일도 함께 업로드되었는가?
2. 웹에서 접근 가능한 URL인가, 로컬 상대 경로인가?
3. 파일 이름과 확장자의 대소문자가 정확한가?
4. 대체 텍스트만으로도 이미지 목적을 이해할 수 있는가?

복잡한 표는 Notion 데이터베이스가 필요한지, 단순 표 블록이면 충분한지 구분한다. 데이터베이스는 속성, 필터, 정렬이 필요한 구조이고 Markdown 표는 정적인 비교 표현이다.

## 6. 여러 환경에서 잘 옮겨지는 문서 작성 기준

- HTML보다 표준 Markdown 문법을 우선한다.
- 제목 계층을 건너뛰지 않는다.
- 한 셀에 너무 많은 내용을 넣는 넓은 표를 피한다.
- 로컬 링크와 이미지 경로의 대소문자를 실제 파일과 맞춘다.
- 서비스 전용 문법은 다른 환경에서 어떻게 보일지 확인한다.
- 원본 Markdown을 기준 문서로 보관하고 변환된 Notion 페이지를 별도 표현으로 생각한다.

## 7. 요약 정리

- Markdown은 텍스트 기호로 문서의 의미 구조를 표현한다.
- 제목, 목록, 링크, 코드 블록은 여러 도구에서 비교적 잘 호환된다.
- `<aside>`는 Markdown Callout이나 Notion Callout과 같은 문법이 아니다.
- 긴 문서는 Notion의 Text & Markdown 가져오기를 사용할 수 있다.
- 비표준 확장, anchor link, 복잡한 표와 로컬 이미지는 변환 뒤 점검이 필요하다.
- 여러 환경에서 사용할 문서는 표준 Markdown을 원본으로 유지하는 편이 안전하다.

🧠 기억할 것: **Markdown은 모양을 완전히 복제하는 형식이 아니라, 여러 도구가 해석할 수 있도록 문서의 구조와 의미를 남기는 형식이다.**
