## 1. 들어가며

실습에서 배운 문법은 이해했다고 느끼기 쉽지만, 직접 빈칸을 채우기 시작하면 어디가 진짜 내 것이 되었는지 바로 드러난다. 이 과제는 바로 그 지점을 겨냥한다. 클래스 파트에서는 객체가 어떤 상태를 가져야 하고, 어떤 동작을 메서드로 둘지 스스로 결정해야 한다. Pandas 파트에서는 단순히 함수를 아는 것이 아니라, 어떤 순서로 데이터 선택, 조건 필터링, 그룹 집계, 재구조화를 할지 연결해서 생각해야 한다.

즉, 이 과제의 핵심은 “아는 문법을 구현으로 바꾸는 힘”이다. 클래스와 DataFrame 조작은 전혀 다른 주제처럼 보이지만, 사실 둘 다 구조를 설계하고 상태를 관리한다는 점에서 닮아 있다.

## 2. 핵심 개념 정리

과제는 크게 두 덩어리로 구성된다. 첫 번째 덩어리는 Python 클래스다. `Dog` 예제로 생성자와 메서드의 기본 구조를 익히고, `BankAccount` 문제에서 상태 관리와 검증 로직까지 포함한 하나의 객체를 구현한다. 두 번째 덩어리는 Pandas다. tips 데이터셋을 이용해 DataFrame을 확인하고, 필요한 열만 뽑고, 조건으로 행을 걸러내고, `groupby`, `pivot`, `melt`로 데이터를 다른 관점에서 다시 본다.

## 3. 본문 정리

### 3.1 클래스 기초: 설계도와 인스턴스의 감각 잡기

클래스는 같은 구조를 가진 객체를 반복해서 만들기 위한 설계도다. 과제는 `Person`, `Calculator` 예제를 먼저 보여준 뒤 `Dog` 클래스를 직접 구현하게 만든다. 이 순서는 꽤 중요하다. 먼저 “속성만 있는 경우”, “동작만 있는 경우”, 그리고 “속성과 동작이 함께 있는 경우”를 차례대로 보여주기 때문이다.

`Dog` 문제의 핵심은 구조가 매우 작아도 클래스의 기본 골격은 그대로라는 점이다.

```python
class Dog:
    def __init__(self, name, breed):
        # 생성자에서 객체마다 다른 상태를 저장한다.
        self.name = name
        self.breed = breed

    def bark(self):
        # 객체 자신의 이름을 이용해 동작을 만든다.
        print(f"{self.name}가 짖습니다: 멍멍!")
```

이 코드에서 중요한 것은 `name`과 `breed`를 단순히 함수 인자로 받는 데서 끝내지 않고, `self.name`, `self.breed`라는 객체 속성으로 저장한다는 점이다. 그래야 객체가 생성된 뒤에도 그 상태를 기억할 수 있다.

쉽게 말하면 생성자는 객체를 만들 때 한 번 불리는 초기 설정 함수다. 여기서 상태를 저장해두면, 이후 메서드는 그 상태를 꺼내어 쓴다.

⚠️ 주의

- `__init__` 안에서 `self.name = name` 저장을 하지 않으면, `bark()`에서 이름을 사용할 수 없다.
- `print()`를 반환하는 것과 문자열을 반환하는 것은 다르다. 문제 요구사항이 출력인지 반환인지 구분해야 한다.

📌 핵심: 클래스의 첫걸음은 “입력값을 객체 상태로 저장하고, 메서드가 그 상태를 사용하게 만드는 것”이다.

### 3.2 BankAccount: 상태와 검증 로직을 함께 설계하기

`BankAccount`는 이 과제의 핵심 클래스 문제다. 여기서는 단순히 값을 저장하는 데서 끝나지 않고, 상태가 잘못 바뀌지 않도록 검증 로직까지 넣어야 한다.

이 클래스가 가져야 하는 상태는 세 가지다.

- `owner`: 계좌 소유자
- `balance`: 현재 잔액
- `history`: 거래 내역 리스트

그리고 동작은 입금, 출금, 잔액 조회, 거래 내역 조회, 객체 문자열 표현까지 포함한다. 즉, “은행 계좌라면 당연히 있어야 할 책임”이 한 객체 안에 모여 있다.

```python
class BankAccount:
    def __init__(self, owner: str, balance: int = 0):
        # 계좌의 기본 상태를 설정한다.
        self.owner = owner
        self.balance = balance
        self.history = []

    def deposit(self, amount: int):
        # 잘못된 입력은 상태를 바꾸지 않는다.
        if amount <= 0:
            print("입금 실패")
            return

        self.balance += amount
        self.history.append(f"입금: {amount}원")
        print("입금 완료")

    def withdraw(self, amount: int):
        # 출금도 입력 검증과 잔액 검증이 먼저다.
        if amount <= 0:
            print("출금 실패")
            return
        if amount > self.balance:
            print("잔액 부족")
            return

        self.balance -= amount
        self.history.append(f"출금: {amount}원")
        print("출금 완료")

    def show_balance(self):
        print(f"현재 잔액: {self.balance}원")

    def get_transaction_history(self):
        if not self.history:
            print("거래 내역이 없습니다.")
            return []

        for record in self.history:
            print(record)
        return self.history

    def __str__(self):
        return f"[계좌 소유자: {self.owner}, 잔액: {self.balance}원]"
```

이 문제에서 특히 중요한 점은 “실패 시 상태를 바꾸지 않는다”는 원칙이다. 입금 금액이 0 이하이거나, 출금 금액이 음수이거나, 잔액보다 큰 금액을 출금하려는 경우에는 메시지만 출력하고 종료해야 한다. 이 원칙을 놓치면 테스트는 물론이고 객체 설계 자체가 흔들린다.

💡 포인트

`history`는 단순한 부가 기능이 아니다. 객체가 지나온 상태 변화를 기록해두는 장치다. 이런 기록 필드는 디버깅과 추적에 매우 유용하다.

⚠️ 주의

- `amount == 0`만 검사하면 음수 입력을 놓칠 수 있다. 요구사항 관점에서는 `<= 0`가 더 안전하다.
- 실패한 거래를 `history`에 기록할지 여부는 요구사항을 먼저 확인해야 한다. 여기서는 실패 시 상태와 내역이 바뀌면 안 된다.
- `__str__`는 출력 편의를 위한 메서드지만, 테스트 코드에서 객체 표현 검증으로도 자주 쓰인다.

📌 핵심: 좋은 클래스는 기능만 있는 클래스가 아니라, 잘못된 상태 변경을 스스로 막는 클래스다.

### 3.3 Pandas 기초: DataFrame을 읽고 필요한 부분만 꺼내기

과제의 Pandas 파트는 `tips` 데이터셋을 사용한다. 이 데이터셋은 식사 금액, 팁, 성별, 흡연 여부, 요일, 시간대, 인원 수를 담고 있어 기본적인 조작 연습에 적합하다.

먼저 해야 할 일은 DataFrame의 구조를 확인하는 것이다.

```python
import seaborn as sns
import pandas as pd

df = sns.load_dataset("tips")

print(df.head())
print(df.info())
print(df.describe())
print(df.shape)
```

이후 가장 기본적인 조작은 열 선택과 조건 필터링이다.

```python
# 필요한 열만 선택하기
# 여러 열을 고를 때는 대괄호를 두 번 쓴다.
tip_bill_df = df[["tip", "total_bill"]]

# 조건에 맞는 행만 남기기
high_bill_df = df[df["total_bill"] >= 20]
```

이 두 문제는 간단해 보이지만, 이후의 거의 모든 DataFrame 조작의 시작점이다. 원하는 열을 선택하고, 원하는 행만 남기는 일이 데이터 분석의 첫 번째 필터 역할을 하기 때문이다.

⚠️ 주의

- `df['tip', 'total_bill']`처럼 쓰면 안 된다. 여러 열은 리스트로 감싸서 `df[[...]]` 형태로 선택해야 한다.
- 조건식은 `df['total_bill'] >= 20`처럼 각 행에 대해 참/거짓을 만드는 식이어야 한다.

📌 핵심: Pandas의 시작은 “전체 표를 보는 것”이 아니라 “필요한 열과 행을 빠르게 골라내는 것”이다.

### 3.4 groupby와 pivot: 같은 데이터를 다른 축으로 보기

이 과제의 Pandas 심화 파트는 데이터 재해석의 감각을 길러준다. 같은 팁 데이터라도 성별과 요일이라는 기준을 세우면 다른 표가 된다. 이때 쓰는 도구가 `groupby`와 `pivot`이다.

먼저 그룹별 집계를 한다.

```python
# 성별과 요일별 평균 팁 계산
mean_tip = df.groupby(["sex", "day"])["tip"].mean().reset_index()
```

이 결과는 여전히 길게 늘어진 표다. 이를 사람이 읽기 좋은 교차표 형태로 바꾸기 위해 `pivot`을 쓴다.

```python
pivot_table = mean_tip.pivot(index="sex", columns="day", values="tip")
```

쉽게 말하면 `groupby`는 기준별로 모아 계산하는 단계이고, `pivot`은 그 계산 결과를 보기 좋은 표 구조로 다시 펼치는 단계다.

💡 포인트

여기서 `reset_index()`가 중요한 이유는, `groupby` 결과가 기본적으로 그룹 컬럼을 인덱스로 올리기 때문이다. `pivot`으로 넘기기 전에 일반 컬럼 형태로 다시 풀어놓아야 다루기 편하다.

⚠️ 주의

- `groupby` 결과를 바로 `pivot`에 쓰기 전에 현재 구조가 인덱스인지 컬럼인지 확인해야 한다.
- `index`, `columns`, `values`에 어떤 컬럼을 둘지 헷갈리면 “행 기준, 열 기준, 칸에 들어갈 값” 순서로 다시 읽어보면 정리가 된다.

📌 핵심: `groupby`는 계산의 기준을 세우는 도구이고, `pivot`은 그 결과를 해석하기 쉬운 표로 바꾸는 도구다.

### 3.5 새로운 컬럼 만들기와 조건 필터링: 데이터 해석의 첫 단계

팁 비율은 `tip / total_bill`로 계산할 수 있다. 이처럼 기존 컬럼으로부터 새로운 의미 있는 지표를 만드는 것은 데이터 분석에서 매우 흔한 작업이다.

```python
# 기존 두 컬럼으로 새 지표를 만든다.
df["tip_percent"] = df["tip"] / df["total_bill"]

# 20% 이상 팁을 남긴 고객만 추린다.
high_tippers = df[df["tip_percent"] >= 0.2]
```

이 문제의 핵심은 새 컬럼을 만든 뒤 끝나는 것이 아니라, 그 컬럼을 다시 분석 조건으로 사용한다는 점이다. 즉, “계산 → 해석 → 필터링”의 최소 흐름을 보여준다.

⚠️ 주의

- 결과를 출력할 때 DataFrame 전체를 넣으면 행 전체가 출력된다. 개수를 출력하고 싶다면 `len(high_tippers)`나 `high_tippers.shape[0]`를 써야 한다.
- 비율 컬럼은 보통 0에서 1 사이로 해석한다. 20%라면 `0.2`다.

📌 핵심: 좋은 분석은 원본 컬럼을 그대로 보는 데서 끝나지 않고, 의미 있는 파생 컬럼을 만들어 해석을 확장한다.

### 3.6 melt: 넓은 표를 긴 표로 바꾸는 감각

`melt`는 처음에는 낯설지만, 실제 데이터 전처리에서 매우 자주 쓰인다. 목표는 여러 열에 나뉘어 있던 값을 “변수명 열 + 값 열” 형태로 길게 펴는 것이다.

과제에서는 `total_bill`과 `tip`을 길게 펴고, `size`는 그대로 식별자로 남긴다.

```python
melted = df.melt(
    id_vars="size",
    value_vars=["total_bill", "tip"],
    var_name="item",
    value_name="amount",
)
```

이 결과는 다음처럼 읽으면 된다.

- `size`는 어떤 행인지 구분하는 기준 열
- `item`은 원래 어떤 열에서 온 값인지 나타내는 열
- `amount`는 실제 수치 값

쉽게 말하면 `melt`는 “열 이름에 숨겨져 있던 의미를 행으로 꺼내는 과정”이다. 시각화나 그룹 분석 전에 long-format이 필요한 경우가 많아서 꼭 익숙해질 필요가 있다.

⚠️ 주의

- `id_vars`는 유지할 기준 열이고, `value_vars`는 세로로 펼칠 대상 열이다. 둘을 거꾸로 넣으면 완전히 다른 결과가 나온다.
- `melt` 후에는 행 수가 늘어난다. 원래 두 열을 세로로 붙였기 때문이다.

📌 핵심: `melt`는 데이터 값을 바꾸는 함수가 아니라, 데이터를 바라보는 형식을 바꾸는 함수다.

### 3.7 groupby 응용: 평균과 최댓값을 통해 패턴 찾기

마지막 문제는 앞서 만든 `tip_percent`를 다시 활용한다. 여기서는 두 가지 질문을 던진다.

1. 인원 수(`size`)에 따라 평균 팁 비율은 달라지는가?
2. 가장 높은 팁 비율을 남긴 고객은 누구인가?

```python
# 인원 수별 평균 팁 비율
size_group = df.groupby("size")["tip_percent"].mean()

# 팁 비율이 가장 높은 행 찾기
top_tipper = df.loc[df["tip_percent"].idxmax()]
```

`groupby().mean()`은 집단의 평균적 성향을 보는 데 적합하고, `idxmax()`는 전체에서 가장 큰 값을 가진 행의 위치를 찾는 데 적합하다. 둘을 나란히 써보면 “집단 경향”과 “개별 극단값”을 구분해서 읽는 감각이 생긴다.

⚠️ 주의

- `idxmax()`는 최댓값 자체가 아니라 최댓값이 있는 인덱스를 반환한다.
- `df.loc[...]`를 붙여야 실제 행 정보를 가져올 수 있다.

📌 핵심: 집계와 최댓값 탐색은 각각 전체 경향과 대표 사례를 찾는 서로 다른 읽기 방식이다.

## 4. 적용 관점에서 다시 보기

이 과제를 실전 감각으로 다시 묶어보면, 클래스 문제와 Pandas 문제는 다음 신호로 구분해 떠올릴 수 있다.

객체가 자기 상태를 오래 들고 있어야 하면 클래스 문제다. 소유자, 잔액, 거래 내역처럼 “하나의 대상이 가진 상태”가 계속 누적될 때는 클래스로 묶는 편이 자연스럽다. 반대로 여러 고객의 식사 정보처럼 많은 행을 한꺼번에 비교해야 하면 DataFrame 문제다.

구현 순서도 다르다.

클래스 문제에서는 먼저 속성을 정하고, 그다음 메서드 책임을 나누고, 마지막에 예외 상황에서 상태가 바뀌지 않도록 검증한다. Pandas 문제에서는 먼저 어떤 열이 필요한지 정하고, 조건으로 행을 줄이고, 그다음 그룹 기준을 세우고, 필요하면 표 형태를 바꾼다.

실전에서 자주 보는 신호는 다음과 같다.

- “입금, 출금, 기록, 현재 상태” → 클래스와 메서드 설계 신호
- “특정 컬럼만 보고 싶다” → 열 선택 신호
- “어떤 조건인 행만 남기고 싶다” → 불리언 인덱싱 신호
- “성별/요일별 평균” → `groupby` 신호
- “행과 열이 교차하는 표” → `pivot` 신호
- “여러 열을 하나의 값 열로 세로 정리” → `melt` 신호

🧠 기억할 것

문제를 보면 먼저 “대상 하나의 상태를 관리하는가, 아니면 표 전체를 변환하는가”를 구분하는 것만으로도 풀이 방향이 훨씬 빨리 잡힌다.

## 5. 배운 점 / 느낀 점 / 확장 포인트

이번 과제는 Python 문법이 실제 문제로 바뀌는 과정을 보여준다. 클래스 파트에서는 객체지향이 추상적인 개념이 아니라, 상태와 검증을 묶어두는 실용적인 설계 방식임을 확인할 수 있다. Pandas 파트에서는 열 선택과 필터링 같은 기초 조작이 결국 `groupby`, `pivot`, `melt` 같은 고급 조작으로 이어진다는 흐름이 잘 보인다.

확장 포인트도 뚜렷하다. 클래스 파트는 이후 상속, 예외 처리, 캡슐화로 넓어질 수 있고, Pandas 파트는 `merge`, `sort_values`, `apply`, `pivot_table`, 시각화로 이어질 수 있다. 특히 `tip_percent` 같은 파생 변수 생성은 실제 분석 프로젝트의 가장 기본적인 패턴이므로 꼭 자기 것으로 만들 필요가 있다.

## 6. 요약 정리

📌 핵심

- 클래스는 상태와 동작을 함께 묶는 구조다.
- 좋은 클래스는 잘못된 입력이 들어와도 상태를 보호한다.
- DataFrame 조작의 출발점은 열 선택과 행 필터링이다.
- `groupby`는 그룹별 계산, `pivot`은 보기 좋은 교차표 생성, `melt`는 long-format 변환이다.
- 파생 컬럼은 데이터를 더 해석 가능하게 만든다.

🧠 기억할 것

- 실패 시 상태를 바꾸지 않는 검증 로직이 중요하다.
- `df[["col1", "col2"]]`와 같이 여러 열은 리스트로 감싸 선택한다.
- `groupby` 결과는 종종 인덱스를 다시 풀기 위해 `reset_index()`가 필요하다.
- `idxmax()`는 위치를 돌려주고, `loc`와 함께 써야 실제 행을 가져온다.
