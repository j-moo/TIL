## 3. 본문 정리

### 3.1 기본 자료형: 값 하나를 정확히 다루는 힘

기본 자료형은 Python에서 가장 작은 단위의 출발점이다. 정수 `int`, 실수 `float`, 문자열 `str`, 참거짓 `bool`, 값이 비어 있음을 나타내는 `None`을 구분할 수 있어야 이후의 모든 코드가 읽힌다.

여기서 막히기 쉬운 지점은 “값”과 “값에 사용할 수 있는 기능”을 함께 보지 못하는 것이다. 예를 들어 숫자는 그냥 숫자가 아니라 `abs`, `round`, 거듭제곱 같은 연산과 연결되고, 문자열은 단순한 글자가 아니라 대소문자 변환, 이어 붙이기, 끝 문자 확인 같은 동작과 연결된다.

쉽게 말하면 자료형은 단순한 분류표가 아니라, “이 값으로 어떤 행동을 할 수 있는가”를 결정하는 기준이다.

```python
# 숫자 하나를 다루더라도, 그 값과 연결된 연산을 함께 이해해야 한다.
a = -3.14159

# 절댓값: 부호를 떼고 크기만 본다.
a_abs = abs(a)

# 반올림: 가장 가까운 정수로 보낸다.
a_rounded = round(a)

# 제곱: 같은 수를 두 번 곱한다.
a_squared = a ** 2
```

이 코드에서 중요한 점은 계산 결과 자체보다도 “어떤 문제에 어떤 연산을 붙일 것인가”를 감각적으로 익히는 데 있다. 예를 들어 거리 비교가 필요하면 절댓값을 떠올리고, 표현을 단순화해야 하면 반올림을 떠올리는 식이다.

문자열도 마찬가지다.

```python
s = "Hello World!"

# 대소문자 변환은 문자열 정규화의 가장 기본적인 예다.
s_lower = s.lower()
s_upper = s.upper()

# 문자열은 + 로 이어 붙일 수 있다.
s_double = s + s

# 특정 문자로 끝나는지 확인할 수 있다.
ends_with_exclamation = s.endswith("!")
```

문자열은 특히 데이터 전처리에서 자주 등장한다. 사용자 입력을 정리하거나, 파일명과 경로를 다루거나, 텍스트에서 패턴을 찾을 때 문자열 메서드가 기본 도구가 된다.

⚠️ 주의

- `round()`의 결과가 항상 `float`라고 생각하기 쉽지만, 인자를 어떻게 주느냐에 따라 결과 모양이 달라질 수 있다.
- 문자열은 수정 가능한 객체처럼 보이지만, 실제로는 새 문자열을 만들어 반환한다. 그래서 `s.lower()`를 호출했다고 원본 `s`가 바뀌는 것은 아니다.

📌 핵심: 자료형은 값을 분류하는 이름이 아니라, 그 값에 붙는 연산과 메서드를 이해하는 출발점이다.

### 3.2 컬렉션 자료형: 여러 값을 어떤 규칙으로 묶을 것인가

여러 데이터를 다뤄야 하는 순간부터는 자료구조 선택이 중요해진다. 실습에서는 `list`, `tuple`, `set`, `dict` 네 가지를 비교하면서, 각각이 어떤 상황에 맞는지 감을 잡게 한다.

#### 리스트와 튜플

리스트는 순서가 있고 수정 가능하다. 반면 튜플은 순서가 있지만 수정 불가능하다. 둘 다 인덱싱과 슬라이싱이 가능하지만, “바꿔도 되는 데이터인가”라는 점에서 역할이 갈린다.

```python
# 리스트는 변경 가능한 순서형 자료구조다.
l = [1, 2, 3, 4]
length = len(l)
has_1 = 1 in l
sublist_2_3 = l[1:3]

# 튜플은 변경 불가능한 순서형 자료구조다.
t = (1, 2, 3, 4)
length_t = len(t)
has_5 = 5 in t
subtuple_2_3 = t[1:3]
```

여기서 슬라이싱 `l[1:3]`이 왜 `[2, 3]`이 되는지 자주 헷갈린다. Python 슬라이싱은 시작 인덱스는 포함하고, 끝 인덱스는 포함하지 않는다. 이 규칙은 리스트뿐 아니라 문자열, 튜플, NumPy 배열에서도 이어진다.

#### 집합과 딕셔너리

집합 `set`은 순서가 없고 중복을 허용하지 않는다. 따라서 인덱싱을 기대하면 안 된다. 대신 포함 여부 확인이나 중복 제거, 집합 연산에 강하다.

딕셔너리 `dict`는 키와 값의 쌍으로 이루어진다. 값을 “순서”가 아니라 “이름표”로 찾는 구조라고 생각하면 이해가 쉽다.

```python
# 집합은 순서보다 '포함 여부'와 '중복 제거'에 초점이 있다.
s = {1, 2, 3, 4}
has_1 = 1 in s

# 딕셔너리는 키를 통해 값에 접근한다.
d = {
    1: "apple",
    2: "banana",
    3: "cheese",
}

keys = list(d.keys())
value_4 = d.get(4)   # 키가 없으면 오류 대신 None 반환
```

💡 포인트

같은 “여러 데이터 저장”이라도 질문이 달라지면 자료구조 선택도 달라진다.

- 순서대로 저장하고 싶다 → 리스트
- 한 번 정하면 바꾸지 않을 값이다 → 튜플
- 중복 제거가 필요하다 → 집합
- 이름표로 값을 찾고 싶다 → 딕셔너리

⚠️ 주의

- 집합은 인덱싱이 안 된다. `s[0]` 같은 접근은 불가능하다.
- 딕셔너리에서 없는 키를 바로 `d[4]`처럼 접근하면 오류가 날 수 있다. 안전하게 확인하려면 `get()`을 먼저 떠올리는 습관이 좋다.

📌 핵심: 컬렉션 자료형은 “여러 값을 저장하는 그릇”이 아니라, 데이터를 어떤 규칙으로 다룰지 결정하는 설계 선택이다.

### 3.3 제어문과 반복문: 코드에 흐름을 넣는 법

프로그램이 항상 한 방향으로만 흘러가면 현실 문제를 다룰 수 없다. 어떤 조건에서는 다르게 행동해야 하고, 어떤 작업은 여러 번 반복해야 한다. 이때 조건문과 반복문이 등장한다.

#### 조건문

```python
score = 85

if score >= 90:
    print("학점: A")
elif score >= 80:
    print("학점: B")
else:
    print("학점: D")
```

조건문은 “갈림길”이라고 생각하면 된다. 위에서부터 조건을 검사하다가 처음 참이 되는 가지로 들어간다. 그래서 순서가 중요하다. 더 넓은 조건을 먼저 써버리면 뒤 조건이 도달하지 못하는 경우가 생긴다.

#### 반복문과 `range`

```python
# 리스트를 순회할 때는 요소를 직접 받는 방식이 자연스럽다.
fruits = ["apple", "banana", "cherry"]
for fruit in fruits:
    print(fruit)

# 횟수를 기준으로 반복할 때는 range를 쓴다.
for i in range(2, 11, 2):
    print(i)
```

`range(start, stop, step)`는 “시작, 끝, 간격”으로 움직인다. 여기서 `stop`은 포함되지 않는다는 점이 가장 자주 틀리는 부분이다.

#### while, break, continue

`while`은 조건이 참인 동안 반복한다. 횟수가 정해지지 않은 반복에 적합하지만, 종료 조건을 놓치면 무한 루프가 되기 쉽다.

```python
count = 5
while count > 0:
    print(count)
    count -= 1   # 종료 방향으로 상태를 바꿔줘야 한다.
```

`break`는 반복 전체를 끊고, `continue`는 현재 반복만 건너뛴다. 둘의 차이를 분명히 구분해야 디버깅이 쉬워진다.

#### 리스트 컴프리헨션과 itertools

리스트 컴프리헨션은 반복과 조건을 더 간결하게 표현하는 방식이다.

```python
squares = [x ** 2 for x in range(10)]
even_numbers = [x for x in range(20) if x % 2 == 0]
```

강의는 여기서 한 걸음 더 나아가 `itertools.product`, `permutations`, `combinations`, `accumulate`까지 소개한다. 이 부분은 뒤의 완전탐색, 경우의 수, 누적 계산 문제와 바로 연결된다.

```python
from itertools import product, permutations, combinations, accumulate
import operator

pairs = list(product([1, 2], ["A", "B"]))
orders = list(permutations([1, 2, 3], 2))
choices = list(combinations([1, 2, 3], 2))
running_sum = list(accumulate([1, 2, 3, 4]))
running_mul = list(accumulate([1, 2, 3, 4], func=operator.mul))
```

⚠️ 주의

- `range(5)`가 1부터 5까지라고 착각하기 쉽다. 실제로는 0부터 4까지다.
- `while`에서는 조건만 쓰면 끝이 아니라, 조건을 바꾸는 코드가 반드시 함께 있어야 한다.
- 리스트 컴프리헨션은 짧다고 해서 항상 쉬운 것이 아니다. 조건이 복잡해지면 일반 `for` 문으로 풀어 써서 먼저 이해하는 편이 낫다.

📌 핵심: 제어문과 반복문은 문법 조각이 아니라, 문제를 절차로 바꾸는 핵심 도구다.

### 3.4 함수: 반복되는 절차에 이름을 붙이는 순간

함수는 특정 작업을 묶어 재사용할 수 있게 만드는 도구다. 같은 계산을 여러 번 하거나, 입력에 따라 결과를 돌려주는 로직이 있을 때 함수가 필요하다.

실습에서는 특히 문자열 안의 숫자를 합하는 함수가 좋은 예시로 등장한다.

```python
def sum_of_digits_in_string(s: str) -> int:
    # 결과를 누적할 변수다.
    result = 0

    # 문자열을 한 글자씩 순회한다.
    for ch in s:
        # 숫자 문자만 골라낸다.
        if ch.isdigit():
            # 문자이므로 int로 바꾼 뒤 더한다.
            result += int(ch)

    return result
```

이 함수가 좋은 이유는, 지금까지 배운 개념이 자연스럽게 모두 들어 있기 때문이다. 문자열 순회, 조건문, 누적 변수, 형변환, 반환값이 한 코드 안에서 연결된다.

⚠️ 주의

- `return`을 빼먹으면 함수는 계산을 했더라도 바깥에 값을 주지 못한다.
- 문자열 안의 숫자는 문자이므로 바로 더하면 안 된다. `int()` 변환이 필요하다.

📌 핵심: 함수는 단순히 코드를 줄이는 수단이 아니라, “이 작업은 하나의 의미 있는 절차다”라고 이름 붙이는 과정이다.

### 3.5 객체지향과 클래스: 데이터와 기능을 하나로 묶기

이 강의에서 클래스는 별도의 고급 문법으로 튀어나오지 않는다. 오히려 “관련 있는 데이터와 기능을 묶는다”는 아주 실용적인 관점에서 소개된다.

강아지 예시는 클래스가 왜 필요한지 가장 직관적으로 보여준다.

```python
class Dog:
    def __init__(self, name, breed):
        # 생성자에서 객체의 초기 상태를 저장한다.
        self.name = name
        self.breed = breed

    def bark(self):
        # 객체가 할 수 있는 동작은 메서드로 묶는다.
        print(f"{self.name}가 멍멍 짖습니다!")

    def __str__(self):
        # print(객체)를 했을 때 사람이 읽기 좋은 문자열을 돌려준다.
        return f"이름: {self.name}, 품종: {self.breed}"
```

여기서 `self`는 “이 메서드를 호출한 바로 그 객체 자신”을 가리킨다. 처음에는 문법처럼 보이지만, 실제로는 객체마다 다른 상태를 갖게 해주는 연결 고리다.

상속 예제도 중요한 의미가 있다. `Puppy(Dog)`처럼 부모 클래스를 기반으로 기능을 물려받고, 필요한 부분만 바꿀 수 있다는 점은 실제 라이브러리를 읽을 때 큰 도움이 된다.

학생 성적을 다루는 `Student` 클래스는 조금 더 실전적인 구조다.

```python
from typing import List, Tuple

class Student:
    def __init__(self, name: str, korean: int, english: int, math: int) -> None:
        self.name = name
        self.korean = korean
        self.english = english
        self.math = math

    def get_total(self) -> int:
        # 여러 속성을 이용해 총점을 계산한다.
        return self.korean + self.english + self.math

    def get_average(self) -> float:
        # 이미 만든 메서드를 다시 활용하면 중복을 줄일 수 있다.
        return self.get_total() / 3


def check_pass(student: Student) -> str:
    if student.get_average() >= 75:
        return "합격"
    return "불합격"


def analyze_students(students: List[Student], threshold: int) -> Tuple[List[str], List[str]]:
    passed = []
    excellent = []

    for student in students:
        if check_pass(student) == "합격":
            passed.append(student.name)
        if student.get_total() >= threshold:
            excellent.append(student.name)

    return passed, excellent
```

이 코드는 클래스가 단지 객체 하나를 만드는 데서 끝나지 않고, 이후 함수와 결합해 여러 객체를 분석하는 흐름으로 이어진다는 점을 잘 보여준다.

💡 포인트

NumPy 배열도, Pandas DataFrame도 결국은 객체다. 즉, 클래스 문법을 배우는 것은 단순히 사용자 정의 클래스를 만들기 위해서만이 아니라, 라이브러리 객체의 메서드를 자연스럽게 읽기 위한 준비이기도 하다.

⚠️ 주의

- `self`를 빼먹으면 메서드 정의가 깨진다.
- `__init__` 안에서 `self.name = name`처럼 속성 저장을 하지 않으면 객체 상태가 남지 않는다.
- 클래스 밖 함수와 클래스 안 메서드의 역할을 구분해야 한다. 무엇이 객체의 책임이고, 무엇이 외부 분석 로직인지 구분하는 감각이 중요하다.

📌 핵심: 클래스는 복잡한 문법이 아니라, 관련된 값과 행동을 함께 묶는 설계 방식이다.

### 3.6 NumPy: 숫자 데이터를 배열로 다루는 방식

NumPy는 Python 리스트를 대체하는 것이 아니라, 수치 계산에 특화된 배열 연산 도구다. AI와 데이터 분석에서 NumPy가 중요한 이유는, 숫자 데이터를 빠르고 일관된 형태로 다룰 수 있기 때문이다.

실습에서는 배열 생성, 모양 확인, 자료형 변환, 행렬곱, 복제와 펼치기 같은 기본 조작을 통해 NumPy의 핵심 감각을 익힌다.

```python
import numpy as np

# 단위행렬 생성
x = np.eye(3)

# 표준정규분포 난수로 3x3 배열 생성
y = np.random.randn(3, 3)

# 특정 위치 값 수정: [행, 열] 인덱싱 사용
x[0, 2] = 1

# 행렬곱
z = x @ y

# 자료형 변환
x_bool = x.astype(bool)
```

여기서 중요한 점은, 리스트의 중첩 구조와 달리 NumPy는 처음부터 “배열의 모양(shape)”을 강하게 의식한다는 점이다. `(3,)`, `(3, 3)`, `(9,)` 같은 shape 정보는 이후 선형대수와 머신러닝 코드에서 계속 등장한다.

두 번째 실습은 벡터 복제와 펼치기를 다룬다.

```python
v = np.array([1, 2, 3])

# 같은 벡터를 3행으로 복제해 행렬 생성
V = np.tile(v, (3, 1))

# 2차원 배열을 1차원으로 펼치기
V_vector = V.flatten()
```

이 코드는 데이터가 행렬에서 벡터로 바뀌는 흐름, 즉 차원이 달라질 때 shape이 어떻게 변하는지 감각적으로 익히게 해준다.

⚠️ 주의

- `*`와 `@`를 혼동하기 쉽다. NumPy에서 `*`는 원소별 곱이고, `@`는 행렬곱이다.
- `(3,)`와 `(3, 1)`은 전혀 다른 shape이다. 겉보기 값이 같아 보여도 계산 결과가 달라질 수 있다.
- 인덱싱은 0부터 시작한다. `1행 3열`을 사람 기준으로 생각하다가 `x[1, 3]`처럼 쓰면 범위를 벗어나기 쉽다.

📌 핵심: NumPy는 숫자 여러 개를 저장하는 도구가 아니라, shape를 가진 배열을 일관되게 계산하는 도구다.

### 3.7 Pandas: 실제 표 데이터를 읽고 조작하는 문법

Pandas는 NumPy 위에서 돌아가지만, 목표가 다르다. NumPy가 숫자 배열 계산에 강하다면, Pandas는 행과 열이 있는 실제 데이터 테이블을 다루는 데 강하다.

실습은 먼저 `Series`와 `DataFrame`의 차이를 보여준다. `Series`는 1차원이고, `DataFrame`은 여러 `Series`가 모인 2차원 표 구조다.

```python
import pandas as pd

ages = pd.Series([25, 30, 28, 35])

# 딕셔너리 기반 DataFrame 생성
_df = {
    "Name": ["Alice", "Bob", "Charlie"],
    "Age": [25, 30, 35],
    "Score": [85.5, 90.3, 78.9],
}

df = pd.DataFrame(_df)
```

강의에서 특히 좋은 포인트는 “어떤 함수가 무엇을 반환하는가”를 의식하게 한다는 점이다. `df.info()`는 화면에 출력하고 `None`을 반환하지만, `df.describe()`는 새로운 DataFrame을 반환한다. 이 차이를 놓치면 초반 Pandas 코드가 매우 헷갈린다.

```python
# DataFrame 기본 탐색
print(df.info())         # 정보 출력, 반환값은 None
print(df.describe())     # 통계 요약 DataFrame 반환
print(df.shape)          # (행, 열) 튜플
print(df.columns.tolist())
print(df.head(2))

# 선택과 접근
age_series = df["Age"]
row0_by_iloc = df.iloc[0]
row0_by_loc = df.loc[0]
subset = df[["Name", "Score"]]
```

이후 실습은 같은 DataFrame을 여러 방식으로 만드는 연습까지 이어진다. `List[Dict]`, `List[List]`, `numpy.ndarray`에서 DataFrame을 만들 수 있다는 점은, 실제 데이터를 어디서 받아오든 결국 표 구조로 바꿔 다룰 수 있다는 감각을 준다.

⚠️ 주의

- `df["Age"]`는 Series이고, `df[["Age"]]`는 DataFrame이다. 대괄호 개수 차이가 반환 타입 차이로 이어진다.
- `info()`처럼 출력용 함수와 `describe()`처럼 반환값이 있는 함수를 혼동하면 변수를 잘못 저장하게 된다.
- `loc`는 라벨 기반, `iloc`는 정수 위치 기반이라는 차이를 초반에 확실히 잡아두는 편이 좋다.

📌 핵심: Pandas는 표 데이터를 읽는 도구가 아니라, 탐색·선택·변환·집계를 하나의 문법으로 묶어주는 작업 환경이다.

## 4. 적용 관점에서 다시 보기

이 실습을 문제풀이 관점에서 다시 보면, 결국 다음 질문에 답하는 과정이다.

먼저 값 하나를 다룰 때는 자료형을 보고 어떤 메서드와 연산을 쓸지 떠올려야 한다. 여러 값을 다룰 때는 자료구조를 먼저 고른다. 그다음에는 조건문과 반복문으로 절차를 만든다. 이 절차가 반복되면 함수로 묶고, 데이터와 기능이 함께 움직여야 하면 클래스로 묶는다. 그리고 수치 계산이 많아지면 NumPy, 표 형식 데이터가 등장하면 Pandas로 넘어간다.

실전에서는 다음 신호를 보면 빠르게 연결할 수 있다.

- “여러 학생의 점수”가 보이면 리스트와 반복문, 혹은 클래스 구조를 떠올린다.
- “중복 제거”가 필요하면 집합을 먼저 생각한다.
- “키로 값 찾기”가 필요하면 딕셔너리를 떠올린다.
- “배열 shape, 행렬곱, 타입 변환”이 보이면 NumPy 신호다.
- “열 선택, 행 필터링, 통계 요약, 표 재구성”이 보이면 Pandas 신호다.

구현 순서도 비교적 일정하다. 입력 자료형을 확인하고, 필요한 자료구조를 선택한 뒤, 반복과 조건으로 처리하고, 자주 쓰는 절차를 함수로 분리한다. 데이터의 성격이 더 복잡해지면 객체나 DataFrame으로 표현을 바꾼다.

🧠 기억할 것

문제를 풀 때는 문법 이름을 떠올리는 것보다 “지금 필요한 데이터 표현이 무엇인가”를 먼저 묻는 편이 훨씬 강하다.

## 5. 배운 점 / 느낀 점 / 확장 포인트

이번 실습에서 가장 큰 수확은 Python 문법이 따로 흩어져 있는 것이 아니라는 점이다. 자료형, 반복문, 함수, 클래스는 서로 다른 장이 아니라 하나의 흐름 위에 놓여 있다. 특히 클래스 파트가 NumPy와 Pandas 이해로 연결된다는 점은 초반 학습에서 자주 놓치기 쉽지만, 실제로는 매우 중요하다.

확장 포인트도 분명하다. 여기서 한 단계 더 나아가면 문자열 전처리, 파일 입출력, 예외 처리, 정렬과 람다, NumPy 브로드캐스팅, Pandas의 `groupby`, `merge`, `pivot_table`로 이어질 수 있다. 즉, 이 강의는 끝이 아니라 이후 데이터 분석과 머신러닝 실습의 기초 체력을 만드는 단계다.
