데이터가 하나씩 따로 존재할 때는 단일 모델만으로도 충분하다. 하지만 실제 서비스에서는 데이터가 서로 연결된다. 댓글은 어떤 게시글에 달렸는지 알아야 하고, 주문은 어떤 사용자에게 속하는지 알아야 한다. 이런 연결을 모델에 표현하지 않으면 데이터를 조회할 때마다 기준이 흐려진다.

N:1 관계는 여러 객체가 하나의 객체에 속하는 구조다. 댓글 여러 개가 게시글 하나에 속하는 상황이 가장 대표적이다.

## 2. 핵심 개념 정리

N:1 관계에서는 N 쪽 모델이 1 쪽 모델을 참조한다. Django에서는 이 참조를 `ForeignKey` 필드로 표현한다.

댓글과 게시글을 예로 들면 댓글이 N, 게시글이 1이다. 하나의 게시글에는 여러 댓글이 달릴 수 있지만, 댓글 하나는 보통 하나의 게시글에만 속한다. 그래서 `Comment` 모델에 `article = models.ForeignKey(...)`를 둔다.

관계가 만들어지면 두 방향으로 조회할 수 있다.

- 정참조: 댓글에서 자신이 속한 게시글을 조회한다.
- 역참조: 게시글에서 자신에게 달린 댓글들을 조회한다.

이 두 방향을 함께 이해해야 N:1 관계를 실제 화면에서 자연스럽게 사용할 수 있다.

## 3. 본문 정리

### 3.1 N:1 관계는 N 쪽에 외래 키를 둔다

관계형 데이터베이스에서는 다른 테이블의 기본 키를 저장해 관계를 표현한다. Django 모델에서는 이를 `ForeignKey`로 작성한다.

```python
# articles/models.py

from django.db import models


class Article(models.Model):
    title = models.CharField(max_length=100)
    content = models.TextField()


class Comment(models.Model):
    # 댓글은 하나의 게시글에 속한다.
    # 그래서 N 쪽인 Comment가 1 쪽인 Article을 참조한다.
    article = models.ForeignKey(
        Article,
        on_delete=models.CASCADE,
    )
    content = models.CharField(max_length=200)
    created_at = models.DateTimeField(auto_now_add=True)
```

`ForeignKey`의 첫 번째 인자는 참조할 모델이다. `on_delete=models.CASCADE`는 참조 대상 게시글이 삭제될 때 그 게시글에 달린 댓글도 함께 삭제한다는 의미다.

⚠️ 주의: 외래 키는 보통 "부모가 자식을 가진다"는 느낌으로 생각하기 쉽지만, 실제 필드는 자식 쪽에 둔다. 댓글이 게시글을 가리켜야 하므로 `Comment`에 `article` 필드가 들어간다.

### 3.2 정참조는 외래 키 필드로 바로 접근한다

정참조는 외래 키를 가진 객체에서 참조 대상 객체로 이동하는 것이다.

```python
comment = Comment.objects.get(pk=1)

# comment가 속한 게시글을 조회한다.
article = comment.article

print(article.title)
```

`Comment` 모델에 `article` 필드를 만들었기 때문에, 댓글 인스턴스에서 `comment.article`로 게시글을 바로 가져올 수 있다. 이 방향은 필드 이름이 명확해서 비교적 이해하기 쉽다.

### 3.3 역참조는 related manager로 조회한다

역참조는 1 쪽 객체에서 자신을 참조하는 N 쪽 객체들을 조회하는 것이다. 게시글에서 댓글 목록을 가져오는 상황이 여기에 해당한다.

```python
article = Article.objects.get(pk=1)

# 이 게시글을 참조하는 모든 댓글을 조회한다.
comments = article.comment_set.all()
```

`comment_set`은 Django가 기본으로 만들어 주는 related manager다. `Comment` 모델이 `Article`을 참조하므로, Article 인스턴스 입장에서는 자신과 연결된 Comment들을 `comment_set`으로 조회할 수 있다.

이 흐름은 게시글 상세 페이지에서 자주 사용된다.

```python
# articles/views.py

from django.shortcuts import get_object_or_404, render
from .models import Article


def detail(request, article_pk):
    article = get_object_or_404(Article, pk=article_pk)
    comments = article.comment_set.all()

    context = {
        'article': article,
        'comments': comments,
    }
    return render(request, 'articles/detail.html', context)
```

### 3.4 댓글을 저장할 때는 어떤 게시글에 속하는지 함께 지정한다

댓글을 새로 만들 때는 내용만 저장하면 부족하다. 반드시 어떤 게시글의 댓글인지 연결해야 한다.

```python
# articles/views.py

from django.shortcuts import get_object_or_404, redirect
from .forms import CommentForm
from .models import Article


def comments_create(request, article_pk):
    article = get_object_or_404(Article, pk=article_pk)
    comment_form = CommentForm(request.POST)

    if comment_form.is_valid():
        # commit=False는 아직 DB에 저장하지 않고 인스턴스만 만든다.
        comment = comment_form.save(commit=False)

        # 저장하기 전에 어떤 게시글에 속한 댓글인지 연결한다.
        comment.article = article
        comment.save()

    return redirect('articles:detail', article.pk)
```

`commit=False`는 form이 만든 객체를 잠시 멈춰 세우는 역할을 한다. 댓글 내용은 form에서 받지만, `article` 정보는 URL의 `article_pk`로 찾은 객체를 직접 넣어야 한다.

📌 핵심: N:1 생성 로직에서는 form에 없는 관계 필드를 view에서 채워 넣는 경우가 많다.

## 4. 적용 관점에서 다시 보기

N:1 관계를 만나면 먼저 "여러 개가 하나에 속하는가"를 확인한다. 댓글 여러 개가 게시글 하나에 속하고, 게시글 여러 개가 사용자 하나에 속한다면 N:1 관계다.

그다음 외래 키를 어느 모델에 둘지 정한다. 답은 N 쪽이다. 댓글-게시글 관계에서는 댓글이 N이므로 `Comment.article`을 만든다.

조회할 때는 방향을 구분한다. 댓글에서 게시글로 가면 정참조이고, 게시글에서 댓글 목록으로 가면 역참조다. 이 방향을 헷갈리지 않으면 view와 template 코드가 훨씬 안정적으로 읽힌다.

## 5. 배운 점 / 확장 포인트

### 5.1 이번 강의 이전에 몰랐던 것 또는 새로 이해된 것

N:1 관계에서는 관계를 소유하는 느낌의 부모 모델이 아니라, 실제로 참조 값을 저장해야 하는 자식 모델에 외래 키를 둔다는 점이 중요하다.

### 5.2 앞으로 이어지는 연결점

N:1 관계는 사용자 인증과 연결되면 더 자주 등장한다. 게시글 작성자, 댓글 작성자처럼 여러 콘텐츠가 하나의 사용자에게 속하는 구조로 확장된다.

### 5.3 더 파볼 만한 주제

`related_name`을 사용하면 기본 역참조 이름인 `comment_set`을 더 읽기 좋은 이름으로 바꿀 수 있다. 프로젝트 규모가 커질수록 역참조 이름 설계가 코드 가독성에 큰 영향을 준다.

## 6. 요약 정리

N:1 관계는 여러 객체가 하나의 객체에 속하는 관계다. Django에서는 N 쪽 모델에 `ForeignKey`를 두어 이 관계를 표현한다.

🧠 기억할 것:

- N:1 관계의 외래 키는 N 쪽 모델에 둔다.
- 정참조는 외래 키 필드로 참조 대상에 접근하는 것이다.
- 역참조는 1 쪽 객체에서 연결된 N 쪽 객체들을 조회하는 것이다.
- 기본 역참조 이름은 `모델명소문자_set` 형태다.
- form으로 저장할 때 관계 필드가 form에 없다면 `commit=False` 후 view에서 채운다.
