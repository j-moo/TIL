## 2. 핵심 개념 정리

좋아요 관계에서는 게시글이 여러 사용자에게 좋아요를 받을 수 있고, 사용자는 여러 게시글에 좋아요를 누를 수 있다. 이 관계는 `Article.like_users`처럼 표현할 수 있다.

팔로우 관계에서는 사용자 한 명이 여러 사용자를 팔로우할 수 있고, 사용자 한 명도 여러 사용자에게 팔로우될 수 있다. 모델이 양쪽 모두 User이므로 자기 자신을 참조하는 N:M 관계가 된다.

Django에서는 자기 자신과의 N:M 관계를 `ManyToManyField('self')`로 표현한다. 이때 팔로우는 서로 자동으로 연결되는 친구 관계가 아니므로 `symmetrical=False`를 사용한다.

## 3. 본문 정리

### 3.1 좋아요 관계는 사용자와 게시글의 N:M이다

좋아요 기능은 N:M 관계의 가장 기본적인 실습 예시다.

```python
# articles/models.py

class Article(models.Model):
    user = models.ForeignKey(
        settings.AUTH_USER_MODEL,
        on_delete=models.CASCADE,
        related_name='articles',
    )
    like_users = models.ManyToManyField(
        settings.AUTH_USER_MODEL,
        related_name='like_articles',
    )
    title = models.CharField(max_length=100)
    content = models.TextField()
```

이 구조에서 조회 방향은 두 가지다.

```python
article.like_users.all()   # 이 게시글을 좋아요한 사용자들
user.like_articles.all()   # 이 사용자가 좋아요한 게시글들
```

버튼을 누르면 관계를 토글한다.

```python
if article.like_users.filter(pk=request.user.pk).exists():
    article.like_users.remove(request.user)
else:
    article.like_users.add(request.user)
```

이 코드는 다음 강의의 Ajax 좋아요 구현에서도 그대로 기반이 된다. 차이는 동기 방식에서는 redirect를 반환하고, Ajax 방식에서는 JSON을 반환한다는 점이다.

### 3.2 팔로우 관계는 User와 User 사이의 N:M이다

팔로우는 사용자와 사용자 사이의 관계다. 예를 들어 A가 B를 팔로우한다고 해서 B가 자동으로 A를 팔로우하는 것은 아니다. 방향이 있는 관계다.

```python
# accounts/models.py

from django.conf import settings
from django.contrib.auth.models import AbstractUser
from django.db import models


class User(AbstractUser):
    followings = models.ManyToManyField(
        'self',
        symmetrical=False,
        related_name='followers',
    )
```

`followings`는 내가 팔로우하는 사람들이다. `followers`는 나를 팔로우하는 사람들이다.

```python
request.user.followings.all()  # 내가 팔로우하는 사용자들
person.followers.all()         # person을 팔로우하는 사용자들
```

`symmetrical=False`는 관계를 단방향으로 만들기 위해 필요하다. A가 B를 팔로우해도 B가 A를 자동으로 팔로우하지 않아야 하기 때문이다.

⚠️ 주의: 팔로우는 친구 추가처럼 서로 연결되는 관계가 아니다. 방향이 있으므로 `symmetrical=False`를 빼먹으면 의도와 다른 관계가 될 수 있다.

### 3.3 팔로우 토글 view는 자기 자신을 제외해야 한다

사용자는 자기 자신을 팔로우할 필요가 없다. 그래서 view에서 대상 사용자와 현재 사용자가 같은지 먼저 확인한다.

```python
# accounts/views.py

from django.contrib.auth import get_user_model
from django.contrib.auth.decorators import login_required
from django.shortcuts import get_object_or_404, redirect


@login_required
def follow(request, user_pk):
    target_user = get_object_or_404(get_user_model(), pk=user_pk)

    if request.user != target_user:
        if target_user.followers.filter(pk=request.user.pk).exists():
            target_user.followers.remove(request.user)
        else:
            target_user.followers.add(request.user)

    return redirect('accounts:profile', target_user.username)
```

여기서 `target_user.followers.add(request.user)`는 "대상 사용자의 팔로워 목록에 현재 사용자를 추가한다"는 뜻이다. 같은 동작을 `request.user.followings.add(target_user)`로 표현할 수도 있다. 두 표현은 바라보는 방향이 다를 뿐 같은 관계를 다룬다.

📌 핵심: 팔로우 관계에서는 followings와 followers의 방향을 문장으로 읽어야 헷갈리지 않는다.

### 3.4 프로필 페이지에서는 팔로잉과 팔로워 수를 함께 보여준다

관계가 만들어지면 프로필 페이지에서 팔로잉 수와 팔로워 수를 보여줄 수 있다.

```html
<p>
  팔로잉 {{ person.followings.count }}
  /
  팔로워 {{ person.followers.count }}
</p>

{% if request.user != person %}
  <form action="{% url 'accounts:follow' person.pk %}" method="POST">
    {% csrf_token %}

    {% if request.user in person.followers.all %}
      <button type="submit">언팔로우</button>
    {% else %}
      <button type="submit">팔로우</button>
    {% endif %}
  </form>
{% endif %}
```

여기서 버튼 조건은 "현재 사용자가 이 사람의 팔로워 목록에 있는가"로 판단한다. 내가 그 사람을 팔로우했다면, 그 사람 입장에서는 내가 follower다.

### 3.5 N:M 관계는 Ajax 토글과 잘 어울린다

좋아요와 팔로우는 둘 다 관계를 추가하거나 제거하는 토글 기능이다. 사용자는 버튼을 누르고 즉시 상태가 바뀌기를 기대한다. 그래서 N:M 관계는 Ajax와 자주 연결된다.

동기 방식에서는 관계를 바꾼 뒤 redirect를 반환한다.

```python
return redirect('accounts:profile', target_user.username)
```

비동기 방식에서는 관계를 바꾼 뒤 현재 상태를 JSON으로 반환한다.

```python
return JsonResponse({
    'is_followed': is_followed,
    'followers_count': target_user.followers.count(),
    'followings_count': target_user.followings.count(),
})
```

이렇게 서버가 현재 관계 상태를 알려주면 JavaScript는 버튼 문구와 숫자를 즉시 바꿀 수 있다.

## 4. 적용 관점에서 다시 보기

N:M 관계를 적용할 때는 먼저 관계의 방향을 문장으로 풀어야 한다.

좋아요는 "사용자가 게시글을 좋아요한다"와 "게시글이 사용자들에게 좋아요를 받는다"라는 양방향 문장이 모두 자연스럽다. 팔로우는 "내가 누군가를 팔로우한다"와 "누군가가 나를 팔로우한다"라는 방향이 중요하다.

구현할 때는 다음 순서를 따르면 좋다.

1. 관계가 N:M인지 확인한다.
2. 필드 이름을 관계의 의미에 맞게 정한다.
3. 역참조 이름을 `related_name`으로 명확하게 정한다.
4. 자기 자신과의 관계라면 `ManyToManyField('self')`를 사용한다.
5. 방향이 있는 관계라면 `symmetrical=False`를 설정한다.
6. add/remove로 토글 로직을 만든다.
7. 화면에서는 현재 관계 여부에 따라 버튼 상태를 나눈다.

## 5. 배운 점 / 확장 포인트

### 5.1 이번 강의 이전에 몰랐던 것 또는 새로 이해된 것

N:M 관계는 단순히 "여러 개와 여러 개가 연결된다"에서 끝나지 않는다. 팔로우처럼 같은 모델끼리 연결될 수도 있고, 이때는 관계의 방향을 명확히 설계해야 한다.

### 5.2 앞으로 이어지는 연결점

팔로우와 좋아요는 Ajax와 결합하기 좋은 기능이다. 관계를 토글한 뒤 JSON으로 현재 상태와 카운트를 반환하면, 페이지 새로고침 없이 UI를 갱신할 수 있다.

### 5.3 더 파볼 만한 주제

팔로우 관계에 생성 시각이나 차단 상태 같은 추가 정보가 필요하면 자동 중개 테이블 대신 `through` 모델을 직접 설계할 수 있다. 소셜 기능이 복잡해질수록 중개 모델 설계가 중요해진다.

## 6. 요약 정리

좋아요는 사용자와 게시글의 N:M 관계이고, 팔로우는 사용자와 사용자 사이의 N:M 관계다. 특히 팔로우는 방향이 있는 자기참조 관계이므로 `symmetrical=False`와 명확한 `related_name`이 중요하다.

🧠 기억할 것:

- 좋아요는 `Article`과 `User` 사이의 N:M 관계다.
- 팔로우는 `User`와 `User` 사이의 자기참조 N:M 관계다.
- `followings`는 내가 팔로우하는 사람들이다.
- `followers`는 나를 팔로우하는 사람들이다.
- 방향이 있는 자기참조 관계에는 `symmetrical=False`가 필요하다.
- N:M 토글은 Ajax와 결합하면 사용자 경험이 좋아진다.
