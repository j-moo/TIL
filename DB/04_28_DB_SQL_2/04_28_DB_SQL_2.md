# DB SQL 2 - 테이블 관리, 데이터 조작, JOIN

- 🎯 글의 목표: SQL에서 테이블을 만들고 수정하는 방법, 데이터를 추가·수정·삭제하는 방법, 그리고 여러 테이블을 연결해 조회하는 JOIN의 흐름을 이해한다.
- 🧩 핵심 키워드: `CREATE TABLE`, `PRAGMA`, `ALTER TABLE`, `DROP TABLE`, `INSERT`, `UPDATE`, `DELETE`, `INNER JOIN`, `LEFT JOIN`, `CONSTRAINT`, `Type Affinity`
- ⭐ 중요도: ★★★★★  
  데이터베이스 기초 문법이면서, Django ORM이나 DRF 프로젝트에서 모델과 테이블 구조를 이해하는 바탕이 된다.
- 📝 한눈에 보는 내용:  
  이번 강의는 **테이블 구조 관리 → 데이터 조작 → 여러 테이블 연결 조회 → SQLite의 타입 처리 특징** 순서로 이어진다.
- 🔗 관련 문제 / 주제: SQL 기본 문법, 데이터베이스 설계, 게시판 사용자-게시글 관계, 외래 키, JOIN 조회

## 1. 들어가며

SQL을 처음 배울 때는 `SELECT`로 데이터를 조회하는 문법이 가장 먼저 눈에 들어온다. 하지만 실제로 데이터베이스를 다루려면 조회만으로는 부족하다. 데이터를 담을 **테이블을 만들고**, 필요하면 **테이블 구조를 수정하고**, 그 안에 데이터를 **추가·수정·삭제**할 수 있어야 한다.

이번 강의는 그 흐름을 한 번에 정리한다. 먼저 `CREATE TABLE`로 테이블을 만드는 법을 배우고, `ALTER TABLE`로 이미 만들어진 테이블의 구조를 바꾸는 방법을 본다. 그 다음 `INSERT`, `UPDATE`, `DELETE`를 통해 데이터를 직접 조작하고, 마지막에는 게시글과 사용자처럼 서로 관련된 여러 테이블을 `JOIN`으로 연결해 조회하는 방법까지 다룬다.

여기서 중요한 점은 SQL 문법을 하나씩 외우는 것보다, **테이블 구조와 데이터 흐름이 어떻게 이어지는지**를 이해하는 것이다. 테이블을 잘 만들지 못하면 데이터 조작이 불편해지고, 테이블 관계를 이해하지 못하면 JOIN이 갑자기 복잡하게 느껴진다. 따라서 이번 정리는 문법을 단순 나열하지 않고, 각각의 명령이 어떤 상황에서 필요한지 함께 연결해서 본다.

## 2. 핵심 개념 정리

이번 강의의 큰 흐름은 다음과 같다.

| 흐름 | 주요 명령 | 핵심 질문 |
|---|---|---|
| 테이블 생성 | `CREATE TABLE` | 어떤 컬럼과 제약 조건으로 테이블을 만들 것인가? |
| 테이블 구조 확인 | `PRAGMA table_info()` | 현재 테이블은 어떤 구조를 가지고 있는가? |
| 테이블 구조 수정 | `ALTER TABLE` | 이미 만든 테이블에 컬럼을 추가·삭제하거나 이름을 바꿀 수 있는가? |
| 테이블 삭제 | `DROP TABLE` | 더 이상 필요 없는 테이블을 제거할 수 있는가? |
| 데이터 조작 | `INSERT`, `UPDATE`, `DELETE` | 테이블 안의 레코드를 어떻게 추가·수정·삭제할 것인가? |
| 테이블 관계 | `FOREIGN KEY`, `JOIN` | 나누어진 테이블을 어떤 기준으로 다시 연결할 것인가? |
| SQLite 특징 | Type Affinity, 날짜/시간 처리 | SQLite는 타입과 날짜를 어떻게 다루는가? |

이 흐름을 보면 SQL은 크게 두 층으로 나눠서 이해할 수 있다.

첫 번째는 **테이블 구조를 관리하는 문법**이다. `CREATE`, `ALTER`, `DROP`처럼 테이블의 형태 자체를 만들거나 바꾸는 명령이 여기에 들어간다. 이 단계에서는 컬럼 이름, 데이터 타입, 제약 조건을 정확히 정하는 것이 중요하다.

두 번째는 **테이블 안의 데이터를 다루는 문법**이다. `INSERT`, `UPDATE`, `DELETE`, `SELECT`가 여기에 해당한다. 테이블 구조가 준비되었다면, 이제 실제 레코드를 넣고 바꾸고 지우며 조회하는 작업을 하게 된다.

마지막으로 여러 테이블이 등장하면 `JOIN`이 필요해진다. 게시글 테이블과 사용자 테이블을 따로 관리하면 중복은 줄어들지만, 화면에 보여줄 때는 게시글 제목과 작성자 이름을 함께 보여줘야 한다. 이때 두 테이블을 다시 연결하는 문법이 JOIN이다.

## 3. 본문 정리

이 장에서는 강의 흐름에 맞춰 SQL 문법을 하나씩 정리한다. 개념을 설명한 뒤 바로 예시, 이미지, 코드, 실수 포인트를 함께 배치해서 복습할 때 흐름이 끊기지 않도록 구성한다.

### 3.1 `CREATE TABLE`로 테이블 만들기

`CREATE TABLE`은 데이터베이스 안에 새로운 테이블을 만드는 명령이다. 테이블을 만들 때는 단순히 이름만 정하는 것이 아니라, 어떤 컬럼을 둘지, 각 컬럼의 데이터 타입은 무엇인지, 어떤 제약 조건을 걸 것인지까지 함께 정한다.

기본 문법은 다음과 같다.

```sql
CREATE TABLE table_name (
    column_1 data_type constraints,
    column_2 data_type constraints,
    ...
);
```

여기서 `table_name`은 만들 테이블 이름이고, 괄호 안에는 컬럼 정의가 들어간다. 각 컬럼은 보통 **컬럼 이름 → 데이터 타입 → 제약 조건** 순서로 작성한다.

예를 들어 `examples` 테이블을 만든다면 다음과 같이 작성할 수 있다.

```sql
CREATE TABLE examples (
    ExamId INTEGER PRIMARY KEY AUTOINCREMENT,
    LastName VARCHAR(50) NOT NULL,
    FirstName VARCHAR(50) NOT NULL
);
```

- `ExamId`는 각 레코드를 구분하는 기본 키이다.
- `INTEGER PRIMARY KEY AUTOINCREMENT`는 정수형 기본 키를 자동 증가시키겠다는 의미이다.
- `LastName`, `FirstName`은 최대 50자 문자열이며, `NOT NULL`이 붙어 있으므로 반드시 값이 들어가야 한다.

![alt text](<../assets/images/04_28_DB_SQL_2/화면 캡처 2026-05-10 195202.png>)

위 화면은 `examples` 테이블이 생성된 뒤 컬럼 구조가 표시된 모습이다. 테이블이 만들어지면 데이터베이스 도구에서 컬럼 목록과 타입을 확인할 수 있다.

⚠️ 주의할 점은 마지막 컬럼 뒤에는 쉼표를 붙이지 않는 것이다. SQL에서는 컬럼 정의를 나열할 때 중간에는 쉼표가 필요하지만, 마지막 컬럼 뒤에 쉼표를 남기면 문법 오류가 발생할 수 있다.

📌 핵심: `CREATE TABLE`은 테이블 이름, 컬럼 이름, 데이터 타입, 제약 조건을 한 번에 정의하는 문법이다.

### 3.2 `PRAGMA table_info()`로 테이블 구조 확인하기

테이블을 만들었다면 실제로 원하는 구조로 생성되었는지 확인해야 한다. SQLite에서는 `PRAGMA table_info()`를 사용해 테이블의 schema, 즉 구조 정보를 확인할 수 있다.

```sql
PRAGMA table_info('examples');
```

![alt text](<../assets/images/04_28_DB_SQL_2/화면 캡처 2026-05-10 195353.png>)

결과에는 각 컬럼의 정보가 행 단위로 출력된다.

| 항목 | 의미 |
|---|---|
| `cid` | 컬럼 ID, 즉 컬럼의 순서 또는 식별 번호 |
| `name` | 컬럼 이름 |
| `type` | 컬럼 데이터 타입 |
| `notnull` | `NOT NULL` 제약 여부 |
| `dflt_value` | 기본값 |
| `pk` | 기본 키 여부 |

여기서 `cid`는 직접 사용하는 값이라기보다, SQLite가 테이블 구조를 보여줄 때 각 컬럼을 구분하기 위해 제공하는 메타데이터에 가깝다.

💡 포인트: `PRAGMA`는 데이터를 조회하는 명령이라기보다, SQLite에서 테이블 구조나 설정 같은 메타 정보를 확인할 때 자주 사용한다.

📌 핵심: 테이블을 만든 뒤에는 `PRAGMA table_info()`로 컬럼, 타입, 제약 조건이 의도대로 적용되었는지 확인한다.

### 3.3 SQLite 데이터 타입과 제약 조건

테이블을 만들 때 컬럼마다 데이터 타입을 지정한다. SQLite에서 기본적으로 자주 다루는 타입은 다음과 같다.

| 데이터 타입 | 의미 |
|---|---|
| `NULL` | 값이 없음을 나타냄 |
| `INTEGER` | 정수 |
| `REAL` | 부동 소수점 수 |
| `TEXT` | 문자열 |
| `BLOB` | 이미지, 동영상, 문서 등 바이너리 데이터 |

데이터 타입이 값의 형태를 정한다면, 제약 조건은 그 값이 지켜야 할 규칙을 정한다. 제약 조건은 영어로 `CONSTRAINT`라고 하며, 데이터의 무결성과 일관성을 지키기 위해 사용한다.

대표적인 제약 조건은 다음과 같다.

| 제약 조건 | 의미 | 사용 목적 |
|---|---|---|
| `PRIMARY KEY` | 레코드를 구분하는 기본 키 | 각 행을 고유하게 식별 |
| `NOT NULL` | NULL 값을 허용하지 않음 | 반드시 값이 필요한 컬럼에 사용 |
| `FOREIGN KEY` | 다른 테이블의 키를 참조 | 테이블 사이 관계를 표현 |

특히 `PRIMARY KEY`는 테이블 안에서 각 레코드를 구분하는 기준이 된다. 게시글이라면 게시글 번호, 사용자라면 사용자 번호처럼, 나중에 특정 데이터를 찾거나 수정할 때 기준으로 쓰인다.

`AUTOINCREMENT`는 자동 증가를 의미한다. 보통 `INTEGER PRIMARY KEY AUTOINCREMENT` 형태로 사용하며, 새 레코드가 추가될 때 이전 최대값보다 큰 값을 자동으로 부여한다.

```sql
CREATE TABLE examples (
    ExamId INTEGER PRIMARY KEY AUTOINCREMENT,
    LastName VARCHAR(50) NOT NULL,
    FirstName VARCHAR(50) NOT NULL
);
```

이 구조에서 `ExamId`는 직접 값을 넣지 않아도 레코드가 추가될 때 자동으로 증가한다. 한 번 사용된 값이 삭제되더라도 SQLite는 일반적으로 그 값을 다시 재사용하지 않고 더 큰 값을 사용한다.

⚠️ 주의: SQLite에서 `AUTOINCREMENT`는 보통 `INTEGER PRIMARY KEY`와 함께 사용한다. `INT`, `BIGINT`처럼 다른 정수 표현을 쓰면 기대한 방식으로 동작하지 않을 수 있다.

📌 핵심: 데이터 타입은 값의 형태를 정하고, 제약 조건은 값이 지켜야 할 규칙을 정한다.

### 3.4 `ALTER TABLE`로 테이블 구조 수정하기

테이블을 만들고 나서도 구조를 바꿔야 하는 경우가 있다. 컬럼을 추가하거나, 컬럼 이름을 바꾸거나, 더 이상 필요 없는 컬럼을 삭제하거나, 테이블 이름 자체를 바꾸는 경우가 대표적이다.

이때 사용하는 명령이 `ALTER TABLE`이다.

| 명령 | 역할 |
|---|---|
| `ALTER TABLE ADD COLUMN` | 필드 추가 |
| `ALTER TABLE RENAME COLUMN` | 필드 이름 변경 |
| `ALTER TABLE DROP COLUMN` | 필드 삭제 |
| `ALTER TABLE RENAME TO` | 테이블 이름 변경 |

강의 필기에서는 `READ COLUMN`, `TALBLE`, `CLOUMN`처럼 철자가 섞여 보일 수 있는데, 실제 SQL에서 사용하는 키워드는 `RENAME COLUMN`이다. SQL은 키워드 철자가 틀리면 바로 오류가 나므로, 구조를 외울 때 정확한 형태로 잡아두는 것이 좋다.

#### 3.4.1 `ADD COLUMN`으로 컬럼 추가하기

`ADD COLUMN`은 기존 테이블에 새 컬럼을 추가할 때 사용한다.

```sql
ALTER TABLE table_name
ADD COLUMN column_definition;
```

예를 들어 `examples` 테이블에 `Country` 컬럼을 추가한다면 다음과 같이 작성한다.

```sql
ALTER TABLE examples
ADD COLUMN Country VARCHAR(100) NOT NULL DEFAULT 'default value';
```

![alt text](<../assets/images/04_28_DB_SQL_2/화면 캡처 2026-05-24 191953.png>)

여기서 중요한 부분은 `NOT NULL DEFAULT 'default value'`이다. 이미 데이터가 들어 있는 테이블에 새 컬럼을 추가할 때 `NOT NULL`만 붙이면 문제가 생길 수 있다. 기존 레코드들은 새 컬럼에 넣을 값이 없기 때문이다. 그래서 `NOT NULL` 컬럼을 추가하려면 기본값인 `DEFAULT`를 함께 설정하는 것이 안전하다.

이번에는 `Age`, `Address` 컬럼을 추가한다.

```sql
ALTER TABLE examples
ADD COLUMN Age INTEGER NOT NULL DEFAULT 0;

ALTER TABLE examples
ADD COLUMN Address VARCHAR(100) NOT NULL DEFAULT 'default value';
```

![alt text](<../assets/images/04_28_DB_SQL_2/화면 캡처 2026-05-24 192317.png>)

SQLite에서는 하나의 `ALTER TABLE ... ADD COLUMN` 문으로 여러 컬럼을 한 번에 추가할 수 없다. 위 코드처럼 컬럼마다 명령을 따로 작성해야 한다.

⚠️ 주의: 기존 테이블에 `NOT NULL` 컬럼을 추가할 때는 기존 데이터에 들어갈 기본값이 필요하다. 이때 `DEFAULT`를 빠뜨리면 오류가 나거나 의도한 구조가 만들어지지 않을 수 있다.

📌 핵심: `ADD COLUMN`은 컬럼을 추가하는 명령이며, `NOT NULL` 컬럼을 추가할 때는 `DEFAULT`를 함께 고려해야 한다.

#### 3.4.2 `RENAME COLUMN`으로 컬럼 이름 바꾸기

컬럼 이름이 잘못되었거나 더 명확한 이름으로 바꾸고 싶을 때는 `RENAME COLUMN`을 사용한다.

```sql
ALTER TABLE table_name
RENAME COLUMN current_name TO new_name;
```

예를 들어 `Address` 컬럼 이름을 `PostCode`로 바꾼다면 다음과 같다.

```sql
ALTER TABLE examples
RENAME COLUMN Address TO PostCode;
```

![alt text](<../assets/images/04_28_DB_SQL_2/화면 캡처 2026-05-24 194542.png>)

`TO` 앞에는 기존 컬럼 이름, `TO` 뒤에는 새 컬럼 이름을 둔다. 이름을 바꾼 뒤에는 `PRAGMA table_info('examples');`로 실제 변경 결과를 확인하는 습관이 좋다.

📌 핵심: `RENAME COLUMN`은 기존 컬럼 이름을 새 이름으로 변경하며, `현재 이름 TO 새 이름` 순서를 지킨다.

#### 3.4.3 `DROP COLUMN`으로 컬럼 삭제하기

더 이상 필요 없는 컬럼은 `DROP COLUMN`으로 삭제할 수 있다.

```sql
ALTER TABLE table_name
DROP COLUMN column_name;
```

예를 들어 `PostCode` 컬럼을 삭제한다면 다음과 같이 작성한다.

```sql
ALTER TABLE examples
DROP COLUMN PostCode;
```

![alt text](<../assets/images/04_28_DB_SQL_2/화면 캡처 2026-05-24 194831.png>)

컬럼 삭제는 되돌리기 어렵기 때문에, 실제 프로젝트에서는 먼저 필요한 데이터가 남아 있지 않은지 확인하고 실행해야 한다. 특히 이미 서비스에서 사용 중인 컬럼이라면 삭제 전에 코드와 쿼리 전체에 영향이 없는지 확인해야 한다.

📌 핵심: `DROP COLUMN`은 컬럼을 제거하는 명령이므로 실행 전 영향 범위를 확인해야 한다.

#### 3.4.4 `RENAME TO`로 테이블 이름 바꾸기

테이블 이름 자체를 바꿀 때는 `RENAME TO`를 사용한다.

```sql
ALTER TABLE table_name
RENAME TO new_table_name;
```

예를 들어 `examples` 테이블 이름을 `new_examples`로 바꾼다면 다음과 같다.

```sql
ALTER TABLE examples
RENAME TO new_examples;
```

![alt text](<../assets/images/04_28_DB_SQL_2/화면 캡처 2026-05-24 195047.png>)

테이블 이름을 바꾸면 이후 모든 쿼리에서 새 이름을 사용해야 한다. 기존 이름으로 조회하면 테이블을 찾지 못하는 오류가 발생한다.

📌 핵심: 테이블 이름을 바꾼 뒤에는 이후 쿼리에서도 반드시 새 테이블 이름을 사용해야 한다.

---

### 3.5 `DROP TABLE`로 테이블 삭제하기

`DROP TABLE`은 테이블 자체를 삭제하는 명령이다. 테이블 구조뿐 아니라 안에 들어 있던 데이터도 함께 사라진다.

```sql
DROP TABLE table_name;
```

예를 들어 이름을 바꾼 `new_examples` 테이블을 삭제하려면 다음과 같이 작성한다.

```sql
DROP TABLE new_examples;
```

이 명령은 `DELETE`와 다르다. `DELETE`는 테이블 안의 레코드를 삭제하지만 테이블 구조는 남긴다. 반면 `DROP TABLE`은 테이블 자체를 없애므로, 이후 같은 테이블을 사용하려면 다시 `CREATE TABLE`로 생성해야 한다.

⚠️ 주의: 실습 중에는 불필요한 테이블을 정리하기 위해 `DROP TABLE`을 자주 쓰지만, 실제 서비스 데이터베이스에서는 매우 조심해서 사용해야 한다.

📌 핵심: `DROP TABLE`은 테이블 자체를 삭제하는 명령이고, `DELETE`는 테이블 안의 데이터를 삭제하는 명령이다.

---

### 3.6 SQL Statements 유형 이해하기

SQL 명령은 역할에 따라 여러 종류로 나눌 수 있다.

![alt text](<../assets/images/04_28_DB_SQL_2/화면 캡처 2026-05-24 195323.png>)

| 유형 | 의미 | 대표 키워드 | 역할 |
|---|---|---|---|
| DDL | Data Definition Language | `CREATE`, `DROP`, `ALTER` | 데이터의 기본 구조 정의 및 변경 |
| DQL | Data Query Language | `SELECT` | 데이터 검색 |
| DML | Data Manipulation Language | `INSERT`, `UPDATE`, `DELETE` | 데이터 추가, 수정, 삭제 |
| DCL | Data Control Language | `COMMIT`, `ROLLBACK`, `GRANT`, `REVOKE` | 권한 및 작업 제어 |

이번 강의의 앞부분에서 다룬 `CREATE`, `ALTER`, `DROP`은 DDL에 해당한다. 지금부터 다룰 `INSERT`, `UPDATE`, `DELETE`는 DML이다. DDL은 테이블 구조를 다루고, DML은 테이블 안의 데이터를 다룬다고 생각하면 흐름을 잡기 쉽다.

📌 핵심: SQL은 역할에 따라 DDL, DQL, DML, DCL로 나뉘며, 이번 강의에서는 구조 관리와 데이터 조작을 중심으로 다룬다.

---

### 3.7 `INSERT`로 데이터 추가하기

테이블을 만들었다면 이제 데이터를 넣어야 한다. `INSERT`는 테이블에 새로운 레코드를 추가하는 명령이다.

실습 전에는 같은 이름의 테이블이 이미 있는지 확인하고, 필요하다면 삭제한 뒤 새로 만드는 흐름을 사용할 수 있다.

```sql
-- articles 테이블의 기존 데이터를 확인한다.
SELECT * FROM articles;

-- 실습을 위해 기존 articles 테이블이 필요 없다면 삭제한다.
DROP TABLE articles;

-- 테이블 구조가 남아 있는지 확인한다.
-- 테이블이 삭제되었다면 결과가 비어 있거나 테이블을 찾지 못한다.
PRAGMA table_info('articles');
```

그 다음 실습용 `articles` 테이블을 만든다.

```sql
CREATE TABLE articles (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title VARCHAR(100) NOT NULL,
    content VARCHAR(200) NOT NULL,
    createdAt DATE NOT NULL
);
```

여기서는 게시글을 저장하는 테이블을 만든다. `id`는 게시글 번호이고, `title`, `content`, `createdAt`은 각각 제목, 내용, 작성일을 의미한다.

`INSERT`의 기본 문법은 다음과 같다.

```sql
INSERT INTO table_name (c1, c2, ...)
VALUES (v1, v2, ...);
```

- `INSERT INTO` 뒤에는 데이터를 넣을 테이블 이름을 작성한다.
- 괄호 안에는 값을 넣을 컬럼 목록을 작성한다.
- `VALUES` 뒤에는 각 컬럼에 들어갈 값을 순서대로 작성한다.

게시글 하나를 추가하는 예시는 다음과 같다.

```sql
INSERT INTO
    articles (title, content, createdAt)
VALUES
    ('hello', 'world', '2000-01-01');
```

여러 개의 데이터를 한 번에 추가할 수도 있다.

```sql
INSERT INTO
    articles (title, content, createdAt)
VALUES
    ('title1', 'content1', '1900-01-01'),
    ('title2', 'content2', '1800-01-01'),
    ('title3', 'content3', '1700-01-01');
```

날짜 값을 직접 적지 않고 SQLite의 날짜 함수를 사용할 수도 있다.

```sql
INSERT INTO
    articles (title, content, createdAt)
VALUES
    ('mytitle', 'mycontent', DATE());
```

⚠️ 주의: 테이블 이름과 컬럼 이름을 일관되게 써야 한다. 예를 들어 테이블을 `articles`로 만들었는데 `article`에 넣으려고 하면 테이블을 찾지 못한다. 또한 `createAt`, `createdAt`처럼 컬럼 이름이 섞이면 이후 `ORDER BY`나 `WHERE`에서 오류가 날 수 있다.

📌 핵심: `INSERT`는 컬럼 목록과 값 목록의 순서가 정확히 대응되어야 한다.

---

### 3.8 `UPDATE`로 데이터 수정하기

`UPDATE`는 기존 레코드의 값을 수정하는 명령이다. 이미 들어 있는 데이터를 바꾸는 것이기 때문에, 어떤 레코드를 수정할지 정하는 `WHERE` 조건이 매우 중요하다.

```sql
UPDATE table_name
SET column_name = expression
WHERE condition;
```

`SET`에는 바꿀 컬럼과 새 값을 작성한다. `WHERE`에는 수정할 레코드를 찾는 조건을 작성한다.

예를 들어 `articles` 테이블에서 `id`가 1인 레코드의 제목을 바꾼다면 다음과 같다.

```sql
UPDATE
    articles
SET
    title = 'update Title'
WHERE
    id = 1;
```

여러 컬럼을 동시에 수정할 수도 있다. 이때 `SET` 안에서 컬럼 사이에는 쉼표가 필요하다.

```sql
UPDATE
    articles
SET
    title = 'update Title',
    content = 'update Content'
WHERE
    id = 2;
```

위 쿼리는 `id`가 2인 게시글의 제목과 내용을 함께 수정한다.

⚠️ 주의: `WHERE`를 작성하지 않으면 테이블의 모든 레코드가 수정된다. 실습에서는 바로 확인할 수 있지만, 실제 데이터베이스에서는 큰 사고로 이어질 수 있다.

📌 핵심: `UPDATE`는 `SET`으로 값을 바꾸고, `WHERE`로 수정 대상을 제한한다.

---

### 3.9 `DELETE`로 데이터 삭제하기

`DELETE`는 테이블 안의 레코드를 삭제하는 명령이다. `DROP TABLE`이 테이블 자체를 삭제한다면, `DELETE`는 테이블은 남겨두고 그 안의 행만 삭제한다.

```sql
DELETE FROM table_name
WHERE condition;
```

예를 들어 `articles` 테이블에서 `id`가 1인 레코드를 삭제하려면 다음과 같이 작성한다.

```sql
DELETE FROM
    articles
WHERE
    id = 1;
```

작성일이 오래된 순으로 레코드 2개를 삭제하는 예시도 볼 수 있다.

```sql
DELETE FROM
    articles
WHERE id IN (
    SELECT id FROM articles
    ORDER BY createdAt
    LIMIT 2
);
```

이 코드는 먼저 서브쿼리에서 `createdAt` 기준으로 오래된 게시글 2개의 `id`를 찾는다. 그 다음 바깥의 `DELETE`가 해당 `id`에 해당하는 레코드를 삭제한다.

흐름을 나누면 다음과 같다.

1. `SELECT id FROM articles`로 게시글 id를 조회한다.
2. `ORDER BY createdAt`으로 작성일이 오래된 순서로 정렬한다.
3. `LIMIT 2`로 앞의 2개만 가져온다.
4. `WHERE id IN (...)` 조건에 해당하는 레코드를 삭제한다.

⚠️ 주의: `DELETE`도 `WHERE`가 없으면 모든 레코드를 삭제한다. 데이터를 지우는 쿼리는 실행 전 항상 조건을 먼저 확인해야 한다.

📌 핵심: `DELETE`는 레코드를 삭제하고, `WHERE` 조건으로 삭제 범위를 반드시 제한해야 한다.

---

### 3.10 관계형 데이터베이스에서 테이블을 나누는 이유

지금까지는 하나의 테이블을 중심으로 문법을 봤다. 하지만 실제 서비스에서는 하나의 테이블에 모든 정보를 넣지 않는다. 예를 들어 게시판을 만든다고 생각해보자.

처음에는 게시글 테이블에 작성자 이름과 역할까지 모두 넣을 수 있다.

![alt text](<../assets/images/04_28_DB_SQL_2/화면 캡처 2026-05-24 201420.png>)

이 방식은 눈으로 보기에는 단순하지만 문제가 있다. 같은 작성자의 이름과 역할이 여러 게시글에 반복된다. 만약 `하석주`라는 사용자가 이름을 바꾸거나 역할이 바뀐다면, 해당 사용자가 작성한 모든 게시글 행을 수정해야 한다.

그래서 사용자 정보, 게시글 정보, 역할 정보를 분리할 수 있다.

![alt text](<../assets/images/04_28_DB_SQL_2/화면 캡처 2026-05-24 201445.png>)

테이블을 나누면 중복을 줄이고, 변경이 필요한 정보를 한 곳에서 관리할 수 있다. 예를 들어 사용자 이름은 `users` 테이블에서 한 번만 수정하면 된다.

그런데 테이블을 나누면 새로운 질문이 생긴다.

- 각 게시글이 누가 작성한 글인지 어떻게 알 수 있을까?
- 사용자의 역할은 어디서 확인할 수 있을까?
- 게시글 목록을 보여줄 때 제목과 작성자 이름을 함께 출력하려면 어떻게 해야 할까?

이때 외래 키가 필요하다. 게시글 테이블에는 `userId`를 두어 어떤 사용자가 작성했는지 연결하고, 사용자 테이블에는 `roleId`를 두어 어떤 역할을 가진 사용자인지 연결할 수 있다.

![alt text](<../assets/images/04_28_DB_SQL_2/화면 캡처 2026-05-24 201554.png>)

예를 들어 관리자인 사람만 보고 싶다면 `roleId = 1`인 사용자를 조회할 수 있다. 또 `하석주`라는 사람이 이름을 바꾼다면, 게시글 테이블의 모든 작성자 이름을 수정하는 것이 아니라 `users` 테이블의 이름만 바꾸면 된다.

📌 핵심: 테이블을 나누는 이유는 중복을 줄이고, 수정·삭제가 쉬운 구조를 만들기 위해서이다.

---

### 3.11 JOIN이 필요한 순간

테이블을 나누면 데이터 관리는 좋아진다. 하지만 출력할 때는 한 가지 문제가 생긴다. 게시글 테이블만 보면 `userId`는 알 수 있지만, 작성자의 실제 이름은 알 수 없다. 사용자 이름은 `users` 테이블에 있기 때문이다.

쉽게 말하면, 테이블을 나누는 것은 보관을 잘하기 위한 방법이고, JOIN은 나누어 보관한 데이터를 다시 화면에 맞게 묶어 보여주는 방법이다.

```text
테이블을 나누는 이유
- 중복을 줄인다.
- 사용자 정보와 게시글 정보를 따로 관리할 수 있다.
- 이름이나 역할이 바뀌어도 한 곳만 수정하면 된다.

하지만 화면에서는
- 게시글 제목과 작성자 이름을 함께 보여줘야 한다.
- 이때 나누어진 테이블을 다시 연결해야 한다.
- 그 방법이 JOIN이다.
```

JOIN에는 여러 종류가 있지만, 이번 강의에서는 `INNER JOIN`과 `LEFT JOIN`을 중심으로 본다.

| JOIN 종류 | 기준 | 결과 특징 |
|---|---|---|
| `INNER JOIN` | 양쪽 테이블 모두에 연결되는 데이터 | 매칭되는 데이터만 출력 |
| `LEFT JOIN` | 왼쪽 테이블 전체 | 매칭이 없어도 왼쪽 데이터는 출력, 오른쪽은 `NULL` |

📌 핵심: JOIN은 분리된 테이블을 특정 조건으로 다시 연결해 조회하는 문법이다.

---

### 3.12 JOIN 실습 준비: `users`와 `articles` 테이블 만들기

JOIN을 연습하기 위해 사용자 테이블과 게시글 테이블을 준비한다. 먼저 기존 테이블을 확인하고, 실습에 방해가 된다면 삭제한다.

```sql
-- 기존 테이블의 데이터가 있는지 확인한다.
SELECT * FROM articles;
SELECT * FROM users;

-- 실습을 위해 기존 테이블을 삭제한다.
DROP TABLE articles;
DROP TABLE users;

-- 테이블 구조가 남아 있는지 확인한다.
PRAGMA table_info('articles');
PRAGMA table_info('users');
```

그 다음 `users` 테이블을 만든다.

```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(50) NOT NULL
);
```

`articles` 테이블은 각 게시글이 어떤 사용자에게 속하는지 나타내기 위해 `userId`를 가진다.

```sql
CREATE TABLE articles (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title VARCHAR(50) NOT NULL,
    content VARCHAR(50) NOT NULL,
    userId INTEGER NOT NULL,
    FOREIGN KEY (userId)
        REFERENCES users(id)
);
```

여기서 `FOREIGN KEY (userId) REFERENCES users(id)`는 `articles.userId`가 `users.id`를 참조한다는 뜻이다. 즉, 게시글의 `userId`를 보면 어떤 사용자가 작성했는지 알 수 있다.

실습 데이터는 다음과 같이 넣는다.

```sql
INSERT INTO
    users (name)
VALUES
    ('하석주'),
    ('송윤미'),
    ('유하선');

INSERT INTO
    articles (title, content, userId)
VALUES
    ('제목1', '내용1', 1),
    ('제목2', '내용2', 2),
    ('제목3', '내용3', 1),
    ('제목4', '내용4', 4),
    ('제목5', '내용5', 1);
```

![alt text](<../assets/images/04_28_DB_SQL_2/화면 캡처 2026-05-24 202711.png>)

여기서 `articles`의 네 번째 게시글은 `userId`가 4이다. 하지만 `users` 테이블에는 `id`가 4인 사용자가 없다. 이 데이터는 `INNER JOIN`과 `LEFT JOIN`의 차이를 확인할 때 중요한 예시가 된다.

⚠️ 주의: 실제 실행에서는 테이블 이름과 컬럼 이름을 정확히 맞춰야 한다. `users`를 만들었는데 `REFERENCES user(id)`처럼 단수형으로 쓰거나, `content`를 `contnet`으로 오타 내면 이후 쿼리에서 오류가 발생한다.

📌 핵심: JOIN을 이해하려면 두 테이블이 어떤 컬럼으로 연결되는지 먼저 확인해야 한다.

---

### 3.13 `INNER JOIN`으로 매칭되는 데이터만 조회하기

`INNER JOIN`은 두 테이블에서 조인 조건에 맞는 데이터만 조회한다. 즉, 양쪽 테이블에 연결되는 값이 있는 경우만 결과에 나온다.

기본 문법은 다음과 같다.

```sql
SELECT
    select_list
FROM
    table_a
INNER JOIN table_b
    ON table_b.fk = table_a.pk;
```

- `FROM` 뒤에는 기준이 되는 메인 테이블을 적는다.
- `INNER JOIN` 뒤에는 연결할 테이블을 적는다.
- `ON` 뒤에는 두 테이블이 어떤 조건으로 연결되는지 작성한다.

작성자가 존재하는 모든 게시글을 작성자 정보와 함께 조회하면 다음과 같다.

```sql
SELECT *
FROM articles
INNER JOIN users
    ON users.id = articles.userId;
```

![alt text](<../assets/images/04_28_DB_SQL_2/화면 캡처 2026-05-24 203103.png>)

결과를 보면 `userId`가 4인 게시글은 출력되지 않는다. `users` 테이블에 `id = 4`인 사용자가 없기 때문이다. 이것이 `INNER JOIN`의 핵심이다. 양쪽 테이블이 연결되는 데이터만 결과에 남는다.

이번에는 1번 회원인 `하석주`가 작성한 게시글의 제목과 작성자명을 조회한다.

```sql
SELECT
    articles.title,
    users.name
FROM articles
INNER JOIN users
    ON users.id = articles.userId
WHERE users.id = 1;
```

이 쿼리는 먼저 `articles`와 `users`를 `userId`와 `id` 기준으로 연결한 뒤, 그중 `users.id = 1`인 데이터만 남긴다. 그래서 1번 사용자가 작성한 게시글 제목과 사용자 이름을 함께 볼 수 있다.

⚠️ 주의: 두 테이블에 같은 이름의 컬럼이 있을 수 있으므로, `articles.title`, `users.name`처럼 `테이블명.컬럼명` 형태로 명확히 적는 습관이 좋다.

📌 핵심: `INNER JOIN`은 조인 조건이 양쪽에서 모두 맞는 데이터만 출력한다.

### 3.14 `LEFT JOIN`으로 왼쪽 테이블 기준 조회하기

`LEFT JOIN`은 왼쪽 테이블의 모든 레코드를 기준으로 출력한다. 오른쪽 테이블에 매칭되는 데이터가 있으면 함께 보여주고, 매칭되는 데이터가 없으면 오른쪽 테이블 컬럼에는 `NULL`이 들어간다.

기본 문법은 다음과 같다.

```sql
SELECT
    select_list
FROM
    table_a
LEFT JOIN table_b
    ON table_b.fk = table_a.pk;
```

모든 게시글을 작성자 정보와 함께 조회하려면 다음과 같이 작성한다.

```sql
SELECT *
FROM articles
LEFT JOIN users
    ON users.id = articles.userId;
```

![alt text](<../assets/images/04_28_DB_SQL_2/화면 캡처 2026-05-24 203610.png>)

`LEFT JOIN` 결과에서는 `articles` 테이블의 모든 게시글이 출력된다. `userId`가 4인 게시글처럼 오른쪽 테이블인 `users`에 연결되는 사용자가 없더라도 게시글 자체는 사라지지 않는다. 대신 사용자 정보 부분이 `NULL`로 표시된다.

쉽게 말하면 `LEFT JOIN`은 이렇게 이해할 수 있다.

```text
LEFT JOIN = 왼쪽 테이블 기준으로 다 보여줘

- 왼쪽 테이블의 모든 레코드는 무조건 출력한다.
- 오른쪽 테이블에 연결된 값이 없으면 NULL로 표시한다.
- 어떤 데이터가 연결되지 않았는지 확인할 때 유용하다.
```

예를 들어 게시글을 작성한 이력이 없는 회원을 찾고 싶다면 `users`를 왼쪽 테이블로 두고 `articles`를 붙인다.

```sql
SELECT
    users.name
FROM users
LEFT JOIN articles
    ON articles.userId = users.id
WHERE articles.userId IS NULL;
```

이 쿼리의 흐름은 다음과 같다.

1. `users`를 기준으로 모든 회원을 가져온다.
2. 각 회원이 작성한 게시글이 있으면 `articles`와 연결한다.
3. 작성한 게시글이 없는 회원은 `articles.userId`가 `NULL`로 남는다.
4. `WHERE articles.userId IS NULL` 조건으로 게시글이 없는 회원만 조회한다.

⚠️ 주의: `NULL` 비교는 `= NULL`이 아니라 `IS NULL`을 사용한다. SQL에서 `NULL`은 일반 값이 아니라 값이 없음을 의미하므로 비교 방식이 다르다.

📌 핵심: `LEFT JOIN`은 왼쪽 테이블의 모든 데이터를 보존하며, 오른쪽에 매칭이 없으면 `NULL`로 표시한다.

### 3.15 SQLite 타입 선호도(Type Affinity)

SQLite는 다른 데이터베이스보다 데이터 타입을 유연하게 다룬다. 이를 타입 선호도, 영어로 `Type Affinity`라고 한다.

타입 선호도는 컬럼에 데이터 타입이 명시적으로 지정되지 않았거나, SQLite가 직접 지원하지 않는 타입이 지정되었을 때 SQLite가 값을 보고 적절한 타입으로 해석하려는 성질이다.

SQLite 타입 선호도의 목적은 다음과 같이 정리할 수 있다.

1. **유연한 데이터 타입 지원**  
   데이터 타입을 엄격하게 제한하지 않고, 저장되는 값의 특성을 바탕으로 타입을 추론할 수 있다.

2. **간편한 데이터 처리**  
   예를 들어 INTEGER 성격의 컬럼에 숫자처럼 해석 가능한 문자열이 들어오면 SQLite가 숫자로 변환해 처리할 수 있다.

3. **SQL 호환성 유지**  
   다른 데이터베이스 시스템에서 쓰는 다양한 타입 표기를 어느 정도 받아들여 호환성을 높인다.

하지만 이 유연함이 항상 장점만 있는 것은 아니다. 타입이 엄격하지 않으면 잘못된 값이 들어가도 바로 오류가 나지 않아, 나중에 조회나 계산 과정에서 예상하지 못한 결과를 만들 수 있다.

📌 핵심: SQLite는 타입을 유연하게 처리하지만, 학습과 실무에서는 의도를 명확히 하기 위해 컬럼 타입을 일관되게 작성하는 것이 좋다.

### 3.16 `NOT NULL`과 NULL 처리 관점

`NOT NULL`은 해당 컬럼에 `NULL` 값을 허용하지 않겠다는 제약 조건이다. 그렇다고 해서 모든 컬럼에 반드시 `NOT NULL`을 붙여야 하는 것은 아니다.

하지만 실제 애플리케이션에서는 값이 비어 있으면 안 되는 경우가 많다. 예를 들어 게시글 제목, 사용자 이름, 상품명처럼 핵심 데이터는 값이 반드시 있어야 한다. 이런 컬럼에는 `NOT NULL`을 붙이는 것이 데이터 무결성을 지키는 데 도움이 된다.

다만 `NULL`을 무조건 피해야 하는 것은 아니다. 값이 아직 정해지지 않았거나, 정말로 모르는 상태를 표현해야 할 때는 `NULL`이 의미를 가진다. 대신 단순히 값이 없다는 이유만으로 무작정 `NULL`을 쓰기보다, 상황에 따라 `0`, 빈 문자열, 기본값 등을 사용할 수 있는지도 생각해야 한다.

```text
NOT NULL을 고려할 때의 기준

- 이 값이 없으면 레코드가 의미를 잃는가?
- 화면이나 기능에서 반드시 필요한 값인가?
- 기본값으로 대체하는 것이 더 자연스러운가?
- NULL과 빈 문자열, 0이 의미상 구분되어야 하는가?
```

📌 핵심: `NOT NULL`은 필수 값을 보장하기 위한 제약 조건이며, NULL을 허용할지 여부는 데이터의 의미를 기준으로 결정해야 한다.

### 3.17 SQLite에서 날짜와 시간 다루기

SQLite에는 날짜와 시간을 위한 별도의 전용 데이터 타입이 없다. 대신 날짜와 시간 값을 저장할 때 `TEXT`, `REAL`, `INTEGER` 같은 타입으로 저장하고, 날짜 함수로 필요한 형식을 만들어 사용한다.

예를 들어 앞에서 사용한 `DATE()` 함수는 현재 날짜 값을 만들어 넣을 때 사용할 수 있다.

```sql
INSERT INTO
    articles (title, content, createdAt)
VALUES
    ('mytitle', 'mycontent', DATE());
```

날짜를 문자열처럼 저장하더라도 정렬과 비교를 고려해야 한다. 일반적으로 `YYYY-MM-DD` 형식은 문자열 정렬을 해도 날짜 순서와 잘 맞기 때문에 실습에서 자주 사용된다.

⚠️ 주의: 날짜 컬럼 이름을 `createAt`, `createdAt`처럼 섞어 쓰면 정렬이나 삭제 쿼리에서 오류가 발생한다. 날짜 컬럼은 처음 테이블을 만들 때 이름을 정한 뒤, 이후 모든 쿼리에서 같은 이름을 사용해야 한다.

📌 핵심: SQLite는 날짜 전용 타입 대신 날짜 함수를 사용하고, 날짜 값은 일관된 형식과 컬럼 이름으로 관리해야 한다.

## 4. 적용 관점에서 다시 보기

이번 강의의 문법은 서로 따로 외우기보다, 실제 작업 순서로 묶어 이해하는 것이 좋다.

먼저 새로운 데이터를 저장해야 한다면 `CREATE TABLE`부터 떠올린다. 이때 컬럼 이름, 타입, 제약 조건을 함께 정한다. 테이블을 만든 뒤에는 `PRAGMA table_info()`로 구조가 제대로 만들어졌는지 확인한다.

이미 만들어진 테이블 구조를 바꿔야 한다면 `ALTER TABLE`을 떠올린다. 컬럼을 추가할 때는 `ADD COLUMN`, 컬럼 이름을 바꿀 때는 `RENAME COLUMN`, 컬럼을 삭제할 때는 `DROP COLUMN`, 테이블 이름을 바꿀 때는 `RENAME TO`를 사용한다. 특히 기존 데이터가 있는 테이블에 `NOT NULL` 컬럼을 추가할 때는 `DEFAULT`를 함께 고려해야 한다.

데이터를 직접 다룰 때는 DML 흐름으로 생각한다.

| 하고 싶은 일 | 사용할 명령 | 가장 조심할 부분 |
|---|---|---|
| 새 데이터 추가 | `INSERT` | 컬럼 목록과 값 목록의 순서 |
| 기존 데이터 수정 | `UPDATE` | `WHERE` 조건 누락 |
| 기존 데이터 삭제 | `DELETE` | `WHERE` 조건 누락 |

여러 테이블이 등장하면 먼저 관계를 확인한다. 게시글과 사용자처럼 한쪽 테이블이 다른 테이블의 `id`를 참조한다면, 그 컬럼이 JOIN 조건의 기준이 된다. 두 테이블 모두에서 매칭되는 데이터만 보고 싶으면 `INNER JOIN`, 왼쪽 테이블의 데이터를 모두 유지하면서 연결 여부를 확인하고 싶으면 `LEFT JOIN`을 사용한다.

문제를 보거나 실습을 할 때 다음 신호를 기억하면 좋다.

- “테이블을 생성하라” → `CREATE TABLE`
- “테이블 구조를 확인하라” → `PRAGMA table_info()`
- “컬럼을 추가/변경/삭제하라” → `ALTER TABLE`
- “레코드를 추가하라” → `INSERT`
- “특정 레코드를 수정하라” → `UPDATE ... WHERE`
- “특정 레코드를 삭제하라” → `DELETE ... WHERE`
- “작성자 이름과 게시글 제목을 함께 조회하라” → `JOIN`
- “매칭되지 않은 데이터도 확인하라” → `LEFT JOIN`과 `IS NULL`

⚠️ 실전에서 가장 많이 틀리는 부분은 이름 불일치이다. 테이블 이름이 `users`인지 `user`인지, 컬럼 이름이 `createdAt`인지 `createAt`인지, `content`를 오타 내지 않았는지 반드시 확인해야 한다. SQL은 작은 오타 하나만 있어도 테이블이나 컬럼을 찾지 못한다.

## 5. 배운 점 / 느낀 점 / 확장 포인트

이번 강의를 통해 SQL은 단순히 데이터를 조회하는 언어가 아니라, 데이터베이스의 구조와 흐름 전체를 다루는 언어라는 점을 확인할 수 있다. `CREATE TABLE`로 구조를 만들고, `ALTER TABLE`로 구조를 바꾸며, `INSERT`, `UPDATE`, `DELETE`로 실제 데이터를 조작한다. 그리고 테이블이 여러 개로 나뉘면 `JOIN`으로 다시 연결해 필요한 형태로 조회한다.

특히 JOIN은 처음에는 문법이 복잡해 보이지만, 핵심은 단순하다. **나누어 저장한 데이터를 어떤 기준으로 다시 붙일 것인가**를 생각하면 된다. 게시글의 `userId`와 사용자의 `id`가 연결 기준이 되듯이, 두 테이블 사이에 같은 의미를 가진 컬럼을 찾아야 한다.

다음 학습에서는 `SELECT`의 조건 조회, 정렬, 그룹화와 JOIN을 함께 사용하는 연습으로 확장할 수 있다. 예를 들어 “사용자별 게시글 수”, “게시글이 없는 사용자”, “특정 역할의 사용자가 작성한 게시글” 같은 문제를 풀어보면 테이블 관계와 SQL 조회 흐름이 더 자연스럽게 연결된다.

## 6. 요약 정리

📌 핵심 정리

- `CREATE TABLE`은 테이블의 컬럼, 타입, 제약 조건을 정의한다.
- `PRAGMA table_info()`는 SQLite에서 테이블 구조를 확인할 때 사용한다.
- `ALTER TABLE`은 이미 만들어진 테이블의 구조를 수정한다.
- `DROP TABLE`은 테이블 자체를 삭제하고, `DELETE`는 테이블 안의 레코드를 삭제한다.
- `INSERT`는 새 레코드를 추가한다.
- `UPDATE`는 기존 레코드를 수정하며, `WHERE` 조건이 중요하다.
- `DELETE`는 기존 레코드를 삭제하며, `WHERE` 조건이 없으면 전체 삭제가 될 수 있다.
- 테이블을 나누면 중복을 줄일 수 있지만, 출력할 때는 JOIN이 필요하다.
- `INNER JOIN`은 양쪽에 매칭되는 데이터만 출력한다.
- `LEFT JOIN`은 왼쪽 테이블의 모든 데이터를 출력하고, 오른쪽에 매칭이 없으면 `NULL`로 표시한다.
- SQLite는 타입 선호도 때문에 타입을 유연하게 처리하지만, 컬럼 타입과 이름은 일관되게 관리해야 한다.

🧠 기억할 것

> 테이블 구조를 만들고, 데이터를 조작하고, 나누어진 테이블을 다시 연결하는 흐름이 SQL 기초의 핵심이다.
