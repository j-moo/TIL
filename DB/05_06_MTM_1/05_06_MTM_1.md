N:1 관계는 여러 객체가 하나의 객체에 속하는 구조였다. 하지만 실제 서비스에는 양쪽 모두 여러 개와 연결되는 관계도 많다. 사용자는 여러 게시글에 좋아요를 누를 수 있고, 게시글 하나도 여러 사용자에게 좋아요를 받을 수 있다. 이런 관계가 N:M이다.

## 2. 핵심 개념 정리

N:M 관계는 한쪽 테이블의 여러 레코드가 다른 쪽 테이블의 여러 레코드와 연결되는 구조다. 관계형 데이터베이스에서는 이를 직접 한 컬럼으로 표현하지 않고, 두 테이블 사이에 중개 테이블을 둔다.

Django의 `ManyToManyField`는 이 중개 테이블을 자동으로 만들어 관리해준다. 개발자는 `add()`, `remove()`, `all()` 같은 related manager 메서드를 통해 관계를 추가하거나 삭제하고 조회할 수 있다.

좋아요 기능을 기준으로 보면, `Article`과 `User` 사이에 N:M 관계가 생긴다.

## 3. 본문 정리

### 3.1 N:M 관계는 양쪽 모두 여러 개와 연결된다

좋아요를 예로 들어 보자.

- 사용자 한 명은 여러 게시글에 좋아요를 누를 수 있다.
- 게시글 하나는 여러 사용자에게 좋아요를 받을 수 있다.

이 관계는 사용자 쪽에서도 여러 개, 게시글 쪽에서도 여러 개다. 그래서 N:M 관계다.

```text
User 1명 -> 여러 Article을 좋아요
Article 1개 -> 여러 User에게 좋아요를 받음
```

N:1처럼 한쪽에 외래 키 하나만 두면 이 구조를 자연스럽게 표현하기 어렵다. 그래서 중간에서 두 모델의 pk를 연결하는 테이블이 필요하다.

### 3.2 ManyToManyField는 중개 테이블을 자동으로 만든다

Django에서는 `ManyToManyField`를 사용해 N:M 관계를 선언할 수 있다.

```python
# articles/models.py

from django.conf import settings
from django.db import models


class Article(models.Model):
    user = models.ForeignKey(
        settings.AUTH_USER_MODEL,
        on_delete=models.CASCADE,
        related_name='articles',
    )
    like_users = models.ManyToManyField(
        settings.AUTH_USER_MODEL,
        related_name='like_articles',
    )
    title = models.CharField(max_length=100)
    content = models.TextField()
```

`like_users`는 이 게시글을 좋아요한 사용자들을 의미한다. `related_name='like_articles'`는 사용자 입장에서 자신이 좋아요한 게시글들을 조회할 때 사용할 이름이다.

```python
article.like_users.all()      # 이 게시글을 좋아요한 사용자들
user.like_articles.all()      # 이 사용자가 좋아요한 게시글들
```

⚠️ 주의: `Article.user`와 `Article.like_users`는 모두 User 모델과 연결된다. 그래서 `related_name`을 설정하지 않으면 역참조 이름이 충돌하거나 의미가 불분명해질 수 있다.

### 3.3 add와 remove로 관계를 토글한다

좋아요 기능은 관계를 추가하거나 삭제하는 토글 동작이다. 이미 좋아요를 눌렀다면 제거하고, 아니라면 추가한다.

```python
from django.contrib.auth.decorators import login_required
from django.shortcuts import get_object_or_404, redirect
from .models import Article


@login_required
def likes(request, article_pk):
    article = get_object_or_404(Article, pk=article_pk)

    if article.like_users.filter(pk=request.user.pk).exists():
        article.like_users.remove(request.user)
    else:
        article.like_users.add(request.user)

    return redirect('articles:index')
```

`add()`는 중개 테이블에 관계를 추가하고, `remove()`는 관계를 삭제한다. 실제 User나 Article 레코드가 삭제되는 것이 아니라, 두 객체를 연결하는 관계만 바뀐다.

📌 핵심: N:M에서 `add`와 `remove`는 객체 자체가 아니라 관계를 추가하고 삭제한다.

### 3.4 포함 여부는 exists로 확인한다

좋아요 버튼을 눌렀을 때 현재 사용자가 이미 좋아요를 눌렀는지 확인해야 한다. 이때 `in`을 사용할 수도 있지만, ORM에서는 `filter().exists()`가 명확하고 효율적이다.

```python
is_liked = article.like_users.filter(pk=request.user.pk).exists()
```

이 값은 템플릿에서도 버튼 상태를 보여주는 기준이 된다.

```html
{% if request.user in article.like_users.all %}
  <button>좋아요 취소</button>
{% else %}
  <button>좋아요</button>
{% endif %}
```

템플릿에서는 가독성을 위해 위와 같이 쓸 수 있지만, view 로직에서는 `exists()`를 사용하면 데이터베이스에 존재 여부만 물어볼 수 있어 더 적절하다.

## 4. 적용 관점에서 다시 보기

N:M 관계를 판단할 때는 양쪽에서 문장을 만들어 보면 좋다.

- 사용자는 여러 게시글을 좋아요할 수 있다.
- 게시글은 여러 사용자에게 좋아요를 받을 수 있다.

두 문장이 모두 "여러"로 끝나면 N:M 관계다. 이때 중개 테이블이 필요하고, Django에서는 `ManyToManyField`가 이를 대신 관리한다.

구현 순서는 다음처럼 잡을 수 있다.

1. 어느 두 모델이 N:M인지 판단한다.
2. 의미가 자연스러운 쪽에 `ManyToManyField`를 추가한다.
3. 역참조 이름이 헷갈리지 않도록 `related_name`을 정한다.
4. `add()`, `remove()`, `exists()`로 관계 토글 로직을 작성한다.
5. 템플릿에서 현재 관계 상태에 따라 버튼을 다르게 보여준다.

## 5. 배운 점 / 확장 포인트

### 5.1 이번 강의 이전에 몰랐던 것 또는 새로 이해된 것

N:M 관계는 두 모델 중 한쪽에 외래 키 하나를 두는 방식으로는 충분하지 않다. 두 객체의 연결 자체를 별도 관계로 관리해야 하며, Django는 이를 `ManyToManyField`로 추상화해준다.

### 5.2 앞으로 이어지는 연결점

좋아요 관계를 이해하면 팔로우 관계도 이해하기 쉬워진다. 팔로우는 사용자와 사용자 사이의 N:M 관계라는 점만 다를 뿐, 관계를 추가하고 삭제하는 흐름은 비슷하다.

### 5.3 더 파볼 만한 주제

N:M 관계에 추가 정보가 필요하면 `through` 옵션으로 중개 모델을 직접 만들 수 있다. 예를 들어 관계가 생성된 시간, 역할, 상태를 함께 저장해야 한다면 자동 중개 테이블만으로는 부족하다.

## 6. 요약 정리

N:M 관계는 양쪽 모두 여러 객체와 연결될 수 있는 관계다. Django에서는 `ManyToManyField`로 관계를 선언하고, related manager를 통해 관계를 조작한다.

🧠 기억할 것:

- N:M 관계는 중개 테이블로 표현된다.
- `ManyToManyField`는 중개 테이블을 자동으로 관리한다.
- `add()`와 `remove()`는 객체가 아니라 관계를 바꾼다.
- `exists()`는 현재 관계가 있는지 확인할 때 유용하다.
- 같은 User 모델과 여러 관계를 맺으면 `related_name`이 중요해진다.
