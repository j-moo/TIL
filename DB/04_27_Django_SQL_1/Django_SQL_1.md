## 1. 들어가며

웹 서비스를 만들다 보면 결국 데이터를 다루게 된다. 회원 정보, 게시글, 댓글, 주문 내역, 상품 목록처럼 서비스가 기억해야 하는 정보는 모두 일정한 장소에 저장되어야 한다. 이때 단순히 파일에 적어두는 방식만으로는 데이터가 많아질수록 찾기 어렵고, 수정하기 어렵고, 정확성을 유지하기도 어렵다.

이번 강의는 이런 문제의식에서 출발한다. 먼저 데이터베이스가 왜 필요한지 살펴보고, 그중에서도 관계형 데이터베이스가 데이터를 어떤 방식으로 구조화하는지 이해한다. 이후 SQL을 사용해 테이블에서 원하는 데이터를 조회하는 기본 문법을 익힌다.

특히 Django를 학습할 때 데이터베이스 개념은 단순한 배경지식이 아니다. Django의 Model과 ORM은 결국 데이터베이스의 테이블, 행, 열, 관계를 파이썬 코드로 다루기 위한 도구이기 때문이다. 따라서 SQL의 기본 구조를 이해해두면 이후 Django ORM이 내부적으로 어떤 요청을 보내는지 훨씬 자연스럽게 받아들일 수 있다.

## 2. 핵심 개념 정리

이번 강의의 흐름은 크게 세 단계로 볼 수 있다.

첫 번째는 **데이터를 왜 구조적으로 저장해야 하는가**이다. 파일이나 스프레드시트도 데이터를 저장할 수 있지만, 데이터의 양이 커지고 여러 사람이 함께 사용하기 시작하면 한계가 드러난다. 데이터베이스는 이 문제를 해결하기 위해 데이터를 체계적으로 저장하고 관리하는 역할을 한다.

두 번째는 **관계형 데이터베이스가 데이터를 어떻게 연결하는가**이다. 관계형 데이터베이스는 데이터를 하나의 큰 덩어리로 저장하지 않고, 여러 테이블로 나누어 저장한다. 그리고 각 테이블은 기본 키와 외래 키를 통해 서로 연결된다. 이 구조 덕분에 중복을 줄이고, 필요한 데이터를 다양한 방식으로 조합해 조회할 수 있다.

세 번째는 **SQL로 데이터를 어떻게 요청하는가**이다. SQL은 관계형 데이터베이스에 원하는 데이터를 요청하기 위한 언어이다. 이번 강의에서는 그중에서도 데이터를 조회하는 DQL 중심으로 `SELECT`, `FROM`, `WHERE`, `ORDER BY`, `DISTINCT`, `LIMIT`, `GROUP BY`, `HAVING`을 다룬다.

흐름을 간단히 정리하면 다음과 같다.

| 흐름 | 핵심 질문 | 주요 개념 |
|---|---|---|
| 데이터 저장 | 데이터를 어디에, 어떻게 저장할 것인가? | Database, File, Spreadsheet |
| 데이터 구조화 | 데이터를 어떻게 나누고 연결할 것인가? | Table, Field, Record, PK, FK |
| 데이터 관리 | 누가 데이터베이스를 관리하고 실행하는가? | DBMS, RDBMS, SQLite |
| 데이터 조회 | 원하는 데이터를 어떻게 요청할 것인가? | SQL, SELECT, WHERE, GROUP BY |

이제 본문에서는 이 흐름을 따라가며, 개념과 예시, 이미지, 코드를 한 자리에서 함께 정리한다.

## 3. 본문 정리

## 3.1 데이터베이스가 필요한 이유

데이터베이스는 **체계적으로 정리된 데이터의 모음**이다. 쉽게 말하면, 컴퓨터 안에 만들어 둔 잘 정리된 책장과 같다. 책을 아무 곳에나 쌓아두면 나중에 필요한 책을 찾기 어렵지만, 주제별·작가별로 분류해두면 훨씬 빠르게 찾을 수 있다.

데이터도 마찬가지다. 웹 서비스에서 데이터가 조금만 있을 때는 파일 하나에 저장해도 큰 문제가 없어 보일 수 있다. 하지만 데이터가 많아지고, 여러 기능에서 같은 데이터를 사용하고, 동시에 여러 사용자가 접근하게 되면 단순한 파일 저장 방식만으로는 관리가 어려워진다.

여기서 말하는 **데이터**는 저장이나 처리를 위해 변환된 정보이다. 사람이 이해하는 정보가 컴퓨터가 다룰 수 있는 형태로 구조화되면 데이터가 된다. 예를 들어 “김철수는 서울에 산다”라는 문장을 이름, 주소, 회원번호 같은 항목으로 나누어 저장하면 데이터베이스에서 검색하고 수정하기 쉬운 데이터가 된다.

### 파일과 스프레드시트 방식

처음 데이터를 저장할 때 가장 쉽게 떠올릴 수 있는 방식은 파일이다. 파일은 어디에서나 쉽게 만들고 열 수 있지만, 데이터가 많아질수록 구조적으로 관리하기 어렵다.

![파일을 이용한 데이터 저장 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 154017.png>)

위와 같은 파일 방식은 간단한 기록에는 적합하지만, 특정 조건에 맞는 데이터를 빠르게 검색하거나 여러 데이터 사이의 관계를 표현하기에는 한계가 있다.

그다음으로 많이 사용하는 방식은 스프레드시트이다. 스프레드시트는 행과 열을 사용하기 때문에 파일보다 구조적인 관리가 가능하다.

![스프레드시트를 이용한 데이터 관리 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 154046.png>)

하지만 스프레드시트도 완전한 해결책은 아니다. 일반적으로 저장 가능한 행 수에 한계가 있고, 접근 권한 관리가 단순하며, 데이터가 여러 시트에 흩어져 있으면 값 하나를 수정할 때 누락이 발생하기 쉽다. 예를 들어 공식 지명이 바뀌었는데 같은 값이 여러 시트에 반복되어 있다면, 모든 위치를 빠짐없이 수정해야 한다.

💡 포인트: 데이터베이스는 단순히 데이터를 “저장하는 곳”이 아니라, 많은 데이터를 **정확하게 찾고, 수정하고, 연결하기 위한 구조**를 제공한다.

### 데이터베이스의 기본 역할: CRUD

데이터베이스의 기본 역할은 흔히 CRUD로 정리한다.

| 기능 | 의미 | 예시 |
|---|---|---|
| Create | 데이터 생성 | 새 회원 가입 정보 저장 |
| Read | 데이터 조회 | 게시글 목록 조회 |
| Update | 데이터 수정 | 회원 주소 변경 |
| Delete | 데이터 삭제 | 댓글 삭제 |

이번 강의에서 집중하는 부분은 이 중 **Read**, 즉 데이터를 조회하는 과정이다. SQL의 `SELECT` 문은 데이터베이스에서 원하는 데이터를 읽어오는 대표적인 명령이다.

📌 핵심: 데이터베이스는 데이터를 많이 저장하기 위한 도구를 넘어, 데이터를 정확하고 일관되게 관리하기 위한 구조이다.

## 3.2 관계형 데이터베이스: 데이터를 나누고 연결하는 방식

관계형 데이터베이스는 **데이터 간에 관계가 있는 항목들을 테이블 형태로 저장하는 데이터베이스**이다. 여기서 중요한 점은 데이터를 하나의 큰 표에 모두 넣는 것이 아니라, 의미에 따라 여러 테이블로 나누고 필요한 순간에 다시 연결한다는 것이다.

예를 들어 병원 접수 시스템을 떠올려 볼 수 있다. 환자 정보와 진료 기록을 한곳에 모두 적어둘 수도 있지만, 그렇게 하면 같은 환자 정보가 여러 번 반복될 수 있다. 대신 환자 테이블에는 환자의 기본 정보를 저장하고, 진료 기록 테이블에는 환자 번호를 함께 저장하면 두 데이터를 정확하게 연결할 수 있다.

![관계형 데이터베이스의 테이블 구조 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 154238.png>)

위 예시처럼 관계형 데이터베이스는 테이블, 행, 열을 기준으로 데이터를 구조화한다. 각각의 테이블은 독립적으로 보이지만, 공통된 키 값을 통해 서로 연결될 수 있다.

### 관계란 무엇인가

관계는 여러 테이블 사이의 논리적 연결이다. 데이터를 각각의 테이블에 나누어 저장하되, 공통된 키 값을 통해 필요한 순간 함께 조회할 수 있게 해준다.

![테이블 간 관계를 이용한 조회 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 154340.png>)

관계가 있으면 단순히 하나의 표만 보는 것이 아니라, 여러 테이블을 조합해 다양한 질문에 답할 수 있다.

예를 들어 다음과 같은 조회가 가능해진다.

- 특정 날짜에 구매한 모든 고객 조회
- 지난달 배송이 지연된 고객 조회
- 특정 고객이 주문한 상품 목록 조회
- 특정 상품을 구매한 고객 목록 조회

즉, 관계형 데이터베이스의 핵심은 “데이터를 나누어 저장하되, 필요할 때 연결해서 사용한다”는 점이다.

### 기본 키와 외래 키

관계형 데이터베이스에서 데이터를 정확히 식별하려면 고유한 값이 필요하다. 이름이나 주소는 겹칠 수 있기 때문에 안전한 식별 기준이 되기 어렵다.

![고객 데이터에서 식별 기준을 고민하는 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 154508.png>)

이 문제를 해결하기 위해 각 데이터에 고유한 식별 값을 부여한다. 이것이 **기본 키 Primary Key, PK**이다.

![기본 키를 이용해 고객 데이터를 구분하는 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 154543.png>)

기본 키는 각 행을 구분하는 고유한 값이다. 고객 테이블에서 고객 번호가 기본 키라면, 이름이 같거나 주소가 같아도 고객 번호를 통해 정확히 한 사람을 구분할 수 있다.

그렇다면 주문 테이블에서 “누가 주문했는지”는 어떻게 표현할까? 주문 테이블에 고객의 이름을 직접 저장할 수도 있지만, 동명이인이 있으면 문제가 생긴다. 그래서 주문 테이블에는 고객 테이블의 기본 키를 참조하는 값을 저장한다. 이것이 **외래 키 Foreign Key, FK**이다.

![외래 키를 이용해 주문과 고객을 연결하는 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 154617.png>)

| 개념 | 의미 | 예시 |
|---|---|---|
| Table / Relation | 데이터를 기록하는 곳 | customers, orders |
| Field / Column / Attribute | 테이블의 세로 항목 | name, age, customer_id |
| Record / Row / Tuple | 실제 데이터 한 줄 | 고객 한 명의 정보 |
| Database / Schema | 테이블의 집합 | 쇼핑몰 데이터베이스 |
| Primary Key | 각 레코드의 고유한 식별자 | customer_id |
| Foreign Key | 다른 테이블의 기본 키를 참조하는 필드 | orders.customer_id |

⚠️ 주의: 이름, 주소, 전화번호처럼 사람이 보기에는 식별자로 보이는 값도 실제 데이터에서는 중복되거나 변경될 수 있다. 관계형 데이터베이스에서는 안정적인 식별을 위해 기본 키를 사용한다.

📌 핵심: 관계형 데이터베이스는 테이블을 나누고, 기본 키와 외래 키로 테이블 사이의 관계를 만든다.

## 3.3 DBMS, RDBMS, SQLite

데이터베이스가 데이터를 저장하는 구조라면, **DBMS Database Management System**은 그 데이터베이스를 관리하는 소프트웨어이다. 사용자는 DBMS를 통해 데이터를 생성하고, 조회하고, 수정하고, 삭제한다.

쉽게 말하면 DBMS는 정리된 서류함을 관리해주는 담당자와 같다. 데이터가 일정한 규칙에 맞게 저장되도록 돕고, 필요할 때 꺼내거나 수정할 수 있게 해준다.

### DBMS의 역할

DBMS는 데이터베이스와 사용자 사이의 인터페이스 역할을 한다.

- 데이터 구성
- 데이터 업데이트
- 데이터 조회
- 데이터 모니터링
- 백업과 복구
- 접근 관리

여기서 관계형 데이터베이스를 관리하는 DBMS를 **RDBMS Relational Database Management System**라고 한다. RDBMS는 데이터를 여러 테이블로 나누어 저장하고, 공통된 키를 통해 관계를 맺어 사용할 수 있도록 해준다.

예를 들어 도서관 대출 시스템에서 책 목록, 회원 명단, 대출 기록은 서로 다른 테이블로 나누어 관리할 수 있다. 그리고 회원 번호와 책 번호를 통해 어느 회원이 어떤 책을 빌렸는지 연결할 수 있다.

### 대표적인 RDBMS

| RDBMS | 특징 |
|---|---|
| SQLite | 가볍고 설치가 간단하여 학습용, 모바일 앱, 소규모 프로젝트에 적합 |
| MySQL | 웹 서비스에서 널리 사용되는 오픈소스 RDBMS |
| PostgreSQL | 표준 SQL 지원과 확장성이 강한 RDBMS |
| Oracle Database | 기업 환경에서 많이 쓰이는 상용 RDBMS |

이번 학습에서 자주 만나는 SQLite는 경량의 오픈소스 데이터베이스 관리 시스템이다. 설치 없이 가볍게 사용할 수 있어 Django 학습 초반이나 소규모 프로젝트에서 자주 사용된다.

💡 포인트: Django 프로젝트를 처음 만들면 기본 데이터베이스로 SQLite가 설정되어 있는 경우가 많다. 그래서 SQL과 SQLite의 기본 구조를 이해해두면 Django에서 생성되는 `db.sqlite3` 파일의 의미도 자연스럽게 이해할 수 있다.

📌 핵심: DBMS는 데이터베이스를 관리하는 프로그램이고, RDBMS는 관계형 데이터베이스를 관리하는 프로그램이다.

## 3.4 SQL: 데이터베이스에 보내는 요청서

SQL은 **Structured Query Language**의 약자로, 관계형 데이터베이스에 요청을 보내기 위한 언어이다. 데이터베이스라는 거대한 도서관에서 원하는 책을 찾기 위해 사서에게 요청서를 쓰는 것처럼, SQL은 DBMS에게 원하는 데이터를 명확한 형식으로 요청한다.

예를 들어 “2000년 이후 출판된 과학 소설 중에서 제목과 저자 정보를 최신순으로 찾아줘”라는 요청을 사람이 말로 할 수도 있다. 하지만 데이터베이스는 모호한 자연어가 아니라 약속된 문법을 필요로 한다. SQL은 그 약속된 요청 형식이다.

### SQL Statement의 기본 형태

SQL을 구성하는 가장 기본적인 코드 블록을 SQL Statement라고 한다.

```SQL
-- column_name에 조회하고 싶은 필드명을 작성한다.
SELECT column_name
-- table_name에는 데이터를 가져올 테이블명을 작성한다.
FROM table_name;
```

위 코드는 `SELECT`와 `FROM`이라는 두 개의 키워드로 구성된다. `SELECT`는 어떤 필드를 조회할지 정하고, `FROM`은 어느 테이블에서 데이터를 가져올지 정한다.

### SQL 문장의 유형

SQL Statement는 수행 목적에 따라 다음과 같이 나눌 수 있다.

![SQL Statement 유형 정리](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 160701.png>)

| 유형 | 의미 | 예시 |
|---|---|---|
| DDL | 데이터 구조 정의 | CREATE, ALTER, DROP |
| DQL | 데이터 검색 | SELECT |
| DML | 데이터 조작 | INSERT, UPDATE, DELETE |
| DCL | 권한 제어 | GRANT, REVOKE |

이번 강의에서 집중하는 것은 데이터를 검색하는 DQL, 그중에서도 `SELECT` 문이다.

### SQL 작성 규칙

```SQL
-- SQL 키워드는 대소문자를 구분하지 않지만,
-- 보통 키워드는 대문자로 작성해 필드명과 구분하기 쉽게 한다.
SELECT column_name
FROM table_name;
```

SQL을 작성할 때는 몇 가지 기본 규칙이 있다.

- SQL 키워드는 대소문자를 구분하지 않는다.
- 다만 `SELECT`, `FROM`, `WHERE`처럼 키워드는 대문자로 쓰는 것을 권장한다.
- SQL Statement의 끝에는 세미콜론 `;`을 붙인다.
- 세미콜론은 하나의 명령이 끝났다는 표시이다.

⚠️ 주의: 강의 필기에는 `FORM`, `SEELCT`처럼 오타가 섞여 있을 수 있다. 실제 SQL에서는 반드시 `FROM`, `SELECT`로 작성해야 한다.

📌 핵심: SQL은 관계형 데이터베이스에 원하는 데이터를 명확한 문법으로 요청하는 언어이다.

## 3.5 SELECT와 FROM: 원하는 필드 조회하기

`SELECT`는 테이블에서 원하는 데이터를 조회하는 가장 기본적인 문법이다. SQL을 처음 배울 때 가장 먼저 익혀야 하는 이유도, 대부분의 데이터 확인 작업이 조회에서 시작되기 때문이다.

기본 구조는 다음과 같다.

```SQL
-- select_list에는 조회할 필드를 작성한다.
SELECT select_list
-- table_name에는 데이터를 가져올 테이블을 작성한다.
FROM table_name;
```

`SELECT` 뒤에는 조회하고 싶은 필드를 하나 이상 작성한다. `FROM` 뒤에는 해당 필드가 들어 있는 테이블명을 작성한다.

### SELECT 활용 예시

`employees` 테이블에서 `LastName` 필드의 모든 데이터를 조회할 수 있다.

![LastName 필드 조회 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 161317.png>)

여러 필드를 보고 싶다면 쉼표로 구분한다. 예를 들어 `LastName`, `FirstName`을 함께 조회할 수 있다.

![LastName과 FirstName 필드 조회 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 161403.png>)

모든 필드를 조회하고 싶다면 별표 `*`를 사용할 수 있다.

![모든 필드 조회 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 161456.png>)

다만 실무에서는 모든 필드를 무조건 조회하기보다, 필요한 필드만 명시하는 습관이 좋다. 데이터가 많을수록 불필요한 필드까지 가져오는 것은 성능과 가독성에 좋지 않기 때문이다.

### 별칭 AS 사용하기

조회 결과의 필드명을 보기 좋게 바꾸고 싶다면 `AS`를 사용할 수 있다. 예를 들어 `FirstName`을 화면에는 `이름`으로 출력할 수 있다.

![AS를 사용해 조회 결과 필드명을 바꾸는 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 161617.png>)

`AS`는 원본 테이블의 필드명을 바꾸는 것이 아니라, 조회 결과에서 보이는 이름만 바꾼다. 그래서 결과를 읽기 좋게 만들 때 유용하다.

### 계산 결과 조회하기

SQL에서는 필드 값을 그대로 조회하는 것뿐 아니라, 계산한 결과를 조회할 수도 있다. 예를 들어 `tracks` 테이블에서 `Milliseconds` 값을 60000으로 나누면 밀리초 단위의 길이를 분 단위로 바꿔 볼 수 있다.

![Milliseconds 값을 분 단위로 계산해 조회하는 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 161734.png>)

```SQL
-- Name은 곡 이름을 그대로 조회한다.
SELECT
    Name,
    -- Milliseconds는 밀리초 단위이므로 60000으로 나누어 분 단위로 계산한다.
    Milliseconds / 60000 AS Minutes
FROM
    tracks;
```

💡 포인트: `SELECT`는 단순히 필드를 가져오는 문법이 아니라, 필요한 경우 계산식이나 별칭을 함께 사용해 결과를 읽기 좋게 만들 수 있다.

⚠️ 주의: `*`는 편리하지만, 어떤 필드가 필요한지 의도가 드러나지 않는다. 학습 중에는 괜찮지만, 실제 프로젝트에서는 필요한 필드를 직접 작성하는 습관이 좋다.

📌 핵심: `SELECT`는 조회할 필드를 정하고, `FROM`은 데이터를 가져올 테이블을 정한다.

## 3.6 ORDER BY: 조회 결과 정렬하기

`ORDER BY`는 조회 결과를 특정 필드 기준으로 정렬할 때 사용한다. 데이터베이스에서 가져온 결과는 항상 우리가 원하는 순서로 나온다고 보장할 수 없기 때문에, 정렬이 필요하다면 명시적으로 `ORDER BY`를 작성해야 한다.

```SQL
SELECT select_list
FROM table_name
-- column1을 기준으로 정렬한다.
-- ASC는 오름차순, DESC는 내림차순이다.
ORDER BY column1 [ASC|DESC], column2 [ASC|DESC];
```

`ORDER BY`는 `FROM` 뒤에 위치한다. 기본 정렬 방향은 오름차순 `ASC`이다. 따라서 `ASC`를 생략하면 오름차순으로 정렬된다.

### 오름차순과 내림차순

`employees` 테이블에서 `FirstName`을 오름차순으로 조회하면 알파벳 순서에 맞게 정렬된다.

```SQL
SELECT FirstName
FROM employees
ORDER BY FirstName;
```

![FirstName 오름차순 정렬 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 180023.png>)

반대로 내림차순 정렬을 하고 싶다면 `DESC`를 붙인다.

```SQL
SELECT FirstName
FROM employees
ORDER BY FirstName DESC;
```

![FirstName 내림차순 정렬 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 180047.png>)

### 여러 기준으로 정렬하기

정렬 기준은 하나만 사용할 필요가 없다. 먼저 `Country`를 내림차순으로 정렬하고, 같은 국가 안에서는 `City`를 오름차순으로 정렬할 수 있다.

```SQL
SELECT Country, City
FROM customers
ORDER BY Country DESC, City;
```

![Country와 City를 함께 사용한 다중 정렬 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 180255.png>)

이 코드는 먼저 `Country DESC`를 적용한다. 그다음 같은 국가 값끼리는 `City` 기준으로 오름차순 정렬한다. 즉, 앞에 적은 정렬 기준이 더 큰 기준이고, 뒤에 적은 기준은 같은 값 안에서 세부 정렬을 담당한다.

### 계산 결과를 기준으로 정렬하기

`tracks` 테이블에서 `Milliseconds`를 분 단위로 바꿔 출력하고, 길이가 긴 순서대로 정렬할 수도 있다.

![Milliseconds를 기준으로 내림차순 정렬하는 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 180423.png>)

```SQL
SELECT
    Name,
    -- 밀리초를 분 단위로 변환해 조회 결과에 함께 보여준다.
    Milliseconds / 60000 AS Minutes
FROM
    tracks
-- 원본 Milliseconds 값을 기준으로 긴 곡부터 정렬한다.
ORDER BY
    Milliseconds DESC;
```

### SELECT 실행 순서 이해하기

SQL을 읽을 때는 작성 순서와 실제 처리 순서가 다르다는 점을 알아두면 좋다.

![SELECT 문 실행 순서 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 180555.png>)

기본 조회와 정렬의 실행 흐름은 다음과 같다.

1. `FROM`: 어느 테이블에서 가져올지 정한다.
2. `SELECT`: 어떤 필드를 조회할지 정한다.
3. `ORDER BY`: 조회 결과를 정렬한다.

⚠️ 주의: `NULL` 값이 있는 필드를 오름차순 정렬하면 `NULL`이 먼저 출력될 수 있다. `NULL`은 일반적인 숫자나 문자열 값과 다르게 취급되므로 정렬 결과를 확인할 때 주의해야 한다.

📌 핵심: `ORDER BY`는 조회 결과의 순서를 명확히 정하기 위한 문법이며, 여러 정렬 기준을 함께 사용할 수 있다.

## 3.7 DISTINCT와 WHERE: 중복 제거와 조건 필터링

데이터를 조회할 때 모든 값을 그대로 보는 것보다, 중복을 제거하거나 특정 조건에 맞는 데이터만 보고 싶은 경우가 많다. 이때 `DISTINCT`와 `WHERE`를 사용한다.

### DISTINCT: 중복 없이 조회하기

`DISTINCT`는 조회 결과에서 중복된 값을 제거한다. 예를 들어 고객 테이블에 여러 고객의 국가 정보가 들어 있을 때, 전체 국가 목록만 보고 싶다면 `DISTINCT`를 사용할 수 있다.

```SQL
SELECT DISTINCT
    -- 중복 없이 보고 싶은 필드를 작성한다.
    Country
FROM
    customers
ORDER BY
    Country;
```

`DISTINCT`를 사용하기 전에는 같은 국가가 여러 번 나올 수 있다.

![DISTINCT 사용 전 Country 조회 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 182028.png>)

`DISTINCT`를 사용하면 중복된 국가는 한 번만 출력된다.

![DISTINCT를 사용한 Country 중복 제거 조회 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 182115.png>)

⚠️ 주의: `DISTINCT`는 `SELECT` 바로 뒤에 작성해야 한다. 또한 여러 필드를 함께 조회하면, 각 필드의 조합이 중복인지 판단한다.

### WHERE: 조건에 맞는 행만 조회하기

`WHERE`는 특정 조건을 만족하는 행만 조회할 때 사용한다.

```SQL
SELECT
    select_list
FROM
    table_name
WHERE
    -- 비교 연산자와 논리 연산자를 사용해 조건을 작성한다.
    search_condition;
```

예를 들어 `customers` 테이블에서 도시가 `Prague`인 고객만 조회할 수 있다.

```SQL
SELECT
    LastName, FirstName, City
FROM
    customers
WHERE
    City = 'Prague';
```

![City가 Prague인 고객 조회 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 182439.png>)

반대로 `Prague`가 아닌 고객만 조회하려면 `!=`를 사용한다.

```SQL
SELECT
    LastName, FirstName, City
FROM
    customers
WHERE
    City != 'Prague';
```

![City가 Prague가 아닌 고객 조회 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 182616.png>)

### NULL 조건과 AND / OR

`Company` 값이 비어 있고, 국가가 `USA`인 고객을 조회하려면 `IS NULL`과 `AND`를 함께 사용한다.

```SQL
SELECT
    LastName, FirstName, Company, Country
FROM
    customers
WHERE
    -- Company 값이 없는 행을 찾는다.
    Company IS NULL
    -- 동시에 Country가 USA인 행만 남긴다.
    AND Country = 'USA';
```

![Company가 NULL이고 Country가 USA인 데이터 조회 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 182830.png>)

`AND`는 두 조건을 모두 만족해야 한다. 반면 `OR`은 둘 중 하나만 만족해도 결과에 포함된다.

```SQL
SELECT
    LastName, FirstName, Company, Country
FROM
    customers
WHERE
    -- Company 값이 없거나
    Company IS NULL
    -- Country가 USA이면 조회 결과에 포함된다.
    OR Country = 'USA';
```

![Company가 NULL이거나 Country가 USA인 데이터 조회 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 183454.png>)

### BETWEEN: 범위 조건 작성하기

`BETWEEN A AND B`는 A 이상 B 이하 범위에 포함되는 값을 찾는다.

```SQL
SELECT
    Name, Bytes
FROM
    tracks
WHERE
    -- Bytes가 10000 이상 500000 이하인 행을 찾는다.
    Bytes BETWEEN 10000 AND 500000;
```

![Bytes 범위 조건 조회 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 183700.png>)

조건으로 거른 뒤 정렬까지 함께 적용할 수 있다.

```SQL
SELECT
    Name, Bytes
FROM
    tracks
WHERE
    Bytes BETWEEN 10000 AND 500000
ORDER BY
    Bytes;
```

![Bytes 범위 조건 후 오름차순 정렬 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 183915.png>)

### IN과 NOT IN: 여러 후보 중 포함 여부 확인하기

`IN`은 여러 값 중 하나에 해당하는지 확인할 때 사용한다.

```SQL
SELECT
    LastName, FirstName, Country
FROM
    customers
WHERE
    -- Country가 세 국가 중 하나라면 조회한다.
    Country IN ('Canada', 'Germany', 'France');
```

![IN을 사용한 여러 국가 조건 조회 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 184141.png>)

반대로 해당 목록에 포함되지 않는 데이터를 조회하려면 `NOT IN`을 사용한다.

```SQL
SELECT
    -- 강의 원문에는 LastaName 오타가 있었으나 실제 필드명은 LastName으로 작성해야 한다.
    LastName, FirstName, Country
FROM
    customers
WHERE
    Country NOT IN ('Canada', 'Germany', 'France');
```

![NOT IN을 사용한 제외 조건 조회 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 184334.png>)

### LIKE와 와일드카드

`LIKE`는 문자열 패턴을 기준으로 데이터를 찾을 때 사용한다. 이때 와일드카드 문자를 함께 사용한다.

| 와일드카드 | 의미 | 예시 |
|---|---|---|
| `%` | 0개 이상의 문자열 | `%son`은 son으로 끝나는 문자열 |
| `_` | 정확히 한 글자 | `___a`는 네 글자이며 a로 끝나는 문자열 |

`LastName`이 `son`으로 끝나는 데이터를 찾으려면 다음처럼 작성한다.

```SQL
SELECT
    LastName, FirstName
FROM
    customers
WHERE
    -- 앞에는 어떤 문자열이 와도 되고, 마지막이 son이면 된다.
    LastName LIKE '%son';
```

![LIKE와 %를 사용한 문자열 패턴 조회 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 184517.png>)

`FirstName`이 네 글자이고 마지막 글자가 `a`인 데이터를 찾으려면 `_`를 사용한다.

```SQL
SELECT
    LastName, FirstName
FROM
    customers
WHERE
    -- _ 세 개는 앞의 세 글자를 의미하고, 마지막 글자는 a로 고정한다.
    FirstName LIKE '___a';
```

![LIKE와 _를 사용한 문자열 패턴 조회 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 184659.png>)

⚠️ 주의: `WHERE`는 개별 행을 대상으로 조건을 검사한다. 나중에 나오는 `HAVING`은 그룹화된 결과를 대상으로 조건을 검사한다. 이 둘의 차이를 구분해야 집계 쿼리에서 헷갈리지 않는다.

📌 핵심: `DISTINCT`는 중복 제거, `WHERE`는 조건 필터링, `LIKE`는 문자열 패턴 검색에 사용한다.

## 3.8 LIMIT: 조회 결과 개수 제한하기

`LIMIT`은 조회 결과에서 가져올 행의 개수를 제한할 때 사용한다. 데이터가 아주 많을 때 전체를 한 번에 가져오면 결과를 확인하기 어렵고 성능에도 부담이 될 수 있다. 이때 `LIMIT`을 사용하면 필요한 개수만 조회할 수 있다.

```SQL
SELECT
    select_list
FROM
    table_name
-- row_count는 가져올 최대 행 수이다.
LIMIT [offset,] row_count;
```

`LIMIT`은 하나의 숫자만 사용할 수도 있고, `offset`과 `row_count` 두 값을 함께 사용할 수도 있다.

### LIMIT과 OFFSET 이해하기

```SQL
SELECT
    ...
FROM
    ...
-- 앞에서 2개를 건너뛰고, 그 다음 5개를 가져온다.
LIMIT 2, 5;
```

![LIMIT과 OFFSET 구조 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 185129.png>)

여기서 첫 번째 숫자 `2`는 건너뛸 행의 개수이다. 두 번째 숫자 `5`는 실제로 가져올 행의 개수이다. 즉, `LIMIT 2, 5`는 “처음 2개를 제외하고 그다음 5개를 가져와라”라는 의미이다.

### 상위 N개 데이터 조회하기

`tracks` 테이블에서 `Bytes`가 큰 순서대로 7개만 보고 싶다면 다음처럼 작성한다.

```SQL
SELECT
    TrackId, Name, Bytes
FROM
    tracks
ORDER BY
    -- 파일 크기가 큰 순서대로 정렬한다.
    Bytes DESC
-- 정렬된 결과 중 앞에서 7개만 가져온다.
LIMIT 7;
```

![Bytes 기준 내림차순 상위 7개 조회 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 185321.png>)

### 특정 위치부터 일부만 조회하기

4번째 데이터부터 7번째 데이터까지 총 4개를 가져오고 싶다면 앞의 3개를 건너뛰고 4개를 가져오면 된다.

```SQL
SELECT
    TrackId, Name, Bytes
FROM
    tracks
ORDER BY
    Bytes DESC
-- 앞의 3개를 건너뛰고 4개를 가져온다.
LIMIT 3, 4;
```

![LIMIT offset을 사용한 부분 조회 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 185645.png>)

⚠️ 주의: 특정 위치의 데이터를 가져올 때는 `ORDER BY`를 함께 사용하는 것이 안전하다. 정렬 기준 없이 `LIMIT`만 사용하면 어떤 순서에서 잘리는지 명확하지 않을 수 있다.

📌 핵심: `LIMIT`은 결과 개수를 제한하고, `offset`을 함께 사용하면 특정 위치 이후의 데이터만 가져올 수 있다.

## 3.9 GROUP BY와 집계 함수: 데이터를 묶어서 계산하기

`GROUP BY`는 같은 값을 가진 행들을 하나의 그룹으로 묶을 때 사용한다. 단순히 행을 하나씩 조회하는 것이 아니라, 국가별 고객 수, 작곡가별 평균 파일 크기처럼 그룹 단위의 결과를 보고 싶을 때 필요하다.

```SQL
SELECT
    c1, c2, aggregate_function(ci)
FROM
    table_name
GROUP BY
    c1, c2;
```

`GROUP BY`는 보통 집계 함수와 함께 사용한다. 집계 함수는 여러 값을 계산해서 하나의 값을 반환한다.

| 집계 함수 | 의미 | 예시 |
|---|---|---|
| SUM | 합계 | 전체 판매 금액 |
| AVG | 평균 | 평균 재생 시간 |
| MAX | 최댓값 | 가장 큰 파일 크기 |
| MIN | 최솟값 | 가장 짧은 곡 길이 |
| COUNT | 개수 | 국가별 고객 수 |

### GROUP BY 기본 예시

`customers` 테이블에서 `Country`를 기준으로 그룹화하면, 같은 국가가 하나의 그룹으로 묶인다.

```SQL
SELECT
    Country
FROM
    customers
GROUP BY
    Country;
```

![Country 기준 GROUP BY 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 190121.png>)

여기에 `COUNT(*)`를 함께 사용하면 국가별 고객 수를 계산할 수 있다.

```SQL
SELECT
    Country,
    -- 각 Country 그룹에 몇 개의 행이 있는지 센다.
    COUNT(*) AS CustomerCount
FROM
    customers
GROUP BY
    Country;
```

![COUNT를 사용한 국가별 고객 수 집계 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 190231.png>)

### 평균값 계산과 정렬

`tracks` 테이블에서 `Composer`별로 `Bytes` 평균을 계산하고, 평균 파일 크기가 큰 순서대로 정렬할 수 있다.

```SQL
SELECT
    Composer,
    -- Composer 그룹별 Bytes 평균을 계산하고 별칭을 붙인다.
    AVG(Bytes) AS avgOfBytes
FROM
    tracks
GROUP BY
    Composer
ORDER BY
    -- 계산된 평균값을 기준으로 내림차순 정렬한다.
    avgOfBytes DESC;
```

![Composer별 Bytes 평균을 내림차순으로 조회하는 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 190607.png>)

강의 원문에서는 별칭이 `avg0fBytes`처럼 보였지만, 의미상 `avgOfBytes`로 읽는 것이 자연스럽다. 중요한 것은 별칭을 붙이면 이후 `ORDER BY`에서 계산 결과를 더 읽기 좋게 사용할 수 있다는 점이다.

### 그룹별 평균에 조건 걸기

`Composer`별로 `Milliseconds`를 분 단위로 바꾼 뒤 평균이 10분 미만인 데이터만 보고 싶다면, 그룹화 이후 조건이 필요하다.

![Composer별 평균 재생 시간이 10분 미만인 데이터 조회 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 191013.png>)

이때 개별 행에 대한 조건은 `WHERE`로 처리하지만, 그룹화된 평균값에 대한 조건은 `HAVING`으로 처리한다. 이 차이가 다음 섹션의 핵심이다.

📌 핵심: `GROUP BY`는 행을 그룹으로 묶고, 집계 함수는 그룹별 계산 결과를 만든다.

## 3.10 HAVING: 그룹화된 결과에 조건 걸기

`HAVING`은 집계 항목에 대한 세부 조건을 지정할 때 사용한다. 주로 `GROUP BY`와 함께 사용하며, 그룹화와 집계가 끝난 뒤 결과 그룹을 필터링한다.

```SQL
SELECT
    Composer,
    -- 밀리초를 분 단위로 바꾼 뒤 Composer별 평균을 계산한다.
    AVG(Milliseconds / 60000) AS avgMinutes
FROM
    tracks
GROUP BY
    Composer
HAVING
    -- 그룹별 평균 재생 시간이 10분 미만인 그룹만 남긴다.
    avgMinutes < 10;
```

위 코드는 `Composer`별 평균 재생 시간을 계산한 뒤, 평균이 10분 미만인 그룹만 조회한다. 여기서 `avgMinutes`는 개별 행의 값이 아니라 그룹별 집계 결과이므로 `WHERE`가 아니라 `HAVING`을 사용한다.

### WHERE와 HAVING 비교

![WHERE와 HAVING 비교 예시](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 191440.png>)

| 구분 | WHERE | HAVING |
|---|---|---|
| 목적 | 개별 행 필터링 | 그룹화된 결과 필터링 |
| 적용 시점 | `GROUP BY` 이전 | `GROUP BY`와 집계 함수 이후 |
| 주 사용 대상 | 일반 필드 조건 | 집계 함수 결과 조건 |
| 예시 | `Country = 'USA'` | `COUNT(*) >= 5` |

쉽게 말하면, `WHERE`는 “그룹으로 묶기 전에 어떤 행을 사용할 것인가”를 정한다. `HAVING`은 “묶고 계산한 뒤 어떤 그룹을 남길 것인가”를 정한다.

### SELECT 문 전체 실행 순서

조건, 그룹화, 정렬, 개수 제한까지 포함하면 `SELECT` 문의 실행 순서는 다음과 같이 이해할 수 있다.

1. `FROM`: 테이블에서 데이터를 가져온다.
2. `WHERE`: 개별 행 조건에 맞는 데이터만 남긴다.
3. `GROUP BY`: 남은 데이터를 기준 필드로 그룹화한다.
4. `HAVING`: 그룹화된 결과에 조건을 적용한다.
5. `SELECT`: 조회할 필드와 계산 결과를 선택한다.
6. `ORDER BY`: 결과를 정렬한다.
7. `LIMIT`: 특정 개수 또는 위치의 결과만 가져온다.

⚠️ 주의: 집계 함수 결과에 조건을 걸 때 `WHERE AVG(...) < 10`처럼 작성하면 오류가 나거나 의도와 다르게 동작한다. 평균, 개수, 합계처럼 그룹 계산 결과를 필터링할 때는 `HAVING`을 사용한다.

📌 핵심: `WHERE`는 그룹화 전 개별 행 조건, `HAVING`은 그룹화 후 집계 결과 조건이다.

## 3.11 NULL 비교와 SQL의 3값 논리

SQL에서 `NULL`은 실제 값이 아니라 **값이 없음** 또는 **알 수 없음**을 의미한다. 이 점 때문에 `NULL`은 일반적인 등호 `=` 연산자로 비교하면 의도한 대로 동작하지 않는다.

예를 들어 `NULL = NULL`은 `TRUE`가 아니다. 두 값이 모두 비어 있으니 같다고 생각하기 쉽지만, SQL에서는 NULL을 “값이 없다” 또는 “알 수 없다”로 보기 때문에 결과가 `UNKNOWN`이 된다.

### SQL의 3값 논리

SQL의 논리 연산 결과는 다음 세 가지로 나뉜다.

| 결과 | 의미 |
|---|---|
| TRUE | 조건이 참이다 |
| FALSE | 조건이 거짓이다 |
| UNKNOWN | 참인지 거짓인지 알 수 없다 |

`NULL`이 포함된 비교는 `UNKNOWN`이 될 수 있다. 따라서 값이 비어 있는지 확인하려면 `=`가 아니라 `IS NULL`을 사용해야 한다.

```SQL
SELECT
    LastName, FirstName, Company
FROM
    customers
WHERE
    -- Company 값이 없음을 명시적으로 확인한다.
    Company IS NULL;
```

반대로 값이 존재하는 행을 찾고 싶다면 `IS NOT NULL`을 사용한다.

```SQL
SELECT
    LastName, FirstName, Company
FROM
    customers
WHERE
    -- Company 값이 존재하는 행만 조회한다.
    Company IS NOT NULL;
```

### = 와 IS의 차이

![NULL 비교에서 = 와 IS의 차이](<../assets/images/04_27_Django_SQL_1/화면 캡처 2026-05-10 192340.png>)

`=`는 실제 값을 비교할 때 사용한다. 예를 들어 `City = 'Prague'`처럼 특정 문자열과 비교할 때 적합하다. 반면 `NULL` 여부를 확인할 때는 `IS NULL`, `IS NOT NULL`을 사용해야 한다.

⚠️ 주의: `Company = NULL`처럼 작성하면 값이 비어 있는 행을 제대로 찾지 못한다. NULL은 값이 아니라 값의 부재를 나타내므로, 반드시 `IS NULL`로 비교해야 한다.

📌 핵심: NULL은 일반 값이 아니므로 `= NULL`이 아니라 `IS NULL`로 비교한다.

## 3.12 SQL 표준과 RDBMS별 차이

SQL은 ANSI와 ISO에 의해 표준이 채택된 언어이다. 그래서 대부분의 RDBMS는 SQL 표준을 지원한다. 하지만 모든 RDBMS가 완전히 같은 문법과 기능만 제공하는 것은 아니다.

예를 들어 SQLite, MySQL, PostgreSQL, Oracle Database는 모두 SQL을 사용하지만, 세부 함수나 자료형 처리, 일부 문법은 다를 수 있다. 따라서 기본 SQL 문법을 먼저 익히되, 실제 프로젝트에서 사용하는 RDBMS의 문서와 특징을 함께 확인하는 습관이 필요하다.

💡 포인트: Django ORM을 사용하면 RDBMS 차이를 어느 정도 감춰주지만, 완전히 사라지는 것은 아니다. 특히 성능 튜닝이나 복잡한 쿼리를 작성할 때는 실제 SQL과 사용 중인 데이터베이스의 특징을 이해해야 한다.

📌 핵심: SQL에는 표준이 있지만, RDBMS마다 세부 문법과 기능 차이가 있을 수 있다.

## 4. 적용 관점에서 다시 보기

이번 강의에서 배운 내용은 단순히 SQL 문법을 외우는 데서 끝나지 않는다. 실제로 데이터를 조회하는 문제를 만나면, 먼저 “내가 원하는 결과가 어떤 형태인가?”를 생각해야 한다.

가장 기본적인 판단 흐름은 다음과 같다.

1. **어느 테이블에서 가져올 것인가?**  
   → `FROM`을 먼저 떠올린다.

2. **어떤 필드를 볼 것인가?**  
   → `SELECT`에 필요한 필드를 작성한다.

3. **개별 행 조건이 있는가?**  
   → 특정 국가, 특정 도시, 특정 범위처럼 행 단위 조건이면 `WHERE`를 사용한다.

4. **중복을 제거해야 하는가?**  
   → 고유한 목록만 필요하면 `DISTINCT`를 사용한다.

5. **정렬이 필요한가?**  
   → 오름차순 또는 내림차순 기준이 있으면 `ORDER BY`를 사용한다.

6. **일부 개수만 필요한가?**  
   → 상위 N개, 특정 구간 조회가 필요하면 `LIMIT`을 사용한다.

7. **그룹별 계산이 필요한가?**  
   → 국가별 고객 수, 작곡가별 평균처럼 그룹 단위 계산이면 `GROUP BY`와 집계 함수를 사용한다.

8. **집계 결과에 조건이 있는가?**  
   → 그룹별 평균, 그룹별 개수 같은 계산 결과에 조건이 있으면 `HAVING`을 사용한다.

SQL을 작성할 때는 작성 순서만 보고 이해하기보다 실행 순서를 함께 떠올리는 것이 좋다. 특히 `WHERE`와 `HAVING`의 차이는 시험이나 실습에서 자주 헷갈리는 부분이다. `WHERE`는 그룹화 전의 행을 걸러내고, `HAVING`은 그룹화 후의 결과를 걸러낸다는 기준을 기억하면 된다.

또한 `NULL` 비교는 실전에서 자주 발생하는 오류 포인트이다. 값이 비어 있는 행을 찾을 때 `= NULL`이라고 쓰지 말고, 반드시 `IS NULL` 또는 `IS NOT NULL`을 사용해야 한다.

## 5. 배운 점 / 느낀 점 / 확장 포인트

이번 강의의 핵심은 데이터베이스를 단순한 저장소가 아니라, 데이터를 구조적으로 관리하고 필요한 형태로 다시 꺼내 쓰는 시스템으로 이해하는 것이다. 파일과 스프레드시트도 데이터를 저장할 수 있지만, 데이터가 많아지고 관계가 복잡해질수록 관계형 데이터베이스의 필요성이 분명해진다.

SQL 문법에서는 `SELECT`와 `FROM`으로 기본 조회를 시작하고, `WHERE`, `ORDER BY`, `LIMIT`을 통해 원하는 결과에 가까워지는 과정을 배웠다. 여기에 `GROUP BY`와 집계 함수가 더해지면 단순 조회를 넘어 데이터를 요약하고 분석하는 단계로 넘어갈 수 있다.

Django 학습과 연결해서 보면, 앞으로 Model을 만들고 QuerySet을 사용할 때 내부적으로는 이러한 SQL 개념이 바탕이 된다. 예를 들어 Django에서 `filter()`, `order_by()`, `values()`, `annotate()` 같은 메서드를 사용할 때, 각각이 SQL의 어떤 절과 연결되는지 떠올리면 ORM을 훨씬 체계적으로 이해할 수 있다.

더 확장해서 학습하면 좋은 주제는 다음과 같다.

- Django Model과 데이터베이스 테이블의 관계
- Django ORM의 `filter()`, `exclude()`, `order_by()`
- `JOIN`을 통한 테이블 연결 조회
- 기본 키와 외래 키가 Django의 `ForeignKey`와 연결되는 방식
- 집계 함수와 Django의 `annotate()`, `aggregate()`

## 6. 요약 정리

📌 데이터베이스는 체계적으로 정리된 데이터의 모음이다. 데이터를 단순히 저장하는 것을 넘어, 정확하게 찾고 수정하고 연결하기 위한 구조를 제공한다.

📌 관계형 데이터베이스는 데이터를 테이블로 나누어 저장하고, 기본 키와 외래 키를 통해 테이블 사이의 관계를 만든다.

📌 DBMS는 데이터베이스를 관리하는 소프트웨어이고, RDBMS는 관계형 데이터베이스를 관리하는 소프트웨어이다. SQLite, MySQL, PostgreSQL, Oracle Database 등이 대표적이다.

📌 SQL은 관계형 데이터베이스에 요청을 보내는 언어이다. 이번 강의에서는 데이터를 조회하는 `SELECT` 문을 중심으로 학습했다.

📌 `SELECT`는 조회할 필드를 정하고, `FROM`은 데이터를 가져올 테이블을 정한다.

📌 `WHERE`는 개별 행 조건을 지정하고, `ORDER BY`는 결과를 정렬하며, `LIMIT`은 가져올 결과 개수를 제한한다.

📌 `GROUP BY`는 데이터를 그룹으로 묶고, `SUM`, `AVG`, `COUNT` 같은 집계 함수는 그룹별 계산 결과를 만든다.

📌 `HAVING`은 그룹화된 결과에 조건을 걸 때 사용한다. `WHERE`와 `HAVING`의 차이는 실행 시점의 차이로 이해해야 한다.

📌 `NULL`은 값이 없는 상태이므로 `= NULL`로 비교하지 않고, `IS NULL` 또는 `IS NOT NULL`로 비교한다.

🧠 기억할 것: SQL 문법은 외우는 것도 필요하지만, “테이블에서 가져오고 → 조건으로 거르고 → 그룹화하고 → 조회하고 → 정렬하고 → 개수를 제한한다”는 실행 흐름으로 이해하면 훨씬 오래 남는다.

## 복습용 SQL 기본 틀

마지막으로 전체 SQL 조회 흐름을 하나의 틀로 정리하면 다음과 같다.

```SQL
SELECT
    -- 5. 최종적으로 보고 싶은 필드 또는 계산 결과를 작성한다.
    select_list
FROM
    -- 1. 데이터를 가져올 테이블을 정한다.
    table_name
WHERE
    -- 2. 개별 행에 대한 조건을 작성한다.
    row_condition
GROUP BY
    -- 3. 그룹화가 필요하다면 기준 필드를 작성한다.
    group_column
HAVING
    -- 4. 그룹화된 결과에 대한 조건을 작성한다.
    group_condition
ORDER BY
    -- 6. 최종 결과의 정렬 기준을 작성한다.
    sort_column DESC
LIMIT
    -- 7. 가져올 결과 개수를 제한한다.
    row_count;
```

이 틀을 그대로 외우기보다, 각 절이 어떤 시점에 어떤 역할을 하는지 연결해서 이해하는 것이 중요하다.
