# React 18·19의 핵심 변화와 호환성 기준

- 🎯 글의 목표: React 18에서 19로 이어진 핵심 변화를 이해하고, 프로젝트 버전에 맞는 API와 타입 패키지를 선택한다.
- 🧩 핵심 키워드: `createRoot`, automatic batching, Strict Mode, Actions, `use`, React 19.2
- ⭐ 중요도: ★★★★☆ — 설치된 버전과 맞지 않는 API를 사용하면 타입·런타임 오류가 발생할 수 있다.
- 📝 한눈에 보는 내용: React 18은 현대적인 root와 동시성 기반을 도입했고, React 19는 비동기 UI와 리소스 처리 API를 확장했다. 실제 적용 전에는 프로젝트의 런타임과 타입 패키지 버전을 함께 확인한다.
- 🔗 관련 주제: Vite 설정, Effect cleanup, 폼 Actions, Suspense
- 🧱 선수 지식: React 렌더링, Hook, npm 패키지 버전

---

React 예제는 작성 시점의 버전에 따라 import 경로와 지원 API가 달라진다. 문법을 그대로 적용하기 전에 현재 프로젝트가 어떤 React와 타입 패키지를 사용하는지 확인해야 한다.

## 1. 먼저 프로젝트 버전을 확인한다

```bash
# 프로젝트 루트에서 실제 설치된 React 버전을 확인한다.
npm list react react-dom
```

예제 코드보다 설치된 `react`, `react-dom`, `@types/react`, 라우터의 주 버전이 우선이다. React 19.2는 2025년 10월 공개되었지만 모든 프로젝트가 같은 버전을 사용하는 것은 아니다.

## 2. React 18에서 정착한 기준

### `createRoot`

```tsx
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import App from './App'

// index.html에서 React가 관리할 DOM 컨테이너를 찾는다.
const container = document.getElementById('root')

// null 가능성을 검사해 createRoot에 실제 HTMLElement만 전달한다.
if (!container) {
  throw new Error('#root 요소를 찾을 수 없습니다.')
}

// React 18 이상에서 사용하는 root를 만들고 최상위 컴포넌트를 렌더링한다.
createRoot(container).render(
  // 개발 중 비순수 렌더링과 cleanup 누락을 찾도록 추가 검사를 켠다.
  <StrictMode>
    <App />
  </StrictMode>,
)
```

기존 `ReactDOM.render`는 React 18에서 deprecated되었고 React 19에서 제거되었다. 새 프로젝트는 `createRoot`를 사용한다.

### 자동 batching과 Strict Mode

React 18의 root에서는 여러 state 업데이트를 더 넓은 범위에서 batching한다. 또한 개발 Strict Mode는 재마운트를 시험해 cleanup이 빠진 Effect를 발견하도록 돕는다. 개발 중 두 번 실행되는 현상을 없애려고 Strict Mode를 바로 제거하기보다 Effect를 다시 실행해도 안전하게 고친다.

## 3. React 19의 학습 가치가 큰 변화

- form `action`에 함수를 전달하고 Actions와 pending 상태를 활용할 수 있다.
- `useActionState`, `useOptimistic`, `use` 등 비동기 UI를 위한 API가 추가되었다.
- 함수 컴포넌트에서 `ref`를 일반 prop처럼 받을 수 있다.
- `<Context value={...}>` 문법으로 Provider를 작성할 수 있다.
- 문서 metadata와 stylesheet 같은 리소스 처리 기능이 확장되었다.
- 현대 JSX transform이 필수이며 여러 deprecated API가 제거되었다.

이 기능은 React 기초를 대체하지 않는다. state, 순수 렌더링, 이벤트, Effect, 폼의 원리를 이해한 뒤 버전별 API를 학습한다.

## 4. React 19.2를 대하는 방법

19.2에는 `<Activity />`, `useEffectEvent`, 성능 프로파일 트랙 등이 추가되었다. 초보 단계에서 모든 새 API를 암기할 필요는 없다.

- `<Activity />`는 조건부 렌더링과 동일한 문법 치환이 아니라 숨겨진 UI의 state와 작업 우선순위를 다루는 기능이다.
- `useEffectEvent`는 Effect의 이벤트 성격 로직을 분리하지만 의존성 규칙을 회피하는 도구로 쓰지 않는다.
- 성능 기능은 실제 병목을 측정한 뒤 적용한다.

## 5. TypeScript 업그레이드 점검

React 19로 올릴 때 런타임 패키지만 바꾸지 않는다.

```bash
# React와 React DOM 런타임의 같은 주 버전을 설치한다.
npm install --save-exact react@^19 react-dom@^19

# TypeScript가 읽는 React 타입 선언도 같은 주 버전으로 맞춘다.
npm install --save-dev --save-exact @types/react@^19 @types/react-dom@^19
```

업그레이드 전에는 React 18.3을 거쳐 deprecated 경고를 확인하는 공식 가이드도 검토한다. 라이브러리가 React 내부 API나 제거된 API에 의존하는지 확인하고, lockfile과 테스트를 함께 갱신한다.

## 6. 오래된 자료를 판별하는 신호

- `ReactDOM.render(...)`를 사용한다.
- 신규 앱에 Create React App을 기본 선택으로 제시한다.
- 클래스 컴포넌트 생명주기를 새 코드의 기본으로 설명한다.
- 모든 재사용 문제에 HOC·render props·상속을 먼저 적용한다.
- 설치한 React Router 버전과 다른 패키지·API를 섞는다.

오래된 코드는 역사적 맥락으로는 가치가 있지만, 새 예제는 함수 컴포넌트·TypeScript·현재 공식 API로 다시 작성한다.

## 7. 적용 관점에서 다시 보기

업그레이드는 먼저 현재 버전과 lockfile을 확인하고, 공식 upgrade guide에서 제거되거나 deprecated된 API를 찾는 순서로 진행한다. 런타임과 `@types`를 함께 올린 뒤 빌드와 테스트를 실행하고, 한 번에 여러 주요 라이브러리까지 동시에 바꾸지 않는다.

오류가 생기면 React 버전, React DOM 버전, 타입 패키지 버전, JSX transform, 라우터와 테스트 라이브러리의 peer dependency를 차례로 확인한다. Strict Mode에서만 보이는 중복 실행은 검사를 끄기 전에 Effect의 cleanup과 순수성을 점검한다.

## 8. 배운 점 / 확장 포인트

### 8.1 새로 이해한 것

버전 숫자는 새 기능 목록만 뜻하지 않는다. 렌더링 진입점, 타입 정의, deprecated API와 주변 라이브러리 호환성까지 함께 바뀔 수 있다.

### 8.2 이전·다음 학습과의 연결

`createRoot`는 렌더링 문서와 연결되고, Actions와 `use`는 폼·데이터 패칭·Suspense로 이어진다. 기본 원리를 이해한 뒤 새 API가 어떤 반복 문제를 줄이는지 비교한다.

### 8.3 더 확인할 주제

- React 19 Actions와 `useActionState`
- `useOptimistic`의 실패 복구
- React 19.2 `Activity`
- React Compiler 적용 조건

## 9. 요약 정리

버전 부록은 기능 목록보다 **어느 버전에서 무엇이 바뀌었는지 판별하는 기준**으로 사용한다. 설치 버전을 먼저 확인하고 공식 업그레이드 가이드와 타입 패키지를 함께 본다.

🧠 기억할 것: React 업그레이드는 런타임, React DOM, 타입 선언, 주변 라이브러리와 테스트를 하나의 호환성 묶음으로 확인한다.

## 10. 미니 퀴즈

1. `ReactDOM.render` 대신 사용하는 API는 무엇인가?
2. 개발 Strict Mode에서 Effect가 다시 실행될 때 무엇을 점검해야 하는가?
3. React 런타임과 함께 갱신해야 하는 TypeScript 패키지는 무엇인가?

<details>
<summary>정답과 해설</summary>

1. `react-dom/client`의 `createRoot`로 root를 만든 뒤 `root.render()`를 사용한다.
2. setup과 반대되는 cleanup이 있는지, 렌더링 중 side effect를 실행하지 않는지 확인한다.
3. `@types/react`와 `@types/react-dom`을 런타임의 주 버전에 맞춰 갱신한다.

</details>
