# React 18·19 자료를 읽을 때의 기준

> 학습 목표: 강의 부록의 버전별 내용을 현재 코드에 무조건 적용하지 않고, React 18에서 19로 이어진 핵심 변화와 호환성 기준을 구분한다.

## 1. 먼저 프로젝트 버전을 확인한다

```bash
npm list react react-dom
```

공부 자료의 코드보다 설치된 `react`, `react-dom`, `@types/react`, 라우터의 주 버전이 우선이다. React 19.2는 2025년 10월 공개되었지만 모든 프로젝트가 같은 버전을 사용하는 것은 아니다.

## 2. React 18에서 정착한 기준

### `createRoot`

```tsx
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import App from './App'

const container = document.getElementById('root')

if (!container) {
  throw new Error('#root 요소를 찾을 수 없습니다.')
}

createRoot(container).render(
  <StrictMode>
    <App />
  </StrictMode>,
)
```

기존 `ReactDOM.render`는 React 18에서 deprecated되었고 React 19에서 제거되었다. 새 프로젝트는 `createRoot`를 사용한다.

### 자동 batching과 Strict Mode

React 18의 root에서는 여러 state 업데이트를 더 넓은 범위에서 batching한다. 또한 개발 Strict Mode는 재마운트를 시험해 cleanup이 빠진 Effect를 발견하도록 돕는다. 개발 중 두 번 실행되는 현상을 없애려고 Strict Mode를 바로 제거하기보다 Effect를 다시 실행해도 안전하게 고친다.

## 3. React 19의 학습 가치가 큰 변화

- form `action`에 함수를 전달하고 Actions와 pending 상태를 활용할 수 있다.
- `useActionState`, `useOptimistic`, `use` 등 비동기 UI를 위한 API가 추가되었다.
- 함수 컴포넌트에서 `ref`를 일반 prop처럼 받을 수 있다.
- `<Context value={...}>` 문법으로 Provider를 작성할 수 있다.
- 문서 metadata와 stylesheet 같은 리소스 처리 기능이 확장되었다.
- 현대 JSX transform이 필수이며 여러 deprecated API가 제거되었다.

이 기능은 React 기초를 대체하지 않는다. state, 순수 렌더링, 이벤트, Effect, 폼의 원리를 이해한 뒤 버전별 API를 학습한다.

## 4. React 19.2를 대하는 방법

19.2에는 `<Activity />`, `useEffectEvent`, 성능 프로파일 트랙 등이 추가되었다. 초보 단계에서 모든 새 API를 암기할 필요는 없다.

- `<Activity />`는 조건부 렌더링과 동일한 문법 치환이 아니라 숨겨진 UI의 state와 작업 우선순위를 다루는 기능이다.
- `useEffectEvent`는 Effect의 이벤트 성격 로직을 분리하지만 의존성 규칙을 회피하는 도구로 쓰지 않는다.
- 성능 기능은 실제 병목을 측정한 뒤 적용한다.

## 5. TypeScript 업그레이드 점검

React 19로 올릴 때 런타임 패키지만 바꾸지 않는다.

```bash
npm install --save-exact react@^19 react-dom@^19
npm install --save-dev --save-exact @types/react@^19 @types/react-dom@^19
```

업그레이드 전에는 React 18.3을 거쳐 deprecated 경고를 확인하는 공식 가이드도 검토한다. 라이브러리가 React 내부 API나 제거된 API에 의존하는지 확인하고, lockfile과 테스트를 함께 갱신한다.

## 6. 오래된 자료를 판별하는 신호

- `ReactDOM.render(...)`를 사용한다.
- 신규 앱에 Create React App을 기본 선택으로 제시한다.
- 클래스 컴포넌트 생명주기를 새 코드의 기본으로 설명한다.
- 모든 재사용 문제에 HOC·render props·상속을 먼저 적용한다.
- 설치한 React Router 버전과 다른 패키지·API를 섞는다.

오래된 코드는 역사적 맥락으로는 가치가 있지만, 새 예제는 함수 컴포넌트·TypeScript·현재 공식 API로 다시 작성한다.

## 7. 요약과 복습

버전 부록은 기능 목록보다 **어느 버전에서 무엇이 바뀌었는지 판별하는 기준**으로 사용한다. 설치 버전을 먼저 확인하고 공식 업그레이드 가이드와 타입 패키지를 함께 본다.

1. `ReactDOM.render` 대신 사용하는 API는 무엇인가?
2. 개발 Strict Mode에서 Effect가 다시 실행될 때 무엇을 점검해야 하는가?
3. React 런타임과 함께 갱신해야 하는 TypeScript 패키지는 무엇인가?
