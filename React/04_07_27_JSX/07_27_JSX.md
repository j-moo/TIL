# TypeScript로 배우는 JSX

- 🎯 글의 목표: JSX의 역할과 작성 규칙을 이해하고 `.tsx` 파일에서 안전하게 UI를 표현한다.
- 🧩 핵심 키워드: JSX, TSX, React 엘리먼트, 표현식, Fragment, `className`
- ⭐ 중요도: 상 — 이후 모든 React 컴포넌트의 반환값을 읽고 작성하는 기초다.
- 📝 한눈에 보는 내용: JSX는 HTML 문자열이 아니라 JavaScript 안에서 HTML과 비슷한 마크업을 작성하는 문법 확장이다.
- 🔗 관련 주제: React 엘리먼트, 렌더링, 컴포넌트, Props
- 🧱 선수 지식: HTML 태그, JavaScript 변수·함수·객체, TypeScript 기본 타입

---

## 1. 들어가며

웹 화면은 마크업과 동작이 서로 밀접하게 연결되어 있다. 버튼의 모양만 바뀌어도 클릭 처리 코드가 함께 바뀌는 경우가 많다.

React는 관련된 마크업과 렌더링 로직을 컴포넌트 안에 함께 둔다. 이때 JavaScript 또는 TypeScript 코드 안에서 HTML과 비슷한 구조를 표현하게 해 주는 문법이 JSX다.

TypeScript 프로젝트에서는 JSX가 들어간 파일의 확장자로 주로 `.tsx`를 사용한다.

## 2. 핵심 개념 정리

```text
TypeScript 값과 렌더링 로직
              ↓
        TSX 안에서 JSX 작성
              ↓
  빌드 도구가 JavaScript 호출로 변환
              ↓
   React가 UI 설명인 엘리먼트 생성
              ↓
       React DOM이 화면에 반영
```

JSX와 React는 같은 것이 아니다.

- React는 UI를 구성하고 렌더링하는 라이브러리다.
- JSX는 JavaScript 안에서 마크업을 표현하는 문법 확장이다.
- JSX를 사용하지 않고도 React 엘리먼트를 만들 수 있지만, JSX가 더 읽기 쉬운 경우가 많다.

## 3. 본문 정리

### 3.1 JSX는 HTML 문자열이 아니다

다음 코드는 HTML 파일에 적힌 문자열이 아니다.

```tsx
const element = <h1>Hello, React!</h1>
```

JSX는 빌드 과정에서 일반 JavaScript 코드로 변환된다. 개념적으로는 다음 코드와 비슷한 결과를 만든다.

```tsx
import { createElement } from 'react'

const element = createElement('h1', null, 'Hello, React!')
```

현대 React 빌드 환경은 자동 JSX 런타임을 사용할 수 있으므로 모든 JSX가 실제 소스에서 `React.createElement()` 호출로 그대로 변환된다고 외울 필요는 없다. 중요한 점은 **JSX가 브라우저가 직접 읽는 HTML이 아니라 빌드 과정에서 JavaScript로 변환되는 문법**이라는 것이다.

⚠️ 원본 필기의 다음 코드는 태그에 오탈자가 있어 실행되지 않는다.

```tsx
// 잘못된 코드
const element = <h1?>Hello, world!</h1>
```

수정하면 다음과 같다.

```tsx
const element = <h1>Hello, world!</h1>
```

### 3.2 JSX와 TSX의 차이

JSX는 문법의 이름이고, TSX는 TypeScript 코드에서 JSX를 사용할 때 쓰는 파일 형식이다.

```text
.jsx
→ JavaScript + JSX

.tsx
→ TypeScript + JSX
```

예를 들어 Props 타입을 함께 작성하려면 `.tsx` 파일을 사용한다.

```tsx
type GreetingProps = {
  name: string
}

function Greeting({ name }: GreetingProps) {
  return <h1>안녕하세요, {name}님!</h1>
}
```

TypeScript는 `<Greeting name={123} />`처럼 잘못된 값을 전달하면 실행 전에 오류를 알려준다.

### 3.3 JSX의 기본 규칙

#### 하나의 루트 요소를 반환한다

컴포넌트는 여러 형제 요소를 그대로 반환할 수 없다.

```tsx
// 잘못된 예
function Profile() {
  return (
    <h1>김종무</h1>
    <p>React 학습 중</p>
  )
}
```

부모 태그로 묶거나 Fragment를 사용한다.

```tsx
function Profile() {
  return (
    <>
      <h1>김종무</h1>
      <p>React 학습 중</p>
    </>
  )
}
```

Fragment `<>...</>`는 요소를 그룹으로 묶지만 실제 DOM에 불필요한 태그를 추가하지 않는다.

#### 모든 태그를 닫는다

```tsx
function Avatar() {
  return <img src="/profile.png" alt="프로필" />
}
```

HTML에서는 생략 가능한 닫는 태그가 있어도 JSX에서는 명시적으로 닫아야 한다.

#### 대부분의 속성은 camelCase로 작성한다

```tsx
function Notice() {
  return (
    <p className="notice" onClick={() => console.log('클릭')}>
      알림
    </p>
  )
}
```

- HTML의 `class` → JSX의 `className`
- HTML의 `onclick` → JSX의 `onClick`
- `aria-*`, `data-*`는 하이픈 형태를 유지한다.

### 3.4 중괄호는 JavaScript 표현식으로 들어가는 창이다

JSX 안에서 문자열을 그대로 쓸 때는 따옴표를 사용한다.

```tsx
const imagePath = '/profile.png'

function Avatar() {
  return <img src="/profile.png" alt="프로필" />
}
```

변수나 계산 결과를 사용할 때는 중괄호를 사용한다.

```tsx
const userName: string = '김종무'
const score: number = 90

function Result() {
  return <p>{userName}님의 점수는 {score + 10}점입니다.</p>
}
```

중괄호 안에는 **문장(statement)**이 아니라 값을 만드는 **표현식(expression)**이 들어간다.

```tsx
// 가능
<p>{score >= 60 ? '통과' : '재도전'}</p>

// if 문은 값을 바로 만드는 표현식이 아니므로 이 위치에 직접 쓸 수 없다.
```

속성에서도 `=` 바로 뒤에 중괄호를 사용할 수 있다.

```tsx
const size: number = 120

function Avatar() {
  return (
    <img
      src="/profile.png"
      alt="프로필"
      width={size}
      height={size}
    />
  )
}
```

`src="{imagePath}"`는 변수 값이 아니라 문자 그대로 `"{imagePath}"`를 전달하므로 주의한다.

### 3.5 객체를 전달할 때 중괄호가 두 겹인 이유

```tsx
function Box() {
  return (
    <div style={{ backgroundColor: 'navy', color: 'white' }}>
      TypeScript와 React
    </div>
  )
}
```

두 겹의 중괄호는 별도의 JSX 문법이 아니다.

```text
바깥 { }
→ JSX에서 JavaScript 표현식을 사용

안쪽 { backgroundColor: ... }
→ JavaScript 객체 리터럴
```

인라인 스타일의 속성 이름도 `background-color`가 아니라 `backgroundColor`처럼 camelCase로 작성한다.

### 3.6 JSX로 만든 것은 React 엘리먼트다

```tsx
const title = <h1 className="greeting">Hello, React!</h1>
```

`title`에는 실제 DOM 노드가 즉시 저장되는 것이 아니다. React가 어떤 UI를 만들지 설명하는 React 엘리먼트가 들어간다.

```text
JSX 작성
→ React 엘리먼트 생성
→ React가 렌더링 결과 계산
→ 필요한 DOM 생성 또는 변경
```

React 엘리먼트와 Props는 생성 후 직접 수정하지 않는 불변의 설명값으로 다룬다. 새로운 화면이 필요하면 기존 엘리먼트를 바꾸는 대신 새로운 렌더링 결과를 만든다.

### 3.7 JSX와 보안

React는 JSX 중괄호에 넣은 문자열을 렌더링할 때 기본적으로 텍스트로 처리한다.

```tsx
const userInput = '<img src=x onerror=alert(1)>'

function Comment() {
  return <p>{userInput}</p>
}
```

위 문자열은 일반적으로 HTML 태그로 실행되지 않고 화면에 텍스트로 표시된다. 이 동작은 대표적인 XSS(Cross-Site Scripting) 위험을 줄여 준다.

그러나 “JSX를 사용하면 모든 보안 문제가 자동으로 해결된다”는 뜻은 아니다.

- `dangerouslySetInnerHTML`로 검증되지 않은 HTML을 넣지 않는다.
- 사용자 입력으로 만든 URL도 허용할 형식인지 검사한다.
- 서버와 클라이언트 양쪽에서 입력값을 목적에 맞게 검증한다.

## 4. 적용 관점에서 다시 보기

JSX 오류가 생기면 다음 순서로 확인한다.

1. 파일 확장자가 `.tsx`인지 확인한다.
2. 여러 요소가 하나의 부모 또는 Fragment로 묶였는지 확인한다.
3. 모든 태그가 닫혔는지 확인한다.
4. `className`, `onClick`처럼 React 속성 이름을 사용했는지 확인한다.
5. 동적 값이 따옴표가 아니라 `{}` 안에 들어갔는지 확인한다.
6. 중괄호 안의 코드가 값을 만드는 표현식인지 확인한다.

## 5. 배운 점 / 확장 포인트

### 5.1 새로 이해한 것

- JSX는 JavaScript와 HTML을 단순히 이어 붙인 문자열이 아니다.
- JSX는 UI 구조를 설명하는 React 엘리먼트로 변환된다.
- TypeScript에서는 `.tsx`와 Props 타입을 사용해 잘못된 값을 미리 찾을 수 있다.

### 5.2 이전·다음 학습과의 연결

마크업은 내용의 구조와 의미를 표현한다. JSX는 이 마크업을 컴포넌트의 렌더링 로직과 가까운 곳에 둔다. 다음에는 JSX가 만든 엘리먼트가 실제 화면에 반영되는 렌더링 과정을 학습한다.

### 5.3 더 확인할 주제

- 조건부 렌더링
- 배열의 `map()`과 `key`
- 접근성을 고려한 시맨틱 HTML

## 6. 요약 정리

1. JSX는 JavaScript 안에서 HTML과 비슷한 마크업을 작성하는 문법 확장이다.
2. TypeScript와 JSX를 함께 쓰는 파일은 일반적으로 `.tsx` 확장자를 사용한다.
3. JSX는 하나의 루트 요소를 반환하고 모든 태그를 닫아야 한다.
4. 동적 값은 `{}` 안에 작성하며, 속성의 문자열은 따옴표로 작성한다.
5. JSX는 React 엘리먼트를 만들고 React가 이를 바탕으로 화면을 계산한다.
6. JSX 문자열 이스케이프는 XSS 위험을 줄이지만 모든 보안을 대신하지는 않는다.

🧠 기억할 것: JSX는 “HTML을 JavaScript에 넣은 문자열”이 아니라 “현재 UI가 어떤 모습이어야 하는지 표현하는 JavaScript 문법”이다.

## 7. 미니 퀴즈

1. JSX와 React는 어떤 차이가 있는가?
2. `.ts` 대신 `.tsx`가 필요한 경우는 언제인가?
3. `class="card"`가 아니라 `className="card"`라고 쓰는 이유는 무엇인가?
4. `src="{imagePath}"`와 `src={imagePath}`는 어떻게 다른가?
5. Fragment를 사용하면 실제 DOM에는 무엇이 추가되는가?

<details>
<summary>정답과 해설</summary>

1. React는 UI 라이브러리이고 JSX는 JavaScript의 문법 확장이다.
2. TypeScript 파일 안에 JSX를 작성할 때 `.tsx`를 사용한다.
3. JSX 속성이 JavaScript 객체의 키로 변환되며 `class`는 JavaScript 예약어이기 때문이다.
4. 앞은 `"{imagePath}"`라는 문자열이고 뒤는 변수의 실제 값이다.
5. Fragment 자체에 해당하는 DOM 태그는 추가되지 않는다.

</details>
