# 1. 뱀 게임 시뮬레이션

> 한 줄 소개: 몸통을 deque로 관리하고, 충돌 판정은 set으로 빠르게 처리하는 구현 문제

- 📚 문제 출처: CodeTree/SWEA 유형 기반 대화 정리

- 🔗 문제 링크: 대화 내 별도 링크 미제공

- 🧭 문제 유형: 시뮬레이션 / deque

- 🎯 핵심 목표: 뱀이 이동하다가 벽 또는 자기 몸과 충돌하는 시간을 구한다.

- 🧩 핵심 키워드: deque, set, 사과 처리, 꼬리 제거 순서, 충돌 판정

- ⭐ 난이도: 중

- 🛠 사용 알고리즘: 시뮬레이션, 큐


## 1. Intro
이 문제는 한 칸씩 이동하는 뱀의 상태를 정확히 갱신하는 것이 핵심이었다. 처음에는 머리 이동, 꼬리 제거, 사과 처리, 충돌 판정이 한꺼번에 섞여 복잡해 보였지만, 상태 갱신 순서를 분리하면 구현 난도가 크게 내려간다.


## 2. 문제 이해
뱀은 매초 머리를 한 칸 이동한다. 이동한 칸에 사과가 있으면 길이가 늘어나므로 꼬리를 제거하지 않고, 사과가 없으면 꼬리를 제거한다. 격자를 벗어나거나 자기 몸과 겹치면 게임이 종료된다.


## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **뱀이 이동하다가 벽 또는 자기 몸과 충돌하는 시간을 구한다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식
몸통 전체를 리스트로 매번 검사하면 충돌 확인이 느리고 구현도 복잡해진다. 그래서 몸통의 순서는 deque, 현재 몸 좌표 존재 여부는 set으로 나누어 관리하는 방식으로 접근했다.


## 5. 풀이 핵심 아이디어
1) 현재 방향으로 다음 머리 좌표를 계산한다.
2) 벽을 벗어나면 종료한다.
3) 사과가 없는 경우에는 꼬리를 먼저 제거한다.
4) 그 뒤 다음 머리가 body_set에 있으면 자기 몸 충돌이다.
5) 충돌이 아니면 머리를 추가한다.


## 6. 구현 과정에서의 포인트
가장 헷갈리는 부분은 사과가 없을 때 자기 몸 충돌을 검사하기 전에 꼬리를 먼저 제거해야 한다는 점이다. 꼬리가 빠져나갈 칸은 같은 초에 비워지기 때문이다.


## 7. 디버깅 또는 시행착오
처음에는 머리 이동 후 바로 body_set으로 충돌을 검사하려고 해서, 꼬리가 빠져나가는 칸으로 이동하는 정상 상황까지 충돌로 볼 위험이 있었다. 사과 유무에 따라 꼬리 제거 순서를 명확히 나누는 것이 디버깅 포인트였다.


## 8. 코드

```python
from collections import deque

# snake: 뱀의 몸 좌표를 순서대로 저장한다. 왼쪽이 꼬리, 오른쪽이 머리
snake = deque([(0, 0)])
body = {(0, 0)}          # 현재 몸이 차지하는 좌표를 O(1)에 확인하기 위한 set
time = 0
direction = 0            # 0: 오른쪽, 1: 아래, 2: 왼쪽, 3: 위
di = [0, 1, 0, -1]
dj = [1, 0, -1, 0]

while True:
    time += 1
    head_i, head_j = snake[-1]
    ni = head_i + di[direction]
    nj = head_j + dj[direction]

    # 1. 벽 충돌 확인
    if not (0 <= ni < n and 0 <= nj < n):
        break

    # 2. 사과가 없다면 꼬리가 먼저 빠진다.
    # 주의: 꼬리가 빠지는 칸으로 머리가 이동할 수 있으므로,
    # 자기 몸 충돌 검사는 꼬리 제거 이후에 해야 한다.
    if (ni, nj) not in apples:
        tail = snake.popleft()
        body.remove(tail)
    else:
        apples.remove((ni, nj))

    # 3. 자기 몸 충돌 확인
    if (ni, nj) in body:
        break

    # 4. 새 머리 추가
    snake.append((ni, nj))
    body.add((ni, nj))

print(time)
```

# 2. 비 피할 거리 BFS

> 한 줄 소개: 여러 대피소를 동시에 시작점으로 넣어 모든 칸의 최단거리를 한 번에 계산하는 문제

- 📚 문제 출처: CodeTree/SWEA 유형 기반 대화 정리

- 🔗 문제 링크: 대화 내 별도 링크 미제공

- 🧭 문제 유형: BFS / 최단거리

- 🎯 핵심 목표: 각 사람 위치에서 가장 가까운 대피소까지의 거리를 구한다.

- 🧩 핵심 키워드: multi-source BFS, 거리 배열, 벽 처리, 시작점 여러 개

- ⭐ 난이도: 중

- 🛠 사용 알고리즘: BFS


## 1. Intro
처음에는 사람 위치마다 BFS를 돌리는 방식이 떠오를 수 있지만, 대피소가 여러 개인 경우에는 반대로 모든 대피소에서 동시에 BFS를 시작하는 편이 효율적이다. 이 방식은 각 칸에서 가장 가까운 대피소까지의 거리를 자연스럽게 계산해 준다.


## 2. 문제 이해
격자에는 빈칸, 벽, 사람, 대피소가 존재한다. 벽은 지나갈 수 없고, 사람마다 가장 가까운 대피소까지의 최단거리를 알아야 한다.


## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **각 사람 위치에서 가장 가까운 대피소까지의 거리를 구한다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식
모든 대피소를 큐에 먼저 넣고 BFS를 시작한다. BFS의 특성상 먼저 도달한 거리가 최단거리이므로, 각 사람 칸의 dist 값을 읽으면 답이 된다.


## 5. 풀이 핵심 아이디어
1) grid 값이 3인 대피소를 모두 큐에 넣고 dist를 0으로 둔다.
2) BFS로 벽이 아닌 칸을 확장한다.
3) grid 값이 2인 사람 위치의 dist를 확인한다.


## 6. 구현 과정에서의 포인트
visited를 True/False로만 둘 수도 있지만, 이 문제에서는 거리가 필요하므로 dist 배열에 -1과 거리를 함께 저장하는 방식이 더 깔끔하다.


## 7. 디버깅 또는 시행착오
대화 중에는 `grid[i][j] == 2` 조건, `visited[i][j] = True`, `cnt` 대신 `dist` 사용, 벽 조건을 `grid[ni][nj] == 1`로 처리하는 점이 핵심 수정 포인트였다.


## 8. 코드

```python
from collections import deque

dist = [[-1] * n for _ in range(n)]
q = deque()

# 모든 대피소를 시작점으로 넣는다.
for i in range(n):
    for j in range(n):
        if grid[i][j] == 3:
            q.append((i, j))
            dist[i][j] = 0

di = [-1, 1, 0, 0]
dj = [0, 0, -1, 1]

while q:
    i, j = q.popleft()

    for d in range(4):
        ni = i + di[d]
        nj = j + dj[d]

        if not (0 <= ni < n and 0 <= nj < n):
            continue
        if grid[ni][nj] == 1:       # 벽은 이동 불가
            continue
        if dist[ni][nj] != -1:      # 이미 최단거리 확정
            continue

        dist[ni][nj] = dist[i][j] + 1
        q.append((ni, nj))

# 사람 위치의 dist 값이 가장 가까운 대피소까지의 거리다.
for i in range(n):
    for j in range(n):
        if grid[i][j] == 2:
            print(dist[i][j])
```

# 3. 정수 1 만들기

> 한 줄 소개: 숫자를 노드로 보고 연산을 간선으로 해석하는 최단거리 문제

- 📚 문제 출처: CodeTree/SWEA 유형 기반 대화 정리

- 🔗 문제 링크: 대화 내 별도 링크 미제공

- 🧭 문제 유형: BFS / 최단 연산

- 🎯 핵심 목표: -1, +1, /2, /3 연산을 사용해 N을 1로 만드는 최소 연산 횟수를 구한다.

- 🧩 핵심 키워드: BFS, 최단거리, 상태 그래프, 방문 배열

- ⭐ 난이도: 중

- 🛠 사용 알고리즘: BFS


## 1. Intro
처음에는 재귀적으로 모든 연산을 시도하는 방식이 떠오르지만, 이 문제는 최소 연산 횟수를 묻기 때문에 BFS가 더 자연스럽다. 숫자 하나를 하나의 상태로 보고, 가능한 연산 결과를 다음 상태로 확장하면 된다.


## 2. 문제 이해
현재 수에서 1을 빼거나 더할 수 있고, 2 또는 3으로 나누어떨어지면 나눌 수 있다. 목표는 N에서 1까지 가는 가장 짧은 연산 횟수다.


## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **-1, +1, /2, /3 연산을 사용해 N을 1로 만드는 최소 연산 횟수를 구한다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식
N에서 시작해 가능한 다음 숫자들을 BFS로 탐색한다. 처음으로 1에 도달하는 순간의 거리가 최소 연산 횟수다.


## 5. 풀이 핵심 아이디어
1) dist[N] = 0으로 시작한다.
2) x-1, x+1, x//2, x//3을 후보로 만든다.
3) 범위 안이고 방문하지 않은 수만 큐에 넣는다.
4) 1에 도달하면 종료한다.


## 6. 구현 과정에서의 포인트
`+1` 연산이 있으므로 탐색 범위를 너무 작게 잡으면 안 된다. 문제 제한에 맞춰 충분한 상한을 두거나, 일반적으로 `2 * N + 2` 정도를 사용할 수 있다.


## 7. 디버깅 또는 시행착오
재귀 DFS는 같은 수를 반복해서 방문하거나 깊이가 무한히 늘어날 수 있다. 최소 횟수 문제이므로 상태별 방문 처리가 있는 BFS가 안정적이다.


## 8. 코드

```python
from collections import deque

limit = 2 * n + 2
dist = [-1] * (limit + 1)

q = deque([n])
dist[n] = 0

while q:
    x = q.popleft()

    if x == 1:
        print(dist[x])
        break

    candidates = [x - 1, x + 1]

    if x % 2 == 0:
        candidates.append(x // 2)
    if x % 3 == 0:
        candidates.append(x // 3)

    for nx in candidates:
        if 1 <= nx <= limit and dist[nx] == -1:
            dist[nx] = dist[x] + 1
            q.append(nx)
```

코드는 문제를 한 번에 해결하려고 하기보다, 핵심 상태를 먼저 만들고 그 상태를 기준으로 갱신한다. 특히 방문 배열, DP 배열, 카운팅 딕셔너리, 포인터와 같은 자료구조가 각각 어떤 의미를 갖는지 명확히 두는 것이 중요하다.

# 4. 돌 치우기와 BFS

> 한 줄 소개: 치울 돌의 조합을 선택한 뒤 BFS를 수행하는 완전탐색 문제

- 📚 문제 출처: CodeTree/SWEA 유형 기반 대화 정리

- 🔗 문제 링크: 대화 내 별도 링크 미제공

- 🧭 문제 유형: 완전탐색 + BFS

- 🎯 핵심 목표: M개의 돌을 치웠을 때 K개의 시작점에서 도달 가능한 칸 수의 최댓값을 구한다.

- 🧩 핵심 키워드: 조합, 재귀 선택, append/pop, BFS, 격자 탐색

- ⭐ 난이도: 중상

- 🛠 사용 알고리즘: 백트래킹, BFS


## 1. Intro
이 문제는 단순 BFS가 아니라, BFS를 하기 전에 어떤 돌을 치울지 선택해야 한다. 즉, 선택 문제와 탐색 문제가 결합된 형태다.


## 2. 문제 이해
격자에 돌이 있고, 이 중 M개를 제거할 수 있다. K개의 시작점에서 이동할 수 있는 칸의 수가 최대가 되도록 돌을 골라야 한다.


## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **M개의 돌을 치웠을 때 K개의 시작점에서 도달 가능한 칸 수의 최댓값을 구한다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식
모든 돌 중 M개를 선택하고, 선택한 돌을 임시로 빈칸으로 바꾼 뒤 BFS를 실행한다. `itertools.combinations`를 쓰면 간단하지만, 대화에서는 조합 모듈 없이 재귀로 선택하는 방식도 함께 정리했다.


## 5. 풀이 핵심 아이디어
1) 돌 좌표를 리스트로 모은다.
2) 재귀로 M개의 돌을 선택한다.
3) 선택된 돌을 빈칸으로 바꾼다.
4) K개의 시작점에서 multi-source BFS를 수행한다.
5) 최대 도달 칸 수를 갱신한다.


## 6. 구현 과정에서의 포인트
재귀 선택에서는 `selected.append()` 후 재귀 호출, 끝나면 `selected.pop()`으로 되돌리는 흐름이 중요하다.


## 7. 디버깅 또는 시행착오
대화 중 코드에서는 `spllit`, `in_range` 매개변수 오타, `global = cnt`, `q.append(i, j)`, visited 초기값 등 구현 실수가 있었다. BFS 이전에 기본 문법과 방문 조건을 안정화하는 것이 먼저였다.


## 8. 코드

```python
from collections import deque

answer = 0
selected = []

def bfs():
    q = deque(starts)          # K개의 시작점을 한 번에 넣는다.
    visited = [[False] * n for _ in range(n)]

    for i, j in starts:
        visited[i][j] = True

    cnt = 0
    while q:
        i, j = q.popleft()
        cnt += 1

        for di, dj in [(-1,0), (1,0), (0,-1), (0,1)]:
            ni, nj = i + di, j + dj

            if not (0 <= ni < n and 0 <= nj < n):
                continue
            if visited[ni][nj] or grid[ni][nj] == 1:
                continue

            visited[ni][nj] = True
            q.append((ni, nj))

    return cnt

def choose_stones(idx):
    global answer

    # M개의 돌을 골랐다면 실제로 치우고 BFS
    if len(selected) == m:
        for i, j in selected:
            grid[i][j] = 0

        answer = max(answer, bfs())

        for i, j in selected:
            grid[i][j] = 1
        return

        return

    # 현재 돌을 선택하는 경우
    selected.append(stones[idx])
    choose_stones(idx + 1)
    selected.pop()

    # 현재 돌을 선택하지 않는 경우
    choose_stones(idx + 1)

choose_stones(0)
print(answer)
```

# 5. 경로의 최솟값을 최대로 만들기

> 한 줄 소개: 각 칸까지 도달했을 때 확보할 수 있는 경로 최솟값의 최댓값을 저장하는 문제

- 📚 문제 출처: CodeTree/SWEA 유형 기반 대화 정리

- 🔗 문제 링크: 대화 내 별도 링크 미제공

- 🧭 문제 유형: 격자 DP

- 🎯 핵심 목표: 오른쪽/아래로 이동하는 경로 중 지나간 값들의 최솟값이 최대가 되도록 한다.

- 🧩 핵심 키워드: DP 상태 정의, max-min 관점, 경로 최적화

- ⭐ 난이도: 중

- 🛠 사용 알고리즘: 동적 계획법


## 1. Intro
처음에는 '최솟값을 최대로 한다'는 표현이 헷갈릴 수 있다. 하지만 각 경로마다 가장 작은 값이 하나씩 정해지고, 그 값들 중 가장 큰 값을 고르는 문제라고 보면 DP로 정리할 수 있다.


## 2. 문제 이해
(1,1)에서 (N,N)까지 오른쪽 또는 아래로만 이동한다. 경로 위 값들 중 최솟값을 구했을 때, 그 최솟값이 최대가 되는 경로를 찾아야 한다.


## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **오른쪽/아래로 이동하는 경로 중 지나간 값들의 최솟값이 최대가 되도록 한다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식
`dp[i][j]`를 `(i,j)`까지 도달하는 경로 중 '경로의 최솟값'을 가장 크게 만들었을 때의 값으로 둔다.


## 5. 풀이 핵심 아이디어
위에서 오는 경우와 왼쪽에서 오는 경우를 비교한다. 어떤 칸에 들어오면 경로의 최솟값은 `min(이전까지 확보한 값, 현재 칸 값)`이 된다. 둘 중 더 큰 값을 선택한다.


## 6. 구현 과정에서의 포인트
초기값은 `dp[0][0] = grid[0][0]`이다. 첫 행과 첫 열도 같은 점화식으로 처리할 수 있도록 범위를 조심한다.


## 7. 디버깅 또는 시행착오
이 문제는 현재 칸의 값이 커도 이전 경로에 더 작은 값이 있었다면 전체 최솟값은 그 작은 값으로 유지된다는 점을 놓치기 쉽다.


## 8. 코드

```python
dp = [[0] * n for _ in range(n)]
dp[0][0] = grid[0][0]

for i in range(n):
    for j in range(n):
        if i == 0 and j == 0:
            continue

        best = -1

        if i > 0:
            # 위에서 내려오는 경우:
            # 이전 경로의 최솟값과 현재 칸 값 중 더 작은 값이 새 경로의 최솟값
            best = max(best, min(dp[i - 1][j], grid[i][j]))

        if j > 0:
            # 왼쪽에서 오는 경우도 같은 방식으로 계산
            best = max(best, min(dp[i][j - 1], grid[i][j]))

        dp[i][j] = best

print(dp[n - 1][n - 1])
```

# 6. 경로의 최대-최소 차이 최소화

> 한 줄 소개: 값의 구간을 정해놓고 그 구간 안의 칸만 지나갈 수 있는지 확인하는 문제

- 📚 문제 출처: CodeTree/SWEA 유형 기반 대화 정리

- 🔗 문제 링크: 대화 내 별도 링크 미제공

- 🧭 문제 유형: 격자 탐색 / 결정 문제

- 🎯 핵심 목표: 경로 위 최댓값과 최솟값의 차이가 최소가 되도록 한다.

- 🧩 핵심 키워드: 구간 제한, 가능성 판정, 이분탐색 또는 투포인터, reachability

- ⭐ 난이도: 상

- 🛠 사용 알고리즘: 결정 문제, BFS/DP


## 1. Intro
이 문제는 최적 경로를 바로 찾기보다, 특정 값 구간 `[low, high]` 안에서 도착이 가능한지 판정하는 식으로 바꾸면 이해가 쉬워진다. 차이를 최소화한다는 목표를 '가능한 구간의 폭을 줄이는 문제'로 바꾸는 것이 핵심이다.


## 2. 문제 이해

## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **경로 위 최댓값과 최솟값의 차이가 최소가 되도록 한다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식
가능한 값 구간을 잡고, 시작점부터 도착점까지 해당 구간 안의 칸만 지나갈 수 있는지 검사한다. 가능하면 차이를 줄여보고, 불가능하면 구간을 넓혀야 한다.


## 5. 풀이 핵심 아이디어
1) 배열의 고유값을 정렬한다.
2) low/high 후보를 잡는다.
3) `low <= grid[i][j] <= high`인 칸만 이동 가능하다고 보고 DP로 도달 가능성을 확인한다.
4) 가능한 구간 중 `high-low`의 최소를 찾는다.


## 6. 구현 과정에서의 포인트
오른쪽/아래 이동만 가능하다면 BFS 대신 boolean DP로도 도달 가능성을 검사할 수 있다.


## 7. 디버깅 또는 시행착오
경로의 실제 최솟값/최댓값을 이동하면서 모두 관리하려고 하면 상태가 커진다. 반대로 값을 구간으로 고정하면 단순한 도달 가능성 문제가 된다.


## 8. 코드

```python
def can_reach(low, high):
    # 시작점과 끝점도 반드시 구간 안에 있어야 한다.
    if not (low <= grid[0][0] <= high):
        return False
    if not (low <= grid[n - 1][n - 1] <= high):
        return False

    reachable = [[False] * n for _ in range(n)]
    reachable[0][0] = True

    for i in range(n):
        for j in range(n):
            if not (low <= grid[i][j] <= high):
                continue

            if i > 0 and reachable[i - 1][j]:
                reachable[i][j] = True
            if j > 0 and reachable[i][j - 1]:
                reachable[i][j] = True

    return reachable[n - 1][n - 1]

values = sorted(set(num for row in grid for num in row))
answer = float('inf')

for left in range(len(values)):
    for right in range(left, len(values)):
        low, high = values[left], values[right]

        if high - low >= answer:
            continue

        if can_reach(low, high):
            answer = high - low
            break

print(answer)
```

# 7. 부분수열 합과 0/1 DP

> 한 줄 소개: DFS 완전탐색이 시간초과날 때 합 가능 여부 DP로 바꾸는 문제

- 📚 문제 출처: CodeTree/SWEA 유형 기반 대화 정리

- 🔗 문제 링크: 대화 내 별도 링크 미제공

- 🧭 문제 유형: DFS → DP 전환

- 🎯 핵심 목표: 부분수열을 골라 특정 합을 만들 수 있는지 빠르게 판단한다.

- ⭐ 난이도: 중

- 🛠 사용 알고리즘: 동적 계획법


## 1. Intro
처음에는 각 원소를 고르거나 고르지 않는 DFS로 접근할 수 있다. 하지만 N이 커지면 2^N 탐색이 되어 시간초과가 발생하므로, 만들 수 있는 합을 DP로 관리하는 방식이 필요하다.


## 2. 문제 이해
각 수는 한 번만 사용할 수 있고, 일부 수를 골라 목표 합을 만들 수 있는지 확인한다.


## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **부분수열을 골라 특정 합을 만들 수 있는지 빠르게 판단한다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식

## 5. 풀이 핵심 아이디어
중요한 점은 뒤에서 앞으로 순회하는 것이다. 앞에서부터 순회하면 방금 사용한 num을 같은 단계에서 다시 사용하게 될 수 있다.


## 6. 구현 과정에서의 포인트
`dp[0] = True`는 아무것도 고르지 않으면 합 0을 만들 수 있다는 뜻이다.


## 7. 디버깅 또는 시행착오
대화에서는 `return True/False`가 필요한지, DFS가 끝까지 갔을 때 무엇을 반환해야 하는지, 그리고 시간초과가 나면 왜 DP로 바꿔야 하는지를 정리했다.


## 8. 코드

```python
dp = [False] * (target + 1)
dp[0] = True

for num in arr:
    # 뒤에서부터 돌아야 현재 num을 한 번만 사용한다.
    for s in range(target, num - 1, -1):
        if dp[s - num]:
            dp[s] = True

print("Yes" if dp[target] else "No")
```

# 8. 퀘스트 경험치 최소 시간

> 한 줄 소개: 경험치를 무게가 아니라 상태로 두고, 시간을 최소화하는 배낭 문제

- 📚 문제 출처: CodeTree/SWEA 유형 기반 대화 정리

- 🔗 문제 링크: 대화 내 별도 링크 미제공

- 🧭 문제 유형: 0/1 Knapsack

- 🎯 핵심 목표: 각 퀘스트를 최대 한 번 사용해 경험치 M 이상을 만들 때 필요한 최소 시간을 구한다.

- 🧩 핵심 키워드: 0/1 배낭, 최소 비용, 경험치 상한 처리, 역순 순회

- ⭐ 난이도: 중상

- 🛠 사용 알고리즘: 동적 계획법


## 1. Intro
이 문제는 '경험치 합은 M 이상, 시간은 최소'라는 조건 때문에 배낭 문제로 볼 수 있다. 각 퀘스트를 한 번만 사용할 수 있으므로 0/1 Knapsack 형태다.


## 2. 문제 이해
N개의 퀘스트가 있고 각 퀘스트는 경험치와 시간이 있다. 같은 퀘스트는 여러 번 진행할 수 없으며, 총 경험치가 M 이상이 되도록 하면서 시간 합을 최소화해야 한다.


## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **각 퀘스트를 최대 한 번 사용해 경험치 M 이상을 만들 때 필요한 최소 시간을 구한다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식
`dp[e]`를 경험치 e를 만들기 위한 최소 시간으로 둔다. M 이상은 모두 M으로 압축해서 관리하면 배열 크기를 줄일 수 있다.


## 5. 풀이 핵심 아이디어
퀘스트 하나를 볼 때마다 경험치 상태를 뒤에서 앞으로 순회한다. `next_exp = min(M, e + exp)`로 M 이상을 M에 모은다.


## 6. 구현 과정에서의 포인트
초기값은 INF로 두고 `dp[0] = 0`으로 시작한다.


## 7. 디버깅 또는 시행착오
대화에서는 이 문제가 2차원 DP인지 질문했고, 2차원으로 이해한 뒤 1차원 역순 순회로 압축할 수 있음을 정리했다.


## 8. 코드

```python
INF = 10**18
dp = [INF] * (m + 1)
dp[0] = 0

for exp, time in quests:
    # 같은 퀘스트를 두 번 쓰지 않기 위해 경험치를 뒤에서부터 순회한다.
    for cur_exp in range(m, -1, -1):
        if dp[cur_exp] == INF:
            continue

        next_exp = min(m, cur_exp + exp)
        dp[next_exp] = min(dp[next_exp], dp[cur_exp] + time)

print(dp[m])
```

# 9. 0, 1, 2 순서 색칠 DP

> 한 줄 소개: 마지막으로 색칠한 숫자를 상태로 저장하고, 색칠하지 않는 경우도 함께 유지하는 문제

- 📚 문제 출처: CodeTree/SWEA 유형 기반 대화 정리

- 🔗 문제 링크: 대화 내 별도 링크 미제공

- 🧭 문제 유형: 3상태 격자 DP

- 🎯 핵심 목표: 오른쪽/아래로 이동하며 0→1→2 순서에 맞춰 최대한 많이 색칠한다.

- 🧩 핵심 키워드: 3차원 DP, 상태 유지, 색칠하지 않는 선택, 현재 칸 처리

- ⭐ 난이도: 상

- 🛠 사용 알고리즘: 동적 계획법


## 1. Intro
이 문제에서 가장 헷갈렸던 지점은 '현재 칸을 색칠하지 않았는데 왜 이전 값이 그대로 내려오는가'였다. 핵심은 이동은 계속할 수 있고, 색칠은 선택이라는 점이다.


## 2. 문제 이해
격자를 오른쪽 또는 아래로 이동하면서 조건에 맞는 숫자 순서로 칸을 색칠한다. 모든 칸을 색칠해야 하는 것이 아니라, 가능한 많이 색칠하는 것이 목표다.


## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **오른쪽/아래로 이동하며 0→1→2 순서에 맞춰 최대한 많이 색칠한다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식
`dp[i][j][k]`를 `(i,j)`까지 왔을 때 마지막으로 색칠한 숫자가 k인 상태에서의 최대 색칠 횟수로 둔다.


## 5. 풀이 핵심 아이디어
현재 칸을 색칠하지 않는 경우에는 이전 상태가 그대로 이어진다. 현재 칸을 색칠하는 경우에는 마지막 숫자 k 다음에 올 수 있는 숫자인지 확인하고 갱신한다.


## 6. 구현 과정에서의 포인트
초기 상태는 아직 아무것도 색칠하지 않은 상태를 표현해야 한다. 문제 조건에 따라 `2 다음은 0`이라고 보고 `dp[0][0][2] = 0`처럼 둘 수 있다.


## 7. 디버깅 또는 시행착오
색칠하지 않는 선택을 빼면 반드시 현재 칸을 색칠해야 하는 것처럼 되어 잘못된 답이 나온다. 이동과 색칠은 다른 행동임을 분리해야 한다.


## 8. 코드

```python
INF = -10**9
dp = [[[INF] * 3 for _ in range(n)] for _ in range(n)]

# 아직 아무것도 색칠하지 않은 상태를 '마지막 숫자 2'로 두면,
# 다음에 0을 색칠할 수 있다.
dp[0][0][2] = 0

for i in range(n):
    for j in range(n):
        # 1. 위/왼쪽에서 현재 칸으로 이동한다.
        if i > 0:
            for k in range(3):
                dp[i][j][k] = max(dp[i][j][k], dp[i - 1][j][k])
        if j > 0:
            for k in range(3):
                dp[i][j][k] = max(dp[i][j][k], dp[i][j - 1][k])

        num = grid[i][j]

        # 2. 현재 칸을 색칠할 수 있다면 색칠한다.
        # 마지막으로 색칠한 숫자가 prev이면, 현재 num을 다음으로 칠할 수 있다.
        prev = (num + 2) % 3
        if dp[i][j][prev] != INF:
            dp[i][j][num] = max(dp[i][j][num], dp[i][j][prev] + 1)

print(max(dp[n - 1][n - 1]))
```

# 10. 장애물과 아이템 수집 경로 수

> 한 줄 소개: 위치뿐 아니라 지금까지 수집한 아이템 개수를 함께 상태로 둬야 하는 문제

- 📚 문제 출처: CodeTree/SWEA 유형 기반 대화 정리

- 🔗 문제 링크: 대화 내 별도 링크 미제공

- 🧭 문제 유형: 3차원 DP

- 🎯 핵심 목표: 오른쪽/아래로 이동하며 모든 아이템을 수집하는 경로 수를 구한다.

- 🧩 핵심 키워드: 3D DP, 아이템 개수 상태, 장애물, 경로 수

- ⭐ 난이도: 상

- 🛠 사용 알고리즘: 동적 계획법


## 1. Intro
처음에는 0, 1, 2 같은 셀 종류를 DP의 세 번째 차원으로 잡아야 하는지 헷갈릴 수 있다. 하지만 이 문제에서 중요한 것은 셀의 종류가 아니라, 현재까지 아이템을 몇 개 수집했는지다.


## 2. 문제 이해
격자의 시작점에서 도착점까지 오른쪽 또는 아래로 이동한다. 장애물은 지나갈 수 없고, 이동 중 모든 아이템을 반드시 수집해야 한다.


## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **오른쪽/아래로 이동하며 모든 아이템을 수집하는 경로 수를 구한다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식
`dp[i][j][k]`를 `(i,j)`에 도착했을 때 아이템을 k개 수집한 경로 수로 둔다.


## 5. 풀이 핵심 아이디어
현재 칸이 아이템이면 이전 k에서 k+1로 이동하고, 아이템이 아니면 k가 그대로 유지된다.


## 6. 구현 과정에서의 포인트
아이템 총 개수를 `item_cnt`로 세고, 정답은 `dp[n-1][m-1][item_cnt]`가 된다.


## 7. 디버깅 또는 시행착오
대화에서는 왜 k를 0/1/2가 아니라 아이템 개수로 두는지 질문했다. DP 차원은 입력값의 종류가 아니라 미래 판단에 필요한 누적 정보로 잡아야 한다.


## 8. 코드

```python
item_cnt = sum(1 for i in range(n) for j in range(m) if grid[i][j] == 2)
dp = [[[0] * (item_cnt + 1) for _ in range(m)] for _ in range(n)]

# 시작 칸 처리
start_item = 1 if grid[0][0] == 2 else 0
if grid[0][0] != 1:
    dp[0][0][start_item] = 1

for i in range(n):
    for j in range(m):
        if grid[i][j] == 1:      # 장애물
            continue

        for k in range(item_cnt + 1):
            if dp[i][j][k] == 0:
                continue

            for di, dj in [(1, 0), (0, 1)]:
                ni, nj = i + di, j + dj

                if not (0 <= ni < n and 0 <= nj < m):
                    continue
                if grid[ni][nj] == 1:
                    continue

                nk = k + 1 if grid[ni][nj] == 2 else k
                if nk <= item_cnt:
                    dp[ni][nj][nk] += dp[i][j][k]

print(dp[n - 1][m - 1][item_cnt])
```

# 11. 수직선 점 개수 질의와 좌표압축

> 한 줄 소개: 큰 좌표값을 작은 인덱스로 바꾸고 누적합으로 구간 개수를 계산하는 문제

- 📚 문제 출처: CodeTree/SWEA 유형 기반 대화 정리

- 🔗 문제 링크: 대화 내 별도 링크 미제공

- 🧭 문제 유형: 좌표압축 / prefix sum

- 🎯 핵심 목표: 여러 구간 질의에 대해 수직선 위 점의 개수를 빠르게 구한다.

- 🧩 핵심 키워드: 좌표압축, query endpoint 포함, prefix sum, bisect

- ⭐ 난이도: 중

- 🛠 사용 알고리즘: 좌표압축, 누적합


## 1. Intro
좌표값이 매우 크면 배열 인덱스로 직접 사용할 수 없다. 이때 등장하는 것이 좌표압축이고, 구간 질의가 많다면 압축된 좌표 위에 prefix sum을 만들면 된다.


## 2. 문제 이해
서로 다른 위치의 점들이 있고, 여러 질의 `[l, r]`에 대해 그 사이에 있는 점의 개수를 출력해야 한다.


## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **여러 구간 질의에 대해 수직선 위 점의 개수를 빠르게 구한다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식
점 좌표뿐 아니라 질의의 양 끝 좌표도 압축 대상에 포함한다. 그래야 질의 좌표가 점에 없더라도 정확한 인덱스를 얻을 수 있다.


## 5. 풀이 핵심 아이디어
1) 점 좌표와 질의 좌표를 모두 모아 정렬한다.
2) 좌표를 인덱스로 매핑한다.
3) 점이 있는 위치에 1을 더한다.
4) prefix sum으로 구간 개수를 계산한다.


## 6. 구현 과정에서의 포인트
질의 좌표가 주어지지 않은 상태라면 bisect를 써서 점 배열에서 직접 세는 방식도 가능하다.


## 7. 디버깅 또는 시행착오
대화에서는 '질의가 주어지지 않은 좌표는 어떻게 처리하는가'가 핵심 질문이었다. 정답은 질의 좌표를 압축에 함께 넣거나, bisect로 경계를 찾는 것이다.


## 8. 코드

```python
# points: 점 좌표 리스트
# queries: (left, right) 질의 리스트

coords = set(points)
for l, r in queries:
    coords.add(l)
    coords.add(r)

coords = sorted(coords)
idx = {x: i for i, x in enumerate(coords)}

count = [0] * len(coords)

for x in points:
    count[idx[x]] += 1

prefix = [0] * (len(coords) + 1)
for i in range(len(coords)):
    prefix[i + 1] = prefix[i] + count[i]

for l, r in queries:
    left = idx[l]
    right = idx[r]
    print(prefix[right + 1] - prefix[left])
```

# 12. 2차원 직사각형 점 개수 질의

> 한 줄 소개: x와 y를 각각 압축한 뒤 2차원 prefix sum으로 직사각형 개수를 구하는 문제

- 🔗 문제 링크: 대화 내 별도 링크 미제공

- 🧭 문제 유형: 2D 좌표압축 / 2D prefix

- 🎯 핵심 목표: 직사각형 영역 안에 포함된 점의 개수를 빠르게 구한다.

- 🧩 핵심 키워드: x/y 좌표압축, 2차원 누적합, 포함-배제

- ⭐ 난이도: 중상

- 🛠 사용 알고리즘: 좌표압축, 2D prefix sum


## 1. Intro
1차원 좌표압축을 2차원으로 확장하면, x축과 y축을 따로 압축해야 한다. 이후 격자에 점 개수를 표시하고 2차원 누적합을 만들면 직사각형 질의를 빠르게 처리할 수 있다.


## 2. 문제 이해
2차원 평면 위 점들이 주어지고, 여러 직사각형 질의 `(x1, y1, x2, y2)`에 대해 내부 점 개수를 출력해야 한다.


## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **직사각형 영역 안에 포함된 점의 개수를 빠르게 구한다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식
모든 점의 x/y, 모든 질의의 x1/x2/y1/y2를 각각 압축한다. 압축 좌표 위에 점 개수 배열을 만들고, 2D prefix sum을 계산한다.


## 5. 풀이 핵심 아이디어
직사각형 합은 `S[x2][y2] - S[x1-1][y2] - S[x2][y1-1] + S[x1-1][y1-1]` 구조로 계산한다.


## 6. 구현 과정에서의 포인트
prefix 배열을 한 칸 더 크게 만들면 인덱스가 훨씬 깔끔해진다.


## 7. 디버깅 또는 시행착오
x와 y를 하나의 좌표 리스트로 섞으면 안 된다. 각각 독립적으로 압축해야 한다.


## 8. 코드

```python
xs, ys = set(), set()

for x, y in points:
    xs.add(x)
    ys.add(y)

for x1, y1, x2, y2 in queries:
    xs.add(x1); xs.add(x2)
    ys.add(y1); ys.add(y2)

xs = sorted(xs)
ys = sorted(ys)

x_idx = {x: i for i, x in enumerate(xs)}
y_idx = {y: i for i, y in enumerate(ys)}

board = [[0] * len(ys) for _ in range(len(xs))]

for x, y in points:
    board[x_idx[x]][y_idx[y]] += 1

prefix = [[0] * (len(ys) + 1) for _ in range(len(xs) + 1)]

for i in range(len(xs)):
    for j in range(len(ys)):
        prefix[i + 1][j + 1] = (
            prefix[i][j + 1]
            + prefix[i + 1][j]
            - prefix[i][j]
            + board[i][j]
        )

for x1, y1, x2, y2 in queries:
    a = x_idx[x1]
    b = y_idx[y1]
    c = x_idx[x2]
    d = y_idx[y2]

    ans = (
        prefix[c + 1][d + 1]
        - prefix[a][d + 1]
        - prefix[c + 1][b]
        + prefix[a][b]
    )
    print(ans)
```

# 13. Union-Find 경로압축

> 한 줄 소개: find 과정에서 지나간 노드의 부모를 루트로 직접 바꾸는 최적화

- 📚 문제 출처: CodeTree/SWEA 유형 기반 대화 정리

- 🔗 문제 링크: 대화 내 별도 링크 미제공

- 🧭 문제 유형: 자료구조 개념

- 🎯 핵심 목표: 서로소 집합에서 find 연산을 빠르게 만드는 경로압축을 이해한다.

- 🧩 핵심 키워드: Union-Find, find, union, path compression, parent

- ⭐ 난이도: 중

- 🛠 사용 알고리즘: Disjoint Set Union


## 1. Intro
경로압축은 Union-Find에서 거의 필수로 등장하는 최적화다. 처음에는 부모를 왜 다시 바꾸는지 헷갈릴 수 있지만, 다음 find를 빠르게 만들기 위한 캐싱이라고 보면 이해가 쉽다.


## 2. 문제 이해
여러 원소가 집합으로 묶여 있고, 두 원소가 같은 집합인지 빠르게 판단해야 한다.


## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **서로소 집합에서 find 연산을 빠르게 만드는 경로압축을 이해한다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식
각 원소의 parent를 관리한다. `find(x)`는 x가 속한 집합의 대표 루트를 찾고, 찾는 과정에서 parent[x]를 루트로 갱신한다.


## 5. 풀이 핵심 아이디어
경로압축을 하지 않으면 트리가 길어질 수 있다. 한 번 루트를 찾은 노드는 바로 루트를 부모로 갖게 만들어 다음 탐색을 줄인다.


## 6. 구현 과정에서의 포인트
재귀 find에서 `parent[x] = find(parent[x])` 한 줄이 경로압축의 핵심이다.


## 7. 디버깅 또는 시행착오
parent[x]를 루트로 바꿔도 집합 관계는 변하지 않는다. 대표자를 더 빨리 찾도록 구조만 평평하게 바꾸는 것이다.


## 8. 코드

```python
parent = [i for i in range(n + 1)]

def find(x):
    # x가 루트가 아니라면 루트를 찾고,
    # 그 결과를 parent[x]에 바로 저장한다.
    if parent[x] != x:
        parent[x] = find(parent[x])
    return parent[x]

def union(a, b):
    root_a = find(a)
    root_b = find(b)

    if root_a == root_b:
        return

    # 간단히 번호가 작은 루트를 대표로 둔다.
    if root_a < root_b:
        parent[root_b] = root_a
    else:
        parent[root_a] = root_b

def is_same(a, b):
    return find(a) == find(b)
```

# 14. 연속 부분수열 합 M

> 한 줄 소개: 구간 합이 작으면 right를 늘리고, 크면 left를 줄이는 전형적인 투포인터 문제

- ⭐ 난이도: 중

- 🛠 사용 알고리즘: Two Pointers


## 1. Intro
이 문제는 배열 원소가 양수라는 조건 덕분에 투포인터가 가능하다. 구간을 늘리면 합이 커지고, 줄이면 합이 작아지는 단조성이 있기 때문이다.


## 2. 문제 이해
연속된 구간의 합이 M이 되는 경우의 수를 세야 한다.


## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **양수 배열에서 합이 M인 연속 부분수열의 개수를 구한다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식
left와 right가 나타내는 현재 구간을 유지하고, 구간 합에 따라 포인터를 이동한다.


## 5. 풀이 핵심 아이디어
합이 M보다 작으면 right를 늘려 더하고, M 이상이면 현재 합을 확인한 뒤 left를 빼며 줄인다.


## 6. 구현 과정에서의 포인트
right가 배열 끝에 도달한 뒤에도 left를 움직이며 남은 구간을 처리해야 한다.


## 7. 디버깅 또는 시행착오
대화에서는 시작 인덱스가 바뀌지 않아 같은 구간만 보는 문제가 있었고, left/right의 역할을 바꿨을 때 흐름이 어떻게 달라지는지도 정리했다.


## 8. 코드

```python
left = 0
right = 0
current_sum = 0
answer = 0

while True:
    # 합이 작고 right를 더 늘릴 수 있으면 오른쪽 확장
    if current_sum < m and right < n:
        current_sum += arr[right]
        right += 1

    # 더 이상 확장할 수 없다면 왼쪽을 줄이는 단계로 넘어간다.
    else:
        if current_sum == m:
            answer += 1

        if left == n:
            break

        current_sum -= arr[left]
        left += 1

print(answer)
```

# 15. B에서 하나 삭제 후 A의 부분수열 만들기

> 한 줄 소개: 왼쪽 매칭과 오른쪽 매칭을 미리 계산해 삭제 위치를 빠르게 판단하는 문제

- 📚 문제 출처: CodeTree/SWEA 유형 기반 대화 정리

- 🔗 문제 링크: 대화 내 별도 링크 미제공

- 🧭 문제 유형: LR 테크닉

- 🎯 핵심 목표: B의 원소 하나를 삭제했을 때 A의 부분수열이 되는 경우의 수를 구한다.

- 🧩 핵심 키워드: 부분수열, left match, right match, delete one, boundary

- ⭐ 난이도: 상

- 🛠 사용 알고리즘: Two Pointers, Prefix/Suffix Match


## 1. Intro
이 문제는 매번 B의 한 원소를 삭제하고 부분수열인지 검사하면 비효율적이다. 삭제 위치의 왼쪽은 앞에서 매칭하고, 오른쪽은 뒤에서 매칭해 두면 각 삭제 위치를 빠르게 판단할 수 있다.


## 2. 문제 이해
B에서 정확히 하나의 원소를 제거했을 때, 남은 수열이 A의 부분수열이 되는 삭제 위치의 개수를 구한다.


## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **B의 원소 하나를 삭제했을 때 A의 부분수열이 되는 경우의 수를 구한다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식
`L[i]`는 B[0..i]를 A에서 어디까지 매칭했는지, `R[i]`는 B[i..끝]을 A에서 어디부터 매칭할 수 있는지를 저장한다.


## 5. 풀이 핵심 아이디어
B[i]를 삭제한다고 하면, 왼쪽 부분 B[0..i-1]이 A의 어떤 위치까지 매칭되고, 오른쪽 부분 B[i+1..]이 그 이후 위치에서 매칭되면 가능하다.


## 6. 구현 과정에서의 포인트
경계 처리가 중요하다. i가 첫 원소면 왼쪽은 비어 있고, i가 마지막 원소면 오른쪽은 비어 있다.


## 7. 디버깅 또는 시행착오
대화에서는 코드를 짜기보다 풀이를 고안하는 데 집중했고, L/R 배열의 의미와 삭제 위치 판단 조건이 핵심이었다.


## 8. 코드

```python
# L[i]: B[0..i]를 A에서 매칭했을 때 마지막으로 사용한 A의 인덱스
L = [-1] * len(B)
p = 0

for i in range(len(B)):
    while p < len(A) and A[p] != B[i]:
        p += 1

    if p < len(A):
        L[i] = p
        p += 1
    else:
        L[i] = len(A)   # 매칭 실패 표시

# R[i]: B[i..끝]을 A에서 매칭했을 때 처음으로 사용한 A의 인덱스
R = [len(A)] * len(B)
p = len(A) - 1

for i in range(len(B) - 1, -1, -1):
    while p >= 0 and A[p] != B[i]:
        p -= 1

    if p >= 0:
        R[i] = p
        p -= 1
    else:
        R[i] = -1       # 매칭 실패 표시

answer = 0

for i in range(len(B)):
    left_pos = -1 if i == 0 else L[i - 1]
    right_pos = len(A) if i == len(B) - 1 else R[i + 1]

    # 삭제한 위치를 기준으로 왼쪽 매칭이 오른쪽 매칭보다 앞에 있으면 가능
    if left_pos < right_pos:
        answer += 1

print(answer)
```

# 16. 세 수의 합 K

- 🔗 문제 링크: 대화 내 별도 링크 미제공

- 🧭 문제 유형: 정렬 + 투포인터 / 해시

- 🎯 핵심 목표: 서로 다른 세 위치의 값을 골라 합이 K가 되는 경우를 센다.

- 🧩 핵심 키워드: three sum, 정렬, left/right, 중복 처리

- ⭐ 난이도: 중

- 🛠 사용 알고리즘: 정렬, 투포인터


## 1. Intro
세 수를 모두 중첩 반복문으로 고르면 O(N³)이 된다. 하나를 고정하고 나머지 두 수를 투포인터로 찾으면 O(N²)로 줄일 수 있다.


## 2. 문제 이해
서로 다른 세 인덱스 i, j, k를 골라 `arr[i] + arr[j] + arr[k] == K`가 되는 경우를 구한다.


## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **서로 다른 세 위치의 값을 골라 합이 K가 되는 경우를 센다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식
배열을 정렬한 뒤, 첫 번째 수를 고정한다. 나머지 구간에서 left/right를 움직이며 목표 합을 찾는다.


## 5. 풀이 핵심 아이디어
현재 합이 K보다 작으면 left를 증가시키고, 크면 right를 감소시킨다. 같으면 정답을 갱신한다.


## 6. 구현 과정에서의 포인트
중복 값이 있을 경우 경우의 수를 어떻게 셀지 문제 조건에 맞게 처리해야 한다.


## 7. 디버깅 또는 시행착오
대화에서는 `set`, `map`, `defaultdict`, `get()` 사용이 헷갈렸고, 변수명을 i, j, k처럼 문제 구조에 맞춰 쓰면 이해가 쉬웠다.


## 8. 코드

```python
arr.sort()
answer = 0

for i in range(n - 2):
    left = i + 1
    right = n - 1

    while left < right:
        total = arr[i] + arr[left] + arr[right]

        if total == k:
            answer += 1
            left += 1
            right -= 1
        elif total < k:
            left += 1
        else:
            right -= 1

print(answer)
```

# 17. DNA 그룹 구분

> 한 줄 소개: A그룹의 3열 패턴을 set에 넣고 B그룹과 겹치는지 확인하는 문제

- 📚 문제 출처: CodeTree/SWEA 유형 기반 대화 정리

- 🔗 문제 링크: 대화 내 별도 링크 미제공

- 🧭 문제 유형: 조합 + set

- 🎯 핵심 목표: 3개의 열을 골라 A/B 그룹을 구분할 수 있는 경우의 수를 센다.

- 🧩 핵심 키워드: column combination, tuple, set, group separation

- ⭐ 난이도: 중

- 🛠 사용 알고리즘: 조합, 해시


## 1. Intro
이 문제는 어떤 열 조합이 그룹을 구분하는지를 판단하는 문제다. 선택한 3개 열에서 A그룹이 만드는 문자열 패턴과 B그룹의 패턴이 하나라도 겹치면 구분할 수 없다.


## 2. 문제 이해
2N장의 DNA 문자열이 있고, 앞 N개는 A그룹, 뒤 N개는 B그룹이다. M개의 열 중 3개를 선택해 그룹을 구분할 수 있는지 확인해야 한다.


## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **3개의 열을 골라 A/B 그룹을 구분할 수 있는 경우의 수를 센다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식
열 3개를 고른 뒤, A그룹의 해당 문자 튜플을 set에 저장한다. B그룹에서 같은 튜플이 나오면 실패다.


## 5. 풀이 핵심 아이디어
set 조회는 O(1)이므로 각 열 조합마다 A 패턴 저장 후 B 패턴 검사를 빠르게 할 수 있다.


## 6. 구현 과정에서의 포인트
문자열을 이어붙여도 되지만, `(s[i], s[j], s[k])` 튜플로 관리하면 명확하다.


## 7. 디버깅 또는 시행착오
대화에서는 'A의 3열 문자열을 저장하고 B에서 확인하면 충분한가'가 핵심 질문이었다. 겹치는 패턴만 없으면 그룹 구분이 가능하므로 충분하다.


## 8. 코드

```python
answer = 0

for a in range(m):
    for b in range(a + 1, m):
        for c in range(b + 1, m):
            seen = set()

            # A그룹의 3열 패턴 저장
            for row in group_a:
                seen.add((row[a], row[b], row[c]))

            possible = True

            # B그룹에서 같은 패턴이 하나라도 나오면 구분 불가
            for row in group_b:
                if (row[a], row[b], row[c]) in seen:
                    possible = False
                    break

            if possible:
                answer += 1

print(answer)
```

# 18. 네 수열의 합 0

> 한 줄 소개: 네 수를 둘씩 나누어 합을 저장하고 반대값을 조회하는 문제

- 📚 문제 출처: CodeTree/SWEA 유형 기반 대화 정리

- 🔗 문제 링크: 대화 내 별도 링크 미제공

- 🧭 문제 유형: Meet-in-the-middle

- 🎯 핵심 목표: A, B, C, D에서 하나씩 골라 합이 0이 되는 경우의 수를 구한다.

- 🧩 핵심 키워드: A+B, C+D, Counter, get(target, 0), 해시

- ⭐ 난이도: 중상

- 🛠 사용 알고리즘: 해시, Meet-in-the-middle


## 1. Intro
네 수를 모두 고르면 O(N⁴)이 되어 비효율적이다. A+B 합을 먼저 저장하고, C+D의 합이 나왔을 때 그 반대값이 몇 번 있었는지 조회하면 O(N²)로 줄일 수 있다.


## 2. 문제 이해
네 개의 수열에서 각각 하나의 원소를 골라 합이 0이 되는 조합의 개수를 세야 한다.


## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **A, B, C, D에서 하나씩 골라 합이 0이 되는 경우의 수를 구한다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식
A와 B에서 만들 수 있는 모든 합을 딕셔너리에 개수로 저장한다. 이후 C와 D의 합을 보며 `-(c+d)`가 A+B에 몇 번 있었는지 더한다.


## 5. 풀이 핵심 아이디어
`ab_count.get(target, 0)`은 target이 딕셔너리에 있으면 그 개수를 가져오고, 없으면 0을 가져온다.


## 6. 구현 과정에서의 포인트
일반 dict를 쓰면 처음 등장한 합에 대해 초기화가 필요하다. `get(total, 0) + 1` 또는 `defaultdict(int)`를 쓰면 편하다.


## 7. 디버깅 또는 시행착오
대화에서는 `answer += ab_count.get(target, 0)`의 의미와 `ab_count[total] += 1`을 그냥 쓰면 KeyError가 나는 이유를 집중적으로 정리했다.


## 8. 코드

```python
ab_count = {}

for a in A:
    for b in B:
        total = a + b
        ab_count[total] = ab_count.get(total, 0) + 1

answer = 0

for c in C:
    for d in D:
        target = -(c + d)

        # target이 없으면 만들 수 있는 A+B 합이 없다는 뜻이므로 0을 더한다.
        answer += ab_count.get(target, 0)

print(answer)
```


## 9. 코드 해설

코드는 문제를 한 번에 해결하려고 하기보다, 핵심 상태를 먼저 만들고 그 상태를 기준으로 갱신한다. 특히 방문 배열, DP 배열, 카운팅 딕셔너리, 포인터와 같은 자료구조가 각각 어떤 의미를 갖는지 명확히 두는 것이 중요하다.


## 10. 코드 리뷰

### ✅ 잘한 점

- 문제를 단순 반복문으로 밀어붙이기보다, 필요한 자료구조와 상태를 분리하려고 했다.

- 디버깅 과정에서 변수의 의미와 조건문의 순서를 다시 확인했다.

### ⚠️ 아쉬운 점

### 💡 개선 아이디어

# 19. 가장 인접한 두 물건의 거리 최대화

> 한 줄 소개: 거리를 직접 답으로 두고, 해당 거리 이상으로 설치 가능한지 판정하는 문제

- 📚 문제 출처: CodeTree/SWEA 유형 기반 대화 정리

- 🔗 문제 링크: 대화 내 별도 링크 미제공

- 🧭 문제 유형: 파라메트릭 서치

- 🎯 핵심 목표: N개의 점 중 M개를 골라 가장 가까운 두 물건 사이의 거리를 최대화한다.

- 🧩 핵심 키워드: binary search on answer, possible(distance), greedy placement

- ⭐ 난이도: 중상

- 🛠 사용 알고리즘: 이분탐색, 그리디


## 1. Intro
이 문제는 어떤 위치를 고를지 직접 탐색하는 대신, '최소 거리 d를 만족하며 M개를 설치할 수 있는가'를 판정하는 방식으로 풀 수 있다. 가능한 d 중 최댓값을 찾는 전형적인 파라메트릭 서치다.


## 2. 문제 이해
서로 다른 N개의 점 위에 M개의 물건을 설치한다. 가장 가까운 두 물건의 거리를 최대한 크게 만들어야 한다.


## 3. 문제를 내 말로 다시 정리
결국 이 문제는 **N개의 점 중 M개를 골라 가장 가까운 두 물건 사이의 거리를 최대화한다.** 문제다. 입력 조건을 그대로 구현하기보다, 필요한 상태와 판단 기준을 먼저 정리해야 한다.


## 4. 내 접근 방식
점들을 정렬하고, 특정 거리 d가 주어졌을 때 왼쪽부터 가능한 한 빨리 물건을 설치한다. M개 이상 설치 가능하면 d는 가능한 거리다.


## 5. 풀이 핵심 아이디어
가능한 거리라면 더 큰 거리도 시도해야 하므로 left를 올린다. 불가능하면 거리를 줄여야 하므로 right를 내린다.


## 6. 구현 과정에서의 포인트
mid는 배열 인덱스가 아니라 '거리 후보'다. 이 점이 대화에서 가장 헷갈렸던 부분이었다.


## 7. 디버깅 또는 시행착오
처음 코드에서는 `range(mid, n)`처럼 mid를 인덱스로 사용했고, `left = mid`로 갱신해 무한 루프 위험이 있었다. 파라메트릭 서치에서는 mid의 의미를 답 후보로 고정해야 한다.


## 8. 코드

```python
points.sort()

def possible(dist):
    count = 1
    last = points[0]

    for i in range(1, n):
        if points[i] - last >= dist:
            count += 1
            last = points[i]

    return count >= m

left = 1
right = points[-1] - points[0]
answer = 0

while left <= right:
    mid = (left + right) // 2

    if possible(mid):
        # mid 거리로 설치 가능하므로 더 큰 거리도 시도한다.
        answer = mid
        left = mid + 1
    else:
        # mid 거리가 너무 크므로 줄인다.
        right = mid - 1

print(answer)
```

# 20. 윤년과 계절 출력

```python
    if y % 400 == 0:
        return True
    if y % 100 == 0:
        return False
    if y % 4 == 0:
        return True
    return False

def is_valid_date(y, m, d):
    if not (1 <= m <= 12):
        return False

    days = [0, 31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]

    if is_leap_year(y):
        days[2] = 29

    return 1 <= d <= days[m]

def get_season(m):
    if 3 <= m <= 5:
        return "Spring"
    if 6 <= m <= 8:
        return "Summer"
    if 9 <= m <= 11:
        return "Fall"
    return "Winter"

Y, M, D = map(int, input().split())

if not is_valid_date(Y, M, D):
    print(-1)
else:
    print(get_season(M))
```

# 월간 회고

이번 달 알고리즘 학습은 단순히 많은 문제를 푼 것보다, 같은 문제를 다시 설명할 수 있을 정도로 구조화했다는 점에서 의미가 있었다. 특히 내가 막혔던 부분을 그대로 남기고, 왜 틀렸는지와 다음에는 어떻게 접근할지를 정리하면서 문제풀이 기록이 단순 풀이집이 아니라 성장 기록이 되었다.


앞으로 비슷한 문제를 다시 만났을 때는 다음 순서로 접근할 것이다.

1. 문제에서 진짜로 요구하는 값을 한 문장으로 정리한다.

2. 필요한 상태가 무엇인지 먼저 정의한다.

3. 완전탐색으로 가능한지 확인하고, 시간초과가 예상되면 DP/해시/투포인터/이분탐색으로 줄일 수 있는지 판단한다.

4. 코드 작성 후 작은 반례로 초기값과 경계 조건을 검증한다.


**한 줄 성장 포인트:** 이번 달에는 '정답 코드'보다 **왜 이 풀이가 성립하는지 설명하는 힘**을 기르는 데 집중했다.
