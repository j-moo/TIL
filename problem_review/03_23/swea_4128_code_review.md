## 1. 문제 이해

이 문제는 **N개의 식재료를 정확히 N//2개씩 두 그룹으로 나눈 뒤**, 각 그룹으로 만든 음식의 맛 차이를 최소화하는 문제다.

맛은 단순히 재료 개수로 정해지는 것이 아니라, **같은 음식 안에 들어간 두 재료의 시너지 값 합**으로 계산된다.
즉, 한 음식에 포함된 재료 쌍 `(i, j)`에 대해 `S[i][j] + S[j][i]`를 모두 더한 값이 그 음식의 맛이다.

### 입력/출력 핵심
- 입력
  - 테스트케이스 수 `T`
  - 각 테스트케이스마다 재료 수 `N`
  - `N x N` 시너지 행렬
- 출력
  - `#테스트케이스번호 최소맛차이`

### 제한 조건에서 중요한 점
- 일반적으로 `N`은 짝수이며 크지 않다.
- 따라서 **완전탐색(조합)** 으로도 충분히 접근 가능하다.
- 순서가 아니라 **어떤 재료를 뽑았는가**가 중요하므로 **순열이 아니라 조합**으로 풀어야 한다.

---

## 2. 문제를 내 말로 재정의

이 문제를 더 쉽게 말하면 다음과 같다.

> **재료 N개 중 절반을 A 음식에 넣고, 나머지 절반을 B 음식에 넣는다.**
> 그리고 **A 음식의 시너지 합**과 **B 음식의 시너지 합**을 각각 계산해서,
> 그 차이가 가장 작아지는 경우를 찾는 문제다.

### 내가 헷갈릴 수 있는 조건 정리
- `N//2`개를 고르면 나머지는 자동으로 반대 음식이다.
- 시너지는 `matrix[i][j]` 하나만 보는 게 아니라 **`matrix[i][j] + matrix[j][i]`** 를 같이 봐야 한다.
- **선택된 재료끼리만** 시너지를 더한다.
- A와 B를 뒤집은 경우는 본질적으로 같은 경우지만, 현재 코드는 전체 조합을 그대로 탐색하는 방식이다.

---

## 3. 관련 개념 정리

### 1) 조합 (Combination)
이 문제는 **N개 중 N//2개를 고르는 문제**다.
즉, `[0, 1]`과 `[1, 0]`은 같은 경우이므로 순열이 아니라 조합이다.

### 2) 백트래킹 (Backtracking)
재귀를 이용해서 재료를 하나씩 선택하고,
탐색이 끝나면 다시 원래 상태로 되돌리는 방식이다.

예시 흐름:
1. i번 재료 선택
2. 다음 재료 선택 재귀 호출
3. 재귀가 끝나면 선택 해제
4. 다음 i 탐색

### 3) 방문 배열 / 선택 배열
현재 코드의 `visited`는 “방문 여부”라기보다,
**A 음식에 들어가는 재료인지 여부**를 표시하는 배열이다.

즉,
- `visited[i] == 1` → A 음식
- `visited[i] == 0` → B 음식

### 4) 시너지 계산
한 음식의 재료 목록이 주어졌을 때,
그 안의 모든 재료 쌍을 뽑아 `matrix[a][b] + matrix[b][a]`를 더해야 한다.

---

## 4. 내 풀이 아이디어 분석

### 내가 어떤 방식으로 접근했는지
이번 풀이는 **조합 + 재귀 + visited 배열** 방식이다.
핵심 아이디어는 다음과 같다.

1. `visited` 배열로 어떤 재료가 A 음식에 들어가는지 표시한다.
2. 재귀 함수 `solve(cnt, idx)`에서 `N//2`개를 고를 때까지 조합을 만든다.
3. `cnt == N//2`가 되면,
   - 선택된 재료를 A
   - 선택되지 않은 재료를 B
   로 나눈다.
4. 각각의 시너지 합을 계산해서 차이를 구하고 최소값을 갱신한다.

### 이 접근의 장점
- **문제 구조와 잘 맞는 정석적인 조합 풀이**다.
- 코드 흐름이 명확하다.
- `get_taste()`로 시너지 계산을 분리해서 역할이 잘 나뉜다.
- `idx`를 이용해 중복 조합을 막는 구조가 좋다.

### 다른 방법과 비교했을 때 특징
- 더 최적화한 코드는
  - `0번 재료를 고정`해서 중복 절반 제거
  - `pair[i][j] = arr[i][j] + arr[j][i]` 미리 계산
  같은 개선을 할 수 있다.
- 하지만 현재 코드는 **풀이 원리를 익히기에 좋은 구조**다.

### 대화를 통해 정리된 해결 과정
처음에는 다음과 같은 부분이 헷갈리거나 잘못 잡혀 있었다.

1. **조합인지 순열인지 헷갈림**
   - 이 문제는 순서가 의미 없으므로 조합으로 풀어야 했다.
2. **`N / 2` 대신 `N // 2` 사용 필요**
   - 종료 조건은 정수 기준이어야 한다.
3. **`if not visited:` 오류 가능성**
   - 리스트 전체가 아니라 `visited[i]`를 확인해야 한다.
4. **`answer = 0`이 아니라 큰 값으로 초기화해야 함**
   - 최소값 문제이므로 `float('inf')`가 맞다.
5. **입력 행렬 대괄호 중첩 실수**
   - `matrix = [list(...)]` 형태여야 한다.
6. **중간 합으로 가지치기하기는 애매함**
   - 이 문제는 최종적으로 A/B가 완성되어야 차이를 계산할 수 있으므로,
     먼저 정확한 조합 완전탐색이 더 안전하다.

## 5. 최종 풀이 전략

### 핵심 로직
- `solve(cnt, idx)`에서 **A 음식에 넣을 재료를 조합으로 선택**한다.
- `cnt == N // 2`가 되면 A/B를 나누고,
  두 음식의 시너지 합 차이를 계산한다.
- 모든 조합 중 최소 차이를 정답으로 저장한다.

### 단계별 흐름
1. `visited` 배열 준비
2. `solve(0, 0)` 호출
3. `for i in range(idx, N)`로 조합 생성
4. `visited[i] = 1` 후 재귀
5. 재귀 종료 후 `visited[i] = 0`으로 복구
6. 절반 선택 완료 시 `get_taste(A)`, `get_taste(B)` 계산
7. `answer = min(answer, abs(taste_A - taste_B))`

### 의사코드
```text
solve(cnt, idx):
    if cnt == N//2:
        visited를 기준으로 A, B 분리
        taste_A 계산
        taste_B 계산
        answer 갱신
        return

    for i in range(idx, N):
        if visited[i] == 0:
            visited[i] = 1
            solve(cnt + 1, i + 1)
            visited[i] = 0
```

## 6. 검증

### 시간복잡도
- 조합 수: 대략 `N C (N//2)`
- 각 조합마다 A, B의 시너지 계산: 대략 `O(N^2)`
- 전체는 대략 **`O((N C (N//2)) * N^2)`**

`N <= 16` 정도의 범위라면 충분히 가능하다.

### 공간복잡도
- `visited`: `O(N)`
- 재귀 호출 스택: `O(N)`
- 행렬 저장: `O(N^2)`

### 제한 조건에서 가능한 이유
- `16C8 = 12870` 수준이라 조합 탐색이 가능하다.
- 각 조합마다 시너지 계산을 하더라도 충분히 통과 가능한 범위다.

### 반례 / 예외 상황 검토
- **맛 차이가 0인 경우** → 이미 최적값이므로 더 작아질 수 없다.
- `matrix[i][i]`는 보통 의미가 없으므로 실제 계산에서 사용되지 않는다.
- `N`은 짝수라는 전제가 중요하다.

## 7. 구현 포인트

### 구현 시 주의점
- 종료 조건은 반드시 `cnt == N // 2`
- 조합 생성은 반드시 `for i in range(idx, N)`
- 시너지 계산은 `matrix[a][b] + matrix[b][a]`
- 최소값 문제이므로 `answer = float('inf')`

### 자주 실수하는 부분
- `N / 2`처럼 실수 나눗셈 사용
- `if not visited:`처럼 리스트 전체 검사
- 입력 행렬에 대괄호 하나 더 쓰기
- 순열처럼 중복 경우를 세는 실수

### 변수/함수 역할 설명
- `get_taste(food)`
  - 하나의 음식 재료 목록을 받아 시너지 총합 계산
- `solve(cnt, idx)`
  - A 음식에 넣을 재료를 조합으로 선택하는 재귀 함수
- `visited`
  - 각 재료가 A 음식에 속하는지 표시
- `answer`
  - 최소 맛 차이 저장
- `cnt`
  - 현재까지 선택한 재료 개수
- `idx`
  - 다음 탐색 시작 위치

## 8. 코드

```python
# import sys
# sys.stdin = open('input.txt', 'r')
# 로컬에서 테스트할 때만 입력 파일을 연결한다.
# SWEA 제출 시에는 보통 주석 처리하거나 제거한다.


# 음식의 맛(시너지 합)을 계산하는 함수
# food: 현재 하나의 음식에 들어간 재료 번호 리스트
# 같은 음식 안의 모든 재료 쌍에 대해 시너지 합을 구한다.
def get_taste(food):
    # 해당 음식의 총 시너지 합
    total = 0
    
    # food 안에 들어있는 재료들 중 2개씩 짝을 만든다.
    # i < j 형태로만 보므로 같은 쌍을 중복 계산하지 않는다.
    for i in range(len(food)):
        for j in range(i + 1, len(food)):
            # 현재 음식 안에서 시너지를 계산할 두 재료 번호
            a = food[i]
            b = food[j]
            
            # 문제 조건상 a->b, b->a 시너지를 모두 더해야 한다.
            total += matrix[a][b] + matrix[b][a]
            
    # 계산한 음식의 총 맛 반환
    return total


# N개의 재료 중 N//2개를 고르는 조합 함수
# cnt: 지금까지 A 음식에 넣은 재료 개수
# idx: 이번 재귀에서 탐색을 시작할 재료 인덱스
# 핵심: idx부터 탐색해야 중복 없는 조합이 된다.
def solve(cnt, idx):
    global answer

    # 종료조건
    # A 음식에 넣을 재료를 정확히 절반 고르면,
    # 나머지는 자동으로 B 음식이 된다.
    if cnt == N // 2:
        # A 음식에 들어갈 재료 목록
        A = []
        # B 음식에 들어갈 재료 목록
        B = []

        # visited를 기준으로 선택된 재료는 A,
        # 선택되지 않은 재료는 B에 넣는다.
        for i in range(N):
            if visited[i]:
                A.append(i)
            else:
                B.append(i)

        # A, B 각 음식의 총 시너지 계산
        taste_A = get_taste(A)
        taste_B = get_taste(B)

        # 두 음식의 맛 차이를 구해서 최소값 갱신
        answer = min(answer, abs(taste_A - taste_B))
        return

    # 조합 생성
    # idx부터 시작해야 이미 앞에서 고른 재료를 다시 고르지 않는다.
    for i in range(idx, N):
        # 아직 A 음식에 넣지 않은 재료라면 선택
        if not visited[i]:
            visited[i] = 1

            # 재료 하나를 더 골랐으므로 cnt + 1,
            # 다음 재료는 i 뒤에서만 보게 i + 1 전달
            solve(cnt + 1, i + 1)

            # 백트래킹: 다른 조합을 위해 선택을 원상복구
            visited[i] = 0


# 테스트케이스 개수 입력
T = int(input())

for tc in range(1, T + 1):
    # 재료 개수 입력
    N = int(input())

    # 시너지 행렬 입력
    # 주의: 대괄호를 하나 더 쓰면 3차원처럼 들어가므로 지금 형태가 맞다.
    matrix = [list(map(int, input().split())) for _ in range(N)]

    # 최소값 문제이므로 매우 큰 값으로 초기화
    answer = float('inf')

    # visited[i] == 1 이면 i번 재료가 A 음식에 들어간 상태
    visited = [0] * N

    # 아직 아무 재료도 선택하지 않았고,
    # 0번 인덱스부터 조합 탐색 시작
    solve(0, 0)

    # 문제 형식에 맞춰 정답 출력
    print(f'#{tc} {answer}')
```

## 9. 코드 해설

### 코드의 전체 흐름
이 코드는 크게 두 부분으로 나뉜다.

1. **`solve(cnt, idx)`**
   - A 음식에 들어갈 재료를 조합으로 선택
2. **`get_taste(food)`**
   - 선택이 끝난 뒤 각 음식의 시너지 합 계산

즉,
**조합 생성**과 **시너지 계산**을 분리한 구조다.

### 중요한 부분 상세 설명

#### 1) `solve(cnt, idx)`의 역할
이 함수는 현재까지 `cnt`개의 재료를 골랐고,
다음 선택은 `idx`부터 시작하겠다는 의미다.

예를 들어,
- `solve(0, 0)` → 아무것도 안 고른 상태
- `solve(1, 3)` → 재료 1개 골랐고, 다음은 3번부터 확인

이렇게 하면 `[1, 3]`을 고른 뒤 다시 `[3, 1]`을 세지 않게 된다.

#### 2) 종료조건이 왜 `cnt == N // 2`인가
A 음식에 절반만 고르면,
나머지 절반은 자동으로 B 음식이 되기 때문이다.

그래서 이 시점에서만
- A 재료 목록 생성
- B 재료 목록 생성
- 각 맛 계산
- 정답 갱신
을 수행하면 된다.

#### 3) `get_taste(food)`의 역할
하나의 음식 안에 들어간 재료 목록이 있으면,
그 안의 모든 재료 쌍을 뽑아 시너지를 더한다.

예를 들어 `food = [0, 2, 3]`이면
- `(0, 2)`
- `(0, 3)`
- `(2, 3)`
를 계산한다.

#### 4) 백트래킹 포인트
```python
visited[i] = 1
solve(cnt + 1, i + 1)
visited[i] = 0
```
이 3줄이 핵심이다.

- 먼저 재료를 선택하고
- 그 상태로 끝까지 탐색한 다음
- 다시 선택을 취소해서 다른 경우를 본다.

이 원상복구가 없으면 다음 조합 탐색이 꼬이게 된다.

### 조건문, 반복문, 재귀 흐름 설명
- `for i in range(idx, N)`
  - 조합 생성을 위해 뒤쪽 재료만 확인
- `if not visited[i]`
  - 아직 선택되지 않은 재료만 사용
- `if cnt == N // 2`
  - 절반 선택 완료 시 계산 수행

### 어디서 버그가 날 수 있는지 설명
- `N / 2`를 쓰면 실수형 비교가 되어 의도와 어긋날 수 있다.
- `if not visited:`는 리스트 전체를 보므로 잘못된 조건이다.
- `matrix = [[...]]`처럼 대괄호를 한 겹 더 쓰면 입력 구조가 깨진다.
- `visited[i] = 0`으로 복구하지 않으면 조합 탐색이 망가진다.

---

## 10. 코드 리뷰

### ✅ 잘한 점
- **조합 문제라는 방향을 제대로 잡았다.**
- `solve()`와 `get_taste()`로 **역할 분리**가 잘 되어 있다.
- `idx`를 사용해 **중복 없는 조합 생성**을 구현했다.
- `visited`를 선택 배열처럼 활용해 **A/B 그룹 분리가 직관적**이다.
- 전체 구조가 **정석적인 백트래킹 흐름**을 잘 따르고 있다.

### ⚠️ 아쉬운 점
- `visited`라는 이름은 의미상 “방문”보다 “선택”에 가까워서,
  `selected` 같은 이름이 더 직관적일 수 있다.
- 현재는 A와 B를 뒤집은 경우도 사실상 모두 탐색한다.
- `get_taste(A)`, `get_taste(B)`를 매번 새로 계산하므로 약간 비효율적일 수 있다.
- `answer == 0`일 때 즉시 종료 같은 단순 가지치기는 추가 가능하다.

### 💡 개선 아이디어
1. **0번 재료를 A에 고정**
   - A/B 대칭 중복을 절반 줄일 수 있다.
2. **pair 합 미리 계산**
   - `pair[i][j] = matrix[i][j] + matrix[j][i]`
   - 이후 계산을 더 간단하게 만들 수 있다.
3. **visited → selected 이름 변경**
   - 코드 의미 전달이 더 좋아진다.
4. **answer == 0 가지치기**
   - 최소 가능한 값이므로 더 볼 필요 없다.

### 🚨 디버깅 포인트
- 종료조건이 `cnt == N // 2`인지 확인
- 조합 반복문이 `range(idx, N)`인지 확인
- 입력 행렬이 2차원으로 잘 들어왔는지 확인
- `visited[i] = 0` 원상복구가 빠지지 않았는지 확인
- 시너지 계산에서 `matrix[a][b] + matrix[b][a]` 둘 다 더하는지 확인

## 11. 회고

### 이 문제에서 배운 점
- **재료를 나누는 문제는 결국 조합 문제로 바뀐다**는 점을 다시 확인했다.
- 순열과 조합의 차이를 실제 코드에서 어떻게 적용하는지 익힐 수 있었다.
- 종료조건, 인덱스, 선택 배열의 의미가 백트래킹에서 얼마나 중요한지 확인했다.
- 최소값 문제에서는 초기값을 `float('inf')`로 두는 습관이 중요하다.

### 다음에 비슷한 문제를 풀 때 적용할 점
- “둘로 나눈다”는 표현이 나오면 먼저 **한쪽만 고르면 다른 쪽은 자동 결정**된다고 생각하기
- 순서가 중요 없는 선택 문제는 먼저 **조합**을 떠올리기
- 처음에는 정확한 완전탐색으로 풀고,
  그 다음에 대칭 제거나 사전 계산으로 최적화하기

### 더 간단하고 효율적인 버전으로 발전시키는 방향
대화에서는 다음과 같은 개선 방향도 정리했다.

- `itertools.combinations` 사용
- `0번 재료를 A에 고정`해서 중복 절반 제거
- `pair[i][j] = arr[i][j] + arr[j][i]` 미리 계산

즉, **현재 코드는 개념 학습용으로 좋고**,
**개선 버전은 실전 최적화용으로 좋다**고 정리할 수 있다.
