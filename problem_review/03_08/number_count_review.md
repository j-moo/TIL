# 숫자 카운트

- 📚 **문제 출처:** 코드트리
- 🔗 **문제 링크:** 미기재
- 🧭 **문제 유형:** 브루트포스, 구현, 완전탐색
- 🎯 **목표:** 주어진 질문들의 1번 카운트/2번 카운트 결과를 모두 만족하는 세 자리 수의 개수를 구한다.
- 🧩 **키워드:** `완전탐색`, `후보 검사`, `스트라이크/볼 판정`, `3중 for문`
- ⭐ **난이도:** 구현형 브루트포스
- 🛠 **핵심 알고리즘:** **1부터 9까지 서로 다른 세 숫자로 만들 수 있는 모든 후보(504개)를 생성한 뒤, 각 후보가 모든 질문 조건과 일치하는지 검사한다.**

---

## 1. 문제 이해

- A는 **1부터 9까지의 서로 다른 숫자 세 개**로 이루어진 세 자리 수를 하나 정한다.
- B는 여러 개의 세 자리 수를 질문하고, A는 다음 두 값을 답해준다.
  - **1번 카운트:** 숫자와 위치가 모두 같은 개수
  - **2번 카운트:** 숫자는 존재하지만 위치가 다른 개수
- 이렇게 주어진 `N`개의 질문과 응답이 있을 때, **조건을 모두 만족하는 가능한 정답 수가 몇 개인지** 구해야 한다.

### 입력/출력 핵심

- 입력:
  - 질문 개수 `N`
  - 각 질문마다 `세 자리 수`, `1번 카운트`, `2번 카운트`
- 출력:
  - 가능한 정답 후보의 총 개수

### 제한 조건에서 중요한 점

- 세 자리 수는 **1~9**만 사용한다.
- 같은 숫자를 **중복해서 사용할 수 없다.**
- 따라서 가능한 후보는 많아 보여도 실제로는 **9P3 = 504개**뿐이다.
- 이 문제의 핵심은 규칙을 추론하는 것이 아니라, **모든 후보를 직접 검사해도 충분하다는 점을 알아내는 것**이다.

---

## 2. 문제를 내 말로 재정의

이 문제는 사실상 다음과 같다.

> **가능한 정답 후보 504개를 전부 만들어 놓고, 각 후보가 질문 결과들과 모순이 없는지 하나씩 확인하는 문제**다.

처음 보면 “어떤 수가 정답일지 추리하는 문제”처럼 보이지만,
실제로는 **후보를 전수조사하는 문제**라고 생각하면 훨씬 쉬워진다.

예를 들어 정답 후보를 `123`이라고 가정했을 때,
질문이 `327`, 결과가 `(1번 1개, 2번 1개)`라면:

- 같은 자리 같은 숫자: `2` 하나 → 1개
- 숫자는 맞지만 자리 다른 숫자: `3` 하나 → 1개

이렇게 계산해서 질문 결과와 일치하면 통과,
하나라도 다르면 그 후보는 탈락시키면 된다.

### 헷갈릴 수 있는 조건 정리

- **1번 카운트**는 숫자와 위치가 모두 같아야 한다.
- **2번 카운트**는 숫자는 있어야 하지만 위치는 달라야 한다.
- 같은 숫자를 중복해서 쓰지 않기 때문에, 한 숫자가 1번/2번 카운트에 동시에 들어가는 일은 없다.

---

## 3. 관련 개념 정리

### 1) 브루트포스(완전탐색)

가능한 답을 전부 만들어 보고 조건에 맞는지 검사하는 방식이다.

이 문제에서는 가능한 세 자리 수가:

- 첫 번째 자리: `1~9`
- 두 번째 자리: `1~9` 중 첫 번째 자리 제외
- 세 번째 자리: `1~9` 중 앞의 두 자리 제외

이므로 총 `9 × 8 × 7 = 504`개다.

즉, 경우의 수가 매우 작기 때문에 **모든 후보를 직접 검사하는 것이 가장 안전하고 직관적이다.**

### 2) 조건 검증형 탐색

이 문제는 정답을 바로 계산하는 것이 아니라,
후보 하나를 잡고 **주어진 조건들과 모두 일치하는지 검사**하는 문제다.

이런 문제의 전형적인 흐름은 다음과 같다.

1. 가능한 후보를 생성한다.
2. 각 후보에 대해 모든 질문을 확인한다.
3. 질문 결과가 하나라도 다르면 탈락시킨다.
4. 끝까지 통과한 후보만 정답으로 센다.

### 3) 1번 카운트 / 2번 카운트 판별

후보 `candidate`, 질문 `query`가 있을 때:

- 같은 인덱스에서 숫자까지 같으면 → **1번 카운트 증가**
- 같은 인덱스는 아니지만 숫자가 후보 안에 존재하면 → **2번 카운트 증가**

예시:

- 후보: `123`
- 질문: `327`

판정 결과:

- `3`은 후보에 있지만 자리 다름 → 2번 카운트 +1
- `2`는 후보에 있고 자리 같음 → 1번 카운트 +1
- `7`은 없음 → 증가 없음

## 4. 내 풀이 아이디어 분석

이번 문제에서 막히기 쉬운 이유는,
겉으로는 추리 문제처럼 보여서 **수학적으로 줄여야 할 것 같다는 압박**이 들기 때문이다.

하지만 실제로는 **정답 후보가 504개뿐**이라서,
복잡하게 생각하지 말고 전부 검사하면 된다.

### 내가 가져가야 할 접근 포인트

- “정답을 직접 찾는다”가 아니라 **“후보를 검증한다”** 라고 생각하기
- 세 자리 수 조건(1~9, 중복 없음)을 먼저 이용해서 **후보 수를 줄이기**
- 각 후보가 질문 결과와 일치하는지만 보면 되므로 구현이 단순해진다.

### 이 접근의 장점

- **구현이 직관적**이다.
- 반례를 따로 복잡하게 생각하지 않아도 된다.
- 주어진 질문 개수가 많아도, 후보 수 자체가 작아서 충분히 빠르다.
- 디버깅할 때도 특정 후보를 직접 찍어보며 검증하기 쉽다.

### 다른 방법과 비교했을 때 특징

이 문제는 백트래킹처럼 보일 수도 있지만,
사실은 **완전탐색 + 조건 검사**가 가장 깔끔하다.

복잡한 자료구조나 재귀 없이도 해결 가능하다는 점이 포인트다.

## 5. 최종 풀이 전략

### 핵심 로직 설명

1. 1부터 9까지의 숫자로 만들 수 있는 **서로 다른 세 자리 후보**를 모두 만든다.
2. 각 후보에 대해 모든 질문을 하나씩 비교한다.
3. 질문마다:
   - 같은 자리 같은 숫자 개수를 센다.
   - 숫자는 있지만 다른 자리에 있는 개수를 센다.
4. 주어진 `(1번 카운트, 2번 카운트)`와 다르면 그 후보는 탈락한다.
5. 모든 질문을 통과한 후보만 정답 개수에 포함한다.

### 흐름을 단계별로 정리

- 질문 정보 입력
- 가능한 세 자리 후보 생성
- 후보마다 질문 전부 검사
- 전부 만족하면 정답 후보 수 증가
- 최종 개수 출력

### 의사코드

```text
후보 개수 answer = 0

for 모든 가능한 세 자리 수 candidate:
    possible = True

    for 각 질문 query:
        strike = 0
        ball = 0

        for 각 자리 idx:
            if candidate[idx] == query[idx]:
                strike += 1
            elif query[idx]가 candidate 안에 있으면:
                ball += 1

        if strike, ball 이 질문 결과와 다르면:
            possible = False
            break

    if possible:
        answer += 1
```

## 6. 검증

### 시간복잡도

- 후보 개수: `9P3 = 504`
- 각 후보마다 질문 `N`개 검사
- 각 질문마다 3자리 비교

따라서 시간복잡도는 대략 **O(504 × N × 3)** 이고,
상수까지 포함해도 매우 작다.

보통은 그냥 **O(N)** 수준처럼 체감될 정도로 충분히 빠르다.

### 공간복잡도

- 질문 정보를 저장하는 리스트 외에는 큰 추가 공간이 필요 없다.
- 따라서 **O(N)**

### 제한 조건에서 가능한 이유

- 후보가 504개뿐이라서, 파이썬으로도 매우 여유롭다.
- 이 문제는 최적화보다 **정확하게 판정하는 것**이 더 중요하다.

### 반례 / 예외 상황 검토

#### 반례 1: 같은 자리와 다른 자리를 혼동하는 경우

- 후보: `123`
- 질문: `132`

이 경우:

- `1`은 같은 자리 → 1번 카운트 +1
- `3`, `2`는 숫자는 맞지만 자리 다름 → 2번 카운트 +2

즉 결과는 `(1, 2)`다.

#### 반례 2: 숫자는 있지만 질문 자리와 후보 자리가 다른 경우

- 후보: `123`
- 질문: `345`

이 경우 `3`만 포함되어 있고 자리가 다르므로 `(0, 1)`이다.

#### 반례 3: 중복 숫자를 후보에 넣는 실수

문제 조건상 `112`, `343` 같은 수는 후보가 될 수 없다.
후보 생성 단계에서 미리 제외해야 한다.

## 7. 구현 포인트

### 구현 시 주의점

- 후보 생성 시 **중복 숫자를 반드시 제거**해야 한다.
- 질문 숫자는 문자열로 바꿔두면 자리 비교가 편하다.
- `if candidate[idx] == q[idx]`를 먼저 검사하고,
  그 다음에 `elif q[idx] in candidate`를 검사해야 한다.
- 같은 자리 같은 숫자를 이미 1번 카운트로 셌는데,
  다시 2번 카운트로 세지 않도록 해야 한다.

### 자주 실수하는 부분

- 1번 카운트와 2번 카운트를 동시에 잘못 세는 실수
- `if`와 `elif` 대신 `if`, `if`를 써서 중복 카운트하는 실수
- 후보 숫자에 중복이 들어가는 실수
- 질문 결과 하나만 맞으면 통과시키고, **모든 질문을 확인하지 않는 실수**

### 변수/함수 역할 설명

- `queries` : 질문 정보 저장 리스트
- `candidate` : 현재 검증 중인 정답 후보
- `cnt1` : 1번 카운트(같은 자리 같은 숫자)
- `cnt2` : 2번 카운트(다른 자리 같은 숫자)
- `possible` : 현재 후보가 모든 질문을 만족하는지 표시
- `answer` : 최종 가능한 정답 수

## 8. 코드

```python
# 질문 개수를 입력받는다.
N = int(input())

# 질문 정보를 저장할 리스트다.
# 각 원소는 (질문 숫자 문자열, 1번 카운트, 2번 카운트) 형태로 저장한다.
queries = []

# N개의 질문 정보를 입력받는다.
for _ in range(N):
    # 질문 숫자와 두 카운트 값을 입력받는다.
    num, cnt1, cnt2 = map(int, input().split())

    # 자리 비교를 쉽게 하기 위해 숫자를 문자열로 바꿔 저장한다.
    queries.append((str(num), cnt1, cnt2))

# 가능한 정답 후보 개수를 저장할 변수다.
answer = 0

# 1부터 9까지의 숫자로 만들 수 있는 모든 세 자리 수를 탐색한다.
for i in range(1, 10):
    for j in range(1, 10):
        # 두 번째 자리는 첫 번째 자리와 같을 수 없다.
        if i == j:
            continue

        for k in range(1, 10):
            # 세 번째 자리도 앞의 두 자리와 모두 달라야 한다.
            if i == k or j == k:
                continue

            # 현재 후보를 문자열로 만든다.
            # 문자열로 만들어 두면 인덱스로 각 자리를 바로 비교할 수 있다.
            candidate = str(i) + str(j) + str(k)

            # 현재 후보가 모든 질문을 만족한다고 가정하고 시작한다.
            possible = True

            # 저장된 모든 질문과 현재 후보를 비교한다.
            for q, target1, target2 in queries:
                # 현재 질문에 대한 1번 카운트와 2번 카운트를 계산할 변수다.
                cnt1 = 0
                cnt2 = 0

                # 세 자리 각각을 비교한다.
                for idx in range(3):
                    # 같은 자리의 숫자가 같으면 1번 카운트를 올린다.
                    if candidate[idx] == q[idx]:
                        cnt1 += 1

                    # 같은 자리는 아니지만 숫자가 후보 안에 존재하면 2번 카운트를 올린다.
                    # 주의: 위에서 같은 자리는 이미 처리했기 때문에 elif를 사용해야 중복 카운트가 없다.
                    elif q[idx] in candidate:
                        cnt2 += 1

                # 계산한 카운트가 문제에서 주어진 결과와 다르면 이 후보는 탈락이다.
                if cnt1 != target1 or cnt2 != target2:
                    possible = False
                    break

            # 모든 질문을 통과한 후보만 정답 개수에 포함한다.
            if possible:
                answer += 1

# 최종 가능한 후보의 개수를 출력한다.
print(answer)
```

## 9. 코드 해설

### 코드의 전체 흐름 설명

이 코드는 크게 세 단계로 나뉜다.

1. 질문 정보 입력
2. 가능한 후보 생성
3. 각 후보가 모든 질문 조건과 맞는지 검사

핵심은 **후보를 하나 정하고, 질문들과 모순이 없는지 확인하는 구조**다.

### 중요한 부분 상세 설명

#### 1) 질문을 문자열로 저장하는 이유

```python
queries.append((str(num), cnt1, cnt2))
```

숫자로 저장해도 되지만,
문자열로 저장하면 `q[0]`, `q[1]`, `q[2]`처럼 각 자리를 바로 비교할 수 있어서 구현이 단순해진다.

#### 2) 후보 생성 부분

```python
for i in range(1, 10):
    for j in range(1, 10):
        if i == j:
            continue
        for k in range(1, 10):
            if i == k or j == k:
                continue
```

이 부분은 **1~9의 서로 다른 세 숫자**만 후보로 만들기 위한 코드다.
문제 조건에 맞지 않는 숫자는 애초에 후보에서 제외하므로,
이후 검증 과정이 훨씬 깔끔해진다.

#### 3) 1번/2번 카운트 계산

```python
if candidate[idx] == q[idx]:
    cnt1 += 1
elif q[idx] in candidate:
    cnt2 += 1
```

여기서 중요한 건 **순서와 분기 방식**이다.

- 먼저 같은 자리인지 검사해서 1번 카운트를 센다.
- 그게 아니면서 후보 안에 숫자가 있으면 2번 카운트를 센다.
- 반드시 `elif`를 써야 같은 숫자를 두 번 세지 않는다.

### 조건문, 반복문 흐름 설명

- 바깥 3중 반복문: 가능한 후보를 생성
- 안쪽 반복문: 각 후보에 대해 모든 질문을 검사
- 가장 안쪽 반복문: 세 자리 각각 비교

즉, 구조는 다음과 같다.

> **후보 하나 선택 → 질문 전부 확인 → 세 자리 비교 → 결과 다르면 탈락**

### 어디서 버그가 날 수 있는지 설명

- `if`, `if`를 써서 같은 숫자를 1번과 2번에 동시에 세는 경우
- 후보 생성 시 중복 숫자를 걸러내지 않은 경우
- 질문 하나가 틀렸는데도 `break`를 안 해서 불필요하게 계속 검사하는 경우
- 문자열/정수 변환을 섞어서 비교하다가 타입 문제로 헷갈리는 경우

## 10. 코드 리뷰

### ✅ 잘한 점

- 이 문제를 **완전탐색 문제로 바라보는 관점**이 맞다.
- 후보를 전부 검사하는 구조는 **가장 직관적이고 안전한 풀이**다.
- 숫자 조건(1~9, 중복 없음)을 후보 생성 단계에서 미리 반영하면,
  이후 판정 로직이 단순해진다.
- 문자열을 사용해 자리 비교를 쉽게 만든 점도 구현 친화적이다.

### ⚠️ 아쉬운 점

- 처음 접근할 때 “추론해야 한다”는 생각이 강하면,
  오히려 간단한 브루트포스를 놓치기 쉽다.
- 1번 카운트/2번 카운트 정의를 머릿속으로만 처리하면,
  구현 중에 중복 카운트 실수가 나기 쉽다.
- 질문 하나만 맞으면 되는 것이 아니라,
  **모든 질문을 동시에 만족해야 한다**는 점을 놓치기 쉽다.

### 💡 개선 아이디어

- 1번 카운트와 2번 카운트 계산 로직을 함수로 따로 분리해도 좋다.
- 예를 들어 `check(candidate, query)` 같은 함수로 만들면 재사용성이 좋아진다.
- 디버깅할 때는 특정 후보 하나를 넣고,
  각 질문에 대해 `(cnt1, cnt2)`가 어떻게 나오는지 직접 출력해 보면 이해가 빨라진다.

예시:

```python
def count_result(candidate, query):
    cnt1 = 0
    cnt2 = 0

    for idx in range(3):
        if candidate[idx] == query[idx]:
            cnt1 += 1
        elif query[idx] in candidate:
            cnt2 += 1

    return cnt1, cnt2
```

### 🚨 디버깅 포인트

- 후보 `123`, 질문 `123` → `(3, 0)`이 나와야 한다.
- 후보 `123`, 질문 `321` → `(1, 2)`가 나와야 한다.
- 후보 `123`, 질문 `456` → `(0, 0)`이 나와야 한다.
- 후보 `123`, 질문 `132` → `(1, 2)`가 나와야 한다.

이런 기본 케이스를 직접 찍어보면 로직 오류를 빨리 찾을 수 있다.

## 11. 회고

이 문제에서 가장 중요한 건,
**가능한 후보 수가 작으면 직접 다 검사하는 것이 오히려 가장 좋은 풀이일 수 있다는 점**이다.

배울 점은 다음과 같다.

- 문제를 보고 복잡해 보여도, 먼저 **전체 경우의 수가 얼마나 되는지 계산해보기**
- 조건이 많을수록 정답을 직접 만들려고 하기보다,
  **후보를 생성하고 조건을 검증하는 방식**을 떠올리기
- 자리 비교 문제는 문자열로 바꾸면 구현이 쉬워질 수 있다는 점 기억하기

다음에 비슷한 문제를 보면,
먼저 “후보 수가 적은가?”를 확인하고 완전탐색 가능 여부부터 판단하는 습관을 들이면 좋다.
