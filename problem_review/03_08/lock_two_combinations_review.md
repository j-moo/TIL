# 두 가지로 열리는 자물쇠

- 📚 **문제 출처:** 코드트리
- 🔗 **문제 링크:** 
- 🧭 **문제 유형:** 브루트포스, 구현, 원형 거리 계산
- 🎯 **목표:** 두 개의 기준 조합 중 하나에 대해 **모든 자리의 원형 거리가 2 이내**인 3자리 조합의 개수를 구한다.
- 🧩 **키워드:** `3중 for문`, `완전탐색`, `원형 거리`, `조건 판별`
- ⭐ **난이도:** 구현형 브루트포스
- 🛠 **핵심 알고리즘:** **모든 3자리 조합을 순회하면서, 각 자리가 기준 조합과 원형 거리 2 이내인지 검사**

---

## 1. 문제 이해

- 이 자물쇠는 **1부터 N까지의 숫자로 이루어진 3자리 다이얼**이다.
- 숫자는 **원형 구조**로 이어져 있어서 `1`과 `N`도 서로 인접하다.
- 자물쇠는 다음 둘 중 하나를 만족하면 열린다.
  - 첫 번째 조합과 비교했을 때 **세 자리 모두 거리 2 이내**
  - 두 번째 조합과 비교했을 때 **세 자리 모두 거리 2 이내**
- 조건을 만족하는 **서로 다른 조합의 수**를 구해야 한다.
- `(1, 2, 3)`과 `(3, 2, 1)`은 **다른 조합**으로 센다.

### 입력/출력 핵심

- 입력:
  - `N`
  - 첫 번째 조합 3개
  - 두 번째 조합 3개
- 출력:
  - 자물쇠가 열리는 조합의 총 개수

### 제한 조건에서 중요한 점

- `N <= 100` 수준이라면 `N^3` 완전탐색이 가능하다.
- 이 문제의 핵심은 **시간복잡도보다 원형 거리 계산을 정확히 구현하는 것**이다.

---

## 2. 문제를 내 말로 재정의

이 문제는 사실상 다음과 같다.

> **1부터 N까지의 모든 3자리 조합을 하나씩 확인하면서, 그 조합이 첫 번째 비밀번호에 충분히 가깝거나, 두 번째 비밀번호에 충분히 가까우면 카운트하는 문제**다.

여기서 중요한 건 **“가깝다”의 기준이 일반 거리값이 아니라 원형 거리**라는 점이다.

예를 들어 `N = 9`일 때:

- `1`과 `2`의 거리는 1
- `1`과 `9`의 거리도 1
- `2`와 `9`의 거리도 2

즉, 단순히 `abs(a - b)`만 사용하면 안 되고, **반대 방향으로 돌렸을 때 더 가까운 경우**도 고려해야 한다.

또 하나 헷갈리기 쉬운 부분은,
**첫 번째 조합의 일부 자리 + 두 번째 조합의 일부 자리**를 섞어서 만족하면 되는 게 아니라,
반드시 **하나의 조합 기준으로 세 자리 모두** 가까워야 한다는 점이다.

---

## 3. 관련 개념 정리

### 1) 브루트포스(완전탐색)

가능한 모든 조합을 직접 확인하는 방식이다.

이 문제에서는:

- 첫 번째 자리: `1 ~ N`
- 두 번째 자리: `1 ~ N`
- 세 번째 자리: `1 ~ N`

이므로 총 `N^3`개의 경우를 검사하면 된다.

### 2) 원형 거리 계산

이 문제의 핵심 개념이다.

두 숫자 `x`, `y`의 원형 거리는 다음과 같이 구한다.

```python
min(abs(x - y), N - abs(x - y))
```

#### 왜 이렇게 계산할까?

- `abs(x - y)` : 한 방향으로 갔을 때 거리
- `N - abs(x - y)` : 반대 방향으로 돌아갔을 때 거리

둘 중 작은 값을 택해야 **진짜 원형 거리**가 된다.

### 3) 조합 판별 조건

문제는 “각 자리 중 하나라도 가까우면”이 아니라,

- **첫 번째 조합의 세 자리 모두 가까움**
  또는
- **두 번째 조합의 세 자리 모두 가까움**

이어야 한다.

즉, 조건 구조는 반드시 다음과 같아야 한다.

```python
(first_combination 전체 만족) or (second_combination 전체 만족)
```

## 4. 내 풀이 아이디어 분석

네 접근은 전체적으로 **좋은 출발**이었다.
특히 아래 흐름은 문제 성격에 잘 맞는다.

### 내가 시도한 접근

- 3자리 조합이므로 **3중 for문으로 모든 경우 탐색**
- `can_distance()` 함수로 **가능한 조합인지 판별**
- 가능하면 `cnt += 1`

### 이 접근의 장점

- **직관적**이다.
- 문제 조건을 코드 흐름으로 옮기기 쉽다.
- `N <= 100` 수준에서는 충분히 빠르다.
- 조건 판별 함수를 따로 분리하려 한 점은 **가독성 면에서 좋은 습관**이다.

### 다른 방법과 비교했을 때 특징

이 문제는 DFS, BFS, 백트래킹 같은 복잡한 탐색이 필요하지 않다.
오히려 **정확한 조건 판별**이 더 중요하다.

즉, 이 문제의 핵심은 “어떻게 탐색하느냐”보다
**“거리 조건을 정확하게 구현했는가”** 에 있다.

다만 기존 코드에서는 다음 부분이 아쉬웠다.

- **원형 거리 계산이 빠져 있었다.**
- `2 < abs(...) < N - 2` 형태는 직관적이지 않고, 원형 구조를 정확히 반영하지 못한다.
- “가능한 경우”를 직접 쓰는 대신 “불가능한 경우”를 뒤집는 식으로 접근하면서 조건이 더 복잡해졌다.

## 5. 최종 풀이 전략

핵심 전략은 단순하다.

### 핵심 로직 설명

1. `1 ~ N` 범위의 모든 3자리 조합 `(i, j, k)`를 확인한다.
2. 각 자리마다 기준 조합과의 **원형 거리**를 구한다.
3. 다음 둘 중 하나라도 만족하면 카운트한다.
   - `(i, j, k)`가 첫 번째 조합과 **세 자리 모두 거리 2 이내**
   - `(i, j, k)`가 두 번째 조합과 **세 자리 모두 거리 2 이내**
4. 최종 개수를 출력한다.

### 흐름을 단계별로 정리

- `close(x, y)` 함수 작성
  - 두 숫자의 원형 거리가 2 이내인지 검사
- `can_distance(i, j, k)` 함수 작성
  - 현재 조합이 첫 번째 또는 두 번째 조합에 대해 조건을 만족하는지 확인
- 3중 for문으로 모든 조합 순회
- 만족하면 `cnt` 증가

### 의사코드

```text
for i in 1..N:
    for j in 1..N:
        for k in 1..N:
            if 첫 번째 조합과 세 자리 모두 가깝다:
                count += 1
            elif 두 번째 조합과 세 자리 모두 가깝다:
                count += 1
```

또는 함수형으로 쓰면:

```text
can_open(i, j, k):
    first = 첫 번째 조합과 세 자리 모두 거리 2 이내
    second = 두 번째 조합과 세 자리 모두 거리 2 이내
    return first or second
```

## 6. 검증

### 시간복잡도

- 총 경우의 수: `N^3`
- 각 경우마다 상수 시간 비교
- 따라서 **O(N^3)**

`N = 100`이면 최대 `1,000,000`번 검사하므로 충분히 가능하다.

### 공간복잡도

- 별도 배열 없이 몇 개 변수만 사용
- **O(1)**

### 제한 조건에서 가능한 이유

- 파이썬에서도 백만 번 정도의 단순 반복은 충분히 처리 가능하다.
- 이 문제는 성능보다 **조건을 정확하게 구현하는 것**이 더 중요하다.

### 반례 / 예외 상황 검토

#### 반례 1: 원형 거리

```text
N = 9
기준값 = 1
비교값 = 9
```

- 단순 거리: `abs(1 - 9) = 8`
- 원형 거리: `min(8, 9 - 8) = 1`

따라서 단순 `abs()`만 쓰면 오답이다.

#### 반례 2: 자리별로 서로 다른 조합에 걸치는 경우

예를 들어 어떤 조합이

- 첫 번째 조합의 1번째 자리와는 가깝고
- 두 번째 조합의 2, 3번째 자리와는 가까워도

이건 **열리는 조합이 아니다.**

왜냐하면 문제는 **하나의 조합 기준으로 세 자리 모두** 가까워야 하기 때문이다.

#### 반례 3: N이 작은 경우

`N`이 매우 작으면 원형 구조 때문에 거의 대부분이 가까워질 수 있다.
이럴 때도 거리 계산이 자연스럽게 동작하는지 점검해보면 좋다.

## 7. 구현 포인트

### 구현 시 주의점

- **원형 거리**는 반드시 `min(abs(x-y), N-abs(x-y))`로 계산해야 한다.
- 조건은 자리별 OR가 아니라, **조합 단위 OR**다.
- 즉:
  - `첫 번째 조합 전체 만족`
  - 또는 `두 번째 조합 전체 만족`

### 자주 실수하는 부분

- `abs(x-y) <= 2`만 쓰는 실수
- `and`, `or` 묶음 우선순위를 잘못 잡는 실수
- “모든 자리” 조건을 빼먹고 일부 자리만 만족해도 통과시키는 실수
- 불가능한 경우를 길게 써서 오히려 조건이 꼬이는 실수

### 변수/함수 역할 설명

- `close(x, y)`
  - 두 숫자의 **원형 거리**가 2 이내인지 확인하는 함수
- `can_distance(i, j, k)`
  - 현재 조합 `(i, j, k)`가 자물쇠를 열 수 있는지 확인하는 함수
- `cnt`
  - 가능한 조합의 수를 누적하는 변수

## 8. 코드

```python
# N값 입력받기
# 자물쇠의 각 자리에는 1부터 N까지의 숫자가 들어갈 수 있다.
N = int(input())

# 두 개의 기준 조합 입력받기
# 각각 첫 번째 비밀번호, 두 번째 비밀번호 역할을 한다.
a1, b1, c1 = map(int, input().split())
a2, b2, c2 = map(int, input().split())


# 두 숫자가 원형 자물쇠에서 거리 2 이내인지 확인하는 함수
# 주의: 단순 abs(x - y) <= 2 로만 판단하면 1과 N이 가까운 경우를 놓치게 된다.
def close(x, y):
    # 일반적인 숫자 차이를 먼저 구한다.
    diff = abs(x - y)

    # 원형 구조이므로 정방향 거리와 반대방향 거리를 모두 고려해야 한다.
    # 예를 들어 N=9일 때 1과 9는 차이가 8이 아니라 실제로는 1칸 차이다.
    return min(diff, N - diff) <= 2


# 현재 조합 (i, j, k)가 자물쇠를 열 수 있는지 확인하는 함수
# 기존 네 코드의 can_distance 구조를 유지하되, 판정 로직만 더 정확하게 바꾼 버전이다.
def can_distance(i, j, k):

    # 첫 번째 조합과 비교했을 때
    # 세 자리 모두 거리 2 이내여야만 True가 된다.
    case1 = (
        close(i, a1) and
        close(j, b1) and
        close(k, c1)
    )

    # 두 번째 조합과 비교했을 때도
    # 마찬가지로 세 자리 모두 가까워야 한다.
    case2 = (
        close(i, a2) and
        close(j, b2) and
        close(k, c2)
    )

    # 둘 중 하나라도 만족하면 자물쇠가 열린다.
    return case1 or case2


# 가능한 조합의 수를 저장할 변수
cnt = 0

# 3중 for문으로 모든 3자리 조합을 탐색한다.
# 이 문제는 자리 수가 3개로 고정되어 있으므로 완전탐색이 가장 단순하고 안전하다.
for i in range(1, N + 1):
    for j in range(1, N + 1):
        for k in range(1, N + 1):

            # 현재 조합이 조건을 만족하면 카운트를 1 증가시킨다.
            if can_distance(i, j, k):
                cnt += 1

# 최종적으로 자물쇠가 열리는 조합 수를 출력한다.
print(cnt)
```

## 9. 코드 해설

### 코드의 전체 흐름 설명

이 코드는 크게 세 부분으로 나뉜다.

1. 입력 받기
2. 조건 판별 함수 정의
3. 모든 조합을 순회하며 개수 세기

전체 구조는 **네가 처음 생각한 흐름을 그대로 유지**하고 있다.
다만 조건 판별 방식을 더 정확하고 읽기 쉽게 다듬었다.

### 중요한 부분 상세 설명

#### 1) `close(x, y)`

이 함수가 사실상 문제의 핵심이다.

```python
diff = abs(x - y)
return min(diff, N - diff) <= 2
```

여기서 `min(diff, N - diff)`를 쓰는 이유는
자물쇠가 원형이기 때문이다.

예를 들어 `N=10`, `x=1`, `y=10`이면:

- 일반 차이: `9`
- 반대로 한 칸만 돌리면 됨: `1`

따라서 진짜 거리는 `1`이다.

#### 2) `can_distance(i, j, k)`

이 함수는 **현재 조합이 열리는지 여부**를 판단한다.

```python
case1 = close(i, a1) and close(j, b1) and close(k, c1)
case2 = close(i, a2) and close(j, b2) and close(k, c2)
return case1 or case2
```

여기서 핵심은 다음과 같다.

- `case1`: 첫 번째 조합 기준으로 **세 자리 모두 가까운가**
- `case2`: 두 번째 조합 기준으로 **세 자리 모두 가까운가**

그리고 둘 중 하나만 만족해도 열리므로 `or`를 쓴다.

#### 3) 3중 반복문

가능한 모든 조합을 직접 검사한다.

```python
for i in range(1, N + 1):
    for j in range(1, N + 1):
        for k in range(1, N + 1):
```

이 문제는 자리 수가 정확히 3개로 고정되어 있으므로,
이 방식이 가장 단순하고 실수할 가능성도 적다.

### 조건문, 반복문 흐름 설명

반복문 하나당 한 자리를 의미한다.

- `i`: 첫 번째 자리
- `j`: 두 번째 자리
- `k`: 세 번째 자리

각 조합 `(i, j, k)`마다 `can_distance()`를 호출해서
열리는 조합인지 확인하고, 맞으면 `cnt`를 늘린다.

재귀가 아니라 반복문 기반 완전탐색이므로,
흐름을 따라가기에도 비교적 쉽다.

### 어디서 버그가 날 수 있는지 설명

#### 1) 원형 거리 계산을 빼먹는 경우

가장 흔한 버그다.

```python
abs(x - y) <= 2
```

이렇게만 쓰면 `1`과 `N`의 인접 관계를 놓치게 된다.

#### 2) 조건을 뒤집어서 쓰는 경우

기존 코드처럼
“둘 다 만족 못하면 False” 방식으로 접근하면
논리식이 길어질수록 실수가 생기기 쉽다.

특히 다음과 같은 형태는

```python
2 < abs(...) < N - 2
```

직관성이 떨어지고, 원형 거리와도 정확히 맞지 않는다.

#### 3) `and / or` 묶음을 잘못 쓰는 경우

이 문제의 정답 구조는 다음과 같다.

```python
(자리1 and 자리2 and 자리3) or (자리1 and 자리2 and 자리3)
```

이지,

```python
(자리1 or 자리2 or 자리3)
```

가 아니다.

## 10. 코드 리뷰

### ✅ 잘한 점

- **3중 for문으로 모든 경우를 확인하겠다는 판단이 적절**했다.
- `can_distance()`로 조건 판별을 분리한 점이 좋다.
- 제한을 보고 **완전탐색이 가능하다고 판단한 점**이 정확했다.
- 문제를 풀기 전에
  - 원형 구조
  - 거리 2 이내
  - 모든 자릿수 검사
  를 먼저 메모한 점도 좋다.

### ⚠️ 아쉬운 점

- 가장 큰 아쉬운 점은 **원형 거리 계산을 정확한 식으로 구현하지 못한 것**이다.
- 아래 조건은 직관적으로 이해하기도 어렵고, 정확성도 떨어진다.

```python
2 < abs(i - a1) < N - 2
```

- 또한 “가능한 경우”를 직접 판별하기보다,
  “불가능한 경우를 뒤집어서 처리”하려다 보니 논리가 더 복잡해졌다.
- 문제 조건 자체는 단순한 편인데, 조건식을 꼬아서 쓰면서 오히려 실수하기 쉬운 구조가 되었다.

### 💡 개선 아이디어

#### 1) 거리 판별을 함수로 완전히 분리하기

```python
def close(x, y):
    diff = abs(x - y)
    return min(diff, N - diff) <= 2
```

이렇게 하면 실수를 크게 줄일 수 있다.

#### 2) 조건은 “긍정형”으로 쓰기

불가능한 경우를 찾는 것보다,
**가능한 경우를 직접 쓰는 편이 훨씬 읽기 쉽다.**

```python
case1 = ...
case2 = ...
return case1 or case2
```

이 구조가 유지보수에도 유리하다.

#### 3) 의미 있는 변수명 사용하기

지금도 나쁘진 않지만, 나중에는 다음처럼 바꿔볼 수도 있다.

```python
first1, first2, first3
second1, second2, second3
```

또는

```python
first = [a1, b1, c1]
second = [a2, b2, c2]
```

형태로 묶어도 좋다.

### 🚨 디버깅 포인트

#### 디버깅 포인트 1: `1`과 `N` 테스트

```text
N = 9
x = 1, y = 9
```

이때 `close(1, 9)`가 반드시 `True`여야 한다.

#### 디버깅 포인트 2: 한 조합 기준 전체 만족 여부

어떤 조합이

- 첫 번째 조합의 일부 자리만 만족하고
- 두 번째 조합의 나머지 자리만 만족한다면

결과는 **False**가 나와야 한다.

#### 디버깅 포인트 3: 작은 N 테스트

`N`이 작을 때는 원형 특성 때문에 많은 수가 가까워질 수 있다.
이럴 때도 조건이 자연스럽게 작동하는지 확인하면 좋다.

## 11. 회고

이 문제에서 가장 중요한 건
**완전탐색 자체보다 조건을 정확하게 해석해서 구현하는 능력**이다.

특히 배울 점은 다음과 같다.

- 원형 구조가 나오면 **단순 차이값으로 끝내면 안 된다.**
- 조건이 복잡할수록 **작은 함수로 쪼개는 것**이 중요하다.
- “불가능한 경우”를 길게 쓰기보다,
  **“가능한 경우”를 명확하게 쓰는 편이 실수를 줄인다.**

다음에 비슷한 문제를 풀 때는:

1. 먼저 조건을 말로 정리하고
2. 핵심 판별 로직을 함수로 분리한 뒤
3. 반복문과 결합하는 습관을 들이면 훨씬 안정적으로 풀 수 있다.
