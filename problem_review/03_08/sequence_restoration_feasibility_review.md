# [미상]. 수열 복원 가능 여부 판별

- 📚 문제 출처: 미상
- 🔗 문제 링크: 미상
- 🧭 문제 유형: 수학, 그리디, 조건 판별
- 🎯 목표: 주어진 수열을 `0`에서 시작해 매 행동마다 `+1`과 `+2`를 **반드시 한 번씩** 수행하여 만들 수 있는지 판별
- 🧩 키워드: **총합**, **3의 배수**, **+2를 배치할 수 있는 자리**, **선형 탐색**
- ⭐ 난이도: 실버 ~ 골드 초반 감각의 사고형 판별 문제
- 🛠 핵심 알고리즘: **합의 성질 관찰 + 각 원소의 수용 가능 횟수 계산**

> **참고:** 이번 정리는 제출 코드가 따로 없어서, 네가 말한 사고 흐름(총합 조건 발견, 완전탐색 고민, 시간초과 우려)을 중심으로 정리했고, `## 8. 코드`에는 **설명용 기준 코드**를 넣었다.

## 1. 문제 이해

이 문제는 처음에 모든 원소가 `0`인 수열에서 시작해서, 아래 행동을 여러 번 반복해 최종 수열을 만들 수 있는지 판단하는 문제다.

한 번의 행동에서는 반드시 아래 두 연산을 **모두** 해야 한다.

- 어떤 원소 하나를 골라 `+1`
- 어떤 원소 하나를 골라 `+2`

같은 원소를 두 번 골라도 된다.

### 입력/출력 핵심
- 길이 `n`의 수열이 주어진다.
- 각 원소를 정확히 맞춰서 만들 수 있으면 가능, 아니면 불가능이다.

### 제한 조건에서 중요한 점
- 원소 개수가 매우 크다. (`n = 100,000` 수준)
- 원소 값도 작지 않다. (`10,000` 수준)
- 따라서 **행동을 직접 시뮬레이션하거나**, `+1`, `+2`를 어디에 줄지 모든 경우를 따지는 방식은 비효율적이다.
- **한 번 훑는 O(n)** 수준 풀이가 사실상 정답 방향이다.

---

## 2. 문제를 내 말로 재정의

이 문제를 쉽게 말하면,

> **최종 수열의 각 칸에 숫자를 채워 넣어야 하는데, 매번 1짜리 하나와 2짜리 하나를 한 세트로만 넣을 수 있다. 이 세트를 여러 번 써서 정확히 목표 수열을 만들 수 있느냐?**

### 내가 헷갈릴 수 있는 조건 정리
- `+1`만 단독으로 쓰는 것은 **불가능**하다.
- `+2`만 단독으로 쓰는 것도 **불가능**하다.
- 한 번 행동할 때마다 항상 `1`과 `2`를 **세트로** 써야 한다.
- 즉, 행동 1번 = 총합이 **3 증가**하는 것과 같다.

---

## 3. 관련 개념 정리

### 1) 총합 보존 관찰 🔍
한 번 행동할 때마다 `+1`과 `+2`를 같이 수행하므로, 수열 전체 합은 항상 **3씩 증가**한다.

따라서 최종 수열의 합이 `3`의 배수가 아니면 애초에 만들 수 없다.

### 2) 각 원소가 받아줄 수 있는 `+2`의 개수 🔍
이 문제가 어려운 이유는 합만 맞는다고 끝이 아니기 때문이다.

예를 들어 `[1, 1, 1]`은 합이 `3`이라서 얼핏 가능해 보이지만, 실제로는 불가능하다.
왜냐하면 행동 1번을 하려면 어디엔가 `+2`를 넣어야 하는데, 최종값이 모두 `1`이라 **어느 칸에도 `+2`를 넣을 수 없기 때문**이다.

즉, 각 원소가 **`+2`를 몇 번까지 받아줄 수 있는지**를 봐야 한다.

- 값이 `0`이면 `+2`를 0번
- 값이 `1`이면 `+2`를 0번
- 값이 `2`이면 `+2`를 1번
- 값이 `3`이면 `+2`를 1번
- 값이 `4`이면 `+2`를 2번

즉, 어떤 값 `x`는 `+2`를 최대 **`x // 2`번** 받아줄 수 있다.

### 3) 선형 판별 아이디어 🔍
수열 전체가 받아줄 수 있는 `+2`의 총 횟수는 다음과 같다.

```text
각 원소의 (값 // 2) 를 모두 더한 값
```

그리고 실제로 필요한 `+2`의 횟수는

```text
전체 합 // 3
```

이다. 왜냐하면 행동을 `k`번 했다면 매번 `+2`를 한 번씩 하므로 총 `k`번 필요하고, 전체 합은 `3k`이기 때문이다.

## 4. 내 풀이 아이디어 분석

네가 떠올린 흐름은 꽤 좋았다.

### 네가 먼저 잡은 포인트 ✅
- **수열의 총합이 3의 배수여야 한다**는 점을 발견했다.
- 이건 이 문제의 가장 핵심적인 1차 조건이다.

### 네가 고민한 접근 🔍
- 각 원소에 `1`과 `2`를 빼보면서 모든 경우를 따져보는 방식도 생각했다.
- 즉, “실제로 어떤 행동 순서로 만들 수 있는지”를 직접 확인하려는 접근이었다.

### 이 접근의 장점 ✅
- 문제를 정직하게 이해하고 있다는 뜻이다.
- 연산이 어떻게 수행되는지 직접 따라가려고 했기 때문에 문제 조건을 놓치지 않았다.

### 하지만 비효율적인 이유 ⚠️
- 원소 수가 `100,000`이면 경우의 수 탐색은 사실상 불가능하다.
- 행동 순서를 따지는 방식은 상태가 너무 많다.
- 같은 최종 수열도 만드는 방법이 여러 개라서, **순서 기반 탐색**은 금방 폭발한다.

### 여기서 필요한 전환 💡
이 문제는 “어떤 순서로 만들지”를 따지는 문제가 아니라,

> **결과적으로 `+2`를 필요한 횟수만큼 담아낼 수 있느냐**

를 보는 판별 문제로 바꿔야 한다.

이 관점 전환이 핵심이다.

## 5. 최종 풀이 전략

### 핵심 로직
정답 판별 조건은 아래 두 가지다.

1. **전체 합이 3의 배수여야 한다.**
2. **수열 전체가 받아줄 수 있는 `+2`의 횟수가, 실제로 필요한 `+2` 횟수 이상이어야 한다.**

### 왜 그런가?

#### 1단계. 필요한 행동 횟수 구하기
한 번 행동하면 총합이 3 늘어나므로,

- 전체 합이 `total`이면
- 필요한 행동 횟수는 `total // 3`

이다.

즉, 이만큼의 `+2` 연산도 반드시 들어가야 한다.

#### 2단계. `+2`를 넣을 자리 계산하기
각 원소 `x`는 `+2`를 최대 `x // 2`번 받을 수 있다.

예를 들어,
- `5`는 `+2`를 2번 받을 수 있다. (`2 + 2 + 1`)
- `3`은 `+2`를 1번 받을 수 있다. (`2 + 1`)
- `1`은 `+2`를 못 받는다.

그래서 전체 수열이 받아줄 수 있는 `+2`의 총량은

```text
sum(x // 2 for x in arr)
```

이다.

#### 3단계. 필요한 횟수와 수용 가능 횟수 비교
- 필요한 `+2` 횟수 = `total // 3`
- 실제 수용 가능 횟수 = `sum(x // 2 for x in arr)`

이때 수용 가능 횟수가 부족하면 불가능하다.

### 의사코드

```text
total = 수열의 합
need = total // 3
room = 각 원소 x에 대해 x // 2 값을 모두 더한 값

if total % 3 != 0:
    불가능
else if room < need:
    불가능
else:
    가능
```

## 6. 검증

### 시간복잡도
- 수열을 한 번 순회하며 합과 `x // 2`를 계산하면 된다.
- **O(n)**

### 공간복잡도
- 입력 배열 외 추가 공간이 거의 없다.
- **O(1)** 또는 입력 포함 시 **O(n)**

### 제한 조건에서 가능한 이유
- `n = 100,000`이어도 O(n)은 충분히 가능하다.
- 완전탐색이나 시뮬레이션과 달리, 각 원소를 한 번씩만 보면 끝난다.

### 반례 / 예외 상황 검토

#### 반례 1. 합은 맞지만 `+2`를 둘 곳이 없는 경우
```text
[1, 1, 1]
```
- 합 = 3 → 3의 배수
- 하지만 어느 칸도 `+2`를 받을 수 없다.
- 따라서 불가능

#### 반례 2. 작은 예시지만 가능한 경우
```text
[2, 1, 0]
```
- 합 = 3 → 행동 1번
- 첫 번째 칸이 `+2`를 1번 받을 수 있음
- 따라서 가능

#### 반례 3. 합부터 안 맞는 경우
```text
[1, 0, 0]
```
- 합 = 1
- 3의 배수가 아님
- 즉시 불가능

---

## 7. 구현 포인트

### 구현 시 주의점
- **합이 3의 배수인지 먼저 확인**하면 빠르게 걸러낼 수 있다.
- `+2`를 몇 번 넣을 수 있는지는 **각 원소의 절반 몫**을 더하면 된다.
- 불필요한 시뮬레이션은 하지 않는다.

### 자주 실수하는 부분 ⚠️
- 합만 보고 가능하다고 판단하는 실수
- `1, 1, 1` 같은 반례를 놓치는 실수
- `x // 2`의 의미를 “2가 몇 묶음 들어가는가”로 이해하지 못해 조건을 빼먹는 실수

### 변수 역할 설명
- `total`: 수열 전체 합
- `need`: 반드시 수행해야 하는 `+2` 연산 횟수
- `room`: 수열 전체가 받아줄 수 있는 `+2` 연산의 최대 횟수

---

## 8. 코드

```python
n = int(input())
arr = list(map(int, input().split()))

# 수열 전체 합을 구한다.
# 한 번 행동할 때마다 총합이 3 증가하므로,
# 이 값으로 필요한 행동 횟수를 판단할 수 있다.
total = sum(arr)

# 수열 전체가 받아줄 수 있는 +2의 최대 횟수를 계산한다.
# 값이 x인 원소는 +2를 최대 x // 2 번까지 받을 수 있다.
room = 0
for x in arr:
    room += x // 2

# 전체 합이 3의 배수가 아니면 절대 만들 수 없다.
# 행동 1번당 총합이 무조건 3 늘어나기 때문이다.
if total % 3 != 0:
    print("No")
else:
    # 필요한 행동 횟수이자,
    # 반드시 수행해야 하는 +2 연산 횟수이다.
    need = total // 3

    # 수열 전체가 +2를 받아줄 수 있는 횟수가 부족하면 불가능하다.
    if room < need:
        print("No")
    else:
        print("Yes")
```

## 9. 코드 해설

### 코드의 전체 흐름
이 코드는 크게 세 단계로 동작한다.

1. **합 계산**
2. **`+2` 수용 가능 횟수 계산**
3. **두 조건을 차례대로 검사**

### 중요한 부분 상세 설명

#### `total = sum(arr)`
이 줄은 단순히 합을 구하는 코드지만, 사실상 첫 번째 핵심 조건을 담당한다.

- 행동 1번 → 총합 3 증가
- 행동 2번 → 총합 6 증가
- 행동 3번 → 총합 9 증가

즉, 최종 합은 반드시 `3k` 꼴이어야 한다.

#### `room += x // 2`
이 부분이 두 번째 핵심이다.

여기서 `x // 2`는 수식처럼 보기보다,

> **이 칸이 `+2`를 몇 번까지 받아줄 수 있지?**

라고 이해하면 된다.

예를 들어,
- `x = 5`면 `+2` 두 번 가능
- `x = 4`면 `+2` 두 번 가능
- `x = 3`이면 `+2` 한 번 가능
- `x = 1`이면 불가능

이를 전체 칸에 대해 다 더한 값이 `room`이다.

#### `if total % 3 != 0:`
이 조건은 빠른 탈락 조건이다.

합이 안 맞으면 뒤를 볼 필요도 없다.

#### `need = total // 3`
이 값은 필요한 행동 횟수다.
그리고 행동 1번마다 `+2`를 무조건 한 번 해야 하므로,
이 값은 동시에 **필요한 `+2` 횟수**이기도 하다.

#### `if room < need:`
이 줄은 “실제로 `+2`를 다 넣을 수 있느냐”를 검사한다.

이 조건이 없으면 `[1, 1, 1]` 같은 반례를 걸러내지 못한다.

### 어디서 버그가 날 수 있는가 🚨
- `total % 3 == 0`만 확인하고 바로 `Yes`를 출력하는 경우
- `need`를 따로 계산하지 않고 막연히 합만 보는 경우
- `x // 2`를 누적하지 않고, 단순히 `x >= 2`의 개수만 세는 경우
  - 예: `4`는 `+2`를 2번 받을 수 있는데, 이를 1번으로만 세면 틀린다.

## 10. 코드 리뷰

### ✅ 잘한 점
- **총합이 3의 배수여야 한다**는 첫 번째 핵심 조건을 잘 발견했다.
- 완전탐색을 바로 구현하지 않고, 제한을 보고 시간초과 가능성을 의심한 판단이 좋았다.
- 문제를 시뮬레이션으로만 보지 않고, 규칙을 찾으려 한 방향이 맞았다.

### ⚠️ 아쉬운 점
- 합 조건까지만 보면 `[1, 1, 1]` 같은 반례를 놓치게 된다.
- “가능한 순서를 찾기” 쪽으로 생각이 길어지면 문제를 어렵게 보게 된다.
- 이 문제는 순서보다 **총량 조건**이 핵심인데, 그 전환이 조금 늦어질 수 있다.

### 💡 개선 아이디어
- 비슷한 판별 문제를 보면 먼저 아래를 체크해보자.
  1. **한 번의 행동이 전체에 주는 영향은 무엇인가?**
  2. **각 원소가 받아줄 수 있는 최대치가 있는가?**
  3. **순서가 중요한가, 아니면 총량만 맞으면 되는가?**
- 앞으로는 시뮬레이션이 떠올라도,
  **“행동의 총 횟수”와 “각 칸의 수용 가능 횟수”로 바꿔볼 수 있을지** 먼저 생각해보면 좋다.

### 🚨 디버깅 포인트
- `[1, 1, 1]` → 정답은 `No`
- `[2, 1, 0]` → 정답은 `Yes`
- `[4, 1, 1]` → 정답은 `Yes`
- `[1, 0, 0]` → 정답은 `No`
- `[3, 3, 0]` → 합 6, `+2` 수용량 2, 필요한 `+2` 횟수 2 → `Yes`

이 반례들을 직접 넣어보면 조건이 왜 필요한지 빠르게 검증할 수 있다.
