# [4837] 문제풀이 정리

- 📚 문제 출처: **SWEA**
- 🔗 문제 링크: 사용자 미제공
- 🧭 문제 유형: **재귀, 조합, 백트래킹**
- 🎯 목표: **1부터 12까지의 수 중 N개를 골라 합이 K가 되는 부분집합의 개수 구하기**
- 🧩 키워드: **조합 생성, start 인덱스, 가지치기, 재귀 호출**
- ⭐ 난이도: 중
- 🛠 핵심 알고리즘: **조합을 재귀로 생성하면서 합과 개수를 동시에 추적하는 DFS / 백트래킹**

---

## 1. 문제 이해

이 문제는 `1`부터 `12`까지의 숫자 중에서 몇 개를 골라,  
**원소의 개수는 정확히 `N`개**, **원소의 합은 정확히 `K`** 가 되도록 만드는  
부분집합의 개수를 구하는 문제다.

즉, 단순히 합만 맞추는 문제가 아니라  
**“몇 개를 골랐는가”와 “합이 얼마인가”를 동시에 만족해야 한다**는 점이 중요하다.

또한 같은 숫자를 여러 번 쓸 수 없고,  
순서가 다른 같은 조합은 하나로 본다.

---

## 2. 문제를 내 말로 재정의

쉽게 말하면 이렇게 볼 수 있다.

> 1부터 12까지 숫자 중에서 **중복 없이 N개를 뽑는다.**  
> 그 숫자들의 합이 **K가 되는 경우만 정답으로 센다.**  
> 이런 경우가 총 몇 개인지 구하자.

헷갈리기 쉬운 조건은 다음과 같다.

- 순서는 중요하지 않다 → **순열이 아니라 조합**
- 같은 숫자를 다시 고르면 안 된다
- 개수 `N`과 합 `K`를 **동시에** 만족해야 한다

---

## 3. 관련 개념 정리

### 3-1. 조합

이 문제는 `1 ~ 12` 중 일부를 고르는 문제인데,  
`[1, 2, 3]`과 `[3, 2, 1]`은 같은 경우로 본다.

즉, 순서가 중요한 순열이 아니라 **조합**이다.

그래서 재귀에서 다음 숫자를 고를 때는  
이미 고른 숫자보다 **뒤쪽 숫자만 보도록** 만들어야 중복을 막을 수 있다.

네 코드의 `start`가 바로 이 역할을 한다.

### 3-2. 재귀 / DFS

이 문제에서는 현재까지 고른 상태를 가지고  
다음 숫자를 하나씩 붙여 나가는 방식이 자연스럽다.

재귀 함수 안에서는 보통 이런 정보를 관리한다.

- `cnt`: 지금까지 고른 숫자 개수
- `total`: 지금까지 숫자 합
- `start`: 다음에 고를 수 있는 시작 위치

이 세 가지가 있으면 현재 상태를 충분히 표현할 수 있다.

### 3-3. 가지치기(Pruning)

네 코드에는 다음 가지치기 조건이 들어 있다.

```python
if total >= K:
    return
```

이 조건은 현재 합이 이미 `K` 이상이면  
이후 숫자를 더해도 합은 더 커질 뿐이므로  
더 깊게 볼 필요가 없다는 뜻이다.

이 가지치기가 가능한 이유는  
배열 `arr = [1, 2, ..., 12]` 가 모두 **양수**이기 때문이다.

---

## 4. 내 풀이 아이디어 분석

네 코드는 **조합을 재귀로 생성하는 전형적인 DFS / 백트래킹 구조**다.

풀이 흐름은 다음과 같다.

1. `arr = [1, 2, ..., 12]` 준비
2. `count_sum(cnt, total, start)` 재귀 함수 정의
3. `cnt == N` 이 되면:
   - `total == K` 인지 확인
   - 맞으면 정답 증가
4. `total >= K` 이면 더 내려가지 않고 종료
5. `for i in range(start, len(arr))` 로 다음 숫자 선택

이 접근의 장점은 다음과 같다.

- 문제를 **조합 생성 문제**로 정확히 이해하고 있다.
- `start`를 사용해서 중복 조합을 잘 막고 있다.
- `total >= K` 가지치기를 넣어 불필요한 탐색을 줄이고 있다.

즉, 단순한 완전탐색이 아니라  
**조합 + 가지치기**가 들어간 깔끔한 재귀 풀이야.

---

## 5. 최종 풀이 전략

### 단계별 흐름

1. `1 ~ 12`까지 숫자를 리스트로 만든다.
2. 재귀 함수에서 현재까지 고른 개수, 현재 합, 다음 시작 위치를 관리한다.
3. `N`개를 다 골랐다면 합이 `K`인지 확인한다.
4. 현재 합이 이미 `K` 이상이면 더 이상 탐색하지 않는다.
5. `start`부터 뒤쪽 숫자들을 하나씩 선택하면서 재귀 호출한다.
6. 모든 가능한 조합을 확인한 뒤 정답 개수를 출력한다.

### 의사코드

```text
count_sum(cnt, total, start):
    if cnt == N:
        if total == K:
            answer += 1
        return

    if total >= K:
        return

    for i in range(start, 12):
        count_sum(cnt + 1, total + arr[i], i + 1)
```

---

## 6. 검증

### 시간복잡도

이 문제는 본질적으로 `1 ~ 12` 중 일부를 고르는 조합 탐색이다.  
최악의 경우 모든 조합을 확인할 수 있으므로 대략 조합 탐색 비용이 든다.

전체 숫자 개수가 12로 작기 때문에  
재귀 탐색으로도 충분히 처리 가능하다.

실전 감각으로 보면 다음처럼 이해해도 좋다.

- 완전탐색 / 조합 탐색
- 다만 `N`, `K`, 가지치기 덕분에 실제 탐색 수는 줄어든다

### 공간복잡도

- 재귀 호출 스택 깊이: 최대 `N`
- 별도 큰 자료구조는 거의 없음

즉, 공간 사용도 크지 않다.

### 제한 조건에서 가능한 이유

이 문제는 숫자 범위가 `1 ~ 12`로 작다.  
그래서 조합을 재귀로 생성해도 충분히 처리 가능하다.

또한 `total >= K` 가지치기 덕분에  
불필요한 분기를 더 줄일 수 있다.

### 반례 / 예외 상황 검토

- `N`개를 다 골랐는데 `total != K` → 정답 아님
- `total`이 이미 `K`보다 커짐 → 더 내려갈 필요 없음
- `K`가 매우 작으면 가지치기가 빨리 일어난다
- `K`가 큰 경우에는 비교적 더 깊이 탐색할 수 있다

---

## 7. 구현 포인트

### 중요한 변수 역할

- `arr`  
  1부터 12까지 숫자를 담은 리스트

- `answer`  
  조건을 만족하는 조합의 개수

- `cnt`  
  현재까지 고른 숫자 개수

- `total`  
  현재까지 고른 숫자의 합

- `start`  
  다음 숫자를 고를 시작 인덱스  
  → 중복 조합 방지의 핵심

### 구현 시 주의점

- `cnt == N`일 때는 **반드시 즉시 종료**해야 한다.
- `start`를 사용하지 않으면 같은 조합이 순서만 바뀐 채 여러 번 세어질 수 있다.
- `total >= K` 가지치기는 이 문제처럼 **모든 수가 양수일 때만 안전하다.**

### 자주 실수하는 부분

- `start` 대신 `0`부터 다시 돌려서 중복 조합이 생기는 경우
- `cnt == N`인데도 재귀를 더 내려가는 경우
- 합과 개수 조건을 동시에 확인하지 않는 경우
- `global answer` 사용 위치를 헷갈리는 경우

## 8. 코드

아래 코드는 **네 코드 구조를 최대한 유지하면서**, 각 줄과 의미 단위가 읽히도록 주석을 보강한 버전이다.

```python
# import sys
# sys.stdin = open('input.txt', 'r')

T = int(input())

for tc in range(1, T + 1):
    # N: 선택할 숫자 개수
    # K: 만들어야 하는 목표 합
    N, K = map(int, input().split())

    # 1부터 12까지 숫자를 준비
    arr = [i for i in range(1, 13)]

    # 조건을 만족하는 조합 개수
    answer = 0

    def count_sum(cnt, total, start):
        global answer
        # 주의:
        # 이 코드는 현재 파일이 최상위 실행 기준이라 global answer가 동작한다.
        # 학습용으로는 nonlocal 또는 반환값 방식이 더 직관적일 수 있다.

        # 종료 조건 1:
        # 정확히 N개를 골랐다면 더 이상 고르지 않고 합만 확인
        if cnt == N:
            if total == K:
                answer += 1
            return

        # 가지치기:
        # 현재 합이 이미 K 이상이면
        # 이후 숫자를 더해도 합은 더 커지므로 중단
        if total >= K:
            return

        # 재귀 호출:
        # start부터 뒤쪽 숫자들만 보면서 조합 생성
        # i + 1을 넘기기 때문에 같은 숫자를 다시 고르지 않고,
        # 순서만 다른 중복 조합도 막을 수 있다.
        for i in range(start, len(arr)):
            count_sum(cnt + 1, total + arr[i], i + 1)

    # 처음에는 아무 숫자도 고르지 않았고,
    # 합은 0, 시작 인덱스는 0부터 시작
    count_sum(0, 0, 0)

    print(f'#{tc} {answer}')
```

---

## 9. 코드 해설

이 코드는 전형적인 조합 생성 재귀다.

### 9-1. 상태 정의

재귀 함수의 매개변수 세 개가 핵심이다.

- `cnt`: 현재까지 몇 개 골랐는가
- `total`: 현재까지 합은 얼마인가
- `start`: 다음 숫자를 어디서부터 볼 것인가

즉, 현재 상태를 이 세 값으로 완전히 표현하고 있다.

### 9-2. 종료 조건

```python
if cnt == N:
    if total == K:
        answer += 1
    return
```

이 부분은 **정확히 N개를 골랐을 때만 정답 여부를 판단**한다는 뜻이다.

개수 조건을 먼저 만족해야 하기 때문에,  
합이 맞더라도 아직 개수가 부족하면 바로 정답으로 세면 안 된다.

### 9-3. 가지치기

```python
if total >= K:
    return
```

현재 숫자들이 모두 양수이기 때문에,  
합이 이미 `K` 이상이면 이후 숫자를 더할수록 더 커질 뿐이다.

따라서 이 시점에서 탐색을 멈추는 건 매우 합리적이다.

### 9-4. start의 역할

```python
for i in range(start, len(arr)):
    count_sum(cnt + 1, total + arr[i], i + 1)
```

이 부분이 조합의 핵심이다.

- `start`부터 시작하므로 앞에서 본 숫자를 다시 보지 않는다.
- `i + 1`을 넘기므로 같은 숫자를 중복 선택하지 않는다.
- 결과적으로 순서만 다른 중복 조합을 막을 수 있다.

즉, `start`는 단순 인덱스가 아니라  
**조합 중복 방지 장치**라고 이해하면 된다.

## 10. 코드 리뷰

### ✅ 잘한 점

- 문제를 순열이 아니라 **조합 문제**로 정확히 이해했다.
- `cnt`, `total`, `start`를 상태로 잡은 점이 좋다.
- `total >= K` 가지치기로 불필요한 탐색을 줄였다.
- 재귀 구조가 전형적이고 학습 가치가 높다.

### ⚠️ 아쉬운 점

- 현재 코드에서 `answer = 0`은 `for tc ...` 블록 안에 있는데,  
  내부 함수에서는 `global answer`를 쓰고 있다.
- 이 구조는 실행 환경에 따라 헷갈릴 수 있고,  
  학습용 관점에서는 **`nonlocal`이나 반환값 방식이 더 자연스럽다.**

즉, 로직 아이디어는 좋지만 **스코프 처리 방식은 다듬을 여지**가 있다.

### 💡 개선 아이디어

학습용으로는 아래 방식도 고려할 수 있다.

- `nonlocal answer`
- 재귀 함수가 개수를 반환하도록 만들기
- 혹은 `answer = [0]` 처럼 리스트로 감싸기

또한 조금 더 공격적인 가지치기도 생각할 수 있다.

예를 들어:

- 이미 `cnt > N`이면 종료
- 남은 숫자를 다 써도 `N`개를 못 채우면 종료

하지만 현재 문제 크기에서는 지금 코드도 충분히 좋다.

### 🚨 디버깅 포인트

- `for i in range(start, len(arr))` 에서 `start`를 `0`으로 고정하면 중복 발생
- `i + 1` 대신 `i`를 넘기면 같은 숫자를 다시 선택하게 됨
- `cnt == N` 검사보다 가지치기를 먼저 두면 의도와 다르게 동작할 수 있음
- `global answer`를 함수/스코프 개념 없이 쓰면 혼란이 생길 수 있음

## 11. 회고

이 문제를 통해 가장 크게 배울 수 있는 점은  
**조합 문제는 “무엇을 고를지”뿐 아니라 “어디서부터 고를지”를 함께 관리해야 한다**는 것이다.

특히 `start`의 의미를 정확히 이해하면  
부분집합 / 조합 / DFS 문제를 훨씬 안정적으로 풀 수 있다.

또한 재귀 문제에서는 항상 이 세 가지를 먼저 떠올리면 좋다.

- 종료 조건은 무엇인가?
- 현재 상태는 무엇으로 표현하는가?
- 중복을 어떻게 막을 것인가?

이 문제는 단순한 부분집합 문제가 아니라,  
**재귀 상태 설계와 가지치기 감각을 연습하기 좋은 문제**다.

## 12. 한 줄 요약

- **`cnt`, `total`, `start`를 상태로 두고 조합을 재귀적으로 만들면, N개를 골라 합이 K인 경우를 깔끔하게 셀 수 있다.**
