## 1. 문제 이해

이 문제는 카드 12장이 순서대로 주어질 때,  
두 명의 플레이어가 **한 장씩 번갈아 카드를 가져가며** 먼저 **Baby-gin**을 완성하는 사람을 찾는 문제다.

Baby-gin은 다음 두 조건 중 하나를 만족하면 된다.

- **triplet**: 같은 숫자 3장
- **run**: 연속된 숫자 3장

중요한 점은 단순히 6장씩 나누는 것이 아니라,  
**입력 순서대로 번갈아 1장씩 나눠가진다**는 점이다.

즉, 카드를 받는 도중에도 누군가 Baby-gin이 되면  
그 즉시 게임이 끝난다.

---

## 2. 문제를 내 말로 재정의

쉽게 말하면 이런 문제다.

- 카드 12장이 차례대로 주어진다.
- 1번 플레이어, 2번 플레이어가 번갈아 한 장씩 가져간다.
- 각 플레이어는 카드를 받을 때마다 자신의 카드 상태가 바뀐다.
- 누군가 **같은 숫자 3장** 또는 **연속된 숫자 3장**을 만들면 즉시 승리한다.
- 끝까지 둘 다 만들지 못하면 0이다.

헷갈리기 쉬운 포인트는 다음과 같다.

- 앞 6장을 player1, 뒤 6장을 player2에게 주는 문제가 아니다.
- 카드 전체를 다 받은 뒤 검사하는 게 아니라, **도중에도 계속 검사해야 한다.**
- 정렬만으로 처리하려 하면 run / triplet 판별에서 헷갈릴 수 있어 **카운트 배열 방식이 더 안정적**이다.

---

## 3. 관련 개념 정리

### 3-1. Baby-gin의 두 조건

#### triplet

같은 숫자가 3번 나오면 triplet이다.

예시:

- `3, 3, 3`
- `7, 7, 7`

#### run

연속된 숫자 3개가 있으면 run이다.

예시:

- `1, 2, 3`
- `4, 5, 6`

즉, 한 플레이어의 카드 상태를 볼 때는 항상 다음 두 가지를 모두 확인해야 한다.

- 어떤 숫자가 3장 이상 있는가?
- 연속된 세 숫자가 각각 1장 이상 있는가?

---

### 3-2. 왜 count 배열이 좋은가?

카드를 리스트로 들고 다니며 정렬해서 검사할 수도 있지만,  
Baby-gin은 사실 **숫자별 개수만 알면 충분한 문제**다.

예를 들어 숫자 카드가 0~9라면,

- `count[3] = 2` → 숫자 3이 두 장 있음
- `count[5] = 1` → 숫자 5가 한 장 있음

이렇게 저장하면:

- triplet 검사: `count[i] >= 3`
- run 검사: `count[i] >= 1 and count[i+1] >= 1 and count[i+2] >= 1`

처럼 아주 간단하게 판별할 수 있다.

즉, 이 문제는 정렬보다 **카운팅 방식이 더 직관적이고 안전한 문제**다.

---

### 3-3. 시뮬레이션

이 문제는 입력된 카드를 **순서대로 처리**해야 한다는 점에서 시뮬레이션 성격도 있다.

게임 진행 흐름은 다음과 같다.

1. 현재 차례 플레이어가 카드 1장을 받는다.
2. 해당 플레이어 카드 상태를 갱신한다.
3. 카드가 3장 이상이면 Baby-gin 검사
4. 되었다면 즉시 승자 결정
5. 아니면 다음 차례로 진행

즉, “최종 결과만 보는 문제”가 아니라  
**게임 과정을 따라가며 상태를 업데이트하는 문제**라고 이해하면 좋다.

---

### 3-4. 재귀로도 볼 수 있는 이유

이 문제는 보통 반복문으로 푸는 것이 가장 자연스럽지만,  
이전에 이야기했듯이 **재귀로도 표현 가능**하다.

재귀 관점에서는 크게 두 가지로 볼 수 있다.

1. **턴 진행 자체를 재귀로 처리**  
   - turn번째 카드 배분  
   - 현재 플레이어 상태 갱신  
   - Baby-gin 검사  
   - 다음 turn 재귀 호출

2. **카드 묶음을 재귀적으로 제거**  
   - triplet 또는 run을 하나 제거  
   - 남은 카드로 다시 검사  
   - 전부 제거되면 성공

하지만 실전에서는 첫 번째보다도,  
그냥 **카운트 배열 + 즉시 검사**가 가장 간단하고 안정적이다.

## 4. 내 풀이 아이디어 분석

이전에 네가 시도했던 코드에서는 크게 네 가지 핵심 포인트가 있었고,  
그중 몇 부분은 반드시 수정이 필요했다.

### 4-1. 잘 잡은 방향

- 플레이어별 카드 상태를 나눠서 보려 한 점
- 카드가 어느 정도 쌓인 뒤 Baby-gin 여부를 검사하려 한 점
- 별도 함수로 판별하려고 한 점

이 방향 자체는 맞다.

### 4-2. 수정이 필요했던 부분

#### (1) 카드 배분 방식

앞 6장 / 뒤 6장으로 나누면 안 되고,  
**입력 순서대로 번갈아 배분**해야 한다.

#### (2) triplet 검사 방식

리스트 슬라이싱 결과와 정수를 비교하면 성립하지 않는다.  
triplet은 “같은 숫자 3장”인지 확인해야 한다.

#### (3) run 검사 누락

Baby-gin은 triplet만 보면 안 되고,  
반드시 run도 함께 검사해야 한다.

#### (4) 함수 호출 결과 확인

함수 자체를 조건문에 넣는 것이 아니라,  
**함수 실행 결과가 True / False인지**를 확인해야 한다.

즉, 이 문제는 단순히 구현만 하는 문제가 아니라  
**게임 흐름 + 판정 로직 + 상태 표현 방식**을 정확히 잡아야 하는 문제다.

## 5. 최종 풀이 전략

### 핵심 아이디어

이 문제를 가장 안정적으로 푸는 방법은 다음과 같다.

1. 플레이어 1, 플레이어 2의 **숫자 개수 배열(count)** 을 준비한다.
2. 입력된 12장의 카드를 앞에서부터 하나씩 처리한다.
3. 짝수 turn이면 player1, 홀수 turn이면 player2에게 준다.
4. 해당 플레이어의 count를 1 증가시킨다.
5. 그 플레이어가 카드를 3장 이상 가졌다면 Baby-gin 검사
6. 검사 결과가 참이면 즉시 승자 반환
7. 끝까지 승자가 없으면 0 반환

### 의사코드

```text
for turn in range(12):
    현재 카드 = cards[turn]

    if turn이 짝수:
        player1 count 갱신
        if player1 카드 수 >= 3:
            if player1이 baby-gin:
                return 1
    else:
        player2 count 갱신
        if player2 카드 수 >= 3:
            if player2가 baby-gin:
                return 2

return 0
```

## 6. 검증

### 시간복잡도

카드는 총 12장으로 고정되어 있고,  
각 턴마다 Baby-gin 검사도 숫자 0~9 범위만 확인하면 된다.

즉,

- 턴 수: 최대 12
- 검사 범위: 최대 10

전체 시간복잡도는 사실상 매우 작고,  
문제 크기상 충분히 빠르다.

### 공간복잡도

- 플레이어별 count 배열 2개 사용
- 각 배열 크기 10

즉, 공간복잡도도 매우 작다.

### 제한 조건에서 가능한 이유

이 문제는 입력 길이가 매우 작고,  
각 상태를 count 배열로만 관리하면 되기 때문에  
복잡한 최적화가 필요 없다.

### 반례 / 예외 상황 검토

- player1이 3장을 받자마자 Baby-gin이면 즉시 1
- player2가 그 다음 차례에 Baby-gin이 되더라도, 이미 player1이 먼저면 player1 승
- 끝까지 아무도 Baby-gin이 아니면 0
- triplet과 run 둘 다 가능한 경우도 있지만, 둘 중 하나라도 성립하면 승리

## 7. 구현 포인트

### 중요한 상태 변수

- `p1`, `p2`  
  각 플레이어의 숫자별 카드 개수 배열

- `turn`  
  현재 몇 번째 카드인지 나타냄

- `p1_cnt`, `p2_cnt`  
  각 플레이어가 현재 몇 장 받았는지 기록

### Baby-gin 검사 함수 핵심

#### triplet 검사

```python
if cnt[i] >= 3:
    return True
```

#### run 검사

```python
if cnt[i] >= 1 and cnt[i+1] >= 1 and cnt[i+2] >= 1:
    return True
```

즉, 검사 함수는 **한 플레이어의 상태만 받아서**  
Baby-gin 여부를 True / False로 반환하는 구조가 가장 깔끔하다.

### 자주 실수하는 부분

- 앞 6장 / 뒤 6장으로 나누는 실수
- 카드 전체를 다 받은 뒤에만 검사하는 실수
- triplet만 보고 run을 빠뜨리는 실수
- 리스트 슬라이싱과 정수 비교 같은 잘못된 조건식 사용
- 함수 자체와 함수 결과를 혼동하는 실수

## 8. 코드

아래 코드는 이전에 정리했던 **정답 코드 기준**으로, 흐름이 드러나도록 주석을 붙인 버전이다.

```python
import sys
sys.stdin = open('input.txt', 'r')


def has_babyjin(cnt, idx=0):
    # 0 ~ 9까지 다 확인했는데 없으면 실패
    if idx >= 10:
        return False

    # triplet 검사
    if cnt[idx] >= 3:
        return True

    # run 검사
    if idx <= 7 and cnt[idx] >= 1 and cnt[idx + 1] >= 1 and cnt[idx + 2] >= 1:
        return True

    # 다음 숫자로 이동
    return has_babyjin(cnt, idx + 1)


def play(turn, p1, p2, p1_cnt, p2_cnt, cards):
    # 12장의 카드를 모두 확인했는데 승자가 없으면 무승부
    if turn == 12:
        return 0

    card = cards[turn]

    # 짝수 turn -> player1 차례
    if turn % 2 == 0:
        p1[card] += 1
        p1_cnt += 1

        # 최소 3장은 있어야 baby-gin 가능
        if p1_cnt >= 3 and has_babyjin(p1):
            return 1

    # 홀수 turn -> player2 차례
    else:
        p2[card] += 1
        p2_cnt += 1

        if p2_cnt >= 3 and has_babyjin(p2):
            return 2

    # 아직 승자가 없으면 다음 turn 진행
    return play(turn + 1, p1, p2, p1_cnt, p2_cnt, cards)


T = int(input())

for tc in range(1, T + 1):
    cards = list(map(int, input().split()))

    # 각 플레이어의 숫자별 카드 개수 저장
    p1 = [0] * 10
    p2 = [0] * 10

    winner = play(0, p1, p2, 0, 0, cards)

    print(f'#{tc} {winner}')
```

---

## 9. 코드 해설

이 코드는 두 부분으로 나뉜다.

### 9-1. `has_babyjin(cnt)`

이 함수는 한 플레이어의 카드 상태를 보고  
Baby-gin인지 아닌지를 판별한다.

검사는 두 단계다.

1. triplet 있는지 확인
2. run 있는지 확인

여기서는 반복문 대신 **재귀로 0부터 9까지 검사**하도록 만들었다.

즉, 이 함수는 “숫자별 카드 개수 배열을 받아서 Baby-gin 여부를 반환하는 판정기” 역할을 한다.

### 9-2. `play(...)`

이 함수는 게임 진행 자체를 재귀로 표현한다.

- 현재 turn의 카드를 가져온다.
- 차례에 맞는 플레이어에게 준다.
- 카드 수가 3장 이상이면 Baby-gin 검사
- 승자가 나오면 즉시 반환
- 아니면 다음 turn 호출

즉, 이 코드는 **게임 진행도 재귀, 판별도 재귀**로 표현한 버전이다.

하지만 중요한 건, 이 문제의 본질이 재귀 자체보다  
**count 배열을 이용해 정확하게 판별하는 것**이라는 점이다.

## 10. 코드 리뷰

### ✅ 잘한 점

- 카드 배분을 **번갈아 진행**해야 한다는 문제 핵심을 잘 반영했다.
- Baby-gin을 triplet / run 두 조건으로 정확히 나눴다.
- count 배열을 사용해서 판별 로직이 명확하다.
- turn 진행과 판별을 함수로 분리해 가독성이 좋다.

### ✅ 특히 좋은 점

이 문제는 정렬 기반으로 접근하면 오히려 헷갈릴 수 있는데,  
count 배열을 사용하면 조건이 딱 떨어진다.

- triplet → 같은 숫자 3장
- run → 연속된 숫자 3종류

이 구조가 명확하게 드러나는 점이 좋다.

### ⚠️ 아쉬운 점

- 재귀로 짜는 것은 학습용으로는 좋지만,  
  실전 구현에서는 반복문 버전이 더 직관적일 수 있다.
- `has_babyjin`은 굳이 재귀가 아니어도 반복문으로 더 간단히 쓸 수 있다.

즉, 이 코드는 **재귀 관점 학습에는 좋지만, 실무형/실전형으로는 반복문 버전이 더 흔하다.**

### 💡 개선 아이디어

- 실전용으로는 `play()`를 반복문으로 바꾸기
- `has_babyjin()`도 반복문으로 바꾸기
- 재귀는 “가능한 풀이”로만 정리하고, 메인 풀이에는 반복문 버전을 우선 배치하기

### 🚨 디버깅 포인트

- turn 기준 player1 / player2가 반대로 들어가면 전체 결과가 틀어진다.
- `turn == 12` 종료 조건이 빠지면 재귀가 끝나지 않는다.
- run 검사 범위를 0~7까지만 봐야 한다.
- `p1_cnt`, `p2_cnt` 없이 무조건 검사해도 되긴 하지만, 최소 3장 미만에서는 불필요한 검사를 하게 된다.

## 11. 회고

이 문제에서 가장 중요한 건  
**“카드 상태를 어떻게 표현할 것인가”** 이다.

처음에는 리스트로 들고 다니며 정렬해서 풀고 싶어질 수 있지만,  
실제로는 숫자별 개수를 세는 방식이 훨씬 안정적이다.

또한 이 문제는 다음 감각을 함께 길러준다.

- 구현 문제에서 **문제 진행 순서**를 정확히 따라가는 능력
- 조건 판별을 위해 **상태를 효율적으로 표현하는 능력**
- 재귀는 가능한가? 반복문이 더 좋은가? 를 비교하는 감각

즉, 이 문제는 단순 카드놀이가 아니라  
**시뮬레이션 + 상태관리 + 판별 로직 설계**를 연습하기 좋은 문제다.

## 12. 한 줄 요약

- **Baby-gin Game은 카드를 번갈아 배분하면서 각 플레이어의 숫자 개수를 관리하고, triplet 또는 run이 생기는 순간 즉시 승자를 판별하는 문제다.**
