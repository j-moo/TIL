- 📚 문제 출처: SW Expert Academy
- 🔗 문제 링크: SWEA 문제 페이지 (로그인 필요)
- 🧭 문제 유형: 그리디(Greedy), 정렬
- 🎯 목표: 트럭마다 컨테이너를 **최대 1개씩만** 실을 수 있을 때, **옮긴 화물의 총 중량 합을 최대로 만드는 것**
- 🧩 키워드: `그리디`, `정렬`, `매칭`, `최대 합`

- 🛠 핵심 알고리즘: **큰 트럭부터 가능한 가장 무거운 화물을 배정하는 그리디**

---

## 1. 문제 이해

- 컨테이너마다 화물 무게가 주어진다.
- 트럭마다 적재 용량이 주어진다.
- **트럭 1대는 컨테이너 1개만** 운반할 수 있다.
- 트럭은 **편도로 한 번만** 운행한다.
- 용량을 초과하는 컨테이너는 해당 트럭에 실을 수 없다.
- 이때 **옮겨진 화물 총무게의 최댓값**을 구해야 한다.

### 입력/출력 핵심
- 테스트케이스 수 `T`
- 각 테스트케이스마다
  - 컨테이너 수 `N`
  - 트럭 수 `M`
  - 화물 무게 리스트
  - 트럭 적재용량 리스트
- 출력은 `#테스트케이스번호 정답` 형식

### 제한 조건에서 중요한 점
- 모든 화물을 다 옮길 필요는 없다.
- 모든 트럭을 반드시 사용할 필요도 없다.
- 핵심은 **몇 개를 옮기느냐가 아니라, 총합이 최대냐**이다.

---

## 2. 문제를 내 말로 재정의

이 문제는 결국

> **트럭과 화물을 1:1로 잘 매칭해서 총 무게 합이 가장 크게 되도록 하는 문제**

라고 볼 수 있다.

헷갈릴 수 있는 포인트는 다음이다.

- 트럭이 화물을 실을 수 있다고 해서 **바로 싣는 게 항상 최선은 아니다.**
- 작은 화물을 너무 빨리 실어버리면, 뒤에서 더 무거운 화물을 놓칠 수 있다.
- 따라서 **현재 가능한 선택이 전체 최적해를 보장하는지** 생각해야 한다.

---

## 3. 관련 개념 정리

### 3-1. 그리디(Greedy)

그리디는 매 순간 가장 좋아 보이는 선택을 하는 방법이다.

이 문제에서의 올바른 그리디는 다음과 같다.

- **큰 트럭부터 본다.**
- 그 트럭이 실을 수 있는 화물 중 **가장 무거운 화물**을 싣는다.

이렇게 해야 큰 적재 용량을 낭비하지 않는다.

### 3-2. 정렬

정렬을 하면 큰 화물, 큰 트럭부터 순서대로 비교하기 쉬워진다.

보통은

- 화물: **내림차순 정렬**
- 트럭: **내림차순 정렬**

후 앞에서부터 비교하며 처리한다.

### 3-3. 왜 큰 것부터 봐야 하는가?

- 작은 트럭은 큰 화물을 절대 못 싣는다.
- 큰 트럭은 작은 화물도 실을 수 있다.

즉, **선택지가 더 많은 큰 트럭을 먼저 처리하는 편이 유리하다.**

## 4. 내 풀이 아이디어 분석

내 코드는 다음 방식으로 접근했다.

1. 화물 리스트와 트럭 리스트를 정렬한다.
2. 재귀 함수 `make_total()`을 만든다.
3. 현재 화물과 현재 트럭을 비교한다.
4. 실을 수 있으면 둘 다 다음으로 넘기고 무게를 더한다.
5. 실을 수 없으면 화물만 다음으로 넘긴다.

즉, 내 의도는

> **정렬된 상태에서 앞에서부터 차례대로 비교하며 가능한 매칭을 만든다**

라고 정리할 수 있다.

### 이 접근의 장점
- 정렬 후 인덱스를 움직이며 풀려는 발상이 깔끔하다.
- 재귀 인자로 현재 상태를 전달해서 흐름을 추적하기 쉽다.
- 종료 조건이 명확해서 코드 읽기가 어렵지 않다.

### 다른 방법과 비교했을 때 특징
- 완전탐색처럼 보이지만, 실제로는 **분기가 거의 없는 순차 진행형 로직**이다.
- 그래서 코드 길이는 짧지만, **최적해를 보장하는 탐색은 아니다.**

## 5. 최종 풀이 전략

### 핵심 로직 설명
정답 방향은 다음과 같다.

1. 화물을 **내림차순 정렬**한다.
2. 트럭도 **내림차순 정렬**한다.
3. 가장 큰 트럭부터 보면서,
4. 실을 수 있는 가장 무거운 화물을 배정한다.

### 흐름을 단계별로 정리

1. 가장 큰 화물과 가장 큰 트럭을 비교한다.
2. 트럭이 그 화물을 실을 수 있으면 배정하고 둘 다 다음으로 이동한다.
3. 못 실으면 그 화물은 현재 트럭뿐 아니라 뒤의 더 작은 트럭들도 못 싣기 때문에, 화물만 다음으로 넘긴다.
4. 트럭이나 화물 중 하나가 끝날 때까지 반복한다.

### 의사코드

```text
화물 내림차순 정렬
트럭 내림차순 정렬

i = 0  # 화물 인덱스
j = 0  # 트럭 인덱스
total = 0

while i < N and j < M:
    if 화물[i] <= 트럭[j]:
        total += 화물[i]
        i += 1
        j += 1
    else:
        i += 1
```

## 6. 검증

### 시간복잡도

현재 네 코드 기준으로 보면

- 화물 정렬: `O(N log N)`
- 트럭 정렬: `O(M log M)`
- 재귀 진행: 인덱스가 한 방향으로만 가므로 `O(N + M)` 수준

따라서 전체는 대체로

**`O(N log N + M log M)`**

이다.

### 공간복잡도

- 리스트 저장: `O(N + M)`
- 재귀 호출 스택: 최악에는 `O(N + M)` 정도 가능

### 제한 조건에서 가능한 이유

정렬 후 선형 탐색 구조이므로 입력 크기가 커도 충분히 처리 가능하다.

### 반례 / 예외 상황 검토

다음 반례를 보면 현재 코드의 문제점이 드러난다.

```text
화물: [1, 2, 3]
트럭: [2, 10]
```

현재 코드 흐름:

- 트럭 2 ← 화물 1
- 트럭 10 ← 화물 2
- 총합 = 3

하지만 최적은

- 트럭 2 ← 화물 2
- 트럭 10 ← 화물 3
- 총합 = 5

즉, **실을 수 있다고 바로 싣는 선택 때문에 최댓값을 놓친다.**

## 7. 구현 포인트

### 구현 시 주의점
- 이 문제는 **매칭 개수**보다 **총합 최대화**가 중요하다.
- 따라서 앞에서부터 가능한 것끼리 단순히 매칭하면 안 된다.
- **정렬 방향**이 매우 중요하다.

### 자주 실수하는 부분
- 오름차순으로 정렬한 뒤 작은 화물을 먼저 확정하는 실수
- 현재 화물이 너무 무거울 때, 화물 인덱스를 움직여야 하는지 트럭 인덱스를 움직여야 하는지 헷갈리는 실수
- 재귀를 썼다고 해서 자동으로 모든 경우를 탐색한다고 착각하는 경우

### 변수/함수 역할 설명
- `n_list`: 컨테이너 무게 목록
- `m_list`: 트럭 적재 용량 목록
- `answer`: 현재까지 구한 최대 총합 저장
- `make_total(n, m, total)`
  - `n`: 현재 보고 있는 화물 인덱스
  - `m`: 현재 보고 있는 트럭 인덱스
  - `total`: 지금까지 실은 화물 총합

## 8. 코드

```python
import sys
sys.stdin = open('input.txt', 'r')  # 입력을 파일에서 읽도록 설정

T = int(input())  # 테스트케이스 수 입력

for tc in range(1, T + 1):
    # 컨테이너 수 N, 트럭 수 M 입력
    N, M = map(int, input().split())

    # 각 컨테이너의 화물 무게 리스트
    n_list = list(map(int, input().split()))

    # 각 트럭의 적재 용량 리스트
    m_list = list(map(int, input().split()))

    answer = 0  # 현재 테스트케이스에서 구한 최대 총합 저장용

    # 오름차순 정렬
    # 의도: 작은 것부터 순서대로 비교하려는 흐름
    # 주의: 이 문제는 오름차순으로 바로 매칭하면 최적해를 놓칠 수 있다.
    n_list.sort()
    m_list.sort()

    # n: 현재 보고 있는 화물 인덱스
    # m: 현재 보고 있는 트럭 인덱스
    # total: 지금까지 실은 화물 총합
    def make_total(n, m, total):
        global answer

        # 트럭을 다 봤거나 화물을 다 봤으면 종료
        # 지금까지의 total 값으로 answer를 갱신한다.
        if m == M or n == N:
            answer = max(answer, total)
            return answer

        # 현재 트럭이 현재 화물을 실을 수 있는 경우
        if m_list[m] >= n_list[n]:
            # 현재 화물을 현재 트럭에 바로 싣고 다음으로 이동
            # 주의: 실을 수 있다고 바로 싣는 선택이 항상 최적은 아니다.
            make_total(n + 1, m + 1, total + n_list[n])
        else:
            # 현재 화물이 너무 무거워서 현재 트럭에 못 싣는 경우
            # 다음 화물을 보도록 화물 인덱스만 증가시킨다.
            make_total(n + 1, m, total)

    # 첫 번째 화물, 첫 번째 트럭부터 시작
    make_total(0, 0, 0)

    # 테스트케이스 결과 출력
    print(f'#{tc} {answer}')
```

## 9. 코드 해설

### 코드의 전체 흐름 설명

이 코드는 정렬 후 재귀로 화물과 트럭을 앞에서부터 비교한다.

- 실을 수 있으면 바로 싣고
- 못 실으면 화물만 넘긴다.

즉, **한 방향으로 인덱스를 이동시키며 가능한 매칭을 하나 만들어 가는 방식**이다.

### 중요한 부분 상세 설명

#### 1) 정렬

```python
n_list.sort()
m_list.sort()
```

이 줄은 작은 것부터 비교하기 쉽게 만드는 코드다.

하지만 이 문제는 총합 최댓값이 목표이기 때문에, **작은 화물을 먼저 보게 되는 구조 자체가 불리할 수 있다.**

#### 2) 종료 조건

```python
if m == M or n == N:
    answer = max(answer, total)
    return answer
```

- 트럭을 다 썼거나
- 화물을 다 봤으면

더 이상 매칭할 수 없으므로 종료한다.

이 부분 자체는 깔끔하고 명확하다.

#### 3) 핵심 분기

```python
if m_list[m] >= n_list[n]:
    make_total(n + 1, m + 1, total + n_list[n])
else:
    make_total(n + 1, m, total)
```

여기가 가장 중요하다.

현재 로직은

- 실을 수 있으면 **무조건 싣고 진행**
- 못 실으면 화물만 넘김

이라는 구조다.

문제는 최적해를 구하려면 때때로

- **실을 수 있어도 지금 안 싣는 선택**

이 필요하다는 점이다.

그런데 현재 코드는 그 선택지를 고려하지 않는다.

### 조건문, 반복문, 재귀 흐름 설명

- 바깥 `for`문: 테스트케이스 반복
- `make_total()` 재귀: 화물/트럭 매칭 진행
- 재귀 내부에서는 인덱스를 증가시키며 상태를 다음 단계로 넘긴다.

다만 이 재귀는 완전탐색이라기보다 **거의 직선형 흐름**이다.

### 어디서 버그가 날 수 있는지 설명

문법적인 버그보다 **알고리즘 선택의 버그**가 핵심이다.

- 실을 수 있으면 무조건 싣는 부분
- 오름차순 정렬로 인해 작은 화물이 먼저 확정되는 부분

이 두 가지가 결합되면서 반례에서 오답이 난다.

## 10. 코드 리뷰

### ✅ 잘한 점
- 정렬 후 인덱스로 문제를 단순화한 발상이 좋다.
- 재귀 인자에 상태를 담아서 흐름을 읽기 쉽게 만들었다.
- 종료 조건이 명확하다.
- `total`을 따로 관리해서 누적합을 추적하는 구조가 깔끔하다.

### ⚠️ 아쉬운 점
- **실을 수 있으면 무조건 싣는 로직** 때문에 최적해를 놓친다.
- 오름차순 정렬이 문제의 목표와 잘 맞지 않는다.
- 재귀처럼 보여도 실제 분기가 부족해서 최적해 탐색이 아니다.
- `global answer`는 이 문제에서는 동작하지만, 구조상 덜 깔끔하게 느껴질 수 있다.

### 💡 개선 아이디어
- 오름차순 대신 **내림차순 정렬**로 관점을 바꾸기
- 재귀보다 **반복문 + 투포인터**로 더 직관적으로 구현하기
- `global` 없이 지역 변수로만 결과를 관리하는 방식 연습하기
- “현재 선택이 미래 선택을 막지 않는가?”를 먼저 점검하는 습관 들이기

### 🚨 디버깅 포인트
- 다음 반례를 직접 넣고 왜 틀리는지 추적해보기

```text
화물: [1, 2, 3]
트럭: [2, 10]
```

- `m_list[m] >= n_list[n]`일 때 **바로 싣는 선택이 정말 최선인지** 확인하기
- 재귀가 여러 경우를 보는 것처럼 보여도, 실제 분기 수가 충분한지 따져보기
- 정렬 방향이 바뀌면 결과가 어떻게 달라지는지 비교해보기
