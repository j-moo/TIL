## 1. 문제 이해

이 문제는 단순히 숫자가 배열 안에 있는지 찾는 문제가 아니다.  
**이진 탐색을 하되, 탐색 과정에서 왼쪽 구간과 오른쪽 구간을 연속해서 같은 방향으로 가면 실패**로 처리해야 한다.

즉,

- 배열 `A` 안에서 `B`의 각 원소를 찾는다.
- 찾는 과정은 **이진 탐색**이어야 한다.
- 단, 탐색 중
  - 왼쪽 갔다가 또 왼쪽 ❌
  - 오른쪽 갔다가 또 오른쪽 ❌
- **좌/우 선택이 번갈아야 한다.**

### 입력/출력 핵심

- `N`: 기준 배열의 크기
- `M`: 찾을 배열의 크기
- `n_arr`: 탐색 대상 배열
- `m_arr`: 찾아야 할 값들
- 출력: 조건을 만족하며 찾은 원소 개수

### 제한 조건에서 중요한 점

- **이진 탐색이므로 `n_arr`는 반드시 정렬**해야 한다.
- 매 원소마다 선형 탐색을 하면 비효율적이므로, **`M`개 원소 각각에 대해 `O(log N)` 탐색**이 필요하다.

---

## 2. 문제를 내 말로 재정의

이 문제를 쉽게 말하면 다음과 같다.

> `m_arr`의 숫자들을 하나씩 꺼내서 `n_arr`에서 찾되,  
> 탐색 방향이 `왼쪽 → 오른쪽 → 왼쪽`처럼 **번갈아 가야만 인정**된다.

즉, **배열 안에 값이 실제로 있어도**, 탐색 과정에서 같은 방향을 연속으로 선택하면 그 숫자는 **찾은 것으로 치지 않는다.**

### 내가 헷갈릴 수 있는 조건

- **배열 안에 존재하는지 여부만 보는 문제가 아니다.**
- **탐색 경로도 조건에 포함된다.**
- 일반 이진 탐색 코드를 그대로 쓰면 오답이 날 수 있다.

---

## 3. 관련 개념 정리

### 1) 이진 탐색(Binary Search)

정렬된 배열에서 가운데 값을 기준으로 절반씩 탐색 범위를 줄여 나가는 알고리즘이다.

- 가운데 값보다 작다 → 왼쪽 구간 탐색
- 가운데 값보다 크다 → 오른쪽 구간 탐색
- 시간복잡도: **`O(log N)`**

### 2) 방향 기록

이 문제에서는 단순히 왼쪽/오른쪽으로 이동하는 것만으로는 부족하다.  
**직전에 어느 방향으로 이동했는지 기억해야 한다.**

예를 들면:

- `prev = 0` : 아직 시작 상태
- `prev = -1` : 직전에 왼쪽으로 이동
- `prev = 1` : 직전에 오른쪽으로 이동

이렇게 두면,

- 또 왼쪽 가야 하는데 `prev == -1` 이면 실패
- 또 오른쪽 가야 하는데 `prev == 1` 이면 실패

라고 처리할 수 있다.

### 3) 왜 정렬이 필요한가?

이진 탐색은 **가운데 값과의 크기 비교를 통해 절반을 버리는 방식**이다.  
정렬되지 않은 배열에서는 이 논리가 성립하지 않는다.

## 4. 내 풀이 아이디어 분석

네가 처음 접근한 흐름은 꽤 좋았다.

- `binary_search(i)`라는 별도 함수로 분리하려고 했고,
- `m_arr`의 원소를 하나씩 검사해서,
- 찾으면 `cnt += 1` 하려는 구조를 잡았다.

이건 문제를 **"탐색 함수 + 전체 반복"** 구조로 나눠 본 점에서 좋다.

### 이 접근의 장점

- **기능 분리**가 되어 있다.
- 메인 로직과 탐색 로직이 나뉘어 있어 읽기 쉽다.
- 이후 방향 조건을 추가하기도 편한 구조다.

### 다만 초기에 막힌 이유

초기 코드에서는 다음이 빠져 있었다.

- 정렬
- `left`, `right`, `mid` 갱신
- 종료 조건
- 방향 기록 변수
- 탐색 대상 배열 구분 (`n_arr` / `m_arr`)

즉, **큰 흐름은 맞았지만 이진 탐색의 필수 구성요소가 덜 들어간 상태**였다.

## 5. 최종 풀이 전략

핵심 전략은 다음과 같다.

1. `n_arr`를 정렬한다.
2. `m_arr`의 각 원소 `x`에 대해 이진 탐색을 수행한다.
3. 탐색 중 직전 방향을 `prev`에 기록한다.
4. 같은 방향을 연속으로 가야 하면 즉시 실패 처리한다.
5. 끝까지 조건을 지키며 찾으면 카운트한다.

### 흐름 요약

```text
for x in m_arr:
    이진 탐색 시작
    가운데 값과 비교
    작으면 왼쪽 / 크면 오른쪽
    단, 이전 방향과 같으면 실패
    찾으면 카운트
```

### 의사코드

```text
binary_search(target):
    left = 0
    right = N - 1
    prev = 0

    while left <= right:
        mid = (left + right) // 2

        if arr[mid] == target:
            return True

        elif target < arr[mid]:
            if prev == LEFT:
                return False
            right = mid - 1
            prev = LEFT

        else:
            if prev == RIGHT:
                return False
            left = mid + 1
            prev = RIGHT

    return False
```

## 6. 검증

### 시간복잡도

- `n_arr` 정렬: **`O(N log N)`**
- `m_arr`의 각 원소 탐색: **`M * O(log N)`**

따라서 전체는:

```python
O(N log N + M log N)
```

### 공간복잡도

- 추가로 쓰는 변수는 `left`, `right`, `mid`, `prev` 정도
- **`O(1)`**

### 제한 조건에서 가능한 이유

배열을 한 번 정렬하고, 이후 각 원소를 로그 시간에 찾으므로 충분히 빠르다.

### 반례 / 예외 상황 검토

#### 1) 값은 있는데 방향이 연속되는 경우
예:

```python
n_arr = [1, 3, 5, 7, 9, 11, 13]
```

`1`을 찾을 때:

- `7` 기준 → 왼쪽
- `3` 기준 → 또 왼쪽

값은 존재하지만 **같은 방향 연속**이라 실패다.

#### 2) 배열에 값이 없는 경우
끝까지 탐색해도 못 찾으면 `False`

#### 3) 원소가 하나뿐인 경우
`left == right`인 상태도 검사해야 하므로 `while left <= right`가 맞다.

---

## 7. 구현 포인트

### 구현 시 주의점

- **반드시 정렬 후 탐색**해야 한다.
- `right = N`이 아니라 **`right = N - 1`** 이어야 한다.
- `mid` 계산은 **`(left + right) // 2`**
- `while True`보다는 **`while left <= right`** 가 안전하다.
- 같은 방향 연속 여부를 확인하는 `prev`가 핵심이다.

### 자주 실수하는 부분

- 탐색 대상 배열을 잘못 쓰는 경우
  - `m_arr`에서 찾는 것이 아니라 **`n_arr`에서 찾아야 한다.**
- `mid`를 잘못 계산하는 경우
- `left`, `right` 갱신을 빠뜨리는 경우
- 방향 조건을 빼먹고 일반 이진 탐색으로 푸는 경우

### 변수 / 함수 역할 설명

- `binary_search(i)` : 숫자 `i`를 조건에 맞게 찾는 함수
- `left`, `right` : 현재 탐색 범위의 시작과 끝
- `m` : 현재 중간 인덱스
- `prev` : 직전 이동 방향
- `cnt` : 조건을 만족하며 찾은 숫자의 개수

## 8. 코드

```python
import sys
sys.stdin = open('input.txt', 'r')
# 로컬에서 input.txt를 표준입력처럼 사용하기 위한 설정
# 제출 환경에서는 보통 이 줄을 제거한다.


def binary_search(i):
    # i : m_arr에서 하나씩 꺼낸, n_arr에서 찾고 싶은 값

    left = 0
    right = N - 1
    # 이진 탐색 범위의 시작과 끝
    # 인덱스는 0 ~ N-1 이므로 right는 N-1이어야 한다.

    prev = 0
    # 직전에 어느 방향으로 이동했는지 저장
    # 0  : 아직 방향 선택 전
    # -1 : 직전에 왼쪽으로 이동
    # 1  : 직전에 오른쪽으로 이동

    while left <= right:
        # 탐색할 구간이 남아 있는 동안 반복
        # left가 right보다 커지면 찾을 수 없는 상태다.

        m = (left + right) // 2
        # 현재 탐색 구간의 가운데 인덱스
        # 이진 탐색의 핵심 계산

        if n_arr[m] == i:
            # 가운데 값이 찾는 값과 같다면
            return True
            # 조건을 지키며 값을 찾았으므로 성공

        elif i < n_arr[m]:
            # 찾는 값이 가운데 값보다 작다면 왼쪽 구간으로 가야 한다.

            if prev == -1:
                # 주의: 직전에도 왼쪽으로 갔다면 같은 방향 연속 선택
                # 이 문제 조건에서는 실패 처리해야 한다.
                return False

            right = m - 1
            # 탐색 범위를 왼쪽 절반으로 줄인다.
            # mid는 이미 확인했으므로 제외한다.

            prev = -1
            # 이번 이동은 왼쪽이었다고 기록

        else:
            # 찾는 값이 가운데 값보다 크다면 오른쪽 구간으로 가야 한다.

            if prev == 1:
                # 주의: 직전에도 오른쪽으로 갔다면 같은 방향 연속 선택
                # 이 문제 조건에서는 실패 처리해야 한다.
                return False

            left = m + 1
            # 탐색 범위를 오른쪽 절반으로 줄인다.
            # mid는 이미 확인했으므로 제외한다.

            prev = 1
            # 이번 이동은 오른쪽이었다고 기록

    return False
    # while문이 끝날 때까지 못 찾았다면 배열 안에 없는 값이다.


T = int(input())
# 테스트 케이스 개수 입력

for tc in range(1, T + 1):
    # 1번부터 T번 테스트 케이스까지 반복

    N, M = map(int, input().split())
    # N : n_arr의 원소 수
    # M : m_arr의 원소 수

    n_arr = sorted(list(map(int, input().split())))
    # 이진 탐색을 위해 기준 배열을 반드시 정렬

    m_arr = list(map(int, input().split()))
    # 찾아야 하는 값들 입력

    cnt = 0
    # 조건을 만족하며 찾은 값의 개수

    for i in m_arr:
        # m_arr의 원소를 하나씩 꺼내 검사

        if binary_search(i):
            # 조건을 만족하며 찾았다면 카운트 증가
            cnt += 1

    print(f'#{tc} {cnt}')
    # 테스트 케이스 번호와 정답 출력
```

## 9. 코드 해설

### 코드의 전체 흐름

전체 구조는 다음 두 부분으로 나뉜다.

1. **`binary_search(i)`**  
   → 숫자 하나를 조건에 맞게 찾는 역할

2. **메인 반복문**  
   → `m_arr`의 원소를 하나씩 꺼내 `binary_search()`에 넣고, 성공하면 개수를 센다.

### 중요한 부분 상세 설명

#### 1) `prev`의 역할

이 문제의 핵심은 이 부분이다.

```python
if prev == -1:
    return False
```

이 뜻은,

> 방금 전에도 왼쪽으로 갔는데 이번에도 왼쪽으로 가야 하네?  
> 그럼 문제 조건 위반이니까 실패.

오른쪽도 동일하다.

#### 2) 범위 갱신

```python
right = m - 1
left = m + 1
```

- 왼쪽으로 갈 때는 `right`를 줄이고
- 오른쪽으로 갈 때는 `left`를 늘린다.

이렇게 해야 탐색 구간이 점점 줄어든다.

#### 3) 종료 조건

```python
while left <= right:
```

이 조건은 **탐색 가능한 구간이 남아 있는 동안 반복**한다는 의미다.

### 어디서 버그가 날 수 있는가?

- `n_arr`가 아니라 `m_arr`에서 찾도록 잘못 작성하는 경우
- `right = N`으로 둬서 인덱스 범위를 벗어나는 경우
- `mid` 공식을 잘못 쓰는 경우
- `prev` 갱신을 안 해서 방향 조건이 무의미해지는 경우
- 정렬을 빼먹는 경우

## 10. 코드 리뷰

### ✅ 잘한 점

- **탐색 로직을 함수로 분리하려는 접근이 좋았다.**
- `for i in m_arr:` 구조로 문제를 자연스럽게 나눠 보려 했다.
- 중간에 주석으로 **문제 조건을 스스로 다시 정리**한 점이 매우 좋다.
- 특히 마지막에
  - “번갈아 탐색하는 것을 어떻게 구현할 것인가?”
  - “이전에 선택한 구간을 기억하는 변수가 필요”

  라고 적은 부분은 **핵심 아이디어를 거의 잡은 상태**였다.

### ⚠️ 아쉬운 점

- 초기에 `binary_search()` 안에서 **탐색 대상 배열이 `m_arr`로 잘못 들어가 있었다.**
- `mid` 계산식이 틀려 있었다.
  - `m = (right - left) // 2 - 1` ❌
- `while True`만 있고 범위 갱신이 없어 **무한 루프 위험**이 있었다.
- 이진 탐색에 필수인 **정렬 단계가 빠져 있었다.**

### 💡 개선 아이디어

- 방향을 문자열 대신 숫자로 두면 비교가 간단하다.
  - `-1`, `0`, `1`
- 함수 인자로 배열과 크기를 넘기면 전역변수 의존이 줄어든다.
- 제출용 코드에서는 `sys.stdin = open(...)`을 제거하면 더 깔끔하다.

예를 들면:

```python
def binary_search(arr, target, size):
    ...
```

처럼 작성할 수도 있다.

- 막히더라도 네가 했던 것처럼 **주석으로 조건을 정리하면 핵심 아이디어를 더 빨리 찾을 수 있다.**
