# 문제풀이 정리 프롬프트 가이드

좋아요. 지금 적어주신 방향은 이미 꽤 좋고, 여기에 조금만 다듬으면 **문제풀이를 나중에 복습하기 좋은 형태**로 훨씬 강하게 만들 수 있어요.

핵심은 단순히  
- 개념 설명
- 코드 붙여넣기

로 끝내는 게 아니라,

**“내가 왜 이렇게 풀었는지”**가 남는 프롬프트로 바꾸는 겁니다.

특히 사용자가 중요하게 적어둔 **문제해결 과정 6단계**를 중심축으로 두고,  
그 위에 **개념 / 풀이전략 / 코드 / 검증 / 회고**를 얹는 구조가 가장 좋습니다.

---

# 더 좋은 결과를 위한 프롬프트 설계 원칙

좋은 문제풀이 정리 프롬프트는 아래 5가지를 강하게 요구해야 합니다.

## 1. 문제를 “요약”하지 말고 “이해 과정”을 남기게 해야 함
많은 정리 결과가 아쉬운 이유는 정답만 예쁘게 정리하고,  
정작 왜 그 풀이를 떠올렸는지가 빠지기 때문이에요.

그래서 반드시 아래가 들어가야 합니다.

- 문제를 내 말로 다시 설명
- 처음 떠올린 접근
- 왜 그 접근을 버렸는지 / 채택했는지
- 반례나 주의점
- 시간복잡도 검토

---

## 2. 코드만 설명하지 말고 “풀이 전략 → 검증 → 구현” 순서를 강제해야 함
문제풀이 정리는 보통 코드 설명으로 바로 들어가면 품질이 떨어집니다.

좋은 구조는:

1. 문제 이해
2. 핵심 아이디어
3. 가능한 방법 비교
4. 최종 방법 선택 이유
5. 복잡도 검토
6. 구현 포인트
7. 코드
8. 회고

이 순서입니다.

---

## 3. “내가 복습할 때” 보기 좋은 형태를 요구해야 함
프롬프트에 아래 요구를 넣으면 결과가 좋아집니다.

- 마크다운 헤더 구조를 명확히 사용
- 표가 필요하면 표 사용
- 너무 긴 문장은 줄이고 핵심 위주
- 하지만 핵심 논리는 생략하지 않기
- 코드 원문은 최대한 유지
- 코드 아래에 흐름 설명 추가

---

## 4. 정답 풀이만 말하지 말고 “틀리기 쉬운 포인트”도 넣게 해야 함
실전 복습에서 가장 중요한 건 이것입니다.

예를 들면:

- 왜 백트래킹인가?
- 왜 그리디는 안 되는가?
- 왜 visited가 필요한가?
- 왜 종료 조건이 저기인가?
- 왜 정렬이 필요한가?

이런 부분이 정리돼야 다음에 비슷한 문제를 풀 수 있어요.

---

## 5. 출력 형식을 구체적으로 지정해야 함
“정리해줘”보다  
“아래 형식으로 정리해줘”가 훨씬 결과가 좋습니다.

즉 프롬프트에는 반드시 다음이 있어야 합니다.

- 제목 형식
- 각 섹션 제목
- 작성 톤
- 어느 정도 자세히 쓸지
- 코드 보존 여부
- 쉬운 설명 포함 여부

---

# 추천하는 최적 프롬프트 구조

아래처럼 작성하면 결과가 훨씬 안정적으로 좋아집니다.

---

## 추천 프롬프트 v1

```markdown
너는 알고리즘 문제풀이 정리 전문가야.

내가 문제 내용, 코드, 또는 풀이 내용을 주면 아래 형식에 맞춰 **복습용 문제풀이 정리 노트**로 작성해줘.

목표는 단순한 정답 요약이 아니라,  
**문제를 어떻게 이해했고, 어떤 방식으로 접근했고, 왜 그 풀이가 맞는지까지 복습할 수 있게 정리하는 것**이야.

아래 원칙을 반드시 지켜줘.

[작성 원칙]
1. 전체 문서는 마크다운으로 작성한다.
2. 제목과 메타 정보를 가장 먼저 작성한다.
3. 문제를 단순 요약하지 말고, **내 언어로 다시 해석한 설명**을 포함한다.
4. 풀이 과정은 반드시 아래 순서를 따른다.
   - 문제 이해
   - 문제를 익숙한 말로 재정의
   - 풀이 아이디어 탐색
   - 최종 풀이 전략 선택 이유
   - 복잡도 검증
   - 구현 포인트
   - 코드 설명
   - 회고 / 개선 포인트
5. 코드가 주어지면 **원본 코드는 최대한 유지**하고, 필요하면 코드 아래에 설명을 덧붙인다.
6. 너무 짧게 요약하지 말고, 그렇다고 불필요하게 장황하지도 않게 작성한다.
7. "왜 이렇게 푸는지"가 드러나게 작성한다.
8. 헷갈리기 쉬운 부분, 실수하기 쉬운 부분, 반례 포인트를 꼭 포함한다.
9. 설명은 초보자도 이해할 수 있도록 쉽게 쓰되, 핵심 알고리즘 용어는 정확히 사용한다.
10. 가능하면 비슷한 유형 문제에 재활용할 수 있는 패턴까지 정리한다.

아래 형식으로 작성해줘.

# [문제번호]. [문제이름]

- 목표:
- 키워드:
- 난이도:
- 핵심 알고리즘:

---

### (필요한 개념별로 정리)
- 개념 정의
- 왜 이 문제에 필요한지

- 처음 떠올릴 수 있는 방법

- 왜 어떤 방법은 부적절한지
- 최종적으로 어떤 방법을 선택했는지

## 5. 최종 풀이 전략

- 핵심 아이디어를 단계별로 설명
- 풀이 흐름을 순서대로 설명

## 6. 검증

- 시간복잡도

## 7. 구현 포인트

- 구현 시 주의할 점
- 자주 틀리는 부분
- 변수/함수 역할 설명

# 왜 이 프롬프트가 좋은가

이 프롬프트의 장점은 3가지예요.

## 1. 풀이 “과정”이 남는다
사용자가 중요하게 본  
**문제해결 과정**이 실제 결과물에 반영됩니다.

즉,
- 문제 이해
- 재정의
- 계획
- 검증
- 구현
- 회고

가 살아 있습니다.

## 2. 코드 복붙 노트가 아니라 복습 노트가 된다
나중에 다시 볼 때  
“아 왜 이렇게 풀었지?”  
가 안 생기게 합니다.

## 3. 알고리즘 공부용으로 좋다
비슷한 문제를 만났을 때  
패턴을 꺼내 쓸 수 있게 해줍니다.

# 더 강하게 만들고 싶다면 추가할 문장

아래 문장들을 추가하면 품질이 더 올라갑니다.

## 1. 너무 요약하지 않게 만들기
```markdown
핵심 논리와 사고 흐름이 사라질 정도로 요약하지 마라.
```

## 2. 내 풀이 기준으로 정리하게 만들기
```markdown
가능하면 정답 풀이만 설명하지 말고, 내가 작성한 코드와 사고 흐름을 기준으로 정리해라.
```

## 3. 헷갈리는 부분을 따로 빼기
```markdown
초보자가 헷갈릴 만한 변수, 조건문, 종료 조건, 반복 범위는 따로 짚어줘.
```

## 4. 비슷한 문제 연결하기
```markdown
이 문제를 어떤 유형의 대표 문제로 볼 수 있는지도 함께 정리해줘.
```

# 사용 목적별 프롬프트 개선 버전

## 1. 복습용에 최적화된 버전
복습이 목적이면 이런 문장을 추가하세요.

```markdown
최종 문서는 “시험 직전 복습용 노트”처럼 작성해줘.
핵심 개념, 풀이 흐름, 실수 포인트가 빠르게 보이도록 정리해줘.
```

---

## 2. 블로그/포트폴리오용 버전
조금 더 읽기 좋게 만들고 싶으면:

```markdown
문서가 너무 딱딱하지 않게, 설명형 블로그 글처럼 자연스럽게 작성해줘.
다만 핵심 알고리즘 설명과 복잡도 검증은 반드시 포함해줘.
```

---

## 3. 코드 리뷰 학습용 버전
내 코드 기준으로 분석하고 싶으면:

```markdown
코드가 주어지면 정답 코드처럼 새로 갈아엎지 말고,
기존 코드의 의도와 흐름을 최대한 살려 설명해줘.
필요하면 개선 포인트를 별도로 제안해줘.
```

# 당신한테 가장 잘 맞는 형태로 다듬은 추천 최종 프롬프트

사용자 스타일을 보면 **“너무 요약되면 싫고, 원본 흐름을 살리면서 깔끔하게 정리”**하는 쪽이 잘 맞습니다.  
그래서 아래 버전을 가장 추천합니다.

```markdown
너는 알고리즘 문제풀이 정리 전문가야.

내가 문제 내용, 내 풀이 코드, 또는 풀이 설명을 주면  
그 내용을 바탕으로 **복습용 문제풀이 정리 노트**를 마크다운 형식으로 작성해줘.

단순히 정답 풀이를 예쁘게 요약하는 것이 아니라,  
**내가 문제를 어떻게 이해하고, 어떤 방식으로 접근했고, 왜 그 풀이가 맞는지까지 복습할 수 있도록** 정리해야 해.

다음 원칙을 반드시 지켜줘.

[핵심 원칙]
- 문제해결 과정이 드러나야 한다.
- 핵심 논리가 사라질 정도로 지나치게 요약하지 않는다.
- 코드가 주어지면 원본 코드는 최대한 유지한다.
- 설명은 쉽게 쓰되, 알고리즘 용어는 정확하게 사용한다.
- “왜 이렇게 푸는가”와 “어디서 실수하기 쉬운가”를 꼭 포함한다.
- 필요한 경우 쉬운 비유나 직관적인 표현도 덧붙인다.
- 복습할 때 빠르게 흐름이 보이도록 마크다운 구조를 깔끔하게 정리한다.

반드시 아래 형식으로 작성해줘.

# [문제번호]. [문제이름]

# 한 가지 더 추천

프롬프트를 더 잘 쓰려면, 문제를 줄 때 아래처럼 같이 주면 결과가 더 좋아집니다.

```markdown
문제:
[문제 본문]

내 코드:
[코드]

내가 헷갈린 점:
- 왜 백트래킹인지
- 가지치기를 왜 이렇게 하는지
- 전선 표시를 왜 2로 하는지

정리 요청:
- 너무 짧게 요약하지 말고
- 복습하기 좋게
- 코드 흐름도 자세히 설명해줘
```

이렇게 주면 결과 품질이 훨씬 올라갑니다.
