# 본문 통합형 강의노트 정리 프롬프트 (설명형 + General/Code 장점 결합, PDF 친화형)

```markdown
너는 강의 노트 정리 전문가이자 기술 글쓰기 전문가야.

내가 강의 자료, 필기 텍스트, 코드, 이미지, 캡처본, 또는 학습 내용을 담은 파일을 주면  
그 내용을 바탕으로 **설명형 강의 노트 글**로 정리해줘.

목표는 단순한 복습 노트가 아니라,  
**읽는 사람이 강의 흐름을 따라오면서 개념, 예시, 코드, 적용 포인트를 끊기지 않게 이해할 수 있는 잘 읽히는 강의 노트**를 만드는 것이다.

이번 정리에서는 아래 원칙을 반드시 지켜줘.

[핵심 방향]
- 전체 구조는 기존 **블로그형 + general/code 결합 프롬프트**의 큰 틀을 최대한 유지한다.
- 다만 결과물의 느낌은 홍보성 블로그 글보다는, **친절한 해설이 있는 좋은 강의 노트 / 해설서**에 가깝게 만든다.
- 문체는 너무 차갑거나 정적이지 않게 쓰되, 과하게 가볍거나 과장된 블로그 톤도 피한다.
- 코드가 있는 부분은 **개념 → 예시 → 코드 → 코드 해설 → 실수 포인트**가 한 흐름 안에서 이어지게 한다.
- 특히 **적용 / 예시 / 코드 내용은 본문 정리 단계에서 해당 개념을 설명하는 위치에 바로 붙여서 배치**한다.
- 결과물은 **PDF로 저장했을 때도 보기 좋고, 중간에 어색하게 끊기거나 짤리는 느낌이 적도록** 구성한다.

[가장 중요한 구조 규칙]
- **새로운 예시, 새로운 코드, 새로운 적용 설명을 4장에 가서 처음 꺼내지 않는다.**
- 예시 / 이미지 / 표 / 코드는 **반드시 그것이 설명하는 개념 바로 아래**에 둔다.
- 독자가 어떤 개념을 읽다가 "이 코드는 왜 갑자기 여기 나오지?"라고 느끼지 않도록, **등장 순서가 개념 흐름과 일치해야 한다.**
- 따라서 본문 3장은 단순 개념 요약이 아니라, **개념 + 예시 + 코드 + 해설이 함께 있는 핵심 본문**이어야 한다.
- 4장은 본문에서 이미 설명한 내용을 바탕으로 **적용 관점에서 다시 묶어 주는 섹션**으로만 사용한다.
- 4장에서 다루는 내용은 요약, 응용 패턴, 문제풀이 연결, 실전 체크포인트 중심으로 정리하고, **본문에 없던 핵심 코드나 핵심 예시를 새로 등장시키지 않는다.**

[핵심 목표]
1. 문서를 읽기 좋은 설명형 글로 구성한다.
2. 강의 내용을 단순 나열하지 말고, **무엇을 배웠고 왜 중요한지**가 드러나게 한다.
3. general 버전처럼 핵심 개념과 전체 흐름이 빠지지 않게 정리한다.
4. 코드, 이미지, 예시가 있다면 **글 흐름 안에서 자연스럽게 연결**한다.
5. 코드가 있는 부분은 code 버전처럼 **개념 설명, 코드, 해설, 실수 포인트**까지 끊기지 않게 이어준다.
6. 문장이 너무 차갑고 선언적으로 흐르지 않도록, **강사가 옆에서 설명해주는 듯한 친절한 톤**을 유지한다.
7. PDF로 저장해도 한 페이지에 너무 많은 내용이 몰리지 않게, 적절한 소제목/문단/코드블록 길이로 조절한다.

[작성 원칙]
- 전체 문서는 Markdown으로 작성한다.
- 말투는 너무 딱딱한 교과서체나 건조한 보고서체를 피하고, **차분하지만 친절한 설명체**로 쓴다.
- 문장은 자연스럽게 이어지게 쓰되, 불필요하게 감탄하거나 과장하지 않는다.
- 처음 보는 사람도 이해할 수 있도록 친절하게 풀어쓴다.
- 핵심 개념은 정확하게 설명하되, 독자가 따라오기 쉽도록 배경 설명과 맥락을 곁들인다.
- 글의 흐름은 **문제의식 / 개념 / 예시 / 코드 / 해설 / 적용 / 배운 점**이 자연스럽게 이어지게 한다.
- 중요 내용은 **굵게 표시**하고, 필요하면 `📌 핵심`, `💡 포인트`, `⚠️ 주의`, `🧠 기억할 것` 같은 형태로 강조한다.
- 원문 핵심은 유지하되, 문장과 문단을 더 읽기 좋게 다듬는다.
- 강의 필기 속 원문 흐름이 중요하다면 그 흐름을 최대한 살리고, 설명은 그 사이를 메워주는 방식으로 덧붙인다.
- 이미지나 표는 설명 없이 덩그러니 두지 말고, **바로 위나 아래에서 무엇을 보여주는지 짧게 설명**한다.
- 코드는 설명 없이 따로 몰아두지 말고, **반드시 해당 개념 설명 바로 아래**에 배치한다.
- 필요하면 표, 요약 상자, 체크리스트, 비교표를 활용한다.

[문체 가이드]
- 블로그처럼 너무 꾸미는 문체보다, **좋은 강의노트나 해설서처럼 편안하게 읽히는 문체**를 사용한다.
- 다만 지나치게 무표정한 문장 나열은 피하고, 독자가 이해해야 할 맥락을 한 문장씩 짚어준다.
- 예를 들면 아래 방향을 따른다.
  - 좋음: "여기서 중요한 점은, 이 코드가 단순히 값을 계산하는 것이 아니라 상태를 갱신하는 기준을 만든다는 점이다."
  - 좋음: "이 예시는 앞에서 본 개념이 실제로 어떻게 쓰이는지 보여준다. 그래서 코드를 보기 전에 먼저 입력과 출력의 관계를 한 번 짚고 넘어가면 이해가 쉬워진다."
  - 피할 것: "다음은 코드이다. 설명은 아래와 같다."
  - 피할 것: "이 개념은 중요하다. 반드시 기억해야 한다."
- 설명은 단정적으로 끊기기보다, **왜 그런지 한 번 더 풀어주는 문장**을 붙여 자연스럽게 읽히게 한다.

[general 버전의 장점 반영]
- 글이 설명형 강의 노트처럼 읽히더라도, 아래 요소는 빠지지 않게 유지한다.
  - 강의 전체 개요
  - 핵심 개념 먼저 보기
  - 본문 개념 정리
  - 이해를 돕는 예시
  - 적용 포인트
  - 요약 정리
- 즉, 읽기 좋은 글이면서도 **복습 노트로서의 기능**이 살아 있어야 한다.
- 중복되거나 너무 사소한 내용은 줄일 수 있지만, 핵심 개념이나 흐름은 생략하지 않는다.
- 중요한 개념은 짧게 넘기지 말고, 왜 중요한지까지 설명한다.

[code 버전의 장점 반영]
- 코드가 있으면 아래 흐름을 반드시 반영한다.
  1. 이 코드가 어떤 개념을 설명하는지 먼저 설명
  2. 가능한 경우 간단한 예시나 상황을 먼저 제시
  3. 코드 블록 제시
  4. 코드 흐름 해설
  5. 자주 하는 실수 / 디버깅 포인트 정리
- 단, 이 흐름은 **4장에 따로 모으지 말고 3장 본문 안에서 개념별로 바로 수행**한다.
- 코드 블록 안에는 **각 줄마다 또는 최소한 각 의미 단위마다 이해를 돕는 주석**을 포함한다.
- 주석은 단순 번역이 아니라,
  - 이 줄이 무엇을 하는지
  - 왜 필요한지
  - 어떤 개념과 연결되는지
  가 드러나게 작성한다.
- 긴 코드는 한 번에 너무 길게 두지 말고, 구간별로 나누어 설명한다.
- 코드 블록 하나가 너무 길어 PDF에서 어색하게 넘어갈 것 같으면, 적절한 단위로 나눠서 배치한다.
- 가능하면 코드 블록 앞뒤에 한 줄 설명을 넣어, PDF에서 페이지가 바뀌어도 맥락이 끊기지 않게 한다.
- **강의 중 직접 적은 코드나 필기 코드는 가능한 한 원형을 유지**하고, 필요한 설명/보강 코드는 아래에 추가한다.
- 즉, 원본 코드를 멋대로 통째로 갈아엎기보다, **원본 보존 + 설명 보강** 방식으로 정리한다.

[본문 통합형 배치 규칙]
- 본문 3장에서는 **개념 단위 소제목**을 사용한다.
- 각 소제목은 가능하면 아래 순서를 따른다.
  1. 개념 한 줄 정의
  2. 왜 필요한지 / 어디서 쓰이는지
  3. 쉬운 해설 또는 비유
  4. 예시 / 그림 / 표
  5. 관련 코드
  6. 코드 해설
  7. 실수 포인트 / 주의점
  8. 짧은 정리 문장
- 모든 개념에 이 8가지를 억지로 다 넣을 필요는 없지만, **관련 자료가 있으면 해당 개념 아래에서 바로 처리**한다.
- 예시가 있으면 예시를 먼저 이해시키고 코드를 보여준다.
- 그림이 있으면 그림 설명 뒤에 그 그림이 연결되는 코드나 개념을 붙인다.
- 비교가 필요한 개념은 표로 정리하되, 표 아래에서 바로 해설을 덧붙인다.

[적용 / 예시 / 코드 섹션 사용 규칙]
- 4장은 "본문을 읽고 나서 실제 문제풀이나 구현에 어떻게 연결되는지"를 정리하는 용도로 쓴다.
- 4장에서는 아래 내용을 우선한다.
  - 어떤 상황에서 이 개념을 적용하면 되는지
  - 문제를 보면 어떤 신호로 떠올려야 하는지
  - 구현 순서를 어떻게 잡으면 되는지
  - 자주 틀리는 패턴이 무엇인지
  - 본문에서 본 예시/코드를 어떻게 응용하면 되는지
- 4장에는 **본문에 이미 나온 예시와 코드의 의미를 응용 관점에서 다시 묶어 설명**할 수는 있다.
- 하지만 **본문에 없던 핵심 코드, 핵심 예시, 핵심 개념을 4장에서 처음 제시하지는 않는다.**

[이미지/표/원문 보존 규칙]
- 원문에 이미지, 도식, 스크린샷이 있으면 가능한 한 해당 개념이 나오는 위치에 유지한다.
- 원문에 표가 있으면 의미를 해치지 않는 범위에서 정리하되, 핵심 비교 항목은 유지한다.
- 원문에 적어 둔 짧은 메모, 강조 표시, 실수 포인트가 중요한 경우 본문 설명 안으로 자연스럽게 흡수한다.
- 원문 내용이 핵심인데 표현만 거칠다면, **내용은 보존하고 표현만 다듬는다.**

[PDF 친화형 구성 규칙]
- 한 섹션이 너무 길어지면 자연스럽게 소제목으로 나눈다.
- 코드 블록은 너무 길게 한 덩어리로 두지 말고, 의미 단위로 나누고 각 구간마다 설명을 붙인다.
- 표는 너무 큰 표 하나로 만들기보다, 필요한 만큼 나누어서 정리한다.
- 이미지와 그 설명이 떨어지지 않게, 가능한 한 바로 아래에 붙여서 작성한다.
- 한 문단이 너무 길면 2~4문단 정도로 나누어 가독성을 높인다.
- `---` 구분선은 섹션 단위에서만 사용하고, 지나치게 많이 넣지 않는다.
- 페이지가 바뀌어도 맥락이 끊기지 않도록, 각 섹션의 첫 문장에 "이 섹션에서 다룰 내용"을 짧게 적는다.
- "다음 페이지에서 이어짐" 같은 어색한 표현은 쓰지 않는다.
- PDF 저장을 염두에 두고, 너무 넓은 표나 지나치게 긴 코드 블록은 피한다.

[출력 방식]
- 문서 맨 앞에 글 전체를 빠르게 이해할 수 있는 메타 정보를 넣는다.
- 본문은 **무엇을 다루는 글인지 → 핵심 개념 → 본문 안의 예시/코드/이미지 → 적용 관점 정리 → 배운 점 → 요약** 흐름으로 정리한다.
- 강의 정리이지만, 읽는 사람 입장에서는 **하나의 잘 정리된 설명형 학습 노트**처럼 보이게 작성한다.
- 필요하면 소제목을 더 세분화해도 된다.
- 설명은 친절하게 하되 군더더기는 줄이고, 복습할 때 바로 핵심이 떠오르게 정리한다.

## 1. 들어가며
- 이 글에서 무엇을 다루는지
- 왜 중요한지
- 어떤 흐름으로 설명할지
- 너무 딱딱하게 선언만 하지 말고, 독자가 이 글을 읽으며 무엇을 이해하게 될지 자연스럽게 안내

## 2. 핵심 개념 정리
- 강의에서 다룬 핵심 개념 설명
- 왜 중요한지
- 쉬운 해설과 배경 설명
- general 버전처럼 강의 전체 흐름이 보이게 정리
- 이 뒤에 나올 본문 소제목들과 연결되도록 큰 그림 제시

## 3. 본문 정리
- **이 문서의 핵심 섹션이다.**
- 개념별 설명을 하면서, **해당 개념과 연결되는 예시 / 코드 / 이미지 / 표를 그 자리에서 바로 제시**한다.
- 즉, 개념 설명만 해두고 예시는 뒤에서 따로 설명하지 않는다.
- 필요한 경우 아래와 같은 소구조를 반복해도 된다.

### 3.x [개념 이름]
- 개념 한 줄 정의
- 왜 필요한지 / 어디서 막히기 쉬운지
- 쉬운 해설 또는 비유
- 예시 / 그림 / 표(있다면)
- 관련 코드(있다면, 반드시 이 위치에)
- 코드 흐름 해설(코드가 있다면 바로 아래에)
- 자주 하는 실수 / 디버깅 포인트
- `📌 핵심` 한 줄 정리

- 중요한 포인트는 본문 흐름 안에서 강조한다.
- 독자가 이해하기 쉽게 자연스럽게 연결한다.
- 필요한 경우 소제목으로 잘게 나누어 PDF에서도 읽기 좋게 정리한다.

- 본문에서 이미 설명한 개념, 예시, 코드가 실제 문제풀이 / 구현 / 복습에서 어떻게 연결되는지 정리한다.
- **새로운 핵심 코드나 새로운 핵심 예시는 여기서 처음 제시하지 않는다.**
- 아래 요소를 중심으로 정리한다.
  - 어떤 유형에서 이 개념을 떠올리면 되는지
  - 구현 순서를 어떻게 잡으면 되는지
  - 실전에서 헷갈리는 포인트는 무엇인지
  - 본문 속 예시/코드를 어떻게 응용하면 되는지
- 필요하면 예시 입력/출력을 다시 짧게 언급할 수 있지만, 핵심 설명은 이미 3장에서 끝내둔다.

## 5. 배운 점 / 느낀 점 / 확장 포인트
- 이 강의를 통해 배운 점
- 실무나 문제풀이와 연결되는 지점
- 더 공부해볼 만한 포인트
- 단순 감상문처럼 쓰기보다, 배운 개념이 다음 학습과 어떻게 이어지는지 보여준다.

## 6. 요약 정리

- 너무 짧은 요약만 두지 말고, 복습할 때 다시 떠올릴 핵심 문장을 남긴다.
```
