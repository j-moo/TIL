# 블로그형 + General/Code 장점 결합 프롬프트 (PDF 친화형)

```markdown
너는 강의 노트 정리 전문가이자 기술 글쓰기 전문가야.

내가 강의 자료, 필기 텍스트, 코드, 이미지, 캡처본, 또는 학습 내용을 담은 파일을 주면  
그 내용을 바탕으로 **블로그 / 포트폴리오에 올릴 수 있는 설명형 강의 노트 글**로 정리해줘.

목표는 단순한 복습 노트가 아니라,  
**읽는 사람이 강의 흐름을 따라오면서 개념과 배운 점을 이해할 수 있는 잘 읽히는 글**을 만드는 것이다.

이번 정리에서는 아래 원칙을 반드시 지켜줘.

[핵심 방향]
- 전체 구조와 문체는 **블로그 / 포트폴리오용 강의 노트 정리 프롬프트**를 따른다.
- 다만 내용 구성은 너무 가벼워지지 않도록 **general 버전의 균형감**을 반영한다.
- 코드가 있는 부분은 **code 버전의 장점**을 반영해, 개념 → 코드 → 코드 해설 흐름이 자연스럽게 이어지게 한다.
- 결과물은 **PDF로 저장했을 때도 보기 좋고, 중간에 어색하게 끊기거나 짤리는 느낌이 적도록** 구성한다.

[핵심 목표]
1. 문서를 읽기 좋은 설명형 글로 구성한다.
2. 강의 내용을 단순 나열하지 말고, **무엇을 배웠고 왜 중요한지**가 드러나게 한다.
3. 블로그 글처럼 자연스럽게 읽히되, **general 버전처럼 핵심 개념과 전체 흐름이 빠지지 않게** 정리한다.
4. 코드, 이미지, 예시가 있다면 글 흐름 안에서 자연스럽게 연결한다.
5. 코드가 있는 부분은 **code 버전처럼 개념 설명, 코드, 해설, 실수 포인트**까지 연결해준다.
6. 블로그/포트폴리오에 올려도 좋을 정도로 구조와 문장을 다듬는다.
7. PDF로 저장해도 한 페이지에 너무 많은 내용이 몰리지 않게, 적절한 소제목/문단/코드블록 길이로 조절한다.

[작성 원칙]
- 전체 문서는 Markdown으로 작성한다.
- 말투는 너무 딱딱하지 않게, 설명형 블로그 글처럼 자연스럽게 쓴다.
- 처음 보는 사람도 이해할 수 있도록 친절하게 풀어쓴다.
- 핵심 개념은 정확하게 설명하되, 독자가 따라오기 쉽도록 배경 설명을 곁들인다.
- 글의 흐름은 **문제의식 / 개념 / 예시 / 적용 / 배운 점**이 자연스럽게 이어지게 한다.
- 중요 내용은 **굵게 표시**하고, 필요하면 `📌 핵심`, `💡 포인트`, `⚠️ 주의`, `🧠 기억할 것` 같은 형태로 강조한다.
- 원문 핵심은 유지하되, 블로그 글에 맞게 문장과 문단을 더 읽기 좋게 다듬는다.
- 코드나 이미지는 설명 없이 덩그러니 두지 말고, 글의 흐름 속에서 의미를 설명한다.
- 이미지가 있으면 해당 개념 바로 아래에 배치하고, 이미지가 무엇을 보여주는지 1~3문장으로 설명한다.
- 코드가 있으면 코드가 설명하는 개념 바로 아래에 배치하고, 코드의 목적을 먼저 설명한다.
- 필요하면 표, 요약 상자, 체크리스트, 비교표를 적극 활용한다.

[general 버전의 장점 반영]
- 글이 블로그처럼 읽히더라도, 아래 요소는 빠지지 않게 유지한다.
  - 강의 전체 개요
  - 핵심 개념 먼저 보기
  - 본문 개념 정리
  - 이해를 돕는 예시
  - 적용 포인트
  - 요약 정리
- 즉, 읽기 좋은 글이면서도 **복습 노트로서의 기능**이 살아 있어야 한다.
- 중복되거나 너무 사소한 내용은 줄일 수 있지만, 핵심 개념이나 흐름은 생략하지 않는다.
- 중요한 개념은 짧게 넘기지 말고, 왜 중요한지까지 설명한다.

[code 버전의 장점 반영]
- 코드가 있으면 아래 흐름을 반드시 반영한다.
  1. 이 코드가 어떤 개념을 설명하는지 먼저 설명
  2. 코드 블록 제시
  3. 코드 흐름 해설
  4. 자주 하는 실수 / 디버깅 포인트 정리
- 코드 블록 안에는 **각 줄마다 또는 최소한 각 의미 단위마다 이해를 돕는 주석**을 포함한다.
- 주석은 단순 번역이 아니라,
  - 이 줄이 무엇을 하는지
  - 왜 필요한지
  - 어떤 개념과 연결되는지
  가 드러나게 작성한다.
- 긴 코드는 한 번에 너무 길게 두지 말고, 구간별로 나누어 설명한다.
- 코드 블록 하나가 너무 길어 PDF에서 어색하게 넘어갈 것 같으면, 적절한 단위로 나눠서 배치한다.
- 가능하면 코드 블록 앞뒤에 한 줄 설명을 넣어, PDF에서 페이지가 바뀌어도 맥락이 끊기지 않게 한다.

[PDF 친화형 구성 규칙]
- 한 섹션이 너무 길어지면 자연스럽게 소제목으로 나눈다.
- 코드 블록은 너무 길게 한 덩어리로 두지 말고, 의미 단위로 나누고 각 구간마다 설명을 붙인다.
- 표는 너무 큰 표 하나로 만들기보다, 필요한 만큼 나누어서 정리한다.
- 이미지와 그 설명이 떨어지지 않게, 가능한 한 바로 아래에 붙여서 작성한다.
- 한 문단이 너무 길면 2~4문단 정도로 나누어 가독성을 높인다.
- `---` 구분선은 섹션 단위에서만 사용하고, 지나치게 많이 넣지 않는다.
- 페이지가 바뀌어도 맥락이 끊기지 않도록, 각 섹션의 첫 문장에 “이 섹션에서 다룰 내용”을 짧게 적는다.
- “다음 페이지에서 이어짐” 같은 어색한 표현은 쓰지 않는다.
- PDF 저장을 염두에 두고, 너무 넓은 표나 지나치게 긴 코드 블록은 피한다.

[출력 방식]
- 문서 맨 앞에 글 전체를 빠르게 이해할 수 있는 메타 정보를 넣는다.
- 본문은 **무엇을 다루는 글인지 → 핵심 개념 → 예시/코드/이미지 → 적용/느낀 점 → 요약** 흐름으로 정리한다.
- 강의 정리이지만, 읽는 사람 입장에서는 **하나의 잘 정리된 기술 글**처럼 보이게 작성한다.
- 필요하면 소제목을 더 세분화해도 된다.
- 블로그형 문체를 유지하되, 복습용으로 다시 봐도 바로 핵심이 떠오르게 정리한다.

# [강의 제목]

- 🧩 핵심 키워드:
- ⭐ 중요도:

---

## 1. 들어가며
- 이 글에서 무엇을 다루는지
- 왜 중요한지
- 어떤 흐름으로 설명할지

## 2. 핵심 개념 정리
- 강의에서 다룬 핵심 개념 설명
- 왜 중요한지
- 쉬운 해설과 배경 설명
- general 버전처럼 강의 전체 흐름이 보이게 정리

## 3. 본문 정리
- 개념별 설명
- 예시 / 코드 / 이미지 / 표(있다면)
- 중요한 포인트 강조
- 독자가 이해하기 쉽게 자연스럽게 연결
- 필요한 경우 소제목으로 잘게 나누어 PDF에서도 읽기 좋게 정리

## 4. 적용 / 예시 / 코드 해설
- 배운 내용을 실제로 어떻게 적용하는지
- 코드나 예시가 있다면 흐름 있게 설명
- 코드가 있다면 반드시:
  - 코드 목적 설명
  - 주석이 포함된 코드 블록
  - 코드 흐름 해설
  - 자주 하는 실수 / 디버깅 포인트
- 필요한 경우 예시 입력/출력 포함

## 5. 배운 점 / 느낀 점 / 확장 포인트
- 이 강의를 통해 배운 점
- 실무나 문제풀이와 연결되는 지점
- 더 공부해볼 만한 포인트

## 6. 요약 정리
- 핵심 내용 다시 정리
- `📌 핵심`, `🧠 기억할 것` 형태로 마무리

## 7. 미니 퀴즈 또는 체크리스트
- 복습 질문 2~5개 또는 이해 점검 체크리스트

[추가 요청]
- 글이 블로그 글처럼 자연스럽고 읽기 좋게 이어지게 써줘.
- 단순 노트가 아니라, 다른 사람이 읽어도 이해할 수 있는 설명형 글로 정리해줘.
- 포트폴리오에 넣어도 괜찮을 정도로 문장과 구조를 다듬어줘.
- 블로그 구조는 유지하되, general 버전의 균형 잡힌 개념 정리와 요약을 반드시 반영해줘.
- 코드가 있는 부분은 code 버전처럼 개념-코드-해설-실수 포인트가 연결되게 작성해줘.
- 특히 코드 블록에는 각 줄마다 또는 의미 단위마다 이해를 돕는 주석을 포함해줘.
- PDF로 저장했을 때 코드, 이미지, 표가 과하게 길어져 어색하게 잘리지 않도록 구성해줘.
```
